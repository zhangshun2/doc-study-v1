# 问题1.0.0-字符串解码

## 📋 **问题描述**

**LeetCode 394. 字符串解码**

给定一个经过编码的字符串，返回它解码后的字符串。

编码规则为: `k[encoded_string]`，表示其中方括号内部的 `encoded_string` 正好重复 k 次。注意 k 保证为正整数。

## 🎯 **核心特征分析**

### **1. 嵌套结构特征**
```
输入: "3[a2[c]]"
解析层次:
  外层: 3[...]     → 重复3次
  内层: a2[c]      → a + 重复2次的c
  最内层: c        → 基础字符
```

### **2. 重复模式特征**
- **格式**: `k[encoded_string]`
- **语义**: 将方括号内的字符串重复 k 次
- **嵌套**: 内层先解码，外层后解码

### **3. 数据特征**
- 数字范围: [1, 300] (可能是多位数)
- 字符串长度: [1, 30]
- 字符类型: 小写字母、数字、方括号
- 保证输入有效

## 🔍 **问题难点识别**

### **难点1: 嵌套处理**
```
"3[a2[c]]" 的处理顺序:
1. 最内层: 2[c] → cc
2. 中间层: a + cc → acc  
3. 外层: 3[acc] → accaccacc
```

**挑战**: 如何正确处理从内到外的解码顺序？

### **难点2: 状态管理**
在解析过程中需要同时跟踪：
- 当前的重复次数
- 当前构建的字符串
- 嵌套层级的状态保存与恢复

### **难点3: 多位数字处理**
```
"12[a]" → 需要正确解析数字12，而不是1和2
"100[leetcode]" → 需要处理三位数
```

### **难点4: 边界情况**
- 普通字符的直接拼接: `"abc3[cd]xyz"`
- 连续的编码块: `"2[abc]3[cd]ef"`
- 深层嵌套: `"2[a3[b2[c]]]"`

## 🧠 **思维模式分析**

### **递归思维**
- 问题具有明显的递归结构
- 内层问题的解决方案可以用于外层

### **栈思维**
- 嵌套结构天然适合栈的"后进先出"特性
- 遇到 `[` 时保存状态，遇到 `]` 时恢复状态

### **状态机思维**
解析过程可以看作状态转换：
- **数字状态**: 累积重复次数
- **字符状态**: 累积字符串内容
- **进入状态**: 遇到 `[` 保存当前状态
- **退出状态**: 遇到 `]` 计算并恢复

1. **双栈设计**: 分离数字和字符串的管理，简化逻辑
2. **状态保存**: 遇到嵌套时及时保存当前状态
3. **逐字符处理**: 通过字符类型判断执行不同操作
4. **从内到外**: 利用栈的特性自然实现正确的解码顺序
