# 5.1.1 动态规划方法详解 - 爬楼梯DP实现思路 (Java版本)
> 深入解析动态规划的核心思想和实现范式
>

## 🎯 核心代码回顾
```java
public class Solution {
    public int climbStairs(int n) {
        // 特殊情况处理
        if (n == 1) {
            return 1;
        }
        if (n == 2) {
            return 2;
        }
        
        // 创建dp数组
        int[] dp = new int[n + 1];
        
        // 设置边界条件
        dp[1] = 1;
        dp[2] = 2;
        
        // 填充dp数组
        for (int i = 3; i <= n; i++) {
            dp[i] = dp[i - 1] + dp[i - 2];
        }
        
        return dp[n];
    }
}
```

## 🧠 DP思路深度解析
### 💡 核心思想：记忆化存储
**问题本质：**

+ 递归方法会重复计算相同的子问题
+ DP通过数组存储已计算的结果，避免重复计算
+ 将"自顶向下"的递归转换为"自底向上"的迭代

**思维转换：**

```plain
递归思维：f(n) = f(n-1) + f(n-2)  (从大到小)
   ↓
DP思维：dp[i] = dp[i-1] + dp[i-2]  (从小到大)
```

### 🔍 逐步执行过程分析
以 `n = 5` 为例，详细分析执行过程：

#### 第1步：初始化
```java
int[] dp = new int[6];  // 创建长度为n+1的数组
// dp = [0, 0, 0, 0, 0, 0]
//       0  1  2  3  4  5
```

#### 第2步：设置边界条件
```java
dp[1] = 1;  // 到达第1阶有1种方法
dp[2] = 2;  // 到达第2阶有2种方法
// dp = [0, 1, 2, 0, 0, 0]
//       0  1  2  3  4  5
```

#### 第3步：自底向上填充
```java
// i = 3
dp[3] = dp[2] + dp[1] = 2 + 1 = 3
// dp = [0, 1, 2, 3, 0, 0]
//       0  1  2  3  4  5

// i = 4
dp[4] = dp[3] + dp[2] = 3 + 2 = 5
// dp = [0, 1, 2, 3, 5, 0]
//       0  1  2  3  4  5

// i = 5
dp[5] = dp[4] + dp[3] = 5 + 3 = 8
// dp = [0, 1, 2, 3, 5, 8]
//       0  1  2  3  4  5
```

#### 第4步：返回结果
```java
return dp[5];  // 返回8
```

### 📊 状态转移可视化
```plain
楼梯阶数:  1    2    3    4    5
方法数量:  1 -> 2 -> 3 -> 5 -> 8
           ↑    ↑    ↑    ↑    ↑
           |    |    |    |    |
计算过程:  直接 直接  1+2  2+3  3+5
```

**关键观察：**

+ 每个位置的值都是前两个位置值的和
+ 这正是斐波那契数列的规律
+ DP将递归关系转化为了迭代计算

## 🎯 DP范式详解
### 📋 标准DP范式的五个要素
#### 1. **状态定义 (State Definition)**
```java
// dp[i] 的含义必须明确
dp[i] = 到达第i阶楼梯的方法数
```

**设计原则：**

+ 状态要能表达问题的本质
+ 状态之间要有明确的转移关系
+ 状态空间要覆盖所有可能情况

#### 2. **状态转移方程 (State Transition)**
```java
// 当前状态如何从之前状态得出
dp[i] = dp[i-1] + dp[i-2]
```

**推导过程：**

+ 要到达第i阶，最后一步只能是爬1阶或2阶
+ 爬1阶：从第(i-1)阶来，方法数为dp[i-1]
+ 爬2阶：从第(i-2)阶来，方法数为dp[i-2]
+ 总方法数：dp[i-1] + dp[i-2]

#### 3. **边界条件 (Base Cases)**
```java
// 最小规模的问题直接给出答案
dp[1] = 1;  // 到第1阶只有1种方法
dp[2] = 2;  // 到第2阶有2种方法
```

**设置原则：**

+ 边界条件要符合实际意义
+ 要能支撑后续的状态转移
+ 通常是最小的1-2个状态

#### 4. **计算顺序 (Computation Order)**
```java
// 从小到大，确保依赖的状态已计算
for (int i = 3; i <= n; i++) {
    dp[i] = dp[i-1] + dp[i-2];
}
```

**顺序原则：**

+ 计算dp[i]时，dp[i-1]和dp[i-2]必须已知
+ 通常是线性顺序（一维DP）
+ 二维DP通常是逐行或逐列

#### 5. **结果提取 (Result Extraction)**
```java
// 从DP数组中提取最终答案
return dp[n];
```

### 🔧 DP实现的通用模板
```java
public class DPTemplate {
    public int solve(int n) {
        // 1. 输入验证和特殊情况处理
        if (n <= 0) return 0;
        if (n == 1) return baseCase1;
        if (n == 2) return baseCase2;
        
        // 2. 创建DP数组
        int[] dp = new int[n + 1];
        
        // 3. 设置边界条件
        dp[1] = baseCase1;
        dp[2] = baseCase2;
        
        // 4. 状态转移
        for (int i = 3; i <= n; i++) {
            dp[i] = transitionFunction(dp, i);
        }
        
        // 5. 返回结果
        return dp[n];
    }
    
    // 状态转移函数（根据具体问题实现）
    private int transitionFunction(int[] dp, int i) {
        return dp[i-1] + dp[i-2];  // 爬楼梯的转移函数
    }
}
```

## 🎯 为什么DP比递归高效？
### ⚡ 时间复杂度对比
**递归方法：**

```plain
f(5) = f(4) + f(3)
     = (f(3) + f(2)) + (f(2) + f(1))
     = ((f(2) + f(1)) + f(2)) + (f(2) + f(1))
     = ...
```

+ f(2)被计算了3次
+ f(3)被计算了2次
+ 时间复杂度：O(2^n)

**DP方法：**

```plain
dp[1] = 1     (计算1次)
dp[2] = 2     (计算1次)
dp[3] = 3     (计算1次)
dp[4] = 5     (计算1次)
dp[5] = 8     (计算1次)
```

+ 每个状态只计算1次
+ 时间复杂度：O(n)

## 🎯 DP思维的核心要点
### 💡 从递归到DP的思维转换
1. **识别重叠子问题**
    - 递归过程中是否有重复计算？
    - 相同的参数是否被多次调用？
2. **定义状态空间**
    - 用什么变量来表示问题的状态？
    - 状态如何覆盖所有可能的情况？
3. **建立状态转移**
    - 当前状态如何从之前状态得出？
    - 转移关系是否正确且完整？
4. **确定计算顺序**
    - 如何保证计算当前状态时依赖状态已知？
    - 是否可以优化空间复杂度？

### 🔧 DP设计的检验标准
1. **正确性检验**
    - 边界条件是否正确？
    - 状态转移是否涵盖所有情况？
    - 结果是否符合预期？
2. **效率检验**
    - 时间复杂度是否优于暴力解法？
    - 空间复杂度是否可以进一步优化？
    - 是否存在更高效的算法？
3. **可读性检验**
    - 代码逻辑是否清晰？
    - 变量命名是否有意义？
    - 注释是否充分？
