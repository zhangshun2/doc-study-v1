## 概述
`ch - 'a'` 是一种将小写字母 `a..z` 映射到数组下标 `0..25` 的常用写法。它依赖于字符的底层数值编码（如 ASCII/Unicode）：将当前字符的编码减去 `'a'` 的编码，得到其相对偏移。

示例：
- `'a' - 'a' = 0`、`'b' - 'a' = 1`、`'z' - 'a' = 25`。
- 典型使用场景：构造长度为 26 的计数数组 `int[26]`，用于异位词分组、滑动窗口、频次统计等。

## 原理与直觉
- 字符在计算机中本质是整数（码点）。Java 的 `char` 可参与算术运算，结果为 `int`。
- 以 `'a'` 为“基准点”，任何小写字母相对于 `'a'` 的距离就是其索引。
- 使用字符字面量而不是 97（`'a'` 的 ASCII 值），可读性更强且避免“魔法数字”。

## 标准用法（Java示例）
```java
int[] count = new int[26];
for (char ch : s.toCharArray()) {
    int idx = ch - 'a';
    if (idx < 0 || idx >= 26) {
        // 超出 a..z 范围的字符，视题目约束选择：忽略/报错/扩展处理
        continue; 
    }
    count[idx]++;
}
```

## 常见场景
- 字母异位词分组（LeetCode 49）：为每个字符串构造 26 维频次向量作为签名。
- 有效的字母异位词（LeetCode 242）：两个字符串频次向量相等即为异位词。
- 找到字符串中所有字母异位词（LeetCode 438）：滑动窗口维护频次差异。

## 边界与安全处理
- 输入约束：通常题目限定为小写字母 `a..z`，否则 `ch - 'a'` 可能越界。
- 大小写处理：
  - 若包含大写字母，可使用 `idx = ch - 'A'`（映射 `A..Z` 到 `0..25`），或先统一 `Character.toLowerCase(ch)` 再映射。
- 非字母字符：
  - 若存在数字或其他符号，需扩展方案：
    - 使用更大数组（如 52 维，大小写分区），或
    - 使用 `Map<Character, Integer>` 计数，更通用但稍慢。
- Unicode 扩展：
  - 对中文等非 ASCII 字符，`ch - 'a'` 无意义，需改用哈希映射或 `codePoint` 基于桶划分。

## 对比与选择
- `ch - 'a'` vs 直接写常数：`ch - 97` 可行但不推荐；字符字面量更清晰、可维护。
- 计数签名 vs 排序签名：
  - 计数签名：每串 `O(L)`，更快；依赖 `ch - 'a'` 这类索引映射。
  - 排序签名：每串 `O(L log L)`，实现更短，更通用（无需字母集假设）。

## 易错点 Checklist
- 忘记校验字符范围导致数组越界。
- 混用大小写但仍用 `'a'` 作为基准，导致索引错误。
- 直接用 `int[]` 作为哈希键（引用比较），应序列化为字符串或使用 `List<Integer>` 并重写比较。
- 键序列化未加分隔符，导致歧义（如 "1,12" 与 "11,2"）。

## 记忆卡片（快速记忆）
- 小写字母映射：`idx = ch - 'a'` → `0..25`。
- 安全原则：先判定范围，再累加计数。
- 扩展思路：大写用 `'A'`，数字用 `'0'`；更复杂字符用 Map。
