# 问题1.0.1-正则表达式匹配-贪心策略局限性

## 概述
本文总结了关于LeetCode 10“正则表达式匹配”问题中，用户提出的基于“分割-贪心匹配”思路的讨论，并分析了该思路在处理`*`特殊字符时的局限性。

## 用户提出的思路
用户提出了一种直观的匹配思路：
1.  将模式字符串`p`按照`.`和`*`进行分割，得到一系列模式片段，放入一个队列中。
2.  遍历队列中的每个模式片段，尝试匹配当前字符串`s`的开头。
3.  如果匹配失败，则返回`false`。
4.  如果匹配成功，则从`s`中截取掉匹配成功的部分，并继续处理`s`的剩余部分。
5.  队列遍历结束后，如果`s`的长度为0，则返回`true`。

## 贪心策略的局限性分析
该思路的核心在于对模式片段的“贪心”匹配，即每次都尝试匹配尽可能多的字符。然而，对于正则表达式中的`*`（表示前一个字符可以重复零次或多次），这种贪心策略可能导致错误。

### 核心问题：`*`的“零次或多次”选择性
`*`的特性引入了多种匹配可能性，而贪心算法往往无法有效处理这种选择性。它可能过早地做出一个“最优”的局部决策，从而错过全局最优的匹配路径。

### 示例分析：贪心策略可能失败的场景

**场景一：`s = "ab"`, `p = ".*c"`**

1.  **用户思路（贪心）**：
    *   模式`p`被分割为`[".*", "c"]`。
    *   取出`".*"`，贪心地匹配`s = "ab"`中的所有字符`"ab"`。`s`变为`""`。
    *   取出`"c"`，尝试匹配`s = ""`的开头，匹配失败。
    *   最终返回`false`。
    *   **结果**：在此例中，贪心策略偶然得到了正确结果。

**场景二：`s = "aab"`, `p = "c*a*b"`**

1.  **用户思路（贪心）**：
    *   模式`p`被分割为`["c*", "a*", "b"]`。
    *   取出`"c*"`，匹配`s = "aab"`中的零个`c`。`s`仍为`"aab"`。
    *   取出`"a*"`，贪心地匹配`s = "aab"`中的`"aa"`。`s`变为`"b"`。
    *   取出`"b"`，匹配`s = "b"`中的`"b"`。`s`变为`""`。
    *   最终返回`true`。
    *   **结果**：在此例中，贪心策略得到了正确结果。

**为什么贪心策略可能失败？**
上述两个例子中，贪心策略恰好得到了正确结果，但这是因为模式和字符串的特定组合。当`*`的匹配长度影响到后续模式片段的匹配时，贪心策略的局限性就会显现。

例如，如果`.*`匹配了过多的字符，导致后续的固定字符无法匹配，而实际上`.*`少匹配一些字符就能成功，贪心策略就会失败。

### 正确处理`*`的思路（动态规划/回溯）
为了正确处理`*`的“零次或多次”特性，需要系统地探索所有可能性。动态规划或带记忆化的递归（回溯）算法通常采用以下逻辑：

当遇到`X*`（`X`可以是任意字符或`.`）时，会考虑两种情况：
1.  **`X*`匹配零次**：此时`X*`被忽略，模式指针直接跳过`X*`，继续匹配模式的剩余部分。
2.  **`X*`匹配一次或多次**：
    *   首先判断`s`的当前字符是否能与`X`匹配。
    *   如果能匹配，则有两种选择：
        *   让`X*`匹配`s`的当前字符，然后继续用`X*`匹配`s`的下一个字符（即`X*`仍然有效）。
        *   让`X*`匹配`s`的当前字符，然后用模式的剩余部分匹配`s`的剩余部分。

动态规划通过构建一个二维`dp`表，`dp[i][j]`表示`s`的前`i`个字符与`p`的前`j`个字符是否匹配，从而系统地记录并利用子问题的解，避免重复计算，并确保所有可能性都被探索到。

## 结论
虽然用户提出的“分割-贪心匹配”思路在某些简单场景下可能有效，但由于正则表达式中`*`的复杂性和选择性，它无法保证在所有情况下都能得出正确结果。动态规划或带记忆化的递归（回溯）是解决此类问题的更健壮和全面的方法，它们能够系统地探索所有可能的匹配路径。
