# 题解2.0.1-正则表达式匹配-DFS记忆化搜索

## 题解概述

本题解采用深度优先搜索（DFS）结合记忆化搜索（Memoization）来解决正则表达式匹配问题。这种方法本质上是带备忘录的递归回溯，与动态规划的自顶向下实现高度相似。它通过递归地尝试所有可能的匹配路径，并利用备忘录存储中间结果，避免重复计算，从而有效处理 `*` 字符带来的多重选择问题。

相比于纯粹的贪心策略，DFS记忆化搜索能够系统地探索 `*` 匹配零次或多次的所有可能性，确保找到正确的匹配结果。

## 步骤/模板

核心是一个递归函数 `dfs(s_idx, p_idx)`，表示 `s` 从 `s_idx` 开始的子串能否与 `p` 从 `p_idx` 开始的子串匹配。

1.  **递归函数定义**: `boolean dfs(int s_idx, int p_idx)`
    *   `s_idx`: 当前 `s` 字符串的起始索引。
    *   `p_idx`: 当前 `p` 模式串的起始索引。
    *   返回值: `true` 表示匹配成功，`false` 表示匹配失败。

2.  **备忘录 (Memoization)**: 使用一个二维数组 `memo[s.length() + 1][p.length() + 1]` 来存储 `dfs(s_idx, p_idx)` 的结果。
    *   `memo[s_idx][p_idx] = 0` 表示未计算。
    *   `memo[s_idx][p_idx] = 1` 表示匹配成功。
    *   `memo[s_idx][p_idx] = -1` 表示匹配失败。

3.  **基本情况 (Base Cases)**:
    *   如果 `p_idx` 到达模式串末尾：
        *   如果 `s_idx` 也到达字符串末尾，则匹配成功 (`return true`)。
        *   否则，匹配失败 (`return false`)。
    *   如果 `s_idx` 到达字符串末尾：
        *   检查 `p` 剩余部分是否都是 `X*` 形式（即可以匹配零次）。如果是，则匹配成功 (`return true`)。
        *   否则，匹配失败 (`return false`)。

4.  **递归逻辑**:
    *   **当前字符匹配判断**: `first_match = (s_idx < s.length() && (s.charAt(s_idx) == p.charAt(p_idx) || p.charAt(p_idx) == '.'))`
        *   `s_idx < s.length()` 确保 `s` 还有字符可匹配。
        *   `s.charAt(s_idx) == p.charAt(s_idx)` 普通字符匹配。
        *   `p.charAt(p_idx) == '.'` `.` 匹配任意单个字符。

    *   **处理 `*` 字符**: 如果 `p_idx + 1 < p.length()` 且 `p.charAt(p_idx + 1) == '*'`：
        *   **情况一：`*` 匹配零次**: 此时 `X*` 整体被跳过，递归调用 `dfs(s_idx, p_idx + 2)`。
        *   **情况二：`*` 匹配一次或多次**: 只有当 `first_match` 为 `true` 时才可能发生。此时 `X` 匹配了 `s.charAt(s_idx)`，然后 `X*` 仍然可以继续匹配 `s` 的剩余部分。递归调用 `dfs(s_idx + 1, p_idx)`。
        *   最终结果是这两种情况的逻辑或 (`||`)。

    *   **处理非 `*` 字符**: 如果 `p.charAt(p_idx + 1) != '*'` (或者 `p_idx + 1` 越界，即没有 `*`)：
        *   只有当 `first_match` 为 `true` 时，才可能匹配成功。此时 `s_idx` 和 `p_idx` 都向前移动一位。递归调用 `dfs(s_idx + 1, p_idx + 1)`。
        *   否则，匹配失败。

5.  **存储并返回结果**: 将计算出的结果存储到 `memo[s_idx][p_idx]` 并返回。

### 伪代码示例

```java
class Solution {
    // memo[i][j] = 0: 未计算, 1: true, -1: false
    int[][] memo;
    String text;
    String pattern;

    public boolean isMatch(String s, String p) {
        text = s;
        pattern = p;
        memo = new int[s.length() + 1][p.length() + 1];
        return dp(0, 0);
    }

    // dp(i, j) 表示 text[i:] 和 pattern[j:] 是否匹配
    private boolean dp(int i, int j) {
        // 如果已经计算过，直接返回
        if (memo[i][j] != 0) {
            return memo[i][j] == 1;
        }

        boolean ans;
        // 基本情况：模式串已匹配完
        if (j == pattern.length()) {
            ans = (i == text.length()); // 字符串也匹配完才算成功
        } else {
            // 判断当前字符是否匹配
            boolean first_match = (i < text.length() &&
                                   (pattern.charAt(j) == text.charAt(i) ||
                                    pattern.charAt(j) == '.'));

            // 如果模式串的下一个字符是 '*'
            if (j + 1 < pattern.length() && pattern.charAt(j + 1) == '*') {
                // 情况一：'*' 匹配零次，跳过 X*
                // 情况二：'*' 匹配一次或多次，当前字符匹配成功后，继续用 X* 匹配下一个字符
                ans = (dp(i, j + 2) || (first_match && dp(i + 1, j)));
            } else {
                // 如果模式串的下一个字符不是 '*'，或者已经到模式串末尾
                // 只有当前字符匹配成功，才继续匹配下一个字符
                ans = (first_match && dp(i + 1, j + 1));
            }
        }

        // 存储结果
        memo[i][j] = ans ? 1 : -1;
        return ans;
    }
}
```

## 正确性要点

*   **系统性探索**: 递归回溯确保了对 `*` 字符所有可能匹配次数（零次、一次、多次）的系统性探索。当遇到 `X*` 时，它会尝试两种路径：
    1.  `X*` 匹配零个 `X`：直接跳过 `X*`，让 `p` 从 `p_idx + 2` 开始匹配。
    2.  `X*` 匹配一个或多个 `X`：如果当前 `s` 字符能与 `X` 匹配，则让 `s` 从 `s_idx + 1` 开始，`p` 仍然从 `p_idx` 开始（即 `X*` 继续尝试匹配下一个 `s` 字符）。
    通过这种方式，所有可能的匹配组合都会被尝试。
*   **备忘录优化**: 由于递归过程中存在大量重叠子问题（即 `dfs(s_idx, p_idx)` 可能会被多次调用），备忘录机制有效地存储了这些子问题的结果。当 `dfs(s_idx, p_idx)` 再次被调用时，可以直接从备忘录中获取结果，避免了重复计算，从而将指数级的时间复杂度优化为多项式级。

## 时间与空间复杂度分析

*   **时间复杂度**: `O(S * P)`，其中 `S` 是字符串 `s` 的长度，`P` 是模式串 `p` 的长度。
    *   递归函数 `dp(i, j)` 的状态数量是 `S * P`。
    *   每个状态的计算时间是常数 `O(1)`（不包括递归调用本身）。
    *   因此，总时间复杂度为 `O(S * P)`。
*   **空间复杂度**: `O(S * P)`，主要用于存储备忘录 `memo` 数组以及递归栈的深度。
    *   备忘录数组的大小是 `(S+1) * (P+1)`。
    *   最坏情况下，递归栈的深度可以达到 `S + P`。
    *   因此，总空间复杂度为 `O(S * P)`。

## 易错点 Checklist

*   **备忘录初始化**: 确保备忘录数组正确初始化，通常用一个特殊值（如 `0`）表示未计算状态。
*   **递归边界条件**: 仔细处理 `s` 和 `p` 都到达末尾，或其中一个到达末尾的情况。特别是 `p` 到达末尾时，`s` 也必须同时到达末尾才算匹配成功。
*   **`*` 字符的处理**: 这是最容易出错的部分。务必区分 `*` 匹配零次和匹配一次或多次的两种情况，并正确地进行递归调用。
*   **`first_match` 的判断**: 在进行 `*` 匹配一次或多次的递归调用前，必须确保当前字符 `s.charAt(s_idx)` 能够与 `p.charAt(p_idx)` 匹配。
*   **索引越界**: 在访问 `s.charAt(s_idx)` 或 `p.charAt(p_idx)` 之前，务必检查 `s_idx` 或 `p_idx` 是否越界。
