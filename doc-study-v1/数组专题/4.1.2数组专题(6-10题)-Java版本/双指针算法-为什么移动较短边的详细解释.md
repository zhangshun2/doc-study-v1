# 双指针算法：为什么要移动较短的那一边？
> 本文档专门解释在"盛最多水的容器"问题中，双指针算法为什么要移动较短的那一边，适合算法初学者理解。
>

---

## 🎯 问题回顾
在LeetCode第11题"盛最多水的容器"中，我们需要找到两条线，使它们与x轴构成的容器能容纳最多的水。

**关键公式：** 容器面积 = 宽度 × 高度（取两条线中较短的那条）

```plain
面积 = (右指针位置 - 左指针位置) × min(左边高度, 右边高度)
```

---

## 🤔 核心疑问：为什么要移动较短的那一边？
### 直观理解
想象你在搬家，有两个人抬一张桌子：

+ 如果一个人很高（1.8米），另一个人很矮（1.5米）
+ 桌子的高度只能按矮的那个人来定（1.5米）
+ 即使高的人再努力举高，桌子还是只能保持在1.5米的高度

**容器装水也是同样的道理：水的高度永远由较短的那条边决定！**

---

## 📊 数学证明：为什么移动长边没有意义？
### 场景设定
假设当前状态：

+ 左指针在位置 `i`，高度为 `height[i] = 3`
+ 右指针在位置 `j`，高度为 `height[j] = 7`
+ 当前面积 = `(j-i) × min(3,7) = (j-i) × 3`

### 情况1：移动长边（右指针）
如果我们移动右指针（高度为7的长边）到位置 `j-1`：

**可能的结果：**

1. `height[j-1] ≥ 3`：新面积 = `(j-1-i) × 3`
2. `height[j-1] < 3`：新面积 = `(j-1-i) × height[j-1]`

**分析：**

+ 情况1：宽度减少了1，高度还是3，面积**必然减少**
+ 情况2：宽度减少了1，高度也减少了，面积**更加减少**

**结论：移动长边，面积只会减少，不会增加！**

### 情况2：移动短边（左指针）
如果我们移动左指针（高度为3的短边）到位置 `i+1`：

**可能的结果：**

1. `height[i+1] > 3`：新面积 = `(j-(i+1)) × min(height[i+1], 7)`
2. `height[i+1] ≤ 3`：新面积 = `(j-(i+1)) × height[i+1]`

**分析：**

+ 情况1：虽然宽度减少了1，但高度可能增加，**面积有可能增加**
+ 情况2：宽度减少了1，高度也减少了，面积减少

**结论：移动短边，面积有可能增加！**

## 🎨 图解说明

```plain
索引:  0  1  2  3  4  5  6  7  8
       ↑                       ↑
      left                   right
      高度=1                  高度=7
      
当前面积 = (8-0) × min(1,7) = 8 × 1 = 8
```

### 如果移动右指针（长边）：
```plain
高度: [1, 8, 6, 2, 5, 4, 8, 3, 7]
索引:  0  1  2  3  4  5  6  7  8
       ↑                    ↑
      left                right
      高度=1               高度=3
      
新面积 = (7-0) × min(1,3) = 7 × 1 = 7 < 8 ❌
```

### 如果移动左指针（短边）：
```plain
高度: [1, 8, 6, 2, 5, 4, 8, 3, 7]
索引:  0  1  2  3  4  5  6  7  8
          ↑                    ↑
         left                right
         高度=8               高度=7
         
新面积 = (8-1) × min(8,7) = 7 × 7 = 49 > 8 ✅
```

**看到了吗？移动短边找到了更大的面积！**

## 🧠 算法思维：贪心策略
### 为什么这是贪心算法？
1. **局部最优选择**：每一步都选择移动短边
2. **全局最优解**：通过一系列局部最优选择得到全局最优
3. **无后效性**：当前的选择不会影响之前的决策

### 贪心策略的正确性
**关键洞察**：移动长边永远不会让面积增加，所以我们永远不需要考虑这种情况。

这就像在迷宫中，如果我们知道某条路肯定是死路，我们就永远不会走那条路。

## 💡 小白友好的记忆方法
### 方法1："木桶效应"
+ 木桶能装多少水，取决于最短的那块板
+ 要想装更多水，必须换掉最短的板
+ 换掉长板没有任何意义

### 方法2："瓶颈理论"
+ 容器的容量被短边"卡住"了
+ 要突破瓶颈，必须解决短板问题
+ 优化非瓶颈部分是浪费时间

### 方法3："机会成本"
+ 移动长边：100%会让面积减少（机会成本高）
+ 移动短边：有可能让面积增加（机会成本低）
+ 理性的选择是移动短边

## 🔍 完整代码解析
```java
class Solution {
    public int maxArea(int[] height) {
        int left = 0, right = height.length - 1;  // 双指针初始化
        int maxArea = 0;
        
        while (left < right) {
            // 步骤1：计算当前面积
            int width = right - left;                    // 宽度
            int minHeight = Math.min(height[left], height[right]); // 高度（短边）
            int area = width * minHeight;                // 面积
            maxArea = Math.max(maxArea, area);           // 更新最大面积
            
            // 步骤2：移动较短的那一边（核心逻辑）
            if (height[left] < height[right]) {
                left++;      // 左边更短，移动左指针
            } else {
                right--;     // 右边更短（或相等），移动右指针
            }
        }
        
        return maxArea;
    }
}
```

### 代码执行轨迹示例
输入：`[1,8,6,2,5,4,8,3,7]`

| 轮次 | left | right | height[left] | height[right] | 宽度 | 高度 | 面积 | 移动 | 原因 |

| 1 | 0 | 8 | 1 | 7 | 8 | 1 | 8 | left++ | 1 < 7 |
| 2 | 1 | 8 | 8 | 7 | 7 | 7 | 49 | right-- | 8 > 7 |

| 4 | 1 | 6 | 8 | 8 | 5 | 8 | 40 | left++ | 8 = 8 |
| ... | ... | ... | ... | ... | ... | ... | ... | ... | ... |

## 🎯 总结
### 核心原理
1. **面积公式**：面积 = 宽度 × min(左高度, 右高度)
2. **关键洞察**：移动长边只会让面积减少
3. **贪心策略**：总是移动短边，寻找更高的线

### 算法优势
+ **时间复杂度**：O(n) - 每个元素最多访问一次
+ **空间复杂度**：O(1) - 只用了几个变量
+ **思路清晰**：逻辑简单，易于理解和实现

### 适用场景
这种"移动短边"的思想在很多双指针问题中都有应用：

+ 三数之和
+ 接雨水
+ 最小覆盖子串
+ 滑动窗口问题
