# 项目规则（project_rules.md）

本规范用于约束与指导智能体在本项目中的对话思考与文档整理方式，确保内容结构统一、命名一致、链接可达与可维护。

## 1. 目标与范围
- 统一对话与思考流程，明确何时产出文档以及文档形态。
- 规范文档命名、路径分类、导航链接与版本管理。
- 提供题解与问题文档的内容模板与质量检查清单。

## 2. 对话与思考流程规范
1) 任务类型判断：
- 非算法类：直接简洁回答问题，必要时指向现有文档，不额外生成文档。
- 算法类：产出成对的 Markdown 文档（问题 + 题解）。

2) 算法类任务的产出要求：
- 先做题目分析，提炼问题可获得的特征与约束。
- 以“引导”为主：给出思路引导与路径选择提示。
- 将可能涉及的知识点单独说明（如邻接表、入度/出度、复杂度、常见误区等）。
- 问题与题解文档必须分离，分别独立存储与维护。

3) 信息获取与协作：
- 优先自查现有代码与文档，尽量减少向用户索取信息。
- 保持回答语言与用户最新输入一致（默认中文）。
- 术语统一、示例明确、强调复杂度直觉与易错点。

## 3. 文档产出规范
- 问题文档命名：`问题1.0.0-<主题>.md`，标题以“问题1.0.0-<概述>”开头。
- 题解文档命名：`题解2.0.0-<主题>.md`，标题以“题解2.0.0-<概述>”开头。
- 搜索与回溯相关文档：最终 MD 必须归档到 `搜索和回溯` 文件夹下；若存在具体分类，建立对应子文件夹。

### 3.1 目录与分类
- 搜索和回溯/图论算法：按主题建立子目录（如 拓扑排序、图的性质、可达性、连通性、最短路、路径枚举 等）。
- 其他学科模块：按项目既有目录归档（如 栈专题、字符串专题、动态规划专题 等）。

### 3.2 标准导航区块（必须）
- 在问题文档与题解文档顶部插入统一的“相关文档导航”区块，使用相对路径，确保双向与交叉引用完整。
- 建议包含：
  - 同主题的题解文档（DFS三色法 / Kahn算法 等）
  - 概念说明文档（邻接表、入度/出度、作用与边界等）
  - 记忆卡片或误区清单（如“易错点 Checklist”）

示例（以课程表为例，路径均为相对路径）：
- 搜索和回溯/图论算法/拓扑排序/题解2.0.0-课程表-DFS三色法.md
- 搜索和回溯/图论算法/拓扑排序/题解2.0.0-课程表-Kahn算法.md
- 搜索和回溯/图论算法/拓扑排序/问题1.0.0-课程表-邻接表是什么.md
- 搜索和回溯/图论算法/图的性质/问题1.0.0-入度与出度是什么.md
- 搜索和回溯/图论算法/图的性质/问题1.0.0-入度与出度的作用.md

## 4. 内容结构模板
### 4.1 问题文档模板（`问题1.0.0-<主题>.md`）
- 问题概述（一句话定位 + 背景）
- 题目特征与约束（可用数据规模、图的类型、边的方向等）
- 思路引导（从直觉到方法选择的路径）
- 涉及的知识点拆解（概念定义：如邻接表、入度/出度、拓扑序）
- 常见误区与边界条件（如方向约定、状态标记、队列/递归栈处理）
- 复杂度直觉（为何选择某种结构或算法）
- 练习建议（变体与扩展题目）
- 相关文档导航（标准区块）

### 4.2 题解文档模板（`题解2.0.0-<主题>.md`）
- 题解概述（算法选择理由与适配场景）
- 步骤/模板（可含伪代码，强调关键状态与数据结构）
- 正确性要点（不变式/证明思路）
- 时间与空间复杂度分析（含结构选择的影响）
- 易错点 Checklist（如 DFS 出口状态、Kahn 入度维护）
- 与相关概念/问题文档的链接（标准区块）

## 5. 命名与链接规范
- 文件命名：严格遵守 `问题1.0.0-` 与 `题解2.0.0-` 前缀规则，主题尽量简洁明确。
- 链接路径：使用相对路径；确保目标文件存在；避免硬编码绝对路径。
- 目录分类：优先放置到对应子目录，避免堆积在根目录。

## 6. 版本管理规范
- 初始版本：问题文档以 `1.0.0`，题解文档以 `2.0.0`。
- 补丁版本（x.x.P）：文字润色、链接修复、轻微增补。
- 次版本（x.M.0）：结构调整、新增重要章节、加入新的对比/示例。
- 主版本（X.0.0）：思路重构、方法替换、代码实现大改。

## 7. 写作风格与质量要求
- 先直觉后形式化：给出简短例子与图示（如有），再做定义与复杂度分析。
- 术语统一：如“邻接表”“入度/出度”“拓扑排序”“DFS三色法”等。
- 图论场景：统一方向约定；明确邻接表构造与入度/出度的计算。
- 记忆卡片：为常用算法（如 DFS 三色法、Kahn）提供“快速记忆步骤”。

## 8. 代码与安全规范（如涉及代码改动）
- 遵循项目既有代码风格与库选择，优先编辑现有文件，避免冗余文件。
- 不引入或暴露任何敏感信息；不提交二进制或超长 hash；图片使用 SVG。
- 变更最少步完成；确保可运行；补充必要的依赖声明（如需）。

## 9. 执行流程清单（Checklist）
- 判断是否为算法类请求。
- 算法类：同时产出/更新“问题文档”和“题解文档”。
- 放置到正确目录与子目录（搜索与回溯及其子目录）。
- 在两类文档顶部加入“相关文档导航”标准区块。
- 检查命名与链接一致性，路径使用相对路径。
- 明确复杂度与易错点；图论题需强调邻接表与入度/出度处理。
- 提供记忆卡片或复盘要点，提升可记忆性与复用性。

## 11. 维护与迭代
- 新增相关文档后，及时在既有题解/问题文档中更新导航区块，保持链接完整。
- 定期复盘规范并根据新增主题扩展子目录分类与导航内容。
