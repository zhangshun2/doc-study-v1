# 题解2.0.7-引用传递的真相大白

## 🎯 你的困惑完全合理！

你说得对！这确实是**引用传递**，`当前邀请名单`确实会被改变！

但是关键在于：**每一层递归结束时都会做remove，所以值又变回来了！**

## 🔍 真相大白：一步步追踪

### 场景：friends = [小明, 小红]

```java
// 第0层开始
当前邀请名单 = []  // 初始状态

// 第0层：i=0，考虑小明
当前邀请名单.add(小明);  // 现在 = [小明]
```

**现在到了关键时刻：**

```java
// 调用递归
发邀请函(friends, 1, [小明], 所有可能的邀请方案);
```

## 🎮 递归内部发生了什么？

### 第1层执行过程：

```java
// 第1层开始：当前邀请名单 = [小明]  ← 确实是引用传递！

// 第1层：i=1，考虑小红
当前邀请名单.add(小红);  // 现在 = [小明, 小红]  ← 值确实变了！

// 继续递归
发邀请函(friends, 2, [小明, 小红], 所有可能的邀请方案);
    // 第2层：没有更多朋友，直接收集结果后返回
    // 第2层结束：当前邀请名单 = [小明, 小红]  ← 第2层没有改变

// 🎯 关键来了！第1层的remove：
当前邀请名单.remove(当前邀请名单.size() - 1);  // remove小红
// 现在 = [小明]  ← 恢复到第1层开始时的状态！

// 第1层结束，返回给第0层
```

## 💡 关键洞察：递归返回时的状态

```java
// 第0层继续执行：
发邀请函(friends, 1, [小明], 所有可能的邀请方案);  // 这行执行完毕

// 🎯 执行完毕后，当前邀请名单 = [小明]  ← 跟调用前一样！
// 为什么？因为第1层的remove把小红撤销了！

// 第0层的remove：
当前邀请名单.remove(当前邀请名单.size() - 1);  // remove小明
// 现在 = []  ← 恢复到第0层开始时的状态
```

```java
void 发邀请函(朋友列表 friends, int start, 当前邀请名单 inviteList, 所有可能的邀请方案 allPlans) {
    System.out.println("进入第" + start + "层，当前邀请名单=" + inviteList);
    
    allPlans.add(new ArrayList<>(inviteList));
    
    for (int i = start; i < friends.length; i++) {
        System.out.println("第" + start + "层：准备邀请 " + friends[i]);
        inviteList.add(friends[i]);
        System.out.println("第" + start + "层：邀请后，当前邀请名单=" + inviteList);
        
        System.out.println("第" + start + "层：调用第" + (i+1) + "层");
        发邀请函(friends, i + 1, inviteList, allPlans);
        System.out.println("第" + start + "层：第" + (i+1) + "层返回，当前邀请名单=" + inviteList);
        
        inviteList.remove(inviteList.size() - 1);
        System.out.println("第" + start + "层：撤销邀请后，当前邀请名单=" + inviteList);
    }
    
    System.out.println("第" + start + "层结束");
}
```

> **"还是说因为里面每一层都做了.remove，所以在当前这层`当前邀请名单`就跟进入发邀请函的方法之前的值一致?"**

**没错！就是这样！**

## 🧠 核心原理：引用传递 + 层级恢复

### 1. **确实是引用传递**
```java
发邀请函(friends, i + 1, 当前邀请名单, 所有可能的邀请方案);
// 传递的是同一个list对象的引用
```

### 2. **递归内部确实会改变值**
```java
// 在递归内部
当前邀请名单.add(某个朋友);  // 值确实变了！
```

### 3. **但每层结束时都会恢复**
```java
// 每层结束前
当前邀请名单.remove(当前邀请名单.size() - 1);  // 恢复到该层开始时的状态
```

### 4. **所以递归返回时，值跟调用前一样**
```java
// 调用前
当前邀请名单 = [小明]

// 调用递归（内部可能变成[小明,小红]，但最后会恢复）
发邀请函(friends, i + 1, 当前邀请名单, 所有可能的邀请方案);

// 调用后
当前邀请名单 = [小明]  // 跟调用前一样！
```

## 🎮 类比：借钱还钱

```java
我的钱包 = [100元]

// 借给小明
我的钱包.借出(50元);  // 现在 = [50元]

// 小明去花钱（递归调用）
小明花钱();  // 小明内部可能各种花钱，但最后会还钱

// 小明还钱
我的钱包.收回(50元);  // 现在 = [100元]  ← 跟借出前一样！
```

## 💡 为什么这样设计？

### 1. **状态隔离**
每层递归都能在"干净的状态"下工作

### 2. **正确回溯**
保证每次尝试都是独立的，不会互相影响

### 3. **内存效率**
不需要每层都创建新的list，节省内存

## 🎯 最终理解

**你的困惑是对的！**

- ✅ 确实是引用传递
- ✅ 递归内部确实会改变值  
- ✅ 但每层的remove会恢复状态
- ✅ 所以递归返回时，值跟调用前一致

**这就是递归回溯的精妙之处：用引用传递的效率，实现值传递的效果！**
