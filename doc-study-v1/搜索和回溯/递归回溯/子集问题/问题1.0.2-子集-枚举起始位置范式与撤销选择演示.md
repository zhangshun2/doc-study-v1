# 问题1.0.2-子集-枚举起始位置范式与“撤销选择”演示

## 问题描述
你在《问题1.0.0-子集.md》中看到“方法2：递归回溯（枚举起始位置）”（第 65-76 行），其中包含：
- `for i in range(start, len(nums))` 从起始位置开始枚举后续元素；
- `path.append(nums[i])` 表示选择当前元素；
- `递归函数(path, i + 1)` 递归处理后续元素；
- `path.pop()`“撤销选择”。

你疑惑的是：该范式到底在描述什么过程？“撤掉（pop）”具体表示什么？

## 引导思路
- 范式（枚举起始位置）是在描述一棵“决策树”的 DFS 过程：每层都从当前 `start` 开始，尝试把一个新元素加入到路径 `path`，并在更深层继续尝试后续元素（`i+1`）。
- “撤销选择（pop）”是回溯的核心动作：回退到上一个决策点，从而探索同层中的“下一个选择”。如果不撤销，上一条路径的选择会污染下一条路径。
- 每个递归入口都“收集当前子集”（即把当前 `path` 记录进结果集），因此每一个节点都代表一个有效子集。

## 核心范式说明（枚举起始位置）
- 输入数组 `nums`，递归函数 `dfs(path, start)`：
  - 收集 `path` 到结果集（每个节点都是一个子集）。
  - 从 `i = start` 到 `len(nums)-1` 遍历：
    - 选择：把 `nums[i]` 加入 `path`。
    - 递归：以新的起始位置 `i + 1` 继续，只考虑后面的元素（避免重复/倒退）。
    - 撤销选择：把刚加入的元素弹出，回到选择前的状态，以便尝试同一层的“下一个 i”。

这保证了：
- 元素只向“后”选择，避免同一元素被重复选择或产生顺序重复的子集。
- 通过“选择→递归→撤销”的节奏，完整探索每个分支但保持状态干净。

## “撤销选择（pop）”到底在做什么？
- 它把上一轮“选择”的元素移除，恢复到进入该轮选择之前的 `path` 状态。
- 它体现的是 DFS 的“回溯”：递归返回后，回到父节点，继续尝试兄弟分支。
- 如果省略 `pop`，`path` 会不断增长且无法回退，下一条分支会在“错误的前缀”基础上展开，结果会重复或错误。

## 演示（nums = [1, 2, 3]）
初始：`path = []`，`start = 0`
- 收集：`[]`
- 循环 i=0：选择 `1` → `path = [1]`，递归 `start = 1`
  - 收集：`[1]`
  - 循环 i=1：选择 `2` → `path = [1,2]`，递归 `start = 2`
    - 收集：`[1,2]`
    - 循环 i=2：选择 `3` → `path = [1,2,3]`，递归 `start = 3`
      - 收集：`[1,2,3]`，返回
    - 撤销选择：`pop()` → `path = [1,2]`（回到“刚选了 2”的状态）
  - 循环 i=2：选择 `3` → `path = [1,3]`，递归 `start = 3`
    - 收集：`[1,3]`，返回
  - 撤销选择：`pop()` → `path = [1]`
- 撤销选择：`pop()` → `path = []`
- 循环 i=1：选择 `2` → `path = [2]`，递归 `start = 2`
  - 收集：`[2]`
  - 循环 i=2：选择 `3` → `path = [2,3]`，递归 `start = 3`
    - 收集：`[2,3]`，返回
  - 撤销选择：`pop()` → `path = [2]`
- 撤销选择：`pop()` → `path = []`
- 循环 i=2：选择 `3` → `path = [3]`，递归 `start = 3`
  - 收集：`[3]`，返回
- 撤销选择：`pop()` → `path = []`

最终结果（收集顺序与实现有关）：
```
[]
[1]
[1,2]
[1,2,3]
[1,3]
[2]
[2,3]
[3]
```

这个过程清楚地展示了“选择 → 递归 → 撤销选择”的节奏，以及 `start` 如何保证只向后选择，避免重复。

## 相关知识点
- 回溯（DFS）核心：决策树、路径变量 `path`、边界与收集、撤销选择。复杂度约 O(2^n)，递归深度 O(n)。
- 与“选择/不选择”写法的关系：两者都能生成所有子集，逻辑等价，范式不同；枚举起始位置更强调“向后选择”，常见于组合类问题。
- BFS（广度优先）对比：若用队列逐层扩展（按子集长度层序），那才是 BFS；本范式不使用队列，属于 DFS。
