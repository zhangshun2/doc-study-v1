# 问题1.0.3-子集-更直观范式解释（枚举起始位置 + 撤销选择）

## 背景与困惑
在“方法2：递归回溯（枚举起始位置）”中，范式常见为：
- 从起始位置 `start` 枚举后续元素（for i in range(start, n)）
- 选择当前元素加入路径 `path.append(nums[i])`
- 递归到下一层 `dfs(path, i + 1)`（只向后选择）
- 撤销选择 `path.pop()`（回到选择前的状态）
你困惑的是：“撤销选择到底在做什么？这个范式如何更直观地理解？”

## 一句话直观理解
把 `path` 看作“临时组合篮”，每一层把一个新元素放进篮子里往下走；走完这条路就把这个元素拿出来（撤销选择），好让同一层尝试下一个元素。`start` 是篮子下一次挑选时“从后面继续挑”的位置，避免重复与倒退。

## 类比（试衣间/购物篮）
- 选衣服：把第 i 件衣服（nums[i]）放进篮子（path），进试衣间（递归）。
- 试完：把第 i 件衣服拿出来（pop），回到货架前，挑下一件 i+1。
- 只向后挑：`start` 保证不往前回挑，避免同一衣服被重复挑，组合不重复。
- 每次进试衣间的当前搭配（path）都拍一张照（收集子集）。

## 决策树图示（nums = [1, 2, 3]）
```
[]                      ← 收集空集
├─ 选择1 → [1]          ← 收集 [1]
│  ├─ 选择2 → [1,2]     ← 收集 [1,2]
│  │  └─ 选择3 → [1,2,3]← 收集 [1,2,3]，返回后撤销选择3 → [1,2]
│  └─ 选择3 → [1,3]     ← 收集 [1,3]，返回后撤销选择3 → [1]
│                返回后撤销选择2 → [1]
└─ 选择2 → [2]          ← 收集 [2]
   └─ 选择3 → [2,3]     ← 收集 [2,3]，返回后撤销选择3 → [2]
               返回后撤销选择2 → []
└─ 选择3 → [3]          ← 收集 [3]，返回后撤销选择3 → []
```

这个树清楚展示了：
- 每次“选择→递归→撤销选择”，路径回到选择之前的状态；
- `start` 使得下一层只从当前位置之后继续枚举（向后选择），因此不会出现 [2,1] 这类倒序组合，也不会重复同一元素；
- 每个节点（每次进入递归）都代表一个要收集的子集。

## 撤销选择（pop）到底在描述什么过程？
- 动作：把刚加入的元素移除，恢复到进入该层选择前的 `path` 状态。
- 目的：回到父节点，继续尝试兄弟分支（同一层的下一个 i）。如果不 pop，路径会一直累加，下一条分支会携带错误前缀，导致结果重复或错误。
- 本质：DFS 的“回溯”步骤，保持状态干净，从而穷举所有分支。

## 精简演示（nums = [1, 2]）
- 初始：`path=[]`, `start=0` → 收集 `[]`
- i=0：选 1 → `path=[1]`，递归 `start=1` → 收集 `[1]`
  - i=1：选 2 → `path=[1,2]`，递归 `start=2` → 收集 `[1,2]` → 返回后 pop → `path=[1]`
  - 结束循环 → 返回后 pop → `path=[]`
- i=1：选 2 → `path=[2]`，递归 `start=2` → 收集 `[2]` → 返回后 pop → `path=[]`
- 结束：结果为 `[], [1], [1,2], [2]`

## 与“选择/不选择”范式的关系
- 两者目标一致：都生成所有子集。
- 差异：
  - “选择/不选择”沿着每个元素两叉（选/不选）深入；
  - “枚举起始位置”更强调组合的有序性（只向后选），常用于组合问题（避免重复）。

## 可能涉及的知识点
- 回溯（DFS）：决策树、路径变量 `path`、状态恢复（pop）、边界与收集。
- 去重原理：通过 `start` 只向后选择，避免顺序重复和元素重复使用。
- 复杂度：总子集数量为 2^n，递归深度 O(n)。

## 小结
“撤销选择”是保证每条分支独立、状态干净的关键；`start` 则保证组合只向后构造、无重复。把它们理解为“试衣间挑搭配、试完放回”的过程，会非常直观。
