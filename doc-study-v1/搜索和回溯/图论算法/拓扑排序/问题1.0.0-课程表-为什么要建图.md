# 问题1.0.0-课程表：为什么要建图？

问题概述
- 在课程表（LeetCode 207）问题中，为什么需要“把先修关系建成图（邻接表/入度表）”？是否可以直接在 prerequisites 数组上做 DFS/判环？

题目特征获取
- 关系本质：每条先修关系 [a, b] 是一条有向边 b → a（先修 b 指向后续 a）。
- 问题本质：判断是否存在环与是否存在拓扑序（能否完成所有课程）。
- 算法需求：快速枚举某个课程的所有后继课程；对整张图做遍历/判环，覆盖不连通的情况。

引导思路
- 为什么建图：
  1) 语义清晰：把“课程→后继课程”的关系结构化为邻接表；DFS/Kahn 的核心操作是“从当前课程走向后继”，没有邻接表就无法高效枚举后继。
  2) 复杂度优化：若不建图，每次在递归或 BFS 中都要遍历整个 prerequisites 数组来筛选后继，单次为 O(E)，整体会退化到 O(V·E)；建邻接表一次性预处理为 O(V+E)，之后枚举后继为 O(出度)。
  3) 边覆盖完整：图不一定连通，建图时为每个课程初始化桶位（即使没有边），保证遍历能覆盖所有课程。
  4) 方向与一致性：将 [a,b] 固化为 b→a 的统一方向，避免在不同操作中反复“想象和转换”，减少出错。
  5) 支持多范式：Kahn 需要入度；DFS 需要后继列表；建图能同时满足这两种范式的输入需求。
- 不建图会遇到的问题：
  - 每次找后继都要线性扫描 prerequisites，导致嵌套循环的高时间成本。
  - 容易遗漏无边课程或处理方向错误，出现错误判环或遗漏遍历。

涉及知识点
- 邻接表与入度数组的作用与区别。
- 有向图判环（回边）与拓扑排序（无环 ⇔ 存在拓扑序）。
- 复杂度从 O(V·E) 优化到 O(V+E) 的预处理思想。

边界与注意事项
- prerequisites 为空：仍需为每个课程建空桶（无后继），遍历更顺畅。
- 自环 [a,a]：建图后直接在遍历中触发回边判环。
- 重复边：入度会累加；一般不影响正确性。
- 离散课程：没有出入边的节点也要建桶以便被遍历到。

结论
- “建图”是把输入转换为算法可直接操作的数据结构，是解决课程表问题的基础步骤：语义更清晰、复杂度更优、实现更可靠。
