# 问题1.0.0-邻接表是否类似链表性质用于快速解决图问题？

问题概述
- 邻接表在图算法中非常常见。很多实现使用 List<List<Integer>> 的结构来保存每个节点的“后继列表”。邻接表是不是就是为了利用“链表”的性质来在图中快速解决问题？

题目特征获取
- 输入关系本质：图的边集（如课程表中的先修 [a,b] ⇒ b→a）。
- 核心操作：从节点 u 快速枚举所有后继 v；对整张图进行遍历（DFS/BFS/Kahn）和判环；图可能不连通。
- 性能关键：邻接表要支持“高效添加边”和“高效迭代后继”，一般不强调随机访问或频繁删除。

引导思路（如何思考这个问题）
1) 邻接表是“图的表示方法”，不是特定容器类型：
   - 邻接表的概念是“每个节点维护一个后继集合”，它可以用动态数组（ArrayList）、链表（LinkedList）、集合（HashSet/TreeSet）等不同容器实现。
   - 选择哪种容器，取决于你的算法对“添加边、迭代、查重/去重、删除”的要求。
2) 为什么常见实现更偏向 ArrayList：
   - 图算法（DFS/Kahn）主要是“追加边”和“迭代后继”，ArrayList 迭代快、内存局部性好、开销低；LinkedList 节点分散、迭代指针跳转多、开销大。
   - 需要查重时才考虑 Set；需要频繁删除才考虑 LinkedList 或索引结构，但课程表这类问题基本不需要删除边。
3) 邻接表的价值不在“链表性质”，而在“结构化组织边”：
   - 它把“从 u 找后继 v”的操作降为 O(出度)；不建图则每次要在整份边集中线性筛选，复杂度退化到 O(V·E)。

可能涉及的知识点（分类说明）
- 图的两种经典表示：邻接矩阵 vs 邻接表（复杂度与空间对比）。
- 不同容器在邻接表中的取舍：ArrayList、LinkedList、HashSet/TreeSet。
- 遍历与判环（DFS 三色法、Kahn 拓扑）对邻接表的操作模式。

思考题（进一步理解）
- 若边需要去重或快速存在性判断（如不允许平行边），是否选择 Set 更合适？
- 若需要频繁删除边或按权值排序后继，容器选择是否改变？
- 稠密图时邻接矩阵是否更优？
