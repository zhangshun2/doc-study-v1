# 问题1.0.0-课程表：邻接表是什么（为什么用它表示先修关系）

问题概述
- 在课程表（LeetCode 207）中，代码 often 使用邻接表（List<List<Integer>>）来表示课程之间的“先修→后继”关系。到底什么是邻接表？为何在本题中要用它？

概念与定义（直观理解）
- 邻接表是“图”的一种常用数据结构表示方法：
  - 对于每个节点 u，都维护一个“后继列表” adj[u]，保存所有能从 u 直接到达的节点 v。
  - 在课程表中，先修关系 [a, b] 表示 b → a（学 a 前先学 b），因此把 a 加入 b 的后继列表中：adj[b].add(a)。

结构形式（本题中的类型）
- Java 常用表示：List<List<Integer>> adj
  - adj.size() == numCourses，索引 0..numCourses-1 对应课程编号。
  - adj.get(u) 返回课程 u 的所有后继课程集合。
- 示例：numCourses=4, prerequisites=[[1,0],[2,0],[3,1]]
  - 0 的后继是 [1,2]（因为 0→1 与 0→2）
  - 1 的后继是 [3]
  - 2 的后继是 []
  - 3 的后继是 []

为什么在代码 L16-22 建邻接表（对应你的 MD 内容片段）
- 目的：把原始的先修数组 prerequisites（边集）转换为“从课程 u 快速枚举其后继 v”的结构。
- 代码逻辑：
  - 初始化桶位：for (i=0..numCourses-1) adj.add(new ArrayList<>())，让每个课程都有一个列表（即使后继为空）。
  - 遍历每条关系 [a,b]：int a=p[0], b=p[1]; 然后 adj.get(b).add(a); 完成 b→a 的边加入。
- 作用：
  - DFS 三色法需要“从 u 枚举所有后继 v”来判回边；
  - Kahn 拓扑也需要后继来降低入度；
  - 邻接表能让这一步变得 O(出度) 高效，而不是每次都在 prerequisites 中线性过滤。

与邻接矩阵的对比（为什么选邻接表）
- 邻接矩阵（二维布尔/整型矩阵）能 O(1) 查询边，但空间是 O(V^2)，在课程数量较多时浪费严重；
- 邻接表空间是 O(V+E)，对于大多数“稀疏图”更高效；枚举后继只需遍历列表，不必扫描所有节点。

复杂度收益（预处理思想）
- 建图一次性 O(V+E)，之后每次枚举后继仅 O(出度)。
- 若不建图、每次在 prerequisites 中筛选后继，会退化到整体 O(V·E)。

注意事项（避免踩坑）
- 方向统一：本题固定使用 b→a（b 是 a 的先修）。
- 全覆盖：即使课程没有出边，也要为其创建空列表，保证遍历覆盖所有课程。
- 重复边：可能导致列表中重复项，一般不影响正确性（Kahn 入度会相应累加）。
- 自环 [a,a]：建图后在遍历中会自然触发回边判环。

结论
- 邻接表是把“先修关系”转换成“可直接枚举后继”的图结构，是课程表问题中 DFS/Kahn 两种范式的共同基础：语义清晰、复杂度更优、实现更可靠。
