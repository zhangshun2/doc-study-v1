# 问题1.0.0-入度与出度是什么：图中边的方向性度量与其作用

## 问题概述
在有向图中，我们经常提到“入度”和“出度”。它们是刻画节点与边之间关系的基本度量，直接影响到诸如拓扑排序（Kahn 算法）、有向无环图（DAG）判断、依赖关系分析等常见算法的实现与复杂度。

## 概念定义
- 有向图（Directed Graph）：边具有方向，记为 u → v。
  - 入度（in-degree）：指向该节点的边条数。即“有多少条边的终点是该节点”。
  - 出度（out-degree）：从该节点发出的边条数。即“有多少条边的起点是该节点”。
- 无向图（Undirected Graph）：边没有方向，节点的“度”是与该节点相连的边条数（每条边对两端节点都贡献 1）。

## 直观理解与示例（以“课程表”问题为例）
课程表（LeetCode 207）中，一条先修关系 [a, b] 表示：要修 a，必须先修 b；把它看作一条有向边 b → a。
- 节点 a 的入度 +1（因为有一条边指向 a）。
- 节点 b 的出度 +1（因为从 b 发出一条边到 a）。
示例：prerequisites = [[1,0],[2,0],[3,1],[3,2]] 对应边 0→1、0→2、1→3、2→3。
- 入度：in[1]=1、in[2]=1、in[3]=2、in[0]=0。
- 出度：out[0]=2、out[1]=1、out[2]=1、out[3]=0。

## 为什么重要（算法层面的意义）
- 拓扑排序（Kahn 算法）：用“入度为 0”的节点作为起点，这些节点没有任何前置依赖，可以先处理。处理后“删除”其出边并减少邻居的入度；若邻居入度变为 0，则继续入队，直到处理完所有可达节点。
- 有环性判断（基于 Kahn）：如果最终无法处理完所有节点（队列过程中没有覆盖全部节点），说明存在环（某些节点的入度始终无法归零）。
- 依赖分析：入度体现“需要依赖多少前置”；出度体现“影响多少后继”。在工程中的任务调度、编译依赖、数据流等场景都非常常见。

## 如何获取入度与出度（从边集或邻接表）
- 从边集（例如 prerequisites）直接统计：
  - 对每条边 u → v：in[v]++；out[u]++。
- 从邻接表统计：
  - 邻接表 graph[u] 存储所有后继 v。遍历所有 u：
    - 对每个 v ∈ graph[u]：in[v]++（出度可由 graph[u].size() 得到）。

## 与“课程表”题的关系与实践
- 建图时将 [a,b] 转为 b → a 的邻接表；同时可顺手统计 in[a]++。
- Kahn 算法从所有 in[i]==0 的节点入队；每弹出一个节点 u，就遍历其后继 v，执行 in[v]-- 并在归零时入队。
- DFS 三色法并不直接使用入度，但依赖“出边枚举”（邻接表）来进行深度优先遍历与环检测。

## 边界与注意事项
- 自环（self-loop）：若存在 u → u，则 in[u]++ 和 out[u]++，这必然是一个环。
- 重复边：若边集有重复（例如 [a,b] 出现多次），会导致入度被重复累计；如不希望计重，应在建图时用 Set 去重。
- 孤立节点：某些节点既无入边也无出边（in=0、out=0），在课程表中意味着“该课既不依赖别人也不被别人依赖”，但仍需在总数量内统计。
- 方向一致性：注意 [a,b] 的语义方向，课程表语义是“b 先于 a”，建边必须是 b → a。

## 思考与练习

- 修改示例：加入一条 [0,3]（即 3 → 0），观察入度变化与拓扑排序是否仍可完成（这里会形成环）。
- 比较“邻接表”与“直接在边集中线性搜索后继”的复杂度差异，理解为什么邻接表更适合图算法。
