# 状态栈分析框架 - 通用方法论
## 🎯 **核心思想**
状态栈处理方式是一种**通用的嵌套问题解决框架**，通过识别变量生命周期和状态转换机制，将复杂的嵌套递归问题转化为线性的栈操作。

## 📋 **四步分析法**
### **Step 1: 问题特征识别**
#### **嵌套结构识别**
```plain
✓ 括号匹配：(), [], {}, <>
✓ 标签嵌套：<div><span></span></div>

✓ 层级结构：文件夹、树形结构
✓ 递归定义：子问题与原问题结构相似
```

#### **状态依赖识别**
```plain
✓ 后续处理依赖前面的状态
✓ 需要"记住"之前的处理进度
✓ 存在"暂停-处理子问题-恢复"的模式
✓ 具有明确的进入/退出边界条件
```

### **Step 2: 中间变量识别与分类**
#### **变量分类体系**
```plain
🔄 实时工作变量
   - 持续更新，反映当前状态
   - 生命周期：整个处理过程
   - 例子：currentStr, num, currentSum

📚 状态保存变量  
   - 阶段性存储，跨层传递
   - 生命周期：从保存到恢复
   - 例子：numStack, strStack, stateStack

⚡ 临时计算变量
   - 短期使用，局部计算
   - 生命周期：单次计算周期
   - 例子：repeatTimes, prevStr, tempResult
```

### **Step 3: 生命周期分析**
#### **生命周期维度**
```plain
📍 诞生时机：什么时候创建/初始化
📍 活跃期间：什么时候被修改/使用  
📍 保存时机：什么时候需要暂存到栈
📍 恢复时机：什么时候需要从栈取回
📍 销毁时机：什么时候不再需要
```

#### **生命周期模式**
```plain
实时工作变量：
诞生 → 持续活跃 → 阶段性重置 → 最终输出

状态保存变量：
创建 → 保存状态 → 栈中等待 → 恢复使用 → 销毁

临时计算变量：
从栈提取 → 立即计算 → 传递结果 → 立即销毁
```

### **Step 4: 逻辑流程梳理**
#### **状态转换机制**
```plain
🔄 触发条件：什么情况下进行状态切换
   - 进入边界：遇到开始标记（如'['）
   - 退出边界：遇到结束标记（如']'）
   - 数据边界：遇到特定字符类型

🔄 保存动作：保存哪些状态到栈中
   - 当前工作变量的值
   - 当前处理的上下文信息
   - 需要在子层处理完后恢复的状态

🔄 处理逻辑：当前层如何处理
   - 重置工作变量
   - 开始新层的数据累积
   - 按照相同逻辑处理子层

🔄 恢复动作：如何从栈中恢复状态
   - 从栈中pop出保存的状态
   - 获取当前层的处理结果
   - 准备进行合并操作

🔄 合并逻辑：如何将结果合并到上层
   - 使用临时变量执行计算
   - 将结果更新到工作变量
   - 继续上层的处理流程
```

## 🛠️ **实际应用模板**
### **代码结构模板**
```java
public ReturnType solve(InputType input) {
    // 1. 状态保存变量（栈）
    Stack<StateType> stateStack = new Stack<>();
    
    // 2. 实时工作变量
    WorkType currentWork = initValue;
    
    // 3. 主处理循环
    for (Element element : input) {
        if (isEnterBoundary(element)) {
            // 保存当前状态
            stateStack.push(currentWork);
            // 重置工作变量
            currentWork = resetValue;
            
        } else if (isExitBoundary(element)) {
            // 4. 临时计算变量
            StateType prevState = stateStack.pop();
            // 合并逻辑
            currentWork = merge(prevState, currentWork);
            
        } else {
            // 累积当前层数据
            currentWork = update(currentWork, element);
        }
    }
    
    return currentWork;
}
```

### **关键设计原则**
```plain
1. 单一职责：每个变量只负责一种类型的状态
2. 生命周期清晰：明确每个变量的创建、使用、销毁时机
3. 状态隔离：不同层级的状态互不干扰
4. 自动回溯：利用栈的LIFO特性实现自然的层级回退
```
