# 单题长时段与保存点规则

这份规则不再把固定的 20、30 或 40 分钟当成学习目标。你可以连续投入较长时间，把一道题的完整因果链走完；保存点的作用是防止中断后丢失上下文，不是催你结束，也不是用“按时完成”制造新的打卡要求。

真正需要限制的不是总时长，而是没有新证据的原地循环。链条能继续变清楚时，可以继续；同一处反复尝试却无法说明缺失关系时，应该保存断点，去补那一个桥接。

## 一条完整链的八个确认点

| 确认点 | 本次必须回答 | 通过证据 |
| --- | --- | --- |
| 1. 对象与目标 | 输入里有哪些对象和关系，最后要返回什么？ | 能用自己的话复述，不先用方法名代替 |
| 2. 最小人工过程 | 人在一个最小例子上按什么顺序做事？ | 每一步都能指向具体对象和状态 |
| 3. 必须保存的信息 | 哪项信息会影响后面的决定，为什么不能丢？ | 能说出“如果不保存它，下一步就无法判断什么” |
| 4. 状态与更新 | 哪个事件改变哪项信息，更新顺序是什么？ | 小例子可以逐轮演算，查询、写入和删除顺序一致 |
| 5. 不变量与安全性 | 为什么当前选择不会漏解、重复或破坏已有结果？ | 有成立理由，也有边界检查 |
| 6. 结构与代码映射 | 需要哪些操作，为什么这个结构支持它们？ | Java 中每个关键标识符能映射回自然语言过程 |
| 7. 反例与失效边界 | 改哪个条件会让模型失效？ | 能给出最小反例并指出第一个断点 |
| 8. 闭卷重建 | 不看资料时能否重新生成过程、伪代码、代码和自测？ | 有真实独立作答证据，关键行能够解释 |

结论只能在链路完成之后出现。比如“用哈希表”“用单调栈”“套回溯模板”都不能代替前面七步。

## 长时段怎么用

状态允许且链路仍在推进时，可以连续完成多个确认点，直到这一轮链路闭合。中途不要求按固定分钟切题，也不要求为了“短时高效”把推导压缩成摘要。

开始前只做两个选择：

1. **完整链**：今天主要把一道题从题意走到独立代码。
2. **断点推进**：今天只处理其中一段，例如补齐“状态与更新”到“不变量”的桥接。

两者都不是半途而废。区别只是本次明确推进了哪一段，而不是用题号数量计算成果。

## 什么时候保存并停止

- 同一处连续尝试两次，仍没有新证据或新的可检验判断：停止原地重试，写下最早断点。
- 已经知道缺失的关系，但需要查讲解：只补那一段，不顺手扩展成多套解法。
- 编译错误完成两轮有目的的定位后仍无法解释：保存输入、报错、当前判断，下一次从该处开始。
- 题干理解不稳：只核对输入、输出、约束和术语，不基于猜测写完整代码。
- 情绪明显升高、身体不适或无法维持注意力：立即停止，不补偿、不在下一时段追题量。
- 链路已经闭合：记录真实证据后结束，不需要为了达到某个时长继续重复。

停止句只需要写清：

```text
已经确认到：第 ___ 段，证据是 ______
最早未确认的是：______
下一次第一件事：______
```

这不叫欠账，而是保留长时段工作的接续点。

## 记录字段

`题号｜本次模式（完整链/断点）｜确认到第几段｜参考使用位置｜最早断点｜下一次第一步｜实际耗时（可选）`

测试用例由你自己挑选并手算。课程不代替你做边界穷举；每次至少留下一个由你设计、能检查当前理解的输入。
