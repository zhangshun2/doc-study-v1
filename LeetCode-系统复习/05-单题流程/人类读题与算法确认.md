# 人类读题与算法确认

> 实际做题先打开 [[单题推导标准卡|单题推导标准卡]] 中的“小白现场七步”。本页解释为什么必须按“读题 -> 扩写题干 -> 对象、慢过程和第一次变化 -> 数据范围 -> 再捕捉变化 -> 确认算法方向 -> 完整思维链”走，以及一个新手在每一段会怎样自然卡住。八问只在做完后用来定位断点。

现场只展开最早那个无法继续的空缺：先找第一个不能变成具体动作的题面句子，再把它改写成“谁、何时、对谁、做什么”。这一步不需要先知道算法；它只需要把当前原句变成一个能用最小例子检查的动作。

## 先定义“人类视角”

这里说的人类视角，不是把专家答案改写成更长的文章，也不是让一个已经知道答案的人表演“我早就想到了”。

真实的人类现场通常是这样：

- 我只确定题面里的几件事。
- 我对“这题像什么”有猜测，但猜测可能错。
- 我能走一个很小的例子，却说不清哪里值得优化。
- 我会先想到一个熟悉方法，然后发现它和题目条件不完全匹配。
- 我需要先找到一个具体矛盾，才会改变原来的判断。
- 最后选择某个方向，是因为它解决了眼前这份重复工作，而不是因为它听起来高级。

因此，一份合格的讲解要能让读者看见判断怎样发生：

```text
我现在看到了什么
-> 我原来以为怎样
-> 哪一步让我发现不对
-> 我现在只改哪个判断
-> 下一步最小要问什么
```

错误候选和暂时不知道不是噪声。它们正是后来选择的依据。把中间犹豫删掉，只留下“显然可以用某结构”，会让复盘时无法判断自己到底在哪一步没想通。

## 为什么不能从方法名开始

“先理解题意，再选算法”这句话没有错，但对新手不够可执行。题面通常压缩了动作、条件和过程；如果直接跳到“这题用哈希”“这题用栈”，被跳过的正是：

```text
题目里的对象是什么
-> 人本来会怎样处理
-> 哪一份工作被重复
-> 哪批候选会失效
-> 需要保存什么
-> 哪种结构支持这些操作
```

方法名是最后给方向起的名字，不是推导的起点。一个名字可以提醒你“可能与此有关”，但它不能证明当前题目真的满足那个方向的条件。

项目采用七段连续判断：

```text
第一段 只读原题事实
第二段 逐句扩写题干 -> 合成可执行过程
第三段 对象 -> 直接人工过程 -> 第一次变化
第四段 数据范围 -> 操作预算 -> 功能候选
第五段 第二次变化 -> 重复查询、候选失效或子问题复用
第六段 比较候选 -> 确认算法方向
第七段 状态、更新、不变量、结构、代码、反例、闭卷重建
```

前六段负责从题面走到方向，第七段负责把方向变成可验证的实现。前六段不是六个必须打勾的任务，而是六个连续判断阶段。每次经过一段，你回答的问题应该比上一段更具体。

## 做完后的八个自然问题与七个阶段的对应

七个阶段不是七道作文题。实际现场先按七步走；走完以后，八个普通问题才用于定位最早断点。阶段只是把相邻问题放在同一个复核范围里。

| 自然问题 | 当前认知状态 | 所属阶段 | 回答后只得到什么 |
| --- | --- | --- | --- |
| 1. 我刚读完题，题目到底给了我什么，要我交回什么？ | 刚读完，脑中可能已经有方法名 | 阶段 1 | 有来源的输入、输出、保证、禁止和未知 |
| 2. 每个字都懂，可一个普通人在纸上第一步做什么？ | 每个字都认识，却无法动手 | 阶段 2 | 能按时间演完的扩写过程 |
| 3. 这个任务里有哪些对象，谁和谁有关系？ | 能演一个大概，但说不清具体卡在哪句，也没有能区分值、位置和身份的新证据 | 阶段 3 | 当前困惑、实际纸面动作、新增证据，以及题目世界里的对象和关系 |
| 4. 照着最笨的办法走一遍，哪一刻什么变了，答案什么时候定下来？ | 会走例子，但不知道重点 | 阶段 3 | 完整人工过程和第一次变化 |
| 5. 这个笨办法最坏会重复多少，数据范围先排除哪些方向？ | 看见变化，但不知道是否值得优化 | 阶段 4 | 操作预算和被排除的复杂度家族 |
| 6. 带着这个代价重看，哪份信息还会被再次问起，哪批候选会过期，哪个子问题会复用，哪条顺序不能乱？ | 知道可能慢，但不知道留下什么 | 阶段 5 | 重复、失效、复用或顺序证据，以及所需操作 |
| 7. 这些操作需要什么方向来承担，另一个方向为什么不够？ | 已经有几个模糊方向 | 阶段 6 | 候选比较和完整方向确认句 |
| 8. 方向已经定了，状态、更新顺序、不变量和代码怎样逐段对应？ | 方向已经确认 | 阶段 7 | 可验证的模型、代码、反例和闭卷重建 |

这八个问题不能当成八段固定独白。问题 3 和问题 4 都属于第三阶段，问题 8 才是第七阶段；有些题可以在一个连续现场里走完，有些题会停在某一个最早缺口。判断是否前进，只看当前问题是否真的由上一份证据产生。

## 下一问为什么只能这样长出来

本页解释原因，实际做题仍以 [[单题推导标准卡|单题推导标准卡]] 为执行入口。一个普通人不需要先具备算法直觉，只要在当前证据里找最早的空缺：

```text
读题后仍只会复述名词
-> 先问“谁对谁做了什么”，去逐句扩写

扩写后仍说不出人在纸上怎样行动
-> 先问“题目对象是什么，最小例子怎么走”，去人工演算

过程能演，但说不清为什么某个东西算独立对象
-> 先问“我具体卡在哪句，做什么纸面动作能多出一点证据”

做完动作并留下新增证据
-> 再问“有哪些对象，谁和谁有关系”，填写六列对象表

人工演算能走通，但不知道优化什么
-> 先问“哪一刻发生了变化，答案何时确定”，补齐第一次变化

看清变化，但不知道是否值得优化
-> 先问“最坏重复多少”，再读数据范围

知道可能慢，但不知道留下什么
-> 带着预算重看，问“哪份工作重复、哪批候选失效、哪个子问题复用”

知道需要什么操作，但不知道选哪个方向
-> 比较候选能否支持这些操作、代价是否允许、在哪个条件失效

方向已经确认
-> 才进入状态、更新、不变量、代码和反例
```

这条链最重要的不是顺序本身，而是每一问都能被上一问的缺口解释。不能回答“为什么现在要问这个”时，通常已经跳过了某段证据。

真正卡住时，不要只写“不会”。把空缺写成五句：

```text
我现在已经能确认：______
我现在还不能确定：______
这个空缺正在阻碍：______
因此下一个最小问题是：______
哪一种具体输入、例子、约束或手算结果能回答它：______
```

如果“这个空缺正在阻碍”写不出来，说明当前方向可能没有依据，只是被一个还不理解的方法名牵着走。

## 自然追问合同：小白凭什么问下一句

七个阶段不是把完整答案切成七块。每一段真正发生的动作，是先用手头已有的证据回答一个最小问题，再让新出现的空缺逼出下一句。每次换问都写成：

```text
这一步是小白的自然追问，因为：______
我刚得到：______
但这份证据只能说明：______
它还不能说明：______
因此现在只允许问：______
回答它至少需要：一条原句 / 一个最小例子 / 一次手算 / 一次预算 / 一项候选比较
回答后只允许新增：______
在回答之前禁止出现：______
```

这里最重要的不是“我刚得到”写得漂亮，而是前后两句有真实依赖。下一问如果换掉上一份证据也照样能问，它就不是由当前空缺产生，而是从后面的方法结论倒推出来。

### 现场生成与反写检查

每个结论只回答四件事：

```text
我刚得到：______
它只能说明：______
它还不能说明：______
因此现在只允许问：______
```

当前一问只能用一条原句、一个最小例子、一次手算、一次预算或一项候选比较回答。回答完成并留下证据后，下一问才允许出现；不能在同一段里从未知直接跳到最终方法名。写完后再做反写检查：隐藏最终方法名后，整条推导是否仍然成立；删掉当前证据后，下一问是否自然消失。如果证据没了，下一问还照常存在，说明它来自答案而不是现场。已知答案时先标“事后校验”。

## 现场因果链：上一份证据怎样逼出下一问

| 当前已有的证据 | 它只能说明 | 它还不能说明 | 因此下一句只问 | 回答后新增什么 |
| --- | --- | --- | --- | --- |
| 原题原句、示例和脑中记忆 | 题目提到了哪些对象，可能要求什么 | 哪个是输入、哪个是输出，哪些条件只是自己的假设 | 问题 1：题目给了我什么，要我交回什么？ | 有来源的事实、未知和真实初始理解 |
| 输入、输出、保证、禁止和未知 | 题目让交回什么，哪些内容没有保证 | 一个普通人按什么时间顺序执行 | 问题 2：普通人在纸上第一步做什么？ | 可执行的人话过程和每个条件的防错作用 |
| 可执行的人话过程 | 人大概怎样处理对象 | 具体卡在哪句，做什么纸面动作才能让值、位置或身份出现可核对的差别 | 进入问题 3 的现场：我此刻卡在哪个原句，做完什么纸面动作后新增了什么证据？ | 当前困惑、实际纸面动作和新增证据 |
| 当前困惑和新增证据 | 哪一句还没有读懂，哪个纸面动作让题目关系多出了一项证据 | 哪些东西是独立对象，谁和谁发生关系 | 问题 3：有哪些对象，谁和谁有关系？ | 题目对象、身份、位置、关系和结果 |
| 对象身份和关系 | 哪些东西是不同的对象 | 最直接的动作落在哪个对象上，答案何时确定 | 问题 4：最笨的办法怎样走，什么变了，答案何时定？ | 完整人工过程、第一次变化和答案产生时刻 |
| 第一次变化和答案产生时刻 | 哪个事件让一个对象从什么状态变成什么状态 | 这份慢过程在最大输入下是否值得处理 | 问题 5：最坏重复多少，范围排除哪些方向？ | 官方约束、操作预算、被排除的复杂度家族和功能候选 |
| 操作预算和功能候选 | 哪些复杂度家族不稳妥，哪些功能方向还值得看 | 未来会重复读取什么、哪批候选失效、需要什么操作 | 问题 6：带着代价重看，什么重复、过期、复用或不能乱序？ | 第二次变化的具体证据和操作需求 |
| 第二次变化和操作需求 | 过程真正需要哪些查询、插入、删除、取极值或恢复现场 | 哪个具体候选能承担这些要求，替代方向为何不够 | 问题 7：哪个方向承担这些操作，另一个为什么不够？ | 候选比较、代价、失效条件和完整方向确认句 |
| 完整方向确认句 | 从题目到算法方向已经有证据 | 变量表示什么、先更新谁、不变量为何成立、代码怎样对应 | 问题 8：状态、顺序、不变量和代码怎样逐段对应？ | 可验证的模型、代码、反例和闭卷重建 |

这条表里的“因此”必须能被上一列解释。比如对象还没有分清时，直接问“该保存值还是保存位置”，其实是在用第五段的结论替第三段作答；范围还没有预算时，直接比较复杂度，也是在用后面的语言填前面的空白。

每一步只接受一种最低证据：一条原句、一个最小例子、一次手算、一次预算或一项候选比较。证据类型不够时，不要用更长的解释补足。例如：

- 不知道普通人在纸上做什么，需要的是原句到动作的扩写，不是数据结构名。
- 说不清第一次变化，需要的是最小例子的逐步手算，不是“这里显然可以优化”。
- 说不清值不值得优化，需要的是最坏重复量，不是直接报一个复杂度目标。
- 说不清保存什么，需要的是未来读取和失效的证据，不是先选一个容器。
- 说不清为什么选它，需要的是候选比较，不是把方法名说得更确定。

这也是为什么第三阶段的现场顺序不能互换：先留下当前困惑、实际纸面动作和新增证据，问题 3 才有对象身份的来源；对象身份分清后，问题 4 才第一次产生按时间发生的状态变化。没有新增证据就填对象表，是在用后面的答案倒推对象；问题 4 没有完成，第四阶段就没有可以估算的慢过程。

## 现场记录应该是什么样

真正卡住时，使用上面的完整五句。五句不是每段都要填的表格；如果当前思路还在产生新的可核对内容，可以连续往前走。机械地在每个小标题下面复制断点，会把思考又变成审核。

每次换问时，至少能在脑子里还原三句：

```text
我刚刚已经确认：______
因此现在最早缺的是：______
我下一问只问：______
```

如果第三句无法由第二句解释，说明这一问并不是当前证据逼出来的。

## 第一段：只读原题事实

### 新手为什么会卡

刚看到题时，记忆通常比阅读更早出现。“这题是不是做过”“是不是要用某结构”“要不要先排序”都会冒出来。最危险的不是不会，而是把记忆、标签和脑补当成题目已经给出的条件。

因此这一段先做一件很朴素的事：

> 关掉题解、标签和讨论区，把题目原话看成一个陌生人交给我的任务。

### 现在只记录六类信息

| 项目 | 我要回答什么 |
| --- | --- |
| 输入 | 有哪些对象，每个对象代表什么，是否允许空、重复、负数或特殊值 |
| 输出 | 返回数量、值、下标、路径还是结构；顺序是否有要求 |
| 示例 | 输入怎样变成输出，示例没有覆盖什么 |
| 保证 | 是否保证答案存在、唯一、有序、连通或满足某种关系 |
| 禁止 | 不能重复使用、不能修改输入、不能改变顺序或不能使用某些操作吗 |
| 未知 | 哪些问题原题没有回答，现在不能自行补上 |

每条内容要能分清来源：

- **事实：** 原句直接写了。
- **推导：** 根据原句必然成立。
- **推测：** 目前没有证据，只是我觉得可能如此。

### 一个常见误判

题面只写“数组”，没有写“有序”。这时不能因为某个常见方法需要有序，就自行补上“数组已经排好”。

另一个常见误判是把“同一个元素不能用两次”缩写成“不能有重复值”。两句话完全不同：两个不同位置可以有相同值，并且各自都可以被使用。

### 什么时候可以往下走

当你能不依赖方法名复述输入、输出、保证、禁止和未知，并且能指出阅读时确实出现过的“看起来自然，但题目没有保证”的假设，就可以进入扩写。如果现场没有产生额外假设，就如实写“没有形成额外假设”，不能为了通过标准现编一个。

## 第二段：逐句扩写题干，再合成可执行过程

### 新手为什么会卡

原题为了简洁，会省略动作之间的连接。人会认识每个字，却不知道谁在什么时候对谁做了什么。这时需要的不是更抽象的解释，而是把压缩句子还原成能看见的时间过程。

### 先抓承载判断的句子，不要做字面翻译

不要读完一整段后直接写一个概括，也不需要把每句话都扩成一段故事。先按原句顺序找出会改变人的动作、顺序、限制或结果的信息，再问：

```text
这句话新增了哪个对象？
它规定了什么动作、顺序或停止条件？
如果我忽略它，会在过程中犯什么具体错误？
它有没有暗中禁止一个我本来想用的假设？
```

| 原句事实 | 在人的过程里意味着什么 | 如果不遵守会错在哪 |
| --- | --- | --- |
|  |  |  |

只展开承载因果的句子。例如“给定一个数组”只需要确认对象和边界；“必须返回原下标”会改变后面能保存什么；“只能向右看”会改变搜索方向；“第一个满足条件的位置”会改变停止时机。后三类信息必须展开，前一类事实通常记录一次就够。

逐句表只负责把事实翻译成动作。全部句子连起来以后，再写成一段完整的人话；顺序不能反过来，否则很容易先形成算法结论，再从结论里挑出支持它的题目信息。

### 用六个问题展开

1. 谁或什么在被处理？
2. 他手里已经有什么？
3. 下一步具体做什么动作？
4. 动作让哪个对象发生了改变？
5. 什么条件出现时停止？
6. 停止时题目要的是哪一个结果？

可以先用这个骨架：

> 我手里有 ______；我从 ______ 开始；我反复 ______；条件“______”意味着我不能 ______；当 ______ 时停止；题目最后要交出的不是 ______，而是 ______。

### 扩写的通过线

写到什么程度才继续，不取决于段落有多长，而取决于下面四件事是否同时成立：

1. 另一个人只看这段话，就能按动作顺序把例子走完。
2. 每个新增动作、限制或停止条件，都能指回原句，或者被明确标成“我的推测”。
3. 每个条件都能说出它防止的具体错误，而不是只把原句换个说法。
4. 扩写中还没有出现最终算法、数据结构或优化结论。

如果第 1 条不成立，说明动作之间还缺连接；如果第 2 条不成立，说明我在脑补题目；如果第 3 条不成立，说明条件只是被抄了一遍；如果第 4 条不成立，说明我已经用结论倒写过程。答案在哪一类事件之后成为确定结果，属于下一段走完最小例子后要观察的第一次变化，不能拿来倒推当前扩写。

### 条件要写出它防住什么

题目里的条件通常在阻止某种具体错误：

```text
条件原句：______
如果忽略它，我会错误地做：______
因此正确过程必须：______
```

例如“同一个元素不能使用两次”表示处理当前元素时，不能把当前这个位置同时当成两个位置。两个不同位置即使数值相同，仍然可以分别使用。

### 什么时候可以往下走

当另一个人只读你的扩写，就能在纸上按步骤执行，并且每条新增解释都能指回原句，就可以进入第三段。先找一个小白此刻真正卡住的句子，做一件能得到新证据的纸面动作；证据出现以后才允许填写对象表。扩写中不能提前出现最终结构，否则你是在用答案倒推题目过程。

## 第三段：当前困惑、新增证据、对象、人工过程和第一次变化

这一段内部不是“先想对象，再走过程”。真实顺序是：

```text
当前困惑
-> 实际纸面动作
-> 新增证据
-> 对象表
-> 人工过程
-> 第一次变化
```

### 1. 先留下当前困惑和实际纸面动作

小白通常不是一开始就知道“有哪些对象”。他先卡在某一句上，需要做一个动作才能把事实分开：

```text
我此刻具体卡在：______
我现在实际做的纸面动作：______
做完以后新增的证据：______
这份证据还不够，因为：______
```

动作可以是圈出返回要求、圈出身份条件、把两个相同值写到不同位置、画一个最小例子，或者补一行“谁拿着什么”。只有新增证据说明了“为什么它们不能合并/为什么它们有关系”，下一张对象表才有来源。

### 2. 证据出现后才列题目对象

代码容器不是题目对象。此时再列：

- 元素：数字、字符、节点、区间或状态。
- 身份：两个值相同但位置不同，是否是不同对象。
- 位置：下标、坐标、层数、时间或区间端点。
- 关系：先后、相邻、包含、依赖、可达或配对。
- 目标：要找、构造、判断、计数还是修改什么。
- 结果：数量、位置、路径、布尔值、区间还是整个结构。

对象身份往往直接决定后面能保存什么。题目要求返回原下标时，两个相同的值就不能被合并成一个无位置的对象。

### 3. 走最直接的人工过程

选一个足够小、却仍能走到停止并暴露关键关系的例子。不要问“标准算法是什么”，先问：

1. 我第一眼看哪个对象？
2. 看完以后，下一步把目光移到哪里？
3. 我在纸上要修改哪个值或记录哪件事？

例子太复杂时缩小一格；太简单、看不到关键关系时，再增加一个能触发关系的对象。

记录时一次只做一个动作：

```text
我现在看到什么
-> 我决定处理哪个对象
-> 我具体做了什么
-> 得到了什么中间结果
-> 下一步为什么从这里继续
```

先写可能很慢但正确的过程。即使最后会优化，也要先在例子中走通。否则你无法知道自己到底在优化哪一份工作。

### 4. 第一次变化只观察，不优化

对关键信息写：

```text
变化前：______
触发事件：______
变化后：______
答案产生时刻：______
```

至少检查：

- 当前处理对象是否移动。
- 可选候选是否增加、减少或失效。
- 历史信息是否累积。
- 临时结果是否更新或覆盖。
- 答案在哪一个事件后不再改变。

第一次变化只能回答“发生了什么”。如果这里出现“用栈维护等待项”“用映射保存历史”，说明结构结论提前混进了观察。

### 什么时候可以往下走

当你能换一个同类小例子，按同一过程重新走通，并指出答案在哪一刻成为确定结果，就可以读数据范围。此时你还不需要知道怎样优化。

## 第四段：读数据范围，估算操作预算，生成功能候选

### 新手为什么会卡

新手常见两种相反的错误：

- 完全不看范围，不知道慢过程是否还能承受。
- 把范围当成算法暗号，看到 `10^5` 就猜一个熟悉的 `O(n)` 方法。

范围真正能回答的是“预算是否足够”，不能单独回答“过程为什么需要某类操作”。

### 先读完整约束

不只读 `n`，还要看：

- 元素数量、节点数、边数、字符串长度或矩阵尺寸。
- 值域、正负、重复、是否稀疏。
- 是否有序、唯一、连通、保证答案存在。
- 输出是否要求原位置、原顺序或原地修改。
- 是否禁止某些操作。

### 再估算慢过程

```text
慢过程反复执行的动作：______
每轮大约重复多少次：______
最多有多少轮：______
合起来大约是：______
```

这一步估算的是学习推导，不是官方推荐复杂度。要明确分开：

| 信息 | 来源 | 用途 |
| --- | --- | --- |
| 官方约束 | 题面明确给出 | 判断允许的操作量级 |
| 操作预算 | 我根据人工过程估算 | 判断当前重复方式是否可能太贵 |
| 功能候选 | 由当前操作、预算和特殊保证产生 | 留给第二次变化和方向比较 |

范围缩成候选时，按四步走，不直接报方法名：

```text
1. 从人工过程里找出最常重复的动作
2. 估算这个动作最多大约发生多少次
3. 判断哪些复杂度家族首先不够用
4. 再把“仍允许的预算”与“过程真正需要的操作、题目特殊保证”合在一起，留下候选
```

例如，范围只说明“不能稳定接受平方级”，并不说明“必须查询历史”。只有人工过程同时出现了“未来会反复询问过去的信息”，历史查询类候选才有依据。

### 候选先描述“要做什么”

第四段可以先产生候选，但最好先写功能，不写最终结构名。例如：

- 继续检查所有位置对。
- 改变数值顺序，让比较后可以排除一批候选。
- 保留过去出现过的值和位置，供未来查询。
- 保留尚未结算的对象，等未来事件到来。
- 保存一个重复子问题的结果。

这些方向还不是答案。它们能进入候选池，是因为人工过程真的产生了相应操作或浪费。

### 数据范围不能直接点名方法

同一个 `10^5` 可能对应历史查询、区间维护、候选淘汰、图遍历或一次扫描。范围只能排除明显不够用的量级；候选还必须来自过程。

### 什么时候可以往下走

当你能分开写出官方约束、自己推导的操作预算和几个功能候选，并说明候选是从哪个实际动作产生的，就可以做第二次变化。

## 第五段：第二次变化，寻找可以省掉的工作

### 新手为什么会卡

此时已经知道慢过程可能太贵，也有几个方向，但仍不知道应该保存值、位置、次数、有效期还是顺序。原因通常不是不会某个结构，而是没有继续观察这份信息以后会怎样被使用和丢弃。

### 第二次变化只找四类现象

| 现象 | 新手要问的问题 | 要找到的证据 |
| --- | --- | --- |
| 重复查询 | 同一个问题是否在未来再次被问 | 哪份历史能回答它，未来需要值、位置还是次数 |
| 候选失效 | 哪个事件后，一批对象已经不可能产生答案或更优答案 | 失效条件是什么，哪些对象可以安全丢弃 |
| 子问题复用 | 不同路径是否到达同一个更小问题 | 状态由什么组成，重复出现的最小例子是什么 |
| 顺序约束 | 新对象应该从哪一端加入、从哪一端结算 | 为什么这个顺序不会漏掉候选 |

实际题目可能有其中一种，也可能同时存在。

### 把“需要保存”问到具体

对每一份想留下的信息，连续问：

```text
未来第 ______ 步会回来问：______？
为了回答它，我现在至少要留下：值 / 位置 / 次数 / 有效期 / 顺序？
当 ______ 发生后，这份信息可以消失？
当前写入会不会影响本轮后面的读取？
```

如果未来不会读取，就不保存。如果未来只问“出现过没有”，保存标记可能足够；如果还要返回原下标，就必须保留位置；如果候选会过期，还要说明过期事件。

### 把变化翻译成操作需求

先写普通语言：

```text
我需要快速插入当前对象
我需要查询以前是否出现过某个值
我还需要取回它的位置
当某个条件发生后，我需要删除一批旧对象
我需要在同一端连续加入和删除
我需要取当前最小或最大的候选
```

这些句子完成以后，才能问“哪种结构支持这些操作”。结构名不是观察结果，是下一步比较的对象。

### 小白怎样从一个结构名想到它的用途

- 反复按某个键查历史，才可能想到映射或计数结构。
- 只关心最近进入且尚未结算的对象，才可能想到一端加入、一端删除。
- 每次都要取最大或最小候选，才可能想到堆或有序结构。
- 连续区间只在一端加入、另一端删除，并且统计可增量维护，才可能想到窗口。
- 同一子问题从多条路径反复出现，才可能想到记忆化或动态规划。
- 每个事件能证明一批候选永远不再最优，才可能想到单调淘汰或指针移动。

如果结构名先出现，就追问一句：“它替我支持了哪项操作，消除了哪份重复工作？”答不上来，方向还没有从过程中长出来。

### 什么时候可以往下走

当你能用最小例子展示重复查询、候选失效或子问题复用真实发生，并写出为了消除它需要支持的操作，就可以比较候选。

## 第六段：比较候选并确认算法方向

现在才允许具体方法名进入正式比较。原因是前面的操作需求已经足够具体，方法名终于有了可核对的对象。

### 新手为什么会卡

候选池里可能有两三个熟悉名字。新手容易选择最熟的那个，而不是最贴合当前操作的那个。确认方向不是证明某个方法“高级”，而是说明它为什么在当前约束下替代了最贵的那份重复工作。

### 每个真实候选回答四项

| 候选 | 消除哪份重复工作 | 需要哪些操作 | 代价或失效条件 |
| --- | --- | --- | --- |
| A |  |  |  |
| 候选 B（仅在存在真实替代方向时填写） |  |  |  |

检查：

1. 它是否真的消除了第二次变化指出的重复动作？
2. 它能否支持当前过程需要的查询、插入、删除、取极值或回溯？
3. 它依赖哪些题目保证？
4. 它在最大约束下大约需要多少时间和空间？
5. 换一个条件后，它会在哪个例子中失效？

### 方向确认句

> 当前过程反复需要 ______；如果继续重新扫描，大约会做 ______ 次操作；因此算法必须支持 ______；候选 A 提供 ______，候选 B 在 ______ 条件下不适用或代价更高；所以当前选择 A，因为它与过程操作和约束同时匹配。

如果现场没有形成第二个真实候选，就把 `候选 B` 改成检查过的熟悉方向，说明它缺少哪项操作或为什么代价更高，不要编造没有认真考虑过的候选。句子里必须出现真实操作、代价和未选条件（或“本题没有形成真实歧义”的理由）。只有算法名不算确认。

### 比较不是贬低另一个方法

未选方案可能完全正确，只是当前题目多了一个限制，或另一个方案更直接。例如：

- 一个方向能找到值，但不能保留原下标。
- 一个方向能找到答案，但比当前需求多做了排序。
- 一个方向能工作，但需要额外恢复被修改的输入。
- 一个方向能处理任意值域，而本题值域很小，因此不是最简。

能说清“为什么当前不优先”，比简单说“它不好”可靠。

### 什么时候可以往下走

当方向确认句能同时包含重复劳动、所需操作、操作代价、未选方案限制和题目保证时，才进入第七段。完整 Java 还不能在这里出现。

## 第七段：方向确认后的推导链

这一段才讨论“怎样把已确认的方向写成可靠模型和代码”。

| 确认点 | 要回答什么 | 做完时能说什么 |
| --- | --- | --- |
| 状态定义 | 每个变量在题目世界里代表什么，覆盖哪段范围 | 不看代码也能说清状态和范围 |
| 初始、停止和答案时机 | 从哪里开始，何时停止，答案何时确定 | 最小例子中的每个初值都能对应现实含义 |
| 一次状态转移 | 当前事件读什么、算什么、写什么 | 能连续手算几轮并预测下一轮 |
| 更新顺序 | 哪两个动作交换后会产生错误 | 能给出交换顺序后的具体错误输入和结果 |
| 不变量与正确性 | 为什么不会漏、不会多、不会错误丢弃 | 能逐条指出证明依赖的条件 |
| 结构与操作 | 过程真正需要哪些操作，为什么结构匹配 | 能与更简单结构作具体比较 |
| 伪代码与 Java | 每段代码对应哪个对象、动作和状态 | 每个关键变量和顺序都能映射回过程 |
| 反例与闭卷重建 | 模型在哪种输入下最容易错，能否独立重来 | 能重走人类判断、模型、代码和自测 |

### 状态必须先于转移

变量名不是定义。一个合格定义至少包含：

> 它覆盖哪些对象；它记录什么事实；处理到哪一步时被读取；哪件事发生后它更新或失效。

### 更新顺序必须用反例证明

不要只背“先查后写”。要构造一个具体输入：

```text
如果先写后查，当前对象会被自己读到，于是得到 ______
题目实际要求 ______
因此必须先 ______，再 ______
```

交换顺序后指不出具体错误，说明顺序还没有真正理解。

### 不变量要防止一种明确错误

不变量要直接回答：

- 为什么不会漏掉某个答案？
- 为什么不会把同一个对象算两次？
- 为什么可以安全丢弃一批候选？
- 为什么当前状态足以支持下一步？

### 代码必须能逐段回到过程

每个关键代码段回答三件事：

1. 它回答了过程中的哪个问题？
2. 它读取或修改了哪个状态？
3. 为什么必须在这个时间、这个顺序执行？

如果一个循环只是为了模仿模板，却说不出它对应哪一项人类动作，就还不能称为掌握。

## 小白完整内心链的两个例子

### 两数之和

```text
我会固定一个数，再检查其他数
-> 每个位置都检查很多次，工作量接近平方级
-> 每个当前数都在问“另一个数是谁”
-> 另一个数可以写成 target - 当前值
-> 如果处理到答案的右边位置，左边位置已经出现过
-> 我需要查询补数及原位置，并写入当前值和位置
-> 比较历史表、排序后双指针和继续枚举
-> 历史表最贴合一次推进、查询补数和返回原位置
-> 先查后写，避免当前元素使用自己
```

### 每日温度

```text
我会让每一天向右找第一个更高温
-> 很多未来日期被不同起始日期重复查看
-> 某个较早日期在更高温到来前一直没有答案
-> 新温度可能同时结算多个更早的等待日期
-> 等待日期从旧到新的温度不会上升
-> 新温度从最近端连续结算，遇到不低于它的温度就停
-> 需要最近端加入、读取和删除
-> 才把栈作为匹配操作的结构
```

两个例子都不是“先认出标签”。它们先出现了具体操作，方法名最后才出现。

## AI 讲解时应该怎样要求它

如果让 AI 讲题，不要一开始要整篇答案。可以按顺序逐段要求：

1. “先只回答：题目给了我什么，要我交回什么？列原题事实、保证、禁止和未知，不出现算法名。”
2. “现在只回答：普通人第一步具体做什么？把题目扩写成谁拿着什么、重复做什么、何时停止；每条扩写指回原句。”
3. “只列题目对象、身份、关系和最终结果，不出现代码容器。”
4. “用一个最小完整例子，按时间顺序走最慢的人工过程；只写第一次变化，不优化。”
5. “读全部约束，单独估算慢过程操作量，再生成功能候选。”
6. “带着预算做第二次变化，判断是重复查询、候选失效、子问题复用还是顺序约束；先写所需操作，不报结构名。”
7. “比较候选，给出完整方向确认句、代价和失效条件。”
8. “方向确认后再讲状态、初始、停止、一次转移、更新顺序、不变量、结构、伪代码、Java、反例和闭卷重建。”

如果 AI 在前一步已经偷跑到下一步，可以只说：

> 你刚才的结论依赖了哪条尚未确认的事实或操作？请撤回那一步，从最早缺失的地方继续。

如果它反复用“显然”“本质上就是”“直接套模板”，就要求它给出：

- 当前对象。
- 当前事件。
- 哪一个值发生变化。
- 为什么下一步需要这项操作。
- 哪个最小反例能检查这个判断。

## 统一规则

### 关于方法名

- 前五段可以描述功能方向，但不把最终方法名当作结论。
- 第六段才比较具体方法名，并说明代价和失效条件。
- 第七段才按已确认方向写状态和代码。

### 关于候选

- 候选必须从人工过程需要的操作中长出来。
- 只有存在真实歧义时，才需要比较多个方向；如果没有，也要说明为什么熟悉但不适配的方向不优先。
- 候选表不是名字清单，每行都要有“消除什么、需要什么、代价是什么”。

### 关于两次变化

- 第一次变化：过程中实际发生了什么。
- 第二次变化：带着预算重看，哪里重复、什么会失效、什么可以复用。
- 两次变化不能合并成一句“优化暴力”。

### 关于数据范围

- 先估慢过程操作量，再判断哪些量级不够。
- 范围只排除复杂度家族，不直接证明某个方法正确。
- 题目特殊保证可以影响候选，但必须单独标明。

### 关于理解

- 能运行不是理解的充分证据。
- 能背方法名不是掌握。
- 能在新例子上重新生成过程、比较方向、证明顺序，才是稳定理解。
- 几天后可以忘记某个 Java API，但不能忘记题目对象、重复劳动、方向理由和更新顺序。

## 复习时怎样使用这套标准

复习不是把题解从第一行读到最后一行，也不是先看代码再倒推理由。一次有效的单题复习，闭卷先按七步回放现场，再用八个自然问题定位最早断点：

1. 我还能不能用原句分开输入、输出、保证、禁止和未知？
2. 我能不能用一个不同的小例子，把题目重新扩写成可执行过程？
3. 我能不能说清题目对象、值、位置和身份的关系？
4. 我能不能独立走完人工过程，指出第一次变化和答案产生时刻？
5. 我能不能根据约束重新估算慢过程，并说明它排除了什么？
6. 我能不能重新找到重复、失效、复用或顺序约束，并说出所需操作？
7. 我能不能比较候选，完整说出方向确认句？
8. 最后我能不能从方向重建状态、更新顺序、不变量、代码和自测？

卡住时不要立刻重读整篇题解。先记录：

```text
我目前能确认：______
最早断掉的判断：______
下一个最小问题：______
哪个具体观察会改变我现在的判断：______
```

然后只打开最早断点对应的那一小段。重复看完整答案会让“眼熟”冒充“能重建”，也会把真正缺失的因果桥掩埋掉。

复习可以发生在一次长时间、连续的推导里，不要求固定分钟数，也不以打卡、连续天数、欠账或完成数量衡量。状态允许时把整条链走完；需要中断时保存上面的断点，下一次从最早缺口继续，不补课，也不从头重刷。
