# 人类读题与算法确认

> 这里解释的不是“专家怎样写答案”，而是一个小白在纸上为什么会按这个顺序产生下一问。唯一执行标准在 [[单题推导标准卡|单题推导标准卡]]。

## 人类视角到底是什么意思

人类视角不是把术语换成口语，也不是把完整答案讲得更长。它要求每一步都保留：

- 我此刻手里已经有什么；
- 这份东西为什么还不能继续；
- 我现在真正会问的那一句话；
- 我准备在纸上做什么；
- 做完以后新增了什么证据；
- 这份证据只能说明什么、不能说明什么；
- 我答不出时回到哪里。

如果一段解释直接从题面跳到“因此用某个方法”，中间无论写得多流畅，都不是人类推导。

## 唯一现场：七阶段、九交接

```text
原题事实
-> 人话扩写
-> 对象
-> 最笨但正确的过程
-> 第一次变化与答案确定时刻
-> 数据范围与慢过程预算
-> 第二次变化
-> 候选比较与方向确认
-> 状态、更新顺序、不变量、代码、反例
```

外层七阶段：

```text
阶段 1：交接 1
阶段 2：交接 2
阶段 3：交接 3 -> 4 -> 5
阶段 4：交接 6
阶段 5：交接 7
阶段 6：交接 8
阶段 7：交接 9
```

这九次交接是不可交换的。尤其不能把“对象、慢过程、第一次变化”写成一句“分析题意”，也不能在数据范围之后跳过第二次变化直接报方法。

## 标准交接句

```text
我现在知道了：______
但它还解释不了：______
所以下一句只能问：______
```

例如：

```text
我现在知道了：每一天要向右找第一次严格更高温。
但它还解释不了：日期、温度和答案能不能当成同一个东西。
所以下一句只能问：这里面谁有独立身份，谁和谁绑定？
```

这三句不是文采要求，而是因果检查。上一份证据没有留下那个空缺，下一问就不应该提前出现。

## 九字段合同

```text
小白此刻真正的原话疑问：______
为什么这个疑问现在才出现：______
纸上实际做了什么：______
做完后新增了什么证据：______
这份证据只能说明什么：______
它还不能说明什么：______
因此下一问只能是什么：______
回答它需要什么证据：______
如果答不出，退回哪里：______
```

九项里最容易造假的是“真实原话疑问”。判断它是否真实，只有一个办法：前一份证据是否直接造成了这个疑问。不能因为模板要求，就补一句“我一开始以为”。

如果没有候选，写“没有形成候选”；如果没有发生转折，写“没有发生转折”。

## 为什么不能从方法名开始

方法名是答案侧标签。它至少跳过了五次交接：

1. 题目对象是什么；
2. 人最笨的执行过程是什么；
3. 哪个事件让答案确定；
4. 这份慢是否超预算；
5. 哪份信息被重复读取、何时失效、需要哪些操作。

知道方法名以后仍然可以学习，但必须标成“事后校验”。把方法名放进“记忆候选，不是题目事实”，然后从原题事实重建。

## 交接 1：只读原题事实

### 小白为什么会卡

每个字都认识，却不知道哪些字重要，因为还不知道要交回什么。

### 纸上先做什么

- 圈出返回要求；
- 分栏抄输入、输出、保证、禁止、示例和未知；
- 每条写来源；
- 方法记忆单独放在一边。

### 什么时候能继续

每项事实都能指回原句，且自己知道现在还不知道什么。

## 交接 2：扩写成可执行人话

### 小白为什么会卡

能复述题目，不等于知道谁先动、下一步做什么、什么时候停止。

### 纸上先做什么

把承载判断的句子逐句改成动作：

```text
谁拿着什么
-> 先看哪里
-> 重复做什么
-> 哪个条件让动作改变或停止
-> 最后写下什么
```

### 什么时候能继续

另一个人只读这段文字，就能在纸上按顺序演完。

## 交接 3：对象

### 小白为什么会卡

过程里出现了“值”“位置”“答案”这些词，但两个相同值到底算一个还是两个对象，还没有证据。

### 纸上先做什么

把两个相同的值写在两个不同位置，检查题目要求的输出是否依赖原位置。然后用六列对象表：

| 题目对象 | 值和状态 | 身份由什么决定 | 位置或时间 | 和谁发生关系 | 最终要得到什么 |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |

### 什么时候能继续

每个对象的身份、位置、关系和结果归属都有题目证据，且没有用代码容器代替题目对象。

## 交接 4：最笨但正确的过程

### 小白为什么会卡

对象已经分清，但没有真的按时间走过一遍。没有过程，就不知道哪里会重复，也不知道答案何时出现。

### 纸上先做什么

选一个最小但完整的例子，逐行写：

| 步骤 | 我现在看见什么 | 这一步处理谁 | 具体做什么 | 做完后什么变了 | 为什么还能继续 |
| --- | --- | --- | --- | --- | --- |
| 1 |  |  |  |  |  |

### 什么时候能继续

过程能完全复走，每一步都能说明为什么继续或停止。不能只写输入和输出。

## 交接 5：第一次变化

### 小白为什么会卡

过程走通了，但“答案在某一刻已经确定”和“后来又算出一个候选”仍然混在一起。

### 纸上先做什么

```text
变化前：______
触发事件：______
变化后：______
答案产生时刻：______
```

### 什么时候能继续

能说出哪个对象因为哪个事件，从什么状态变成什么状态。此时仍不能讨论保存什么或优化。

### 两个容易混淆的时刻

- 第一次算出一个候选，通常只改变当前最好值；
- 所有仍可能更好的候选都被排除，答案才确定。

只有题目保证唯一解，或已经证明淘汰规则，第一次命中才能等于答案确定。

## 交接 6：数据范围

### 小白为什么会卡

已经知道慢过程怎样走，但不知道它在最大输入上到底有多慢。

### 纸上先做什么

抄全约束，取最坏输入，数一轮核心动作，再乘轮数：

```text
一轮做什么：______
做多少次：______
最多多少轮：______
合起来：______
```

### 什么时候能继续

能说出慢过程的最坏预算，以及哪些复杂度家族不能稳定承受。

### 这个阶段绝对不能做什么

不能出现任何具体方法名或结构名。范围只能排除复杂度家族，不能从 `n` 直接跳到答案。

## 交接 7：第二次变化

### 小白为什么会卡

知道慢，不代表知道该保留什么。必须回到同一条过程，找出真正重复、会失效、会复用或必须保序的信息。

### 纸上先做什么

四类现象逐项标“发生”或“没有形成该现象”：

| 现象 | 是否发生 | 最小例子 | 未来读取、失效、复用或保序什么 | 操作动词 |
| --- | --- | --- | --- | --- |
| 重复查询 |  |  |  |  |
| 候选失效 |  |  |  |  |
| 子问题复用 |  |  |  |  |
| 顺序约束 |  |  |  |  |

### 什么时候能继续

每个发生现象都有最小例子，并能翻译成加入、查询、删除、取极值或恢复现场等操作。此时仍不能报容器。

## 交接 8：方向确认

### 小白为什么会卡

需要哪些操作已经知道，但不知道哪个候选真能承担，也不知道代价是否允许。

### 纸上先做什么

| 候选 | 支持哪些操作 | 缺少什么 | 何时失效 | 代价 |
| --- | --- | --- | --- | --- |
|  |  |  |  |  |

然后写完整因果句：

> 因为慢过程在 ______ 重复，预算是 ______；第二次变化需要 ______ 操作；候选 A ______，候选 B ______；所以当前方向选择 ______。

### 什么时候能继续

方向由操作长出来，支持、缺口、失效和代价都有证据。

## 交接 9：完整思维链

方向确认后，才按下面顺序进入：

```text
对象
-> 人工动作
-> 操作需求
-> 状态变量
-> 初始与转移
-> 更新顺序
-> 不变量
-> 结构
-> 伪代码
-> Java 代码位置
-> 反例
-> 闭卷重建
```

变量必须对应题目对象，转移必须对应人工动作。更新顺序必须用反例证明，不能用“代码跑通”代替。

## 每日温度：从人类现场到方向

### 读题

关键原句：“之后、第一个、严格更高、几天后”。因此对第 `i` 天，要向右找未来第一次严格更高温，写下日期差；没有则写 `0`。

### 扩写

拿着第 `i` 天 -> 向右逐日看 -> 第一次看到严格更高 -> 两个日期相减 -> 否则记 `0`。

### 对象

- 日期由原下标确定身份；
- 温度绑定在某一天，不能代替日期身份；
- 答案属于每一天，是日期差。

### 最笨但正确的过程

用 `[70, 70, 71]`：

- 第 0 天遇到另一个 `70`，继续；遇到 `71`，答案 `2`；
- 第 1 天遇到 `71`，答案 `1`；
- 第 2 天右边没有日期，答案 `0`。

### 第一次变化

变化前第 0 天没有答案；触发是游标第一次遇到严格更高的 `71`；变化后答案确定为 `2`。答案产生时刻是写下日期差时。

### 数据范围

`n <= 10^5`。最坏单调不升时，比较次数约为 `n(n-1)/2`，即约五十亿次。每个日期完整重扫的平方级过程不能稳定承受。

这一阶段只留预算和复杂度家族，不提前说具体方法。

### 第二次变化

用 `[75, 71, 69, 72]` 看从左到右的事件：

```text
72 到来 -> 结算 69 -> 结算 71 -> 75 继续等待
```

于是发现：

- 一个未来温度会被很多起始日期重复扫描；
- 一个更高温可以同时结算一批更低温；
- 日期从最近端加入、读取和连续删除；
- 等待日期从旧到新，温度不增。

### 方向确认

慢在逐日重扫；预算是平方级；需要最近端加入、读取和连续删除；保存尚未结算日期能承担这组操作。到这里才允许说具体结构。

### 思维链

先结算严格更低的等待日期，再把今天加入；不变量是等待日期仍属于未来、下标递增、温度不增。用 `[70, 70]` 证明相等不能结算，用先加入今天的错误顺序证明更新顺序不能交换。

## 已知答案时怎样复盘

1. 把已知答案标成“事后校验”；
2. 把方法名写成“记忆候选，不是题目事实”；
3. 从交接 1 开始重建；
4. 每次只问当前证据允许的问题；
5. 如果某一步只能靠记住答案通过，那一步就是最早断点。

## 事后八问只用来定位断点

完成整条现场后，才可以用八问检查：

1. 题目给了我什么，要我交回什么？
2. 普通人在纸上第一步做什么？
3. 有哪些对象？
4. 最笨但正确的过程怎样走？
5. 哪一刻什么变了，答案何时确定？
6. 最坏重复多少，范围排除哪些复杂度家族？
7. 哪份信息重复、过期、复用或必须保序？
8. 哪个候选能承担操作，方向确认句是什么？

它们不是开始前的待办。现场主线始终是九次交接。

## 统一规则

### 关于方法名

交接 1 到 7 都不能用具体方法名推进。交接 8 才允许比较，交接 9 才允许完整落地。

### 关于候选

候选必须从操作需求长出来。没有真实候选就写“没有形成候选”，不要补造。

### 关于两次变化

- 第一次变化：对象在过程里怎样改变；
- 第二次变化：哪份工作会重复、失效、复用或必须保序。

### 关于范围

范围只给预算和复杂度家族。不能把 `n` 当算法暗号。

### 关于理解

闭卷后能从原题事实重新生成对象、过程、预算、变化、方向和代码，才叫理解；能背出最终答案不算。
