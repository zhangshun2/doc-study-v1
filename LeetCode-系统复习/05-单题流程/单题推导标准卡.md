# 单题推导标准卡

> 这是做题时实际打开的标准卡。长文标准负责解释原因，这张卡负责保证每一次推导都没有从题面直接跳到算法名。
>
> 核心标准只有一句：先恢复一个不知道答案的人怎样读题、做事，再在数据预算下重新观察变化，确认候选方向，最后才允许出现状态、数据结构和代码。

## 使用方式

每次开始一道题，按下面的七道判断门走。可以在一道门停留很久，也可以从上一处断点继续，但不能在没有证据时跳到后面的方法名。第三道门内部仍有三个连续产物：对象、手工过程、第一次变化；它们不是三个可以乱序完成的独立任务。

```text
第一道门：只读原题事实
第二道门：把题干扩写成完整生活过程
第三道门：对象 -> 人工过程 -> 第一次变化
第四道门：读数据范围 -> 估算操作预算 -> 缩小候选方向
第五道门：带着候选再捕捉变化
第六道门：比较候选并确认算法方向
第七道门：状态、初始、停止、转移、顺序、不变量
          -> 结构、伪代码、Java、反例 -> 闭卷重建
```

## 七道判断门

| 门 | 小白此刻要回答的问题 | 这段的产物 | 通过证据 | 不通过的信号 |
| --- | --- | --- | --- | --- |
| 1. 读题 | 题目原句到底给了什么、要什么、禁止什么？ | 输入、输出、保证、禁止、未知 | 能区分事实、推导和推测 | 已经在想方法名 |
| 2. 扩写 | 谁拿着什么，从哪里开始，重复做什么，何时停止？ | 能演出来的人话过程 | 每条扩写都能指回原句 | 只把词语换成同义词 |
| 3. 对象、过程、变化 | 题目世界里有什么，人最直接会怎么走，什么因此改变？ | 对象表、最小演算、变化记录 | 换一个同类小例子仍能执行 | 直接套高级过程 |
| 4. 范围与候选 | 慢过程要做多少事，哪些量级不够，由实际操作能提出哪些方向？ | 官方约束、操作预算、候选池 | 三类信息分开写，范围只做排除 | 看到 `10^5` 就报算法名 |
| 5. 第二次变化 | 哪里在重复，哪批候选会失效，哪个子问题被复用？ | 重复劳动、信息寿命、所需操作 | 能用最小例子证明变化真实发生 | 仍只是在重复第一次变化 |
| 6. 确认方向 | 哪个候选真正支持这些操作和预算，另一个为什么暂不选？ | 候选比较、方向确认句、依赖条件 | 能说出重复劳动、操作、代价和失效条件 | 只有算法名，没有因果句 |
| 7. 推导链 | 状态、更新、不变量和代码能否逐段回到题目过程？ | 完整模型、代码、反例、闭卷记录 | 每段都能映射回对象和变化 | 代码能跑但解释只能靠模板 |

每一段都只留下四行现场记录：

```text
我现在确定：______
我还不确定：______
为了排除它，下一个最小问题是：______
这一步的通过证据是：______
```

如果四行写不出来，不要用“我大概懂了”进入下一段。真正卡住时，只补最早缺失的那一段。

小白不需要一次回答整题。标准动作是只处理眼前这个最小问题，答完再问下一问。答案里允许出现“我原来以为……，但这一步看到……，所以必须改成……”；这条变化本身就是因果链的一部分，不能为了显得流畅而删掉。

允许回退。例如读范围后发现人工过程漏掉了一项变化，可以回到对象或过程重新观察。但必须写清“前面的哪条判断被新证据推翻”，不能悄悄把后面的结论塞回前面。

## 一、只读原题事实

### 小白此刻为什么会卡住

刚看到题时，人会同时产生很多猜测：这像不像以前做过的题，要不要排序，是不是用双指针。此时最能误导人的不是不会算法，而是把记忆、标签和脑补当成题目已经给的条件。

因此第一步不是想解法，而是回答：“题面到底说了什么，哪些话只是我暂时猜的？”

### 这一段要做什么

先关掉题解、标签和讨论区，只读原题。把信息分成下面几类：

| 项目 | 要写清什么 |
| --- | --- |
| 输入 | 有哪些对象，每个对象代表什么，是否允许空、重复、负数或特殊值 |
| 输出 | 返回数量、值、下标、路径还是结构；顺序是否有要求 |
| 保证 | 题目保证存在答案、唯一、已排序、连通或满足某种关系吗 |
| 禁止 | 不能重复使用、不能修改输入、不能改变顺序、不能使用某些操作吗 |
| 示例 | 从输入到输出发生了什么，示例没有覆盖什么 |
| 未知 | 哪些问题原题没有回答，现在不能自行补上 |

每条内容再标一种来源：

- **事实：** 原句直接写了。
- **推导：** 根据原句必然成立。
- **推测：** 目前没有证据，只是我觉得可能如此。

### 小白怎样从读字走到理解

不要问“这题考什么”，先问下面四个更小的问题：

1. 题目交给我的是什么东西？
2. 题目要我交回什么东西？
3. 哪些关系必须始终保持？
4. 我有没有把“通常如此”误当成“本题保证如此”？

比如题面没有写“数组有序”，就不能因为常见做法需要有序而自行加入这个条件。题面说明“同一个元素不能使用两次”，也不能直接缩写成“不能有重复值”，因为两个不同位置可以有相同的值。

### 必须留下的产物

一张事实卡。它至少要能让我不看原题复述输入、输出、保证、禁止和未知，并且知道每句话来自哪里。

### 通过证据

- 能逐条指出某个条件是原题事实，还是我自己的推测。
- 能说出一个示例没有覆盖、但约束允许的情况。
- 能发现至少一个“看起来很自然，但题目并没有保证”的假设。

### 假通过

- 只写“输入数组，输出答案”。
- 已经把“使用哈希表”“这是滑动窗口”写进读题结果，却还不能复述题目禁止什么。
- 把方法经验当成题目保证，例如自行认定有序、无重复、答案唯一。

## 二、把题干扩写成完整生活过程

### 小白此刻为什么会卡住

原题为了简洁，会省略很多动作之间的连接。人会认识每个字，却不知道“谁在什么时候对谁做了什么”。这时需要的不是更抽象的解释，而是把压缩句子还原成能看见的时间过程。

### 这一段要做什么

逐句回答六个问题：

1. 谁或什么在被处理？
2. 他手里已经有什么？
3. 下一步具体做什么动作？
4. 动作让哪个对象发生了改变？
5. 什么条件出现时停止？
6. 停止时题目要的是哪一个结果？

可以先用这个骨架：

> 我手里有 ______；我从 ______ 开始；我反复 ______；条件“______”意味着我不能 ______；当 ______ 时停止；题目最后要交出的不是 ______，而是 ______。

### 条件不能只抄一遍

题面里的条件通常阻止某种具体错误。每遇到一个条件，都要补一句“它防住了什么”：

```text
条件原句：______
如果忽略它，我会错误地做：______
因此正确过程必须：______
```

例如“同一个元素不能使用两次”并不是一句需要背的限制。它表示处理当前元素时，不能把当前这个位置同时当成两个位置；两个不同位置即使数值相同，仍然可以分别被使用。

### 小白怎样从一句题面想到完整过程

把名词先当成题目世界里的人或物，把动词先当成一个可见动作，把条件先当成一道守卫，把“返回”先当成最后需要交出的实物。

仍然不懂时，只补一个最小问句：

- 现在谁是主语？
- 他手上拿着什么？
- 他下一步眼睛看哪里、手做什么？
- 做完以后什么变了？
- 为什么现在可以停？

### 必须留下的产物

一段按时间顺序能演出来的生活过程。每个新增解释都能指回原题；推测内容单独标注。

### 通过证据

- 能用自己的话说出开始、重复动作、停止条件和返回物。
- 每个条件都能说明它阻止了哪种具体错误。
- 另一个人只读扩写，也能在纸上按步骤执行。

### 假通过

- 只是把原句中的词换成同义词，仍然没有动作顺序。
- 加入原题没有的主语、限制或保证。
- 扩写中已经出现高级方法，其实是在用最终答案倒推题目过程。

## 三、清点题目里的对象

### 小白此刻为什么会卡住

人容易一看到数组就想到下标，一看到关系就想到图，一看到重复就想到哈希。但代码容器不是题目对象。题目对象先决定“世界里有什么”，代码对象以后才决定“拿什么保存它”。

### 这一段要做什么

按题目世界列出对象：

| 对象类型 | 要回答的问题 |
| --- | --- |
| 元素 | 单个数字、字符、节点、区间或状态是什么 |
| 身份 | 两个值相同但位置不同，是否是不同对象 |
| 位置 | 下标、坐标、层数、时间或区间端点代表什么 |
| 关系 | 对象之间是先后、相邻、包含、依赖、可达还是配对 |
| 目标 | 要找、构造、判断、计数还是修改什么 |
| 结果 | 最后交出路径、数量、位置、布尔值、区间还是整个结构 |

### 小白怎样从一个名词想到对象

连续追问四层：

1. 这个词在题目世界里是什么东西？
2. 它靠什么和其他东西区分？
3. 它会和谁发生关系？
4. 题目最后需要它的值、位置、顺序还是身份？

例如题目里有两个数值相同的元素。只保存值会把它们合并成一个，只有当题目不关心位置时才可以这样做。若答案需要原下标，它们就是两个不同身份，必须保留位置。

### 必须留下的产物

一列业务对象及其关系。此时不出现 Map、Queue、Stack、dp 数组等实现对象，除非它们已经能从题目对象直接解释。

### 通过证据

- 能说清两个相同值为什么可能仍然是不同对象。
- 能说清最终答案是哪一个业务对象。
- 能指出当前哪些对象只是题目对象，哪些以后可能需要记录历史。

### 假通过

- 只写“主要对象是数组”。
- 直接说“用 Map 保存值”，却没有说题目里的对象身份和关系。
- 把代码变量名当成对象定义。

## 四、让普通人手工走最小例子

### 小白此刻为什么会卡住

能复述题目，不等于能动手。人常见的感觉是“我懂意思，但不知道第一步做什么”。这时要选一个足够小、却仍能暴露关键关系的例子，让自己按普通人的慢办法走完。

### 最小例子怎样选

例子要满足三个条件：

- 小到每一步都能手写。
- 完整到能够走到停止和返回。
- 至少包含一个关键关系，例如重复、等待、候选淘汰、区间变化或子问题复用。

只看输入和输出不够。必须把中间状态写出来。

### 这一段要做什么

按一次只做一个动作的方式记录：

```text
我现在看到什么
-> 我决定处理哪个对象
-> 我具体做了什么
-> 得到了什么中间结果
-> 下一步为什么从这里继续
```

先写最直接、可能很慢但正确的过程。即使最后会被优化，也要先把它在例子中走通。

### 小白怎样从不理解走到能手工执行

不要问“标准算法是什么”，只问下面三个问题：

1. 我第一眼看哪一个对象？
2. 看完以后我下一步把目光移到哪里？
3. 我在纸上要修改哪一个值或记录哪一件事？

如果还不能动手，把例子再缩小一格，只处理一两个对象；如果过程太简单而看不到问题，再增加一个能触发关键关系的对象。

### 必须留下的产物

一个最小但完整的演算表或时间序列。每个中间值都能从上一行得到。

### 通过证据

- 能不跳步骤走到答案。
- 每一步都能说出为什么看这个对象、为什么下一步去那里。
- 换一个同样小的例子后仍能执行同一过程。

### 假通过

- 只列输入、输出和最终公式。
- 中间步骤由“然后自然就知道答案”带过。
- 一开始就使用从题解记住的高级过程，无法解释普通人的慢办法。

## 五、第一次捕捉变化

### 小白此刻为什么会卡住

例子走完以后，人容易觉得“过程就是这样”，但说不清到底是什么在变化。没有变化记录，后面的优化就没有对象。

### 这一段只观察发生了什么

对每一类关键信息写：

```text
变化前：______
触发事件：______
变化后：______
```

至少检查四本变化账：

| 变化账 | 要观察什么 |
| --- | --- |
| 当前位置 | 当前处理对象是否移动，下一步会看向哪里 |
| 历史信息 | 已经见过、已经完成或尚未结算的信息是否累积 |
| 候选范围 | 可选对象是否增加、减少或因为某个事件失效 |
| 当前结果 | 临时答案、累计量或最终结果在哪一刻改变 |

还要单独回答：答案是在当前动作发生时产生，还是最后从记录中读取？哪一种事件发生后，该位置的答案已经不会再改变？

### 小白怎样从“看懂了”走到“看见变化”

把每一步读成一句有主语和宾语的句子：

> 第 ______ 步，______ 对 ______ 做了 ______，所以 ______ 从 ______ 变成 ______。

如果句子只能写成“遍历一下”或“更新答案”，说明变化还没有被看见，需要回到最小例子。

### 必须留下的产物

一组“变化前、触发事件、变化后”的记录，以及答案确定时机。

### 通过证据

- 能指出哪个对象在移动，哪个信息在留下。
- 能说出同一份信息是否在多个步骤中被重复产生或重复读取。
- 能指出答案在哪一个事件后不再改变。

### 假通过

- 只写“随着循环，状态发生变化”。
- 把“这里可以优化”混进第一次变化。
- 直接写出“需要哈希表、栈或动态规划”，却没有先说明过程里到底发生了什么。

第一次变化可以记录“同一个未来对象在多次扫描中再次出现”这类现象，但不能在这里决定保存什么结构。那是第二次变化与方向确认的工作。

## 六、读数据范围，估算操作预算

### 小白此刻为什么会卡住

小白常见两种错误：完全不看范围，或者把范围当成算法暗号。前者不知道慢过程是否还能接受；后者看到 `10^5` 就猜一个熟悉的 `O(n)` 方法，却没有题目过程作为依据。

### 这一段要做什么

先读全所有约束，不只读 `n`：

- 元素数量、节点数、边数、字符串长度或矩阵尺寸。
- 值域、正负、重复、是否稀疏。
- 是否有序、唯一、连通、保证存在答案。
- 输出是否要求原位置、原顺序或原地修改。
- 是否禁止某些操作。

然后回到人工过程，估算它最坏会做多少次核心动作：

```text
慢过程反复执行的动作：______
每轮大约重复多少次：______
最多有多少轮：______
合起来大约是：______
```

最后把三类信息分开写：

| 信息 | 来源 | 能用来做什么 |
| --- | --- | --- |
| 官方约束 | 题面明确给出 | 判断允许的操作量级 |
| 操作预算 | 我根据慢过程估算 | 判断当前重复方式是否可能太贵 |
| 候选方向 | 由操作形态、预算和特殊保证产生 | 等待第二次变化继续淘汰 |

### 范围只能排除，不能点名

范围可以告诉我们“继续完整重扫可能不够”，不能单独告诉我们“所以用双指针”。同一个 `10^5` 可能对应历史查询、区间维护、候选淘汰或图遍历，必须看过程需要什么操作。

可以保留这张常见量级参考，但它不是算法映射表：

| 常见上界 | 可以继续考虑的量级 | 不能直接推出 |
| --- | --- | --- |
| `n <= 10` | 指数枚举、全排列可能进入候选 | 一定要回溯 |
| `n <= 20` | 子集枚举、状态压缩可能进入候选 | 一定要位运算 |
| `n <= 100` | `O(n^3)` 可能还能接受 | 一定要三重循环 |
| `n <= 1,000` | `O(n^2)` 可能还能接受 | 一定要动态规划 |
| `n <= 10^5` | 通常要重点检查 `O(n)` 或 `O(n log n)` | 一定要排序、哈希或双指针 |
| `n <= 10^6` | 通常只剩接近 `O(n)` 的方向 | 一定要一次遍历 |

### 从慢过程生成候选池

候选不是从题目标签抄来的，而是从“人现在反复做什么”长出来的。先写操作，再允许方法名进入候选表：

| 人工过程中反复出现的操作 | 可以进入候选池的方向 | 此刻仍不能确定 |
| --- | --- | --- |
| 反复问以前是否出现、出现几次、位置在哪 | 哈希查询、计数表、位置表、前缀记录 | 保存全部历史还是最近一份 |
| 对象先出现，必须等未来事件才能结算 | 栈、队列、堆、按值索引 | 哪一端先结算，哪些对象可同时丢弃 |
| 连续区间扩张、收缩后仍可增量维护统计 | 滑动窗口、前缀和、差分 | 条件是否单调，边界移动是否安全 |
| 某事件能证明一批候选永远不再最优 | 双指针、单调栈、贪心淘汰 | 淘汰条件是否覆盖所有情况 |
| 同一小问题会被不同路径重复遇到 | 记忆化、动态规划、状态图搜索 | 状态是否完整，按什么顺序复用 |
| 每一步有多个选择，而且需要撤回 | DFS、回溯、搜索 | 完成条件、去重和恢复方式 |
| 输入有序，或答案具有可判定的单调性 | 二分、双指针 | 判定函数是否真的单调 |

### 小白怎样由范围想到候选

不要问“这个范围对应哪个模板”，依次问：

1. 如果完全照慢过程做，最坏要做多少次核心动作？
2. 这个数量在最大输入下还能不能接受？
3. 慢过程最常重复的是哪一种操作？
4. 题目有没有额外保证，能让某些候选提前进入或退出？
5. 哪些方向只是在记忆里熟悉，却还没有和当前操作对应上？

候选池的作用是保留一小组可比较假设，不是在这里宣布答案。

### 必须留下的产物

一张候选池卡：

| 项目 | 本次答案 |
| --- | --- |
| 官方约束 |  |
| 慢过程在重复什么 |  |
| 最坏大约多少操作 |  |
| 范围排除了什么 |  |
| 仍允许哪些量级 |  |
| 由操作形态产生的候选 |  |
| 题目特殊保证影响哪些候选 |  |
| 此刻仍不能决定什么 |  |

### 通过证据

- 官方约束、操作预算和候选方向没有混成一句话。
- 能说明候选是由哪项实际重复动作产生的。
- 能说清范围排除了什么，但不把范围当成算法证明。

### 假通过

- 只看到 `n`，立刻写“所以用 O(n)”。
- 候选池里只有题目标签对应的一个方法，没有比较对象。
- 把“我觉得这题像某题”当成过程证据。

## 七、第二次捕捉变化

### 小白此刻为什么会卡住

此时已经知道慢过程太贵，也产生了几个候选，但新手仍然不知道应该保存值、位置、次数、有效期还是顺序。原因通常不是不会某个数据结构，而是没有继续观察“这份信息以后会怎样被使用和丢弃”。

### 这一段要做什么

带着操作预算重新走人工过程，只寻找三类变化：

| 第二层变化 | 小白要问的问题 | 要找到的证据 |
| --- | --- | --- |
| 重复查询 | 同一个问题是否会在未来再次被问 | 哪份历史能回答它，未来需要值、位置还是次数 |
| 候选失效 | 哪个事件发生后，一批对象已经不可能产生答案或更优答案 | 失效条件是什么，哪些对象可以安全丢弃 |
| 子问题复用 | 不同路径是否到达同一个更小问题 | 状态由什么组成，重复出现的最小例子是什么 |

实际题目可能是其中一种，也可能是多种同时存在。

### 把“需要保存”问到具体

对每一份想留下的信息，连续问：

```text
未来第 ______ 步会回来问：______？
为了回答它，我现在至少要留下：值 / 位置 / 次数 / 有效期 / 顺序？
当 ______ 发生后，这份信息可以消失？
当前写入会不会影响本轮后面的读取？
```

如果未来不会读取，就不保存。如果未来只问“出现过没有”，保存一个标记可能足够；如果还要返回原下标，就必须保留位置；如果候选会过期，还要说明过期事件。

### 把变化翻译成操作需求

先写普通语言，不写结构名：

```text
我需要快速插入当前对象
我需要查询以前是否出现过某个值
我还需要取回它的位置
当某个条件发生后，我需要删除一批旧对象
我需要在同一端连续加入和删除
我需要取当前最小或最大的候选
```

这些句子完成以后，才允许问“哪种结构支持这些操作”。

### 小白为什么会自然想到某个结构

不是因为记得标签，而是因为操作形状已经出现：

- 反复按某个键查历史，才会想到映射或计数结构。
- 只关心最近进入且尚未结算的对象，才会想到一端加入、一端删除。
- 每次都要取最大或最小候选，才会想到堆或有序结构。
- 连续区间只在一端加入、另一端删除，并且统计可增量维护，才会想到窗口。
- 同一子问题从多条路径反复出现，才会想到记忆化或动态规划。
- 每个事件能证明一批候选永远不再最优，才会想到单调淘汰或指针移动。

如果结构名先出现，就追问一句：“它替我支持了哪项操作，消除了哪份重复劳动？”答不上来，说明方向还没有从过程中长出来。

### 必须留下的产物

- 第二层变化属于哪一类，或多个类的组合。
- 真正重复的动作。
- 未来会读取的历史字段。
- 候选失效事件。
- 所需操作清单。
- 一个确实发生这类变化的最小例子。

### 通过证据

- 能说清“为什么现在需要留下它”，而不只是“这里通常用某个结构”。
- 能说清信息未来怎样被读取，什么时候可以丢弃。
- 能用最小例子展示重复查询、候选失效或子问题复用真实发生。

### 假通过

- 只说“有重复，所以用哈希表”。
- 只说“要取最值，所以用堆”，却没有说明候选如何进入、何时失效。
- 只说“子问题重复，所以动态规划”，却没有用完整句子定义那个子问题。
- 第二次变化仍然只是重复第一次变化的“当前位置移动”。

## 八、比较候选并确认算法方向

### 小白此刻为什么会卡住

候选池里可能有两三个熟悉名字，新手容易选择最熟的那个，而不是最贴合当前操作的那个。确认方向的任务不是证明某个方法“高级”，而是说明它为什么在当前约束下替代了最贵的那份重复劳动。

### 这一段要做什么

存在真实歧义时，至少比较两个候选。每个候选写四项：

| 候选 | 消除哪份重复劳动 | 需要支持哪些操作 | 代价、限制或失效条件 |
| --- | --- | --- | --- |
| A |  |  |  |
| B |  |  |  |

比较时逐项检查：

1. 它是否真的消除了第二次变化指出的重复动作？
2. 它能否支持当前过程需要的查询、插入、删除、取极值或回溯？
3. 它依赖哪些题目保证？
4. 它在最大约束下大约要多少时间和空间？
5. 换一个条件后，它会在哪个例子中失效？

### 方向确认句

必须说完整下面这句话：

> 当前过程反复需要 ______；如果继续重新扫描，大约会做 ______ 次操作；因此算法必须支持 ______；候选 A 提供 ______，候选 B 在 ______ 条件下不适用或代价更高；所以当前选择 A，因为它与过程操作和约束同时匹配。

句子里必须出现真实操作、代价和失效条件。只出现算法名不算通过。

### 必须留下的产物

候选比较表、方向确认句，以及所选方案依赖的题目保证。

### 通过证据

- 能说清所选方案替掉了哪份重复劳动。
- 能说清一个未选方案具体在哪里不优先或失效。
- 能用操作需求解释结构选择，而不是用标签解释。

### 假通过

- 只列两个算法名，没有比较过程。
- 说“这个更标准”“这个更常见”“这个更简单”。
- 方向确认句只有“因为 n 是 10^5，所以用某算法”。

方向确认是闸门。没有通过这里，不写完整 Java。

## 九、方向确认后的第二层思维链

从这一节开始，讨论的才是“怎样把已确认的方向写成可靠模型和代码”。

| 确认点 | 小白此刻要问什么 | 必须留下的产物 | 通过的证据 | 假通过 |
| --- | --- | --- | --- | --- |
| 1. 状态定义 | 每个变量在题目世界里代表什么，覆盖哪段范围 | 用完整句子定义每个状态 | 不看代码也能说清状态和范围 | 只写 `dp[i]`、`left`、`seen` 等名字 |
| 2. 初始、停止和答案时机 | 从哪里开始，什么时候停，答案何时确定 | 初始值、停止条件、返回时机 | 最小例子中的每个初值都能对应现实含义 | 初始化靠模板记忆，停止条件与目标脱节 |
| 3. 一次状态转移 | 当前事件读什么、算什么、写什么 | 一轮输入事件、旧状态、计算、新状态 | 能连续手算至少三轮并预测下一轮 | 能写循环，却只能靠运行结果解释 |
| 4. 更新顺序 | 哪两个操作交换后会产生错误 | 查询、写入、删除、覆盖的先后理由 | 能给出交换顺序后的具体错误输入和错误结果 | 只说“代码习惯这样写” |
| 5. 不变量与正确性 | 为什么不会漏、不会多、不会错误丢弃 | 每一步开始和结束都成立的关系 | 能逐条指出证明依赖的题目条件和更新顺序 | 只说“这样遍历就覆盖了” |
| 6. 结构与操作 | 过程真正需要哪些操作，为什么该结构匹配 | 所需操作与结构代价对照 | 能与更简单结构的不足作具体比较 | 先点名结构，再逆向编用途 |
| 7. 伪代码与 Java | 每段代码对应哪个对象、动作和状态 | 自然语言伪代码与清晰 Java | 每个关键变量、循环和返回位置都能映射回过程 | 代码可运行，但无法解释为什么这一行在这里 |
| 8. 反例与闭卷重建 | 模型在哪种输入下最容易错，我能否独立重来 | 反例、边界、手算结果、闭卷记录 | 能重走人类判断、模型、代码和自测 | 只默写代码，不能恢复算法方向 |

### 状态必须先于转移

如果还不能用题目语言说出状态，不要写转移公式。变量名不是定义。一个合格定义至少要包含：

> 它覆盖哪些对象；它记录什么事实；处理到哪一步时被读取；哪件事发生后它更新或失效。

### 更新顺序必须用反例证明

不要只背“先查后写”。要构造一个具体输入：

```text
如果先写后查，当前对象会被自己读到，于是得到 ______
题目实际要求 ______
因此必须先 ______，再 ______
```

交换顺序后指不出具体错误，说明顺序还没有真正理解。

### 不变量要说明防止哪种错误

不变量不是一句装饰性的“记录历史”。它必须直接回答：

- 为什么不会漏掉某个答案？
- 为什么不会把同一个对象算两次？
- 为什么可以安全丢弃一批候选？
- 为什么当前状态足以支持下一步？

### 代码必须能逐段回到过程

每个关键代码段回答三件事：

1. 它回答了过程中的哪个问题？
2. 它读取或修改了哪个状态？
3. 为什么必须在这个时间、这个顺序执行？

如果一个循环只是为了模仿模板，却说不出它对应哪一项人类动作，就还不能称为掌握。

## 十、两次变化不能合并

第一次变化和第二次变化回答的是两个不同问题：

```text
第一次：人工过程里实际发生了什么？
第二次：带着预算重看，哪里重复、什么会失效、什么可以复用？
```

错误写法：

```text
第一次变化：用单调栈维护尚未结算的日期。
```

这里已经从观察跳到了结构结论，中间的等待、批量结算、单端删除和所需操作都消失了。

合格写法应当先出现过程事实，再出现操作需求：

```text
第一次变化：
较早日期进入等待；未来更高温到来时，该日期从不等待变成已结算；
一个新日期可能连续结算多个更早日期；相等温度不能结算。

第二次变化：
等待对象会反复被未来事件读取；某些对象一旦结算便永远失效；
被新温度挡住的较早期对象暂时不能结算。
我还需要观察等待对象以什么顺序进入和离开，才能判断需要哪种操作。
```

这时仍然不急着点名结构。继续比较候选后，才确认最终方向。

## 十一、给 AI 的逐段指令

如果让 AI 讲题，可以按下面顺序逐段要求，不需要一次要整篇答案：

1. “先只列原题事实、保证、禁止和未知，不出现算法名。”
2. “把题目扩写成谁拿着什么、重复做什么、何时停止；每条扩写指回原句。”
3. “只列题目对象、身份、关系和最终结果，不出现代码容器。”
4. “用一个最小完整例子，按时间顺序走最慢的人工过程。”
5. “只做第一次变化，写变化前、触发事件、变化后，不优化。”
6. “读全部约束，单独估算慢过程操作量，再生成待验证候选池。”
7. “做第二次变化，判断是重复查询、候选失效还是子问题复用，先写所需操作，不报结构名。”
8. “比较候选，给出完整方向确认句和失效条件。”
9. “方向确认后再讲状态、初始、停止、一次转移和更新顺序。”
10. “最后再讲不变量、结构、伪代码、Java、反例和闭卷重建。”

如果 AI 在前一步已经偷跑到下一步，可以只要求它撤回：“你现在给出的内容依赖了哪条尚未确认的事实或操作？请回到最早缺失的那一段。”

其中第 3 至 5 条共同组成第三道判断门。AI 可以逐条展开，但不能在对象还没有清点时直接演算，也不能在人工过程还没有走通时宣布优化。

## 十二、七道门是否合格的六条硬标准

1. **没有偷加条件。** 原题事实、推导、推测分开；没有把常见题设当成本题保证。
2. **人话过程能执行。** 能看见谁在何时对谁做什么，停止和返回都清楚。
3. **第一次变化没有优化结论。** 只写过程事实，不提前出现结构名。
4. **范围和候选没有互相冒充。** 官方约束、操作预算、候选方向分开；范围只排除量级。
5. **方向有比较和失效条件。** 能说清消除哪份重复劳动、需要哪些操作、为什么没选另一个方案。
6. **第二层能回到过程。** 状态、更新顺序、不变量、结构和代码都能映射回题目对象与变化。

只要其中一条缺失，这段讲解就不应被标记为“完整推导”。代码运行通过不能补齐前五条。

## 十三、断点与完成标准

一次学习可以只完成一段，也可以连续完成整条链。不要用固定时长、题量或连续打卡决定是否结束。

断点时写：

```text
已经确认到：第 ______ 段
通过证据：______
最早未确认的是：______
下一次第一件事：______
```

这里的“已经确认”必须是能复述、手算、比较或运行验证的内容，不是“刚刚看过”。

一套完整掌握至少要求：

- 能从原题事实独立扩写出可执行过程。
- 能用最小例子完成第一次变化。
- 能估算慢过程操作量并生成候选池。
- 能用第二次变化指出重复劳动、历史需求和失效条件。
- 能比较候选并说明当前选择为什么成立。
- 能独立重建状态、更新顺序、不变量和代码。
- 能设计一个反例或边界输入，并解释结果。
- 隔一段时间后，仍能闭卷重走“题面到方向”的路径。
