# 单题推导标准卡

> 这张卡不是把一个已经知道的答案拆成几段，而是规定一个还不知道方法的人，现场怎样一步一步把题读懂、把过程走通、把重复工作找出来，最后才允许说算法。
>
> 实际顺序是：
>
> `读题 -> 扩写题干 -> 对象、过程、第一次变化 -> 数据范围缩小方向 -> 重新捕捉变化 -> 确认方向 -> 思维链`
>
> 八个自然问题嵌在七个阶段里。不要从头背检查项；只走到当前第一个无法用原句、例子、约束或手算回答的地方，然后只问那一句。

## 先只问现在能问的

刚拿到题时，不要先问“这题考什么”。先问：

> 题目给了我什么，要我交回什么？

答完以后，如果还不知道人怎样动手，再问：

> 一个普通人拿着这些对象，第一步具体做什么？

这不是把完整答案切成八段。下一问必须由上一段留下的空缺产生；上一段没有产生这个空缺，就不应该提前回答下一段。

## 八个自然问题

| 顺序 | 小白现场最自然的问题 | 这个问题只能产出什么 | 此时不能做什么 |
| --- | --- | --- | --- |
| 1 | 我刚读完题，题目到底给了我什么，要我交回什么？ | 输入、输出、示例、保证、禁止、未知，以及真实的初始理解 | 不能把方法名、标签或记忆当成题目事实 |
| 2 | 每个字都懂，可一个普通人在纸上第一步做什么？ | 谁拿着什么、从哪里开始、反复做什么、何时停止、最后交出什么 | 不能只把原句换成同义词，也不能提前优化 |
| 3 | 这个任务里有哪些对象，谁和谁有关系？ | 值、位置、身份、关系、目标和结果 | 不能先列代码容器 |
| 4 | 照着最笨的办法走一遍，哪一刻什么变了，答案什么时候定下来？ | 一条完整的人工过程，以及第一次变化 | 不能把“发生了什么”写成“应该用什么结构” |
| 5 | 这个笨办法最坏会重复多少，数据范围先排除哪些方向？ | 官方约束、自己的操作预算、被排除的复杂度家族、仍待验证的可能方向 | 不能从 `n` 的大小直接点名算法 |
| 6 | 带着这个代价重看，哪份信息还会被再次问起，哪批候选会过期，哪个子问题会复用，哪条顺序不能乱？ | 重复查询、候选失效、子问题复用或顺序约束的最小证据，以及必须支持的操作 | 不能只写“暴力太慢，所以优化”，也不能提前宣布最终结构 |
| 7 | 这些操作需要什么方向来承担，另一个方向为什么不够？ | 候选比较和完整的方向确认句 | 不能只报方法名，不能把熟悉当成证明 |
| 8 | 方向已经定了，状态、更新顺序、不变量和代码怎样逐段对应？ | 状态、初始、转移、顺序、不变量、结构、代码、反例和闭卷重建 | 不能把模板顺序当成正确性证明 |

这八个问题对应七个连续阶段：

```text
阶段 1：问题 1
阶段 2：问题 2
阶段 3：问题 3 -> 问题 4
阶段 4：问题 5
阶段 5：问题 6
阶段 6：问题 7
阶段 7：问题 8
```

阶段 3、4、5 的内部必须真的走完，不能用一句话带过。尤其不能把“对象、过程、第一次变化”压缩成“分析题意”，也不能把“数据范围之后重新观察”压缩成“优化暴力”。

## 第一阶段：问题 1，先读题，不先认标签

关掉题解、标签和讨论区，只留下题目原话。先写下面几类内容：

- 输入对象是什么，每个位置或字段代表什么。
- 输出要交回数量、值、下标、路径、布尔值还是整个结构。
- 示例怎样从输入走到输出，示例没有覆盖什么。
- 题目明确保证什么，明确禁止什么。
- 哪些问题题目没有回答，现在不能自己补。

每条信息都要能指出来源：

- **事实：** 原句直接写了。
- **推导：** 结合已确认的原句必然成立，并能指出依赖哪几条事实。
- **推测：** 题目没有保证，只是现在觉得可能如此，不能进入后续证明。

如果脑子里已经冒出“哈希”“栈”“双指针”，把它写在旁边，标成 `记忆候选，不是题目事实`。它不是题目给的证据，暂时不能用来证明后面的任何判断。

如果现场连方向都没有想出来，就写“没有形成候选”，不要为了显得聪明补造一个更合理的初始反应。

如果现场确实出现过一个听起来自然、但题目没有保证的假设，就写出来并留在证明之外；如果没有，就写“没有形成额外假设”，不要为了显得真实补一段犹豫。

读完题后，允许自己仍然不知道怎么做。此时合格的产物不是方法，而是：

```text
题目确认的输入是：______
题目要求交回的是：______
题目明确保证：______
题目明确禁止：______
我现在还不知道：______
下一条能回答它的是原句、示例还是手算：______
```

题目事实读错是一票否决。后面所有过程、预算和方向都建立在事实上；事实错了，不能靠后面写得很长来补偿。

## 第二阶段：问题 2，逐句扩写，直到一个普通人能照做

认识每个字，不等于知道动作顺序。扩写不是把整段题面换成更顺口的话，而是逐句检查：

1. 这句话新增了哪个对象、动作、身份、顺序、停止条件或禁止项？
2. 如果忽略它，会在具体过程中做错哪一个动作，或者交回什么错误结果？
3. 这句话要求谁先处理、谁后处理，或者哪个对象不能提前丢掉？

然后把这些片段按时间合起来：

```text
我手里有：______
我从：______
开始
我反复做：______
条件“______”意味着我不能：______
当：______
时停止
我最后要交出的不是：______
而是：______
```

每条新增解释都要标成事实、推导或推测。指不回原句又没有标成推测的内容，按脑补处理。

扩写完成时，别人只读这段文字就应该能在纸上按顺序演完。此时仍然不需要出现最终方法名。扩写只是在回答“人怎样执行题目”，还没有回答“这份执行哪里值得优化”。

## 第三阶段：问题 3 -> 问题 4，对象、过程、第一次变化

### 3.1 先分清题目世界里的对象

不要先列 `Map`、`Queue` 或 `Stack`。先看题目里真实存在什么：

- 元素：数字、字符、节点、区间、括号或状态。
- 身份：两个值相同但位置不同，是不是两个不同对象。
- 位置：下标、坐标、层数、时间或区间端点。
- 关系：先后、相邻、包含、依赖、可达或配对。
- 目标：要找、构造、判断、计数还是修改什么。
- 结果：数量、位置、路径、布尔值、区间还是整个结构。

身份决定后面能保存什么。题目要求返回原下标时，两个相同的值不能合并成一个没有位置的对象。

### 3.2 用一个最小但完整的例子走最笨的过程

选一个足够小、又能走到停止并暴露关键关系的例子。不要先问标准方法，先把人最直接会做的事一步一步写出来：

```text
我现在看到什么
-> 我处理哪个对象
-> 我具体做了什么
-> 哪个值或关系发生了变化
-> 下一步为什么从这里继续
```

例子太复杂时缩小一格；太简单、看不到关键关系时，再增加一个能触发关系的对象。先保证过程正确，再讨论它慢不慢。

### 3.3 第一次变化只记录发生了什么

对过程中最关键的一刻写：

```text
变化前：______
触发事件：______
变化后：______
答案产生时刻：______
```

第一次变化只回答：

> 哪个对象，因为哪个事件，从什么状态变成了什么状态？

它不能回答：

> 哪份工作重复得最多？应该保存什么？最终用哪个结构？

如果第一次变化里已经出现“用栈维护等待项”，结构结论就跑到了观察前面。把结构名撤回，继续看过程。

用每日温度 `[70, 70, 71]` 做第一次手算时，人只是逐天向右看：

- 第 0 天遇到另一个 `70`，还不算更高；再遇到 `71`，第一次满足。
- 第 1 天也向右看到 `71`，第一次满足。
- 第 2 天右边没有日期，保持 `0`。

第一次变化可以写成：

```text
变化前：某个起始日期还没有答案，未来游标在它右边
触发事件：未来游标第一次遇到严格更高的温度
变化后：这个起始日期得到答案，不再向右看
答案产生时刻：写下两个日期的下标差时
```

这时最多只能说“同一个未来日期可能被多个起始日期重复检查”。还不能说用栈。

## 第四阶段：问题 5，读数据范围，只缩小可能方向

先读完整约束，不只读 `n`。同时看值域、正负、是否有序、是否唯一、是否连通、输出是否要求原位置，以及题目有没有禁止修改输入。

然后照着第三阶段已经走通的最笨过程估算：

```text
慢过程重复的核心动作：______
每一轮大约做多少次：______
最多有多少轮：______
合起来大约是：______
```

每日温度的官方约束是：

```text
1 <= temperatures.length <= 10^5
30 <= temperatures[i] <= 100
```

如果每天都向右看到末尾，最坏可以取单调不升的温度。比较次数约为：

```text
(n - 1) + (n - 2) + ... + 1
= n(n - 1) / 2
```

当 `n = 10^5` 时，这大约是五十亿次比较。这个估算只说明：不能稳定依赖“每个日期都完整向右重扫”的平方级过程。

数据范围能做的事情只有两件：

1. 排除当前过程不能稳定承受的复杂度家族。
2. 把仍允许的预算和当前过程真实需要的操作合在一起，留下待验证方向。

它不能直接说出某个方法名。同样是 `10^5`，可能有历史查询、区间维护、候选淘汰、图遍历或一次扫描；必须由过程补充操作需求。

这一步可以暂时形成功能候选，例如：

- 继续完整重扫。
- 保存过去出现过的值和位置，供未来查询。
- 利用很小的温度值域记录最近位置。
- 保存尚未结算的对象，等未来事件到来。
- 保存重复子问题的结果。
- 维护一个能查询区间信息的结构。

这些只是可能方向。候选池不是结论，范围也不是算法暗号。

## 第五阶段：问题 6，带着代价重新捕捉变化

现在回到第三阶段的人工过程，不是再复述一遍，而是带着第四阶段的预算找四类现象：

| 现象 | 现场要问 | 需要拿出的证据 |
| --- | --- | --- |
| 重复查询 | 同一个问题会不会在后面再次被问起？ | 哪份历史能回答它，未来需要值、位置还是次数 |
| 候选失效 | 哪个事件后，一批对象已经不可能产生答案或更优答案？ | 失效条件是什么，为什么可以安全丢掉 |
| 子问题复用 | 不同路径会不会到达同一个更小问题？ | 重复出现的最小例子和需要保存的结果 |
| 顺序约束 | 新对象从哪一端加入，又该从哪一端结算？ | 为什么这个顺序不会漏掉候选 |

这里才是“最后再去捕捉变化”的核心。第一次变化说明过程里发生了什么；第二次变化说明哪份工作值得消除、哪些信息有生命周期、未来需要哪些操作。

继续看每日温度 `[75, 71, 69, 72]`。第一次向右扫描会看到同一段未来被反复读取。带着预算重看后，可以换成“按时间从左到右经过每个日期”：

```text
第 0 天，75 到来，暂时没有答案，进入等待
第 1 天，71 到来，不能结算 75，71 自己进入等待
第 2 天，69 到来，不能结算 71，69 自己进入等待
第 3 天，72 到来
-> 高于 69，第 2 天得到答案
-> 高于 71，第 1 天得到答案
-> 不高于 75，第 0 天继续等待
-> 72 自己进入等待
```

这段观察产生了新的信息：

- 一个未来温度可以同时结算多个更早的等待日期。
- 等待日期按进入时间排列，新日期从最近的一端加入。
- 新温度也先从最近端检查，因为那里是最后进入、最可能先被超过的日期。
- 已经结算的日期可以从同一端删除。
- 遇到一个温度不低于今天的等待日期后，更早的等待日期也不会被今天解决。

为什么最后一句成立？假设两个仍在等待的日期是 `i < j`，并且 `temperatures[i] < temperatures[j]`。那么第 `j` 天到来时已经严格高于第 `i` 天，第 `i` 天早该在那时被结算，不可能还留在等待集合里。所以仍等待的日期从旧到新，温度不会上升。

到这里，操作需求才具体起来：

```text
需要从最近端加入今天
需要读取最近端等待日期
需要从最近端连续删除已经结算的日期
```

仍然先不报结构名。现在需要的是“最近端加入、读取、连续删除”这组操作，不是某个熟悉标签。

如果找不到重复、失效、复用或顺序约束，不要直接跳到“优化暴力”。回到第三阶段继续走过程，或回到第四阶段确认预算是否真的构成压力。

## 第六阶段：问题 7，比较候选，确认算法方向

现在才允许具体方法名进入比较。每个候选至少回答四件事：

1. 它消除了第二次变化里的哪份重复工作？
2. 它支持哪些查询、插入、删除、取极值或恢复现场操作？
3. 它在当前约束下大约需要多少时间和空间？
4. 它在哪个条件或最小例子上失效，或者为什么不是当前最简单方案？

每日温度可以比较：

| 候选 | 消除什么工作 | 需要什么操作 | 限制 |
| --- | --- | --- | --- |
| 每个日期向右重扫 | 不消除 | 反复访问未来 | 最坏约五十亿次比较 |
| 记录每种温度最近出现的位置 | 减少未来扫描 | 查询更高温度中的最近日期 | 可利用小值域，但仍要处理范围查询 |
| 保存尚未结算的日期 | 新温度一次结算多个等待对象 | 最近端加入、读取、连续删除 | 需要证明等待顺序和停止条件 |
| 区间查询结构 | 快速找更高温度中的最近位置 | 建结构、更新位置、范围查询 | 可行，但当前操作需求已有更简单对应 |

完整方向确认句可以写成：

> 直接过程会让同一批未来温度被很多起始日期重复扫描，最坏约五十亿次。一个新的更高温到来时，可以同时解决多个仍在等待且温度更低的旧日期；等待日期从旧到新温度不会上升，所以检查到第一个不低于今天的等待日期就可以停止。我需要支持最近端加入、读取和连续删除。保存尚未结算的日期正好承担这些操作，因此当前方向选择这种等待结算模型。

这里“栈”可以出现在句尾，但它不能代替前面的操作和证明。

没有真实歧义时，也检查一个熟悉替代方向为什么不够。不能为了满足“至少两个候选”临时编一个自己从未认真考虑过的方案；有真实替代时，保留它的拒绝证据。

## 第七阶段：问题 8，方向确认后，才进入思维链

这一段才讨论状态、更新和代码。顺序如下：

1. 用完整句子定义每个状态在题目世界里表示什么，覆盖哪些对象。
2. 说明初始值、停止条件和答案产生时机对应的现实含义。
3. 把一次转移拆成读取、计算、写入。
4. 交换两个更新动作，构造一个最小输入，说明具体错误。
5. 写出不变量，分别解释为什么不会漏、不会重复、为什么可以安全删除。
6. 从所需操作反推结构，并和更简单的结构比较。
7. 写伪代码和清晰 Java，让关键行逐段对应题目对象和动作。
8. 用反例、边界和闭卷重建检查整条链。

每日温度的方向确认后，状态可以是：

```text
answer[i]：第 i 天第一次遇到严格更高温还要等几天
waiting：尚未结算的日期下标，按进入时间排列
```

一次转移是：

```text
读取今天
-> 当 waiting 非空，且今天温度高于最近等待日期：
     弹出最近等待日期
     写下今天与它的下标差
-> 今天进入等待
```

必须先结算旧日期，再加入今天。如果先加入今天，等待集合会混入当前日期，后续比较可能把今天和自己比较，状态含义也从“过去尚未结算的日期”变成不一致的混合集合。

不变量可以写成：

```text
waiting 中只有已经出现、仍未结算的日期；
下标从旧到新递增；
温度从旧到新不增。
```

因为每个日期只在第一次遇到严格更高的未来温度时被删除，删除时写下的是当前下标差，所以不会漏；因为只删除严格低于今天的等待日期，相等温度不会提前结算，所以不会错；因为等待日期温度不增，遇到不低于今天的日期就可以停止，所以不会无意义地继续检查。

到这里，`ArrayDeque`、`push`、`pop` 和 `while` 才有来源。代码只是把已经确认的状态和操作写下来。

## 每一步的结论必须有来源

现场每条关键结论只能来自下面几类之一。混用来源时，要拆开重写：

| 来源 | 它能证明什么 | 它不能证明什么 |
| --- | --- | --- |
| 原句事实 | 输入、输出、保证、禁止、顺序和边界 | 题目没有写出的算法方向 |
| 手算推导 | 某个最小例子里真实发生的动作、变化和答案时刻 | 所有输入都必然如此 |
| 操作预算 | 慢过程大约重复多少次，哪些复杂度家族不稳妥 | 必须使用某个具体方法 |
| 候选假设 | 一个方向可能承担哪些操作，还缺什么验证 | 它已经被选中 |
| 设计选择 | 状态、更新顺序、结构和代码怎样落实已确认方向 | 它可以反过来证明方向正确 |

没有来源的结论不能进入下一步。尤其不能把“我记得这题用某结构”写成题目事实，也不能把“范围只允许 `O(n log n)`”写成“所以必须用某个算法”。

## 不通过信号

出现下面任何一种情况，先撤回，不要继续写后面的完整答案：

- 标题或第一段先宣布结构名，后面才开始找题目对象。
- 数据范围一出现就跳到方法名。
- 人工过程里还没有重复或失效，就说“这里可以优化”。
- 第一次变化里已经出现最终结构。
- 每个犹豫候选都恰好证明最终方法正确，像为了衬托答案补写的。
- 只有方法名，没有它替掉了哪份重复工作、依赖什么条件。
- 用“显然”“只需”“本质上”“核心就是”代替中间推导。
- 代码能运行，却说不清变量覆盖哪些题目对象、为什么必须按这个顺序更新。

提前出现方法名时，不删掉它装作没想过。把它标成记忆候选，暂时撤掉证明资格，回到最早缺失的阶段补证据。

## 卡住时只留五句

真正卡住时，不要只写“不会”。把断点写完整：

```text
我现在已经能确认：______
我现在还不能确定：______
这个空缺正在阻碍：______
因此下一个最小问题是：______
哪一种具体输入、例子、约束或手算结果能回答它：______
```

如果写不出“这个空缺正在阻碍什么”，当前通常不是推导断点，而是还没有认真读题或手算。下一问要小到能当场用原句、例子或一次演算回答，不能直接问“完整算法是什么”。

## 复习时怎样使用

复习不是把题解从第一行看到最后一行，也不是先看代码再倒推理由。闭卷按八个问题重走：

1. 我还能不能分开事实、推导和未知？
2. 我能不能用一个新例子把题目重新扩写成可执行过程？
3. 我能不能说清对象身份，并独立走完第一次人工过程？
4. 我能不能指出第一次变化和答案产生时刻？
5. 我能不能根据约束重新估算慢过程，并说明它排除了什么？
6. 我能不能重新找到重复、失效、复用或顺序约束，并说出所需操作？
7. 我能不能比较候选，完整说出方向确认句？
8. 我能不能从方向重建状态、更新顺序、不变量、代码和反例？

卡住时只打开最早断点对应的那一小段。不要因为代码熟悉就跳过题目事实，也不要因为看懂了最后一段就假装前面已经推导过。

状态允许时可以连续完成整条链；需要中断时保存五句断点，下一次从最早缺口继续。这里没有固定分钟数，也没有必须完成的题量。保存点只是保留上下文，不是欠账。
