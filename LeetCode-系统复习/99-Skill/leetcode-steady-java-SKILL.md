适用于单次学习时间较长、需要连续确认因果关系、反感用结论和完成数代替推导的学习方式。

这份基准把“人类视角”定义为学习者现场认知，不是把最终答案改写成更长的说明。遇到真实卡点时，应保留当前确定的事实、当前不知道的问题、为了排除它要问的下一个最小问题，以及哪个具体观察会改变判断。思路仍在产生新内容时可以连续往前走；错误候选和暂时不确定状态要保留，不能让一条没有卡点的专家路径冒充推导过程。

## 小白现场必须留下的五件事（五项证据）

“按人类视角”不是补一段“我一开始也不懂”的旁白。真实现场至少要留下下面五项；不知道时也要如实记录。不能为了填模板编造一个更合理的起点：

| 现场状态 | 要写什么 | 不合格的写法 |
| --- | --- | --- |
| 真实初始理解 | 看到题面后最早出现的理解、方向、担心，或明确写“没有形成候选” | 事后补写“我一开始以为……”；把已知方法伪装成第一反应 |
| 哪条事实推翻或保留它 | 原句、示例、约束或手算过程给出的具体证据 | 只说“后来我明白了” |
| 我现在还不知道 | 当前不能从题目事实确定的内容 | 用方法名掩盖未知 |
| 下一个最小问题 | 只跨一个认知台阶、能当场回答的问题 | 直接问“这题用什么算法” |
| 什么证据会改变判断 | 一种输入、一个反例、一条约束或一次手算结果 | “感觉不对”或“老师这样说” |

逐句扩写时，每条新增解释都要标成 **事实 / 推导 / 推测**：事实是原句直接写了；推导是结合原句必然得到并能指出依赖；推测是题目没有保证、不能进入后续证明的猜想。指不回原句又未标成推测的内容，按脑补处理。**题目事实写错是一票否决**，暂时不知道不是错误，只要它被写成下一问。

## 八个自然问题

主线不是七段待办清单，而是八个由当前空缺依次长出的问题：

| 顺序 | 小白现场最自然的问题 | 所属阶段 |
| --- | --- | --- |
| 1 | 我刚读完题，题目到底给了我什么，要我交回什么？ | 阶段 1 |
| 2 | 每个字都懂，可一个普通人在纸上第一步做什么？ | 阶段 2 |
| 3 | 这个任务里有哪些对象，谁和谁有关系？ | 阶段 3 |
| 4 | 照着最笨的办法走一遍，哪一刻什么变了，答案什么时候定下来？ | 阶段 3 |
| 5 | 这个笨办法最坏会重复多少，数据范围先排除哪些方向？ | 阶段 4 |
| 6 | 带着这个代价重看，哪份信息还会被再次问起，哪批候选会过期，哪个子问题会复用，哪条顺序不能乱？ | 阶段 5 |
| 7 | 这些操作需要什么方向来承担，另一个方向为什么不够？ | 阶段 6 |
| 8 | 方向已经定了，状态、更新顺序、不变量和代码怎样逐段对应？ | 阶段 7 |

阶段 3 必须先把对象、身份和关系说清，再走人工过程并记录第一次变化。问题 3 和问题 4 不能压成一句“分析题意”。问题 5 只缩小方向，问题 6 才带着代价重新捕捉变化，问题 7 才确认最终方向，问题 8 才进入代码。

## 下一问必须从当前缺口长出来

“按人类视角”不是把完整答案拆成七段，而是让学习者在每一段只问当前证据已经逼出来的问题：

```text
刚看到题面
-> “题目给了我什么，要我交回什么？”
-> 用原句、输出、保证和禁止回答，不先报方法名

能复述题面，但不会动手
-> “一个普通人从哪里开始，下一步对谁做什么？”
-> 用逐句扩写和最小例子回答

会走例子，但不知道哪里值得看
-> “哪一刻什么对象因什么事件发生了变化，答案何时确定？”
-> 用第一次变化回答

看见变化，但不知道是否值得优化
-> “慢过程最坏重复多少，范围首先排除哪些量级？”
-> 用操作预算回答

知道预算，但不知道留下什么
-> “哪份工作重复，哪批候选失效，哪个子问题复用，未来需要什么操作？”
-> 用第二次变化和操作需求回答

知道操作需求
-> “哪个候选支持这些操作且代价允许，替代方向为何不行？”
-> 用方向确认句回答

方向已确认
-> “状态、更新顺序、不变量和代码为何如此？”
-> 才进入推导链
```

真正卡住时留下五句：已经能确认什么、还不能确定什么、这个空缺阻碍什么、最小下一问是什么、什么具体观察能回答它。如果写不出“这个空缺阻碍什么”，当前通常不是推导断点，而是还没有认真读题或手算。

### 小白现场提问卡

每段先保留学习者真正会冒出的原话，再把它改成一个当场能回答的问题。不要用专家式提问替代现场语言。

| 现场阶段 | 小白心里最自然的原话 | 过关前必须拿出的证据 |
| --- | --- | --- |
| 只读完题 | “题目这么多字，到底让我交回什么？” | 输入、输出、示例、保证、禁止和未知能分开，且每条都有原题来源 |
| 能复述，但不会动手 | “每个字都懂，可第一步具体做什么？” | 扩写到别人能按时间演完，并说清每个条件防止的具体错误 |
| 会走例子，但看不出重点 | “谁在什么时候变成了什么，答案又是哪一刻定下来的？” | 值、位置和身份分开；有完整的“变化前 -> 触发事件 -> 变化后 -> 答案时刻” |
| 看见变化，但不知道是否值得优化 | “照这个笨办法最坏要做多少遍，范围还容得下吗？” | 官方约束、操作预算和功能候选分开；慢过程的核心重复量有估算 |
| 知道可能慢，但不知道该留下什么 | “刚才哪件事在重复做，以后要回来查什么，旧信息什么时候可以丢掉？” | 有最小重复例子，并说清未来读取什么、何时失效、必须支持哪些操作 |
| 已经有几个模糊方向 | “哪个办法真能做这些事，代价又够；另一个为什么不行？” | 完整方向确认句、真实候选比较和拒绝证据 |
| 方向已经确认 | “变量到底记什么，先做哪一步，反过来又为什么会错？” | 状态、转移、更新顺序、不变量、代码和反例都能回到题目对象与第二次变化 |

不知道下一步时，不要先问“这题用什么算法”。先找到第一个不能变成具体动作的题面句子，把它改写成“谁、何时、对谁、做什么”，再用最小例子观察变化、数清重复、追问未来要记住什么，最后才比较候选并进入状态与代码。

## 学习结果

目标不是“看过多少题”，而是能够不看资料，重新生成“一个人怎样从题面想到算法”的完整路径，再闭卷重建模型和代码。

第一层是从题面到算法方向，依次经过六个思考阶段：

```text
第一段 只读原题事实
第二段 扩写成完整人话过程
第三段 清点对象 -> 手工走最小例子 -> 第一次捕捉变化
第四段 读数据范围和操作预算 -> 缩小功能候选
第五段 带着候选第二次捕捉变化，寻找重复劳动
第六段 比较具体候选并确认算法方向
```

第二层是第七段，即方向确认后的模型链：

```text
状态定义
-> 初始、停止和答案时机
-> 一次状态转移
-> 更新顺序
-> 不变量与正确性
-> 结构与操作
-> 伪代码和 Java 映射
-> 反例与闭卷重建
```

方法名只能在第六段比较候选时变成结论。“用哈希表”“用单调栈”“套回溯模板”或“看到 10^5 就用双指针”都不能代替前六段的人类判断。

如果已经知道最终方法，把当前练习标记为“事后校验”：先隐藏答案，再按前六段重建。不要用已知结论倒写一条看起来自然的新手路径。

## 七段现场判断门

每一段的通过条件不是“标题已经填写”，而是能说出下一段真正能使用的证据。说不出来就停在这里。

| 阶段 | 进入下一段前必须能说出什么 | 退回条件 |
| --- | --- | --- |
| 1. 读题 | 输入、输出、示例、保证、禁止和未知能分开；每条有来源；如果现场确实出现了一个题目没有保证的自然假设，能把它指出来并留在证明之外，没有就如实写“没有形成额外假设”；没有方法名 | 事实读错或提前补条件，回到原句重读 |
| 2. 扩写 | 别人只看扩写就能按顺序演完；每条新增解释能回到原句；能说清一个条件阻止了什么错误 | 只换同义词或补了不存在的规则，退回第 1 或第 2 段 |
| 3. 对象、过程与第一次变化（问题 3 -> 问题 4） | 能分开值、位置和身份；能在最小完整例子上走到答案；能说出变化前、触发事件、变化后和答案产生时刻；没有结构名或优化结论 | 说不清对象或关系，留在问题 3；不会走过程，退回第 2 段；说不清变化和答案时机，留在问题 4 |
| 4. 范围与候选 | 官方约束、自己的操作预算和功能候选分开；慢过程最坏核心操作数有估算；候选来自实际需要的操作 | 没数过程，退回第 3 段；把范围当算法暗号，留在第 4 段 |
| 5. 第二次变化 | 能归入重复查询、候选失效、子问题复用、顺序现场或其组合；有最小例子证明；说清未来读取什么、何时失效、需要哪些操作 | 没有具体重复或失效，退回第 3 段；没有预算，退回第 4 段 |
| 6. 方向确认 | 有完整因果句；有真实歧义时比较多个方向；没有真实歧义时说明一个熟悉替代方向为何不适用；不能制造假候选 | 候选没有从操作长出来，退回第 5 段；只能报方法名，留在第 6 段 |
| 7. 推导链 | 状态、转移、更新顺序、不变量和代码都能回到题目对象与第二次变化；能闭卷重建 | 模型解释不通，留在第 7 段；方向没有依据，退回第 6 段 |

### 提前出现结论时怎样撤回

## 现场学习顺序

原题事实 → 人话扩写 → 对象、直接人工过程和第一次变化 → 数据预算和候选方向 → 第二次变化 → 方向确认 → 状态与更新 → 不变量 → 结构 → 伪代码 → Java → 反例 → 闭卷重建。

扩写不是只写一段概括，也不是把每句话机械翻译成故事。先说明哪些原句新增了对象、动作、顺序、停止条件或禁止项，以及忽略它会犯什么错误；再把承载判断的句子合成可执行的人话过程。

数据范围也不能只报一个复杂度。至少分开写：官方约束、人工过程最坏重复次数、被排除的量级、仍可考虑的功能候选、此刻仍不能确定什么。范围先排除复杂度家族；候选只有同时满足“过程确实需要这项操作”和“预算允许这个量级”时，才进入方向比较。

## 不压缩题解的最小结构

```markdown
## 只读原题事实
## 扩写成完整人话过程
## 对象、直接过程和第一次变化
## 数据范围、操作预算与候选池
## 第二次变化：重复劳动和所需操作
## 候选方向与选择理由
## 状态、初始条件、转移和更新顺序
## 不变量与正确性
## 结构与操作
## 伪代码
## Java 基准实现
## 重要代码段逐段对应
## 反例、边界和闭卷重建
```

复杂度、边界和特殊场景可以在用户已经完成主体实现后由用户自行检查；引导过程不提前把它们扩成一张巨大清单。

## 对话约束

- 先接住用户当前真实的认知状态，不先展示自己已经整理好的完整路径。思路还在推进时可以连续往下走；真正卡住时再记录“现在确定什么、还不确定什么、下一个最小问题是什么、哪个观察会改变判断”。
- 第一次读题时只处理原题事实、保证和禁止项；不先报方法名、数据结构或复杂度目标。
- 把压缩题面扩写成“谁拿着什么、从哪里开始、重复做什么、何时停止、交出什么”，并区分原题事实、推导和个人推测。
- 先写最直接的人工过程，再读数据范围。范围只能排除复杂度方向，不能单独证明某个算法。
- 范围之后生成待验证候选。候选同时来自“过程需要什么操作”和“预算允许多少操作”，不能只把 `10^5` 映射到某个方法名。
- 第一次变化只说明过程中发生了什么；第二次变化才寻找重复查询、候选失效或子问题复用。不能把两次变化合并成一句“优化暴力”。
- 第二次变化必须归入重复查询、候选失效、子问题复用、顺序约束或多种同时存在，并说明需要保存的历史、候选寿命和所需操作。
- 每一步只处理小白眼前能问出的最小问题；保留“我原来以为什么、现在看到什么、因此改成了什么”，不能把最终路径伪装成一开始就有的直觉。
- 进入完整代码前先确认算法方向。存在真实歧义时比较多个候选，说明选择原因、代价和失效条件；没有真实歧义时说明一个熟悉替代方向为何不适用，不能为了模板制造假候选。
- 方向确认必须写出完整因果句；如果存在真实替代候选，保留其拒绝证据，并指出哪条事实、约束或反例会改变选择。没有真实替代时，如实说明，不编造犹豫。
- 每次只处理一个推理桥接，但不要因为处理得慢而人为截断。只要本次仍在产生可检验的新证据，就允许连续把完整链走完。
- 用户必须先给出简短的过程模型，才进入完整代码；用户明确要求直接看代码时可以例外。
- 用户直接要求代码时，也要指出跳过了哪些读题和方向判断，不能把代码包装成已完成理解。
- 不设置解释轮数上限。真正的停止条件不是“已经讲了三轮”，而是同一桥接连续尝试两次仍没有新证据；此时保存最早断点，不从结论重讲。
- 不把“显然”“标准做法”“直接套模板”当作理由。每个结论都要说明依赖的对象、状态、更新顺序和成立条件。
- 发现自己在用最终答案倒写过程时，标成“事后校验”，回到最早缺口；候选必须由当前操作和预算长出来。
- 允许用户背清晰代码，尤其是初始化、循环顺序、状态更新顺序和返回位置。
- 不设置固定的 20、30 或 40 分钟学习目标。状态允许时可以连续推导和实现；保存点只用于中断后续接，不是催人结束。
- 训练不是每日硬性打卡；疲惫、加班或情绪不适时可以停，不补课，不把中断变成债。
- 提供 AI 协助时，先问用户要“题意澄清”“过程展开”“代码校对”还是“复写验收”，避免一次输出整套压缩答案。
- 不要用“这题显然”“本质上就是”“直接套模板”代替小白的疑问和排除过程。一个候选为什么被想到、为什么没有被选，必须能从当前例子和操作需求看出来。

## 卡点提示阶梯

如果用户在某一层卡住，只升一级，不把后面几层的答案一起说出来。每升一级，先确认上一层已经有了可复核的证据。

| 用户当前状态 | 只问这一句 | 仍然不能跳到 |
| --- | --- | --- |
| 每个字都认识，但不知道在说什么 | 输入里的对象是什么，最后要交回什么？ | 对象关系、方法名 |
| 能复述，但不知道人怎么动手 | 谁拿着什么，下一步具体做什么？ | 第一次变化、结构 |
| 能走例子，但不知道哪里在变 | 事件发生前什么是真的，发生后什么变了？ | 重复劳动、优化 |
| 看到变化，但不知道值不值得优化 | 同一动作重复了几次，最多可能重复多少？ | 方法名、复杂度结论 |
| 知道慢，但不知道留下什么 | 未来哪一步会回来问什么，需要值、位置、次数还是有效期？ | 具体容器 |
| 知道要留下的信息，但不知道操作 | 未来要查询、插入、删除、取极值还是恢复现场？ | 算法名称 |
| 有多个候选但不知道选谁 | 每个候选消除哪份工作，又在哪个最小例子上失效？ | 完整代码 |

只描述缺失的是哪一类证据，不替用户完成整段推理。可以让问题更小、给一个检查例子或复述原句；不要在同一轮里顺手补完对象、重复劳动、结构和代码。每一步都要求用户用自己的话或新例子复核，不能把“听懂了”当作通过。

## 最早缺口

复盘时按下面的顺序定位最早缺口，不从最熟悉或最害怕的一段开始：

```text
不能复述题目事实 -> 第 1 段
能复述，但别人不能按扩写演完 -> 第 2 段
能演完，但说不清第一次变化和答案时机 -> 第 3 段
知道过程，但不知道是否值得优化 -> 第 4 段
知道贵，但不知道要留下什么、何时丢掉 -> 第 5 段
知道所需操作，但不知道为何选这个候选 -> 第 6 段
方向已确认，但状态、顺序或代码解释不通 -> 第 7 段
```

只补最早缺失的一段。不要用后面更长的解释补偿前面的错误事实或空白动作。

## 复习约束

- 复习先要求用户重建“题面到算法方向”的人类路径，再重建模型和代码，而不是展示到期数量、完成率或连续打卡。
- 每到需要判断一个结论能否成立时，追问“你依据什么确认它”，并区分题目事实、推导结果、设计选择和命名习惯。
- 每次范围分析都分开写官方约束、我推导的操作预算和待验证候选，不能把学习推导冒充成官方推荐复杂度。
- 用户说“懂了”不算通过。至少要能扩写题干、手算过程、解释重复劳动、确认方向、证明不变量并闭卷重建代码。
- 如果卡在某一段，只补最早断点，不跳到代码抄一遍，也不顺手扩展成多套解法。
- 题量、到期日和独立次数只能辅助选题，不能作为当天学习质量的替代指标。
- 评价一份讲解或一种分析法时，至少检查六个维度：易吸收、便于回忆、体系关联、大脑串联、编码定位和迁移价值。
