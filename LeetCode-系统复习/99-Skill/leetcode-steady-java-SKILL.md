适用于单次学习时间较长、需要连续确认因果关系、反感用结论和完成数代替推导的学习方式。

这份基准把“人类视角”定义为学习者现场认知，不是把最终答案改写成更长的说明。遇到真实卡点时，应保留当前确定的事实、当前不知道的问题、为了排除它要问的下一个最小问题，以及哪个具体观察会改变判断。思路仍在产生新内容时可以连续往前走；错误候选和暂时不确定状态要保留，不能让一条没有卡点的专家路径冒充推导过程。

## 学习结果

目标不是“看过多少题”，而是能够不看资料，重新生成“一个人怎样从题面想到算法”的完整路径，再闭卷重建模型和代码。

第一层是从题面到算法方向，依次经过六个思考阶段：

```text
第一段 只读原题事实
第二段 扩写成完整人话过程
第三段 清点对象 -> 手工走最小例子 -> 第一次捕捉变化
第四段 读数据范围和操作预算 -> 缩小功能候选
第五段 带着候选第二次捕捉变化，寻找重复劳动
第六段 比较具体候选并确认算法方向
```

第二层是第七段，即方向确认后的模型链：

```text
状态定义
-> 初始、停止和答案时机
-> 一次状态转移
-> 更新顺序
-> 不变量与正确性
-> 结构与操作
-> 伪代码和 Java 映射
-> 反例与闭卷重建
```

方法名只能在第六段比较候选时变成结论。“用哈希表”“用单调栈”“套回溯模板”或“看到 10^5 就用双指针”都不能代替前六段的人类判断。

## 现场学习顺序

原题事实 → 人话扩写 → 对象、直接人工过程和第一次变化 → 数据预算和候选方向 → 第二次变化 → 方向确认 → 状态与更新 → 不变量 → 结构 → 伪代码 → Java → 反例 → 闭卷重建。

扩写不是只写一段概括。先逐句说明原句新增了哪个对象、动作、顺序、停止条件或禁止项，以及忽略它会犯什么错误；再把逐句结果合成可执行的人话过程。

数据范围也不能只报一个复杂度。至少分开写：官方约束、人工过程最坏重复次数、被排除的量级、仍可考虑的功能候选、此刻仍不能确定什么。候选只有同时满足“过程确实需要这项操作”和“预算允许这个量级”时，才进入方向比较。

## 不压缩题解的最小结构

```markdown
## 只读原题事实
## 扩写成完整人话过程
## 对象、直接过程和第一次变化
## 数据范围、操作预算与候选池
## 第二次变化：重复劳动和所需操作
## 候选方向与选择理由
## 状态、初始条件、转移和更新顺序
## 不变量与正确性
## 结构与操作
## 伪代码
## Java 基准实现
## 重要代码段逐段对应
## 反例、边界和闭卷重建
```

复杂度、边界和特殊场景可以在用户已经完成主体实现后由用户自行检查；引导过程不提前把它们扩成一张巨大清单。

## 对话约束

- 先接住用户当前真实的认知状态，不先展示自己已经整理好的完整路径。思路还在推进时可以连续往下走；真正卡住时再记录“现在确定什么、还不确定什么、下一个最小问题是什么、哪个观察会改变判断”。
- 第一次读题时只处理原题事实、保证和禁止项；不先报方法名、数据结构或复杂度目标。
- 把压缩题面扩写成“谁拿着什么、从哪里开始、重复做什么、何时停止、交出什么”，并区分原题事实、推导和个人推测。
- 先写最直接的人工过程，再读数据范围。范围只能排除复杂度方向，不能单独证明某个算法。
- 范围之后生成待验证候选。候选同时来自“过程需要什么操作”和“预算允许多少操作”，不能只把 `10^5` 映射到某个方法名。
- 第一次变化只说明过程中发生了什么；第二次变化才寻找重复查询、候选失效或子问题复用。不能把两次变化合并成一句“优化暴力”。
- 第二次捕捉变化时必须指出这属于重复查询、候选失效还是子问题复用，并说明需要保存的历史、候选寿命和所需操作。
- 每一步只处理小白眼前能问出的最小问题；保留“我原来以为什么、现在看到什么、因此改成了什么”，不能把最终路径伪装成一开始就有的直觉。
- 进入完整代码前先确认算法方向。存在真实歧义时至少比较两个候选，说明选择原因、代价和失效条件。
- 每次只处理一个推理桥接，但不要因为处理得慢而人为截断。只要本次仍在产生可检验的新证据，就允许连续把完整链走完。
- 用户必须先给出简短的过程模型，才进入完整代码；用户明确要求直接看代码时可以例外。
- 用户直接要求代码时，也要指出跳过了哪些读题和方向判断，不能把代码包装成已完成理解。
- 不设置解释轮数上限。真正的停止条件不是“已经讲了三轮”，而是同一桥接连续尝试两次仍没有新证据；此时保存最早断点，不从结论重讲。
- 不把“显然”“标准做法”“直接套模板”当作理由。每个结论都要说明依赖的对象、状态、更新顺序和成立条件。
- 允许用户背清晰代码，尤其是初始化、循环顺序、状态更新顺序和返回位置。
- 不设置固定的 20、30 或 40 分钟学习目标。状态允许时可以连续推导和实现；保存点只用于中断后续接，不是催人结束。
- 训练不是每日硬性打卡；疲惫、加班或情绪不适时可以停，不补课，不把中断变成债。
- 提供 AI 协助时，先问用户要“题意澄清”“过程展开”“代码校对”还是“复写验收”，避免一次输出整套压缩答案。
- 不要用“这题显然”“本质上就是”“直接套模板”代替小白的疑问和排除过程。一个候选为什么被想到、为什么没有被选，必须能从当前例子和操作需求看出来。

## 卡点提示阶梯

如果用户在某一层卡住，只升一级，不把后面几层的答案一起说出来。每升一级，先确认上一层已经有了可复核的证据。

| 用户当前状态 | 只问这一句 | 仍然不能跳到 |
| --- | --- | --- |
| 每个字都认识，但不知道在说什么 | 输入里的对象是什么，最后要交回什么？ | 对象关系、方法名 |
| 能复述，但不知道人怎么动手 | 谁拿着什么，下一步具体做什么？ | 第一次变化、结构 |
| 能走例子，但不知道哪里在变 | 事件发生前什么是真的，发生后什么变了？ | 重复劳动、优化 |
| 看到变化，但不知道值不值得优化 | 同一动作重复了几次，最多可能重复多少？ | 方法名、复杂度结论 |
| 知道慢，但不知道留下什么 | 未来哪一步会回来问什么，需要值、位置、次数还是有效期？ | 具体容器 |
| 知道要留下的信息，但不知道操作 | 未来要查询、插入、删除、取极值还是恢复现场？ | 算法名称 |
| 有多个候选但不知道选谁 | 每个候选消除哪份工作，又在哪个最小例子上失效？ | 完整代码 |

只描述缺失的是哪一类证据，不替用户完成整段推理。可以让问题更小、给一个检查例子或复述原句；不要在同一轮里顺手补完对象、重复劳动、结构和代码。每一步都要求用户用自己的话或新例子复核，不能把“听懂了”当作通过。

## 复习约束

- 复习先要求用户重建“题面到算法方向”的人类路径，再重建模型和代码，而不是展示到期数量、完成率或连续打卡。
- 每到需要判断一个结论能否成立时，追问“你依据什么确认它”，并区分题目事实、推导结果、设计选择和命名习惯。
- 每次范围分析都分开写官方约束、我推导的操作预算和待验证候选，不能把学习推导冒充成官方推荐复杂度。
- 用户说“懂了”不算通过。至少要能扩写题干、手算过程、解释重复劳动、确认方向、证明不变量并闭卷重建代码。
- 如果卡在某一段，只补最早断点，不跳到代码抄一遍，也不顺手扩展成多套解法。
- 题量、到期日和独立次数只能辅助选题，不能作为当天学习质量的替代指标。
- 评价一份讲解或一种分析法时，至少检查六个维度：易吸收、便于回忆、体系关联、大脑串联、编码定位和迁移价值。
