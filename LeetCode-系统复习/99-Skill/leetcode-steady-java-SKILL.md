# LeetCode Steady Java

这是本用户 LeetCode Hot 100 学习与复习的唯一基准。用户已经做过大部分题，
熟悉常见数据结构和 DFS/BFS，但仍需要稳定复现代码，并对贪心、较难动态规划、
回溯以及“为什么现在会想到这一步”的连续确认有更高要求。

这份基准中的“人类视角”指学习者现场真实能确认的认知状态，不是把专家答案改写得更长。
每个结论都必须由上一份证据逼出来。允许暂时不知道、保留错误候选、停在最小问题上；
不允许用一条没有卡点的专家路径冒充推导，也不允许用题量、完成感或代码运行结果代替理解。

开始做题时，先打开标准卡里的“一张现场纸”，不要先背九个标题。第一遍只读题意、示例和返回要求，
暂时遮住数据范围、标签、题解和讨论区。纸上只允许出现当前一步能核对的产物：

```text
题目事实 -> 可执行人话 -> 对象表 -> 最小例子的逐行过程 -> 第一次变化
-> 范围预算与待验证方向 -> 第二次变化 -> 方向确认 -> 状态、代码和反例
```

数据范围只能回答“当前慢过程是否超预算、哪些复杂度家族先排除”，不能直接回答“该用哪个算法”。

现场每次换动作只写五句；九字段只在整题完成后复盘：

```text
我现在只能确认：______
它还不够回答：______
因此现在只做：______
做完必须多出的证据：______
证据不足就退回：______
```

## 唯一的现场顺序：七阶段、九次交接

开始一道题时，不先背九问和验收表，只按下面顺序推进：

```text
阶段 1：交接 1  原题事实
阶段 2：交接 2  人话扩写
阶段 3：交接 3  对象
        交接 4  最笨但正确的过程
        交接 5  第一次变化与答案确定时刻
阶段 4：交接 6  数据范围与慢过程预算
阶段 5：交接 7  第二次变化
阶段 6：交接 8  候选比较与方向确认
阶段 7：交接 9  状态、更新顺序、不变量、代码、反例
```

阶段 3 必须拆成三次独立交接。不能把对象、过程和第一次变化压成一句“分析题意”。
数据范围只能在第一次变化之后、第二次变化之前读取。它先排除复杂度家族，也可以触发记忆中的
待验证方向；方法名可以出现在明确标记的待验证区，但必须写清依赖条件、想消除的重复工作、
预算和缺失证据。交接 7 回过程取证，交接 8 才允许选择，方向确认后才进入代码。

## 小白为什么会自然走到下一步

不能把专家结论改写成“小白也会这么想”。每一步都必须由上一份证据留下的空缺逼出来：

| 当前证据 | 还缺什么 | 下一句自然只能是 |
| --- | --- | --- |
| 只读到题面文字 | 不知道要交回什么 | 题目给了我什么，要我交回什么？ |
| 输入输出已经分开 | 不知道人的动作顺序 | 一个人先拿什么、做什么、何时停？ |
| 动作里有值和位置 | 不知道相同值是否同一对象 | 里面的对象怎样区分身份？ |
| 对象已经分清 | 还没有真实执行 | 最笨但正确的过程怎样走？ |
| 慢过程已经走完 | 不知道答案何时确定 | 哪一刻什么变了，答案何时算定？ |
| 第一次变化已经写出 | 不知道是否超预算 | 最坏重复多少，范围排除哪些量级？ |
| 知道可能太贵 | 不知道留下什么、何时丢掉 | 哪份信息重复、失效、复用或必须保序？ |
| 操作需求已经具体 | 不知道由什么承担 | 哪个候选支持这些操作，另一个为什么不够？ |
| 方向已经确认 | 还不能保证状态和顺序正确 | 对象怎样变成状态、代码和不变量？ |

数据范围不能提前当暗号。没有完整慢过程，就不知道一轮在重复什么、最多重复多少轮；
范围只缩小复杂度家族和候选空间，最终方向仍要由第二次变化和候选比较确认。

## 完成后的九字段留痕（不是起步模板）

整条现场走完后，再用下面九项保存每次交接的证据。它不是开始前要填的表格，也不能替代纸算、例子和比较：

```text
小白此刻真正的原话疑问：______
为什么这个疑问现在才出现：______
纸上实际做了什么：______
做完后新增了什么证据：______
这份证据只能说明什么：______
它还不能说明什么：______
因此下一问只能是什么：______
回答它需要什么证据：______
如果答不出，退回哪里：______
```

“纸上实际做了什么”必须是可核对的动作：圈出一句原题、写出两个候选位置、
补一行人工过程、走一个最小例子、数一轮重复、标出一个失效时机，或比较两个候选。
只写“想了想”“分析了一下”不算证据。

回答下一问只允许使用一条原句、一个最小例子、一次手算、一次预算或一项候选比较。
没有真实候选时写“没有形成候选”；没有真实转折时写“没有发生转折”。
不能为了显得像新手而补造“我一开始以为”。

## 九次交接的证据检查

| 交接 | 所处阶段 | 小白此刻只能问什么 | 纸上动作 | 新增证据 | 仍然不能做什么 |
| --- | --- | --- | --- | --- | --- |
| 1. 原题事实 | 阶段 1 | 题目给了我什么，要我交回什么？ | 圈返回要求，分栏抄输入、输出、保证、禁止、示例和未知 | 每项能指回原句 | 不能把方法名、标签或记忆当成题目事实 |
| 2. 人话扩写 | 阶段 2 | 一个人拿着什么，从哪里开始，何时停止？ | 替换代词，逐句写动作、顺序、停止条件和它防住的错误 | 别人能按时间执行的人话过程 | 不能优化，不能补题目没保证的规则 |
| 3. 对象 | 阶段 3 | 谁是一个独立对象，值和位置怎样分开，这份状态能保留到什么时候？ | 圈身份条件；把相同值放在不同位置；写寿命、关系和结果归属 | 每个对象的身份、位置或时间、有效期、关系和目标 | 不能先列代码容器，不能把相同值合成一个对象 |
| 4. 最笨但正确的过程 | 阶段 3 | 最直接的人类办法先看谁，接着看谁，何时停？ | 用最小完整例子逐行演算 | 一条能复走的人工过程 | 不能写优化理由，不能用输入输出摘要代替演算 |
| 5. 第一次变化 | 阶段 3 | 谁因哪个事件从什么状态变成什么状态，答案凭什么此刻确定？ | 标出谁发生变化、触发事件、变化前、变化后、答案确定时刻和为什么不是更早或更晚 | 第一次变化和答案确定时刻 | 不能回答该保存什么，不能出现最终结构 |
| 6. 数据范围 | 阶段 4 | 慢过程最坏重复多少次，范围允许保留哪些量级，哪些方向只能先算待验证？ | 抄全约束，选最坏输入，数一轮并乘轮数；把脑中方向另栏标记为待验证 | 官方约束、自己的操作预算、被排除的复杂度家族，以及未获证明资格的待验证方向 | 不能直接宣布最终方向；出现方法名时必须写清依赖条件、要解决的重复工作、预算和缺失证据 |
| 7. 第二次变化 | 阶段 5 | 哪份信息重复读取、过期、复用或必须保序？ | 回到同一条过程，用最小例子逐类取证，再写成操作动词 | 重复、寿命、复用或顺序证据，以及操作需求 | 不能报容器，不能把候选池当结论 |
| 8. 方向确认 | 阶段 6 | 哪个候选真能承担这些操作，另一个为什么不够？ | 比较支持、缺口、失效条件和代价，写完整因果句 | 有取舍依据的方向确认句 | 不能只有方法名，不能提前写完整代码 |
| 9. 完整思维链 | 阶段 7 | 对象怎样变成状态，先更新谁，为什么不会漏？ | 逐段接对象、动作、操作、状态、代码、顺序、不变量和反例 | 可闭卷重建的完整链 | 不能换方向，不能用运行通过补推导 |

## 阶段 1：原题事实

只打开原题，不先看题解、标签、讨论区和数据范围。先确认：

- 输入对象是什么；
- 输出要交回数量、值、下标、路径、布尔值还是整个结构；
- 示例怎样从输入走到输出；
- 题目明确保证什么、明确禁止什么；
- 哪些问题原题没有回答；
- 自己现在真实知道什么、真实不知道什么。

逐句扩写时，每条新增解释标成 `事实`、`推论` 或 `推测`：

- 事实是原句直接写了；
- 推论是由已确认事实必然得到；
- 推测是题目没有保证，不能进入后续证明。

**题目事实写错是一票否决。** 暂时不知道不是错误，但必须变成下一问。
脑中先出现方法名时，标成“记忆候选，不是题目事实”，暂时撤掉证明资格。
已经知道答案但仍要重走理解链时，标记为“事后重建”，先隐藏答案，再严格从原题生成证据。
只检查已有答案、代码、反例或闭卷重建结果时，标记为“事后校验”，不能用它倒写前面的推导。

## 阶段 2：人话扩写

能复述文字，不等于知道人的动作顺序。逐句问：

1. 它新增了什么对象、身份、动作、顺序、停止条件或禁止项？
2. 如果忽略它，具体会在哪一步做错？
3. 它要求谁先处理、谁后处理，哪个对象不能提前丢掉？

先把每个关键原句填进同一张表：

| 原句 | 我自己的话 | 它要求我做什么动作 | 忽略后具体错在哪 | 来源：事实 / 推论 / 推测 |
| --- | --- | --- | --- | --- |
|  |  |  |  |  |

最后必须合成一段别人能照着执行的过程：

```text
我手里有：______
我从：______ 开始
我反复做：______
条件“______”意味着我不能：______
当：______ 时停止
我最后要交出：______
```

扩写阶段不写优化理由、方法名、结构名或复杂度目标。

## 阶段 3：对象、慢过程、第一次变化

阶段 3 内部有三次独立交接。交接 3 完成前不进入交接 4；交接 4 完成前不进入交接 5。

### 交接 3：对象

先做一个能产生身份证据的纸面动作。对象表使用七列：

| 题目对象 | 值和状态 | 身份由什么决定 | 位置或时间 | 从何时有效到何时失效 | 和谁发生关系 | 最终要得到什么 |
| --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |

必须区分值、位置或时间、身份、有效期和关系。值相同不代表对象相同；
要求返回原下标时，两个相同的值不能合并成一个没有位置的对象。

### 交接 4：最笨但正确的过程

对象分清后，用一个最小但完整的例子，按人最直接会做的顺序走一遍：

| 步骤 | 我现在看见什么 | 这一步处理谁 | 具体做什么 | 做完后什么变了 | 为什么还能继续 |
| --- | --- | --- | --- | --- | --- |
| 1 |  |  |  |  |  |

如果某一步只能靠“然后算法会……”补上，说明还没有人工过程。
例子太复杂就缩小；看不到关键关系就增加一个能触发关系的对象。

### 交接 5：第一次变化与答案确定时刻

过程走完后，才允许观察：

```text
谁发生变化：______
触发事件：______
变化前：______
变化后：______
答案确定时刻：______
为什么不是更早或更晚：______
```

它只能回答“哪个对象因为哪个事件，从什么状态变成什么状态，答案为什么恰好在这一刻确定”。
它不能回答“哪份工作重复、应该保存什么、最终用什么结构”。
求最大值、最小值或最近值时，第一次算出候选通常只是第一次状态变化；
只有唯一性保证命中，或已经证明其余候选被淘汰，才叫答案确定时刻。

## 阶段 4：数据范围与慢过程预算

第一次变化说明过程里发生了什么，但没有说明这份慢是否值得处理。现在才读完整约束。

```text
慢过程重复的核心动作：______
每一轮大约做多少次：______
最多有多少轮：______
合起来大约是：______
```

然后用范围判断：

1. 哪些复杂度家族不能稳定承受最坏输入；
2. 当前过程仍保留哪些功能方向；
3. 还缺什么过程证据，才能决定保留哪个方向。

读完范围后想起熟悉方法很常见，不要假装没有。先把它降级成待验证方向：

```text
范围后想到的方向：______（没有形成方向就写“没有形成方向”）
它可能消除的重复或失效工作：______
它依赖的题目条件：______
最坏预算是否允许：______
目前仍缺少什么过程证据：______
它还不能被选为主方向，因为：______
```

方法名只有在六项都写清后才算“待验证方向”，仍然没有选择资格。范围只排除复杂度家族，
不能替人宣布算法；选择留到交接 8。数据范围只能回答“当前慢过程是否超预算、哪些复杂度家族
先排除”，不能直接回答“该用哪个算法”。

## 阶段 5：第二次变化

带着阶段 4 的代价，回到同一条人工过程，寻找四类真实现象：

| 现象 | 小白要问 | 需要的证据 |
| --- | --- | --- |
| 重复查询 | 同一个问题会不会被以后再问一次？ | 哪份历史能回答，未来读取值、位置还是次数 |
| 候选失效 | 哪个事件后，一批对象已经不可能产生答案？ | 失效条件是什么，为什么能安全丢掉 |
| 子问题复用 | 不同路径会不会到达同一个更小问题？ | 重复出现的最小例子和需要保存的结果 |
| 顺序约束 | 新对象从哪一端加入，又从哪一端结算？ | 为什么这个顺序不会漏掉仍可能的候选 |

四类都要逐项给出“发生”或“没有形成该现象”。没有发生就到此为止，
不能补一个现场没出现过的现象。

把真实发生的变化翻译成操作，而不是容器：

```text
需要加入什么：______
需要查询什么：______
需要删除或结算什么：______
读取和删除必须遵守什么顺序：______
```

## 阶段 6：候选比较与方向确认

操作需求已经具体，才允许具体方法名进入比较：

| 候选 | 支持哪些操作 | 缺少什么 | 何时失效 | 时间、空间和额外维护代价 |
| --- | --- | --- | --- | --- |
|  |  |  |  |  |

没有真实歧义时，不必为了凑数量编一个自己从没考虑过的方案；
但仍要说明当前方向为什么能承担阶段 5 的操作。

完整方向确认句必须是一条因果链：

> 因为慢过程在 ______ 上重复，最坏预算是 ______；第二次变化证明未来需要 ______ 操作；
> 候选 A 支持 ______，但缺少 ______；候选 B 能承担 ______，代价是 ______；
> 所以当前方向选择 ______。

## 阶段 7：状态、更新顺序、不变量、代码、反例

方向已经确认，不再比较新方向。按下面顺序逐段接上：

1. 每个状态在题目世界里代表哪个对象，覆盖什么，不覆盖什么；
2. 初始值、停止条件和答案写入时机对应什么现实动作；
3. 一次转移拆成读取、计算、写入；
4. 交换两个更新动作，用最小输入证明具体错误；
5. 写不变量，解释为什么不会漏、不会重复、为什么可以安全删除；
6. 从操作反推结构，再写伪代码和 Java；
7. 关键代码逐段映射回题目对象、人工动作和操作需求；
8. 用反例、边界和闭卷重建检查整条链。

代码映射表：

| 题目对象 | 人工过程里的动作 | 第二次变化提出的操作要求 | 状态变量 | 伪代码 | Java 代码位置 | 更新顺序或不变量 | 对应反例 |
| --- | --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |  |

只写“可能出错”不够。最小反例必须真的让状态、不变量或更新顺序失效，
并指出错误最早发生在哪一步。

## 完成后的九问只用于诊断

九问不是另一套现场主线，不能在开始前逐条背诵。完成整条链后，再用它定位最早断点：

| 事后问题 | 对应交接 |
| --- | --- |
| 题目给了我什么，要我交回什么？ | 1 |
| 一个普通人在纸上第一步做什么？ | 2 |
| 有哪些对象，谁和谁有关系？ | 3 |
| 最笨但正确的过程怎样走？ | 4 |
| 哪一刻什么变了，答案何时确定？ | 5 |
| 最坏重复多少，范围排除哪些复杂度家族？ | 6 |
| 哪份信息会重复、过期、复用或必须保序？ | 7 |
| 哪个候选能承担操作，完整方向确认句是什么？ | 8 |
| 对象怎样变成状态、顺序、不变量、代码和反例？ | 9 |

九问只用于回查，不改变现场顺序；交接 9 不能反过来替交接 3 到 8 补证据。

## 小白动作与推理转折

不知道方法时，不要求先产生正确直觉。先做一个纸面动作：

| 最早卡点 | 现在先做 | 做完后多出的证据 | 仍然不能做 |
| --- | --- | --- | --- |
| 只知道题面文字 | 圈出返回要求，分开写给我什么和交回什么 | 输入、输出、边界和未知 | 猜方法 |
| 知道要求但不会动 | 把代词换成具体对象，写谁拿着什么、下一步做什么 | 可执行的人话过程 | 提前优化 |
| 对象混在一起 | 给对象写值、位置或时间、身份和关系 | 能分开值和对象身份 | 先列代码容器 |
| 能说过程但不会走 | 用最小完整例子逐步写读谁、比较谁、写什么 | 人工过程和第一次变化 | 用摘要代替演算 |
| 看见变化但不知道是否值得处理 | 在最坏输入上数重复动作并加总 | 操作预算 | 从 `n` 直接点名算法 |
| 知道贵但不知道留下什么 | 标出历史信息第二次被读取的位置、失效时机和所需操作 | 重复、寿命和操作需求 | 把候选池当结论 |
| 已经能说出操作 | 把操作写成加入、查询、删除、取极值、恢复现场 | 候选比较依据 | 只报方法名 |
| 方向已经确认 | 把对象、动作、状态、伪代码、Java 位置和反例接起来 | 推导链和对应反例 | 让运行通过补推导 |

每一步留下：

```text
当前最早空缺：______
第一件实际做的纸面动作：______
做完后多出的证据：______
此刻真实候选：______（没有形成候选就写“没有形成候选”）
下一步只问：______
```

真实出现判断变化时，保留：

```text
我原来看到或以为：______
当时支持它的证据是：______
后来哪个最小例子、原句或约束让它不能继续：______
因此我现在只修正：______
我接下来做的纸面动作是：______
做完以后，哪项证据能告诉我可以继续：______
```

## 对话约束

- 先接住用户当前真实认知状态，不先展示完整专家路径。
- 第一次读题只处理原题事实、保证和禁止项，不报方法名、结构名或复杂度目标；数据范围后想到的方法必须先降级成待验证方向。
- 每次只跨一个认知台阶。链条仍在产生可核对的新证据时，允许连续走完，不人为截断。
- 不用“显然”“核心就是”“本质上”“直接套模板”代替中间推导。
- 用户说“懂了”不算通过。至少能扩写、手算、解释第二次变化、确认方向、证明不变量并闭卷重建。
- 用户要求直接看代码时，也要指出跳过了哪些事实、过程和方向判断，不能把代码包装成已完成理解。
- 候选必须从当前操作和预算长出来。已知答案但重走理解链时先标“事后重建”；只检查已有答案、代码或反例时标“事后校验”，不能倒写新手直觉。
- 允许用户背清晰代码，尤其是初始化、循环顺序、状态更新顺序和返回位置。

## 卡点提示阶梯

只升一级，不把后面几层的答案一起说出来：

| 当前状态 | 只问这一句 | 仍然不能跳到 |
| --- | --- | --- |
| 每个字都认识，但不知道在说什么 | 输入里的对象是什么，最后要交回什么？ | 对象关系、方法名 |
| 能复述，但不知道人怎么动手 | 谁拿着什么，下一步具体做什么？ | 对象表、第一次变化、结构 |
| 能走例子，但不知道哪里在变 | 事件发生前什么是真的，发生后什么变了？ | 重复劳动、优化 |
| 看到变化，但不知道值不值得优化 | 同一动作重复几次，最多重复多少？ | 方法名、复杂度结论 |
| 知道慢，但不知道留下什么 | 未来哪一步会回来问什么，需要值、位置、次数还是有效期？ | 具体容器 |
| 知道要留下的信息，但不知道操作 | 未来要查询、插入、删除、取极值还是恢复现场？ | 算法名称 |
| 有多个候选但不知道选谁 | 每个候选消除哪份工作，又在哪个最小例子上失效？ | 完整代码 |

## 最早缺口

复盘时按顺序定位，不从最熟悉或最害怕的一段开始：

```text
不能复述题目事实 -> 交接 1
能复述，但别人不能按扩写演完 -> 交接 2
能演，但分不清对象身份 -> 交接 3
对象清楚，但过程走不通 -> 交接 4
过程走通，但说不清第一次变化和答案时机 -> 交接 5
知道变化，但不知道是否值得优化 -> 交接 6
知道贵，但不知道要留下什么、何时丢掉 -> 交接 7
知道所需操作，但不知道为何选这个候选 -> 交接 8
方向已确认，但状态、顺序或代码解释不通 -> 交接 9
```

只补最早缺失的一次交接，不用后面更长的解释补偿前面的错误事实或空白动作。

## 复习约束

- 复习先重建“题面到算法方向”的人类路径，再重建模型和代码，不展示到期数量、完成率或连续打卡。
- 每到一个结论都追问“你依据什么确认它”，并区分题目事实、推导结果、设计选择和命名习惯。
- 每次范围分析都分开写官方约束、自己的操作预算和待验证候选，不把学习推导冒充成官方推荐复杂度。
- 如果卡在某次交接，只补最早断点，不跳到代码抄一遍，也不顺手扩展成多套解法。
- 题量、到期日和独立次数只能辅助选题，不能作为当天学习质量的替代指标。
- 不设置固定分钟目标。状态允许时可以连续推导和实现；保存点只用于中断后续接，不是催人结束。
- 训练不是每日硬性打卡。疲惫、加班或情绪不适时可以停，不补课，不把中断变成债。
- 情绪明显波动时优先保护性停止：保存当前确认点和最早断点即可，不用完成题量换取安心。
- 评价一份讲解或分析法时，至少检查六个维度：易吸收、便于回忆、体系关联、大脑串联、编码定位和迁移价值。
