# 非压缩题解模板

> 这是给 AI 和学习者共同使用的题解基准。它保留从题意到代码的中间过程，不把关键观察压缩成一个标签或公式。

## 题目到底要什么

- 输入对象：
- 输出结果：
- 题目明确保证：
- 这里没有额外添加的假设：

## 一个小例子：人是怎么一步步做的

用一个最小但能体现问题的例子，按时间顺序写：

1. 当前手里有什么。
2. 这一步选择或观察什么。
3. 哪个值发生了变化。
4. 下一步为什么可以继续。

## 哪些信息必须留下

对于每个变量，用完整句子解释它表示的事实，以及不保存它会失去什么信息。

## 一步发生什么变化

写出一次事件的前后变化：

`事件发生前：…… → 当前动作：…… → 事件发生后：……`

说明什么时候更新答案，什么时候只更新过程状态。

## 为什么这个结构能完成需要的操作

先写普通问题：“我们需要快速询问或修改什么？”再说明结构保存什么、执行什么操作，以及为什么数组或更简单的结构在此题可能不足。

## 朴素过程与浪费点

先给一个正确但可能较慢的过程，再指出重复劳动发生在哪里。不要先从方法名反推代码。

## 方案的自然语言版本

不要写“用滑动窗口/DP/贪心”就结束。按步骤描述完整过程，包括前进、收缩、选择、撤销或状态更新。

## 伪代码

伪代码中的每个变量都对应上面的自然语言含义，不提前使用难以解释的压缩表达式。

## Java 基准实现

先使用清晰、可运行、满足约束的版本。保留中间变量；除非它是题目必要条件，不主动使用位技巧、滚动数组或一行表达式。

## 重要代码段逐段对应

对每个关键代码段回答：

- 它回答了过程中的哪个问题？
- 它读取或改变了哪个状态？
- 为什么更新顺序是这样？

## 为什么成立与复杂度

只说明足以支持当前方案的正确性理由、时间复杂度和空间复杂度。复杂边界和更多特殊场景在主体代码稳定后由学习者自行测试。
