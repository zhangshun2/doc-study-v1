# Hot 100 标签白话指南

标签不是看见词就套代码的暗号。它只是提醒你：题目里的过程可能有哪些重复劳动，哪些信息值得留下。真正开始写前，先把题面翻成普通人能描述的步骤，等人工过程真的产生了对应操作，再让标签进入候选。

## 一、先整理数据或顺序

| 标签 | 人话里的问题 | 过程模型常见关注点 |
| --- | --- | --- |
| 排序 | 把对象排成一个更容易比较的次序 | 排完后相邻关系、区间先后或左右指针是否获得了新意义；比较器具体按什么字段排 |
| 哈希表/集合 | 我以前见过这个值吗？它对应什么信息？ | 每读一个对象，查询历史记录，再更新记录；记录的是下标、次数、状态还是分组 |
| 前缀和/前后缀 | 当前区间或当前位置的答案，能否由之前累计的信息算出？ | 先定义累计到哪里，再确认查询“之前多少”还是“到当前位置多少”；顺序更新会影响是否把自己算进去 |
| 双指针 | 两端、快慢两个位置，能不能共同缩小待处理范围？ | 每步移动谁、为什么这一步不会丢掉更好的答案；排序常用于让移动方向有意义 |
| 滑动窗口 | 连续区间能否一边扩张、一边在条件满足后收缩？ | 窗口左右边界、窗口内统计量、何时记录答案、何时移动左边界 |
| 二分查找 | 有序范围或答案范围能否每次排除一半？ | 定义左右边界代表什么；每次判断后保留哪半边；循环结束时边界表示什么 |

## 二、让等待和选择变简单

| 标签 | 人话里的问题 | 过程模型常见关注点 |
| --- | --- | --- |
| 栈 | 最近遇到、尚未解决的对象是否应该先处理？ | 栈顶代表最近未结算项；新对象到来时会解决哪些旧对象 |
| 单调栈 | 过去哪些位置还在等一个更大/更小的对象？ | 栈里保存下标或值；被新元素解决后怎样结算答案；相等时保留哪一边 |
| 队列/BFS | 哪个已发现的对象应该按先来顺序继续处理？ | 队列保存待处理对象；每次取出后发现哪些下一步对象；首次访问时何时标记 |
| 双端队列/单调队列 | 窗口里哪些候选还有可能成为最大/最小？ | 过期候选从哪端删除，被新候选压过的项从哪端删除，队首为什么就是答案 |
| 堆/优先队列 | 候选不断改变时，怎样快速取当前最优的一个？ | 堆保存什么候选、比较方向、每轮删除的元素代表什么；Java 默认 PriorityQueue 是小顶堆 |
| 链表指针 | 修改节点连接时，哪些原连接必须先保存？ | 当前节点、前驱、后继各代表什么；先保存后继再改指向，避免后续链断掉 |
| 树递归 | 一棵子树能给父节点提供什么结果？ | 函数输入代表哪棵子树，返回值是什么，当前节点如何合并左右结果 |
| Trie | 一串字符的共同前缀能否共享路径？ | 每层沿一个字符前进；节点保存哪些子路口，何时标记完整单词 |

## 三、搜索组合、约束与复用

| 标签 | 人话里的问题 | 过程模型常见关注点 |
| --- | --- | --- |
| DFS/BFS | 从当前对象出发，怎样系统查看可到达的后续对象？ | DFS 深入一条路，BFS 按步数层层扩散；访问标记代表“曾经到过”还是“当前路径用过” |
| 回溯 | 有多个选择，需要枚举所有合法结果时，如何走完一条再回到分叉点？ | 当前选择、递归入口、完成条件、撤销什么；不同题的关键差别在选择范围和去重规则 |
| 贪心 | 每一步能否先选一个局部看起来最好的选择，并证明不会耽误整体目标？ | 明确优化目标；举反例检查直觉；再解释替换最优解中的选择为何仍可完成 |
| 动态规划 | 不同选择会反复遇到同一类小问题，能否记住每种小问题的答案？ | `dp` 的一句话含义、当前决策来源、初始化、遍历方向、答案位置；先写清递归关系再谈压缩 |
| 拓扑排序 | 有前后依赖的任务，哪些现在已没有未完成前置任务？ | 保存依赖和剩余前置数；处理可执行任务后减少后续任务的等待数；全部处理完才表示没有环 |
| 位运算 | 能否把整数中的 0/1 位当作多个开关，批量查看或修改？ | 先把数字写成二进制，逐位执行规则，再说明题目为何满足抵消或掩码条件 |

## 四、每次读题的短流程

1. **事实：** 不看标签，题目明确给了什么、要求什么、禁止什么？
2. **扩写：** 谁拿着什么，从哪里开始，重复做什么，何时停止并交出什么？
3. **当前困惑、对象、过程与第一次变化：** 我具体卡在哪句，做完什么纸面动作后多出了什么证据？然后才是题目世界里的元素、位置、关系，一个普通人会按什么顺序做，哪个信息因什么事件从什么变成什么？
4. **范围、预算与候选：** 官方约束是什么，朴素过程大约要做多少操作，范围排除了哪些量级，由实际操作又能产生哪些待验证方向？
5. **第二次变化：** 这是重复查询、候选失效、子问题复用还是顺序约束？哪些历史值得留下，哪些候选可以丢弃？
6. **方向确认：** 现在才把具体方法名放进候选表，比较它们消除什么工作、需要哪些操作、代价和失效条件是什么。
7. **推导链：** 方向确认后才定义状态、初始、转移、更新顺序、不变量、结构、代码和反例。

先用自己的话按顺序走完这七步，再让方法名成为结论。完成以后，可用八个自然问题定位断点，问题 3 和问题 4 同属第三步；前六步负责从题面走到算法方向，第七步负责把方向变成可验证的实现。标签只负责提醒可能的方向，不代替这段描述。
