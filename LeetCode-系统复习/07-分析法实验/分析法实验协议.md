# 分析法实验协议

## 一、实验目的

实验要回答三个可验证的问题：

1. 一条解释能不能让不知道答案的人，从原题事实自然走到算法方向？
2. 换一个同类例子后，这条路径还能不能重新生成关键判断？
3. 写成 Java 后，能不能用这条路径定位更新顺序、边界和不变量错误？

实验不比较“谁写得更像标准答案”，也不比较“谁用的方法名更高级”。

## 二、实验单位

每次实验只处理一道题，并固定以下版本信息：

```text
题号：
官方来源：
事实核对日期：
实验版本：
本次是首次推导还是事后校验：
当前最早空缺：
本次允许回答到哪一阶段：
```

如果已经知道最终方法，必须标成 `事后校验`。这时可以比较解释质量，但不能把自己的记忆倒写成“我一开始自然想到”的现场。

每次实验只改变一个因素。例如：

- 同一道题，比较“标签倒推”和“人工过程法”；
- 同一道题，比较“每天向后重扫”和“等待生命周期”；
- 同一条人工过程，比较“候选失效”和“按值域查询最近位置”；
- 同一条递推关系，比较“朴素 DFS”“BFS 最短路”和“按金额递增的 DP”。

不能在同一轮同时更换题目、事实、判分标准和最终方向，否则无法判断差异来自哪里。

## 三、实验前先固定题目事实

题目事实错误时，后续所有比较作废。开始前先记录：

```text
输入对象与字段：
必须返回什么：
示例实际说明了什么：
明确保证：
明确禁止：
没有保证、不能添加的条件：
事实来源：
```

`problems.json` 是官方题面的结构化快照，具体记录仍回到对应标准题解核对。示例只能帮助理解，不能替代题目规则。

## 四、七阶段、九次交接是共同基线

所有路径都按同一顺序受检：

```text
阶段 1：交接 1  原题事实
阶段 2：交接 2  人话扩写
阶段 3：交接 3  对象
        交接 4  最笨但正确的过程
        交接 5  第一次变化与答案确定时刻
阶段 4：交接 6  数据范围与慢过程预算
阶段 5：交接 7  第二次变化
阶段 6：交接 8  候选比较与方向确认
阶段 7：交接 9  状态、更新顺序、不变量、代码和反例
```

阶段 3 必须保留三次独立交接；交接 6 先排除复杂度家族，脑中方法只能写成六项齐全且未获证明资格的待验证方向；交接 7 只留下重复、失效、复用或顺序证据并翻译成操作需求；交接 8 才允许候选进入比较并确认；交接 9 才写完整状态、代码和反例。现场先做纸面动作；整条链走完后，再为每次交接提取“疑问、为什么现在才问、纸面动作、新增证据、只能说明什么、不能说明什么、下一问、下一问需要什么证据、答不出退回哪里”九个字段复盘。

每个交接只允许使用前一次交接已经产生的证据。下面是最小检查表：

| 交接 | 必须留下 | 仍然不能出现 |
| --- | --- | --- |
| 1 原题事实 | 有来源的输入、输出、保证、禁止和未知 | 方法名、结构名、复杂度结论 |
| 2 人话扩写 | 谁拿什么、按什么顺序、何时停止、条件防止什么错误 | 优化理由、题面没有的规则 |
| 3 对象 | 对象身份、位置或时间、关系和结果归属 | 容器选择、优化结论 |
| 4 慢过程 | 最小完整例子的逐行动作和前后变化 | 用输入输出摘要代替演算 |
| 5 第一次变化 | 变化前、触发事件、变化后和答案确定时刻 | 保存方案、最终结构 |
| 6 范围与预算 | 官方约束、最坏输入、操作预算、被排除的复杂度家族；方法记忆只能放入六项待验证区 | 未写缺口的裸方法名、把待验证方向当成选择 |
| 7 第二次变化 | 重复查询、等待结算、对象失效、子问题复用或顺序约束的最小证据，以及所需操作 | 具体容器、完整伪代码 |
| 8 方向确认 | 真实候选比较、适用条件、失效原因、代价和完整因果句 | 只报方法名、完整 Java |
| 9 完整思维链 | 状态、初始、转移、更新顺序、不变量、代码映射和反例 | 用运行通过补推导 |

如果路径在某一阶段失去证据，后续内容只作为该路径的失败证据，不再计为完整推导。

## 五、五类分析视角

这五类不是并列模板。人工过程是共同底座，其余四类由第二次变化选择。

### 1. 人工过程法

要产出：

- 一个最小但完整的例子；
- 普通人按时间能执行的动作；
- 每一步前后的变化；
- 答案在何时确定；
- 最直接做法在哪里重复。

它回答“人怎样做这道题”，不提前回答“应该用什么结构”。

### 2. 状态生命周期法

适合对象产生后不会立即结束，需要等待、结算、过期或持续查询的场景。

要产出：

```text
对象何时进入：
谁持有它：
什么事件让它继续等待：
什么事件让它结算或失效：
结算时是否需要原始顺序：
未来读取值、位置、次数还是有效期：
```

### 3. 候选淘汰与不变量法

适合候选集合太多，但一个局部事实能同时排除一批候选的场景。

要产出：

```text
当前候选集合：
当前代表候选：
支配关系：
被一起排除的候选范围：
为什么不会漏掉更优解：
淘汰后集合怎样缩小：
```

只有指针移动，没有“为什么整批候选安全失效”，不算完成。

### 4. 递归职责法

适合问题由相同形状的更小问题组成，或需要显式枚举选择与恢复现场的场景。

要产出：

```text
函数输入代表哪个子问题：
函数承诺返回什么：
当前层怎样使用子结果：
发出多个分支时共享什么：
返回时恢复什么：
```

### 5. 子问题复用法

适合同一个子问题从多条路径重复到达，且答案与到达路径无关的场景。

要产出：

```text
什么信息唯一确定一个子问题：
不同路径为什么得到同一个子问题：
子问题的值是否足以构造更大的问题：
依赖顺序：
答案保存位置：
```

## 六、单条路径的记录格式

每条路径都保留同一组字段，便于事后比较：

```text
路径名称：
首次出现于哪一阶段：
当时支持它的证据：
它想消除的重复劳动或不确定性：
它需要的操作：
它依赖的题目条件：
它在哪一步失效或缺少证据：
事实核对：通过 / 失败
七阶段、九次交接自然可达：通过 / 失败
因果闭包：通过 / 失败
代码映射与反例：通过 / 失败
六维分数：易吸收 / 便于回忆 / 体系关联 / 大脑串联 / 编码定位 / 迁移价值
最终状态：主方向 / 查漏方向 / 淘汰 / 待验证
```

如果当前没有形成候选，直接写 `没有形成候选`。如果没有真实发生转折，写 `没有发生转折`。不要为了看起来像人的思考，补造错误和犹豫。

## 七、对照公平性

比较不同分析法时，先固定以下条件：

1. **同一题面事实。** 不允一条路径使用约束，另一条路径忽略约束。
2. **同一最小例子。** 先让两条路径都走过同一个能暴露关键变化的例子。
3. **同一代码入口。** 允许一篇路径只到方向确认，但进入实现比较时必须使用同一方法签名。
4. **同一判分门槛。** 不能因为熟悉某个方法，就对它跳过事实和因果检查。
5. **同一失败记录。** 错误候选保留在它真正失败的阶段，不把整条路径改写成“后来自然就想到了”。
6. **同一闭卷条件。** 比较回忆质量时，不看原文、题解和代码提示。

如果实验者已经知道答案，必须承认记忆会影响“首次到达”的评估。这时评分重点是解释是否仍然可由题面证据复核，而不是声称自己当时真的不知道。

## 八、什么时候可以停止实验

满足下面四条即可停止当前题目的实验：

1. 事实核对通过，没有缺条件或补条件。
2. 有一条路径从读题到方向确认连续可复核。
3. 至少一个真实替代方向被比较；没有真实替代时，用熟悉方向检查适用边界，并如实说明。
4. 主方向能映射到状态、更新顺序、不变量、代码位置和至少一个反例。

如果同一条路径连续两次尝试仍停留在同一个缺失证据，停止扩写整条题解，只记录：

```text
最早断点：
已有证据：
仍缺的证据：
下一次只做的纸面动作：
什么结果会允许继续：
```

这不是失败统计，也不会产生补课债务。下一次从该断点继续。

## 九、实验输出

一轮实验至少留下：

- 官方事实核对；
- 一条完整主路径；
- 真实出现过的替代或错误路径；
- 每条路径的准入门槛和六维评分；
- 最终主方向与适用边界；
- 一个可执行的复习提取方式；
- 指向标准题解、核心模型或代码的稳定链接。

如果只留下最终方法名和代码，本轮实验没有完成。
