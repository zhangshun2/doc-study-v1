# 量产与复习协议

## 一、目标

把一次实验变成可重复流程，同时保持四个边界：

1. 题目事实只维护一份权威源。
2. 推导过程保留“人的判断怎样发生”，不写成专家结论摘要。
3. 每道题只选一个主分析方向，其他方向用于查漏。
4. 复习从因果链开始，不从代码抄写开始。

## 二、一道题从进入队列到可复习

### 步骤 1：登记题目事实

从 `problems.json` 和对应标准题解确认：

```text
题号：
中文标题：
官方来源：
事实核对日期：
输入：
输出：
保证：
禁止：
约束：
方法签名：
```

标准题解仍是题意、签名、权威 Java 和复习日期的唯一来源。实验目录不复制第二份官方题面和提交代码。

### 步骤 2：声明本轮模式

只允许两种模式：

| 模式 | 含义 | 能证明什么 |
| --- | --- | --- |
| 首次推导 | 在不知道最终方向时，从题面和纸面动作推进 | 能证明路径是否自然可达 |
| 事后校验 | 已经知道答案，检查结论能否由已有证据复核 | 能证明解释是否完整，不能声称当时真实经历了什么 |

如果模式说不清，后续分数不可比较。

### 步骤 3：写七阶段、九次交接主路径

按固定顺序产出：

```text
阶段 1：交接 1  原题事实
阶段 2：交接 2  人话扩写
阶段 3：交接 3  对象
        交接 4  最笨但正确的过程
        交接 5  第一次变化与答案确定时刻
阶段 4：交接 6  数据范围与慢过程预算
阶段 5：交接 7  第二次变化
阶段 6：交接 8  候选比较与方向确认
阶段 7：交接 9  状态、更新顺序、不变量、代码和反例
```

交接 1 到 7 只描述题目事实、人工过程、第一次变化、预算、第二次变化和操作需求。交接 6 的方法记忆只能进入六项齐全、未获证明资格的待验证区，不能成为选择；交接 8 才比较并确认具体方向；交接 9 才进入完整代码。现场先完成各段的纸面动作；整条链走完后，再为每次交接提取九个字段复盘，不能把阶段 3 压成一段“分析题意”。

### 步骤 4：只做有信息增益的对照

不是每道题都强行写多套解法。出现下列任一情况时才增加对照：

- 题目标签或记忆中的方法名早于题目证据出现；
- 有两个真实候选都符合当前操作需求；
- 一条路径能写出代码，但说不清更新顺序或反例；
- 同一类题最近反复混淆；
- 需要检查迁移边界。

对照必须固定同一题面、同一最小例子和同一评分门槛。没有真实对照组时，用一个熟悉方向做适用性检查，不制造假候选。

### 步骤 5：过门槛并评分

先检查：

```text
事实保真：
自然可达：
因果闭包：
代码可定位：
闭卷可再生：
```

前两项不过，不选为主方向。通过后再记录六维分数：

```text
易吸收：
便于回忆：
体系关联：
大脑串联：
编码定位：
迁移价值：
```

每项分数必须能指向一段证据。详细规则见 [[评分与选择规则|评分与选择规则]]。

### 步骤 6：建立代码映射

在完整 Java 之前填表：

| 题目对象 | 人工动作 | 第二次变化要求的操作 | 状态变量 | 伪代码 | Java 代码位置 | 更新顺序或不变量 | 反例 |
| --- | --- | --- | --- | --- | --- | --- | --- |

每一行都必须能从题目对象走到具体代码位置。填不出来时回到最早缺失的人类动作、操作需求或顺序证据，不先复制一份代码再倒推。

### 步骤 7：关联已有五层

| 层 | 保存什么 | 链接关系 |
| --- | --- | --- |
| 官方事实 | 题面、示例、约束、签名 | `problems.json` 与标准题解 |
| 标准题解 | 权威 Java、复杂度、边界 | 主路径最终指向这里 |
| 核心模型 | 一句话本质、状态事件、最小演算 | 用于快速回忆，不复制代码 |
| 完整建模 | 人工过程、浪费点、证明、迁移 | 保存完整推导 |
| 分析实验 | 路径比较、门槛、评分、主方向选择 | 解释为什么当前题采用这条讲法 |

实验页不是第六份题面，也不是第二份实现。它只记录“哪种分析路径更适合当前学习者”和相应证据。

### 步骤 8：建立复习提取

复习分四层，先闭卷，再逐层给最小提示：

| 层级 | 不看资料时先做什么 | 卡住后才允许看的提示 |
| --- | --- | --- |
| L0 完整链 | 从题目对象和人工过程重新走到方向确认 | 不提供提示，先写出最早空缺 |
| L1 对象与变化 | 写出对象、第一次变化、答案时刻和最贵重复 | 只提示对象类别或变化类型 |
| L2 操作与方向 | 写出重复、失效、操作需求，并比较候选 | 只提示“查询、加入、删除、取极值、恢复”之一 |
| L3 状态与代码 | 写出状态、更新顺序、不变量和代码位置 | 只打开标准题解的对应段，不先看完整代码 |

每次复习只记录：

```text
本轮从哪一层开始：
最早断在哪个阶段：
当时可用的证据：
下一次只做的纸面动作：
是否使用了参考代码：
```

不以“看懂了”作为通过证据。能独立重建并解释更新顺序，才算离开当前层。

## 三、同分异构：一道题可以有多个入口

“同分异构”不是给一道题复制多份题解，而是让同一份权威事实和代码从不同学习问题进入。

### 1. 官方事实

用途：核对题目到底写了什么。

维度：

- 题号；
- 难度；
- 官方标签；
- 精确题面和约束。

### 2. 面试高频策展

用途：按当前求职准备优先级选题。

要求：

- 明确标为本地策展，不伪装成 LeetCode 官方评级；
- 保留来源、核对日期和入选理由；
- 不覆盖题目事实。

### 3. 计算机问题形态

用途：按“这道题体现了什么计算问题”组织。

同一道题可以挂多个形态，例如：

```text
739. 每日温度
-> 未来首个更大值的等待结算
-> 候选生命周期管理
-> 单调结构
```

这不等于三个主算法。页面可以让它出现在多个形态入口，但推导链和代码仍然只有一份权威源。

当前网站若只按 `primaryPattern` 显示，应把多形态视为后续策展扩展；在数据契约实现之前，不能声称已经完成多形态关联。

### 4. 官方标签

用途：按平台原始标签查找相似题。

标签只能帮助检索，不能证明当前题一定要使用同名方法。

### 5. 分析路径

用途：回答“这道题为什么这样讲”。

维度：

- 第二次变化的主流现象；
- 选中的辅助分析法；
- 合法替代方向；
- 已淘汰路径及最早失败阶段。

### 6. 复习状态

用途：决定下一次打开哪道题。

只维护在标准题解的属性区：

```text
mastery
reviewStatus
nextReview
lastReviewed
errorTags
independentAttempts
```

实验目录不维护第二份日期或到期债务。

## 四、题解量产的停点

一道题达到下面状态后，可以停止继续扩写：

1. 原题事实和约束无缺失。
2. 主路径能由最小例子走通。
3. 数据范围与操作预算没有混写。
4. 第二次变化有具体证据。
5. 主方向有完整因果句，并检查过至少一个真实替代或熟悉边界。
6. 状态、更新顺序、不变量和 Java 映射完整。
7. 至少有一个反例和一次闭卷重建记录。
8. 页面能链接回标准题解和权威代码。

继续增加相似段落、重复证明或再抄一份代码，不会提高掌握度。

## 五、批次推进

不是一次性重写全部题目。按验证过的小批次推进：

### 第 1 批：已完成的四道实验题

- `1. 两数之和`：历史查询；
- `739. 每日温度`：等待结算；
- `11. 盛最多水的容器`：候选淘汰；
- `322. 零钱兑换`：子问题复用。

用途：冻结实验协议和评分方式。

### 第 2 批：线性结构与字符串

重点验证：

- 连续区间如何从对象和过程产生；
- 双指针淘汰是否总有安全条件；
- 哈希历史保留是否解释返回位置、次数或有效期。

### 第 3 批：树、图与回溯

重点验证：

- 递归职责是否能说清函数输入和返回值；
- 搜索状态、访问标记和共享现场恢复；
- BFS 首次到达为什么能确定最短距离。

### 第 4 批：动态规划与选择

重点验证：

- DP 状态句是否先于转移；
- 依赖顺序和初始化是否有现实含义；
- 贪心是否有交换、支配或反例。

每一批先选两道代表题做实验。协议没有暴露新问题前，不批量推广新的分析模板。

## 六、维护规则

- 事实变化先更新 `problems.json` 和标准题解，再回看实验结论是否失效。
- 修改分析方法时增加实验版本，不直接覆盖旧评分证据。
- 一条路径从主方向降为替代时，保留原因和失效条件。
- 新增评分维度前，先证明已有六维无法表达该证据。
- 不能手工修改网站生成的 `_site` 来代替源文件修改。
- 每批修改后运行人工阅读契约、题库契约、Java 示例和站点构建。

## 七、可执行检查

实验数据由 `tools/validate_analysis_experiment.py` 检查：

```bash
python3 学习文库/算法学习/tools/validate_analysis_experiment.py
```

它至少验证：

- 四道代表题都存在；
- 每题至少两条真实分析路径；
- 六维分数完整且在 `0..4`；
- 门槛失败路径不能被选为主方向；
- 主方向必须通过事实和自然可达门槛；
- 最高门槛路径与主方向选择没有明显冲突；
- 文档入口、评分规则和实验数据互相链接。

检查通过不等于推导正确。事实、例子和代码仍要回到原题、标准题解与 Java 验证。
