# 题库与题解生产协议 v2

> 本文件是题库讲解、单题题解、复习材料和网站阶段页的唯一生产权威。其他文档只说明入口、评分或量产职责；出现顺序冲突时，一律以本文件为准。

## 一、目标与边界

这份协议不要求学习者先“像一个算法专家”给出方法名。它要求材料从一个还没有答案的人此刻手里的证据出发：

```text
我确认了什么
-> 它还不能回答什么
-> 所以我现在只能做哪个纸面动作
-> 做完多出了什么证据
-> 证据不足就退回哪里
```

一份合格内容不是把专家的最终答案改写得更长，也不是给结论补几段解释。每个结论都必须能指回上一份证据；如果删掉上一份证据，下一问仍然原样存在，说明下一问是模板或答案带进来的。

本协议适用于：

- 新题解从读题到 Java 实现的完整生产；
- 旧题解从“结论先行”迁移到人类现场顺序；
- 复习材料从题目重新生成方向和代码；
- 网站阶段页对信息的分阶段门控；
- 自动化校验对字段、锚点和阶段泄漏的检查。

## 二、唯一现场顺序

```text
阶段 1｜交接 1：原题事实
阶段 2｜交接 2：逐句扩写题干
阶段 3｜交接 3：对象
阶段 3｜交接 4：最笨但正确的过程
阶段 3｜交接 5：第一次变化与答案确定时刻
阶段 4｜交接 6：数据范围与慢过程预算
阶段 5｜交接 7：第二次变化
阶段 6｜交接 8：候选比较与方向确认
阶段 7｜交接 9：状态、更新顺序、不变量、代码、反例
```

三条硬边界：

1. 阶段 3 的三次交接必须分开。对象、慢过程、第一次变化不能合成“分析题意”。
2. 数据范围只能在交接 5 完成、慢过程已经可以计数之后读取。它只排除复杂度家族，不能直接宣布算法。
3. 方法名在交接 6 最多是“待验证方向”，在交接 7 只作为需要被操作需求检验的候选，到交接 8 才能正式比较和选择。

## 三、九次交接生产表

| 交接 | 进入条件 | 当前只能问 | 纸上动作 | 通过证据 | 禁止出现 | 退回 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 原题事实 | 刚打开题，遮住范围、标签、题解和讨论区 | 题目给了我什么，要我交回什么？ | 圈返回要求；分栏抄输入、输出、保证、禁止、示例和未知 | 每条都能指回原句的事实表 | 方法名、结构名、复杂度结论、题面没有的条件 | 原句和示例 |
| 2 人话扩写 | 输入输出已经分开，但文字还不能照着执行 | 一个人拿着什么，从哪里开始，何时停？ | 逐句写“原句 -> 自己的话 -> 动作 -> 忽略会错在哪”，再合成时间顺序 | 别人只读文字就能演完的过程 | 优化理由、最终结构、未保证规则 | 交接 1 中对应的原句 |
| 3 对象 | 人话过程已出现值、位置或时间，但身份还没确认 | 谁是一个独立对象，值和位置怎样分开，它何时失效？ | 把相同值放到不同位置；填身份、位置、寿命、关系和结果归属 | 两个值相同但对象不同的最小身份证据 | 代码容器、优化结论、把相同值合成一个对象 | 交接 2 的动作和返回要求 |
| 4 慢过程 | 对象身份已经分清，但还没有真实执行 | 最直接的人类办法先看谁，接着看谁，何时停？ | 用最小完整例子逐行手算看到谁、处理谁、做什么、什么变了 | 一条能复走并得到正确答案的人工过程 | 用输入输出摘要代替演算、插入优化动作 | 交接 3 的对象表和最小例子 |
| 5 第一次变化 | 慢过程已经完整走通 | 谁因哪个事件从什么状态变成什么状态，答案凭什么此刻确定？ | 标出变化前、触发事件、变化后、答案确定时刻和不是更早更晚的原因 | 第一次状态变化和答案确定时刻 | 应保存什么、最终结构、优化理由 | 交接 4 的逐行过程；必要时回交接 1 核对保证 |
| 6 数据范围 | 第一次变化已经写出，慢过程有可数动作 | 这份慢过程最坏重复多少次，哪些复杂度家族先排除？ | 抄全约束；选最坏输入；数一轮并乘轮数；另栏写待验证方向 | 官方约束、自己的操作预算、被排除的复杂度家族、六项待验证方向 | 把范围当算法暗号、待验证方向直接变成结论 | 交接 4 和交接 5；没有过程就不能读范围 |
| 7 第二次变化 | 已知慢过程代价，但还不知道该留下什么 | 哪份信息重复读取、过期、复用或必须保序？ | 回到同一条过程，用最小例子逐类取证，再翻译成操作动词 | 重复、寿命、复用或顺序证据，以及查询、加入、删除、取极值、恢复等操作 | 具体容器、完整伪代码、没有证据就补现象 | 交接 4 的同一条过程；没有预算就回交接 6 |
| 8 方向确认 | 操作需求已经具体 | 哪个候选真能承担这些操作，另一个为什么不够？ | 比较支持、缺口、失效条件、时间空间代价；写完整因果句 | 有取舍依据的方向确认句 | 只报方法名、完整 Java、用熟悉程度代替正确性 | 交接 7 的操作需求或交接 6 的预算 |
| 9 完整思维链 | 方向已经确认，不再更换方向 | 对象怎样变成状态，先更新谁，为什么不会漏？ | 逐段接对象、动作、操作、状态、代码、顺序、不变量和反例 | 可闭卷重建的状态转移和实现链 | 换方向、用运行通过补推导、代码与对象无映射 | 最先说不清的交接；状态或顺序错误回本交接 |

## 四、每次交接都必须解释“为什么现在是这一问”

不是把九句疑问依次抄一遍。每一段都必须写出：

```text
上一份证据：______
它已经能回答：______
它仍然不能回答：______
因此现在只问：______
做完必须多出的证据：______
证据不足就退回：______
```

例如交接 4 不能因为模板列了“最笨过程”就开始演算。它必须由交接 3 的结果逼出来：

```text
上一份证据：两个值相同的元素已经被证明是两个不同位置上的对象。
它已经能回答：答案要绑定原位置，当前对象不能被错误合并。
它仍然不能回答：这些对象按什么时间顺序参与比较，第一步先处理谁。
因此现在只问：最直接的人类办法怎样逐行走完？
做完必须多出的证据：一条不借助最终算法也能得到答案的人工过程。
证据不足就退回：对象表或人话扩写。
```

如果一段内容只有“接下来我们分析对象”“接下来看数据范围”这样的标题，没有说明上一份证据为什么不够，它没有通过本协议。

### 4.1 小白自然可达验收（不新增阶段）

每次交接先按生产表检查六项，再遮住当前交接后面的全部内容，只留上一份产物，逐项回答：

1. **只看上一步，能自己问出这一问吗？** 如果不看标题、模板、题解和最终答案，学习者就说不出当前问题，说明这一问不是由现场证据逼出来的。
2. **删掉上一步，这一问会消失吗？** 删除上一份原句、对象、手算、变化、预算或操作证据后，当前问题仍然原样存在，说明它来自模板或答案。
3. **纸面动作能当场做吗？** 必须能指出圈哪句、写哪两个位置、走哪个最小例子、数哪一轮重复或比较哪两个候选；“想一下”“分析关系”不算。
4. **新增证据的边界说清了吗？** 分别写出这份证据只能证明什么，以及仍不能证明什么；一个例子不能自动证明全部输入，预算也不能自动证明方向。
5. **方法名最早出现在哪里？** 交接 1 到 5 不出现选择语气；交接 6 只能进入待验证区；交接 8 才能选择或否决候选；交接 9 才能映射代码。
6. **换掉一个最小条件，最早从哪里失效？** 只改一个会改变答案位置、停止时刻、对象寿命或重复结构的条件，指出整条链最早要退回哪次交接；指不出来，说明当前理解仍依赖记忆。

最小条件替换只检查迁移，不要求每题制造错误：

| 原条件 | 只改一个条件 | 最早失效的位置 | 为什么不能照搬 |
| --- | --- | --- | --- |
| 两数之和要求返回原下标 | 改成只返回两个值 | 交接 3：值、位置和结果归属改变 | 排序候选不再因“必须保留原下标”失效，交接 8 的取舍必须重写 |
| 每日温度要求第一次“严格更高” | 改成“高于或等于” | 交接 2：动作改变和停止条件改变 | 第一次变化、结算时机和交接 8 的条件都要跟着改 |
| 零钱兑换允许每种硬币无限次使用 | 改成每种只能用一次 | 交接 2：一次选择的后果改变 | 慢过程、子问题是否可复用以及状态含义都要重新取证 |

真实发生过的误读、停顿和修正要保留；没有发生就写“没有发生转折”，不能为了显得像新手而补造“我一开始以为”。

## 五、逐句扩写题干的标准

阶段 2 不是把题目换一种说法，也不是读到题面后直接概括出“核心过程”。它要让一个还没有答案的人，
只借助原句就能知道：谁拿着什么、第一步碰谁、之后重复什么、哪个条件改变动作、最后把什么交回。
读者必须能沿这条过程复述，而不是只同意一个结论。

每条影响执行的关键原句都先原样保留，再填同一组九个字段：

```text
原句（不改写）：______
代词指向：______
谁在做事、手里有什么：______
第一步：______
重复动作：______
动作改变或停止：______
最后交回：______
忽略会错在：______
来源：事实 / 推论 / 推测
```

全部关键句处理完后，再合成一段按时间可执行的人话：

```text
合成可执行过程：______
```

“原句（不改写）”必须来自题面。不能先把它改写成自己的概括，再从概括里寻找动作。
“代词指向”要消解“它、这个、该位置、之后、此时、前一个”等所指；原句没有代词也要写“无代词”。
“谁在做事、手里有什么”要写出执行者当前拿到的值、位置、容器外的题目名词或已确认结果。
“第一步”必须是一个纸面或脑内能实际执行的动作，不能写“理解题意”“分析关系”。
“重复动作”要写清楚反复比较、移动、选择、累加或检查的到底是什么。
“动作改变或停止”要写出第一次满足、越界、失效、失败或题目保证触发时，动作怎样变化。
“最后交回”要区分值、位置、数量、路径、布尔值和结果归属，不能只写“返回答案”。
“忽略会错在”必须落到一个具体动作或具体错误输出；只写“会不严谨”“会漏情况”不算。

写这组字段时依次做十一件事：

1. 原句照抄，先不改写。
2. 消解代词和时间词，确认它指向哪个对象、位置或时刻。
3. 写谁在做事，手里拿着什么，当前结果属于谁。
4. 写第一步，只写现在能执行的动作。
5. 写反复做什么，确认重复对象和方向。
6. 写哪个条件会让动作改变或停止。
7. 写最后交回什么，以及交回到哪个位置或对象。
8. 写忽略这句话会在哪一步产生什么错误。
9. 给整条记录标来源：`事实`、`推论` 或 `推测`。
10. 删除题目没有保证的假设。标成 `推测` 的内容不能进入后续证明。
11. 把全部记录合成一段按时间可执行的人话，再换一个最小例子复述。

“来源”只有三种：

- `事实`：原句直接写了；
- `推论`：由多个已确认事实必然得到；
- `推测`：题目没有保证，不能用于后续证明。

阶段 2 同时固定两个观察位置：

```text
第一次变化；数据范围之前：谁因哪个事件改变状态，答案何时确定？
第二次变化；数据范围之后：哪份信息重复查询、失效、复用或必须保序？
```

在阶段 2 只允许写“第一次变化将在慢过程里观察”，不能提前宣布变化内容；第二次变化更必须在数据范围之后。

### 5.1 困难原句示范：每日温度

下面是对 739 题关键句的事后重建。它演示一张合格记录怎样从原句走到动作，
不代表作者当时真的在现场产生过这些犹豫：

> 对于第 `i` 天，下一个更高温度出现在几天后。如果气温在这之后都不会升高，请在该位置用 `0` 来代替。

| 字段 | 记录 |
| --- | --- |
| 原句（不改写） | 对于第 `i` 天，下一个更高温度出现在几天后。如果气温在这之后都不会升高，请在该位置用 `0` 来代替。 |
| 代词指向 | “第 `i` 天”是当前起始日期；“这之后”指第 `i` 天之后；“该位置”指第 `i` 天对应的答案位置 `answer[i]`。 |
| 谁在做事、手里有什么 | 我拿着起始日期 `i` 和它的温度 `temperatures[i]`，眼前有一条从 `i + 1` 开始的未来日期序列。 |
| 第一步 | 从 `i + 1` 开始向右看下一天。 |
| 重复动作 | 逐日向右比较未来温度是否严格高于 `temperatures[i]`。 |
| 动作改变或停止 | 第一次遇到严格更高温就停止；若一直走到末尾都没有遇到，也停止并写 `0`。 |
| 最后交回 | 把发现日下标减去 `i` 写入 `answer[i]`，交回的是等待天数，不是温度值，也不是发现日原下标。 |
| 忽略会错在 | 忽略“第一个”会越过更近的合法日期；忽略“严格”会把相等温度误判为更高；忽略“该位置”会写错答案位置或返回错误内容。 |
| 来源 | 事实 |
| 合成可执行过程 | 对每一天 `i`，从 `i + 1` 向右逐日比较；第一次遇到严格更高温时，把两个日期的下标差写入 `answer[i]` 并停止；走到末尾仍没有更高温时，在 `answer[i]` 写 `0`。 |

这张记录仍有明确边界：它说明怎样执行题意，不说明对象身份、最笨过程、答案第一次变化、
数据范围、第二次变化或应该保存什么。那些问题必须由后续交接分别取得证据。

如果题目原句很长，不要一次扩写整段后再拆。先找出会改变对象、方向、顺序、停止条件或返回内容的句子；
没有影响执行且不产生歧义的说明句可以只保留事实，不强行制造动作。

## 六、对象、过程、第一次变化

### 6.1 对象

对象表固定七列：

| 题目对象 | 值和状态 | 身份由什么决定 | 位置或时间 | 从何时有效到何时失效 | 和谁发生关系 | 最终要得到什么 |
| --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |

对象表的作用不是提前列容器，而是回答“答案跟着谁走”。值相同、位置不同时，必须给出最小身份证据。返回原下标、第几天或原路径时，位置或时间必须成为对象身份的一部分。

### 6.2 最笨但正确的过程

慢过程必须满足：

1. 不借助最终算法名也能执行；
2. 用最小但完整的例子走到题目要求的输出；
3. 每一步记录看见谁、处理谁、做什么、做完后什么变了；
4. 不把最终算法的动作删掉条件后伪装成慢过程；
5. 不只写输入输出摘要。

### 6.3 第一次变化

```text
谁发生变化：______
触发事件：______
变化前：______
变化后：______
答案确定时刻：______
为什么不是更早或更晚：______
```

“第一次找到候选”不等于“答案已经确定”。只有题目保证唯一命中，或已经证明其他候选被淘汰，候选出现才可能成为答案确定时刻。

## 七、数据范围与慢过程预算

数据范围必须晚于第一次变化，原因不是排版偏好，而是没有完整过程就没有可数对象：

```text
数据范围之前：我还不知道每一轮在重复什么，也没有东西可以数。
数据范围之后：我知道一轮核心动作是什么，可以估算最坏轮数和总操作量。
```

预算分成三层，不能混写：

| 层 | 内容 | 来源 |
| --- | --- | --- |
| 官方事实 | 约束、边界、保证 | 原题和 `problems.json` |
| 自己的预算 | 一轮动作、最坏轮数、总操作量 | 交接 4 的慢过程 |
| 待验证方向 | 想消除什么重复、依赖什么条件、预算是否允许、还缺什么证据 | 范围触发的记忆，不是结论 |

范围后想到方法时，只能写：

```text
范围后想到的方向：______（没有就写“没有形成方向”）
它可能消除的重复或失效工作：______
它依赖的题目条件：______
最坏预算是否允许：______
目前仍缺少什么过程证据：______
它还不能被选为主方向，因为：______
```

六项没有写全，方法名不能进入交接 7 的候选比较。

### 7.1 算法方向收窄漏斗：范围只缩圈，不点名

数据范围只负责缩小复杂度家族，不负责替学习者说出方法名。范围后想到的任何方向都必须经过同一条漏斗，不能从“数字看起来像某种题”直接跳到结论：

```text
先用交接 4 的慢过程数出最坏操作量
-> 范围只排除装不下的复杂度家族
-> 脑中方法名降级为“待验证方向”，写全六项
-> 回到交接 4 的同一条过程寻找第二次变化
-> 只记录重复查询、候选失效、子问题复用、顺序约束中真实发生的现象
-> 把现象翻译成加入、查询、删除、取极值、恢复或保序等操作动词
-> 有操作需求以后才比较候选
-> 交接 8 才写正式方向确认句
```

这个漏斗里允许“想到某个方法”，但不允许“因为想到所以确认”。方法记忆只能提出一个待检查问题：

| 范围后的记忆 | 它仍不能回答 | 必须回到过程取得的证据 | 最早允许结论 |
| --- | --- | --- | --- |
| “这个规模可能要用更快的结构” | 哪份工作被重复执行 | 同一输入上被反复读取或反复计算的最小例子 | 交接 7 的操作需求 |
| “某个结构也许能加速查询” | 查询键、返回值和寿命是什么 | 每次查询要取回值、位置还是次数 | 交接 7 的操作动词 |
| “某个方向应该能过” | 它是否处理了全部合法候选 | 被整批淘汰的对象和不会漏解的理由 | 交接 8 的方向比较 |
| “另一个方向看起来也像” | 两个方向分别缺什么、代价是多少 | 支持、缺口、失效条件和时间空间预算 | 交接 8 的完整因果句 |

如果交接 7 写不出任何过程证据，不能为了凑满表格编造“重复”或“失效”，也不能把待验证方向直接扶正。此时只能写“没有形成该现象”，回到交接 4 重走最小例子；连续没有新增证据时按本协议第十三节停止。

方向收窄还必须区分三种句子：

```text
事实句：当前慢过程最坏约 n(n-1)/2 次比较。
假设句：我想到了某个可能减少重复的方法，但还不知道它要承担哪些操作。
确认句：因为过程需要 ______ 操作，候选 A/B 分别缺少 ______，所以当前选择 ______。
```

事实句可以出现在交接 6；六字段里的假设句只能算待验证方向；确认句最早出现在交接 8。缺少这一步区分，文章即使把方法名放在“分析”标题下，也仍然是结论先行。

## 八、第二次变化

回到同一条人工过程，逐项写“发生”或“没有形成该现象”：

| 现象 | 小白要问 | 需要的证据 | 翻译成的操作 |
| --- | --- | --- | --- |
| 重复查询 | 同一个问题会再次被问吗？ | 哪份历史能回答，未来读取值、位置还是次数 | 查询、取回 |
| 候选失效 | 哪个事件后一批对象不可能产生答案？ | 失效条件和安全淘汰证明 | 删除、跳过、结算 |
| 子问题复用 | 不同路径会到达同一个更小问题吗？ | 重复到达的最小例子和结果是否足够 | 保存、读取 |
| 顺序约束 | 新对象从哪端加入，从哪端结算？ | 交换顺序后最先出错的最小输入 | 加入、结算、保序 |

没有发生的现象写“没有形成该现象”，不能为了凑满表格编造候选。第二次变化只允许写题目对象、事件和操作动词，不能提前报具体容器。

## 九、候选比较与方向确认

交接 8 才允许具体方法名正式进入比较：

| 候选 | 支持哪些操作 | 缺少什么 | 何时失效 | 时间、空间和额外维护代价 |
| --- | --- | --- | --- | --- |
|  |  |  |  |  |

方向确认必须是一条完整因果句：

> 因为慢过程在 ______ 上重复，最坏预算是 ______；第二次变化证明未来需要 ______ 操作；候选 A 支持 ______，但缺少 ______；候选 B 能承担 ______，代价是 ______；所以当前方向选择 ______。

合法替代方向保留为查漏入口；被淘汰方向保留最早失败阶段和证据。不能只留下主方向，也不能把“另一种方法也能做”写成没有条件的并列。

## 十、状态、更新顺序、不变量、代码与反例

方向确认后只做实现链，不再换方向：

```text
题目对象 -> 人工动作 -> 操作需求 -> 状态变量
-> 初始条件 -> 转移 -> 更新顺序 -> 不变量
-> 代码位置 -> 最小反例 -> 闭卷重建
```

代码映射表固定八列：

| 题目对象 | 人工动作 | 操作要求 | 状态变量 | 伪代码 | Java 代码位置 | 更新顺序或不变量 | 对应反例 |
| --- | --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |  |

“可能出错”不算反例。反例必须真的让状态、不变量或更新顺序失效，并指出错误最早发生在哪一行动作。

## 十一、文章和页面验收

发布前必须逐项通过：

```text
[ ] 读题阶段没有方法名、标签、题解、数据范围和代码。
[ ] 每个关键原句都有扩写，忽略了会犯的错误是具体的。
[ ] 对象、慢过程、第一次变化分三段出现。
[ ] 第一次变化之后才读数据范围。
[ ] 数据范围只排除复杂度家族，没有直接宣布方法。
[ ] 第二次变化有发生或“没有形成该现象”的真实证据。
[ ] 具体候选到交接 8 才比较。
[ ] 方向确认句能独立解释为什么选它。
[ ] 状态、更新顺序、不变量、代码和至少一个反例能逐段对应。
[ ] 复习时能闭卷重建，而不是只复述方法名。
[ ] 只留上一份产物时，学习者能自己问出当前一问。
[ ] 删掉上一份产物后，当前一问会消失，而不是仍照模板存在。
[ ] 每步都能指出纸面动作，并写清证据只能证明什么、仍不能证明什么。
[ ] 只换一个最小条件后，能指出整条链最早从哪次交接失效。
```

页面还必须做阶段门控：

- 阶段 1 至 5 不读取比较字段、题解关联、代码和评分；
- 阶段 6 才展示路径比较、六维评分、最早失败阶段和代码映射；
- 阶段 7 才展示 Java 模板和官方提示；
- 前五阶段看不到后续内容，不是靠遮挡 CSS，而是渲染函数根本不读取这些字段。

## 十二、旧内容迁移规则

旧文可以先保留，但必须标明用途：

| 标记 | 含义 | 允许做什么 | 不能声称什么 |
| --- | --- | --- | --- |
| `complete-human-chain` | 已按 v2 九交接重写并通过校验 | 作为标准样板 | 不能省略失败路径证据 |
| `post-hoc-pending-migration` | 已有正确结论，仍按旧结构讲解 | 作为事后校验和迁移素材 | 不能声称是小白首次现场顺序 |
| `rejected` / `superseded` | 已被门槛、预算或反例淘汰 | 保留最早失败证据 | 不能删除失败原因只留结果 |

旧文迁移时先补最早断点，不从代码往前提。若旧文先给“核心观察/最优方案”，只能作为事后校验入口，直到对象、慢过程、第一次变化、范围和第二次变化都可独立复核。

## 十三、失败与停止

同一断点连续两次没有新增证据时，停止扩写，只保存：

```text
最早断点：______
已有证据：______
仍缺的证据：______
下一次只做的纸面动作：______
什么结果会允许继续：______
```

不把“今天没推完”记为欠账，也不通过多看一份题解制造完成感。下一次从最早断点继续，不从方法名或完整代码重新开始。
