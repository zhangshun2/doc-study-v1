# 16 周弹性计划

这份计划按 16 周排布，适合有 3 至 5 个月准备时间、已经做过约七成 Hot 100 的情况。每周安排 **2 至 4 个自选时段**，每次 25 至 45 分钟；不规定必须在哪天完成。加班或状态不佳就跳过，不补课、不累积欠账。若想拉长到 20 周，把每阶段的复现周延长即可。

## 开始前：轻量盘点

用 2 至 3 个时段，各抽 2 道熟悉题，从题面开始独立写。目的只是观察目前主要卡在代码记忆、Java API、循环边界还是方法推理，不是考试，也不按通过数评价自己。

每题结束后只标一个状态：

- **A：** 过程和代码都能独立复现。
- **B：** 过程想得起，代码有局部遗忘或实现错误。
- **C：** 需要提示才能想起关键过程。
- **D：** 还没做过或题意没有读稳。

A 题降低频率；B 题练代码；C 题补一次展开推理再复写；D 题按课程顺序进入。不要为了盘点而额外刷完题单。

## 阶段安排

| 周次 | 内容 | 当阶段的产物 |
| --- | --- | --- |
| 1–2 | Java 数组、集合、Deque、PriorityQueue、Comparator、位运算；排序题 | 一套自己能直接调用的 Java 操作记忆；排序题复现卡 |
| 3–5 | 哈希、链表、栈、单调栈/队列、堆、Trie | 结构操作顺手；每种结构挑 2–3 题反复写 |
| 6–8 | 双指针、滑动窗口、二分、前缀和、矩阵、字符串 | 用自然语言描述窗口或指针如何变化，再闭卷实现 |
| 9–10 | 树、递归、DFS/BFS、搜索与回溯 | 已熟悉的搜索骨架少讲解，多练现场修改与恢复 |
| 11–12 | 贪心 | 每题固定记下局部选择、适用目标、为什么不会损失答案；完成后重复代码 |
| 13–15 | 动态规划：一维、网格、背包、序列、状态机、区间、树形 | 固定状态含义和 Java 写法；复杂题先接受基准版本，不无限追问 |
| 16 | 图与拓扑、全题混合抽测 | 复现 207；混合抽题，确认标签提示减少后是否还能写 |
| 17–20（可选） | 对 B/C 题增加间隔复现；困难题只选已见过方法的题 | 逐步拉长复习间隔，形成长期维护池 |

这是顺序建议，不是进度承诺。若某阶段题量超出精力，先减少每周题数，不压缩睡眠，也不因计划表上的周数追赶。

## 一个轻松的周节奏

- 时段 A：一题闭卷复现。
- 时段 B：到期复习一至两题。
- 时段 C（可选）：一个薄弱题的非压缩讲解，然后由你输出过程模型并重写代码。
- 时段 D（可选）：短的混合抽测或补休。

一周没有完成安排时，下周从当前题继续，不把前一周变成债务。休息本身不需要被算法学习补偿。

## 复习间隔

同一题可以先按“本次 → 下一次可用时段 → 3 天左右 → 1 周 → 2 周 → 1 个月”回访。日期是提醒，不是期限。到了复习日但状态很差时可顺延或跳过；不会因为错过某个间隔而重置整套计划。

连续两次能独立写出并通过自己设计的测试后，降低复习频率。若某次忘记，回到最近一次成功的版本，针对忘掉的代码片段练习即可，不必重新看完整理论。

## 复习池维护

每题只维护一行状态，使用 [[../06-学习记录/TODO|TODO 清单]] 或 [[../06-学习记录/单题复习记录模板|单题复习记录模板]]：

`题号｜状态 A/B/C/D｜下一次复现｜最近卡点｜我的过程模型`

每次只更新真实发生的内容。不要把打卡连续天数、总题量或“全做完”当作自我评价。
