## 融合原则

1. 当前 `AGENTS.md` 和 schema v3 是唯一规范，旧 Markdown 不能直接覆盖正式文件。
2. 先按 LeetCode 题号、题名和路径建立映射，再判断重叠、缺口和重复；不能按旧目录整体搬迁。
3. 官方题意、约束、签名和示例只从 LeetCode 重新同步，旧题面只用于发现漏题或对照差异。
4. 标准题解继续是提交代码和复杂度的唯一权威副本；旧 Java 只能帮助复核边界，不能形成第二份实现。
5. 通用原理先判断是否真的跨题。只有至少两道代表题已经进入稳定层后，才新增概念卡。
6. 内容先进入 `整理工作区/`，通过人工筛选和 `./validate-all.sh` 后才进入正式学习层。
7. 旧库和学习方法材料不因为“文件多”就不筛选地迁移；能归因到具体题目的内容优先回到题目层。
