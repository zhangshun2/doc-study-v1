# 从公式求值到过程建模：面对生活中不直观问题的思考

日期：2026-08-30  
起点：[每日温度中的过程建模](./2026-08-30-每日温度中的过程建模.md)

## 1. 两类看起来相似、实则不同的问题

有些问题只要条件齐全，就能直接代入公式：

```text
路程 = 速度 x 时间
单利利息 = 本金 x 利率 x 时间
每日温度中，已知答案日 i 后：等待天数 = i - j
```

这类问题的难点通常是：找准变量、确认单位、选择正确公式。

另一些问题没有一个可以直接代入的稳定公式：

```text
怎样真正学会算法？
怎样让身体在半年后更健康？
该不该换工作？
怎样修复一段正在变差的关系？
怎样建立长期可信的判断力？
```

这些问题的结果来自一连串状态变化，而且会受到反馈延迟、环境变化、他人行动、偶然事件和自身执行波动的影响。此时继续寻找一个“正确答案公式”，常常会制造虚假的确定感。

更合适的提问是：

> 我能否建立一个足够简单的过程模型，让自己知道当前处于什么状态、下一步能做什么、何时观察反馈、何时修正方向？

这也是算法本身的魅力。它不是脱离具体场景去玩弄公式，而是反过来帮助具体场景变得明晰：目标是什么，状态是什么，约束在哪里，变化由什么触发，结果又该如何验证。

当一个过程不断重复时，算法会继续寻找重复背后的结构，用少量可维护的状态代替反复劳动，并在给定目标和约束下寻找更优的处理方式。只有问题边界稳定、目标可以度量并且正确性能够证明时，我们才进一步称它为“最优解”。面对生活这样的开放系统，过程建模的价值通常不是宣称找到了全局最优，而是让下一步更有依据，让反馈能够进入下一轮改进。

## 2. 不要把“公式”和“过程”理解成对立面

公式是对稳定关系的压缩，过程模型是对变化机制的描述。二者处在不同层次。

| 维度 | 公式求值 | 过程建模 |
| --- | --- | --- |
| 核心问题 | 已知变量后结果是多少 | 状态会如何一步步变化 |
| 前提 | 关系稳定，变量可测 | 关系可能变化，信息不完整 |
| 时间 | 常被压缩进一个变量 | 时间顺序本身会影响结果 |
| 反馈 | 通常不改变公式 | 反馈会改变下一步行动 |
| 不确定性 | 多半被忽略或作为误差 | 必须显式管理 |
| 适合场景 | 计算、校验、局部预测 | 学习、健康、职业、关系、长期决策 |

现实中更常见的结构是：

```text
大过程由许多状态转移组成
每次转移内部可能使用若干公式
```

例如复利公式可以计算“固定收益率下资金会变成多少”，但真实投资过程还包括收入是否稳定、能否持续投入、费用和税、回撤时的行为、流动性需求以及收益率本身的不确定性。公式没有错，只是它只负责整个过程中的一小段。

## 3. 为什么人会偏爱直接求结果

### 3.1 结果给人确定感

一个数字、排名或结论看起来可以结束思考。过程模型却会暴露“不知道”和“还要观察”，心理上更不舒服。

### 3.2 结果容易比较

分数、工资、体重和粉丝数都能横向比较；理解深度、恢复能力、信任质量和选择空间则很难立即量化。

### 3.3 结果容易叙述

“他成功是因为做了 X”比“多种条件长期相互作用，且包含运气”更容易传播。但易讲述不等于真实。

### 3.4 人容易事后压缩过程

结果出现后，我们会把曲折过程改写成一条直线，低估试错、路径依赖和偶然性。这会让别人的经验看起来像一条可以直接套用的公式。

因此，遇到人生经验时，一个值得保持的警觉是：

> 对方给我的究竟是因果机制、适用条件明确的经验，还是结果发生后的漂亮解释？

## 4. 过程模型最少要包含什么

一个实用的生活过程模型，不需要精确模拟世界，但至少应回答六件事。

### 4.1 状态

现在真正影响后续结果的变量是什么？

例如学习算法时，不只是“刷了多少题”，还可能包括：

- 能否识别题型信号
- 能否从暴力推到优化
- 能否说出不变量
- 隔几天后能否独立重写
- 卡住时能否定位自己卡在哪一层

### 4.2 行动或事件

哪些变化由自己主动发起，哪些由外部事件触发？必须区分“我能控制什么”和“我只能观察什么”。

### 4.3 状态转移

一次行动为什么可能改变状态？如果说不出机制，只是重复一个流行做法，就很难知道何时该调整。

### 4.4 约束

时间、精力、金钱、健康、责任和注意力都是真实约束。忽略约束的计划不是模型，只是愿望。

### 4.5 反馈与延迟

有些行动立刻反馈，有些几周后才显现。把延迟反馈误判为无效，或把短期波动误判为长期趋势，都会导致错误调整。

### 4.6 不确定性

不是所有变量都可知、可控、可量化。好的模型会保留余量、设置止损，并允许在新信息出现后更新判断。

可以把它压缩成：

```text
下一状态 = 当前状态 + 行动影响 + 外部事件 + 随机波动
下一行动 = 目标、当前状态、反馈和约束共同决定
```

这不是用于精确计算的公式，而是用于检查思考有没有缺项。

## 5. 五个生活场景中的过程建模

### 5.1 学习：完成数量不是掌握程度

结果式提问：

```text
刷 100 道题后，我能达到什么水平？
```

这个问题无法只由题目数量回答。更好的过程模型是：

```text
输入：一道题、已有知识、可用时间
状态：识别能力、推导能力、实现能力、记忆强度
行动：独立尝试、看提示、复盘、间隔重做、讲给别人
反馈：是否能解释选择、是否能处理变式、是否能隔天重写
转移：从“看懂”到“能复现”，再到“能迁移”
```

这里值得追踪的领先指标，不是当天多写了几道，而是：

- 首次独立思考了多久
- 卡点是否被准确命名
- 是否能从题意推导状态和不变量
- 是否安排了间隔复习
- 新题出现时是否识别出相同结构

### 5.2 健康：体重是输出，不是控制旋钮

结果式提问：

```text
我怎样一个月减掉 5 公斤？
```

过程建模会先区分：体重是滞后且有噪声的输出，睡眠、饮食结构、活动量和压力管理才是更接近过程的变量。

```text
状态：体能、恢复、饮食习惯、伤病风险
行动：训练、进食、睡眠安排
反馈：周均体重、围度、力量、静息心率、主观疲劳
约束：工作时间、既往伤病、可持续性
调整：按周看趋势，不因单日波动大幅改变计划
```

真正要优化的不是某一天的数字，而是一个能持续运行且风险可控的系统。

### 5.3 职业：薪资是重要结果，但不是完整状态

结果式提问：

```text
哪个选择能让我三年后收入最高？
```

没人能精确知道。可建模的部分包括：

```text
状态：可迁移技能、行业知识、信誉、协作网络、财务缓冲
行动：承担项目、刻意训练、公开产出、建立合作、探索机会
外部事件：行业周期、组织调整、技术变化
反馈：市场面试、项目影响、他人复用、议价能力
风险：技能过度绑定单一公司，收入提升但选择空间下降
```

这里一个常被忽略的变量是“选择权”。同样的短期收益，如果一个选择增加未来可选路径，另一个选择锁死路径，它们的长期价值并不相同。

### 5.4 关系：不能把人当成确定性函数

结果式提问：

```text
我做了 X，对方为什么没有给出 Y？
```

关系中不存在稳定的单输入单输出公式。对方有独立意愿、历史经验和当下状态。更合适的模型关注互动循环：

```text
事件：分歧或需求出现
解释：双方如何理解这件事
行动：表达、回避、防御、倾听或协商
反馈：安全感和信任增加还是减少
累积状态：以后更愿意坦诚，还是更倾向隐藏
```

一次“正确表达”不保证立即得到理想回应，但长期反复出现的互动模式会改变关系状态。过程建模在这里的边界尤其重要：它帮助自己看清互动，却不把对方简化成可操纵对象。

### 5.5 金钱：计算收益不等于管理财务过程

公式能计算固定条件下的复利，却不能替你决定风险承受能力。

一个更完整的个人财务过程会包含：

```text
状态：现金流、应急资金、债务、长期资产、保险保障
事件：收入中断、疾病、家庭责任、市场回撤
规则：先保证流动性，再承担与期限匹配的风险
反馈：储蓄率、负债成本、资产集中度，而非只看短期收益
```

最值得防范的往往不是平均情况下少赚一点，而是在极端情况下失去继续参与未来的能力。

## 6. 从“每日温度”能得到哪些克制的生活启发

算法不能直接充当人生哲学，但它可以提供几种思考结构。

### 6.1 未决问题不等于必须立刻解决

每日温度把暂时没有答案的日期保留在等待状态，直到足够的信息到来。生活中也有一些问题尚不具备决策条件。

但等待不应等于无限拖延。可以为未决事项记录：

```text
还缺什么信息
什么事件到来后重新判断
最晚何时必须决定
继续等待的成本是什么
```

### 6.2 新信息可能一次改变多个旧判断

一个项目经历、一次体检、一段真实合作，可能同时修正过去多个假设。与其为每个疑问分别空想，不如寻找信息密度高、可同时验证多个假设的小实验。

### 6.3 状态需要压缩，但压缩会丢信息

算法只保留影响未来答案的最小状态。生活中记太多细节会造成认知负担，但压缩成单一指标又可能失真。

因此值得问：

```text
我当前使用的指标保留了什么？
它丢掉了什么？
被丢掉的部分会不会改变决策？
```

### 6.4 结果常在事件发生时确认，而能力在此前积累

面试通过、项目上线、考试得分是结果显现的事件；能力和准备早已在前面的过程里积累。不能因为结果尚未显现，就断言过程毫无变化；也不能因为偶然得到好结果，就断言过程一定正确。

### 6.5 局部规则成立，不代表能机械推广到人生

单调栈的世界边界明确、规则稳定、数据诚实。现实里规则可能变化，变量可能不可见，人也会因为被建模而改变行为。因此生活模型必须允许例外、更新和伦理边界。

## 7. 更值得长期思考的十二个问题

### 7.1 我追的是结果，还是产生结果的能力？

一次高分和稳定学习能力不同，一次高收入和持续创造价值的能力不同。结果重要，但能力决定结果能否重复。

### 7.2 哪些是领先指标，哪些是滞后指标？

体重、收入、考试分数通常滞后；睡眠、练习质量、客户反馈等更接近过程。只盯滞后指标，调整总会来得太晚。

### 7.3 反馈要多久才可信？

有的系统按分钟反馈，有的按季度反馈。使用错误的观察周期，会把噪声当趋势，或者在错误方向上坚持太久。

### 7.4 当前行动是可逆的吗？

可逆决策适合快速试验，不可逆或高代价决策需要更多证据。不要把所有决定都用同一种慎重程度处理。

### 7.5 最坏情况会不会让我失去继续选择的能力？

平均收益不能代表生存性。健康、现金流、信誉和法律风险中，尾部损失常比平均收益更重要。

### 7.6 我是否保留了缓冲？

把时间、资金和精力排到满载，会让一次小波动扩散成系统性失败。缓冲看似低效，却提供恢复能力。

### 7.7 我优化的指标会不会反过来伤害目标？

刷题数可能挤压复盘，工时可能替代价值，消息回复速度可能破坏深度工作。当指标成为目标时，它常会失去作为指标的意义。

### 7.8 我的模型忽略了谁的视角？

涉及他人时，自己的收益函数不是全部世界。团队、伴侣、客户和家人各有独立目标与约束。

### 7.9 这是因果关系，还是只看见了相关性和幸存者？

成功者共有的特征，不一定是成功原因；失败者可能也做过同样的事，只是没有出现在叙事中。

### 7.10 当前选择会怎样改变未来的可选项？

有些行动不立即产出最大结果，却增加技能、信誉、健康或现金储备，从而打开更多未来路径。

### 7.11 我是在解决问题，还是在缓解面对问题的不适？

频繁换计划、购买工具、收集资料可能让人感觉在行动，却没有改变核心状态。需要观察行动是否真的进入反馈闭环。

### 7.12 什么证据会让我承认模型错了？

如果没有任何证据能改变判断，那不是模型，而是信念。提前写出更新条件，可以减少事后为原判断辩护。

## 8. 一套用于现实问题的轻量建模方法

面对一个不直观的问题，可以在一页纸上完成下面八步。

### 第一步：明确期望结果和时间尺度

```text
我希望什么发生？
在多长时间内观察？
什么算有改善，什么算失败？
```

### 第二步：区分可控、可影响和不可控

```text
可控：自己的行动和投入
可影响：合作、沟通、谈判后的共同结果
不可控：市场、天气、他人的最终选择
```

把精力分配给不同层次，而不是对不可控结果假装拥有控制权。

### 第三步：选择少数关键状态

只记录会改变下一步行动的变量。状态太少会失真，太多则无法维护。

### 第四步：写出可能的变化机制

不要只写“每天努力”，而要写清行动通过什么机制产生变化。例如“间隔重做通过主动提取加强记忆，并暴露伪理解”。

### 第五步：设计低成本实验

先用一到两周验证关键假设，尽量让一次行动提供多种信息。实验的目的不只是成功，也是降低不确定性。

### 第六步：设置反馈节奏

明确什么按天记录、什么按周看趋势、什么按月复盘，避免情绪驱动的随时改计划。

### 第七步：设置边界和停止条件

```text
最大投入是多少？
出现什么信号必须暂停？
什么时候升级投入？
什么时候承认方向不成立？
```

### 第八步：根据新信息更新模型

复盘不是只问“我有没有坚持”，还要问：

```text
原来的因果假设成立吗？
哪个状态变量最能解释变化？
出现了什么未预料的约束？
下一轮只改哪一个关键部分？
```

## 9. 示例：把“学好算法”改写成可运行的过程

目标：未来 12 周提升常见算法题的独立建模能力。

```text
结果指标：限定时间内独立完成新题，并能解释正确性与复杂度

关键状态：
- 题型识别
- 暴力到优化的推导
- 不变量表达
- Java 实现准确性
- 间隔后的提取能力

每周过程：
- 选择 3 至 5 道同模型、不同表面的题
- 每题先写暴力、重复点、未决状态、事件和不变量
- 首次尝试后再看提示，并记录提示解决的是哪一层卡点
- 48 小时后无参考重写
- 周末随机抽一道变式口头讲解

反馈：
- 独立推导比例
- 需要哪一级提示
- 重写时的错误类型
- 能否解释为什么该数据结构足够

调整规则：
- 若实现错误多，减少新题并补边界测试
- 若只会复现原题，增加变式和对比题
- 若无法推导，先练“暴力重复点 -> 状态”而不是继续背模板
```

这里没有承诺“做满多少题就必然达到某水平”。它提供的是一个能持续产生反馈、允许修正的过程。

## 11. 最后保留三条边界

第一，模型不是现实。它必然省略细节，价值在于帮助行动和更新，而不是证明自己完全掌控局面。

第二，可量化不等于重要，不可量化也不等于无法思考。尊严、信任、意义和体验不能因为难以计数就被排除。

第三，人不是算法中的元素。涉及他人时，过程建模必须保留对方的主体性、知情权和选择权，不能把“预测与优化”变成操纵。

可以把全文压缩成一句话：

> 能稳定计算的地方用公式，不能直接计算的地方建过程；对过程持续观察、保留余量，并允许事实修改自己的模型。
