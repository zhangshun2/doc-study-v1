## 阶段 1｜交接 1：原题事实

```text
小白此刻真正的原话疑问：硬币数量无限，是不是可以把同一枚硬币想拿几次就拿几次，只要最后金额刚好等于 amount？
为什么这个疑问现在才出现：刚打开题，只看到“不同面额”“无限”和“最少硬币个数”，还没确认“无限”限制的是面额种类还是物理硬币数量。
纸上实际做了什么：圈出“不同面额的硬币”“组成总金额”“最少的硬币个数”“没有组合返回 -1”“每种硬币数量无限”，抄下三个官方示例。
做完后新增了什么证据：可以选择任意面额、任意次数；目标不是所有凑法，而是硬币枚数最少的凑法；凑不出时输出 -1；amount 为 0 时输出 0。
这份证据只能说明什么：答案由一组可重复选择的面额和一个总枚数共同决定。
它还不能说明什么：一个普通人先选哪枚硬币、试错后怎么回退、什么时候知道已经找到最少枚数。
因此下一问只能是什么：拿着 coins 和 amount，人怎样一枚一枚试，直到要么凑出金额，要么确认不可能？
回答它需要什么证据：一条按时间执行、允许失败并知道停止条件的人话过程。
如果答不出，退回哪里：原句和示例，重新确认“无限”和“最少”分别限制什么。
```

### 官方题面原句

> 给你一个整数数组 `coins` ，表示不同面额的硬币；以及一个整数 `amount` ，表示总金额。
>
> 计算并返回可以凑成总金额所需的 **最少的硬币个数** 。如果没有任何一种硬币组合能组成总金额，返回 `-1` 。
>
> 你可以认为每种硬币的数量是无限的。

### 只抄能指回原句的事实

| 原句 | 我现在能确认的事实 | 来源 | 我不能自行补上的假设 |
| --- | --- | --- | --- |
| `coins` 表示不同面额 | 每种面额是一个可选择的值 | 事实 | 面额是否排序、是否有倍数关系 |
| 每种硬币数量无限 | 同一种面额可以在一条方案里重复出现 | 事实 | 重复使用后一定能更少枚数 |
| 凑成总金额 `amount` | 已选面额之和必须恰好等于目标，不能多也不能少 | 事实 | 每次选最大面额就一定最优 |
| 返回最少硬币个数 | 多条可行方案之间要比较枚数 | 事实 | 第一次找到的方案就是最少方案 |
| 没有组合时返回 `-1` | 必须区分“凑不出”和“需要 0 枚” | 事实 | 可以把不可达状态当成普通数字 0 |
| `amount` 可以为 0 | 如果目标本来就是 0，不需要任何硬币 | 事实 | 仍要继续尝试正数面额 |


## 阶段 2｜交接 2：人话扩写

```text
小白此刻真正的原话疑问：我手里有几种硬币，第一次到底拿哪一枚？
为什么这个疑问现在才出现：输入、输出和边界已分开，但还没有可执行的尝试顺序。
纸上实际做了什么：把“凑金额”改写成从剩余金额开始，每次挑一种面额减去；减到 0 记下一次成功，减成负数就撤回上一次选择。
做完后新增了什么证据：一条能做完整搜索的过程：沿当前选择往下走，失败回到上一个分叉，成功记录枚数，最后在所有成功方案里取最少。
这份证据只能说明什么：这样能走到所有可能的硬币序列，也能发现完全凑不出的情况。
它还不能说明什么：硬币选择、剩余金额、方案枚数和最终答案是不是同一种对象，也不能提前宣布最少枚数。
因此下一问只能是什么：题目里哪些东西可以被重复选择，哪些状态会随每一步改变，答案最后归属于谁？
回答它需要什么证据：对象表和最小身份证据。
如果答不出，退回哪里：交接 1 的“无限使用”和“最少枚数”。
```

关键原句的九项记录（事后重建）：

```text
原句（不改写）：计算并返回可以凑成总金额所需的最少的硬币个数。如果没有任何一种硬币组合能组成总金额，返回 -1。
代词指向：“最少的硬币个数”是数量；“总金额”是剩余金额回到 0 的目标；“-1”表示所有合法路径都失败。
谁在做事、手里有什么：我拿着 coins、当前剩余金额和当前路径已经用掉的枚数。
第一步：从剩余金额等于 amount、已用 0 枚开始，尝试第一枚不超过剩余金额的硬币。
重复动作：每次从剩余金额减去一枚硬币、把已用枚数加一，再把新局面继续展开。
动作改变或停止：剩余金额等于 0 时记录一条成功路径；小于 0 时撤回；所有分支走完才停止。
最后交回：在成功路径的枚数中取最小值；一条成功路径都没有时交回 -1。
忽略会错在：忽略“无限个”会少枚举重复使用；忽略“最少”会把第一条成功当答案；忽略“-1”会把无解写成 0 枚。
来源：事实
合成可执行过程：从金额 amount 和 0 枚开始，每次尝试一枚不超过剩余金额的硬币并展开新局面；到 0 记录枚数，低于 0 撤回；所有分支结束时比较成功路径并取最小枚数，没有成功路径就返回 -1。
```

```text
第二次变化；数据范围之后：哪份信息重复查询、失效、复用或必须保序？
```

### 逐句扩写

| 原句事实 | 它在人的过程里新增什么 | 如果忽略会错在哪 | 来源 |
| --- | --- | --- | --- |
| 硬币面额来自 `coins` | 每一步只能从给定面额中选一枚 | 可能使用题目没有给的面额 | 事实 |
| 每种硬币无限 | 同一面额在尝试中可以被再次选择 | 可能错误地认为每枚只能用一次 | 事实 |
| 要凑成总金额 | 每选一枚都减少剩余金额，减到 0 才成功 | 可能把超过目标的方案也算作成功 | 事实 |
| 求最少硬币个数 | 每成功一条方案还要和已有最少值比较 | 可能把第一条成功方案直接当成答案 | 事实 |

### 合成后的人话过程

```text
我手里有硬币面额和剩余金额。
我从剩余金额等于 amount、已用 0 枚开始。
每一步挑一种硬币，把它从剩余金额里减掉，并把已用枚数加一。
如果剩余金额变成 0，我记录这条方案的枚数。
如果剩余金额小于 0，我撤销这次选择，回到上一步换一种硬币。
所有选择都试完以后，在所有成功记录里取最少枚数。
如果没有任何成功记录，就返回 -1。
```

## 阶段 3｜交接 3：对象

```text
小白此刻真正的原话疑问：同一种面额的硬币用了很多次，它们到底是很多个对象，还是同一个可重复选择的对象？
为什么这个疑问现在才出现：人话过程已经出现“同一面额再次选择”，但还没有区分面额种类、每一次选择和金额状态。
纸上实际做了什么：用 coins = [2]、amount = 4 写出 2 + 2；两个 2 来自同一种面额，但代表两次选择、两枚计数。
做完后新增了什么证据：面额种类可以重复使用；每次使用会增加一枚计数；剩余金额是随选择变化的独立状态。
这份证据只能说明什么：答案不是“用了哪些不同面额”，而是“从哪些面额中选了多少次，总次数是多少”。
它还不能说明什么：完整搜索每一步怎样改变剩余金额，以及哪些失败路径需要撤回。
因此下一问只能是什么：普通人不用任何优化时，怎样一枚一枚试到一个完整方案，并证明失败的路径确实被检查过？
回答它需要什么证据：最小完整例子的逐行搜索。
如果答不出，退回哪里：交接 2 的尝试与撤回过程。
```

### 七列对象表

| 题目对象 | 值和状态 | 身份由什么决定 | 位置或时间 | 从何时有效到何时失效 | 和谁发生关系 | 最终要得到什么 |
| --- | --- | --- | --- | --- | --- | --- |
| 硬币面额 | `coins[i]` | 面额数值决定可选项 | 输入数组中的一种选择 | 整题都可重复选择 | 每次选择都会减少剩余金额 | 不直接成为输出 |
| 一次硬币选择 | 当前拿的是哪种面额 | 面额和这一次选择共同决定 | 搜索路径中的一步 | 进入该分支时有效，撤回后失效 | 改变剩余金额和已用枚数 | 增加一枚方案计数 |
| 剩余金额 | 还差多少才凑到目标 | 当前路径已经选过的面额总和决定 | 随搜索路径变化 | 每次选择/撤回时更新 | 决定还能选哪些硬币以及是否成功 | 为状态复用提供身份 |
| 成功方案 | 一组选择和它的总枚数 | 一条能减到 0 的完整路径 | 一条搜索路径 | 找到后保留枚数，路径可撤回 | 与其他成功方案的枚数比较 | 提供候选最少枚数 |
| 最终答案 | 最少枚数或 `-1` | 所有成功方案中的最小值 | 整题结束 | 搜索完成后确定 | 与每个成功方案比较 | 返回整数 |

同一个面额可以被使用多次，但每一次使用都增加枚数；不能因为面额只出现一次，就把它当成最多使用一次。

## 阶段 3｜交接 4：最笨但正确的过程

```text
小白此刻真正的原话疑问：一条路径怎样开始、失败，然后回到上一步换硬币？
为什么这个疑问现在才出现：对象身份已经分开，但还没有实际执行一次完整搜索。
纸上实际做了什么：用 coins = [1,3,4]、amount = 6，从剩余 6 开始按面额尝试，记录成功路径和枚数。
做完后新增了什么证据：先试 4 得到 4+1+1 的三枚方案；继续尝试后发现 3+3 的两枚方案；也可以找到 1 重复六次的方案；最少是 2。
这份证据只能说明什么：逐条搜索能覆盖可行与不可行路径，并找到正确最少枚数。
它还不能说明什么：第一条成功方案出现时，为什么不能立刻停止；哪些状态会在不同路径中重复出现。
因此下一问只能是什么：找到 4+1+1 以后，哪一份记录发生了变化，什么时候才能说最少值已经确定？
回答它需要什么证据：第一次变化六字段。
如果答不出，退回哪里：本交接的逐行搜索和对象表。
```

### 最小完整例子的逐行搜索

```text
coins = [1,3,4]
amount = 6
```

| 步骤 | 当前选择路径 | 已用枚数 | 剩余金额 | 当前结果 | 下一步动作 |
| --- | --- | --- | --- | --- | --- |
| 1 | 4 | 1 | 2 | 还没成功 | 继续从 2 中选 |
| 2 | 4 + 1 | 2 | 1 | 还没成功 | 继续 |
| 3 | 4 + 1 + 1 | 3 | 0 | 成功，最少记录变成 3 | 回到上一个分叉继续搜索 |
| 4 | 4 + 3 | 2 | -1 | 超过目标，失败 | 撤回 3，换更大面额也只会更负 |
| 5 | 3 | 1 | 3 | 还没成功 | 继续 |
| 6 | 3 + 3 | 2 | 0 | 成功，最少记录从 3 变成 2 | 继续检查是否还有更少 |
| 7 | 1 + 1 + 1 + 1 + 1 + 1 | 6 | 0 | 成功，但枚数更大 | 不替换最少记录 |

这个顺序故意先选较大的 4，让“最直觉的贪心”只得到三枚；继续搜索后才发现 3+3 只用两枚。因此慢过程必须允许失败和回退，不能只保留一条看起来顺眼的路径。

## 阶段 3｜交接 5：第一次变化与答案确定时刻

```text
小白此刻真正的原话疑问：第一次得到 4+1+1 时已经成功了，为什么还不能直接返回 3？
为什么这个疑问现在才出现：逐行搜索第一次产生了成功方案，但题目要求所有成功方案中的最少枚数。
纸上实际做了什么：把第一次成功标成“记录变为 3”，继续找到 3+3 后改成 2，再检查其余分支没有更少。
做完后新增了什么证据：第一次变化发生在第一次成功方案出现时；最终答案要在所有可能路径检查完以后才确定。
这份证据只能说明什么：成功方案出现只说明“至少有一种方案”，不说明“已经最少”。
它还不能说明什么：全量路径在最大金额上会重复多少次，以及同一剩余金额为什么会从不同路径反复到达。
因此下一问只能是什么：amount 最大时，这种逐条尝试最坏会产生多少次选择？
回答它需要什么证据：完整约束、最坏路径数量和操作预算。
如果答不出，退回哪里：本交接的逐行搜索和交接 1 的“最少”。
```

```text
谁发生变化：当前最少硬币记录
触发事件：搜索第一次到达剩余金额 0，得到一条完整成功方案
变化前：还没有成功方案，最少记录是“未确定”
变化后：记录变成 3，因为 4 + 1 + 1 使用了三枚
答案确定时刻：所有可能选择路径都检查完，且没有更少方案时
为什么不是更早或更晚：第一次成功只证明可行；更早无法排除两枚或一枚方案，全部路径结束后才没有未比较方案
```

后面 3+3 把记录从 3 改成 2，说明“第一次变化”和“答案确定时刻”确实不是同一件事。

## 阶段 4｜交接 6：数据范围与慢过程预算

```text
小白此刻真正的原话疑问：如果金额是一万，我每次都在最多十二种面额中尝试，路径数量会不会爆炸？
为什么这个疑问现在才出现：完整搜索已经走通，现在才有分支动作、层数和最坏次数可以估算。
纸上实际做了什么：抄下 coins 最多 12 种、amount 最大 10^4；观察每条路径最多走 amount 层，每层最多试 coins.length 种面额。
做完后新增了什么证据：不加记忆时，同一类选择会大量重复，路径数量可能远远超过 amount * coins.length 这一量级。
这份证据只能说明什么：按完整序列逐条搜索不能稳定承受，范围要求消除重复路径。
它还不能说明什么：哪些剩余金额会从多条路径重复到达，以及应该保留该金额的什么结果。
因此下一问只能是什么：回到同一搜索过程，能否找到不同选择顺序到达同一个剩余金额的最小例子？
回答它需要什么证据：重复到达的路径、它们共同缺少的信息和可以复用的结果。
如果答不出，退回哪里：交接 4 的搜索过程；没有路径证据就没有资格读范围。
```

### 官方约束

- `1 <= coins.length <= 12`
- `1 <= coins[i] <= 2^31 - 1`
- `0 <= amount <= 10^4`

### 最坏操作预算

```text
一条选择路径最多走 amount 层。
每层最多试 coins.length 种面额。
若不消除重复路径，分支会沿层数继续展开，
总路径数量可能远大于 amount * coins.length。

amount = 10^4、coins.length = 12 时：
单层最多 12 个选择，重复层数最多 10^4。
```

| 官方约束 | 限制了什么 | 慢过程最坏预算 | 排除哪些复杂度家族 | 仍不能确定什么 |
| --- | --- | --- | --- | --- |
| `amount <= 10^4` | 剩余金额最多一万种 | 可以接受与金额近似线性的状态量 | 指数级完整路径展开 | 哪些路径会到达同一个剩余金额 |
| `coins.length <= 12` | 每层选择种类很少 | 每个金额最多检查十二种面额 | 依赖巨大分支因子反而更差的方案 | 是否应该保存每个金额的最小结果 |
| 面额可以重复使用 | 选择层数可能很多 | 同一金额可能从不同顺序到达 | 把每种面额限制为只用一次的方向 | 复用结果是否仍满足无限使用 |
| 求最少枚数 | 同一金额可能对应多种方案 | 需要比较不同路径的枚数 | 只记录“能否到达”的空间 | 应该保存能否到达还是最少枚数 |

### 用最小重复路径捕捉子问题

取 `coins = [1,2,5]`、`amount = 11`：

```text
路径 A：1 + 2，已用 2 枚，剩余 8
路径 B：2 + 1，已用 2 枚，剩余 8
```

两条路径前面选择的顺序不同，但到达的剩余金额相同。之后都只能从 `[1,2,5]` 中继续凑 8，已经用掉的 2 枚也一样。因此：

```text
凑 8 所需的最少枚数，不会因为先选 1 再选 2 或先选 2 再选 1 而改变。
```

真正重复的不是硬算 1 + 2 和 2 + 1 的加法，而是：

```text
反复询问：凑出剩余金额 x 至少还需要多少枚硬币？
```

### 状态和初始条件

```text
dp[x]：恰好凑出金额 x 所需的最少硬币枚数
```

初始化：

```text
dp[0] = 0
dp[1..amount] = amount + 1
```

`amount + 1` 表示不可达。面额至少为 1，所以任何真实可行方案最多使用 `amount` 枚；用 `amount + 1` 不会和合法答案混淆，也不会在加一时溢出。

### 一次转移

```text
当前金额 current
尝试每一种面额 coin
如果 coin <= current：
    dp[current] = min(dp[current], dp[current - coin] + 1)
```

金额上限是 `amount`，所以可能达到 `amount + 1` 个最小线性值；不重复展开路径时，每个金额最多检查十二种面额，最坏操作量与二者乘积同阶。

### 不变量

```text
计算金额 current 之前，所有 0 <= x < current 的 dp[x] 已经确定。
dp[x] 要么是不可达标记，要么是恰好凑出 x 的最少枚数。
dp[current] 只读取严格更小的金额。
```

### 为什么金额递增不会漏

任意凑出 `current` 的方案都有一枚“最后放进去”的硬币 `coin`。去掉它以后，剩余金额是 `current - coin`，严格小于 `current`。递增计算时这份更小结果已经完成，所以每个可能的最后一枚都能被检查到。

### 题目对象到代码的逐段映射

| 题目对象 | 人工动作 | 需要什么操作 | 状态变量 | 初始化 | 转移 | 更新顺序或不变量 | 对应反例 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 当前金额 | 已经走到还差 `current` 元 | 按金额读取此前结果 | `current`、`dp` | 从 1 到 amount | 每轮处理一个金额 | 处理 current 前，更小金额已完成 | 先算大金额会读到不可达默认值 |
| 最后一枚硬币 | 从可选面额中挑一枚作为最后一步 | 枚举可选面额并读取更小金额 | `coin`、`current - coin` | 无额外初始化 | `dp[current - coin] + 1` | 只读取严格更小的下标 | `coin > current` 时不能使用 |
| 当前最少枚数 | 在多个最后硬币方案中取更少者 | 比较并更新最小值 | `dp[current]` | `amount + 1` | `Math.min(...)` | 每轮只减少，不会把已更优值变差 | 从不可达标记直接返回会错 |
| 0 元目标 | 不选硬币就已经恰好凑出 | 提供初始合法结果 | `dp[0]` | `0` | 被更大金额读取 | 必须先于所有正金额确定 | 把 `dp[0]` 设为不可达会破坏所有方案 |

### 最小反例

```text
最小输入：coins = [2]，amount = 3
原本应保持的不变量或更新顺序：不可达状态不能等于 0
如果破坏它，具体哪一步先算错：把 dp[1]、dp[2]、dp[3] 都初始化为 0，会把没有方案的金额 3 误当成已经凑出
错误输出：0
修复动作：除 dp[0] 外填入 amount + 1，最后仍为标记时返回 -1
```

依赖顺序反例：

```text
最小输入：coins = [2]，amount = 4
若先算金额 4 再算金额 2，dp[2] 还没有确定，dp[4] 就读取不到 2 枚的合法结果。
按金额 1、2、3、4 递增，dp[2] 先变成 1，dp[4] 才能从 dp[2] + 1 得到 2。
```

### 伪代码

```text
unreachable = amount + 1
dp[0] = 0
其余 dp[x] = unreachable

for current from 1 to amount:
    for coin in coins:
        if coin <= current:
            dp[current] = min(dp[current], dp[current - coin] + 1)

if dp[amount] == unreachable:
    return -1
return dp[amount]
```

### 权威 Java 实现

> 本节是本题可提交代码和复杂度的唯一权威副本。

### LeetCode 可直接提交代码

> 入口类与方法已根据 2026-08-30 的官方 Java 模板核验。本代码不包含本地 `main`。

```java
import java.util.Arrays;

class Solution {
    public int coinChange(int[] coins, int amount) {
        int unreachable = amount + 1;
        int[] dp = new int[amount + 1];
        Arrays.fill(dp, unreachable);
        dp[0] = 0;

        for (int current = 1; current <= amount; current++) {
            for (int coin : coins) {
                if (coin <= current) {
                    dp[current] = Math.min(
                            dp[current], dp[current - coin] + 1);
                }
            }
        }
        return dp[amount] == unreachable ? -1 : dp[amount];
    }
}
```

### 复杂度和正确性

- 时间复杂度：`O(amount * coins.length)`。每个金额枚举每种面额。
- 空间复杂度：`O(amount)`。保存每个金额的最少枚数。
- 不丢解：任意方案都可以取出一枚最后的硬币，剩下一份更小金额的子方案。
- 取到最少：所有可能最后一枚都参与比较，更小金额已经最优，因此当前金额也最优。
- 不混淆无解：`amount + 1` 始终大于任何真实方案枚数，不会被误当成合法答案。

## 边界与易错点

- `amount == 0` 时答案是 0，不需要硬币。
- 不可达哨兵不要用 `Integer.MAX_VALUE` 后直接加一，否则可能溢出。
- `amount + 1` 是安全哨兵：面额至少为 1，任何可行方案最多使用 `amount` 枚。
- 本题硬币无限；若每枚只能用一次，转移来源和循环含义会改变。
- 判断不可达可以写 `dp[amount] == unreachable`，因为每次更新只会把状态改小。
- 当前金额必须移到更小的可达到金额。因为选择的是“正数面额”且只读取 `current-coin`，所以不会出现负下标。

## 复习闭环

- **本次主分析法：** 从逐条凑钱路径出发，发现同一个剩余金额被不同顺序重复到达，再把“还需多少枚”保存成子问题。
- **闭卷过程链：** 读题确认无限和最少 -> 逐条搜索 -> 第一次成功不等于最优 -> 发现重复金额 -> 比较候选 -> 写按金额递增的状态。
- **最早断点：** 为什么到达同一个剩余金额后，前面的选择顺序不再重要。
- **下次第一步：** 关掉本页，用 `[1,2,5]`、11 写出两条到达剩余金额 8 的不同路径。
