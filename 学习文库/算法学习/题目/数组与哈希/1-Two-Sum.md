## 阶段 1｜交接 1：原题事实

```text
小白此刻真正的原话疑问：题目说找“两个整数”，又说不准使用同一个元素两次，那 [3, 3] 这样的两个 3 到底算几个东西？
为什么这个疑问现在才出现：刚打开题，只看见了“找两个数”和“返回下标”，还没有核对答案对象的身份。
纸上实际做了什么：圈出“和为目标值”“两个”“数组下标”“每种输入只会对应一个答案”“不能使用两次相同的元素”，再抄下三个官方示例。
做完后新增了什么证据：最终要交回两个不同的原始下标；两个值可以相同，但两个位置不能相同；题目保证只有一个合法答案，顺序不限。
这份证据只能说明什么：答案是一对不同的位置，不是两个随便出现的数值。
它还不能说明什么：一个没有方法记忆的人应该先拿哪个位置、再和哪个位置比较，以及什么时候停止。
因此下一问只能是什么：拿着 nums 和 target，一个普通人第一眼先固定谁，接下来怎样检查另一个人？
回答它需要什么证据：一条按时间顺序执行的人话过程。
如果答不出，退回哪里：原句和示例，重新确认“两个不同下标”与“唯一答案”。
```

### 官方题面原句

> 给定一个整数数组 `nums` 和一个整数目标值 `target`，请你在该数组中找出 **和为目标值** `target` 的那 **两个** 整数，并返回它们的数组下标。
>
> 你可以假设每种输入只会对应一个答案，并且你不能使用两次相同的元素。
>
> 你可以按任意顺序返回答案。

### 只抄能指回原句的事实

| 原句 | 我现在能确认的事实 | 来源 | 我不能自行补上的假设 |
| --- | --- | --- | --- |
| 给定一个整数数组 `nums` 和一个整数目标值 `target` | 输入有两个对象：一组按位置排列的整数和一个目标整数 | 事实 | 数组是否有序、是否没有重复值 |
| 找出和为目标值 `target` 的那两个整数 | 要找到两个数值，它们相加必须恰好等于 `target` | 事实 | 是否只需要考虑相邻位置 |
| 返回它们的数组下标 | 输出不是两个数值，而是这两个元素原来所在的位置 | 事实 | 返回顺序是否有大小要求 |
| 每种输入只会对应一个答案 | 在题目保证下，不需要处理多个答案，也不需要选“最左”或“最优”答案 | 事实 | 题目保证之外是否仍会出现无解输入 |

### 官方示例

```text
示例 1
输入：nums = [2,7,11,15], target = 9
输出：[0,1]
解释：nums[0] + nums[1] = 2 + 7 = 9

示例 2
输入：nums = [3,2,4], target = 6
输出：[1,2]

示例 3
输入：nums = [3,3], target = 6
输出：[0,1]
```

示例 3 是最小身份证据：两个 `3` 的值相同，但位置分别是 `0` 和 `1`。因此后面的过程不能只保存或比较一个“值”，还必须记住位置。

## 阶段 2｜交接 2：人话扩写

```text
小白此刻真正的原话疑问：我总不能一眼扫出答案，那第一步究竟先抓住哪一个位置？
为什么这个疑问现在才出现：输入、输出和保证已经分开，但它们仍是一段静态文字，没有动作顺序。
纸上实际做了什么：把“找两个数”改写成“先固定一个位置，再从另一个位置开始逐个检查”，并逐句核对有没有偷偷加入题目没保证的条件。
做完后新增了什么证据：一条能照着演完的过程：固定第一个位置，检查它后面的不同位置；两个位置上的数相加等于 target 就返回；不等于就继续换位置。
这份证据只能说明什么：这样会检查到所有不同的位置对，也可以避免同一个位置被拿两次。
它还不能说明什么：值、位置和“答案对”是不是三种不同对象，也不知道哪一刻答案真正确定。
因此下一问只能是什么：题目里到底有哪些对象，两个相同的值为什么仍然可能是两个不同对象？
回答它需要什么证据：一个值相同但位置不同的最小例子，以及题目要求交回什么。
如果答不出，退回哪里：交接 1 的“返回下标”和“不能使用两次相同的元素”。
```

### 逐句扩写

| 原句事实 | 它在人的过程里新增什么 | 如果忽略会错在哪 | 来源 |
| --- | --- | --- | --- |
| 数组 `nums` 有多个位置 | 每个位置上的值都有自己的位置身份 | 只记两个数值，最后不知道要返回哪两个下标 | 事实 |
| 选两个整数 | 一次要拿出一对位置，而不是只看一个元素 | 可能把单个元素当成答案 | 事实 |
| 它们的和等于 `target` | 拿到两个数后，先计算和，再与目标值比较 | 可能只因为两个数都出现过就返回 | 事实 |
| 返回两个下标 | 一旦找到满足条件的两个位置，要保留这两个位置的身份 | 只返回数值或不完整的下标 | 事实 |
| 不能使用两次相同的元素 | 第二个位置必须与第一个位置不同 | 可能把同一个下标拿两次 | 事实 |
| 每种输入只有一个答案 | 第一次找到合法的一对后，不需要继续挑选 | 可能在唯一答案之后继续处理并覆盖它 | 事实 |

### 合成后的人话过程

```text
我手里有 nums 和 target。
我先把位置 0 当作第一个位置。
我从第一个位置后面的一个位置开始，找第二个位置。
我把两个位置上的数相加，再和 target 比较。
如果相等，就把这两个位置交回去并停止。
如果不等，就换下一个第二个位置。
第一个位置后面的位置都试完，再把第一个位置向后移动一格。
直到找到那一对为止。
```

这里有两个容易混淆的动作：

- “两个数”不是“两个值必须不同”。题目允许值和值相同，只禁止同一个位置被使用两次。
- “按任意顺序返回”不代表可以按任意顺序使用同一个元素。两个下标仍然必须不同。

## 阶段 3｜交接 3：对象

```text
小白此刻真正的原话疑问：数组里两个 3 看起来一模一样，它们到底算一个对象还是两个对象？
为什么这个疑问现在才出现：人话过程已经区分第一个位置和第二个位置，但还没有证据说明“值”和“位置”谁决定身份。
纸上实际做了什么：写出 nums = [3, 3]，target = 6，并在两个 3 下面分别标上位置 0 和位置 1。
做完后新增了什么证据：两个 3 的数值相同，位置不同；它们的和等于 6，可以组成合法答案 [0,1]。
这份证据只能说明什么：位置是对象身份的一部分；两个值相同的元素不能被合并成一个没有位置的对象。
它还不能说明什么：最笨的比较过程具体怎样逐步走完，哪一步会让答案确定。
因此下一问只能是什么：照最直接的办法，第一个位置和第二个位置怎样一步一步检查到停止？
回答它需要什么证据：一个最小完整例子的逐行手算。
如果答不出，退回哪里：交接 2 的人话过程，检查第二个位置为什么必须来自另一个下标。
```

### 七列对象表

| 题目对象 | 值和状态 | 身份由什么决定 | 位置或时间 | 从何时有效到何时失效 | 和谁发生关系 | 最终要得到什么 |
| --- | --- | --- | --- | --- | --- | --- |
| 数值 | `nums[index]` 的取值，例如 `3` | 值本身不能单独决定身份 | 跟随所在位置 | 从读入起一直有效，数值本身不会失效 | 与另一个数值相加，和 `target` 比较 | 本身不是答案 |
| 位置 | 当前是待检查还是已经参与答案 | 数组下标 `index` | 数组中的原始位置 | 从输入开始到本题结束都保持原身份 | 两个不同位置组成一个待检查的位置对 | 输出中的两个整数 |
| 目标值 | 固定的 `target` | 由这一次输入确定 | 不随位置移动 | 整道题内始终有效 | 约束两个位置上的数值之和 | 用来判断一对位置是否合法 |
| 一对位置 | 待检查或已经合法 | 由两个不同下标共同决定 | 两个原始位置 | 两个位置都进入检查时成立；命中后停止继续检查 | 共同产生一次和 | 合法时成为答案 |

值相同的两个位置仍然是两个不同对象。比如 `[3,3]` 中两个 `3` 有相同的值，但位置分别是 `0` 和 `1`，所以不能返回 `[0,0]`。

## 阶段 3｜交接 4：最笨但正确的过程

```text
小白此刻真正的原话疑问：我固定第一个位置以后，第二个位置到底要检查到哪里才算把这一轮走完？
为什么这个疑问现在才出现：值、位置和位置对已经分清，但还没有按真实时间执行过一遍。
纸上实际做了什么：用 nums = [3,2,4]、target = 6，固定第一个位置从 0 开始，再让第二个位置只检查它后面的位置。
做完后新增了什么证据：先检查 (0,1) 得到 3+2=5，再检查 (0,2) 得到 3+4=7；固定位置 1 后检查 (1,2) 得到 2+4=6，第一次出现合法位置对。
这份证据只能说明什么：这条最笨过程能完整找到合法位置对，而且不会把同一个位置使用两次。
它还不能说明什么：哪一刻这对位置从“刚被发现”变成“可以停止的答案”，也不知道这个过程在最大输入上是否太慢。
因此下一问只能是什么：第一次出现合法的和时，究竟是谁从什么状态变成了什么状态？
回答它需要什么证据：谁发生变化、触发事件、变化前、变化后、答案确定时刻，以及为什么不是更早或更晚。
如果答不出，退回哪里：交接 3 的对象表和本交接的逐行手算。
```

取 `nums = [3,2,4]`，`target = 6`：

| 步骤 | 我现在看见什么 | 这一步处理谁 | 具体做什么 | 做完后什么变了 | 为什么还能继续 |
| --- | --- | --- | --- | --- | --- |
| 1 | 第一个位置 0，第二个位置 1 | 位置 0 与位置 1 | 计算 `3 + 2 = 5` | 这一对不合法 | 第一个位置 0 的右侧位置还没检查完 |
| 2 | 第二个位置移动到 2 | 位置 0 与位置 2 | 计算 `3 + 4 = 7` | 这一对不合法 | 第一个位置 0 的右侧位置已经检查完 |
| 3 | 第一个位置移动到 1 | 位置 1 与位置 2 | 计算 `2 + 4 = 6` | 第一次出现合法位置对 | 题目保证唯一，答案可以停止 |

这里没有优化理由，也没有保存历史信息。它只是一条能完整复走的人工过程。

## 阶段 3｜交接 5：第一次变化与答案确定时刻

```text
小白此刻真正的原话疑问：刚找到 (1,2) 时，为什么可以直接停，而不是继续检查后面还有没有别的答案？
为什么这个疑问现在才出现：手算第一次出现了合法的两数和，但“合法”能不能直接等于“最终答案”还需要题目保证。
纸上实际做了什么：在 (1,2) 上圈出“合法”，再回看原题“每种输入只会对应一个答案”。
做完后新增了什么证据：变化前还没有合法位置对；触发事件是第一次满足两个数之和等于 target；变化后出现一对合法位置；唯一性保证让这对位置直接成为最终答案。
这份证据只能说明什么：在本题的唯一性条件下，第一次合法位置对就是答案确定时刻。
它还不能说明什么：这种逐个检查在最大输入上会重复多少次，是否值得减少工作。
因此下一问只能是什么：最坏输入下，最笨过程大约要比较多少对位置？
回答它需要什么证据：完整数据范围、最坏输入形状和一次最坏预算。
如果答不出，退回哪里：交接 4 的逐行手算和交接 1 的唯一性保证。
```

```text
谁发生变化：还没有答案的检查过程，以及由位置 1 和位置 2 组成的位置对
触发事件：位置 1 与位置 2 上的数相加，第一次等于 target
变化前：已经检查过的位置对都不满足条件，我还没有答案。
变化后：这两个位置被确定为答案。
答案确定时刻：第一次出现合法位置对的那一步；题目保证只有一个答案。
为什么不是更早或更晚：更早时还没有任何合法位置对，答案不存在；题目又保证只有一个答案，所以第一次出现后也不必继续寻找。
```

如果题目没有唯一性保证，第一次找到合法位置对只能说明“找到一个候选”，不能自动说明后面没有更好的答案。本题可以停止，是因为原题明确保证每种输入只有一个答案。

## 阶段 4｜交接 6：数据范围与慢过程预算

```text
小白此刻真正的原话疑问：如果 nums 非常长，我固定第一个位置后都把后面检查完，最坏要做多少次加法？
为什么这个疑问现在才出现：答案怎样出现已经确定，但还不知道这条能工作的慢过程是否会超过输入规模允许的代价。
纸上实际做了什么：抄下 2 <= nums.length <= 10^4、元素和目标都在正负 10^9 内；选择没有提前命中的最长过程，数每个第一个位置还要检查多少个第二个位置。
做完后新增了什么证据：第一个位置为 0 时最多检查 n-1 个位置，为 1 时最多检查 n-2 个，总比较次数最多为 n(n-1)/2；n=10^4 时接近五千万次。
这份证据只能说明什么：逐对完整重扫的平方级代价不能作为最终方向；值域跨度远大于输入长度，也不能把每个数值直接当成连续位置来分配空间。
它还不能说明什么：过程里哪份历史信息会被重复询问，未来需要按什么键取回什么内容，以及哪些操作必须保序。
因此下一问只能是什么：带着五千万次的代价回到同一条过程，站在当前值上时，哪份过去的信息会被一遍又一遍再问起？
回答它需要什么证据：同一条人工过程里的最小重复例子。
如果答不出，退回哪里：交接 4 的人工过程和交接 5 的答案确定时刻。
```

### 官方约束

- `2 <= nums.length <= 10^4`
- `-10^9 <= nums[i] <= 10^9`
- `-10^9 <= target <= 10^9`
- 每种输入只会存在一个有效答案
- 进阶目标：思考一个时间复杂度小于 `O(n^2)` 的算法

### 最坏操作预算

```text
第一位置取 0 时，最多检查 n - 1 个第二位置
第一位置取 1 时，最多检查 n - 2 个第二位置
...
总比较次数最多为 n(n - 1) / 2

n = 10^4 时：
10000 * 9999 / 2 = 49,995,000
```

| 官方约束 | 限制了什么 | 慢过程最坏预算 | 排除哪些复杂度家族 | 仍不能确定什么 |
| --- | --- | --- | --- | --- |
| `n <= 10^4` | 最多一万个位置 | 约 `n^2/2`，接近五千万次比较 | 稳定的平方级全量重扫 | 哪份信息会被重复读取 |
| 元素和目标在 `±10^9` 内 | 数值跨度约为二十亿 | 不能按整个数值跨度分配连续空间 | 与数值跨度成正比的空间方案 | 查询时应该取回什么 |
| 返回原始下标 | 不能丢失位置身份 | 任何重排都要额外保存原位置 | 会让原位置无法恢复的方向 | 怎样在查询值的同时保留位置 |

### 用最小例子捕捉重复

取 `nums = [2,7,11,15]`，`target = 9`。

当当前值来到 `7` 时，需要的搭档值是：

```text
9 - 7 = 2
```

`2` 已经在当前值之前出现过。如果每次来到一个新位置都重新向左找，过去的位置会被未来的多个当前位置反复检查。

这里真正重复的不是“把加法再算一次”，而是：

```text
反复询问：某个需要的值，是否已经在历史位置出现过？
如果出现过，它原来的位置是什么？
```

### 为什么可以把当前值当成较晚的位置

对任意一个合法数对，两个下标总有一个较小、一个较大：

```text
若 i < j，且 nums[i] + nums[j] = target
那么处理到 j 时，i 已经处理过了。
```

返回顺序任意，所以可以把 `j` 当作当前值，把 `i` 当作之前出现过的搭档。这样每个合法数对至少会在较晚的那个位置被检查一次，不会因为固定一个扫描方向而漏掉。

### 顺序要求从哪里来

题目说不准使用两次相同的元素。用 `[3,3]`、`target = 6` 检查：

- 处理第一个 `3` 时，如果先把自己加入历史，再查询补数，就会查到当前位置自身，得到 `[0,0]`。
- 先查询、后加入时，处理第一个 `3` 查不到自己；处理第二个 `3` 才能查到前面位置 `0` 的 `3`，得到 `[0,1]`。

### 一次转移

```text
读取当前值 nums[i]
计算 need = target - nums[i]
查询 need 的历史位置
```

### 为什么更新顺序不能交换

如果先把当前值加入历史，再查询 `need`，当前下标可能被自己查询到。最小反例是 `[3,3]`、`target = 6`：处理下标 `0` 时，当前值本身就会满足 `need`，得到错误的 `[0,0]`。

因此必须：

```text
先查询历史
后加入当前值
```

### 为什么不会漏

对任意合法答案，两个下标中总有一个较晚出现。扫描到较晚的那个下标时，较早的下标已经在历史中；此时计算它的补数，就一定查询到较早位置。题目保证只有一个合法答案，所以第一次命中就是答案。

### 权威 Java 实现

> 本节是本题可提交代码和复杂度的唯一权威副本。

### LeetCode 可直接提交代码

> 入口类与方法已根据 2026-08-30 的官方 Java 模板核验。本代码不包含本地 `main`。

```java
import java.util.Arrays;
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> indexByValue = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            int need = target - nums[i];
            Integer previousIndex = indexByValue.get(need);
            if (previousIndex != null) {
                return new int[]{previousIndex, i};
            }
            indexByValue.put(nums[i], i);
        }
        throw new IllegalArgumentException("No valid pair");
    }
}
```

### 复杂度和正确性

- 时间复杂度：平均 `O(n)`。每个位置最多查询一次、写入一次；哈希表的平均查询和写入为 `O(1)`。

- 不多用：查询发生在写入之前，当前元素不能成为自己的搭档。
- 不漏解：每个合法数对都有较晚出现的下标，处理到它时，较早下标已经在表里。
