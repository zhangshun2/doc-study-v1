### 官方题面原句

> 给定一个长度为 `n` 的整数数组 `height` 。有 `n` 条垂线，第 `i` 条线的两个端点是 `(i, 0)` 和 `(i, height[i])` 。
>
> 找出其中的两条线，使得它们与 `x` 轴共同构成的容器可以容纳最多的水。
>
> 返回容器可以储存的最大水量。
>
> **说明：**你不能倾斜容器。

关键原句的九项记录（事后重建）：

```text
原句（不改写）：找出其中的两条线，使得它们与 x 轴共同构成的容器可以容纳最多的水。
代词指向：“它们”指两个不同位置的边界；“最多”指在所有合法线对中比较，不是最后算到的一对。
谁在做事、手里有什么：我拿着 height、左边界下标 left 和右边界下标 right。
第一步：固定 left = 0，让 right 从 1 开始取一个不同位置。
重复动作：用 right - left 算宽度，用两条线中较矮的高度算水位，相乘得到当前面积。
动作改变或停止：当前面积超过已记录最大值时更新；right 走到末尾后，left 向右移动并重新开始。
最后交回：所有不同线对都算完后，交回记录中的最大面积。
忽略会错在：忽略“较矮”会用高边高估水位；忽略位置差会丢掉宽度；忽略“最多”会把最后一对误当答案。
来源：事实
合成可执行过程：固定一个左边界，依次和它右侧每个右边界组成线对；每对用宽度乘较矮高度得到面积，并和当前最大值比较；右侧走完后左边界向右移动，直到所有不同线对都被计算。
```

### 合成后的人话过程

```text
我手里有每条线的位置和高度。
我先固定最左边的线作为左端点。
我依次拿它右边的每一条线作为右端点。
宽度是右下标减左下标。
水位最高只能到两条线里较矮的那条。
面积 = 宽度 * 较矮高度。
如果这次面积比之前记录的大，就更新记录。
左端点右边的线都试完，再把左端点向右移动一位。
所有不同线对都试完以后，交回记录中的最大值。
```

### 七列对象表

| 题目对象 | 值和状态 | 身份由什么决定 | 位置或时间 | 从何时有效到何时失效 | 和谁发生关系 | 最终要得到什么 |
| --- | --- | --- | --- | --- | --- | --- |
| 一条垂线 | 高度 `height[i]` | 高度和原下标共同决定 | 数组下标 `i` | 从输入开始到整题结束都有效 | 与另一条线共同围成容器 | 不单独成为输出 |
| 两条线组成的线对 | 待计算或已经计算 | 两个不同下标共同决定 | 较左和较右的位置 | 选中这一对时成立，算完这一对后结束 | 共同决定宽度和较短高度 | 产生一个候选面积 |

## 阶段 4｜交接 6：数据范围与慢过程预算

```text

因此下一问只能是什么：带着五十亿次面积的代价回到同一条过程，能否证明某一整批线对不可能超过当前记录？
回答它需要什么证据：同一条过程上的失效条件、最小例子和淘汰证明。

```

### 官方约束

- `n == height.length`
- `2 <= n <= 10^5`
- `0 <= height[i] <= 10^4`

### 最坏操作预算

```text
left = 0 时有 n - 1 个右端点
left = 1 时有 n - 2 个右端点
...
总线对数 = n(n - 1) / 2

n = 10^5 时：
100000 * 99999 / 2 = 4,999,950,000
```

| 官方约束 | 限制了什么 | 慢过程最坏预算 | 排除哪些复杂度家族 | 仍不能确定什么 |
| --- | --- | --- | --- | --- |
| `n <= 10^5` | 最多十万条线 | 约五十亿个线对 | 稳定的平方级完整枚举 | 哪些线对可以被一次排除 |

### 状态和初始条件

```text
left：当前尚未淘汰区间的最左位置
```

初始时 `left = 0`、`right = height.length - 1`、`best = 0`。初始区间最宽，但还没有计算任何面积。

### 一次转移

```text
读取当前 left 和 right
计算 width = right - left
计算 limitedHeight = min(height[left], height[right])
用 width * limitedHeight 更新 best
若 height[left] < height[right]，淘汰 left
否则淘汰 right
```

### 不变量

```text

left 和 right 始终是尚未淘汰区间的两个不同端点。
```

### 为什么移动较短边不会漏

设当前 `height[left] <= height[right]`。如果保持 `left` 不动，只把 `right` 向左移动，则：

```text
新宽度 < 当前宽度
新高度上限 <= height[left]
所以新面积 <= 当前面积
```

因此所有仍使用当前 `left`、但右端更靠内的线对，都不可能超过当前面积，可以连同这个左端点一起淘汰。右边较短时对称。

若两边相等，固定任何一边向内移动都不会提高较小高度，因此淘汰任意一边都安全；代码选择移动右侧。

### 最小反例

取官方示例 `[1,8,6,2,5,4,8,3,7]`：

```text
最小输入：height = [1,8,6,2,5,4,8,3,7]
原本应保持的不变量或更新顺序：每轮淘汰较短一端，保留较高一端
如果破坏它，具体哪一步先算错：第一轮两端为 0 和 8，较短端是 0；若反规则移动较高端 8，会连续丢掉得到面积 49 所必需的右端点
错误输出：最大值无法达到 49
修复动作：当 height[left] < height[right] 时移动 left，而不是 moving right
```

另一个顺序反例是先把端点移动再计算面积。取 `[1,1]`，若先移动任一端，`left == right`，当前容器消失，面积 1 根本没有被记录。

### 伪代码

```text
left = 0
right = n - 1
best = 0

while left < right:
    width = right - left
    limitedHeight = min(height[left], height[right])
    best = max(best, width * limitedHeight)

    if height[left] < height[right]:
        left = left + 1
    else:
        right = right - 1

return best
```

### 权威 Java 实现

> 本节是本题可提交代码和复杂度的唯一权威副本。

### LeetCode 可直接提交代码

> 入口类与方法已根据 2026-08-30 的官方 Java 模板核验。本代码不包含本地 `main`。

```java
class Solution {
    public int maxArea(int[] height) {
        int left = 0;
        int right = height.length - 1;
        int best = 0;

        while (left < right) {
            int width = right - left;
            int limitedHeight = Math.min(height[left], height[right]);
            best = Math.max(best, width * limitedHeight);

            if (height[left] < height[right]) {
                left++;
            } else {
                right--;
            }
        }
        return best;
    }
}
```

### 复杂度和正确性

- 时间复杂度：`O(n)`。每轮至少淘汰一个位置，`left` 和 `right` 合起来最多移动 `n - 1` 次。
- 空间复杂度：`O(1)`。只维护两个端点、当前面积和最大值。
- 不丢解：每次淘汰较短一侧时，所有以该侧为端点、另一端更靠内的容器都被当前面积支配。
- 不早停：只有两个端点相遇时才停止，此时所有尚未被支配的区间都已处理。
- 顺序正确：每轮先计算当前面积，再淘汰端点。

## 边界与易错点

- 高度取 `min`，不是 `max`；水会从较短边界溢出。
- 宽度是 `right - left`，不是 `right - left + 1`。
- 必须淘汰较短边；错误淘汰较高端会丢失后续更优面积的来源。
- 相等高度时可以淘汰任意一边，但代码固定淘汰右侧，必须与不变量描述一致。
- 当前题求两个边界之间的最大整块水量，不是逐列累计雨水的题。
