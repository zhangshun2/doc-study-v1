# 搜索模型跨题对照

这一层把多道题放在同一张搜索骨架上比较。它保留完整题意、示例、约束、Java 入口和权威代码片段，目的是让读者看见“条件只改了一处，状态和过程因此改变了什么”，不必反复从零阅读每道题。

## 当前专题

- [[04-跨题对照/搜索模型对照-从岛屿数量到四种变化|从岛屿数量到四种变化]]

## 阅读顺序

1. 先用 `200 岛屿数量` 建立共同骨架：对象、相邻关系、当前状态、触发事件、待处理集合和结束条件。
2. 再逐题只看“相对基础模型的变化”，不要重新推导已经相同的部分。
3. 每看到一个状态变化，就回到完整 Java 代码定位对应操作。
4. 最后只回答一个问题：如果题目条件再改一处，哪一项状态必须跟着改？

## 与相邻层的分工

- `02-概念专题/` 沉淀跨题概念，不复制题目事实和代码。
- `04-跨题对照/` 为了直接比较，集中展示五题完整题目与权威代码摘录。
- `题目/` 始终是方法签名、提交代码和复杂度的唯一权威来源；本节嵌入的 Java 会由校验器逐字对照。
- `核心模型/` 负责单题速查，`建模专题/T0/` 负责完整试错过程。
