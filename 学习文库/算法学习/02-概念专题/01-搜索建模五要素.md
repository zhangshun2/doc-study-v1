# 搜索建模五要素

## 一句话本质

搜索题先不要选 DFS 或 BFS，先回答五个问题：世界里有哪些对象，对象怎样相连，当前必须记住什么，下一步由什么事件触发，最后要得到什么结果。

## 直观过程

把岛屿网格想象成一张地图。每个格子是对象，上下左右相邻是一条关系。当前正在检查的格子、已经到达的陆地和尚未检查的边界，合起来就是状态。检查到一个陆地，是触发事件；把所有相连陆地找完，是目标事件。

如果一开始直接问“这题用 DFS 吗”，思考会被算法名称截断。先描述地图怎样扩展，DFS 和 BFS 只是两种不同的扩展顺序。

## 对象与状态

| 要素 | 要回答的问题 | 岛屿例子 |
| --- | --- | --- |
| 对象 | 可以独立被判断、访问或改变的是什么 | 每个网格格子 |
| 关系 | 一个对象能通向哪些对象，方向是什么 | 上下左右相邻，无向 |
| 状态 | 哪些事实会影响下一步 | 当前格子、访问标记、待搜索集合 |
| 事件 | 发生什么会让状态变化 | 进入一个未访问陆地 |
| 目标 | 何时得到答案，答案是什么 | 所有连通陆地找完后统计岛屿数 |

状态不是把所有数据都记住。只保留会影响未来选择的信息，才算真正建模。已经搜索完的格子若再被访问也没有新作用，就可以被永久标记。

## 不变量

每次准备进入一个新对象时，它必须满足“尚未处理”的条件。搜索过程中已经完成的区域不再产生新答案，尚未进入的候选仍留在边界集合中。这个不变量保证每个对象只承担一次有效工作，也使结果不会被同一对象重复计数。

## 最小演算

输入是两行两列：

```text
1 1
0 1
```

从左上角开始。当前对象是 `(0,0)`，发现它尚未访问，于是把岛屿数从零变成一。它的右邻 `(0,1)` 和下邻 `(1,0)` 中，前者是陆地，后者是水，所以继续进入 `(0,1)`。再从 `(0,1)` 进入 `(1,1)`。边界集合随后为空，这一轮搜索结束。外层继续扫描，剩余格子都已访问，因此最终答案为一。

## 适用信号

- 题目给出格子、单词、课程、选择列表等对象，并规定一种“下一步可达”的关系。
- 需要判断是否可达、最短要几步、共有多少连通块或多少种方案。
- 直接枚举所有组合会出现重复，但每一步只依赖有限状态。

看到这些信号时，先在纸上写出五要素，再决定用队列、栈、递归或集合。数据结构是后面的实现选择，不是建模起点。

## 最小反例

如果只把“旁边有格子”当作关系，就会错误地把对角格子也算进同一个岛。在两格对角、中间为空的地图上，模型会得到一块岛，实际答案却是两块。关系定义错，后面的算法再正确也只会更快地得到错误结果。

## 代码映射

```text
1. 建立对象集合与邻接规则
2. 初始化当前状态、边界集合和目标变量
3. while 边界集合非空:
4.     取出一个可处理对象
5.     if 它不符合未处理条件: continue
6.     标记它已经处理
7.     更新目标状态
8.     for 每个由关系产生的邻居:
9.         if 邻居合法且尚未处理:
10.            加入边界集合
11. 返回目标变量
```
