# 回溯的选择与现场恢复

## 一句话本质

回溯是在决策树上走一段路：做一个选择，进入新状态，深入尝试；这条分支返回后，必须把现场恢复到做选择之前，才能公平地尝试下一个选择。

## 直观过程

全排列 `[1,2,3]` 的根节点什么都没有选。第一层选择 `1`，当前路径变成 `[1]`，并把 `1` 标为已使用。进入下一层选择 `2`，路径变成 `[1,2]`。这个分支完成后，要删除 `2` 并取消使用标记，才能在同一层继续选择 `3`。如果不恢复，下一分支会看见上一分支留下的现场。

单词搜索也一样。进入一个格子时暂时把它标记为不可重复使用；四个方向都试完并返回后，要恢复原字符。这样另一条候选路径才能再次经过它。

## 对象与状态

当前路径保存已经做出的选择，候选集合保存接下来还能选什么，撤销操作保存怎样回到父状态。三者必须配套，不能只维护其中一个。

恢复现场通常不是单纯为了节省一个全局记录表的内存。它首先是为了保证语义正确：同一格或同一元素在不同分支中可能有全新用途。全局状态会把这些用途混在一起。即便使用一个复制后的路径集合也能表达分支独立，但那仍然是在保存“当前路径”，而且每个分支都要复制，成本更高。

## 不变量

进入某个递归节点时，路径、访问标记和候选范围共同描述当前分支。递归返回父节点后，这些状态必须与做出当前选择之前逐项一致。这个“进入前等于返回后”的性质，保证兄弟分支从同一个起点出发。

## 最小演算

从空路径开始，选择 `1` 后状态是 `path=[1], used={1}`。继续选择 `2` 后是 `path=[1,2], used={1,2}`。该分支形成排列 `[1,2,3]`。返回上一层时先撤销 `2`，恢复成 `path=[1], used={1}`，随后才能选择 `3`，形成另一条前缀 `[1,3]`。

如果只执行 `continue` 而不撤销刚才的 `add` 和 `used=true`，循环虽然继续，状态却没有回到分叉点。`continue` 只能跳过当前迭代的后续语句，不能替你恢复已经发生的修改。

## 适用信号

- 题目要求枚举全部排列、组合、子集或路径。
- 每一步有多个候选，选择之间必须互不影响。
- 当前选择会修改路径、集合、棋盘或计数，而这些信息会影响后续候选。

## 最小反例

在 `[1,2]` 的全排列中，选择 `1` 后若忘记取消 `used[1]`，回到根节点再选择 `2` 时，集合里仍残留 `1` 的占用信息。最终可能少生成排列，甚至错误地认为 `1` 不可用。输出也许仍有结果，但结果集合已经不完整。

## 代码映射

```text
1. backtrack(当前状态):
2.     if 当前状态已经形成完整答案:
3.         保存答案副本
4.         return
5.     for 每个合法候选:
6.         修改状态，表示选择该候选
7.         进入下一层
8.         撤销修改，恢复父状态
9.     返回
```
