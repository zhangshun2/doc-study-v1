# 剪枝与可行性判断

## 一句话本质

剪枝不是“看起来不可能就先跳过”，而是证明当前分支无论怎样继续都无法形成合法答案，提前结束探索。

## 直观过程

单词搜索进入一个格子前，会检查三个条件：位置是否在棋盘内、字符是否等于目标字符、当前路径有没有用过这个格子。任何一项失败都说明这条路无法继续匹配，可以直接返回。

全排列中，已经使用的元素不能再次选择；这是把非法候选挡在分支之外。子集用起始下标限制选择方向，避免同一集合以不同顺序重复出现。剪枝减少的是已经被证明无效的工作，不应该改变剩余合法答案。

## 对象与状态

先辨认约束来自哪里。范围约束处理越界，关系约束处理字符或边是否合法，路径约束处理重复使用，目标约束处理剩余数量是否足够。对每个候选，只需判断它是否仍然能够通向一个完整合法结果。

有效剪枝依赖一个不变量：被跳过的分支里不存在任何尚未发现的答案。若只能凭经验说“大概率没用”，那不是剪枝，而是启发式选择，不能以牺牲完整性为代价。

## 不变量

每进入一个搜索节点，当前状态都已满足所有硬约束。候选筛选只排除违反约束的下一步；递归返回前的状态恢复保证剪枝判断不会把临时条件泄漏给兄弟分支。对于最短路搜索，某个状态已经按更短距离访问过，再以更长距离到达它也不会改善答案，这才可以安全跳过。

## 最小演算

棋盘只有 `A`，目标是 `AB`。从 `A` 进入后，匹配位置加到一，还没有完成目标。四个方向都越界，于是所有候选都不可能继续。函数返回失败，外层也不会把这个结果当作答案。

如果目标是 `A`，匹配位置已经覆盖最后一个字符，应在进入邻居前直接成功返回。这个提前结束不是省步骤，而是目标已经完整满足。

## 适用信号

- 一个候选违反了明确的边界、类型、方向或数量限制。
- 剩余搜索深度无法补足当前缺口，例如还需要三个字符但只剩两个格子。
- 同一状态已经按更优距离或更完整的信息处理过。

## 最小反例

把“字符不匹配”误判成“整条搜索失败”会过早结束外层，但更常见的错误是忘记检查已访问路径。没有路径检查时，搜索可能在同一格反复绕圈，表面上一直在工作，实际永远到不了新的字符位置。

另一个错误是把访问集合永久化。单词搜索的一次失败不能证明某个格子对后续所有起点都无用；这会剪掉真正合法的路径。

## 代码映射

```text
1. 进入候选:
2.     if 越界: return false
3.     if 不满足关系约束: return false
4.     if 违反当前路径约束: return false
5.     if 已达到目标: return true
6.     if 剩余资源不可能完成目标: return false
7.     标记并深入
8.     恢复现场
9.     返回本分支是否成功
```
