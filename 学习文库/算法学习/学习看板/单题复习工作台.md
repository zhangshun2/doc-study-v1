# 单题复习工作台

这页把题库和既有复习规则接到同一个闭环里。题库负责题意、模型和代码，复习负责提取、暴露缺口和安排下一次回访。读完题解、运行通过一次代码，都不算完成一轮复习。

长时段、保存点、间隔计划和记录规则仍以 `LeetCode-系统复习/` 为准。本页只回答一个实际问题：面对题库里的某一道题，今天应该按什么顺序做，做完以后把结果写回哪里。

复习的核心产物不是“今天完成了几题”，而是一条能由你重新生成并确认的因果链。你可以连续投入较长时间把整条链走完，也可以在明确断点处保存；后者只是暂停，不用题量或打卡补偿。

## 一条单题闭环

```text
从看板选题
-> 用自己的话读题
-> 选一个分析法建立过程模型
-> 写代码并自测
-> 关闭参考做一次提取
-> 记录最早卡点
-> 回写掌握状态、错因和下一次日期
```

每个动作只产生一种产物：

| 动作 | 产物 | 保存位置 |
| --- | --- | --- |
| 读题 | 对象、动作、变化、保存、停止、规模 | 当次记录 |
| 选分析法 | 一条能复述的过程链 | 当次记录或核心卡 |
| 作答 | 可运行 Java | 标准题解 |
| 自测 | 最小反例和实际结果 | 当次记录 |
| 复写 | 本次能独立做到哪一层 | 复习记录 |
| 回写 | 状态、错因、日期、尝试次数 | 标准题解属性区 |

## 一、先用六步读题

这六步来自标签白话指南，目的是先描述过程，再决定方法名。

1. **对象：** 输入里的元素、节点、区间或状态分别是什么？
2. **动作：** 人工从头处理时，一步具体做什么？
3. **变化：** 这一步改变了什么，哪些旧信息还会影响后面？
4. **保存：** 为了下一次快速判断，必须留下哪些值或候选？
5. **停止与输出：** 什么时候结束，题目要哪一个结果？
6. **规模：** 朴素过程做多少工作，题目约束是否允许？

读完后只写一到三句：

> 我逐步处理 ______；为了后面能作决定，我保存 ______；每一步发生 ______ 时就更新 ______；最后用 ______ 得到答案。

如果这句话说不出来，先不要用“哈希”“单调栈”“动态规划”代替过程。方法名可以后填，过程链不能缺失。

## 二、只选一个主分析法

同一道题可以用多种方式分析，但一次作答只选一个主线。其他视角只用于检查遗漏，不并行扩写成长文。

| 分析法 | 先回答什么 | 适合的题 | 卡住时的信号 |
| --- | --- | --- | --- |
| 人工过程法 | 我不用算法，会按什么顺序手工做 | 数组、字符串、模拟、多数面试题 | 例子能做完，但说不出重复劳动 |
| 状态生命周期法 | 哪个值从产生到失效，中间经历哪些事件 | 窗口、栈、队列、链表、设计题 | 知道结构名，却说不清何时加入删除 |
| 候选淘汰与不变量法 | 为什么这一步可以安全排除一批候选 | 双指针、二分、贪心、单调栈 | 能背循环，却不能解释为什么不会漏解 |
| 递归职责法 | 一个函数对一棵子树或一个子问题承诺返回什么 | 树、回溯、分治、递归搜索 | 递归能写，但返回值含义摇摆 |
| 子问题复用法 | 哪些重复小问题值得保存，按什么顺序复用 | 动态规划、记忆化搜索 | 状态定义靠猜，转移和边界对不上 |

选择规则：

- 先用“人工过程法”写出最小例子，任何题都适用。
- 出现重复扫描、候选失效或状态复用压力时，再转向更具体的分析法。
- 选中的分析法必须能一路解释到初始化、循环顺序、更新顺序和返回位置。
- 如果换分析法后代码结构也要大改，先把当前链条确认到的位置、两个候选的优缺点和下一次实验点保存下来；不要为了凑满某个时段仓促切换。

分析法的质量不按“看起来高级”评价，只看四项证据：第一次能否复述，几天后能否只靠过程链恢复，能否连接到同族题，实际编码时能否帮助定位错误。

## 三、用保存点承接长时段

不把固定分钟数当成复习目标。状态允许时，可以连续推进到整条链闭合；需要中断时，保存当前确认点和最早断点。完整规则见 `LeetCode-系统复习/05-单题流程/单题时间切片.md`。

| 本次模式 | 适用情形 | 结束条件 |
| --- | --- | --- |
| 完整链 | 时间充足，能把题意推到独立代码 | 八段链条闭合，代码和解释都有证据 |
| 断点推进 | 当前只能处理一段，或需要在某处查阅 | 该段已确认，或最早断点已准确定位 |
| 保护性停止 | 情绪明显波动、身体不适或注意力无法维持 | 保存当前位置后立刻结束，不补题量 |

如果同一处连续尝试两次仍没有新证据，不再原地重试。只补最早缺失的关系，不顺手扩展成多套方案。收尾写清：

```text
已经确认到：第 ___ 段，证据是 ______
最早未确认的是：______
下一次第一件事：______
```

这里的“已经确认”指能复述、演算或运行验证，不是“感觉看过”。长时段里也不要用连续工作几个小时替代链路检查。

## 四、复写后按 A/B/C/D 验收

A/B/C/D 描述本次提取结果，不评价能力，也不等同于 `mastery`。

| 本次结果 | 实际证据 | 回写建议 |
| --- | --- | --- |
| A | 过程能复述，代码能独立写出，自测通过 | `mastery` 可提升到“可独立实现”；拉长复习间隔 |
| B | 过程清楚，代码有局部遗忘或更新顺序错误 | 保持“已理解”；按具体错误加 `errorTags`，近期再写一次 |
| C | 需要提示才能想起关键过程 | 保持“已理解”；下次从提示对应的那一层开始 |
| D | 题意不稳，或还没有形成过程模型 | 不宣称独立实现；先补读题和最小演算 |

`independentAttempts` 只在没有打开答案、没有使用关键提示时增加。看了题解后能抄写一遍，不增加这个数字。

## 五、把结果写回唯一位置

复习排期以 `type: "problem"` 的标准题解为唯一权威来源。核心卡、完整建模和 Java 速查负责解释与回忆，不再各自生成同题复习任务。

| 字段 | 回答什么 | 写法 |
| --- | --- | --- |
| `mastery` | 是否真的能独立实现或迁移 | 未学、已理解、可独立实现、可迁移 |
| `reviewStatus` | 当前是否在等待下一次提取 | 未安排、待复习、已复习 |
| `nextReview` | 下一次提醒日期 | `YYYY-MM-DD` 或 `null` |
| `lastReviewed` | 最近一次真实复写日期 | `YYYY-MM-DD` |
| `errorTags` | 重复出现的错误属于哪一层 | 边界、更新顺序、不变量、结构选择、复杂度、题意 |
| `independentAttempts` | 无参考独立完成过几次 | 非负整数 |

`reviewStatus = "已复习"` 只表示本轮已经执行，不表示已经掌握。下一次回访前再改为“待复习”并填写日期。`mastery = "可迁移"` 也不覆盖复习状态，两者始终独立。

`independentAttempts`、A/B/C/D 和完成题数都只是证据记录，不是学习目标。一个数字增加，不能替代“这条关系为什么成立”的说明。

## 六、记录只保留下一轮需要的信息

长记录使用 `LeetCode-系统复习/06-学习记录/单题复习记录模板.md`，至少保留：

- 标准题解路径和题号。
- 六步读题的一到三句过程模型。
- 本次采用的主分析法。
- 最早卡点属于哪一层。
- 本次独立尝试次数。
- 下次第一步。

不要在复习记录里再复制一份完整 Java。代码回到标准题解，记录只保留“这次没想起什么”和“下次从哪里开始”。

## 完成一轮的检查

- 我能不用方法标签复述对象、动作、变化、保存和停止条件。
- 我能解释关键更新为什么必须放在当前位置。
- 我至少手算了一个最小例子或反例。
- 我知道这次最早卡在哪一层。
- 我只更新了一份标准题解的复习属性。
- 下一次日期和第一步已经写清。
