# 239. 滑动窗口最大值：核心模型

> **双轨阅读：** [[题目/单调结构/239-Sliding-Window-Maximum.md|标准题解]] · [[建模专题/T0/239-Sliding-Window-Maximum-直观建模.md|完整建模]]

## 一句话本质

某个旧元素若不大于刚进入的新元素，那么新元素更大且离开窗口更晚，旧元素从此再无成为窗口最大值的机会。删除所有这类“被支配”的下标后，候选值从队首到队尾严格递减。

## 直观画面与扩题

像候场队伍：当前元素一出现，就能淘汰那些以后再也不可能成为答案的旧候选。

在本题中，对象是 **仍可能成为答案的候选下标或值**；把它从“枚举全部可能”改写为“只维护影响下一步的最少信息”。

## 关系重写

把题目翻译成一条可执行关系：某个旧元素若不大于刚进入的新元素，那么新元素更大且离开窗口更晚，旧元素从此再无成为窗口最大值的机会。删除所有这类“被支配”的下标后，候选值从队首到队尾严格递减。

## 最小演算

官方首例输入：`nums = [1,3,-1,-3,5,3,6,7], k = 3`，输出：`[3,3,5,5,6,7]`。

1. **初始状态：** 遍历右端下标 right： 若队首下标 < right - k + 1，说明已离开窗口，从队首删除。
2. **触发事件：** 若队首下标 < right - k + 1，说明已离开窗口，从队首删除。
3. **结束条件：** 因此队首既是未过期候选中值最大的，也是当前窗口真实最大值。
4. **核对首例：** 按上述状态与事件逐步更新，最终应得到题面给出的输出；若结果不符，优先检查状态初始化、更新先后顺序和边界收缩方向。

## 为什么成立

每轮处理后保持： 队列中的下标严格递增，且全部位于当前窗口。

## 代码映射

```text
1. 若队首下标 < right - k + 1，说明已离开窗口，从队首删除。
2. 队尾值 <= nums[right] 时不断删除队尾。
3. 把 right 加入队尾。
4. 当 right >= k - 1 时，队首值就是一个完整窗口的答案。
```

## 复杂度

- 时间复杂度：O(n)；每个下标至多入队一次、从队首或队尾出队一次。
- 空间复杂度：O(k)，队列最多保存一个窗口内的下标。

## 30 秒识别信号

- 主题型：`单调结构`
- 切入点：队列应保存下标而不是只保存值，才能判断元素是否已经离开窗口。

## 最小反例与易错点

- 过期判断是 < windowLeft；等于左边界的下标仍在窗口中。
- 输出数组长度是 n - k + 1。
