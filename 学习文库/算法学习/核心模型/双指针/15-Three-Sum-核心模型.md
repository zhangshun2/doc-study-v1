# 15. 三数之和：核心模型

> **双轨阅读：** [[题目/双指针/15-Three-Sum.md|标准题解]] · [[建模专题/T0/15-Three-Sum-直观建模.md|完整建模]]

## 一句话本质

排序同时解决两件事：双指针可以按和的大小定向移动，相同值也会相邻便于去重。固定 nums[first] 后，需要在 (first,n) 中寻找和为 -nums[first] 的两个数。

## 直观画面与扩题

像两个人从两端向中间收网，每走一步都能排除一批不可能答案。

在本题中，对象是 **有序区间两端的候选位置**；把它从“枚举全部可能”改写为“只维护影响下一步的最少信息”。

## 最小演算

官方首例输入：`nums = [-1,0,1,2,-1,-4]`，输出：`[[-1,-1,2],[-1,0,1]]`。

1. **初始状态：** 等于 0：记录答案，两端都移动，并跳过各自重复值。
2. **触发事件：** 若与前一个固定值相同就跳过。
3. **结束条件：** 等于 0：记录答案，两端都移动，并跳过各自重复值。
4. **核对首例：** 按上述状态与事件逐步更新，最终应得到题面给出的输出；若结果不符，优先检查状态初始化、更新先后顺序和边界收缩方向。

## 为什么成立

固定 first 后，双指针区间内尚未排除所有可能配对。若当前和小于 0，因为数组有序，保持左值而缩小右指针只会让和更小，所以必须增大左值；和大于 0 时对称地必须减小右值。这些移动不会跳过解。每个固定值和命中后的相邻重复值都只处理一次，因此既找到全部数值组合，也不产生重复三元组。

## 复杂度

- 时间复杂度：排序 O(n log n)，扫描 O(n^2)，总体 O(n^2)。
- 空间复杂度：忽略排序实现栈和答案为 O(1)；Java Arrays.sort(int[]) 的辅助空间由实现决定，通常可视为 O(log n) 调用栈级别。

## 30 秒识别信号

- 主题型：`双指针`
- 切入点：排序后固定第一个数，剩余问题变成在右侧有序区间中找两数之和。

## 最小反例与易错点

- 只对结果使用 Set 而不在扫描中去重，会产生大量无效重复工作。
- 固定值去重条件是与前一个比较；不能无条件与后一个比较，否则可能漏解。
