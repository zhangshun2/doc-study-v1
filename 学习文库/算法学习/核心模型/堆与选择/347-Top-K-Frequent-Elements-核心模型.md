# 347. 前 K 个高频元素：核心模型

> **双轨阅读：** [[题目/堆与选择/347-Top-K-Frequent-Elements.md|标准题解]]

## 一句话本质

排序的是频率，而频率是有界整数，最大不超过数组长度 n。因此无需比较排序：建立 n+1 个桶，buckets[f] 保存频率为 f 的所有元素。倒序遍历桶就是按频率降序。

## 直观画面与扩题

像只保留最值得关注的少数候选，每次新元素到来时淘汰最不可能入选的那个。

在本题中，对象是 **大小为 K 或 K+1 的动态候选集合**；把它从“枚举全部可能”改写为“只维护影响下一步的最少信息”。

## 关系重写

把题目翻译成一条可执行关系：排序的是频率，而频率是有界整数，最大不超过数组长度 n。因此无需比较排序：建立 n+1 个桶，buckets[f] 保存频率为 f 的所有元素。倒序遍历桶就是按频率降序。

## 最小演算

官方首例输入：`nums = [1,1,1,2,2,3], k = 2`，输出：`[1,2]`。

1. **初始状态：** 一次扫描建立 frequency 哈希表。
2. **触发事件：** 从 n 递减扫描频率，将桶内元素加入答案，收够 k 个停止。
3. **结束条件：** 从 n 递减扫描频率，将桶内元素加入答案，收够 k 个停止。
4. **核对首例：** 按上述状态与事件逐步更新，最终应得到题面给出的输出；若结果不符，优先检查状态初始化、更新先后顺序和边界收缩方向。

## 为什么成立

哈希表准确统计每个不同元素频率，因此元素被放入且只放入与真实频率相等的桶。从最大下标向下扫描时，任何尚未扫描桶中的频率都不高于当前已扫描频率。因此收集到的前 k 个元素就是频率最高的 k 个，顺序不影响正确性。

## 代码映射

```text
1. 一次扫描建立 frequency 哈希表。
2. 创建长度 n+1 的列表数组。
3. 对每个 (num,count)，把 num 加到 buckets[count]。
4. 从 n 递减扫描频率，将桶内元素加入答案，收够 k 个停止。
```

## 复杂度

- 时间复杂度：O(n)，计数、分桶和扫描桶均为线性级别。
- 空间复杂度：O(n)，哈希表、桶和答案合计线性空间。

## 30 秒识别信号

- 主题型：`堆与选择`
- 切入点：任何元素的出现次数范围都在 [1,n]。

## 最小反例与易错点

- 桶数组长度要是 n + 1，因为频率可能正好为 n。
- Java 不能直接创建泛型数组，需创建 List[] 并抑制受控警告。
