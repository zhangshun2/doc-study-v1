# 139. 单词拆分：核心模型

> **双轨阅读：** [[题目/动态规划/139-Word-Break.md|标准题解]]

## 一句话本质

字符串的切分选择看似很多，但后续是否成功只与“当前处理到哪个下标”有关，而与此前如何切分无关。这说明问题具有重复子问题与最优子结构，可以用布尔动态规划压缩搜索状态。 定义 dp[i]：s 的前 i 个字符，即 s[0..i)，是否能由字典单词拼出。空前缀天然可拆分，所以 dp[0] = true。

## 直观画面与扩题

像填写一张递推账本，当前格子的答案只由少量已经算好的前序格子决定。

在本题中，对象是 **可复用的子问题状态**；把它从“枚举全部可能”改写为“只维护影响下一步的最少信息”。

## 关系重写

把题目翻译成一条可执行关系：字符串的切分选择看似很多，但后续是否成功只与“当前处理到哪个下标”有关，而与此前如何切分无关。这说明问题具有重复子问题与最优子结构，可以用布尔动态规划压缩搜索状态。 定义 dp[i]：s 的前 i 个字符，即 s[0..i)，是否能由字典单词拼出。空前缀天然可拆分，所以 dp[0] = true。

## 最小演算

官方首例输入：`s = "leetcode", wordDict = ["leet", "code"]`，输出：`true`。

1. **初始状态：** dp[i] = 存在某个 j，使 dp[j] == true 且 s[j..i) 在字典中
2. **触发事件：** 对每个前缀终点 i，枚举最后一个单词的起点 j： dp[i] = 存在某个 j，使 dp[j] == true 且 s[j..i) 在字典中
3. **结束条件：** 处理下标 i 时，不变量是：dp[0..i] 已准确表示对应前缀是否可拆分。
4. **核对首例：** 按上述状态与事件逐步更新，最终应得到题面给出的输出；若结果不符，优先检查状态初始化、更新先后顺序和边界收缩方向。

## 为什么成立

处理下标 i 时，不变量是：dp[0..i] 已准确表示对应前缀是否可拆分。 若算法设置 dp[end] = true，则存在可拆分前缀 s[0..i)，且 s[i..end) 在字典中，两者拼接后 s[0..end) 必然可拆分。

## 代码映射

```text
1. 对每个前缀终点 i，枚举最后一个单词的起点 j：
2. 对每个前缀终点 i，枚举最后一个单词的起点 j： dp[i] = 存在某个 j，使 dp[j] == true 且 s[j..i) 在字典中
3. dp[i] = 存在某个 j，使 dp[j] == true 且 s[j..i) 在字典中
```

## 复杂度

- 时间复杂度：设 n = s.length()，最长单词长度为 L，至多检查 nL 个片段；Java 生成子串还需复制字符，严格上界为 O(nL^2)。本题 L <= 20，通常写作 O(nL)。
- 空间复杂度：O(n + D)，dp 占 O(n)，哈希集合存储字典字符总量 D。

## 30 秒识别信号

- 主题型：`动态规划`
- 切入点：不要直接问“整个字符串是否在字典中”，而要问“某个前缀能否被拆分”。

## 最小反例与易错点

- dp 长度必须是 n + 1，其中 dp[0] 代表空前缀。
- 题目允许重复使用同一个字典单词，不要在使用后删除它。
