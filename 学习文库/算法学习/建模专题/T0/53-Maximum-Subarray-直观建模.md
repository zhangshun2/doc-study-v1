本篇要解决的困难，不是记住一行 `max`，而是回答下面几个更基础的问题：为什么“连续”会迫使上一段结束在 `i - 1`；为什么旧段的和为负时可以永久丢弃；为什么局部状态与全局答案必须用两个变量；为什么全负数组会让“初始化为零”暴露语义错误。文章会先从人工枚举和候选关系推导状态与不变量，直到模型已经确定以后，才说明它通常被称为一维动态规划或 Kadane 算法。

## 2. 完整题目

给定一个非空整数数组 `nums`。需要从中选择一段连续的、至少包含一个元素的子数组，使这段子数组中所有元素之和尽可能大，并返回这个最大和。

“连续”表示被选择元素的下标必须从某个左端点 `left` 一直延伸到某个右端点 `right`，中间不能跳过任何元素。返回值只要求最大和，不要求返回区间本身。

**输入：** 一个整数数组 `nums`。

**输出：** 所有非空连续子数组的元素和中的最大值。

**示例 1：**

```text
输入：nums = [-2,1,-3,4,-1,2,1,-5,4]
输出：6
解释：连续区间 [4,-1,2,1] 的和为 6，其他连续区间的和都不超过 6。
```

**示例 2：**

```text
输入：nums = [1]
输出：1
解释：数组只有一个元素，唯一合法的非空连续子数组就是 [1]。
```

**示例 3：**

```text
输入：nums = [5,4,-1,7,8]
输出：23
解释：选择整个数组，和为 5 + 4 - 1 + 7 + 8 = 23。
```

**全部约束：**

- `1 <= nums.length <= 10^5`。
- `-10^4 <= nums[i] <= 10^4`。
- 子数组必须非空。
- 官方进阶要求是：在线性时间解法之外，再尝试用分治法求解。
- 官方接口当前没有额外算法提示。

Java 方法入口为：

```java
class Solution {
    public int maxSubArray(int[] nums) {
        return 0;
    }
}
```

这里的 `return 0` 只是为了让签名片段语法完整，不代表题目的默认答案。题目保证数组非空，因此正式实现可以从 `nums[0]` 建立第一个合法状态。数组长度可到十万，说明平方级枚举的区间数量会达到约五十亿；目标应当是每个元素只处理常数次。最大可能总和为 `10^5 * 10^4 = 10^9`，最小可能总和为 `-10^9`，都在 Java `int` 范围内，所以本题不必为了官方约束改用 `long`。

## 3. 先把题目说成人话

**一句话生活化复述：** 一串每天的收益和亏损已经固定，现在必须选择连续营业的一段时间，不能中途停业再回来，想让这段时间的总收益最大。

**一句话关系化复述：** 在数组的所有下标区间 `[left, right]` 中，寻找元素和最大的一个非空连续区间，并返回它的和。

先用具体数据理解变量。对数组 `[4,-1,2]`，区间 `[0,2]` 表示选择下标 `0、1、2`，和为 `5`；`[0,0]` 表示只选择第一个元素，和为 `4`。不能选择下标 `0` 和 `2` 却跳过下标 `1`，因为那是子序列，不是子数组。

```text
下标：   0    1    2    3    4
数值：   3   -6    5    2   -1
                 |---------|
合法区间：       left=2    right=4，和为 6

非法选择：下标 0、2、3
原因：从 0 到 2 中间跳过了下标 1，不连续
```

| 要素 | 本题含义 |
| --- | --- |
| 对象 | 数组元素、元素下标，以及由左右端点确定的非空连续区间 |
| 关系 | 一个区间包含一段相邻元素，它的分数是这些元素之和 |
| 方向 | 从左向右读入新元素；新元素只能接在结束于前一位置的连续区间后面 |
| 目标 | 在所有合法区间中找最大和 |
| 限制 | 至少选一个元素，且被选下标不能断开 |
| 隐含选择 | 每到一个位置，要判断是接上旧段，还是从当前位置重新开段 |

这一翻译先保留“连续区间”和“最大和”两个事实，不急着问算法名称。真正要优化的是候选区间太多，而不是求和运算本身有多复杂。

## 4. 第一切入点：读题时先看什么

第一分钟应先圈出三个词：**连续**、**至少一个元素**、**最大和**。

“连续”决定了状态之间的连接规则。如果准备让一个区间在下标 `i` 结束，那么它在加入 `nums[i]` 之前只能结束在 `i - 1`；不能从更早位置直接跨过中间元素。“至少一个元素”决定了零不是天然候选，尤其当全部元素为负时，答案必须是某个负数。“最大和”说明多个能够延伸到同一位置的旧区间之间可能存在支配关系：如果以后给它们追加完全相同的后缀，当前和更大的那个永远不会变得更差。

题名中的“子数组”是数学约束，不是“真的创建一个新数组”的要求；“返回”只是接口动作；故事中也没有必须保留每个区间元素的要求。这些包装暂时忽略。

数据范围给出的信号很直接：长度最大为 `100000`，连续区间总数是 `n(n+1)/2`。当 `n=100000` 时，约有 `5,000,050,000` 个区间。即使每个区间能在常数时间内得到和，逐个枚举也不合适。因此需要压缩候选，而不是仅把区间求和从多次加法改成前缀和查询。

在最小样例 `[1]` 中，人工不需要做选择：必须选这个元素，答案是 `1`。再看 `[5,-2,4]`：人工会比较 `[5]`、`[5,-2]`、`[5,-2,4]`、`[-2]`、`[-2,4]`、`[4]`，发现答案为 `7`。这里已经出现一个有用现象：虽然 `-2` 单独看是亏损，但为了把左右两个正收益保持在同一个连续区间里，可以接受它。由此可知，“遇到负数就切断”不是正确规则；真正该观察的是加入当前元素之前，那整段历史对未来究竟是帮助还是拖累。

## 5. 最直接的人工或暴力模型

最接近人工检查的方法，是枚举区间的两个边界。

1. 依次把每个下标当作左端点 `left`。
2. 对固定的 `left`，让右端点 `right` 从 `left` 向数组末尾移动。
3. 每右移一步，就把 `nums[right]` 加入当前区间和。
4. 用当前区间和更新目前见过的最大值。
5. 所有左右边界都检查后返回最大值。

可以用下面的完整 Java 片段表达这个直接模型：

```java
final class EnumerateAllIntervals {
    public int maximumNonEmptyIntervalSum(int[] nums) {
        int bestOverall = nums[0];

        for (int left = 0; left < nums.length; left++) {
            int intervalSum = 0;
            for (int right = left; right < nums.length; right++) {
                intervalSum += nums[right];
                bestOverall = Math.max(bestOverall, intervalSum);
            }
        }
        return bestOverall;
    }
}
```

这个方案一定正确，因为任意非空连续子数组都能由唯一的一对边界 `(left, right)` 表示，其中 `0 <= left <= right < n`。外层循环会访问它的左端点，内层循环会继续走到它的右端点，所以它一定被检查；反过来，循环产生的每一对边界也都对应合法的非空连续区间，不会混入跳跃选择。

如果每个区间都重新从 `left` 加到 `right`，三层工作量会达到 `O(n^3)`。上面的写法让固定左端点的区间增量扩张，只用一次加法从 `[left,right-1]` 得到 `[left,right]`，于是总共处理 `n(n+1)/2` 个区间，时间为 `O(n^2)`。它只使用几个整数变量，辅助空间为 `O(1)`。

直接模型很有价值：它给出完整候选集合和可靠的正确性基线。后续优化不能凭感觉删除候选，而要证明被压缩掉的候选永远不可能影响最终答案。

## 6. 暴力到底浪费在哪里

仍看经典输入的前半段：

```text
下标：  0   1   2   3   4   5   6
数值： -2   1  -3   4  -1   2   1
```

当固定不同左端点并向右累加时，同一段后缀会被反复经过：

```text
left=0：-2 -> -1 -> -4 -> 0 -> -1 -> 1 -> 2
left=1：      1 -> -2 -> 2 ->  1 -> 3 -> 4
left=2：          -3 -> 1 ->  0 -> 2 -> 3
left=3：                4 ->  3 -> 5 -> 6
left=4：                     -1 -> 1 -> 2
left=5：                           2 -> 3
left=6：                                1
```

为了得到所有在下标 `6` 结束的区间，暴力模型保留了七个候选和：

| 区间 | 和 |
| --- | ---: |
| `[0,6]` | 2 |
| `[1,6]` | 4 |
| `[2,6]` | 3 |
| `[3,6]` | 6 |
| `[4,6]` | 2 |
| `[5,6]` | 3 |
| `[6,6]` | 1 |

假设明天又追加同一个数 `x`。这七个区间若继续，都只是分别加上同一个 `x`。当前和为 `6` 的 `[3,6]` 加上 `x` 后仍然不会比其余六个延伸候选差。对于“未来继续向右延伸”这件事，其余六个候选已被 `[3,6]` 支配，无需分别保存。

重复还发生在相邻右端点之间。计算结束于 `5` 的最好区间时，我们已经知道 `[3,5]` 的和为 `5`；处理下标 `6` 时，却又从多个左端点重新走过 `4,-1,2`，没有把“结束于 `5` 的最好结果”当成可复用结论。大量中间和在更新一次全局答案后就被丢弃，下一轮又以另一种边界组合重新计算。

具体看负历史的淘汰。处理下标 `3` 的值 `4` 之前，结束于下标 `2` 的最佳和是 `-2`，来自 `[1,-3]`。如果把它接到 `4` 前面，得到 `-2 + 4 = 2`；直接从 `4` 开始却得到 `4`。以后无论再接什么相同后缀，携带这笔 `-2` 都只会少 `2`，因此它不仅当前输，而且永久不可能翻盘。

优化目标可以明确写成：

> 不再为每个左端点分别扫描未来；每读到一个新位置，只结算“必须在这里结束”的最佳区间，并把其他对未来永远不占优的同终点候选压缩掉。

## 7. 容易想到但走不通的方向

### 方向一：只把正数加起来

最大和让人自然想到“正数有利、负数有害”。但若直接累加所有正数，在 `[5,-2,5]` 中会得到 `10`，对应的是跳过中间 `-2` 的非法选择；合法最大区间是整个数组，和为 `8`。这个方向保存了元素的正负，却丢失了下标连续关系。得到的新条件是：状态必须描述一段真实连续区间，不能把相隔的好元素自由拼接。

### 方向二：一看到负元素就切断

这比“只加正数”更尊重顺序，但仍把“当前元素为负”和“整段历史为负贡献”混为一谈。在 `[5,-1,5]` 中，遇到 `-1` 就切断只能得到单侧的 `5`，而跨过它的整个连续区间和为 `9`。单个负元素可能是连接两个更大正收益的必要成本。真正能决定是否重启的不是 `nums[i] < 0`，而是加入 `nums[i]` 之前的最佳结尾和是否会拖累新段。

### 方向三：把运行和降到负数时设成零，并把答案也初始化为零

在含正数的常见样例里，这段写法经常碰巧正确，因为零可以被理解为“暂时不选任何元素，等待以后开始”。但本题禁止空子数组。对 `[-3,-2,-5]`，所有合法答案都是负数，最大的是 `-2`；若运行和与全局答案都从零开始，算法会返回不存在的空选择 `0`。这个方向不是状态转移完全错误，而是求解了“允许不选元素”的另一道题。新条件是：基础状态必须来自第一个真实元素，始终代表非空区间。

### 方向四：排序后挑最大的元素

排序能把大数放到一起，因而看上去适合“最大”问题；但排序会改变原下标邻接关系，而连续性正是本题最重要的约束。即使只取排序后的若干正数，也回到了非法跳选。排序不是超时，而是改变了问题本身。从这个失败得到的条件是：遍历必须保留原顺序，任何候选淘汰都要在原下标关系中证明。

前缀和则不同：它是正确工具。区间 `[left,right]` 的和可写成 `prefix[right+1]-prefix[left]`；若对每个右端点维护此前最小前缀，也能在线性时间求解。但对初学建模而言，“结束在当前位置的最佳非空区间”更直接地保留了连续关系和重启动作，所以本文把它作为主线。前缀和模型是等价视角，不是错误方向。

## 8. 关键视角转换

暴力模型把一个完整答案看成一对边界，因此一直在问：“从每个左端点出发，右端点可以走到哪里？”新的问题是：“如果右端点已经固定为 `i`，结束在这里的所有区间中，哪个最好？”

每个非空连续区间都有唯一右端点，所以可以把全部候选分组：

```text
所有合法区间
├─ 右端点为 0：[0,0]
├─ 右端点为 1：[0,1] [1,1]
├─ 右端点为 2：[0,2] [1,2] [2,2]
└─ 右端点为 i：[0,i]、[1,i]，依次直到 [i,i]
```

> **小白追问：** 按右端点分组，为什么既不会漏掉区间，也不会把同一区间算两遍？
>
> **先给短答：** 一段非空连续区间只有一个最后下标，这个下标就是它唯一所属的组号。
>
> **最小例子：** 数组 `[2,-1]` 只有 `[0,0]`、`[0,1]`、`[1,1]` 三个区间。`[0,0]` 进入右端点 `0` 组，后两个进入右端点 `1` 组。没有区间无组可进，也没有区间同时拥有两个右端点。
>
> **回到模型/代码：** 循环下标 `i` 就是当前组号。`bestEndingHere` 结算这一组，`bestOverall` 再把这一组的结果并入历史答案。

在同一组中只需留下和最大的候选。原因不是“只关心最大值”这么简单，而是所有同终点候选面对未来时拥有完全相同的追加选择：下一元素若要保持连续，只能统一追加在它们后面。给两个和分别为 `a`、`b` 的候选追加同一后缀和 `s`，若 `a >= b`，则始终有 `a+s >= b+s`。较小候选以后不可能反超。

> **小白追问：** 延续到未来时，为什么只保留同一右端点下和最大的旧区间？
>
> **先给短答：** 同终点候选以后只能追加同一段后缀，当前较小的和不会因为加了相同内容而反超。
>
> **最小例子：** 在 `[2,-1,3]` 中，结束于下标 `1` 的候选和是 `1` 与 `-1`。都追加下标 `2` 的 `3` 后，它们变成 `4` 与 `2`。原来较小的候选仍然较小。
>
> **回到模型/代码：** 更新下标 `i` 时，延续分支只读取旧 `bestEndingHere`，再计算 `bestEndingHere + nums[i]`。其他同终点旧和已被这个值代表。

处理新位置 `i` 时，任何必须在 `i` 结束的合法区间只有两类：

1. 只取 `nums[i]`，在当前位置重新开始。
2. 长度至少为二。删除最后的 `nums[i]` 后，剩余部分必然是一个结束于 `i-1` 的非空连续区间。

> **小白追问：** 为什么要特意定义“必须在 `i` 结尾”，直接保存目前见过的最大和不行吗？
>
> **先给短答：** 只有结束于 `i-1` 的区间才能合法接上 `nums[i]`，历史最大区间可能早已结束，不能跨位置连接。
>
> **最小例子：** 对 `[4,-10,3]`，处理完 `-10` 后，历史最大和是 `4`，但它结束在下标 `0`。若直接做 `4+3` 会跳过 `-10`，得到非法的 `7`。结束于下标 `1` 的最佳和是 `-6`，它才有资格接 `3`。
>
> **回到模型/代码：** `bestEndingHere` 是可以接当前元素的连续状态；`bestOverall` 只负责记历史纪录，绝不能出现在延续候选的加法里。

第二类中无需尝试结束于 `i-1` 的所有区间，只要接在其中最大的那个后面。于是：

```text
必须以 i 结尾的最好和
= max(
    nums[i],
    必须以 i-1 结尾的最好和 + nums[i]
  )
```

这一步把“枚举完整区间”转换成“枚举最后一步的两种来源”，把每个右端点下的多个候选压缩为一个局部最优状态。

但这个局部状态仍不等于最终答案。经典输入最后一个位置的局部最好和为 `5`，全局最好和却是更早在下标 `6` 结束的 `6`。因此还要让另一个状态持续记住所有已结算右端点中的最大值。

| 转换前 | 转换后 |
| --- | --- |
| 枚举每一对左右边界 | 按右端点依次结算候选组 |
| 保存同一终点的许多区间和 | 只保存同一终点的最大和 |
| 每个起点重新扫描后缀 | 新元素到来时从上一终点增量转移 |
| 把局部候选和最终答案混在一起 | 分开维护当前终点最优与历史全局最优 |

## 9. 正式建立模型

先给两个状态明确命名：

- `bestEndingHere(i)`：在所有**必须以下标 `i` 结尾**的非空连续子数组中，最大的元素和。
- `bestOverall(i)`：右端点不超过 `i` 的所有非空连续子数组中，最大的元素和。

当只写滚动变量时，`bestEndingHere` 和 `bestOverall` 分别代表当前 `i` 对应的这两个量。

| 建模项 | 本题结论 |
| --- | --- |
| 对象 | 依次到来的数组位置，以及按当前右端点分组的非空连续区间 |
| 关系 | 新位置要么独自成为新区间，要么接在结束于前一位置的区间之后 |
| 状态 | 当前右端点的最大区间和 `bestEndingHere`；所有已处理右端点中的最大和 `bestOverall` |
| 事件 | 从左向右读到 `nums[i]`，需要结算右端点为 `i` 的候选组 |
| 不变量 | 一轮结束后，`bestEndingHere` 只代表以 `i` 结尾的最好非空区间，`bestOverall` 代表前缀 `[0,i]` 内所有合法区间的最好和 |
| 结果时机 | 最后一个位置结算后，`bestOverall` 已覆盖每个可能的右端点，直接返回它 |

状态转移是：

```text
bestEndingHere(i)
= max(nums[i], bestEndingHere(i-1) + nums[i])

bestOverall(i)
= max(bestOverall(i-1), bestEndingHere(i))
```

第一个式子回答“这次是否延续”；第二个式子回答“这次产生的局部最好是否刷新历史纪录”。两者语义不能交换。若只返回最后的 `bestEndingHere`，就强迫答案在数组末尾结束；若只维护 `bestOverall` 又拿它去延伸，会把一个可能结束在很早位置的区间跨过中间元素后接到当前元素上，破坏连续性。

> **小白追问：** `bestEndingHere` 和 `bestOverall` 都在保存最大和，为什么不能合并成一个变量？
>
> **先给短答：** 前者回答“谁有资格继续连接”，后者回答“历史上谁最大”，这是两个不同问题。
>
> **最小例子：** 在 `[4,-10,3]` 结尾处，`bestEndingHere=3`，因为必须包含最后的 `3`；`bestOverall=4`，因为最优答案早在下标 `0` 结束。只留 `3` 会忘记答案 `4`，只留 `4` 又会在后续产生非法跨接。
>
> **回到模型/代码：** 第一条 `Math.max` 先结算当前终点，第二条 `Math.max` 再刷新历史纪录。两个变量分别承接这两条更新链。

### 为什么状态足够

所有长度至少为二、结束于 `i` 的区间，删除 `nums[i]` 后都会变成结束于 `i-1` 的区间。它们追加的是同一个 `nums[i]`，所以上一组中和最大的候选追加后仍最大。无需保存它的完整元素列表、左端点或其他较小的区间和，因为本题只返回最大和；这些信息不会影响以后做“继续还是重启”的数值比较。

### 旧和为负时为什么能安全丢弃

设上一轮 `bestEndingHere = p`，当前值为 `x`。若 `p < 0`，则 `p + x < x`。携带旧段严格劣于从 `x` 重启。对未来任意后缀和 `s`，仍有 `p+x+s < x+s`，所以旧段不只在当前输了，以后也永远无法反超，从候选集合删除是安全的。

> **小白追问：** 负的旧段为什么能永久丢弃，会不会后面出现大正数后又需要它？
>
> **先给短答：** 大正数会同时加到“带负担”和“不带负担”两条路线，旧负担造成的差距不会被抹掉。
>
> **最小例子：** 在 `[-2,4,-1]` 中，携带 `-2` 到 `4` 只能得到 `2`，从 `4` 重启得到 `4`。再追加 `-1` 后，两条路线分别是 `1` 与 `3`，前者仍少 `2`。
>
> **回到模型/代码：** 当旧 `bestEndingHere < 0` 时，`Math.max(nums[i], bestEndingHere + nums[i])` 会选择 `nums[i]`。旧段被覆盖后不再恢复。

若 `p = 0`，延续与重启的和相等。只求最大和时任选其一都正确；若扩展为返回最短区间、最早区间或最长区间，就必须额外规定相等时的选择策略。若 `p > 0`，则 `p+x > x`，延续严格优于重启，即使当前 `x` 为负也可能值得保留。

> **小白追问：** 延续与重启相等时不区分路线，真的不会影响本题答案吗？
>
> **先给短答：** 本题只返回最大和，不返回区间身份；两条路线的数值相同，后续再加同一元素仍然相同。
>
> **最小例子：** 对 `[0,2]`，延续得到区间 `[0,2]`，重启得到 `[2]`，两者和都是 `2`。若后面再来 `-1`，两者都会变成 `1`。
>
> **回到模型/代码：** `Math.max` 只保存数值，没有保存左右端点。若题目改成返回最短或最早区间，才需要端点状态和平局规则。

### 遍历方向与边界

状态只依赖左侧相邻终点，所以自然从左向右。初始化为：

```text
bestEndingHere = nums[0]
bestOverall    = nums[0]
```

它让两个状态从一开始就代表合法的非空区间。重复值不需要去重，因为区间由下标而不是值确定；本题只求和，相同值只是正常贡献。数组保证非空，正式代码无需制造空状态；若将模型迁移到允许空数组的业务接口，必须先单独定义空输入应该返回什么，而不能擅自返回零。

模型和不变量确定后，可以给它命名：这是一维动态规划的滚动状态写法，也通常称为 Kadane 算法。名称只是对已经推导出的“局部结尾最优 + 全局最优”模型的简称。

## 10. 所需数据结构详解

这个模型不需要栈、队列、哈希表或树。真正需要的状态容器只有只读数组和两个整数变量。

### 原数组 `int[] nums`

数组把元素按固定下标连续存放，支持按下标随机访问，读取 `nums[i]` 是 `O(1)`。本题只按从左到右的顺序读取，每个值读一次，不修改原数组。数组保留原顺序，正好满足连续区间不能重排的约束。若改用链表，也能顺序遍历并得到相同的 `O(n)` 时间，但平台入口已经提供数组，链表节点和指针不会增加任何能力。

数组中保存的是原始贡献值，不保存区间对象。最坏情况下输入本身有 `n` 个元素，但输入空间不计入算法额外空间；算法不会再复制一个长度为 `n` 的数组。

### 两个滚动整数状态

`bestEndingHere` 保存当前右端点的局部最好和，`bestOverall` 保存历史所有右端点中的全局最好和。对每个新元素只需要：

- 读取当前值：`O(1)`。
- 做一次加法，比较“重启”和“延续”：`O(1)`。
- 比较局部最好与全局最好：`O(1)`。
- 覆盖旧滚动状态：`O(1)`。

它们的关键特征不是先进先出或后进先出，而是**状态生命周期只有相邻两轮**。计算下标 `i` 时只读取 `i-1` 的局部状态；一旦 `i` 结算完，旧状态以后不会再被直接读取，可以原地覆盖。`bestOverall` 则是一个只会保持或变大的聚合值，用来防止丢掉在早期结束的答案。

> **小白追问：** 不保存整张 `dp[]` 表，覆盖旧局部状态后怎么保证以后不缺信息？
>
> **先给短答：** 下一轮只依赖刚结算出的局部值，更早的局部值已通过连续转移被吸收到它里面，历史答案另由全局变量保存。
>
> **最小例子：** 处理 `[2,-3,4]` 的 `4` 时，只需知道结束于 `-3` 的最佳和是 `-1`。下标 `0` 的局部值 `2` 不能跳过 `-3` 直接接 `4`；而历史答案 `2` 已留在 `bestOverall` 中。
>
> **回到模型/代码：** 第一条更新读取并覆盖旧 `bestEndingHere`；第二条更新保留历史 `bestOverall`。这两个整数已经覆盖下一轮所需的全部信息。

如果使用 `dp[]` 数组，令 `dp[i] = bestEndingHere(i)`，也能正确运行，时间仍为 `O(n)`，但会额外占用 `O(n)` 空间。完整表适合教学、调试或需要恢复每个位置状态的变式；本题只返回一个数，滚动变量更匹配最小信息需求。

前缀和数组可以让任意区间和查询为 `O(1)`，但若仍枚举所有边界，候选数还是 `O(n^2)`；它优化了“一个区间如何求和”，没有自动解决“为什么要检查这么多区间”。维护最小历史前缀的线性模型是另一种正确方案，却需要同时处理前缀下标和先后顺序。栈、队列、堆和哈希表都没有本题所需的额外职责，强行引入只会扩大状态。

两个变量无论 `n` 多大都只保存两个整数，最坏额外状态数量为常数。根据官方数值边界，所有合法区间和都处于 `[-10^9,10^9]`，`int` 足够；若业务变式扩大元素值或长度，状态容器要改为 `long`。

## 11. 生活化类比及边界

把数组想成按日期排列的一本营业损益账。你要申报一段连续营业期，不能跳过某一天。每天关账时，会形成两本极小的账：一本只回答“如果申报期必须在今天结束，最好能报多少”；另一本回答“从开业到今天，历史最高申报额是多少”。

| 生活对象或动作 | 算法中的对应物 |
| --- | --- |
| 按日期排列的每日盈亏 | 原数组 `nums`，下标表示不可重排的时间顺序 |
| 今天的盈亏 | 当前元素 `nums[i]` |
| 必须在今天结束的申报期 | 任何右端点为 `i` 的非空连续子数组 |
| “今日结算账” | `bestEndingHere` |
| “历史纪录账” | `bestOverall` |
| 延续昨天的营业期 | `previousBestEndingHere + nums[i]` |
| 今天重新开一个申报期 | 单独选择 `nums[i]` |
| 昨日累计为负债时不再携带 | 旧局部和小于零时，延续严格劣于重启 |
| 今天刷新历史纪录 | `bestOverall = max(bestOverall, bestEndingHere)` |
| 最终申报额 | 遍历结束后的 `bestOverall` |

例如昨天结束时的最好营业期仍亏 `2`，今天盈利 `4`。带着昨天的负债只能得到 `2`，今天重新开始可得到 `4`，以后再接任何相同日程，前者始终少 `2`，所以可以把亏损历史结清。反过来，昨天累计盈利 `5`，今天亏 `1`，延续后仍有 `4`；不能因为今天是负数就切断。

类比到这里为止。现实经营可能有停业成本、税费、跨日折扣、不能随意选择申报期等额外规则，本题都没有；“负债清零”也不是修改原数组或免除真实亏损，而是决定最优候选不再以那段历史为左侧部分。类比帮助理解状态变化，严格正确性仍来自连续区间的两类来源和同后缀加法保持大小关系。

## 12. 典型输入的完整数据变化图

完整演算官方经典输入：

```text
遍历方向：从左向右  ----->

下标 i：   0    1    2    3    4    5    6    7    8
nums[i]： -2    1   -3    4   -1    2    1   -5    4
```

初始化下标 `0`。此时只有区间 `[0,0]` 合法：

```text
当前输入：nums[0] = -2
处理前状态：没有已结算位置
判断依据：子数组必须非空，唯一候选是 [-2]
执行动作：两个状态都从 nums[0] 建立
处理后状态：bestEndingHere = -2，bestOverall = -2
新增结果：前缀 [0,0] 的答案为 -2
```

后续每一轮都先比较“当前值单独开始”和“上一局部最好加当前值”，再更新全局纪录：

| `i` | `nums[i]` | 处理前局部和 | 重启：只取当前 | 延续：旧局部和 + 当前 | 新 `bestEndingHere` | 新 `bestOverall` | 局部决策 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 0 | -2 | 无 | -2 | 无 | -2 | -2 | 初始化为非空区间 `[0,0]` |
| 1 | 1 | -2 | 1 | -1 | 1 | 1 | 丢掉负历史，从下标 1 重启 |
| 2 | -3 | 1 | -3 | -2 | -2 | 1 | 延续虽仍为负，但比单独 `-3` 好 |
| 3 | 4 | -2 | 4 | 2 | 4 | 4 | 丢掉负历史，从下标 3 重启 |
| 4 | -1 | 4 | -1 | 3 | 3 | 4 | 延续 `[4,-1]` |
| 5 | 2 | 3 | 2 | 5 | 5 | 5 | 延续 `[4,-1,2]` 并刷新纪录 |
| 6 | 1 | 5 | 1 | 6 | 6 | 6 | 延续 `[4,-1,2,1]` 并刷新纪录 |
| 7 | -5 | 6 | -5 | 1 | 1 | 6 | 延续后的局部仍合法，但未刷新全局 |
| 8 | 4 | 1 | 4 | 5 | 5 | 6 | 延续得到 5，全局答案仍在更早位置结束 |

下标 `1` 的完整快照：

```text
当前输入：nums[1] = 1
处理前状态：bestEndingHere = -2，bestOverall = -2
判断依据：延续得 -2 + 1 = -1；重启得 1；负历史只会拖累
执行动作：bestEndingHere = 1；bestOverall = 1
处理后状态：局部最好对应 [1,1]；全局最好也为 1
新增结果：结束于下标 1 的候选组被压缩为和 1
```

下标 `2` 展示了“当前元素负数不等于立即重启”：

```text
当前输入：nums[2] = -3
处理前状态：bestEndingHere = 1，bestOverall = 1
判断依据：延续得 1 + (-3) = -2；重启得 -3；延续更大
执行动作：bestEndingHere = -2；bestOverall 保持 1
处理后状态：局部最好对应 [1,-3]，它虽然为负，仍是必须在 2 结束的最好候选
新增结果：没有刷新全局纪录
```

下标 `3` 是关键淘汰点：

```text
当前输入：nums[3] = 4
处理前状态：bestEndingHere = -2，bestOverall = 1
判断依据：延续得 2，重启得 4；旧段为负，当前和未来都只会被拖累
执行动作：从下标 3 重新开始，bestEndingHere = 4
处理后状态：bestOverall = 4，不变量恢复
新增结果：当前局部候选 [4] 同时成为新的全局答案
```

从下标 `3` 到 `6` 的局部区间变化可以画成：

```text
i=3： [4]                 和 4
i=4： [4, -1]             和 3
i=5： [4, -1, 2]          和 5
i=6： [4, -1, 2, 1]       和 6  <- 全局最好
i=7： [4, -1, 2, 1, -5]   和 1
i=8： [4, -1, 2, 1, -5,4] 和 5
```

最后一行说明 `bestEndingHere` 与 `bestOverall` 绝不能混为一个变量：遍历结束时局部值是 `5`，因为它必须包含最后的 `4`；全局值仍是 `6`，允许答案在下标 `6` 提前结束。

若把局部状态写成完整 DP 表，则数据变化为：

```text
下标 i：              0   1   2   3   4   5   6   7   8
nums[i]：            -2   1  -3   4  -1   2   1  -5   4
bestEndingHere(i)：  -2   1  -2   4   3   5   6   1   5
bestOverall(i)：     -2   1   1   4   4   5   6   6   6
遍历方向：            --------------------------------->
```

滚动实现没有真的保存这两行数组，但在每一轮结束时，两个变量与表中当前列完全一致。

## 13. 边界场景的数据变化

### 场景一：全部为负数

输入 `[-8,-3,-6,-2,-5,-4]`。每一步都必须保留一个真实非空区间：

| `i` | 当前值 | 延续值 | 重启值 | `bestEndingHere` | `bestOverall` |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | -8 | 无 | -8 | -8 | -8 |
| 1 | -3 | -11 | -3 | -3 | -3 |
| 2 | -6 | -9 | -6 | -6 | -3 |
| 3 | -2 | -8 | -2 | -2 | -2 |
| 4 | -5 | -7 | -5 | -5 | -2 |
| 5 | -4 | -9 | -4 | -4 | -2 |

最终答案是 `-2`，对应单元素区间 `[-2]`。若初始化为零，零会一直大于所有合法区间和，最终返回非法空区间。这不是一个小边界补丁，而是检验“状态是否始终代表非空候选”的核心用例。

> **小白追问：** 很多求最大值的代码都把答案初始化为 `0`，这里为什么一定不行？
>
> **先给短答：** `0` 在本题中会代表“一个元素也不选”，但题目要求子数组非空。
>
> **最小例子：** 对 `[-3,-2]`，合法候选和只有 `-3`、`-5`、`-2`，答案是 `-2`。若 `bestOverall=0`，任何合法负数都无法刷新它，最终会返回并不存在的空选择。
>
> **回到模型/代码：** `bestEndingHere` 与 `bestOverall` 都从 `nums[0]` 初始化，保证变量从第一刻起就对应真实的非空区间。

```text
错误空状态：bestOverall = 0  -> 数组中没有和为 0 的合法选择
正确非空状态：bestOverall = nums[0] = -8 -> 后续由真实元素逐步刷新到 -2
```

### 场景二：只有一个元素

输入 `[1]`：

```text
初始化：bestEndingHere = 1，bestOverall = 1
循环范围：i 从 1 到 0
实际循环：0 次
返回：bestOverall = 1
```

没有访问 `nums[1]`，不会越界，也没有残留集合。基础状态已经解决唯一合法区间。

### 场景三：零和相等决策

输入 `[0,2]`。处理下标 `1` 时，延续 `[0,2]` 与重启 `[2]` 的和都为 `2`。只求最大和时，任一候选都能产生正确数值；本文的 `Math.max(nums[i], bestEndingHere + nums[i])` 在数值层面无需区分。若要返回最短区间，应在相等时选择重启；若要返回最早左端点，则可能选择延续。相等值没有破坏当前模型，只是提醒我们：扩展输出内容时，状态要增加区间端点和明确的平局规则。

### 场景四：官方数值上界

长度 `100000` 且每个元素都是 `10000` 时，状态从 `10000` 逐步增加到 `1000000000`。循环执行 `99999` 次，两个变量仍是 `int` 可表示的正数。若元素上界或长度继续扩大，使总和可能超过 `2147483647`，应把局部和与全局和改为 `long`；那是数值容器变化，不改变状态转移。

## 14. 正确性与不变量

要证明的不是某一行代码看起来合理，而是两个状态在每个位置都具有声明的业务语义。

### 局部状态为什么正确

对任意下标 `i > 0`，取一个必须以 `i` 结尾的非空连续子数组。它若长度为一，只可能是 `[nums[i]]`。它若长度大于一，删除最后一个元素后，剩余区间一定非空、连续并且结束于 `i-1`。因此所有候选被完整分成“当前重启”和“从前一终点延续”两类，没有第三类。

在延续类中，所有旧区间都追加同一个 `nums[i]`。上一位置和最大的区间追加后仍然最大，因此只用 `bestEndingHere(i-1)` 就能代表整个延续类。取重启候选与最佳延续候选的较大值，正好得到所有以 `i` 结尾区间中的最大和。这既说明产生的结果合法，也说明没有漏掉任何可能的左端点。

### 被丢弃候选为什么以后不需要

同一右端点下，若候选 A 的和不小于候选 B，未来任何保持连续的扩展都会给二者追加同一串元素。加上相同数不会颠倒大小，B 永远不能超过 A，所以保留 A 足够。

若上一局部最好和已经为负，连这个组内最好的旧候选都比从当前值重启更差，组内其他候选更不可能有用。删除整段负历史后，当前形成的新区间仍连续且非空。若旧和等于零，删除与保留得到相同最大和；对只返回数值的本题，任意选择都不会遗漏更优答案。

### 全局状态为什么正确

处理完下标 `i` 后，所有合法区间按右端点分成两部分：右端点小于 `i` 的区间，以及右端点恰好为 `i` 的区间。前一部分的最大和已经由旧 `bestOverall` 保存；后一部分的最大和就是新 `bestEndingHere`。取二者较大值后，新 `bestOverall` 覆盖右端点不超过 `i` 的所有合法区间。

这也解释了为什么不能返回局部状态：局部状态只覆盖最后一组，而全局状态覆盖已经出现的所有组。

> **小白追问：** 循环结束时已经处理了最后一个元素，为什么不能直接返回 `bestEndingHere`？
>
> **先给短答：** 处理到最后只表示最后一组已结算，不表示最优区间必须属于最后一组。
>
> **最小例子：** 在 `[5,-10,1]` 中，最后的 `bestEndingHere=1`，它代表必须以最后位置结束的最好区间 `[1]`。历史最佳却是更早的 `[5]`，所以 `bestOverall=5`。
>
> **回到模型/代码：** 每轮先用局部结果刷新 `bestOverall`，方法最后返回 `bestOverall`。返回局部变量会错误地增加“答案必须到达数组末尾”这一限制。

### 循环不变量与结束条件

初始化后，两个变量都等于 `nums[0]`。它们分别正确表示结束于 `0` 的唯一非空区间，以及前缀 `[0,0]` 的全局最好区间。

假设处理 `i` 之前：

```text
bestEndingHere = bestEndingHere(i-1)
bestOverall    = bestOverall(i-1)
```

先按两类来源计算新的局部状态，再用它更新全局状态，根据前面的论证，处理后两个变量恰好变为 `bestEndingHere(i)` 与 `bestOverall(i)`。因此不变量从一轮保持到下一轮。

循环按 `i=1,2,3` 依次处理直到 `n-1`，每次下标增加一，必然终止。结束时所有可能右端点 `0..n-1` 都已结算；任何非空连续子数组都有且只有一个右端点，所以它所属的候选组已经进入过全局比较。此时 `bestOverall(n-1)` 就是题目要求的最大和。

## 15. 时间与空间复杂度推导

令 `n = nums.length`。在官方约束下，整数读取、加法、比较和赋值都按 `O(1)` 计算。题目只返回一个整数，因此返回结果本身占 `O(1)` 空间。

### 完全重新求和的三层直接模型

左右边界共有 `n(n+1)/2 = Theta(n^2)` 对。若每对边界又遍历区间元素求和，区间长度最坏为 `n`，总时间上界是 `O(n^3)`。更精确地看，所有区间长度之和为 `n(n+1)(n+2)/6`，所以时间为 `Theta(n^3)`。只保留循环变量和最大值时，辅助空间为 `O(1)`。

### 增量扩张的两层暴力模型

第 5 节代码对每个 `left` 把 `intervalSum` 置零，然后逐步右移 `right`。每对边界只触发一次加法和一次最大值比较，操作次数与区间数量同阶，因此时间为 `Theta(n^2)`。没有建立前缀数组或区间列表，辅助空间为 `O(1)`。

如果先建立长度为 `n+1` 的前缀和，再对每对边界做常数时间查询，总时间仍为 `Theta(n^2)`，额外空间变为 `O(n)`。瓶颈是候选区间数量，而不是单次求和。

### 完整 DP 表

若保存 `dp[i] = bestEndingHere(i)`，需要结算 `n` 个状态。每个状态做一次加法和常数次比较，总时间为 `Theta(n)`；长度为 `n` 的表占 `O(n)` 辅助空间。这里没有递归调用栈。

### 推荐的滚动状态模型

初始化处理第一个元素一次，循环再处理其余 `n-1` 个元素。每个元素只进行固定次数的读取、加法、比较和赋值，操作总数与 `n` 成正比，所以时间为 `Theta(n)`，常写作 `O(n)`。

算法始终只保存 `bestEndingHere`、`bestOverall` 和循环下标，不论输入多长，存活状态数量不增长，辅助空间为 `O(1)`。输入数组不计入额外空间，算法也不修改它。

> **小白追问：** `O(n)` 时间和 `O(1)` 空间分别是怎么数出来的，而不是看到单层循环就直接背结论？
>
> **先给短答：** 时间数处理次数，空间数随输入增长而新增的存活状态；本题每个位置处理一次，额外状态始终只有常数个。
>
> **最小例子：** 长度为 `4` 的数组先用下标 `0` 初始化，再执行下标 `1、2、3` 三轮。每轮固定做一次加法和两次最大值比较；数组变长时，变量仍只是两个和与一个下标。
>
> **回到模型/代码：** `for` 循环总共结算 `n-1` 次，因此时间随 `n` 线性增长。代码没有 `dp[n]`、递归栈或集合，因此额外空间不随 `n` 增长。

本算法没有隐藏的内层循环，不需要用均摊分析才能得到线性复杂度；它是每个元素直接花费常数时间。旧局部状态的生命周期是：在下一元素到来时被读取一次，产生新局部状态后立即覆盖，之后永不恢复。正是这个只跨一轮的依赖关系允许把 `O(n)` 的 DP 表压缩成 `O(1)` 空间。

| 方案 | 时间复杂度 | 辅助空间 | 主要浪费或用途 |
| --- | --- | --- | --- |
| 每个区间重新求和 | `Theta(n^3)` | `O(1)` | 同一区间片段被反复相加 |
| 固定左端点增量扩张 | `Theta(n^2)` | `O(1)` | 仍逐个枚举全部区间 |
| 前缀和后枚举边界 | `Theta(n^2)` | `O(n)` | 单次求和快，但候选数未减少 |
| 完整局部 DP 表 | `Theta(n)` | `O(n)` | 便于观察每个位置状态 |
| 两状态滚动模型 | `Theta(n)` | `O(1)` | 本题推荐实现 |

### 泛用模型骨架

下面先给“有序贡献流中的最佳非空连续阶段”骨架。它适用于每日盈亏、连续质量评分、连续净收益等问题，前提是阶段分数等于元素贡献之和、阶段必须非空且不能跳过元素。骨架使用 `long` 展示迁移到更大数值范围时的容器选择，并显式拒绝空输入，避免悄悄把空阶段当成合法答案。

```java
final class BestNonEmptyContiguousStageModel {
    public long findBestScore(long[] contributions) {
        if (contributions == null || contributions.length == 0) {
            throw new IllegalArgumentException("contributions must be non-empty");
        }

        long bestEndingHere = contributions[0];
        long bestOverall = contributions[0];

        for (int position = 1; position < contributions.length; position++) {
            long currentContribution = contributions[position];
            long restartHere = currentContribution;
            long extendPreviousStage = bestEndingHere + currentContribution;

            bestEndingHere = Math.max(restartHere, extendPreviousStage);
            bestOverall = Math.max(bestOverall, bestEndingHere);
        }
        return bestOverall;
    }
}
```

骨架中的“可迁移”不表示所有连续区间题都能直接相加。如果分数是乘积，负数会交换最大与最小，需要同时保存两个局部状态；如果允许至多删除一个元素，状态还要区分“尚未删除”和“已经删除”；如果允许空阶段，初始化和返回语义也要改变。稳定可迁移的是“先定义必须在当前位置结束的局部状态，再维护历史全局状态”这一控制结构。

### LeetCode 可直接提交代码

```java
class Solution {
    public int maxSubArray(int[] nums) {
        int bestEndingHere = nums[0];
        int bestOverall = nums[0];

        for (int i = 1; i < nums.length; i++) {
            bestEndingHere = Math.max(nums[i], bestEndingHere + nums[i]);
            bestOverall = Math.max(bestOverall, bestEndingHere);
        }
        return bestOverall;
    }
}
```

模型角色与代码的对应关系：

| 模型角色 | Java 变量或代码块 |
| --- | --- |
| 当前对象 | 下标 `i` 与当前贡献 `nums[i]` |
| 前一终点的最优状态 | 更新前的 `bestEndingHere` |
| 重启候选 | `nums[i]` |
| 延续候选 | `bestEndingHere + nums[i]` |
| 局部状态变化 | 第一条 `Math.max`，结算必须以 `i` 结尾的最好和 |
| 全局状态 | `bestOverall` |
| 结果产生时机 | 每轮局部状态结算后更新 `bestOverall`，循环结束后返回 |
| 非空基础状态 | 两个变量都初始化为 `nums[0]` |

代码故意保留两个有业务语义的变量。把两条更新压成难读的表达式不会减少复杂度，却会掩盖局部与全局的不同职责。

> **小白追问：** 两条更新语句为什么必须先算局部状态，再更新全局状态？
>
> **先给短答：** 当前右端点的新候选必须先产生，历史纪录才能拿它参加比较。
>
> **最小例子：** 对 `[-2,3]`，处理 `3` 时新局部值应先变成 `3`。若先执行全局比较，它只能看到旧局部值 `-2`，数组又恰好结束，最终会漏掉答案 `3`。
>
> **回到模型/代码：** 第一条 `Math.max` 写回 `bestEndingHere`，下一行才用更新后的值刷新 `bestOverall`。这正对应“先结算当前组，再汇入历史”的模型顺序。

## 17. 边界、常见错误与调试观察点

| 层次 | 常见错误 | 可见现象 | 修正依据 |
| --- | --- | --- | --- |
| 建模错误 | 把子数组当成子序列，只挑正数 | `[5,-2,5]` 错误得到 `10` | 连续区间不能跳过中间元素 |
| 建模错误 | 看到负元素就重启 | `[5,-1,5]` 只得到 `5` | 判断旧整段贡献，不判断当前单值正负 |
| 建模错误 | 用全局最优去延伸当前元素 | 可能跨过中间位置拼接不连续区间 | 只有结束于 `i-1` 的局部状态能延伸到 `i` |
| 建模错误 | 最后返回 `bestEndingHere` | 经典输入返回 `5` 而不是 `6` | 最终答案不一定在最后位置结束 |
| 条件错误 | 把两个状态初始化为 `0` | 全负数组返回非法的 `0` | 子数组必须非空，应从 `nums[0]` 初始化 |
| 条件错误 | 循环从 `i=0` 开始却已用首元素初始化 | 首元素被重复加入，正数样例偏大 | 初始化结算了下标 `0`，循环应从 `1` 开始 |
| 条件错误 | 把“旧和小于零”误写成“当前值小于零” | 无法跨过有价值区间中的小负数 | 比较重启值与延续值，或检查旧局部和 |
| 实现错误 | 先更新全局值，再更新局部值 | 当前右端点的候选未参与全局比较 | 先结算局部，再刷新全局 |
| 实现错误 | 业务扩展后仍用 `int` | 大输入出现溢出后的负数 | 按最大可能区间和选择 `long` |
| 扩展错误 | 返回区间时只保存和 | 能得到最大和，却无法恢复左右边界 | 重启时记录候选起点，刷新全局时保存两端 |

调试时最值得观察的不是整个数组，而是每轮的两个候选和两个状态：

```text
i
nums[i]
restartHere = nums[i]
extendPrevious = 更新前 bestEndingHere + nums[i]
更新后 bestEndingHere
更新后 bestOverall
```

对经典输入，关键日志应该包含：

```text
i=1, value=1,  restart=1,  extend=-1, ending=1,  overall=1
i=2, value=-3, restart=-3, extend=-2, ending=-2, overall=1
i=3, value=4,  restart=4,  extend=2,  ending=4,  overall=4
i=6, value=1,  restart=1,  extend=6,  ending=6,  overall=6
i=8, value=4,  restart=4,  extend=5,  ending=5,  overall=6
```

若全负数组输出零，先检查初始化；若经典输入输出五，检查是不是返回了局部状态；若 `[5,-1,5]` 输出五，检查是不是按当前元素的正负强制重启；若某一轮 `bestOverall` 变小，说明更新写错，因为它按定义是历史最大值，只能保持或增大。

还可以在调试版中同时保留 `int[] dp`，让 `dp[i]` 记录每一轮的局部状态，并断言滚动变量等于 `dp[i]`。这能区分“局部转移错了”和“全局聚合错了”。不要仅打印最终答案再猜测错误发生在哪个位置。

## 18. 最终模型卡

| 模型卡项目 | 结论 |
| --- | --- |
| 识别指纹 | 原顺序不可改变，答案是一段非空连续区间，区间分数可由前一终点状态加当前贡献得到，目标是全局最大值 |
| 一句话关系模型 | 所有区间按右端点分组，每组只保留必须在该位置结束的最大和，再对各组最大值取全局最大 |
| DP 实际保存什么 | `bestEndingHere` 保存当前终点的局部最好和；`bestOverall` 保存所有已结算终点中的最好和 |
| 状态何时变化 | 新元素到来时，在“当前重启”和“延续前一局部最好”之间选择 |
| 答案何时产生 | 每个右端点结算后都可能刷新全局答案；遍历结束返回历史纪录 |
| 核心不变量 | 一轮结束后，局部状态必须以当前下标结尾，全局状态覆盖当前前缀内全部非空连续区间 |
| 时间复杂度 | `O(n)`，每个元素做常数次工作 |
| 辅助空间复杂度 | `O(1)`，只保存两个核心和状态 |

**四句建模结论：**

```text
我正在处理的对象是：按右端点分组的所有非空连续子数组。
我必须持续保存的是：必须以当前位置结尾的最大和，以及此前所有位置中的全局最大和。
当一个新元素到来时，我执行：比较从当前元素重启与延续上一局部最优，并用新的局部结果刷新全局纪录。
答案在最后一个右端点结算完成时，由覆盖所有候选组的 bestOverall 计算出来。
```

**泛用控制模板：**

```text
确认答案对象必须连续且非空
按每个可能的结束位置给完整候选分组
定义“必须在当前位置结束”的局部状态
列出局部候选的全部来源
证明同一来源组中只保留最佳旧状态就足够
先更新局部状态，再更新历史全局状态
检查全负、单元素和相等决策是否符合非空语义
依赖只跨一轮时，把完整 DP 表压缩成滚动变量
```

| 题目或变化 | 保持的建模骨架 | 必须改变的状态或条件 |
| --- | --- | --- |
| 返回最大和区间的左右下标 | 局部结尾最优与全局最优仍分开 | 重启时记录局部起点，刷新全局时保存起点和终点；相等时定义平局规则 |
| 918. 环形子数组的最大和 | 仍需要普通非环形最大连续段 | 增加总和与最小连续段；还要排除“删除整个数组”造成的空答案 |
| 152. 乘积最大子数组 | 仍按“必须在当前位置结束”转移 | 负数会让最大与最小交换，必须同时保存局部最大乘积和局部最小乘积 |
| 至多删除一个元素的最大子数组和 | 仍从左向右结算当前终点 | 状态增加“未删除”和“已删除”两层，事件多出删除当前元素或先前元素 |

复习时不要只背 `current = max(x, current + x)`。真正可迁移的推导顺序是：连续性让新段只能接在前一终点后面；按终点分组覆盖所有答案；给相同未来的候选只需保留当前最优；局部终点状态负责延伸，全局状态负责记住可能早已结束的答案。
