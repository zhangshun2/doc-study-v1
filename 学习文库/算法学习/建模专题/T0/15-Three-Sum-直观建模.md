这道题真正难的地方，通常不是写出 `left++` 和 `right--`，而是解释这两个动作为什么敢做。原数组是无序的，三个位置看起来可以任意组合；答案还要求按数值组合去重，却又允许相同数值来自不同下标。若直接记住“3Sum 等于排序加双指针”，很容易在固定值去重、命中后去重、下标互异以及排序副作用上出错。

本篇要解决五个具体困难：怎样把“三个数同时未知”拆成一个固定值和一个两数目标；排序除了让数组好看，还创造了什么可以证明的方向；一次指针移动究竟排除了哪些组合；为什么 `[-1, -1, 2]` 合法而相同结果只能出现一次；以及为什么上一题 Two Sum 的哈希表不能不加改造地直接搬来。

## 2. 完整题目

给定一个整数数组 `nums`，寻找所有满足以下条件的三元组：三元组中的三个数来自三个互不相同的数组下标，并且三个数之和等于 `0`。返回的是数值三元组，而不是原下标。

答案中不能包含重复的数值组合。比如数组中可能有多个位置都保存 `-1`，不同下标组合可能反复得到 `[-1, 0, 1]`，但这个数值三元组在结果中只能保留一次。三元组内部的顺序以及多个三元组之间的输出顺序都不作要求。

### 输入与输出

- 输入：一个长度至少为 3 的整数数组 `nums`。
- 输出：所有互不重复、元素和为 `0` 的三元素数值列表。
- 下标条件：若三个值取自 `i`、`j`、`k`，则 `i`、`j`、`k` 两两不同。
- 去重口径：按三个数的数值组合去重，不是按下标组合去重。

### 示例 1

```text
输入：nums = [-1, 0, 1, 2, -1, -4]
输出：[[-1, -1, 2], [-1, 0, 1]]
```

数组里存在多组下标可以得到 `-1 + 0 + 1 = 0`，但它们表达的是同一个数值组合，因此只返回一份。两个 `-1` 位于不同下标，所以 `[-1, -1, 2]` 合法。

### 示例 2

```text
输入：nums = [0, 1, 1]
输出：[]
```

数组只有三个元素，它们的和是 `2`，不存在符合条件的三元组。

### 示例 3

```text
输入：nums = [0, 0, 0, 0]
输出：[[0, 0, 0]]
```

任取三个不同下标都可以得到和 `0`，但是所有下标组合对应的数值组合都相同，所以答案只有一份。

### 约束与方法入口

- `3 <= nums.length <= 3000`
- `-10^5 <= nums[i] <= 10^5`
- Java 方法入口：

```java
public List<List<Integer>> threeSum(int[] nums)
```

长度上限 `3000` 是重要性能信号。三层枚举最坏要检查约 `3000^3 / 6` 个下标组合，数量达到数十亿级，不能作为提交方案；平方级扫描约为数百万次，才进入合理范围。数值上限也意味着三个数的和位于 `[-300000, 300000]`，本题使用 Java `int` 不会溢出。本文仍会在泛用骨架中使用 `long` 表达目标和，提醒读者把模型迁移到 Four Sum 等题时重新检查数值范围。

## 3. 先把题目说成人话

**一句话生活化复述：**从一堆写着正数、负数和零的卡片中拿出三张不同卡片，让三张卡片的数值正好收支平衡，并且相同的金额组合只登记一次。

**一句话关系化复述：**寻找三个不同下标 `i`、`j`、`k`，使 `nums[i] + nums[j] + nums[k] = 0`，最后按三个值组成的无序组合去重。

这里同时存在两种“相同”，必须先拆开：

- **位置身份不同：**同一个位置不能使用两次，但两个不同位置可以保存相同数值。
- **结果数值相同：**只要三个值相同，不管来自哪三个下标，都算同一个答案。

例如 `nums = [-1, -1, 2]` 中，两个 `-1` 是两张不同卡片，因此可以同时选；而 `nums = [-1, 0, 1, -1]` 中，用第一个或最后一个 `-1` 得到的 `[-1, 0, 1]` 只登记一次。

> **小白追问：** 排序把元素的位置全改了，题目又要求三个下标不同，为什么还能排序？
>
> **先给短答：** 题目要返回数值组合，排序只重新排列已有元素，不会把两个原位置合成一个位置。
>
> **最小例子：** 原数组 `[1,-1,0]` 的三个元素来自原下标 `0、1、2`。排序后得到 `[-1,0,1]`，它们仍是刚才那三个元素，只是站位变成 `0、1、2`。取三个不同的排序位置，仍然对应三个不同的原位置；而答案只需写成 `[-1,0,1]`，不需要报告原下标。
>
> **回到模型/代码：** `Arrays.sort(nums)` 可以丢掉原顺序，是因为返回类型是数值列表；`first < left < right` 负责保证使用三个不同元素。若题目要求返回原下标，就必须把“值和原下标”一起排序，不能只保留值。

> **小白追问：** “三个下标互异”和“结果不能重复”不都是去重吗，为什么要分成两件事？
>
> **先给短答：** 前者限制一次答案怎样取元素，后者限制不同取法怎样合并为一份数值答案。
>
> **最小例子：** `[0,0,0,0]` 中，下标 `(0,1,2)` 合法，因为三个位置不同；下标 `(0,0,1)` 非法，因为位置 `0` 用了两次。合法取法 `(0,1,2)` 和 `(1,2,3)` 又都得到数值 `[0,0,0]`，所以输出只保留一份。
>
> **回到模型/代码：** `first < left < right` 处理下标互异；固定值去重和命中后的左右去重处理数值组合唯一。不要用一条“相等就跳过”的规则混合这两种职责。

### 题目关系图

```text
原关系：三个位置同时未知

    nums[i] + nums[j] + nums[k] = 0
       ?          ?          ?

固定 nums[i] = a 之后：

    nums[j] + nums[k] = -a
       ?          ?       已知目标

下标职责：i < j < k
数值职责：排序后 a <= nums[j] <= nums[k]
结果职责：同一组 [a, nums[j], nums[k]] 只记录一次
```

| 要素 | 本题含义 |
| --- | --- |
| 对象 | 数组中的位置，以及这些位置承载的数值 |
| 关系 | 三个不同位置的值相加等于 0 |
| 方向 | 原数组没有方向；排序后，向右数值不减，指针移动才有可预测影响 |
| 目标 | 找全所有不同的数值三元组，而不是找任意一个下标答案 |
| 限制 | 三个下标不同；相同值可使用的次数不能超过数组中的实际出现次数；结果不能重复 |

## 4. 第一切入点：读题时先看什么

第一分钟先圈出四组词：**三个数**、**和为零**、**下标互不相同**、**答案不重复**。其中“和为零”给出的是代数关系；“三个数”提示可以尝试固定一部分未知量；后两项则分别约束取数合法性与输出唯一性。题名只是标签，“判断是否存在”也不是本题的完整目标，因为它要求返回全部唯一组合。

接着暂时忽略“正数、负数”背后的故事，不要先问该用哪种数据结构。人工处理 `[-1, 0, 1, 2, -1, -4]` 时，常见动作是先把数摆整齐：

```text
原数组：[-1, 0, 1, 2, -1, -4]
排序后：[-4, -1, -1, 0, 1, 2]
```

然后先拿一张 `-1`，剩下两张必须合计为 `1`。此时 `-1 + 2 = 1`、`0 + 1 = 1`，于是得到两个答案。这个人工过程透露了两个切入点：

1. 三元关系可以通过固定一个数，降成目标明确的两元关系。
2. “摆整齐”不仅方便观察，它使“当前和偏小就换大一点的数”成为单向动作。

> **小白追问：** 固定一个数后，为什么三数问题就真的变成了“两数目标为 `-first`”的问题？
>
> **先给短答：** 因为固定值已经是常量，把它移到等式右边后，只剩另外两个未知数。
>
> **最小例子：** 固定值为 `-2` 时，原条件是 `-2 + b + c = 0`。两边同时加 `2`，得到 `b + c = 2`，而 `2` 正好是 `-(-2)`。因此右侧只需要寻找 `0+2` 或 `1+1` 这样的两数配对。
>
> **回到模型/代码：** 本题代码直接比较三数总和与 `0`；泛用骨架把同一关系显式写成 `requiredPairSum = target - values[fixed]`。这两种写法表达的是同一次降维。

数据规模进一步验证方向：需要从 `O(n^3)` 降到大约 `O(n^2)`。固定第一个数本身要 `O(n)` 次，所以对每个固定值，剩余两数最好在 `O(n)` 内解决，而不能再用两层循环。

最小样例 `[0, 0, 0]` 还提醒我们：相等值不能一概跳过。三个 `0` 来自三个不同位置，恰好构成答案。去重必须跳过的是“同一模型角色的重复选择”，而不是禁止答案内部出现相同值。

## 5. 最直接的人工或暴力模型

最可靠的起点是枚举所有不同下标组合。为了天然保证下标不同并避免把 `(i,j,k)` 的位置排列反复枚举，可以规定 `i < j < k`：

```text
for i 从 0 到 n - 3
    for j 从 i + 1 到 n - 2
        for k 从 j + 1 到 n - 1
            如果 nums[i] + nums[j] + nums[k] == 0
                把三个值整理成非递减顺序
                放入按数值组合去重的集合
```

这个方案一定不会漏解。任意三个不同下标总能按从小到大重新命名为唯一的 `i < j < k`，三层循环一定会走到它。整理三个值只是在建立结果的统一表示，不改变和；集合再把不同下标产生的同值三元组合并。

暴力模型的价值很大，因为它把正确性边界说清楚了：我们枚举的是下标组合，输出去重的是数值组合。后面的优化必须保留这两个语义，不能只追求更少循环。

设 `n` 为数组长度。三元下标组合数量是：

```text
C(n, 3) = n(n - 1)(n - 2) / 6
```

因此时间复杂度是 `O(n^3)`。每个命中三元组只有三个值，对三个值排序可视为常数成本。若用集合保存唯一答案，除返回结果外还可能保存 `u` 个唯一三元组，额外空间是 `O(u)`，其中 `u` 表示答案数；若先保存所有命中再去重，空间还会被大量重复下标组合放大。

## 6. 暴力到底浪费在哪里

看排序后的数组 `[-4, -1, -1, 0, 1, 2]`。暂时固定 `-1`，希望右侧两个数之和为 `1`。暴力会这样工作：

```text
固定 first = 1，值为 -1

leftCandidate = 2，值为 -1：
    依次试 0、1、2 -> 两数和 -1、0、1，最后命中 2

leftCandidate = 3，值为 0：
    又试 1、2 -> 两数和 1、2，命中 1

leftCandidate = 4，值为 1：
    又试 2 -> 两数和 3，不命中
```

当 `-1 + 2` 已经说明右端最大值与当前左值正好匹配后，暴力仍把每个左候选和后面的数重新组合。更明显的是，若当前两端相加仍偏小，例如固定 `-4` 时 `-1 + 2 = 1`，目标却是 `4`，那么保持这个 `-1` 再换任何更小的右值都不可能变大到 `4`。这些候选已经永久不可能成为答案，却仍会被内层循环逐个检查。

重复还来自相同数值。示例中两个 `-1` 可以作为不同下标参与同一个合法答案，但若二者轮流充当固定值，后续会再次生成 `[-1, 0, 1]`。暴力先制造重复，再依赖集合清理；中间计算没有被复用。

具体说，暴力丢失了三类中间结论：

- “当前和太小”只被当成一次失败，没有用来排除同一左值与所有更小右值。
- “当前和太大”没有用来排除同一右值与所有更大左值。
- “这个固定数值已经完整处理”没有阻止下一个相同固定值重走同一片搜索区间。

因此优化目标可以写成一句可执行的话：

> 先建立数值顺序；固定一个数后，用当前和的大小一次排除一整批不可能配对，并在相同数值连续出现时只让每个数值承担一次相同角色。

## 7. 容易想到但走不通的方向

### 方向一：直接照搬 Two Sum 的一张全局哈希表

想到哈希表非常自然。Two Sum 中扫描当前值 `x`，查询 `target - x` 是否出现，就能找到一对数。于是可能想对整个数组只建一张“值到下标”的表，然后查询另外两个数。

问题在于，固定第一个数 `a` 后，目标变成 `-a`；换一个 `a`，两数目标也会变化。更重要的是，本题不是找任意一组下标，而是找全所有唯一数值三元组。全局表只回答某个值是否存在，若不额外维护出现次数和允许的下标范围，可能把固定位置本身重复使用；即使找到了所有下标组合，仍要解决三元组内部规范化和结果去重。

哈希并非逻辑上不可行。可以对每个固定下标重新扫描右侧区间，用一个集合解决 Two Sum，时间做到 `O(n^2)`，额外空间 `O(n)`；再对固定值和答案做谨慎去重，也能通过。但它没有天然提供三元组的有序表示，去重规则更分散。由这个方向得到的新条件是：本题需要的不只是快速查询，还需要一个能同时支持**定向排除和局部去重**的表示。

### 方向二：排序后对每对数做二分查找

排序后固定 `i` 和 `j`，再在 `j` 右侧二分查找 `-(nums[i] + nums[j])`，时间复杂度是 `O(n^2 log n)`。它是正确方案，也比三层枚举快，所以不能说“走不通”；但它没有用足顺序信息。`j` 增大时，所需的第三个数会单调减小，反复从头二分等于不断丢弃上一次查找边界。

这个偏差告诉我们：排序后的查询之间有关联。如果两个候选边界只会单向收缩，就应维护边界，而不是把每次查询当成互不相关的任务。

### 方向三：用 `Set<List<Integer>>` 包住所有重复问题

集合能保证最终答案不重复，因此代码似乎可以完全不写跳重逻辑。它通常仍能得到正确结果，但会反复生成、装箱、计算哈希和比较相同列表。对 `[0,0,0,0,...]` 这样的输入，许多下标组合都会制造同一个 `[0,0,0]`。

集合解决的是“重复产生后怎样清理”，而排序后的相邻关系允许我们解决“怎样根本不重复产生”。由此得到去重原则：不要看到相等值就跳；要看这个值是否即将再次承担同一个角色。固定值与前一个固定值相同，就会重建同一个两数目标；命中后左值或右值继续取相同数值，就会重建同一个三元组，因此这两处才需要跳过。

## 8. 关键视角转换

真正的优化不是把三层 `for` 机械改成两个指针，而是连续发生了三次视角转换。

### 转换一：从无序位置组合到有序数值组合

原数组中从一个位置移动到另一个位置，数值可能变大也可能变小，所以“和偏小”无法指导下一步。排序后有：

```text
下标向右  => 数值不会减小
下标向左  => 数值不会增大
```

于是比较结果不再只是“这次没中”，而能决定应该让和变大还是变小。相同值也被放到一起，结果三元组天然按非递减顺序生成，去重可以局部完成。

### 转换二：从枚举完整三元组到固定一个角色

三个数同时变化时，搜索空间是立方体。固定最左数 `a` 后，关系变成：

```text
b + c = -a
```

现在每个固定值对应一个二维配对问题。固定下标 `first`，再规定 `first < left < right`，三个位置天然不同，不需要额外集合检查位置身份。

### 转换三：从逐对尝试到按偏差淘汰边界

对当前 `first`，令三数和为 `sum`：

- `sum < 0`：需要更大的和。右指针已经是当前范围最大值；连它都不够大，当前左值和任何更小右值都不可能成功，所以淘汰当前左值，`left++`。
- `sum > 0`：需要更小的和。左指针已经是当前范围最小值；连它都太大，当前右值和任何更大左值都不可能成功，所以淘汰当前右值，`right--`。
- `sum == 0`：当前三个不同下标构成答案。记录后两端都离开当前值，并越过重复值，寻找下一个不同组合。

> **小白追问：** 当前和偏小时，为什么移动 `left`，而不是尝试把 `right` 向左移动？
>
> **先给短答：** `right` 已经拿着剩余候选中的最大值，连最大值都不够，换更小的右值只会更差。
>
> **最小例子：** 固定 `-4`，剩余候选为 `[-1,0,2]`。当前两端是 `-1` 和 `2`，总和为 `-3`。若把右端换成 `0`，总和变成 `-5`，离 `0` 更远；只有把左端从 `-1` 换成更大的 `0`，总和才有机会增加。
>
> **回到模型/代码：** `sum < 0` 分支执行 `left++`。这一步不是猜测，而是在删除“当前左值与所有仍可选右值”这一整批已证明不可能的组合。

> **小白追问：** 当前和偏大时，为什么 `right--` 能安全淘汰当前右值的一整批组合？
>
> **先给短答：** `left` 已经是剩余候选中的最小值，连最小值配当前右值都太大，换更大的左值更不可能成功。
>
> **最小例子：** 固定 `-1`，剩余候选为 `[1,2,4]`。当前使用 `1` 和 `4`，总和是 `4`。若保留右值 `4`，把左值换成 `2`，总和只会升到 `5`；所以右值 `4` 在本轮可以整体淘汰。
>
> **回到模型/代码：** `sum > 0` 分支执行 `right--`。被删除的是当前右边界这个值与区间中所有可能左值的组合，不只是眼前这一对。

转换前，每次失败只排除一个 `(left,right)` 点；转换后，一次比较会排除一整行或一整列候选。两端边界只向中间移动，不会回头，这就是每个固定值只需线性时间的来源。

## 9. 正式建立模型

| 建模项 | 本题结论 |
| --- | --- |
| 对象 | 排序数组中的三个角色：固定位置 `first`、左候选 `left`、右候选 `right` |
| 关系 | `nums[first] + nums[left] + nums[right] == 0`，且 `first < left < right` |
| 状态 | 当前固定值、尚未排除的闭区间 `[left,right]`、已记录的唯一三元组列表 |
| 事件 | 三数和小于、等于或大于 0；以及新角色的值与该角色上次使用值相同 |
| 不变量 | 数组有序；固定值不重复处理；区间外的配对已被安全排除；结果中没有重复数值组合 |
| 结果时机 | 当 `left < right` 且三数和恰好为 0 时立即记录当前非递减三元组 |

> **小白追问：** “区间外候选已被安全排除”为什么叫不变量，它到底约束了什么？
>
> **先给短答：** 它表示每轮开始时都能相信：答案若尚未找到，只可能还在当前 `[left,right]` 中，不需要回头。
>
> **最小例子：** 固定 `-4`，当前 `left=-1`、`right=2` 时总和仍小于 `0`。我们证明了这个 `-1` 配任何不大于 `2` 的右值都失败，于是 `left++`。下一轮开始，旧左值位于区间外，并且已有证据说明它不含答案。
>
> **回到模型/代码：** 每个 `sum < 0` 或 `sum > 0` 分支都先完成淘汰证明，再缩小边界。这个“缩小后仍包含全部未发现答案”的性质就是内层循环依赖的不变量。

### 为什么这些状态已经足够

固定 `first` 后，未来是否存在答案，只取决于当前尚未排除的 `[left,right]`。区间左侧的值已经因为“过小”被证明无法与任何剩余右值配对；区间右侧的值已经因为“过大”被证明无法与任何剩余左值配对。我们不必保存排除历史，因为排序关系让证明永久有效。

答案只要求数值，不要求原下标，因此排序后无需保存“原位置到新位置”的映射。`first < left < right` 已经证明三个元素来自不同排序位置；排序只是位置置换，不会凭空增加或删除元素，所以它也证明来自三个不同原始位置。

### 什么可以永久丢弃

- 三数和小于 0 时，当前 `left` 可以永久丢弃。对任意 `r' <= right`，都有 `nums[r'] <= nums[right]`，换成它只会让和更小。
- 三数和大于 0 时，当前 `right` 可以永久丢弃。对任意 `l' >= left`，都有 `nums[l'] >= nums[left]`，换成它只会让和更大。
- 当前固定值与前一个固定值相等时，整个固定轮次可以跳过。前一轮从更宽的右侧区间已经处理过这个数值能够形成的所有数值组合。
- 命中后，连续相同的左值或右值可以跳过，因为固定值和另一端值不变时，它们只会生成相同的三元组。

> **小白追问：** 外层为什么只跳过与前一个固定值相同的 `first`，不能看到它与后一个相同就先跳？
>
> **先给短答：** 第一次出现的固定值必须负责完整搜索，只有后续相同固定值才是在重复已经做过的工作。
>
> **最小例子：** 排序数组 `[-1,-1,2]` 中，若第一个 `-1` 因为后面也是 `-1` 而被跳过，下一轮固定第二个 `-1` 时右侧只剩 `2`，凑不出两个位置，答案 `[-1,-1,2]` 就丢了。正确做法是处理第一个 `-1`，再跳过第二个固定轮次。
>
> **回到模型/代码：** 条件必须是 `first > 0 && nums[first] == nums[first - 1]`。它防止相同数值第二次承担固定角色，不禁止另一个相同值留在右侧承担 `left` 角色。

> **小白追问：** 命中后跳过重复 `left` 值是在防什么，为什么不能和外层去重混为一句？
>
> **先给短答：** 它防止同一固定值下，相同的第二个数再次生成同一个三元组；外层去重防的是第一个数重复。
>
> **最小例子：** 在 `[-2,0,0,2]` 中固定 `-2`，`left` 指向第一个 `0`、`right` 指向 `2` 时得到 `[-2,0,2]`。若只把 `left` 移到第二个 `0` 而右值仍是 `2`，下一次仍会得到同一个数值组合。
>
> **回到模型/代码：** `usedLeftValue = nums[left]` 保存刚刚作为第二角色写入答案的值；左侧 `while` 越过所有相同值。它只在已经命中之后执行，不会提前删掉组成答案所需的重复元素。

> **小白追问：** 命中后跳过重复 `right` 值又是在防什么，只处理左侧不够吗？
>
> **先给短答：** 右侧去重负责让第三角色也直接进入下一个不同数值，避免相同右值留在后续稳定状态中接受无效比较。
>
> **最小例子：** 在 `[-2,0,2,2]` 中固定 `-2` 并命中 `[-2,0,2]`。右侧从最后一个 `2` 移到前一个 `2` 时，位置变了，第三角色的数值却没变。继续把它当新右候选没有新信息，所以本实现让右侧越过刚用过的值，直到相遇或遇到不同值。
>
> **回到模型/代码：** `usedRightValue = nums[right]` 单独记录第三角色的旧值；右侧 `while` 负责清理它。某些变体只在一侧跳重，也能靠后续和的比较保持正确，但本文选择两侧都跳，使第二角色和第三角色遵守同一条“命中后进入不同值”的规则。

> **小白追问：** 命中后为什么两边都要移动，固定一边继续找另一个答案不行吗？
>
> **先给短答：** 固定值不变时，命中的左值与右值都已被证明不可能再和另一端的新值配平，所以本模型立即淘汰两端。
>
> **最小例子：** 固定 `-1` 时，两数目标是 `1`，命中 `left=0`、`right=1`。若保留左值 `0`，任何更小的新右值都会让两数和小于目标；若保留右值 `1`，任何更大的新左值都会让两数和大于目标。
>
> **回到模型/代码：** 命中分支先记录两个旧值，再让左侧越过旧左值、右侧越过旧右值。只移动一端的变体可以在后续比较中再淘汰另一端，但会多保留一个已经结算的边界；本文让两端立即离开，直接恢复“区间内只含未结算候选”的不变量。

### 遍历方向、相等值与提前结束

固定位置从左向右，保证它总是三元组中最小或并列最小的数值。左右指针相向移动，使未搜索区间单调缩小。若 `nums[first] > 0`，由于它右边的数都不小于它，三个数必然全为正，后续不可能再得到 0，可以直接结束固定循环。

相等值的处理要区分角色。`[0,0,0]` 中三个值相等但位置不同，合法；第一次命中前不能跳掉它们。命中后再越过同角色的重复值，防止相同数值组合再次产生。固定值去重也只在 `first > 0` 时与前一个比较，不能因为它与后一个相等就提前跳过，否则 `[-1,-1,2]` 中第一个 `-1` 会被错误跳过。

> **小白追问：** `nums[first] > 0` 时为什么可以提前结束，`nums[first] == 0` 时也能结束吗？
>
> **先给短答：** 固定值大于 `0` 时，右侧两个值都不小于它，三数和必然大于 `0`；固定值等于 `0` 时，右侧仍可能有两个 `0`。
>
> **最小例子：** 排序后的 `[0,0,0,1]` 在 `first=0` 时必须继续，才能找到 `[0,0,0]`。而 `[1,2,3]` 在 `first=0` 时最小可能总和已经是 `1+2+3=6`，后续固定值更大，更不可能回到 `0`。
>
> **回到模型/代码：** 专用提交代码使用 `if (nums[first] > 0) break;`，不能写成 `>= 0`。泛用目标不一定是 `0`，因此泛用骨架没有照搬这条剪枝。

## 10. 所需数据结构详解

本题核心没有栈、队列或哈希表。真正需要的是一个可随机访问的有序数组、三个整数下标，以及一个结果列表。先从模型需要的操作出发，比先背数据结构名更重要。

### 有序 `int[]`：方向性的来源

Java 的 `int[]` 在连续下标上保存整数，支持按下标 `O(1)` 读取和修改。调用 `Arrays.sort(nums)` 后，数组按非递减顺序排列。本文使用的关键操作是读取 `nums[first]`、`nums[left]`、`nums[right]`，比较相邻重复值，以及移动下标。

排序本身耗时 `O(n log n)`；排序完成后每次数组访问和指针移动都是 `O(1)`。数组的随机访问和有序性正好匹配“比较两端并收缩边界”。链表即使排好序，也不能方便地把右指针向前移动或按下标读取；哈希表擅长精确查询，却不提供“小了该往哪边走”的全序关系。

数组中保存的是**值**，不是原下标。因为输出也只要求值，丢失原顺序没有影响。但 `Arrays.sort(nums)` 会直接修改调用方传入的数组，这是接口副作用。若业务调用者还要使用原顺序，应先执行 `int[] sorted = Arrays.copyOf(nums, nums.length)`，再排序副本。LeetCode 本题通常允许修改输入，因此提交代码直接排序以保持简洁。

### `first`、`left`、`right`：三个角色边界

指针在 Java 里只是整数变量，不是特殊容器：

- `first` 固定三元组的第一个值，并把三元问题降成两数目标。
- `left` 指向未排除范围内最小的候选值，只向右移动。
- `right` 指向未排除范围内最大的候选值，只向左移动。

每个变量的读取、比较、加一或减一都是 `O(1)`。最坏情况下它们覆盖整个数组，但只占常数个整数空间。双指针适合本题，不是因为“数组题常用双指针”，而是因为状态恰好是一个有序区间，两侧候选又能根据比较结果永久淘汰。

> **小白追问：** 为什么只保存三个下标就够了，不需要保存已经试过的所有配对？
>
> **先给短答：** 排序让每次失败都能永久删除一个边界，过去的配对不会重新变成可行候选。
>
> **最小例子：** 固定 `-4` 时，若 `left=-1`、`right=2` 仍偏小，当前 `-1` 已经和可用最大值试过。它再配 `1、0、-1` 只会更小，所以不必记录这些失败项；把 `left` 移走就等于一次性结清它们。
>
> **回到模型/代码：** `first` 定义当前子问题，`left` 和 `right` 定义尚未排除的全部范围。这个边界状态已经概括历史，额外的 `Set` 或配对列表不会提供新的决策信息。

### `List<List<Integer>>`：保存输出而非辅助查询

外层列表保存不同三元组，内层列表固定保存三个装箱后的 `Integer`。追加一个三元组按三个元素计是 `O(1)`；若答案数为 `u`，返回结果占 `O(u)` 个三元组，也就是 `O(3u) = O(u)` 个数值槽位。

这个列表不承担去重查询。唯一性来自遍历规则，因此无需额外 `HashSet`。这点很重要：数据结构越少不一定越好，但当不变量已经阻止重复产生时，再加集合会重复承担职责，并掩盖去重是否真正想清楚。

### Java 排序空间应怎样表述

Oracle 文档确认 Java 17 的 `Arrays.sort(int[])` 对基本类型数组使用经过调优的排序实现，并给出 `O(n log n)` 性能说明；它的公开 API 并没有把辅助空间作为调用者可依赖的契约。算法分析中可以分两层写：双指针扫描本身是 `O(1)` 额外空间；若计入常见 JDK 基本类型排序实现的递归栈，可记为通常 `O(log n)`。返回答案的 `O(u)` 单独列出，避免把输出空间与算法工作空间混为一谈。

## 11. 生活化类比及边界

把数组想成一排按金额从小到大摆好的收支凭证：负数表示支出，正数表示收入，三张凭证合计为 0 表示正好平账。审计员先固定最左边一张凭证，再让两名助手分别站在剩余凭证的最左端和最右端。

如果三张合计仍为负，说明最右助手已经拿了当前可选的最大收入，仍然补不平。继续保留左助手手里的小金额，再把右助手向左换成更小金额，只会更负。因此应让左助手向右换一张更大的凭证。合计为正时完全对称，让右助手向左换小一些的凭证。平账成功后登记金额组合，并让两名助手越过相同面额，避免登记同一金额组合。

| 生活对象或动作 | 算法中的对应物 |
| --- | --- |
| 按金额排好的凭证 | 排序后的 `nums` |
| 审计员固定的一张凭证 | `nums[first]` |
| 站在剩余区间两端的助手 | `left` 与 `right` |
| 合计为负，需要增加金额 | `sum < 0` 时执行 `left++` |
| 合计为正，需要减少金额 | `sum > 0` 时执行 `right--` |
| 正好平账并登记 | `sum == 0` 时写入 `answer` |
| 跳过连续的相同面额 | 固定值去重及命中后的左右去重 |
| 助手之间尚未检查的凭证 | 未排除区间 `[left,right]` |
| 相同金额组合只登记一次 | 结果唯一性不变量 |

**类比到这里为止。**现实凭证可能有编号、时间、归属人和审批状态，但本题输出不关心原下标身份，只关心金额组合。现实审计也可能禁止修改凭证顺序，而算法中的排序只是内存重排。若题目改成返回原下标，便必须额外保存身份映射；若要求统计所有下标三元组，跳过重复面额反而会丢失应计数量。类比帮助理解指针为什么移动，不能替代后面的数学排除证明。

## 12. 典型输入的完整数据变化图

完整演算示例 `[-1,0,1,2,-1,-4]`。先排序：

```text
下标：  0    1    2    3    4    5
数值： -4   -1   -1    0    1    2
方向： first 从左向右；left ->；<- right
```

### 固定 `first = 0`，值为 `-4`

```text
下标：  0    1    2    3    4    5
数值： -4   -1   -1    0    1    2
        F    L                   R
```

| 步骤 | 处理前状态 `(F,L,R)` | 三数和 | 判断依据与动作 | 处理后状态 | 新增结果 |
| ---: | --- | ---: | --- | --- | --- |
| 1 | `(0,1,5)` 即 `(-4,-1,2)` | `-3` | 偏小；右端已最大，淘汰当前左值，`L++` | `(0,2,5)` | 无 |
| 2 | `(0,2,5)` 即 `(-4,-1,2)` | `-3` | 第二个 `-1` 也偏小，`L++` | `(0,3,5)` | 无 |
| 3 | `(0,3,5)` 即 `(-4,0,2)` | `-2` | 偏小，`L++` | `(0,4,5)` | 无 |
| 4 | `(0,4,5)` 即 `(-4,1,2)` | `-1` | 偏小，`L++` 后 `L == R` | `(0,5,5)`，本轮结束 | 无 |

这里没有因为看到重复 `-1` 就无条件跳过。它们处于左候选角色且尚未命中；逐个移动仍然保持简单、正确的边界规则。即使进一步优化成移动时顺带跳重复，也只改变常数，不改变模型。

### 固定 `first = 1`，值为 `-1`

```text
下标：  0    1    2    3    4    5
数值： -4   -1   -1    0    1    2
             F    L              R
```

| 步骤 | 当前输入 | 处理前状态 | 判断依据 | 执行动作 | 处理后状态 | 新增结果 |
| ---: | --- | --- | --- | --- | --- | --- |
| 1 | `(-1,-1,2)` | `F=1,L=2,R=5` | 和为 `0` | 记录；保存左右当前值；两端越过这些值 | `F=1,L=3,R=4` | `[-1,-1,2]` |
| 2 | `(-1,0,1)` | `F=1,L=3,R=4` | 和为 `0` | 记录；两端移动 | `L=4,R=3`，本轮结束 | `[-1,0,1]` |

第一次命中后的快照是：

```text
命中前：[-4, -1, -1,  0,  1,  2]
              F    L               R

登记：  [-1, -1, 2]

移动后：[-4, -1, -1,  0,  1,  2]
              F         L    R
```

### 后续固定值

```text
first = 2，nums[2] = -1
前一个固定值 nums[1] 也是 -1
=> 同样的数值角色已经完整处理，整轮跳过

first = 3，nums[3] = 0
left = 4，right = 5
0 + 1 + 2 = 3 > 0
=> right--，此时 left == right，本轮结束
```

最终结果为：

```text
[[-1, -1, 2], [-1, 0, 1]]
```

整个过程中，每一行表格都是一个稳定状态：`[left,right]` 之外的配对已经排除，之内的配对还待判断。指针没有回退，结果也没有依赖集合二次清洗。

## 13. 边界场景的数据变化

### 全部相等：`[0,0,0,0]`

这是同时检验“下标不同”和“结果去重”的关键场景。

```text
下标：  0    1    2    3
数值：  0    0    0    0
        F    L         R

sum = 0 + 0 + 0 = 0
记录 [0,0,0]

leftValue = 0，rightValue = 0
left 依次从 1 -> 2 -> 3
right 因 left < right 已不成立而停止移动
此时 left == right，双指针循环结束

下一轮 first = 1：nums[1] == nums[0]
固定值重复，直接跳过
```

最终只有 `[[0,0,0]]`。算法没有把同一个位置使用三次，因为命中时始终有 `first < left < right`；它只是允许三个不同位置具有相同数值。去重循环中的 `left < right` 同时保护数组边界，不会越过后再访问非法下标。

> **小白追问：** 左侧去重把 `left` 一直推到 `right`，右侧循环没有执行，这算不算漏做右侧去重？
>
> **先给短答：** 不算；指针已经相遇，当前固定值下已不存在两个不同位置，搜索必须结束。
>
> **最小例子：** `[0,0,0,0]` 命中时是 `first=0、left=1、right=3`。左侧循环越过值 `0` 后到达 `left=3`，此时只剩位置 `3` 一个候选。右侧即使再移动，也不可能组成两个不同位置，所以停止正是正确结果。
>
> **回到模型/代码：** 两个去重循环都带 `left < right`。这条条件首先保护下标互异和数组边界；只要区间已经耗尽，就没有必要强求两个循环都至少执行一次。

### 重复负数与正数：`[-1,-1,0,1,1]`

这个小样例同时让固定角色、左角色和右角色都遇到重复值。排序后数组不变，完整过程如下：

```text
下标：  0    1    2    3    4
数值： -1   -1    0    1    1
        F    L              R

first=0, left=1, right=4
sum = -1 + -1 + 1 = -1，偏小
淘汰 left=1；left -> 2

first=0, left=2, right=4
sum = -1 + 0 + 1 = 0，命中 [-1,0,1]
保存 usedLeftValue=0，usedRightValue=1
left: 2 -> 3
right: 4 -> 3（离开已使用的最右 1；因指针相遇而停止）
left == right，本轮结束

first=1，nums[1] == nums[0]
相同固定值已经处理，跳过整轮

first=2，值为 0；left=3，right=4
sum = 0 + 1 + 1 = 2，偏大
right: 4 -> 3，区间耗尽

最终结果：[[-1,0,1]]
```

这个过程没有跳过组成答案所需的第一个 `1`。右侧去重发生在答案已经记录之后，它越过的是“再次承担第三角色只会产生重复”的值。第二个固定 `-1` 被跳过，则是因为第一个固定 `-1` 已从更宽的右侧范围完成了相同目标的搜索。

### 没有答案：`[0,1,1]`

```text
下标：  0    1    2
数值：  0    1    1
        F    L    R

sum = 2 > 0
right: 2 -> 1
left == right，循环结束
answer 仍为空列表
```

只有三个元素时，固定循环只可能执行一次；双指针相遇后没有三个不同位置，必须停止。默认结果是已经创建的空列表，不需要特殊返回值。

### 排序副作用边界

对输入 `[-1,0,1]` 调用提交实现后，原数组会变成 `[-1,0,1]`，看不出变化；对 `[1,-1,0]` 调用后则会被改成 `[-1,0,1]`。这不影响 LeetCode 返回值，但在复用数组的业务代码里是可观察副作用。若契约要求输入只读，模型不变，只需在排序前复制数组，并把后续状态都建立在副本上。

## 14. 正确性与不变量

要证明的不是“代码看起来扫描了很多数”，而是三件事：记录的每个结果都合法；每个合法数值三元组都能被找到；同一个数值三元组不会记录两次。

### 合法性

结果只在 `left < right` 且三数和为 0 时产生。固定循环又保证 `first < left`，因此 `first < left < right`，三个排序位置互不相同。排序只是对原元素做置换，所以它们也对应三个不同原下标。写入列表的三个值经过实际求和判断，必然满足题目条件。

### 指针移动为什么不会漏解

固定 `first`，假设当前和小于 0。数组有序，对当前 `left` 和任意尚未考虑的 `r'`，都有 `r' <= right`，从而：

```text
nums[first] + nums[left] + nums[r']
<= nums[first] + nums[left] + nums[right]
< 0
```

所以当前左值不可能再和区间内任何右值组成答案，`left++` 不会漏解。和大于 0 时对称：任意 `l' >= left` 都使总和不小于当前总和，因此当前右值不可能与任何剩余左值成功，`right--` 安全。

这也是“最左和最右”不可随便换成中间两个位置的原因。排除证明依赖它们分别是剩余候选中的最小值和最大值。

> **小白追问：** 每次只看当前两端，怎么确认中间某一对不会被跨过去？
>
> **先给短答：** 指针只删除已证明整行或整列都失败的边界，中间配对始终留在未排除区间里，直到被检查或被同样的证明覆盖。
>
> **最小例子：** 固定 `-3`，候选 `[0,1,2,4]`。两端 `0` 和 `4` 使三数和为 `1`，偏大，因此删除右值 `4`；中间答案 `1+2=3` 仍在新区间 `[0,1,2]`。随后删除过小左值 `0`，最终两端正好到达 `1` 和 `2`。
>
> **回到模型/代码：** 循环不变量保证 `[left,right]` 始终包含所有尚未否定的配对。`left++` 和 `right--` 的证明对象是边界值的全部配对，不是随意跨过一个位置。

### 为什么固定一个数能覆盖全部答案

任意合法三元组的三个值都可以写成非递减顺序 `a <= b <= c`。排序数组中一定存在三个不同位置承载它们。固定循环第一次处理数值 `a` 时，右侧区间包含可用的 `b` 和 `c`；双指针只会排除已被证明不可能的边界，因此最终会到达某组值为 `b`、`c` 的位置并记录答案。

即使 `a == b` 或 `b == c`，只要数组有足够出现次数，它们仍位于不同排序位置。固定值去重跳过的是第二次及之后让 `a` 充当固定角色的轮次，不会跳过第一次轮次中位于右侧的另一个 `a`。

### 去重为什么不会误删

固定值相同意味着两轮寻找的目标 `-a` 相同。第一次固定该值时，它右侧拥有不少于后续重复固定位置的候选集合，因此已经能够发现后续轮次可形成的所有数值组合。跳过后续相同固定值只删除重复工作。

命中 `[a,b,c]` 后，若左指针继续落在另一个值仍为 `b` 的位置，在固定 `a`、右值仍为 `c` 时只能再次生成 `[a,b,c]`；右侧重复值同理。越过连续相同值后，才可能产生新的数值组合。排序保证相同值连续，因此局部跳过足以完成全局结果去重。

### 循环结束为什么完整

每一步至少让 `left` 增大或让 `right` 减小，二者距离严格缩短，所以内层循环一定终止。终止时 `left >= right`，不存在两个不同的剩余位置。固定循环覆盖所有可能成为三元组最小值的非重复位置；一旦固定值大于 0，后续三个值都大于 0，不可能和为 0。此时所有合法组合都已记录。

## 15. 时间与空间复杂度推导

定义：

- `n` 表示输入数组长度。
- `u` 表示最终不同三元组的数量。
- 一次求和、比较、数组访问、指针增减按 `O(1)` 计算。

### 直接模型

直接模型枚举所有 `i < j < k`，组合数为 `C(n,3)`，最高次项是 `n^3 / 6`，因此时间复杂度为 `O(n^3)`。每个命中项整理三个值是常数操作，不改变数量级。

若用集合按值去重，集合最终至少承载 `u` 个答案，额外空间为 `O(u)`；若把返回结果本身排除在辅助空间之外，去重集合仍是 `O(u)` 的额外工作空间。暴力若不去重则不满足题意，不能把它的空间简单写成 `O(1)`。

### 推荐模型

排序耗时 `O(n log n)`。外层最多固定 `n - 2` 次。对某个固定位置，虽然内层是 `while`，但不是每轮都重新扫描：

```text
left  生命周期：从 first + 1 开始，只能向右，最多移动 n 次
right 生命周期：从 n - 1 开始，只能向左，最多移动 n 次
```

一次内层迭代至少消耗一个指针位置，命中时可能同时消耗两端。因此每个固定值的总移动次数是 `O(n)`，而不是因为有两个指针就成为 `O(n^2)`。外层 `O(n)` 乘以内层整段生命周期 `O(n)`，扫描总计 `O(n^2)`。加上排序：

```text
O(n log n) + O(n^2) = O(n^2)
```

去重循环也不会额外抬高复杂度。被它跨过的元素本来就是 `left` 或 `right` 生命周期中的一次单向移动，每个位置在当前固定轮次不会被反复跨越。

> **小白追问：** 外层 `for` 里面还有 `while`，命中后又套两个 `while`，为什么不是 `O(n^3)`？
>
> **先给短答：** 对一个固定值，所有内层循环共享同一对只向中间移动的指针，总移动次数最多是线性的。
>
> **最小例子：** 剩余区间有 5 个位置时，`left` 最多向右跨 4 次，`right` 最多向左跨 4 次。去重循环多跨一步，就会少留一步给主循环；同一个位置不会先被去重跨过，之后又回头再处理。
>
> **回到模型/代码：** 每个 `first` 的指针生命周期是 `O(n)`，外层最多 `O(n)` 个固定位置，所以扫描是 `O(n) * O(n) = O(n^2)`。多个语法上的嵌套不应直接相乘，必须先看它们是否消费同一批单向状态。

双指针主体只使用 `first`、`left`、`right`、`sum` 和两个去重值，额外空间为 `O(1)`。若计入常见 JDK 基本类型排序实现的调用栈，可将工作空间记为通常 `O(log n)`；Java API 不把具体辅助空间策略作为稳定契约。返回的 `u` 个三元组占 `O(u)`，通常单独报告为输出空间。于是清晰的结论是：**不含输出时，扫描 `O(1)`，计入排序实现时通常 `O(log n)`；含输出时再加 `O(u)`。**

### 泛用 Java 建模骨架

下面不是只针对目标 `0` 的记忆代码，而是“固定一个值，把三元目标降成有序区间中的两数目标”的完整骨架。`target` 使用 `long`，使这个关系模型更容易迁移到目标值范围更大的题。它会原地排序 `values`。

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

final class OrderedThreeValueModel {
    static List<List<Integer>> collectUniqueTriples(
            int[] values, long target) {
        Arrays.sort(values);
        List<List<Integer>> uniqueTriples = new ArrayList<>();

        for (int fixed = 0; fixed < values.length - 2; fixed++) {
            if (fixed > 0 && values[fixed] == values[fixed - 1]) {
                continue;
            }

            long requiredPairSum = target - values[fixed];
            int smallerCandidate = fixed + 1;
            int largerCandidate = values.length - 1;

            while (smallerCandidate < largerCandidate) {
                long pairSum = (long) values[smallerCandidate]
                        + values[largerCandidate];

                if (pairSum < requiredPairSum) {
                    smallerCandidate++;
                } else if (pairSum > requiredPairSum) {
                    largerCandidate--;
                } else {
                    uniqueTriples.add(Arrays.asList(
                            values[fixed],
                            values[smallerCandidate],
                            values[largerCandidate]));

                    int usedSmallerValue = values[smallerCandidate];
                    int usedLargerValue = values[largerCandidate];
                    while (smallerCandidate < largerCandidate
                            && values[smallerCandidate] == usedSmallerValue) {
                        smallerCandidate++;
                    }
                    while (smallerCandidate < largerCandidate
                            && values[largerCandidate] == usedLargerValue) {
                        largerCandidate--;
                    }
                }
            }
        }
        return uniqueTriples;
    }
}
```

骨架中的抽象关系很明确：`fixed` 决定当前子问题；`requiredPairSum` 是降维后的两数目标；`smallerCandidate` 与 `largerCandidate` 围住所有尚未排除的配对；两个 `while` 只跨过刚刚已经写入结果的数值角色。若目标不是 0，不能使用“固定值大于 0 就结束”的专用剪枝，所以泛用骨架没有加入该判断。

> **小白追问：** 代码为什么必须先记录命中值，再执行两个去重循环，顺序换一下会怎样？
>
> **先给短答：** 去重需要知道刚刚命中的两个数值；若先移动指针，比较基准就可能变成新候选，甚至越界。
>
> **最小例子：** `[0,0,0,0]` 命中时 `left=1、right=3`。先保存旧值 `0`，才能明确“越过连续的 0”。若先做 `left++` 再把 `nums[left]` 当旧值，读到的是另一个位置；更短区间里还可能已经出现 `left == right`，继续读取就会破坏边界约束。
>
> **回到模型/代码：** 命中分支的顺序是 `answer.add`，保存 `usedLeftValue/usedRightValue`，再分别移动。它对应“先结算当前答案，再清理承担过相同角色的候选”，不能交换成先清理后结算。

### LeetCode 可直接提交代码

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        Arrays.sort(nums);
        List<List<Integer>> answer = new ArrayList<>();

        for (int first = 0; first < nums.length - 2; first++) {
            if (nums[first] > 0) {
                break;
            }
            if (first > 0 && nums[first] == nums[first - 1]) {
                continue;
            }

            int left = first + 1;
            int right = nums.length - 1;
            while (left < right) {
                int sum = nums[first] + nums[left] + nums[right];
                if (sum < 0) {
                    left++;
                } else if (sum > 0) {
                    right--;
                } else {
                    answer.add(Arrays.asList(
                            nums[first], nums[left], nums[right]));

                    int usedLeftValue = nums[left];
                    int usedRightValue = nums[right];
                    while (left < right && nums[left] == usedLeftValue) {
                        left++;
                    }
                    while (left < right && nums[right] == usedRightValue) {
                        right--;
                    }
                }
            }
        }
        return answer;
    }
}
```

### 代码与模型角色映射

| 模型角色 | Java 变量或代码块 |
| --- | --- |
| 建立全序与重复邻接 | `Arrays.sort(nums)` |
| 当前固定对象 | `first` 与 `nums[first]` |
| 降维后的两数候选范围 | `left`、`right` 围住的区间 |
| 偏小事件 | `sum < 0`，执行 `left++` |
| 偏大事件 | `sum > 0`，执行 `right--` |
| 结果产生时机 | `sum == 0` 时调用 `answer.add(...)` |
| 固定角色去重 | `nums[first] == nums[first - 1]` 时跳过本轮 |
| 命中角色去重 | 记录 `usedLeftValue`、`usedRightValue` 后越过连续相同值 |
| 提前结束 | `nums[first] > 0` 时 `break` |

代码没有单独验证三个下标是否不同，因为模型已经通过初始化和循环条件表达了这个约束：`left = first + 1`，且只有 `left < right` 时才求和。也没有使用 `Set` 检查答案是否存在，因为固定角色和命中角色的局部去重已经维持了全局唯一性。

## 17. 边界、常见错误与调试观察点

| 层次 | 常见错误 | 后果 | 应观察的状态 |
| --- | --- | --- | --- |
| 建模错误 | 未排序就根据和大小移动指针 | 移动方向没有单调保证，可能漏解 | 每次移动前后的值是否真的单调变化 |
| 建模错误 | 把结果理解为下标组合 | 同值结果被重复保存，或错误保存原位置 | 当前需求究竟返回值还是下标 |
| 建模错误 | 把哈希版 Two Sum 原样使用一张全局表 | 可能重复使用固定位置，且难以保证唯一三元组 | 固定值变化后两数目标、下标范围和计数 |
| 条件错误 | 固定值与后一个值相等就跳过 | 可能漏掉 `[-1,-1,2]` | `first` 是否是该数值第一次充当固定角色 |
| 条件错误 | 命中后只移动一端 | 重复生成相同组合，或搜索停滞 | 命中前后的 `left/right` 是否都越过使用值 |
| 条件错误 | 内层使用 `left <= right` | 指针相遇时会重复使用同一位置 | 始终检查 `first < left < right` |
| 实现错误 | 去重时先移动再读取旧值，边界又未检查 | 越界或跳重基准错误 | `usedLeftValue`、`usedRightValue` 保存时机 |
| 实现错误 | 忘记排序会修改输入 | 调用方后续看到顺序变化 | 方法调用前后打印 `nums` |
| 实现错误 | 迁移到更大数值范围仍用 `int sum` | 溢出后比较方向错误 | 同时打印数值和用 `long` 算出的和 |

最有效的调试输出不是只打印答案，而是每轮打印稳定状态：

```text
first=1(-1), left=2(-1), right=5(2), sum=0, action=record-and-skip
first=1(-1), left=3(0),  right=4(1), sum=0, action=record-and-skip
first=2(-1), action=skip-duplicate-fixed
```

若出现漏解，先核对排序后的数组和每次“排除一整批”的理由；若出现重复答案，分别检查固定值去重与命中后两端去重，二者职责不同。若循环不结束，检查每个分支是否至少移动一个指针。若 `[0,0,0,0]` 返回空，重点检查是否在命中之前错误跳过了相等值。

还应主动测试：最小长度 `[0,0,0]`；无答案 `[1,2,3]`；答案使用重复值 `[-2,1,1]`；多个重复答案来源 `[-1,-1,-1,0,1,1]`；全为负数；全为正数；输入排序前后差异明显的数组。调试目标是验证不变量，而不是堆积随机用例。

## 18. 最终模型卡

| 项目 | 复习结论 |
| --- | --- |
| 题型识别指纹 | 找全固定个数元素的目标和组合；原数据无序；结果按数值去重；排序后比较具有单调方向 |
| 一句话关系模型 | 固定三元组的最小值 `a`，把 `a+b+c=0` 降成右侧有序区间中的 `b+c=-a` |
| 实际保存什么 | 固定下标、尚未排除区间的左右边界、已生成的唯一结果 |
| 状态何时变化 | 和偏小时淘汰左边界，和偏大时淘汰右边界，命中时记录并越过两端重复值 |
| 答案何时产生 | `first < left < right` 且三数和为 0 时 |
| 核心不变量 | 数组有序；区间外候选已安全排除；每个数值只承担一次相同角色；结果不重复 |
| 时间复杂度 | 排序 `O(n log n)`，全部扫描 `O(n^2)`，总体 `O(n^2)` |
| 空间复杂度 | 扫描主体 `O(1)`；计入常见排序栈通常 `O(log n)`；输出另计 `O(u)` |

### 四句建模结论

```text
我正在处理的对象是：排序数组中由固定值和左右候选组成的三数关系。
我必须持续保存的是：当前固定位置、尚未排除的左右边界以及已经生成的唯一三元组。
当 当前三数和偏小、偏大或恰好命中 发生时，我执行：淘汰左边界、淘汰右边界，或记录结果后越过两端重复值。
答案在 三个不同位置的数值和恰好为零时 由 nums[first]、nums[left] 和 nums[right] 计算出来。
```

### 泛用迁移模板

```text
1. 先问：输出关心值还是原位置，排序是否允许。
2. 排序，让比较结果能指导候选向单一方向变化，并让重复值相邻。
3. 固定一个或多个角色，把 K 元关系降成更低维目标。
4. 在剩余有序区间维护最小候选和最大候选。
5. 根据偏小或偏大证明可以永久淘汰哪一侧。
6. 只在同一角色即将重复时去重，不禁止不同角色使用相同值。
7. 分开证明合法性、完整性、排除安全性与结果唯一性。
```

### 后续变式

- **16. 最接近的三数之和：**关系从“恰好命中”改为“差值最小”。状态要增加当前最优和；答案在每次比较时都可能更新，而不是只在相等时产生。
- **18. 四数之和：**固定角色从一个变成两个，再把四元关系降成两数目标。排除逻辑不变，但总时间变为 `O(n^3)`，并应使用 `long` 防止求和溢出。
- **167. 两数之和 II：**输入已经有序，且通常只需一个答案。省去固定角色和三元组去重，直接保留左右边界及定向排除。
- **通用 K Sum：**递归固定一个值，把 K Sum 降为 `(K-1)` Sum，直到两数双指针。变化的是固定层数和剪枝边界，底层关系仍是有序区间中的单向排除。
