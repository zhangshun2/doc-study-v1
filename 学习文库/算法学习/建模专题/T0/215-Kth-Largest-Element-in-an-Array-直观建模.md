# 215. 数组中的第 K 个最大元素：从反复找最大值到维护入选门槛

本篇要解决的困难，不是背下“第 `k` 大就用小顶堆”，而是从排名的含义一步步推出：为什么已经看过的数字中只需要留下 `k` 个候选；为什么候选中最小的那个数字最值得随时访问；为什么比门槛更小的数字可以永久淘汰；为什么最后的门槛恰好是第 `k` 大；以及重复值为什么必须按出现次数参与排名。

当前题面还明确要求设计 `O(n)` 算法。本文仍把大小为 `k` 的有界候选集作为主模型，因为它的状态最直观、最坏性能稳定、不修改输入，并且能直接迁移到数据流场景；其时间复杂度是 `O(n log k)`，并不满足把 `k` 也视为输入变量时的严格线性要求。需要严格对齐该要求时，应采用标准题解中的随机化快速选择，或利用本题固定值域做计数。本文不会把教学主模型冒充成唯一方案。

## 2. 完整题目

给定一个整数数组 `nums` 和整数 `k`，把数组中的每一次出现都看成一个独立的排名位置。需要返回这些元素按从大到小排列后位于第 `k` 个位置的值。

这里找的是“第 `k` 个最大的元素”，不是“第 `k` 个不同的值”。因此重复数字不会被去重。例如 `[5, 5, 4]` 从大到小仍是 `[5, 5, 4]`，第 `2` 大是 `5`，不是 `4`。

### 示例 1：普通排列

```text
输入：nums = [3, 2, 1, 5, 6, 4], k = 2
输出：5
解释：从大到小排列为 [6, 5, 4, 3, 2, 1]，第 2 个值是 5。
```

### 示例 2：含有重复值

```text
输入：nums = [3, 2, 3, 1, 2, 4, 5, 5, 6], k = 4
输出：4
解释：从大到小排列为 [6, 5, 5, 4, 3, 3, 2, 2, 1]。
      两个 5 分别占据第 2 和第 3 名，所以第 4 大是 4。
```

### 示例 3：负数与重复值

```text
输入：nums = [-1, -1], k = 2
输出：-1
解释：两个 -1 都要参与排名，第 2 大仍然是 -1。
```

### 官方约束与性能要求

- `1 <= k <= nums.length <= 10^5`。
- `-10^4 <= nums[i] <= 10^4`。
- 当前题面要求设计并实现时间复杂度为 `O(n)` 的算法。
- 数组一定非空，`k` 一定合法，所以题目不存在“第 `k` 大不存在”的返回语义。

Java 方法入口为：

```text
class Solution {
    public int findKthLargest(int[] nums, int k) {
    }
}
```

约束给出三个重要信号。第一，`n` 可达十万，按名次逐轮完整扫描在最坏情况下会很慢。第二，值可以为负数，不能随意拿 `0` 当“尚未找到”的哨兵。第三，值域只有 `[-10000, 10000]` 共 `20001` 个整数，因此计数数组是本题特有的线性替代方案；不过有界堆不依赖固定值域，对任意可比较整数和持续到来的数据都成立。

## 3. 先把题目说成人话

**一句话生活化复述：** 一批分数陆续摆到桌面上，只关心最终排名前 `k` 的分数，而答案是这份入选名单里最弱的分数。

**一句话关系化复述：** 在包含重复出现的数值多重集合中，求恰好有至少 `k - 1` 个出现位置排在它前面的那个顺序统计值。

先用 `[6, 5, 5, 4, 3]` 理解“第 `k` 大”。当 `k = 4` 时，前四名是 `[6, 5, 5, 4]`。答案 `4` 有两个等价身份：它既是全体元素的第 `4` 大，也是“最大的四个元素”当中最小的一个。第二种说法非常重要，因为它把一个最终排名问题改写成了一个可以随输入逐步维护的候选集合问题。

```text
全体元素：6  5  5  4  3
          \_________/
           最大的 k=4 个

这 k 个中的最小值 = 4 = 全体第 k 大
```

> **小白追问：** “第 `k` 大”为什么能改写成“最大的 `k` 个数中的最小值”？这不是换了一道题吗？
>
> **先给短答：** 没有换题，只是把同一个降序排名的第 `k` 个位置改成了一个候选集合的下边界。
>
> **最小例子：** `[7, 4, 2]`、`k = 2` 时，降序是 `[7, 4, 2]`，第 `2` 大为 `4`。最大的两个数是 `[7, 4]`，其中最小值仍是 `4`。若选出的两个数不是全体最大的两个，例如 `[7, 2]`，其最小值 `2` 就不会等于第 `2` 大；因此“最大的 `k` 个”这项前提不能省略。
>
> **回到模型/代码：** `largestK` 负责保存“最大的 `k` 个”，`largestK.peek()` 负责读取这组候选的最小值。前者保证候选身份，后者才把候选集合转换成第 `k` 大答案。

| 要素 | 本题中的含义 |
| --- | --- |
| 对象 | 数组中的每一次元素出现，而不只是不同数值 |
| 关系 | 数值之间的大小关系，以及由此形成的排名关系 |
| 方向 | 输入可以从左向右逐个处理；排名本身与原下标顺序无关 |
| 目标 | 找到全体最大的 `k` 个出现位置中最小的值 |
| 限制 | 重复值不去重；`k` 合法；主模型希望不修改原数组，只保留有限状态 |

题目没有要求输出前 `k` 名的完整有序名单，也没有要求给出原下标。原下标、已淘汰数字之间的顺序、前 `k` 名内部除最小值外的精确顺序，都不是返回答案所必需的信息。建模的方向因此不是“怎样一直维护完整排序”，而是“怎样只保留仍可能影响第 `k` 大的最小信息”。

## 4. 第一切入点：读题时先看什么

第一分钟应先圈出“**第 `k` 大**”和“**不是第 `k` 个不同元素**”。前者说明只关心排名边界，不要求完整排序结果；后者说明元素应按出现次数参与竞争，`Set` 会改变题意。再看返回值只有一个整数，说明完整的前 `k` 名最终也只是中间状态，答案仅需要其中的边界值。

“数组”只是输入载体，不代表一定要使用数组下标技巧。原位置不会影响大小排名，因此可以暂时忽略元素之间的相邻关系、连续区间和先后顺序。真正不能忽略的是：每来一个新数字，它有没有资格进入当前最大的 `k` 个；如果进入，应该挤掉谁。

数据范围提供了性能信号。`n <= 10^5` 允许 `O(n log n)` 排序通常通过，但题面提出了更高的严格 `O(n)` 目标。与此同时，若 `k` 很小，例如从十万个数据中找第 `10` 大，那么只维护十个候选的 `O(n log k)` 模型会非常实用；若 `k` 接近 `n` 且必须满足线性要求，则快速选择或固定值域计数更合适。模型选择必须同时看清晰度、输入是否允许修改、是否是流式数据和性能合同。

用最小非平凡样例 `[2, 1]`、`k = 1` 人工处理：先看到 `2`，当前第一大是 `2`；再看到 `1`，它不可能替代 `2`，直接忽略。再看 `[2, 3]`、`k = 1`：新来的 `3` 比当前候选 `2` 更强，于是淘汰 `2`。这里已经出现了主模型的雏形：容量固定，候选满后只比较入选门槛。

第一切入点可以记成一句话：

> 先把“求第 `k` 大”改写成“保留最大的 `k` 个”，再问新元素只需要和这 `k` 个中的谁比较。

## 5. 最直接的人工或暴力模型

最贴近日常排名的办法，是连续举行 `k` 轮“找当前最大值”：每轮扫描全部尚未使用的元素，找出最大者并标记这个出现位置已经被取走；第 `k` 轮取出的值就是答案。标记的是下标而不是数值，因此两个相等值可以在不同轮次分别被选中。

自然语言步骤如下：

1. 创建长度为 `n` 的 `used` 数组，初始都为 `false`。
2. 第 `1` 轮扫描所有未使用位置，找到最大值及其下标，将该下标标记为已使用。
3. 第 `2` 轮重新扫描所有未使用位置，再找到当前最大值。
4. 重复直到第 `k` 轮，返回这一轮找到的最大值。

例如 `[5, 5, 4]`、`k = 2`：第一轮可以取下标 `0` 的 `5`，第二轮仍能取下标 `1` 的 `5`。如果错误地按数值标记“5 已使用”，就会误答 `4`。

这个模型一定正确。第一轮选出的必然是全体第 `1` 大；假设前 `r - 1` 轮已经分别拿走了前 `r - 1` 大的出现位置，那么第 `r` 轮面对的剩余元素，其最大值正是全体第 `r` 大。按轮次归纳，第 `k` 轮得到的就是题目答案。它也说明了一个基础事实：排名可以通过逐个淘汰更大元素来定义。

设 `n = nums.length`。每轮检查 `n` 个位置，共进行 `k` 轮，所以时间复杂度是 `O(nk)`；当 `k` 与 `n` 同阶时退化为 `O(n^2)`。`used` 数组使用 `O(n)` 额外空间。也可以复制数组并把每轮最大值交换到已处理区域，但这会修改副本，仍然需要 `O(n)` 复制空间；直接改原数组则改变了调用方数据。

另一个更实用的直接模型是完整排序后返回升序下标 `n - k`。它是正确的 `O(n log n)` 基线，但它计算了所有名次。本节用逐轮扫描，是为了把“我们真正重复寻找的是什么”暴露得更清楚。

## 6. 暴力到底浪费在哪里

用 `nums = [3, 2, 1, 5, 6, 4]`、`k = 3` 观察逐轮扫描：

| 轮次 | 本轮再次检查的未使用值 | 找到的值 | 本轮结束后丢掉的中间信息 |
| ---: | --- | ---: | --- |
| 1 | 3、2、1、5、6、4 | 6 | 除了“6 最大”，没有保留 5 和 4 已经很靠前 |
| 2 | 3、2、1、5、4 | 5 | 又比较 3、2、1、4，并再次丢掉 4 的候选地位 |
| 3 | 3、2、1、4 | 4 | 第三次检查 3、2、1，才返回 4 |

值 `3、2、1` 在每一轮都被访问，却从来没有机会超过 `4、5、6`。第一次完整扫描其实已经见过所有值，但模型只留下当轮冠军 `6`，把亚军和季军的信息全部丢掉，下一轮只好重新恢复这些信息。若 `k` 很大，大量较小数字会被无意义地扫描许多次。

从候选淘汰的角度看，第一次处理完全部数据后，我们真正需要的不是每一轮冠军，而是 `[4, 5, 6]` 这个容量为三的候选集合。只要这个集合能够在扫描过程中增量维护，数组就不需要被重看。更进一步，判断新数字能否入选时，也不用把它与三位候选全部比较：只需知道候选中最小的 `4`。新数字连 `4` 都不超过，就不可能进入前三；新数字超过 `4`，就应该占据它的席位。

哪些候选可以永久消失？假设当前已经有 `k` 个数都不小于某个新数字 `x`，那么无论未来还来什么，`x` 前面已经至少有这 `k` 个出现位置。未来只会增加竞争者，不会删掉旧元素，所以 `x` 永远不可能成为全局前 `k`，可以立即丢弃。

优化目标因此可以写得很具体：

> 不要为了取出每个名次反复扫描全体元素；让每个数字只到达一次，并持续维护当前最大的 `k` 个数字以及其中最小的入选门槛。

## 7. 容易想到但走不通的方向

### 方向一：使用 `TreeSet` 保存最大的 k 个不同值

看到“有序”和“只保留 `k` 个”时，很容易想到有序集合。它能快速获得最小值，也能控制集合大小，但 `Set` 会合并相等值。对 `[5, 5, 4]`、`k = 2`，集合只留下 `{4, 5}`，门槛成为 `4`，而正确答案是 `5`。这不是性能问题，而是对象建模错误：本题排名的对象是“每次出现”，不是“不同数值”。若使用有序树，必须使用支持重复计数的多重集合，Java 标准库没有直接提供这种容器。

得到的新条件是：状态必须保留重复出现的数量。`PriorityQueue<Integer>` 可以同时保存多个相等整数，正好符合这一点。

### 方向二：完整排序后直接取下标

排序非常自然，而且完全正确。升序排序后 `nums[n - k]` 就是答案，重复值也自动保留。它的问题是为一个排名边界确定了所有元素的精确相对顺序，付出 `O(n log n)` 时间，并且对原始 `int[]` 调用 `Arrays.sort` 会修改输入。

排序不是应该被排斥的“错误解法”。当后续会查询很多不同的 `k`，一次排序后每次查询只需 `O(1)`；当调用方允许修改数组、代码简洁优先且规模可接受时，它往往最合适。它只是没有利用“只问一个边界”的信息条件。

### 方向三：把全部元素放进大顶堆，再弹出 k 次

大顶堆让当前最大值位于堆顶，因此连续弹出 `k` 次可以得到第 `k` 大。这与人工逐轮拿冠军很贴近，结果也正确。但它保存了全部 `n` 个元素，建堆需要 `O(n)`，再进行 `k` 次 `O(log n)` 删除，总时间为 `O(n + k log n)`、空间为 `O(n)`。当 `k` 很小时，它仍然为大量永远不会进入前 `k` 的小元素分配了状态。

这条路给出的新条件是：结构不应围绕“每次最快拿到全局最大”设计，而应围绕“最快判断谁配不上前 `k`”设计。后者需要访问的是入选者中最小的一个，所以堆的方向应反过来。

### 方向四：快速选择

快速选择通过分区只保留目标下标所在的一侧，随机化后期望时间 `O(n)`、迭代实现额外空间 `O(1)`，更贴合当前题面的严格性能目标。它不是走不通，而是另一条更强但状态变化更技巧化的路线：它会重排输入，最坏时间可到 `O(n^2)`，也不能自然处理一个无法一次装入内存的数据流。

本篇把它放在对照位置，是为了明确选择依据：一次性数组、允许修改、强调期望线性时间时选快速选择；输入逐个到来、不能修改、希望最坏性能可预测或希望模型更容易审计时选有界小顶堆。固定值域计数则利用 `nums[i]` 范围只有 `20001` 种这一专用条件，时间 `O(n + 20001)`、空间 `O(20001)`。

## 8. 关键视角转换

直接模型把第 `k` 大理解成“先找最大，再找第二大，直到第 `k` 轮”；新模型把它理解成“最大的 `k` 个元素形成一个动态入选区，第 `k` 大只是入选区的最低门槛”。

| 转换前 | 转换后 |
| --- | --- |
| 逐轮寻找下一个名次 | 单次扫描中维护前 `k` 名整体 |
| 每轮重新检查几乎所有元素 | 每个元素到来时只做一次资格判断 |
| 只记住本轮冠军 | 记住仍能影响答案的 `k` 个候选 |
| 关注候选中的最大值 | 关注候选中最容易被替换的最小值 |
| 最后第 `k` 次取值才产生答案 | 扫描结束后，当前门槛直接就是答案 |

为什么新视角减少重复？处理完某个前缀后，模型没有丢掉“谁属于这个前缀的前 `k` 名”。下一个数字到来时，只会出现两种情况：它不超过门槛，前 `k` 名的数值集合无需变化；它超过门槛，就用它替换当前最弱候选。旧前缀中的其余数字已经有明确淘汰证明，不需要再次扫描。

> **小白追问：** 为什么只保留最大的 `k` 个，而不是把所有看过的数字留下，等最后再决定？
>
> **先给短答：** 因为一旦某个值前面已经有 `k` 个不小于它的值，未来新增元素不可能让它的名次变好。
>
> **最小例子：** `k = 2`，已处理 `[6, 4, 1]`。值 `1` 前面已有 `6` 和 `4`，所以它最多排第 `3`。以后再来一个 `0`，`1` 仍排在前两名之外；以后来一个 `7`，`1` 只会再后退。留下 `1` 不会帮助判断第 `2` 大。
>
> **回到模型/代码：** `largestK` 的容量上限是 `k`。未进入它或从它被 `poll()` 淘汰的值不再保存，因为不变量已经给这些值提供了至少 `k` 个“不小于它”的见证。

还要继续追问：为了支持这种更新，候选集需要哪些操作？容量未满时加入；容量满时读取最小候选；新数字更大时删除最小候选并加入新数字；最终再次读取最小候选。我们不需要频繁读取最大值，也不需要让所有候选保持完整排序。到这里，状态和操作已经推导完成，才适合给容器命名：一个容量受控、最小值位于顶部的优先队列，也就是有界小顶堆。

> **小白追问：** 候选有 `k` 个，为什么新值只和最小候选比较，不需要逐个比较？
>
> **先给短答：** 最小候选是进入前 `k` 名必须跨过的最低门槛；跨不过它，就更不可能跨过其余更大的候选。
>
> **最小例子：** `k = 2`，候选是 `[4, 7]`。新值 `3` 连 `4` 都不超过，不可能挤掉 `7`；新值 `6` 超过 `4`，便应得到前两名中的一个席位，候选变为 `[6, 7]`。两种情况都只需要先看 `4`。
>
> **回到模型/代码：** 满员后，资格判断就是 `currentValue > largestK.peek()`。`peek()` 给出最低门槛；只有条件成立，才执行一次 `poll()` 和一次 `offer()`。

这个转换的核心不是“堆比排序高级”，而是先缩小保存范围，再选择能便宜维护边界的结构。即使换成别的语言或手写二叉堆，模型仍然成立。

## 9. 正式建立模型

从左到右处理数组。设已经处理了前 `i` 个元素，状态 `largestK` 满足下面的不变量：当 `i < k` 时，它保存这 `i` 个元素的全部出现；当 `i >= k` 时，它保存这 `i` 个元素中数值最大的 `k` 个出现。若有相等值，可以保存任意身份的相等出现，因为题目只返回数值。

| 建模项 | 本题结论 |
| --- | --- |
| 对象 | 当前读到的一个整数出现，以及最多 `k` 个仍有资格影响答案的出现 |
| 关系 | 当前值是否大于前 `k` 名中的最小值，即是否越过入选门槛 |
| 状态 | 容量不超过 `k` 的候选集合，顶部始终是候选中的最小值 |
| 事件 | 读到新值；容量未满则加入，容量已满且新值越过门槛则替换顶部 |
| 不变量 | 每步结束后，候选集合保存已处理前缀中最大的 `min(k, 已处理数量)` 个值 |
| 结果时机 | 全部元素处理完后，候选数恰为 `k`，顶部最小值就是全局第 `k` 大 |

这里的“不变量”不是一个额外的数据。它是一句每轮处理结束后都必须为真的承诺，用来检查状态有没有维护错：`largestK` 里究竟应该有哪些值，不能由堆碰巧留下什么来决定。

> **小白追问：** 为什么候选还没满时必须无条件加入？很小的数看起来明明迟早会被淘汰。
>
> **先给短答：** 在看够 `k` 个元素以前，“第 `k` 大”还没有形成，任何值都暂时没有足够的对手证明自己出局。
>
> **最小例子：** `k = 2`，目前只看到 `[9]`，再来 `1`。虽然 `1` 很小，但当前一共只有两个数，`1` 就是当前第 `2` 大。若因为它小而拒绝，候选只剩 `[9]`，此时根本没有第二名可返回。
>
> **回到模型/代码：** `largestK.size() < k` 必须排在门槛比较之前，并直接执行 `offer(currentValue)`。只有 `size() == k` 时，`peek()` 才具有“第 `k` 名门槛”的含义。

### 为什么状态足够

容量满后，所有被丢弃的值都至少被当前 `k` 个候选压在后面。未来到来的值只可能进一步挤压它们，不可能让它们排名上升。因此未来更新只依赖当前前 `k` 名及其中最小值，不依赖淘汰者、原下标或淘汰历史。

候选集内部不需要完整排序。我们只需知道谁是最小候选来做替换，最终也只返回这个最小候选。其余 `k - 1` 个值相互谁更大，在当前动作中没有区别。保留它们是因为后续可能连续来多个更大的数字，门槛逐步上升时，它们可能成为新的最小候选。

### 三种更新事件

```text
事件 A：候选数 < k
动作：无条件加入当前值。
原因：前缀元素还不足 k 个，没有任何出现可以被排除在前 k 名之外。

事件 B：候选数 = k，当前值 <= 顶部门槛
动作：忽略当前值。
原因：已有 k 个候选都 >= 门槛 >= 当前值，它不可能进入前 k 名。

事件 C：候选数 = k，当前值 > 顶部门槛
动作：删除顶部，再加入当前值。
原因：当前值应入选，而旧顶部是现有候选中唯一最应该让出的席位。
```

> **小白追问：** 新值越过门槛时，为什么只淘汰一个堆顶，不能淘汰更多候选？
>
> **先给短答：** 一个新元素只新增一个排名位置，因此它只会把原前 `k` 名中的一个元素挤到第 `k + 1` 名。
>
> **最小例子：** `k = 2`，候选为 `[4, 7]`，新值是 `6`。新的前两名应是 `[6, 7]`，只需让 `4` 出局。若连 `7` 也删除，候选只剩 `6`，便丢掉了真正的第一名。
>
> **回到模型/代码：** 替换分支严格执行一次 `largestK.poll()`，紧接一次 `largestK.offer(currentValue)`。这组顺序让满员状态从 `k` 暂时变成 `k - 1`，再恢复为 `k`。

先删后加与先加后删最小值在结果上等价。本文使用“满且越过门槛才替换”，因为它直接呈现资格判断，并让未入选元素不进入结构。

### 相等值怎样处理

当 `currentValue == largestK.peek()` 时，可以直接忽略。假设门槛是 `5`，候选中已经有一个值为 `5`，新来的也是 `5`。替换旧 `5` 只会改变出现位置身份，不会改变候选的数值多重集合，更不会改变最终返回值。本题不要求返回具体下标，所以忽略是安全的。如果业务要求稳定保留更早或更新的记录，则候选元素必须保存“值 + 身份”，相等时再定义业务规则。

> **小白追问：** 题目说重复值要参与排名，为什么等于门槛的新值又可以忽略？
>
> **先给短答：** 重复值在填满 `k` 个席位前必须分别进入；席位满后，用一个相等值替换另一个相等值不会改变数值排名。
>
> **最小例子：** `[5, 5, 4]`、`k = 2`。前两个 `5` 到来时容量未满，它们都进入候选，形成 `[5, 5]`，所以第 `2` 大是 `5`。如果此时再来第三个 `5`，忽略它后仍有两个 `5`；若替换其中一个，候选数值也仍是 `[5, 5]`。
>
> **回到模型/代码：** 是否接纳重复值先由 `largestK.size() < k` 决定。满员后代码使用严格条件 `currentValue > largestK.peek()`；相等时不替换，只省去一次没有数值效果的操作。

遍历方向选择从左向右，只是为了让每个输入发生一次到达事件；由于排名与原顺序无关，从右向左也能维护同样不变量。对真正的数据流，只有到达顺序而没有随机访问，左到右模型仍然可以工作，这也是它比原地分区更通用的原因。

## 10. 所需数据结构详解

### 10.1 模型需要的操作

候选容器必须支持四件事：加入一个值、读取最小值、删除最小值、限制最多保存 `k` 个值。读取门槛会对几乎每个后续元素发生，因此应接近常数时间；加入和删除可以稍贵，但不应扫描全部候选。

### 10.2 小顶二叉堆怎样组织数据

小顶二叉堆是一棵完全二叉树，并保持“每个父节点不大于自己的孩子”。所以整棵树的最小值一定在根节点。它只保证父子方向的局部有序，不保证同层有序，也不保证按数组迭代时得到排序序列。

完全二叉树可以紧凑地存进数组。若某节点下标为 `i`：

```text
父节点下标：      (i - 1) / 2
左孩子下标：      2 * i + 1
右孩子下标：      2 * i + 2

示意：
              heap[0]          <- 全局最小值 / 入选门槛
             /       \
        heap[1]      heap[2]
        /    \        /    \
   heap[3] heap[4] heap[5] heap[6]
```

加入元素时，先放到数组末尾，再沿父节点方向上浮，直到父节点不大于它；删除根时，用最后一个元素填到根，再沿较小孩子方向下沉。堆高为 `O(log k)`，所以上浮和下沉最多经过 `O(log k)` 层。

### 10.3 本题各操作的成本

| 操作 | Java 调用 | 单次复杂度 | 本题作用 |
| --- | --- | --- | --- |
| 读取最小值 | `peek()` | `O(1)` | 查看当前入选门槛 |
| 加入候选 | `offer(value)` | `O(log k)` | 容量未满时入选，或替换后加入 |
| 删除最小值 | `poll()` | `O(log k)` | 给越过门槛的新值腾出席位 |
| 查询数量 | `size()` | `O(1)` | 判断候选是否已经满员 |

Java 的 `PriorityQueue<Integer>` 默认按自然顺序把最小整数放在顶部，因此正好是小顶堆。它本身不会自动限制容量；构造参数 `new PriorityQueue<>(k)` 只是初始容量提示，不是上限。真正的“有界”来自算法每次替换前后的 `size` 规则。

> **小白追问：** 求的是第 `k` 大，为什么反而使用小顶堆，不使用更符合“大”字的大顶堆？
>
> **先给短答：** 我们需要反复找到的是“前 `k` 名里最弱、下一次最可能被替换的人”，而不是最强的人。
>
> **最小例子：** `k = 2`，当前候选是 `[9, 6]`，新值为 `7`。应被淘汰的是 `6`，候选变成 `[9, 7]`。小顶堆顶部直接给出 `6`；大顶堆顶部给出 `9`，它恰恰是最不该删除的值。
>
> **回到模型/代码：** 默认的 `PriorityQueue<Integer>` 让 `peek()` 和 `poll()` 都指向最小候选。若改成大顶堆，现有的比较条件与删除动作就不再维护 `largestK` 不变量。

容器中保存的是整数值，不保存下标。重复值可以重复入堆，最坏保存恰好 `k` 个 `Integer`。如果题目改为返回元素身份、原位置或关联业务记录，就应保存复合对象，并提供按排名字段比较的 `Comparator`。

### 10.4 为什么替代结构不够贴合

- 无序数组保存 `k` 个候选，加入是 `O(1)`，但每次找门槛需要 `O(k)`；总时间会到 `O(nk)`。
- 始终有序的数组读取门槛是 `O(1)`，但插入新值需要移动最多 `k` 个元素，仍是 `O(nk)`。
- 平衡搜索树能用 `O(log k)` 更新并读取最小值，但要额外解决重复计数，接口和常数更复杂。
- 大顶堆优化的是“取最大”，而本模型每次需要淘汰候选中的最小值，方向不匹配。

小顶堆并不是因为题目标签写了 Heap 才出现，而是因为模型已经要求“高频读最小值，偶尔删除最小值和加入新值，并且无需完整排序”。结构特征恰好匹配这些动作。

## 11. 生活化类比及边界

把过程想成一场只设 `k` 个晋级席位的资格赛。选手分数逐个登记，晋级区门口的显示牌始终显示当前晋级者中的最低分。

候选不足 `k` 人时，新选手直接进入。满员后，新分数如果不高于显示牌，就无法改变晋级分数集合；如果高于显示牌，最低分选手离场，新选手入场。所有人登记完后，显示牌上的最低晋级分正是全体第 `k` 高分。

| 生活对象或动作 | 算法中的对应物 |
| --- | --- |
| 逐个登记的选手分数 | 从左到右读到的 `currentValue` |
| 只有 `k` 个席位的晋级区 | 容量不超过 `k` 的 `largestK` |
| 门口最低晋级分显示牌 | `largestK.peek()` 返回的小顶堆根 |
| 席位未满直接入场 | `largestK.size() < k` 时 `offer` |
| 新分数高于显示牌 | `currentValue > largestK.peek()` |
| 最低分离场、新人入场 | `poll()` 后 `offer(currentValue)` |
| 登记结束时的显示分 | 数组的第 `k` 大元素 |
| 两名同分选手 | 两次相等的元素出现，排名中都占席位 |

这个类比最有价值的地方，是解释为什么门口只需显示“晋级者中的最低分”，不需要把全部选手实时排成完整名次。它也解释了淘汰的单向性：一名选手没能超过当前门槛，后面新增选手只可能让竞争更激烈，不会让他的排名变好。

类比到这里为止。现实比赛可能有报名撤回、并列晋级、复议、按时间破同分和固定录取身份等规则，本题都没有。算法只返回数值，不返回哪位同分选手入选；因此相等于门槛的新出现可以被忽略。若输入支持删除旧元素，门槛可能下降，当前“永久淘汰”证明就失效，需要双堆、计数树或其他可删除结构。

## 12. 典型输入的完整数据变化图

完整演算 `nums = [3, 2, 3, 1, 2, 4, 5, 5, 6]`、`k = 4`。为了让读者核对候选内容，下面把堆快照写成从小到大的“概念视图”，竖线左侧是堆顶门槛；Java `PriorityQueue` 的实际内部数组只保证父节点不大于孩子，并不承诺剩余部分按此顺序排列。

```text
输入方向：左 -> 右

下标：  0  1  2  3  4  5  6  7  8
数值：  3  2  3  1  2  4  5  5  6
        ^
        当前处理位置逐步右移

堆概念快照格式：[门槛 | 其他候选]
```

| 步骤 | 当前输入 | 处理前状态 | 判断依据 | 执行动作 | 处理后状态 | 本步结果 |
| ---: | ---: | --- | --- | --- | --- | --- |
| 1 | 3 | `[]` | 候选数 `0 < 4` | 加入 3 | `[3]` | 尚不足 4 人，无正式门槛 |
| 2 | 2 | `[3]` | 候选数 `1 < 4` | 加入 2 | `[2 \| 3]` | 尚不足 4 人 |
| 3 | 3 | `[2 \| 3]` | 候选数 `2 < 4` | 加入 3 | `[2 \| 3, 3]` | 重复值按一次出现加入 |
| 4 | 1 | `[2 \| 3, 3]` | 候选数 `3 < 4` | 加入 1 | `[1 \| 2, 3, 3]` | 首次满员，门槛为 1 |
| 5 | 2 | `[1 \| 2, 3, 3]` | `2 > 1` | 删除 1，加入 2 | `[2 \| 2, 3, 3]` | 门槛升到 2 |
| 6 | 4 | `[2 \| 2, 3, 3]` | `4 > 2` | 删除一个 2，加入 4 | `[2 \| 3, 3, 4]` | 仍有另一个 2，门槛仍为 2 |
| 7 | 5 | `[2 \| 3, 3, 4]` | `5 > 2` | 删除 2，加入 5 | `[3 \| 3, 4, 5]` | 门槛升到 3 |
| 8 | 5 | `[3 \| 3, 4, 5]` | `5 > 3` | 删除一个 3，加入 5 | `[3 \| 4, 5, 5]` | 第二个 5 独立占席位 |
| 9 | 6 | `[3 \| 4, 5, 5]` | `6 > 3` | 删除 3，加入 6 | `[4 \| 5, 5, 6]` | 扫描结束，门槛为 4 |

把第 5 步和第 8 步展开看，能看到模型最关键的两次变化：

```text
第 5 步，当前值 2：

处理前候选                 新值
      1 <- 最弱门槛          2
     / \
    2   3
   /
  3

2 越过门槛 1
=> 1 永久出局
=> 2 入选
=> 新候选数值为 [2, 2, 3, 3]

第 8 步，当前值 5：

处理前候选数值 [3, 3, 4, 5]
新值 5 > 门槛 3
=> 只删除一个 3
=> 新来的 5 与原来的 5 都保留
=> 新候选数值 [3, 4, 5, 5]
```

每一步稳定后，表中的候选恰好是当前前缀最大的 `min(4, 前缀长度)` 个值。最终候选 `[4, 5, 5, 6]` 不必真正按降序排好；只要顶部能告诉我们其中最小的 `4`，答案就已经产生。

## 13. 边界场景的数据变化

### 场景一：全部或部分相等，重复值不能去重

处理 `nums = [5, 5, 4]`、`k = 2`：

```text
初始：[]

读 5：容量未满
      [] -> [5]

读 5：容量仍未满
      [5] -> [5 | 5]
      两个 5 分别占一个排名位置

读 4：候选已满，4 <= 门槛 5
      [5 | 5] -> [5 | 5]
      4 被永久忽略

结束：堆顶 5，第 2 大为 5
```

如果误用 `Set`，第二个 `5` 无法进入，便会得到错误的 `[4, 5]`。有界堆中允许重复值，所以无需额外分支。

### 场景二：k 等于 1，模型退化为维护最大值

处理 `nums = [-1, -3, -2]`、`k = 1`：

```text
读 -1：[] -> [-1]
读 -3：-3 <= -1，忽略，仍为 [-1]
读 -2：-2 <= -1，忽略，仍为 [-1]
结束：堆顶 -1
```

这也说明不能把 `0` 当默认候选。所有输入都可能为负数，正确初始状态是空堆，而不是装入一个人为的零。

### 场景三：k 等于 n，所有元素都必须保留

处理 `nums = [2, 1, 2]`、`k = 3`：

```text
读 2：[2]
读 1：[1 | 2]
读 2：[1 | 2, 2]
循环结束，容量刚好第一次满员；没有发生任何淘汰。
堆顶 1 = 全体最小值 = 第 3 大。
```

数组不可能为空，且 `1 <= k <= n`，所以循环至少执行一次，最终堆一定包含 `k` 个值，`peek()` 不会返回 `null`。题目也不存在无答案场景。若把这个模型迁移到未校验的业务输入，方法入口应先拒绝空数组、`k <= 0` 或 `k > n`，而不是让拆箱空值时才报错。

## 14. 正确性与不变量

证明对象是第 9 节的不变量：处理任意长度前缀后，堆保存这个前缀中最大的 `min(k, 前缀长度)` 个元素出现。我们用逐步处理来说明它始终成立。

### 初始状态

还没有读取元素时，已处理前缀为空，堆也为空。它确实保存空前缀中最大的零个元素，所以不变量成立。

### 容量未满时为什么直接加入

假设当前已经处理 `i < k` 个元素，堆保存它们全部。新元素到来后，前缀共有 `i + 1 <= k` 个元素。所谓最大的 `i + 1` 个就是全部元素，因此把新值加入后，不变量继续成立。此时不能淘汰任何值，因为最终 `k` 个排名席位还没有填满。

### 容量已满且新值不越过门槛

假设堆已保存旧前缀最大的 `k` 个值，堆顶 `threshold` 是这 `k` 个中的最小值。如果新值 `x <= threshold`，堆中已有 `k` 个值都满足 `candidate >= threshold >= x`。因此在加入 `x` 后的新前缀里，至少已有 `k` 个出现不小于 `x`；`x` 无需占据前 `k` 名。

继续保留原堆不会漏掉更优答案。若 `x < threshold`，它严格排在这 `k` 个候选之后；若 `x == threshold`，用新 `x` 替换旧门槛只会交换两个相同值的身份，候选数值多重集合和答案都不变。因为未来只增加元素，已经落在前 `k` 名之外的 `x` 以后也不可能重新上升，可以永久删除。

> **小白追问：** 一个现在被忽略的小值，为什么以后绝对没有机会重新进入前 `k` 名？
>
> **先给短答：** 本题只会新增元素，不会删除已经排在它前面的元素，所以它前方已有的 `k` 个见证永远存在。
>
> **最小例子：** `k = 2`，候选是 `[4, 8]`，当前值是 `3`。此时 `4` 和 `8` 已经同时不小于 `3`。未来若来 `2`，`3` 仍排在二者之后；若来 `9`，`3` 只会再后退。不存在一种新增值能把 `4` 或 `8` 从历史中删掉。
>
> **回到模型/代码：** 当 `currentValue > largestK.peek()` 为假时，代码不保存 `currentValue`。这个丢弃依赖“输入只有到达、没有过期或撤回”的前提；滑动窗口场景不能直接复用该分支。

### 容量已满且新值越过门槛

若 `x > threshold`，新值一定应该进入新前缀的前 `k` 名。原来的 `k` 个候选里，门槛是最小者；保留其余 `k - 1` 个较大候选，再加入 `x`，恰好得到新的 `k` 个最大值。删除别的更大候选反而可能留下更小的门槛，所以删除堆顶是唯一符合数值排名的淘汰动作。

旧前缀中不在堆里的值都不大于旧门槛，它们也不可能击败新来的 `x` 或其余候选，因此无需重新考虑。执行 `poll` 和 `offer` 后，不变量恢复。

### 结束时为什么堆顶就是答案

由于 `k <= n`，全部 `n` 个元素处理完后，堆中恰好有 `k` 个元素。根据不变量，它们是全数组最大的 `k` 个出现。小顶堆根是这 `k` 个值中的最小者，也就是从大到小排列时位于第 `k` 个位置的值。所有输入都已处理，所有被淘汰值都有至少 `k` 个不小于它的见证，因此既不会漏掉更大的候选，也不会留下不够资格的候选。

> **小白追问：** 最终堆顶为什么恰好是第 `k` 大，而不只是“一个比较小的入选值”？
>
> **先给短答：** 堆中恰好保留全体最大的 `k` 个值，堆顶又是这 `k` 个值中最小的，所以它正好站在降序第 `k` 个位置。
>
> **最小例子：** `[8, 3, 6]`、`k = 2` 处理结束后，候选是 `[6, 8]`。`8` 是第 `1` 大，`6` 是第 `2` 大，堆顶为 `6`。被排除的 `3` 不可能比门槛更靠前。
>
> **回到模型/代码：** 循环维持“保存当前前 `k` 名”的不变量；官方约束保证最终 `largestK.size() == k`；因此返回 `largestK.peek()` 同时使用了候选内容、容量和小顶方向三个条件。

算法会终止，因为外层只遍历长度为 `n` 的数组；每次堆调整都沿有限高度的父子路径移动，堆容量不超过 `k`。

## 15. 时间与空间复杂度推导

先定义变量：`n` 表示数组长度，`k` 表示要求的排名以及候选容量，`R` 表示可能数值的种类范围。本题固定值域下 `R = 20001`。

### 15.1 逐轮扫描模型

人工暴力进行 `k` 轮，每轮检查 `n` 个位置并用 `used` 跳过已选位置。即使跳过只花常数时间，也仍会访问该位置，所以总检查次数是 `n * k`，时间复杂度为 `O(nk)`；最坏 `k = n` 时为 `O(n^2)`。`used` 数组长度为 `n`，额外空间 `O(n)`。

### 15.2 完整排序模型

比较排序通常需要 `O(n log n)` 时间，之后按下标取值是 `O(1)`。额外空间取决于排序实现；对 Java 原生基本类型数组，排序会修改输入。若为了保留输入先复制数组，则副本明确占用 `O(n)` 空间。排序适合一次整理后进行多次排名查询。

### 15.3 有界小顶堆模型

外层恰好读取 `n` 个元素。读取 `size` 和 `peek` 都是 `O(1)`。一个元素的生命周期只有以下几种：

```text
未入选：到达 -> 与门槛比较 -> 永久丢弃
初始入选：到达 -> offer -> 可能以后成为门槛 -> 至多 poll 一次
替换入选：到达 -> 越过门槛 -> offer -> 可能以后至多 poll 一次
```

每个输入元素最多入堆一次；一个已经入堆的元素最多出堆一次。入堆上浮和出堆下沉各自最多经过堆高 `log k`，所以所有堆调整总成本至多是常数倍的 `n log k`。即使代码在某轮同时执行一次 `poll` 和一次 `offer`，也只是两个 `O(log k)` 操作，不会变成平方复杂度。最坏时间复杂度为 `O(n log k)`。

堆最多保存 `k` 个整数，额外空间为 `O(k)`。返回值是一个整数，不另计输出集合。该模型不递归，没有递归栈，也不修改 `nums`。当 `k = 1` 时，`log k` 可视为常数，模型退化为一次线性扫描；当 `k` 接近 `n` 时，时间接近 `O(n log n)`。

> **小白追问：** 外层只有一次扫描，为什么时间不是 `O(n)`，而是 `O(n log k)`？
>
> **先给短答：** “读到一个元素”是常数次事件，但入堆或替换时还要沿最多 `log k` 层恢复堆的父子顺序。
>
> **最小例子：** `[4, 1, 3]`、`k = 2`。前两个值各执行一次 `offer`；读到 `3` 时又执行一次 `poll` 和一次 `offer`。候选只有两层以内，调整很短；若 `k` 继续增长，堆高也会增长，不能把这部分统一当成常数。
>
> **回到模型/代码：** `for` 循环执行 `n` 次；其中 `size()`、`peek()` 是 `O(1)`，`offer()`、`poll()` 是 `O(log k)`。最坏每轮做常数个堆调整，因此总上界为 `O(n log k)`，不是嵌套循环推出来的平方复杂度。

### 15.4 快速选择与固定值域计数

随机化快速选择每轮对当前区间做线性分区，并只继续目标所在一侧，期望时间 `O(n)`、迭代实现额外空间 `O(1)`，但最坏连续选到极端枢轴时是 `O(n^2)`，而且会重排输入。它是标准题解选择的主方案，也是严格追求题面线性目标时更通用的答案。

计数模型先用长度 `R` 的数组统计每个值的出现次数，再从最大值向下累计直到覆盖第 `k` 个出现，时间 `O(n + R)`、空间 `O(R)`。对本题 `R = 20001` 是固定常数，因此随 `n` 增长可视为线性；但若值域扩大到任意 32 位整数，`R` 会变得不可接受。有界堆的价值在于不依赖值域，且可在线处理。

> **小白追问：** 题面明确要求 `O(n)`，主代码却是 `O(n log k)`，这算不算没有完成题目？
>
> **先给短答：** 若 `O(n)` 是必须履行的评审合同，就应换用快速选择或本题固定值域计数；本文选择堆，是为了完整讲透更直观且可流式迁移的模型。
>
> **最小例子：** `[4, 1, 3]`、`k = 2` 可以一边到达一边更新两个候选，堆无需改动原数组。快速选择则要在这三个数组位置之间做分区和交换，适合数据已经完整装入数组的场景。两者答案相同，但输入条件和性能承诺不同。
>
> **回到模型/代码：** 当前 `Solution` 的明确合同是最坏 `O(n log k)`、空间 `O(k)`、不修改 `nums`。取舍表中的“随机快速选择”对应期望 `O(n)`；“固定值域计数”对应 `O(n + R)`。不能把三者的复杂度混写成同一个结论。

| 模型 | 时间 | 额外空间 | 修改输入 | 流式可用 | 主要适用场景 |
| --- | --- | --- | --- | --- | --- |
| 逐轮找最大 | `O(nk)` | `O(n)` | 可避免 | 否 | 建立正确性起点 |
| 完整排序 | `O(n log n)` | 取决于实现/副本 | 通常是 | 否 | 多次排名查询 |
| 有界小顶堆 | `O(n log k)` | `O(k)` | 否 | 是 | 小 `k`、不改输入、持续数据 |
| 随机快速选择 | 期望 `O(n)`，最坏 `O(n^2)` | 迭代 `O(1)` | 是 | 否 | 单次数组查询、强调期望线性 |
| 固定值域计数 | `O(n + R)` | `O(R)` | 否 | 可增量计数 | 值域很小且已知 |

### 第一层：有界优胜候选集骨架

下面的骨架把“容量、排序规则、入选门槛”提炼成一个可复用组件。它可以保存整数，也可以保存带业务字段的对象。`ordering` 定义谁更强；小顶优先队列让当前保留对象中最弱的一个位于顶部。所有调用都已定义，代码语法完整。

```java
import java.util.Comparator;
import java.util.PriorityQueue;

final class BoundedLargestCandidates<T> {
    private final int capacity;
    private final Comparator<? super T> ordering;
    private final PriorityQueue<T> selected;

    BoundedLargestCandidates(int capacity, Comparator<? super T> ordering) {
        if (capacity <= 0) {
            throw new IllegalArgumentException("capacity must be positive");
        }
        this.capacity = capacity;
        this.ordering = ordering;
        this.selected = new PriorityQueue<>(capacity, ordering);
    }

    void consider(T currentCandidate) {
        if (selected.size() < capacity) {
            selected.offer(currentCandidate);
            return;
        }

        T currentThreshold = selected.peek();
        if (ordering.compare(currentCandidate, currentThreshold) > 0) {
            selected.poll();
            selected.offer(currentCandidate);
        }
    }

    boolean isFull() {
        return selected.size() == capacity;
    }

    T threshold() {
        if (!isFull()) {
            throw new IllegalStateException("not enough candidates");
        }
        return selected.peek();
    }
}
```

`consider` 对应一个新对象到达事件；`selected.size() < capacity` 对应席位尚未填满；`ordering.compare(currentCandidate, currentThreshold) > 0` 表示新对象严格越过当前门槛；`threshold()` 只有满员后才有排名语义。若业务需要在同分时按时间或编号决定身份，应把第二排序字段写入 `Comparator`，而不是偷偷改成 `>=`。

> **小白追问：** 为什么泛用骨架的 `threshold()` 在未满时直接报错，不能先返回当前堆顶？
>
> **先给短答：** 未满时的最小候选只是“目前见过的最小值”，还不是容量为 `k` 的入选边界，提前返回会给它错误的业务含义。
>
> **最小例子：** 容量为 `2`，目前只收到 `[8]`。堆顶虽然是 `8`，但第二大还不存在；下一项若是 `3`，真正门槛会变成 `3`。在只看到一个元素时把 `8` 当第 `2` 大，结论没有定义。
>
> **回到模型/代码：** `isFull()` 对应“排名席位已经形成”的前提。`threshold()` 先检查它；题目专用代码则依赖 `1 <= k <= nums.length`，在完整循环结束后才调用 `largestK.peek()` 返回答案。

### LeetCode 可直接提交代码

```java
import java.util.PriorityQueue;

class Solution {
    public int findKthLargest(int[] nums, int k) {
        PriorityQueue<Integer> largestK = new PriorityQueue<>(k);

        for (int currentValue : nums) {
            if (largestK.size() < k) {
                largestK.offer(currentValue);
            } else if (currentValue > largestK.peek()) {
                largestK.poll();
                largestK.offer(currentValue);
            }
        }

        return largestK.peek();
    }
}
```

代码角色与模型一一对应：

| 模型角色 | Java 变量或代码块 |
| --- | --- |
| 当前到达对象 | `currentValue` |
| 最大的 `k` 个候选 | `largestK` |
| 容量未满事件 | `largestK.size() < k` |
| 当前入选门槛 | `largestK.peek()` |
| 越过门槛 | `currentValue > largestK.peek()` |
| 淘汰最弱候选 | `largestK.poll()` |
| 接纳新候选 | `largestK.offer(currentValue)` |
| 最终结果时机 | 循环结束后返回 `largestK.peek()` |

## 17. 边界、常见错误与调试观察点

| 层次 | 常见错误 | 后果 | 应观察的状态 |
| --- | --- | --- | --- |
| 建模错误 | 把第 `k` 大理解成第 `k` 个不同值 | 重复值样例错误 | 每个相等值是否分别占一个堆元素 |
| 建模错误 | 用大顶堆但仍只保存 `k` 个最大候选 | 顶部是最大值，不是第 `k` 大门槛 | 堆顶到底代表最强还是最弱入选者 |
| 建模错误 | 候选未满就开始比较并淘汰 | 最终不足 `k` 个，排名无定义 | 每步后的 `size` 是否为 `min(k, 已处理数)` |
| 条件错误 | 将 `size() < k` 写成 `size() <= k` | 堆可能保存 `k + 1` 个，门槛错位 | 每步后打印堆大小 |
| 条件错误 | 遇到更大值只 `offer`，忘记 `poll` | 容量持续增长，顶部不再表示第 `k` 大 | 更新前后容量是否都为 `k` |
| 条件错误 | 无论大小都先删除门槛 | 小值也会挤掉合格候选 | 记录 `currentValue` 与更新前 `peek` |
| 实现错误 | 认为构造器参数 `k` 会自动限容 | `PriorityQueue` 实际可以继续增长 | 每轮断言 `largestK.size() <= k` |
| 实现错误 | 遍历或打印堆时认为结果全局有序 | 根据错误顺序调试出错误结论 | 只信任 `peek`，核对内容时另行排序副本 |
| 实现错误 | 用 `0` 作为初始门槛 | 全负数组被误判 | 空状态应由 `size` 表达，不用数值哨兵 |
| 性能误判 | 声称有界堆严格是 `O(n)` | 当 `k` 增长时忽略 `log k` | 同时打印或记录 `n`、`k`，写清性能合同 |

最有效的调试日志不是打印一句“进入循环”，而是每轮输出以下快照：

```text
index=<当前下标>
current=<当前值>
beforeSize=<更新前数量>
beforeThreshold=<未满时记为 N/A，满时记录 peek>
action=FILL / REPLACE / DISCARD
afterSize=<更新后数量>
afterThreshold=<满时记录新的 peek>
```

还可以在测试环境把堆复制为列表并排序，仅用于验证不变量：处理完下标 `i` 后，将数组前缀复制并降序排序，取前 `min(k, i + 1)` 个，与堆中元素按多重集合比较。不要把这种昂贵校验放进提交代码。

建议重点测试：`k = 1`、`k = n`、单元素、全部相等、含多个门槛相等值、严格递增、严格递减、全负数，以及新值连续多次替换门槛。若业务输入不受题目约束，还要测试空数组和非法 `k` 能否被清楚拒绝。

最后需要分清“代码正确”和“满足指定复杂度”是两件事。本篇堆代码能正确通过常见判题并有稳定的 `O(n log k)` 上界，但当前题面明确写了 `O(n)` 目标；若评审把这个目标作为硬性合同，应切换到随机化快速选择或固定值域计数，而不是修改复杂度描述。

## 18. 最终模型卡

| 卡片项 | 结论 |
| --- | --- |
| 识别指纹 | 只问一个排名边界；允许重复；不要求完整排序；数据可能逐个到来或不能修改输入 |
| 一句话关系模型 | 第 `k` 大等于全体最大的 `k` 个出现中最小的那个值 |
| 实际保存什么 | 当前已处理前缀中最大的 `min(k, 已处理数)` 个值 |
| 状态何时变化 | 未满时直接加入；满员且新值严格大于门槛时替换顶部 |
| 答案何时产生 | 所有元素处理完后读取小顶堆顶部 |
| 核心不变量 | 每一步后，堆恰好代表当前前缀应保留的前 `k` 个数值出现 |
| 淘汰依据 | 已有 `k` 个值不小于当前值时，当前值以后不可能进入全局前 `k` |
| 时间复杂度 | 有界堆 `O(n log k)`；严格线性目标可改用期望 `O(n)` 快速选择 |
| 空间复杂度 | 有界堆 `O(k)`，不计输入数组 |

**四句建模结论：**

```text
我正在处理的对象是：数组中逐个到来的整数出现，包括重复出现。
我必须持续保存的是：当前前缀里最大的 k 个值，以及它们中最小的入选门槛。
当候选未满或新值越过门槛时，我执行：直接加入，或淘汰旧门槛后接纳新值。
答案在全部输入处理结束时由小顶堆顶部的最低入选值计算出来。
```

**泛用模板：**

```text
确定排名对象是否按出现次数计算
-> 把第 k 名改写成“保留一侧的 k 个对象”
-> 找到这 k 个对象中最容易被替换的边界
-> 新对象到来时，只和边界做资格判断
-> 证明被拒绝对象以后不会重新获得资格
-> 选择能高效读取并替换该边界的数据结构
```

**迁移变式：**

1. **数据流中的第 K 大元素（LeetCode 703）**：条件从一次性数组变为持续调用 `add`，状态不变，答案时机改为每次加入后立即返回堆顶。有界堆在这个场景比快速选择更自然。
2. **最小的 k 个数**：保留方向相反，维护容量为 `k` 的大顶堆；门槛变成当前入选者中的最大值，新值更小时替换。
3. **前 K 个高频元素（LeetCode 347）**：对象先从原始值转换成“值及其频次”，候选比较字段由数值改为频次；结果需要输出整个候选集合，而不只是门槛。
4. **滑动窗口第 K 大**：条件增加旧元素过期事件，原先“淘汰后永不回来”的单向性失效；状态必须支持按身份删除，通常需要有序多重集合、双堆加延迟删除或计数树。

复习时不要只记“小顶堆求第 `k` 大”。真正可迁移的结论是：当答案是一个入选边界时，先证明只保留有限候选足够，再让数据结构围绕“最容易被替换者”提供高效访问。
