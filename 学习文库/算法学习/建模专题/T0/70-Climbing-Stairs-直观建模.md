# 70. 爬楼梯：从枚举完整走法到结算最后一步

> **双轨入口：** [[题目/动态规划/70-Climbing-Stairs.md|标准题解]] · [[核心模型/动态规划/70-Climbing-Stairs-核心模型.md|核心模型]]

本篇重点解决四个常见困难：为什么能把完整路线压缩成一个计数；`dp[i]` 究竟表示什么；为什么 `dp[0]` 应设为 `1` 而不是 `0`；以及只保留两个变量后，如何确认它们没有在更新时错位。这里不会把“楼梯题等于斐波那契”作为起点，因为知道数列名字并不能帮助我们在下一道陌生题里重新建立模型。

## 2. 完整题目

有一段共 `n` 阶的楼梯，从楼梯下面的起点出发，恰好到达第 `n` 阶就算到达楼顶。每次只能向上走 `1` 阶或 `2` 阶。求一共有多少种不同的走法。

一条走法可以表示为一个由 `1` 和 `2` 组成的有序序列，序列中所有数字之和必须恰好等于 `n`。顺序不同算不同走法。例如 `[1, 2]` 与 `[2, 1]` 都能到达第 `3` 阶，但它们是两种不同的方法。不能走过楼顶后再退回，也没有“停在中途”这一类答案。

**输入：** 一个整数 `n`，表示楼梯总阶数。

**输出：** 一个整数，表示恰好到达第 `n` 阶的不同步长序列数量。

**示例 1：**

```text
输入：n = 2
输出：2
解释：两种走法分别是 [1,1] 和 [2]。
```

**示例 2：**

```text
输入：n = 3
输出：3
解释：三种走法分别是 [1,1,1]、[1,2] 和 [2,1]。
```

**示例 3（补充演算）：**

```text
输入：n = 5
输出：8
解释：八种走法分别是：
[1,1,1,1,1]
[1,1,1,2]
[1,1,2,1]
[1,2,1,1]
[2,1,1,1]
[1,2,2]
[2,1,2]
[2,2,1]
```

官方约束为：

- `1 <= n <= 45`。
- 官方额外提示要求思考：要到达第 `n` 阶，前一步可能位于哪些台阶。
- Java 入口签名为 `public int climbStairs(int n)`。

约束影响两个实现判断。第一，官方输入没有 `n = 0`，但为了让递推从最小位置自然启动，我们仍会定义“到达起点”的组合语义。第二，`n = 45` 的答案为 `1836311903`，仍小于 Java `int` 最大值 `2147483647`；再增大一阶就会溢出，所以 `int` 只是在本题约束内安全。

## 3. 先把题目说成人话

**一句话生活化复述：** 用面值只有 `1` 和 `2` 的步长卡排成一列，要求总和正好是 `n`，统计有多少种不同排列。

**一句话关系化复述：** 统计所有元素属于 `{1, 2}`、元素和为 `n` 的有序序列数量。

这两句话去掉了楼梯的外壳，留下真正决定算法的关系：固定终点、有限动作、动作有顺序、求方案总数。我们不是求最少走几步，也不是判断能否到达；“求数量”意味着同一个位置可能由多条历史路线到达，而这些历史路线都要累加。

| 要素 | 本题翻译 |
| --- | --- |
| 对象 | 位置 `0` 到位置 `n`，以及一次长度为 `1` 或 `2` 的移动 |
| 关系 | 一种到达方式由“前驱位置的一种方式 + 最后一次移动”组成 |
| 方向 | 为了求位置 `i`，回看更小的 `i-1` 与 `i-2` |
| 目标 | 统计恰好到达 `n` 的不同有序步长序列数量 |
| 限制 | 每次只能前进 `1` 或 `2`，不能跨过终点后折返 |
| 区分方式 | 步长顺序不同就是不同方案，例如 `[1,2]` 与 `[2,1]` |

可以把位置关系画成一张有方向的图：

```text
0 ----1步----> 1 ----1步----> 2 ----1步----> 3 ----1步----> 4
 \             \             \             \
  \----2步----> 2 ----2步----> 3 ----2步----> 4

方向：小位置 ------------------------------------------> 大位置
```

每条从 `0` 到 `n` 的有向路径就是一种走法。题目要的不是节点数，而是路径数。这个关系图已经暗示：到达同一位置的不同历史，继续向后时面对完全相同的选择，因此可以先把它们汇总为一个计数。

## 4. 第一切入点：读题时先看什么

第一分钟先圈出三组词：

1. “每次可以走 `1` 或 `2` 阶”说明动作集合很小且固定。
2. “到达楼顶”说明终点固定为 `n`，不能只到附近，也不能越过后折返。
3. “多少种不同方法”说明目标是计数，所有合法历史都要保留其数量，但不一定要保留每条历史的完整内容。

“楼梯”“楼顶”“向上爬”只是帮助想象的故事词，可以暂时忽略。真正应写在草稿纸上的是：当前位置、允许增量、终点、方案数。不要因为看见楼梯就先回忆某个算法标签，也不要因为允许走 `2` 阶就立刻选择“尽量多走两阶”的贪心策略；贪心更常用于求一个最优方案，而这里要统计全部方案。

数据范围 `n <= 45` 并没有强迫我们追求极端优化，但指数枚举在 `45` 附近已经非常昂贵。它提示我们：直接列举每条路线适合帮助理解，却不适合作为最终实现。答案仍在 `int` 范围内，又让我们可以把注意力放在模型，而不必让大整数处理遮住主线。

从最小样例人工观察：

```text
n = 1：只能 [1]，共 1 种
n = 2：[1,1]、[2]，共 2 种
n = 3：[1,1,1]、[1,2]、[2,1]，共 3 种
```

这时最有价值的问题不是“后一个数是不是前两个数之和”，而是“为什么会相加”。观察 `n = 3` 的最后一步：以 `1` 结尾的走法来自第 `2` 阶，以 `2` 结尾的走法来自第 `1` 阶。这个问题会把经验规律变成可证明的模型。

## 5. 最直接的人工或暴力模型

最接近“真的爬一遍”的方法是构造一棵选择树。站在某个位置时，分别尝试走 `1` 阶和 `2` 阶；若恰好到达 `n`，找到一种合法方法；若越过 `n`，这条分支作废；否则继续选择下一步。

用“还剩多少阶”写成完整递归规则更简洁：

```text
count(remaining):
    如果 remaining == 0：
        返回 1，因为当前选择序列恰好组成一种完整走法
    如果 remaining < 0：
        返回 0，因为已经越过终点
    返回 count(remaining - 1) + count(remaining - 2)
```

以 `n = 3` 为例，选择树是：

```text
起点，剩余 3
├─ 走 1，剩余 2
│  ├─ 走 1，剩余 1
│  │  ├─ 走 1，剩余 0  -> [1,1,1]，计 1
│  │  └─ 走 2，剩余 -1 -> 越界，计 0
│  └─ 走 2，剩余 0      -> [1,2]，计 1
└─ 走 2，剩余 1
   ├─ 走 1，剩余 0      -> [2,1]，计 1
   └─ 走 2，剩余 -1     -> 越界，计 0

总数 = 1 + 1 + 1 = 3
```

它一定正确，因为每个内部节点都完整尝试了当前允许的两个动作；每条由 `1`、`2` 组成的序列在树中有唯一的一条根到节点路径。恰好到达的序列被计数一次，越界序列被计数零次，没有合法动作被漏掉，也不会让同一序列走两条不同树枝。

设 `T(r)` 是处理剩余 `r` 阶的调用成本，递归关系近似为 `T(r)=T(r-1)+T(r-2)+O(1)`。它的增长速度与斐波那契数列同阶，即 `O(phi^n)`，其中 `phi` 约为 `1.618`；若只需要一个便于记忆的宽松上界，也常写成 `O(2^n)`。递归沿着全走 `1` 的分支最深可达 `n` 层，所以调用栈空间为 `O(n)`。如果真的保存每条完整路径，输出级别的存储还会随方案数指数增长；本题只求数量，递归可以在返回时直接相加而不保存路径。

暴力模型不是无用的绕路。它明确了什么算一个答案、为什么顺序不同要分开计数、终止条件是什么。后面的优化不会修改这棵选择树所代表的答案集合，只会避免对结构相同的子树反复求值。

## 6. 暴力到底浪费在哪里

选择 `n = 5`，只写递归参数而不写完整路径，可以看清重复：

```text
count(5)
├─ count(4)
│  ├─ count(3)
│  │  ├─ count(2)
│  │  └─ count(1)
│  └─ count(2)          <- count(2) 再算一次
└─ count(3)             <- 整棵 count(3) 再算一次
   ├─ count(2)          <- count(2) 再算一次
   └─ count(1)
```

把更下层也展开，`count(1)` 与 `count(0)` 会出现更多次。第一次算出 `count(3)=3` 后，递归函数只把数字 `3` 返回给父调用，没有保存“剩余 3 阶共有 3 种走法”这个已经结算的事实。另一条历史路线再次来到“剩余 3 阶”时，又从头展开相同的两个选择。

重复并不是因为前面的路径完全相同，恰恰相反，前面的路径可能不同：

```text
先走 [1,1]：还剩 3 阶
先走 [2]：  还剩 3 阶
```

但从“还剩 3 阶”开始，未来允许的动作和合法完成数量完全相同。过去怎样到达当前状态不会改变未来，这正是可以合并状态的条件。我们不应合并已经产生的方案数量，而应把不同历史带来的数量相加后，再让这个总数共同向后传播。

从调用次数看，直接递归为同一参数建立了多棵一模一样的子树；从信息生命周期看，一个子问题的答案算完就被丢弃，随后又被重新生产。记忆化可以直接缓存 `count(r)`，把每个 `r` 只算一次；进一步观察依赖方向，还可以让较小状态先结算，再按顺序推到较大状态。

本题的具体优化目标是：

> 不再为每条完整走法重复展开未来，而是让所有到达同一台阶的历史先汇总成一个计数，并让这个计数只参与后续状态计算。

## 7. 容易想到但走不通的方向

### 方向一：每次尽量走两阶的贪心

它很自然，因为如果题目问“最少需要几步”，尽量走 `2` 的确能构造一个最短方案。但本题问所有方案。对 `n = 3`，贪心只会得到 `[2,1]`，遗漏 `[1,2]` 与 `[1,1,1]`。它保存的是一个当前选择，缺少其他选择分支的数量。

这不是实现细节问题，而是目标函数不匹配。贪心通常要证明某个局部选择不会损害全局最优；计数题不能主动丢弃合法分支。由此得到的新条件是：每个能到达当前状态的互斥来源都要累加，不能只保留一个看起来更快的来源。

> **小白追问：** 为什么这里不能每次尽量走 `2` 阶？它不是更快接近楼顶吗？
>
> **先给短答：** “更快到达”只是在挑一条路线，而题目要统计所有路线；挑得再好，也不能代表没有被挑中的合法路线。
>
> **最小例子：** `n=3` 时，优先走 `2` 只能得到 `[2,1]`。但 `[1,2]` 与 `[1,1,1]` 同样合法，所以一个局部选择只保住了 `1` 个答案，真实答案却是 `3`。
>
> **回到模型/代码：** 代码不会保存“本轮选择走 `1` 还是 `2`”。它让 `dp[i-1]` 和 `dp[i-2]` 两类来源都进入加法；这个加法对应“全部计数”，不是贪心中的“二选一”。

### 方向二：先计算要走几个两阶，再做排列组合

若用了 `k` 个两阶，就还要用 `n-2k` 个一阶，总动作数为 `n-k`，这一组的排列数是从 `n-k` 个位置中选择 `k` 个位置放二阶。对所有合法 `k` 求和，确实能得到正确答案：

```text
sum C(n-k, k)，其中 0 <= k <= floor(n/2)
```

这条路不是错误，但需要组合数计算、边界控制和可能的中间溢出，且一旦题目增加“某阶不能踩”“不同台阶代价不同”等局部限制，单纯按步数个数分类就很难继续。它揭示了方案是有序组合，却没有形成最易迁移的局部状态。对本专题目标而言，最后一步模型更直观，也更容易扩展。

### 方向三：直接记住斐波那契公式

观察答案 `1,2,3,5,8` 后想到斐波那契很正常。用闭式公式或矩阵快速幂都能更快计算，但“数列长得像”不是正确性理由。浮点闭式公式还可能因精度产生取整错误；矩阵快速幂对 `n <= 45` 又增加了不必要的实现负担。

数列名称只能帮助识别已推导出的递推，不能替代状态定义。真正可迁移的收获是：完整答案是否能按最后一个动作分成若干个不重不漏的来源。只有回答了这个问题，未来遇到三种步长、禁用台阶或带权路径时才知道如何修改状态。

### 方向四：记忆化递归

给暴力递归加缓存是完全正确的：第一次算出 `count(remaining)` 后保存，下次直接返回，时间降为 `O(n)`。它不是走不通，而是仍保留 `O(n)` 的递归栈和自顶向下的控制成本。本题依赖只从较小台阶指向较大台阶，顺序非常清楚，因此可以改为自底向上；这个对比帮助我们看见，记忆化和动态规划表不是两个毫无关系的模板，它们都在确保一个状态只被结算一次。

## 8. 关键视角转换

原视角问：“从起点出发，下一步走 `1` 还是 `2`，最终能形成哪些完整路线？”它会展开一棵树，同一个剩余量被多次访问。

新视角问：“如果一条路线已经恰好到达第 `i` 阶，它的最后一步可能是什么？”答案只有两类：

```text
最后走 1 阶：此前必须恰好位于 i-1
最后走 2 阶：此前必须恰好位于 i-2
```

> **小白追问：** 为什么不继续研究第一步，偏要把完整路线改成研究最后一步？
>
> **先给短答：** 第一步之后还剩一整棵未知分支；最后一步之前却只可能站在两个确定位置，因此能把大量完整路线汇总到少量前驱状态。
>
> **最小例子：** 到达第 `4` 阶的路线有 `[1,1,1,1]`、`[1,1,2]`、`[1,2,1]`、`[2,1,1]`、`[2,2]`。看第一步后仍要继续枚举；删掉最后一步后，它们只落到位置 `3` 或位置 `2`。
>
> **回到模型/代码：** 循环变量 `step` 表示正在结算的终点。`waysOneStepBack` 和 `waysTwoStepsBack` 就是删掉最后一步后得到的两个前驱，而不是两条具体路线。

令 `dp[i]` 表示从起点出发、恰好到达第 `i` 阶的走法数量。删除一条完整走法的最后一步：

- 若最后一步是 `1`，就唯一得到一条到达 `i-1` 的走法。
- 若最后一步是 `2`，就唯一得到一条到达 `i-2` 的走法。

反过来，任意一条到达 `i-1` 的走法追加 `1`，都唯一形成一条到达 `i` 的走法；任意一条到达 `i-2` 的走法追加 `2`，也一样成立。两组答案的最后一个数字不同，因此互不重叠；任意合法走法的最后一个数字只能是 `1` 或 `2`，因此两组又覆盖全部答案。于是：

```text
dp[i] = dp[i - 1] + dp[i - 2]
```

> **小白追问：** 把两个前驱的数量直接相加，怎么确认既没有重复，也没有漏掉路线？
>
> **先给短答：** 用最后一步给路线贴标签：标签只能是 `1` 或 `2`，一条路线只有一个最后数字，所以两组互斥并且覆盖全部路线。
>
> **最小例子：** `i=3` 时，来自 `i-1=2` 的路线追加 `1`，得到 `[1,1,1]`、`[2,1]`；来自 `i-2=1` 的路线追加 `2`，得到 `[1,2]`。前一组都以 `1` 结尾，后一组以 `2` 结尾，不可能撞成同一个序列。
>
> **回到模型/代码：** `currentWays = waysOneStepBack + waysTwoStepsBack` 不是经验公式。加号左边对应“末步为 `1`”的集合大小，右边对应“末步为 `2`”的集合大小。

转换前后的差别可以概括为：

| 转换前 | 转换后 |
| --- | --- |
| 枚举每条完整走法 | 只统计到达每个位置的数量 |
| 从起点不断猜下一步 | 从当前终点反看最后一步 |
| 同一剩余量展开多次 | 每个台阶状态结算一次 |
| 保存递归路径或调用现场 | 保存前驱状态的计数 |
| 到叶子才产生一个答案 | 处理位置 `i` 时直接汇总全部答案 |

还差基础状态。`dp[1]=1` 很直观：只有 `[1]`。为了让 `i=2` 也统一使用递推，我们定义 `dp[0]=1`，意思不是“有一种爬楼动作”，而是“从起点到起点有一种不做任何动作的空走法”。这样，从 `0` 追加一个 `2` 能正确产生 `[2]` 这一种方案：

```text
dp[2] = dp[1] + dp[0] = 1 + 1 = 2
```

如果把 `dp[0]` 设成 `0`，就等于错误地否认“直接走一个两阶”所需的前驱空方案，`dp[2]` 会被算成 `1`。这里的 `1` 是组合计数的单位元语义，而不是官方把 `n=0` 当成了输入用例。

> **小白追问：** 明明没有爬任何台阶，为什么 `dp[0]` 不是 `0`，反而算作 `1` 种？
>
> **先给短答：** `dp[0]=1` 数的是一条“什么都不做”的空序列；它不是一次爬楼动作，而是让第一步可以从起点合法追加的唯一基础方案。
>
> **最小例子：** 求 `dp[2]` 时，一类路线从 `dp[1]` 追加 `1`，得到 `[1,1]`；另一类从 `dp[0]` 的空序列追加 `2`，得到 `[2]`。若 `dp[0]=0`，第二类会消失，答案就从 `2` 错成 `1`。
>
> **回到模型/代码：** `waysTwoStepsBack` 初始化为 `1`，此时它扮演 `dp[0]`。当 `step=2` 时，这个值参与第一次 `currentWays` 计算，之后不再需要特殊分支。

## 9. 正式建立模型

| 建模项 | 本题结论 |
| --- | --- |
| 对象 | 台阶位置 `i`，以及恰好到达该位置的走法集合 |
| 关系 | 到达 `i` 的走法按最后一步唯一来自 `i-1` 或 `i-2` |
| 状态 | `dp[i]`：从位置 `0` 出发，恰好到达位置 `i` 的走法数 |
| 事件 | 按升序处理新的位置 `i`，两个前驱状态已经完成结算 |
| 不变量 | 计算 `i` 前，保存的两个值分别等于 `dp[i-2]` 与 `dp[i-1]` |
| 结果时机 | 处理到 `i=n` 后，当前较新状态就是 `dp[n]` |

状态只保存数量，不保存完整路径，因为未来能走什么只取决于当前所在位置，不取决于到达这里时各步的排列。不同历史的身份对未来无影响，只需累加其数量。这个性质可称为“状态足够”：知道 `i` 和到达 `i` 的方案数，就足以向 `i+1`、`i+2` 传播贡献。

> **小白追问：** `dp[i]` 只存一个数字，路线内容都丢了，后面怎么知道该接 `1` 还是接 `2`？
>
> **先给短答：** 本题的后续动作只由当前位置决定；到达同一位置的所有路线都拥有完全相同的下一步选项，所以传播时只需要知道它们有多少条。
>
> **最小例子：** 到达位置 `3` 的 `[1,2]` 和 `[2,1]` 历史不同，但两者接下来都能追加 `1` 到 `4`，也都能追加 `2` 到 `5`。未来不会询问“上一段先走了什么”，因此保存两条字符串没有额外作用。
>
> **回到模型/代码：** `waysOneStepBack` 保存 `dp[i-1]` 的计数。执行加法时，这个数字代表整组路线同时追加同一种末步；代码无需遍历或恢复每条路线。

数组版先保存 `dp[0..n]`，便于观察每个状态。随后再检查依赖：计算 `dp[i]` 只读取 `dp[i-1]` 与 `dp[i-2]`，更早的 `dp[i-3]` 不会被任何未来状态直接读取，因为下一次只需要新的相邻两项。因此在算出 `dp[i]` 后，可以永久丢弃 `dp[i-2]` 之前的所有表项，只保留两个滚动变量。丢弃的是已经完成最后一次直接贡献的数值，不是丢弃方案。

遍历必须从小到大。处理 `i` 时，它依赖的两个较小状态已经确定；若从大到小，在没有递归或额外方程求解的情况下，前驱尚未得到。这里不存在相等值去重问题：`dp[i-1]` 与 `dp[i-2]` 即使数值偶然相同，也代表不同前驱位置和不同最后一步类别，必须相加。

> **小白追问：** 递推式已经写出来了，为什么循环方向还必须从小到大？
>
> **先给短答：** 计算 `dp[i]` 前必须先拿到最终的 `dp[i-1]` 和 `dp[i-2]`；从小到大正好让依赖先完成、使用者后完成。
>
> **最小例子：** 求 `dp[3]` 需要 `dp[2]=2` 和 `dp[1]=1`。若从 `3` 倒着开始，`dp[2]` 仍是数组默认值 `0`，会把 `dp[3]` 错算成 `1`；先结算 `2`，再结算 `3` 才得到 `3`。
>
> **回到模型/代码：** 本题代码从 `step=2` 递增到 `n`。每轮开始时，两个滚动变量已经分别代表 `dp[step-2]` 与 `dp[step-1]`，这就是遍历方向要维护的前提。

> **小白追问：** `dp[0]` 和 `dp[1]` 都等于 `1`，数值相同，为什么相加时不需要去重？
>
> **先给短答：** DP 数值只是集合大小，不是路线身份；两个 `1` 分别属于不同前驱位置，追加的最后一步也不同，所以代表两组不同答案。
>
> **最小例子：** 计算 `dp[2]` 时，`dp[1]=1` 代表路线 `[1]`，追加 `1` 后得到 `[1,1]`。`dp[0]=1` 代表空路线，追加 `2` 后得到 `[2]`。来源计数同为 `1`，产生的完整路线却不相同。
>
> **回到模型/代码：** 两个变量的角色由下标距离决定，而不是由数值决定。`currentWays` 无条件相加两个前驱计数；本题不出现对 `1`、`2` 等计数值做集合去重的代码。

滚动变量可以命名为：

```text
waysTwoStepsBack = dp[i-2]
waysOneStepBack  = dp[i-1]
currentWays      = dp[i]
```

一次更新必须先用两个旧值计算 `currentWays`，再整体向前滚动。若先覆盖 `waysOneStepBack`，就会在同一轮混用新旧状态，破坏不变量。

## 10. 所需数据结构详解

模型推导完成后，真正需要的数据结构并不复杂：先是一张按位置索引的线性状态表，压缩后只是两个整数变量。动态规划不是某个特殊容器的名字，而是一种“把重复子问题的答案按依赖顺序保存并复用”的组织方法。

### 一维状态表

`int[] dp = new int[n + 1]` 让下标直接对应位置，值对应方案数。它在内存中连续存放元素，支持按下标 `O(1)` 随机访问。本题使用的操作只有：写入基础值、读取前两个位置、把两者之和写入当前位置。

| 问题 | 回答 |
| --- | --- |
| 为什么是数组 | 状态编号是连续整数 `0..n`，正好可以直接做下标 |
| 里面存什么 | 到达对应位置的方案数量，不存路径本身 |
| 何时写入 | 两个前驱都已结算后写入 `dp[i]` |
| 何时读取 | 计算后继 `dp[i+1]` 或 `dp[i+2]` 时 |
| 单次操作 | 下标读写为 `O(1)`，整数相加为 `O(1)` |
| 最大规模 | `n+1` 个整数，额外空间为 `O(n)` |

数组的优势是语义透明，特别适合第一次检查状态定义与基础值。哈希表也能按键保存 `i -> 方案数`，但状态编号连续，哈希计算、装箱和桶结构都没有必要。栈与队列强调访问顺序，却不能比两个明确命名的前驱变量更清楚地表达依赖。保存所有完整序列则远超题目需要，空间会随答案数量增长。

### 两个滚动变量

当依赖窗口固定为前两项时，可以把状态表压缩为两个 `int`：较远前驱与较近前驱。每轮先求和，再让较远变量接收旧的较近值，让较近变量接收新值。三个赋值都是 `O(1)`，最坏只保存三个整数，包括临时的 `currentWays`，额外空间为 `O(1)`。

> **小白追问：** 为什么只留两个变量就够了，`dp[0]` 到 `dp[i-3]` 真的永远不会再用吗？
>
> **先给短答：** 每个新状态只读取紧挨着它的前两个状态；当循环准备计算下一项时，更早的值已经完成最后一次直接贡献。
>
> **最小例子：** 算 `dp[4]` 只要 `dp[3]` 和 `dp[2]`。算完后，下一项 `dp[5]` 只要 `dp[4]` 和 `dp[3]`，`dp[2]` 不再出现在公式里，所以可以让保存 `dp[2]` 的变量改存 `dp[3]`。
>
> **回到模型/代码：** `waysTwoStepsBack = waysOneStepBack` 把窗口左端推进一格，`waysOneStepBack = currentWays` 放入新右端。若步长扩为 `1、2、3`，依赖窗口会变成三项，就不能照搬两个变量。

滚动变量不是改变模型，也不是让某些状态不再存在。逻辑上仍有完整的 `dp[0..n]`；物理上只保留未来还会读取的窗口。若后续要输出每个台阶的方法数、恢复具体选择、或转移依赖更早位置，就可能需要保留数组，不能机械压缩。

### 数值类型

Java `int` 是 32 位有符号整数。本题最大答案 `dp[45]=1836311903`，所以提交代码使用 `int` 与官方签名一致。若把模型迁移到更大的 `n`，`dp[46]=2971215073` 已经越过 `int` 上限；这时数据结构的逻辑不变，但值容器要改为 `long`、`BigInteger` 或题目指定的取模整数。数据结构选择还包括数值表示范围，不能只看访问方式。

> **小白追问：** 递推关系没有变，为什么把 `n` 从 `45` 扩到 `46` 就必须考虑换数值类型？
>
> **先给短答：** 模型算出的数学答案仍然正确，但 Java 变量能表示的整数范围有限；容器装不下结果时，代码值会溢出，不能再代表模型状态。
>
> **最小例子：** `dp[44]=1134903170`、`dp[45]=1836311903` 都能放进 `int`。两者相加得到 `dp[46]=2971215073`，超过 `2147483647`，所以同一个加法在 `int` 中不会得到真实答案。
>
> **回到模型/代码：** 官方约束停在 `45`，提交方法返回 `int`，当前两个滚动变量因此安全。迁移模型前要重新核对答案上界，再决定把变量改成 `long`、`BigInteger` 还是取模值。

## 11. 生活化类比及边界

把楼梯想成一排结算窗口。每个窗口不记录每位旅客完整的行程，只在账本上登记“有多少条合法路线到达这里”。要结算第 `i` 个窗口，工作人员只查看两个入口：从 `i-1` 走短通道来的人，以及从 `i-2` 走长通道来的人。两个入口贴着不同标签，所以人群不会重复；除此以外没有第三个入口，所以相加后不会遗漏。

| 生活对象或动作 | 算法中的对应物 |
| --- | --- |
| 起点窗口 | 状态 `dp[0]`，有一条空行程作为后续追加动作的起点 |
| 第 `i` 个结算窗口 | 台阶状态 `i` |
| 窗口账本上的人数 | `dp[i]`，到达 `i` 的方案数 |
| 短通道 | 从 `i-1` 追加最后一步 `1` |
| 长通道 | 从 `i-2` 追加最后一步 `2` |
| 两个入口的人数相加 | `dp[i-1] + dp[i-2]` |
| 按窗口编号依次结算 | 从小到大遍历 `i` |
| 只把最近两本账放桌上 | `waysTwoStepsBack` 与 `waysOneStepBack` |
| 结算最后一个窗口 | 返回 `dp[n]` |

`dp[0]=1` 可以类比为起点有一张已经登记的空行程凭证。它不是说有人爬了零阶还完成了官方任务，而是让“直接通过一条长通道到第 2 阶”有一个合法来源。计数递推里，空结构常常是一种组合的起点。

类比到这里为止。现实窗口可能限流、旅客可能有身份、两条路线可能在中途相遇后仍要区分个人，这些细节都不属于算法。算法只关心有序步长序列的数量；相同位置的历史可以合并为计数，是因为未来规则只由位置决定。如果未来可走动作还依赖旅客之前是否走过长通道，那么只记录位置就不够，状态中必须增加那段历史信息。

## 12. 典型输入的完整数据变化图

用 `n = 5` 完整演算。先看逻辑状态表，再看滚动变量如何承载同一张表。

### 状态来源图

```text
dp[0]=1      dp[1]=1
   \          /
    \        /
     -> dp[2]=2
        \        dp[1]=1
         \      /
          -> dp[3]=3
             \        dp[2]=2
              \      /
               -> dp[4]=5
                  \        dp[3]=3
                   \      /
                    -> dp[5]=8

计算方向：0 -> 1 -> 2 -> 3 -> 4 -> 5
每条斜线表示“追加一种允许的最后一步”。
```

完整 DP 表为：

| 位置 `i` | 最后走 1 的来源 | 最后走 2 的来源 | `dp[i]` |
| ---: | ---: | ---: | ---: |
| 0 | 不适用 | 不适用 | 1，空走法 |
| 1 | `dp[0]=1` | 不存在 | 1 |
| 2 | `dp[1]=1` | `dp[0]=1` | 2 |
| 3 | `dp[2]=2` | `dp[1]=1` | 3 |
| 4 | `dp[3]=3` | `dp[2]=2` | 5 |
| 5 | `dp[4]=5` | `dp[3]=3` | 8 |

### 滚动状态逐步快照

初始化时已结算 `dp[0]` 与 `dp[1]`：

```text
位置下标：         0       1       2       3       4       5
逻辑 DP：          1       1       ?       ?       ?       ?
滚动角色：         ^       ^
             twoSteps   oneStep
下一次处理：i = 2
```

处理 `i = 2`：

```text
当前输入：位置 2
处理前状态：waysTwoStepsBack=dp[0]=1，waysOneStepBack=dp[1]=1
判断依据：所有到达 2 的走法最后一步只可能来自 0 或 1
执行动作：currentWays = 1 + 1 = 2
处理后状态：waysTwoStepsBack=1，waysOneStepBack=2
新增结果：dp[2]=2
```

处理 `i = 3`：

```text
当前输入：位置 3
处理前状态：waysTwoStepsBack=dp[1]=1，waysOneStepBack=dp[2]=2
判断依据：最后走 2 来自位置 1，最后走 1 来自位置 2
执行动作：currentWays = 1 + 2 = 3
处理后状态：waysTwoStepsBack=2，waysOneStepBack=3
新增结果：dp[3]=3
```

处理 `i = 4`：

```text
当前输入：位置 4
处理前状态：waysTwoStepsBack=dp[2]=2，waysOneStepBack=dp[3]=3
判断依据：两个来源已经结算，类别按最后一步互斥
执行动作：currentWays = 2 + 3 = 5
处理后状态：waysTwoStepsBack=3，waysOneStepBack=5
新增结果：dp[4]=5
```

处理 `i = 5`：

```text
当前输入：位置 5
处理前状态：waysTwoStepsBack=dp[3]=3，waysOneStepBack=dp[4]=5
判断依据：最后一步为 2 或 1，覆盖全部合法走法
执行动作：currentWays = 3 + 5 = 8
处理后状态：waysTwoStepsBack=5，waysOneStepBack=8
新增结果：dp[5]=8，即最终答案
```

汇总为稳定时刻表：

| 本轮完成位置 | 更新前较远值 | 更新前较近值 | 新值 | 更新后两个滚动状态 |
| ---: | ---: | ---: | ---: | --- |
| 初始化到 1 | `dp[0]=1` | `dp[1]=1` | 无 | `(1,1)` |
| 2 | 1 | 1 | 2 | `(1,2)` |
| 3 | 1 | 2 | 3 | `(2,3)` |
| 4 | 2 | 3 | 5 | `(3,5)` |
| 5 | 3 | 5 | 8 | `(5,8)` |

每一行结束后，右边二元组始终表示“当前已完成位置的前一项与当前项”。旧的较远值在本轮相加后完成最后一次直接用途，可以被覆盖。

## 13. 边界场景的数据变化

### 场景一：官方最小输入 `n = 1`

```text
初始化：
waysTwoStepsBack = dp[0] = 1
waysOneStepBack  = dp[1] = 1

循环范围：step 从 2 到 1
实际执行：0 次
返回：waysOneStepBack = 1
```

循环一次也不执行，但状态已经代表答案。数组没有访问负下标，滚动变量也不需要读取不存在的 `dp[-1]`。这说明基础状态不是补丁，而是循环开始前已经解决的最小问题。

### 场景二：第一个真正触发递推的位置 `n = 2`

```text
处理前：(dp[0], dp[1]) = (1,1)
currentWays = 1 + 1 = 2
滚动后：(dp[1], dp[2]) = (1,2)
返回：2
```

如果误设 `dp[0]=0`，这里会得到 `1`，恰好漏掉直接走 `[2]`。因此 `n=2` 是检查基础语义最有效的用例。

> **小白追问：** 为什么 `n=1` 和 `n=2` 不分别写两个 `if`，却说同一套初始化已经统一处理？
>
> **先给短答：** 初始化先让较近变量代表 `dp[1]`；循环只负责从 `dp[2]` 开始生成新状态，所以 `n=1` 自然零轮返回，`n=2` 自然执行一轮返回。
>
> **最小例子：** `n=1` 时循环条件 `2 <= 1` 为假，返回初始值 `1`。`n=2` 时只算一次 `1+1=2`，再返回 `2`。两个边界都没有访问负位置，也没有额外分支。
>
> **回到模型/代码：** 统一性来自变量语义和循环范围：初始化对应 `dp[0]、dp[1]`，`for (step=2; step<=n; step++)` 只结算尚未完成的位置。

### 场景三：官方最大输入 `n = 45`

算法仍然只循环 `44` 次，从 `step=2` 到 `45`，最终状态为：

```text
dp[43] = 701408733
dp[44] = 1134903170
dp[45] = 1836311903
```

最后一次相加仍未超过 `int` 上限，变量中不残留集合或递归调用。若把输入扩展到 `46`，数学答案 `2971215073` 会发生 `int` 溢出；这不是递推关系错误，而是数值容器不再满足扩展后的约束。

### 场景四：扩展语义中的 `n = 0`

官方不会传入 `0`。在通用组合模型里可以定义 `dp[0]=1`，返回一条空走法；在产品业务里也可能规定“零阶不算方案”，从而返回 `0`。两种接口约定都可能合理，但不能混用。本文的提交实现只处理官方 `1..45`，`dp[0]=1` 是内部递推语义，不是在修改官方输入定义。

## 14. 正确性与不变量

要证明的对象是：对每个 `i`，计算出的值等于所有恰好到达第 `i` 阶的不同走法数量；滚动压缩后仍保持这个值，没有因覆盖数组而改变结果。

### 状态转移为什么满足题目条件

任取一条到达 `i` 的合法走法。因为每步只能是 `1` 或 `2`，最后一步必属于且只属于以下一类：

- 最后一步是 `1`，删除它后得到一条恰好到达 `i-1` 的合法走法。
- 最后一步是 `2`，删除它后得到一条恰好到达 `i-2` 的合法走法。

反过来，对任意到达 `i-1` 的走法追加 `1`，以及对任意到达 `i-2` 的走法追加 `2`，所得序列都恰好到达 `i`。追加动作合法，且不会越界。于是两个前驱状态产生的结果全部满足题目条件。

### 为什么不会遗漏或重复

没有第三种允许的最后步长，所以任意合法走法都落入上述一类，不会遗漏。两类走法的最后一个元素分别是 `1` 和 `2`，一条序列不可能同时属于两类，所以相加不会重复。同一前驱集合中的每条序列追加固定末尾后仍保持一一对应，也不会把两条不同前驱序列合并成同一完整序列。

### 基础状态为什么成立

`dp[0]=1` 表示唯一空序列，其元素和为 `0`；`dp[1]=1` 表示唯一序列 `[1]`。它们分别为统一递推提供两个最小已知状态。尤其是从 `dp[0]` 追加 `2`，恰好构成到达第 `2` 阶的序列 `[2]`。

### 归纳说明所有状态都正确

假设 `dp[i-1]` 与 `dp[i-2]` 已正确统计各自位置的全部走法。根据最后一步的完备且互斥分类，`dp[i-1]+dp[i-2]` 正好统计到达 `i` 的全部走法，因此 `dp[i]` 正确。基础状态正确，所以从 `i=2` 依次应用该结论，直到 `i=n`，每个状态都正确。

> **小白追问：** 证明里先“假设前两项正确”，这会不会是在拿还没证明的结论证明自己？
>
> **先给短答：** 不是一次性假设所有项正确，而是先确认最小的两项，再证明“只要相邻前两项正确，下一项就正确”，最后按顺序逐项推进。
>
> **最小例子：** 已直接列出 `dp[0]=1`、`dp[1]=1`。它们推出 `dp[2]=2`；已经确认的 `dp[1]、dp[2]` 再推出 `dp[3]=3`；随后才用 `dp[2]、dp[3]` 推出 `dp[4]=5`。每一步只依赖更早已经落地的结论。
>
> **回到模型/代码：** `for` 循环正是这条证明链的执行顺序。循环开始前基础项成立；一次循环保持不变量并产生下一项，所以循环结束时 `waysOneStepBack` 才能代表已经证明正确的 `dp[n]`。

### 滚动变量为何不会破坏状态

循环处理 `step` 之前维持不变量：

```text
waysTwoStepsBack == dp[step-2]
waysOneStepBack  == dp[step-1]
```

先用两个旧值求得 `currentWays=dp[step]`。随后令较远变量等于旧的较近值，令较近变量等于新值，因此更新后它们分别是 `dp[step-1]` 和 `dp[step]`，恰好满足下一轮的不变量。被覆盖的旧 `dp[step-2]` 以后不再是任何新状态的直接前驱，删除安全。

> **小白追问：** 覆盖旧状态会不会把某些路线也删掉，导致后面的答案变少？
>
> **先给短答：** 覆盖的是一个已经完成最后一次读取的存储位置，不是从数学上的路线集合中扣除方案；它的贡献已经进入 `currentWays`。
>
> **最小例子：** 算 `dp[4]=dp[3]+dp[2]=3+2=5` 后，`dp[2]` 的两条路线已经包含在数字 `5` 中。下一轮只用 `dp[4]=5` 和 `dp[3]=3`，无需再次单独读取 `dp[2]=2`。
>
> **回到模型/代码：** 循环不变量规定更新前两个变量是当前所需前驱，更新后是下一轮所需前驱。只要 `currentWays` 在覆盖前算好，旧值的业务贡献就已经完成。

### 结束时为什么得到最终答案

循环按有限的整数区间 `2..n` 前进，每轮 `step` 增加 `1`，一定终止。最后一轮结束后，较近变量根据不变量等于 `dp[n]`；若 `n=1`，循环不执行，初始化的较近变量已经是 `dp[1]`。因此返回值对官方全部输入都正确。

## 15. 时间与空间复杂度推导

定义 `n` 为楼梯总阶数，也可视为最大状态编号。一次整数比较、相加、赋值或数组访问在本题数值范围内按 `O(1)` 计算。返回值只是一个整数，不存在与 `n` 成比例的输出空间。

### 直接递归枚举

对剩余 `r` 阶，递归会调用剩余 `r-1` 与 `r-2` 的分支。调用规模满足斐波那契型递推，因此时间为 `Theta(phi^n)`；写成更宽松的 `O(2^n)` 也成立。这里不是简单地因为“每层两个分支”就断言树有完整 `2^n` 个节点，而是因为越界和提前到达会截断分支，精确增长率接近 `phi^n`。

最长调用链每次只减少 `1`，从 `n` 到 `0`，递归深度为 `O(n)`，辅助栈空间为 `O(n)`。递归返回后兄弟分支复用栈帧，不会同时保存整棵树；若额外保存所有具体路径，则所需空间还会与输出总长度有关，但纯计数实现不需要。

### 记忆化递归与完整 DP 表

合法状态只有 `0..n` 共 `n+1` 个。缓存后每个状态首次计算一次，每次只做两个缓存读取和一次加法，总时间为 `O(n)`。记忆数组是 `O(n)`，递归栈最深仍为 `O(n)`，所以辅助空间为 `O(n)`。

自底向上的数组 DP 同样计算 `n+1` 个状态，每个状态做常数次工作，总时间 `O(n)`；数组保存全部状态，空间 `O(n)`，但不再需要递归栈。

### 推荐的滚动状态模型

初始化是常数工作。循环从 `2` 到 `n`，共执行 `n-1` 次；每轮一次加法和固定次数赋值，因此总时间为 `O(n)`。无论 `n` 多大，算法只保存较远前驱、较近前驱和当前值三个整数，辅助空间为 `O(1)`。

> **小白追问：** 为什么时间是 `O(n)`、空间是 `O(1)`？循环中的数字越来越大，难道不算更多空间吗？
>
> **先给短答：** 在本题 `int` 约束下，每一阶只做固定次数操作，循环次数随 `n` 线性增长；同时存活的变量数量始终固定，不随台阶数增加。
>
> **最小例子：** `n=5` 时结算位置 `2、3、4、5`，共 `4` 轮；`n=6` 只多结算位置 `6`，增加一轮。两种输入运行时都只保存两个前驱和一个当前值，而不是分别保存 `5` 个或 `6` 个状态。
>
> **回到模型/代码：** `for` 循环执行 `n-1` 次，每轮一加两次滚动赋值，得到 `O(n)`。局部整数 `waysTwoStepsBack`、`waysOneStepBack`、`currentWays` 的个数固定，得到辅助空间 `O(1)`。

这里没有隐藏的均摊分析，也不能因为只保存两个变量就说时间是 `O(1)`。空间压缩减少的是同时存活的状态数量，仍然必须按顺序结算每个位置。若采用矩阵快速幂，可以把理论时间降为 `O(log n)`，但那是另一种模型；在本题范围内，线性递推更清晰。

| 方案 | 时间复杂度 | 辅助空间 | 重复子问题 |
| --- | --- | --- | --- |
| 直接递归 | `Theta(phi^n)`，宽松上界 `O(2^n)` | `O(n)` 调用栈 | 大量重复 |
| 记忆化递归 | `O(n)` | `O(n)` 缓存加调用栈 | 每个状态结算一次 |
| 数组 DP | `O(n)` | `O(n)` | 每个状态结算一次 |
| 滚动变量 DP | `O(n)` | `O(1)` | 每个状态结算一次，只保留依赖窗口 |

### 泛用模型骨架

先给一个“允许若干正步长、统计有序走法”的泛用骨架。它仍以最后一步分类：`ways[position]` 等于所有合法前驱 `ways[position-stepSize]` 之和。数组版有意保留完整状态，便于迁移到步长种类更多的题；`long` 用于扩大示例骨架的数值范围，但调用者仍需根据题目上界判断是否足够。

```java
final class OrderedStepCountingModel {
    public long countWays(int targetPosition, int[] allowedStepSizes) {
        if (targetPosition < 0) {
            return 0L;
        }

        long[] ways = new long[targetPosition + 1];
        ways[0] = 1L;

        for (int position = 1; position <= targetPosition; position++) {
            long currentWays = 0L;
            for (int stepSize : allowedStepSizes) {
                int previousPosition = position - stepSize;
                if (stepSize > 0 && previousPosition >= 0) {
                    currentWays += ways[previousPosition];
                }
            }
            ways[position] = currentWays;
        }
        return ways[targetPosition];
    }
}
```

骨架假设 `allowedStepSizes` 中是互不重复的正整数，否则相同步长会被当作不同动作重复计数。外层按位置递增，意味着 `[1,2]` 与 `[2,1]` 在不同前驱链中分别产生，因此统计的是有序方案。若题目把顺序不同视为同一种组合，循环组织方式需要改变，不能直接套用。

> **小白追问：** 泛用骨架只是在数组里累加数字，它怎样保留 `[1,2]` 和 `[2,1]` 的先后区别？
>
> **先给短答：** 它不保存序列文本，而是让每个前驱方案在到达新位置时追加一个末步；末步不同或前驱历史不同，都会沿不同的状态来源各贡献一次。
>
> **最小例子：** 步长为 `1、2`，目标为 `3`。结算位置 `2` 时已包含 `[1,1]` 与 `[2]`；结算位置 `3` 时，前者追加 `1` 产生 `[1,1,1]`，后者追加 `1` 产生 `[2,1]`，而位置 `1` 的 `[1]` 追加 `2` 产生 `[1,2]`。
>
> **回到模型/代码：** 外层 `position` 保证先结算前驱，内层 `stepSize` 枚举当前路线的最后一步。`currentWays += ways[previousPosition]` 把该前驱位置中的所有有序历史一起转移到当前终点。

本题的步长固定为 `1`、`2`，每个位置只依赖相邻两项，所以完整数组还能压缩为两个变量。

> **小白追问：** 为什么滚动更新必须先计算 `currentWays`，不能先把某个变量向前移动？
>
> **先给短答：** 两个前驱都还是旧轮次的值时，才能计算当前状态；提前覆盖任意一个前驱，就会把不同轮次的数据混在同一次加法里。
>
> **最小例子：** 计算 `dp[4]` 前两个变量应是 `dp[2]=2`、`dp[3]=3`。正确结果是 `5`。若先让较远变量变成 `3`，再相加就会得到 `3+3=6`，已经不是 `dp[2]+dp[3]`。
>
> **回到模型/代码：** `int currentWays = waysOneStepBack + waysTwoStepsBack;` 必须位于两条赋值之前。临时变量保存新状态，后两行才把窗口从 `(dp[i-2], dp[i-1])` 推进到 `(dp[i-1], dp[i])`。

### LeetCode 可直接提交代码

```java
class Solution {
    public int climbStairs(int n) {
        int waysTwoStepsBack = 1; // dp[0]：一条空走法
        int waysOneStepBack = 1;  // dp[1]：只有走一步

        for (int step = 2; step <= n; step++) {
            int currentWays = waysOneStepBack + waysTwoStepsBack;
            waysTwoStepsBack = waysOneStepBack;
            waysOneStepBack = currentWays;
        }
        return waysOneStepBack;
    }
}
```

| --- | --- |
| 当前对象 | 循环中的位置 `step` |
| 较远前驱状态 | `waysTwoStepsBack`，循环开始时为 `dp[step-2]` |

## 17. 边界、常见错误与调试观察点

| 层次 | 常见问题 | 现象 | 修正依据 |
| --- | --- | --- | --- |
| 建模错误 | 把计数题当成最少步数题并贪心走 `2` | 只得到一个方案，遗漏其他合法排列 | 目标是方案总数，所有互斥前驱都要累加 |
| 建模错误 | `dp[i]` 定义成“从 `i` 出发的方法数”，代码却按“到达 `i`”初始化 | 基础值与遍历方向互相矛盾 | 状态定义、转移方向和返回位置必须统一 |
| 建模错误 | 看到答案数列后直接写公式 | 不能解释变式，也容易写错下标偏移 | 先按最后一步证明递推，再识别数列 |
| 条件错误 | 把 `dp[0]` 设成 `0` | `n=2` 得到 `1`，漏掉 `[2]` | 空走法是追加第一个动作的唯一前驱 |
| 条件错误 | 循环写成 `step < n` | 返回 `dp[n-1]` | 当前状态必须一直结算到 `n`，上界要包含 `n` |
| 条件错误 | 从 `step=3` 开始却仍初始化为 `dp[0]`、`dp[1]` | 直接跳过 `dp[2]`，后续全部错位 | 循环起点必须与变量角色对应 |
| 实现错误 | 先更新较近变量再计算当前值 | 同一轮混用新旧值，数列增长异常 | 覆盖前先把两个旧前驱相加 |
| 实现错误 | 无约束扩大 `n` 仍用 `int` | 从 `n=46` 开始出现负数或错误值 | 按答案上界选择 `long` 或 `BigInteger` |
| 泛化错误 | 步长数组含重复值 | 相同步长被当成不同动作重复计数 | 泛用骨架要求正整数步长互不重复 |
| 泛化错误 | 组合不区分顺序却仍按位置外循环 | `[1,2]` 与 `[2,1]` 被分开统计 | 先明确“方案相同”的判定，再设计循环 |

调试时不要只打印最终答案。每轮打印下面四项：

```text
step
更新前 waysTwoStepsBack
更新前 waysOneStepBack
计算出的 currentWays
```

对 `n=5`，稳定输出应为：

```text
step=2, before=(1,1), current=2
step=3, before=(1,2), current=3
step=4, before=(2,3), current=5
step=5, before=(3,5), current=8
```

如果第一行不是 `2`，先查 `dp[0]` 和循环起点；如果前几行正确而后面突然出现不符合“当前等于前两项和”的值，查更新顺序；如果只在大输入出现负数，查数值溢出。还可以暂时恢复 `int[] dp`，同时运行数组版与滚动版，并在每一阶比较两者，而不是盯着最终数字猜错在哪一轮。

一个实用断言是：在本题正计数范围内，`currentWays` 应不小于任一前驱。它不是完整的正确性证明，却能在未溢出时快速暴露赋值错位。到 `n=45` 仍应保持正数；一旦迁移到更大范围，出现负数通常意味着 `int` 溢出，而不是方案数真的减少。

## 18. 最终模型卡

| 模型卡项目 | 结论 |
| --- | --- |
| 识别指纹 | 固定终点、有限正向动作、求有序方案数，未来只由当前位置决定 |
| 一句话关系模型 | 到达当前位置的所有走法，可按最后一步唯一拆成若干个前驱位置的走法集合 |
| DP 实际保存什么 | 到达某个位置的方案总数，不保存每条完整路线 |
| 状态何时变化 | 前驱状态已结算、开始处理新位置时，把所有合法前驱计数相加 |
| 答案何时产生 | 结算位置 `n` 后，`dp[n]` 就是答案 |
| 核心不变量 | 每轮开始时两个滚动变量分别等于当前目标的 `dp[i-2]` 和 `dp[i-1]` |
| 时间复杂度 | `O(n)` |
| 辅助空间复杂度 | `O(1)`，完整数组表达时为 `O(n)` |

**四句建模结论：**

```text
我正在处理的对象是：从起点到每一个台阶位置的有序走法集合。
我必须持续保存的是：到达当前目标前两个位置的方案数量。
当开始结算一个新台阶时，我执行：按最后一步为 1 或 2，把两个互斥前驱的计数相加并滚动状态。
答案在第 n 阶结算完成时，由代表 dp[n] 的较近滚动变量计算出来。
```

**泛用控制模板：**

```text
定义 dp[state] 的业务语义
找出构成 state 的所有可能“最后一个动作”
把每个最后动作对应到一个更小前驱
证明这些来源互斥且覆盖全部答案
为最小状态赋予能启动递推的组合语义
按依赖方向逐个结算状态
只在确认未来不再读取时压缩旧状态
```

**迁移变式：**

| 题目或变化 | 保持不变的模型 | 需要改变的部分 |
| --- | --- | --- |
| 509. 斐波那契数 | 每项依赖前两项，滚动不变量相同 | 基础值改为 `F(0)=0`、`F(1)=1`，状态不再表示走法 |
| 每次可走 `1..k` 阶 | 按最后一步分类并累加前驱不变 | 依赖窗口扩大到前 `k` 项，可用数组或滑动和 |
| 746. 使用最小花费爬楼梯 | 从最后一步寻找前驱不变 | 聚合操作从“方案相加”变成“代价取最小再加当前成本” |
| 某些台阶禁止落脚 | 位置状态与正向结算不变 | 禁止位置的方案数置为 `0`，前驱只向允许位置贡献 |

复习时不要只记 `a+b`。真正的识别顺序是：先确定答案是否能按最后动作分类，再确认不同来源是否互斥和完备，然后定义一个足够描述未来的状态，最后才选择数组、缓存或滚动变量。

闭卷检查时，不要先背答案数列。应先说清最后一步为何只有两个来源、两个来源为何不重不漏，以及覆盖旧变量前为何必须先算出当前状态。能把这三件事讲明白，才算真正掌握了本题模型。
