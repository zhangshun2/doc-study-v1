# 11. 盛最多水的容器：从面积公式走到劣势边界淘汰

> **双轨入口：** [[题目/双指针/11-Container-With-Most-Water.md|标准题解]] · [[核心模型/双指针/11-Container-With-Most-Water-核心模型.md|核心模型]]


## 1. 题目档案

- 题号：`11`
- 中文题名：盛最多水的容器
- 英文题名：Container With Most Water
- 难度：`Medium`
- 来源：[LeetCode 题目原页](https://leetcode.cn/problems/container-with-most-water/)
- 标准题解：[11. 盛最多水的容器](../../题目/双指针/11-Container-With-Most-Water.md)
- 清单优先级：`P0`
- 原清单标签：`Two Pointers 双指针`、`Greedy 贪心`
- 本专题的核心模型：面积由距离和较短边共同决定；算完当前最宽候选后，用支配关系安全淘汰较短边。

这篇文章重点解决的不是“记住左右各放一个指针”，而是三个更根本的问题：为什么从最外侧开始，为什么必须移动较短的一边，以及一次移动凭什么代表没有漏掉许多尚未枚举的组合。只有把这三个问题说明白，代码中的 `left++` 或 `right--` 才是模型的结果，而不是需要死记的口诀。

## 2. 完整题目

给定整数数组 `height`，数组长度为 `n`。在二维坐标中，第 `i` 个元素表示位于横坐标 `i` 处的一条竖线，它从 `(i, 0)` 延伸到 `(i, height[i])`。

任选两条竖线，把它们和 `x` 轴看作一个竖直容器的两侧与底部。容器不能倾斜，因此水面只能是水平的，水会从较短的那条边上方溢出。请返回所有选法中能够容纳的最大水量。

输入是一维整数数组 `height`，输出是一个整数，表示最大容积。在本题二维截面模型中，厚度视为 `1`，所以“水量”数值等同于矩形面积。

### 示例 1

```text
输入：height = [1,8,6,2,5,4,8,3,7]
输出：49
```

选择下标 `1` 和 `8`。两边距离为 `8 - 1 = 7`，水面高度由较短边限制为 `min(8, 7) = 7`，所以水量为 `7 * 7 = 49`。

### 示例 2

```text
输入：height = [1,1]
输出：1
```

只有这一对边界，距离为 `1`，限制高度为 `1`，水量为 `1`。

### 示例 3

```text
输入：height = [1,2,4,3]
输出：4
```

最佳边界是下标 `1` 和 `3`：距离为 `2`，限制高度为 `2`，面积为 `4`。这个例子也能检验“总是移动较高边”为什么会漏解。

### 约束

- `n == height.length`
- `2 <= n <= 10^5`
- `0 <= height[i] <= 10^4`
- 容器不能倾斜

Java 入口签名为：

```java
public int maxArea(int[] height)
```

约束给出两个建模信号。第一，至少有两条线，所以一定存在一对合法边界，不需要为空数组定义答案。第二，`n` 可达 `10^5`，全部边界对接近五十亿组，平方级枚举不适合作为最终方案。最大可能乘积小于 `10^5 * 10^4 = 10^9`，在本题约束内 `int` 不会溢出。

## 3. 先把题目说成人话

### 一句话生活化复述

在一排高低不同、间距相同的柱子中选两根做容器边界，希望“柱子之间的距离乘以较矮柱子的高度”尽可能大。

### 一句话关系化复述

从所有下标对 `(left, right)` 中，最大化“下标差”和“两端较小值”的乘积。

先看一个具体对。若 `left = 1`、`right = 8`、两端高度分别为 `8` 和 `7`：

```text
宽度       = right - left                 = 8 - 1 = 7
限制高度   = min(height[left], height[right]) = min(8, 7) = 7
面积       = 宽度 * 限制高度              = 7 * 7 = 49
```

于是任意一对边界的关系公式是：

```text
area(left, right)
= (right - left) * min(height[left], height[right])
```

这里的 `min` 不是代码技巧，而是物理限制：较高边超过较短边的部分挡不住水。

> **小白追问：** 为什么面积高度一定由短边决定，较高的那一边不能多装一部分水吗？
>
> **先给短答：** 水面必须保持水平；只要水位超过短边，多出来的水就会从短边上方流走，因此稳定水位最多等于两边中较小的高度。
>
> **最小例子：** 只有两根线 `[3,8]`，位置分别是 `0` 和 `1`。水位到 `3` 时，两侧都能挡住；水位尝试到 `4` 时，左边高度只有 `3`，高出的一层没有边界，会立刻流走。最终宽度是 `1`，有效高度是 `3`，面积只能是 `1 * 3 = 3`，而不是 `1 * 8 = 8`。
>
> **回到模型/代码：** “水平水面”和“两端共同围住”对应 `limitedHeight = Math.min(height[left], height[right])`。如果误写成 `Math.max`，算出的矩形有一部分没有边界承托，不是题目允许的容器。

### 题目关系图

```text
下标：       left                              right
             |<----------- 距离 ------------->|
高度：       8                                  7
             |                                  |
有效水面：   +==================================+  高度只能到 7
             |                                  |
地面：       +----------------------------------+

面积由两个因素共同决定：
1. 距离 right - left，越宽越有利；
2. 短板 min(height[left], height[right])，越高越有利。
```

| 要素 | 本题中的含义 |
| --- | --- |
| 对象 | 两个有先后顺序的数组下标，以及它们对应的高度 |
| 关系 | 两个下标组成一对边界，分数是距离乘以短板 |
| 方向 | 左边界只能向右换，右边界只能向左换 |
| 目标 | 在所有 `left < right` 的组合中求面积最大值 |
| 限制 | 水平面不能高于短边；移动边界后距离只会缩短 |

## 4. 第一切入点：读题时先看什么

第一次读题，先圈出三个真正决定模型的词：

1. **“两条线”**：答案由一对下标共同决定，不是每个位置单独产生一份水量。
2. **“最多”**：需要比较所有合法边界对的评分，保留全局最大值。
3. **“不能倾斜”**：有效高度必然由较短边限制，面积公式中出现 `min`。

“容器”“水”“垂线”帮助理解公式，但在建立关系后可以先拿掉故事包装。真正的问题是一个离散配对最值：

```text
在有序位置中选 i < j，最大化 (j - i) * min(h[i], h[j])。
```

接着看两个互相竞争的因素。两端离得远，宽度大；两端都高，短板高。只选择最高的两根柱子不一定最好，因为它们可能靠得太近；只选择最远的两根也不一定最好，因为端点可能太矮。

最小样例 `[1, 1]` 告诉我们，宽度是下标差而不是元素个数。稍大的 `[1, 2, 1]` 可以人工列完：

```text
(0, 1): 宽 1，短板 1，面积 1
(0, 2): 宽 2，短板 1，面积 2
(1, 2): 宽 1，短板 1，面积 1
```

最高柱子只参与面积 `1` 的组合，反而最外侧的两根矮柱得到答案 `2`。因此第一分钟应该先写面积关系，再判断能否排除一批组合，不能只盯着“最高”。

> **小白追问：** 指针向内后宽度一定变小，面积为什么还有可能变大？
>
> **先给短答：** 面积是“宽度乘短板”，宽度虽然下降，但如果新的短板升高得更多，乘积仍然可能变大。
>
> **最小例子：** 对 `[1,3,4]`，最外侧 `(0,2)` 的宽度是 `2`、短板是 `1`，面积为 `2`。左边向内来到 `(1,2)` 后，宽度降为 `1`，短板却从 `1` 升到 `3`，面积变成 `3`。缩短的一格宽度被更高的短板补偿了。
>
> **回到模型/代码：** `width` 每轮只会减小，但 `limitedHeight` 可能升高，因此代码必须重新计算 `currentArea` 并与 `bestArea` 比较。移动短边是在争取提高 `limitedHeight`，不是假设下一轮面积一定更大。

最后看数据规模。`n = 10^5` 意味着“两层循环试完所有对”虽然正确，却最多要计算约 `n(n-1)/2` 次。我们需要寻找一种每一步都能永久排除候选的关系。

## 5. 最直接的人工或暴力模型

在不知道更优结构时，最可靠的模型就是枚举所有下标对：

```text
best = 0
对每个 left，从 0 到 n - 2：
    对每个 right，从 left + 1 到 n - 1：
        width = right - left
        limitedHeight = min(height[left], height[right])
        currentArea = width * limitedHeight
        best = max(best, currentArea)
返回 best
```

它一定正确，因为任何合法答案都恰好对应某个 `left < right` 的下标对。外层循环会到达这个 `left`，内层循环会到达这个 `right`，面积会被计算并与 `best` 比较。不存在未被枚举的合法组合。

这一步有重要价值：它确定了正确的评分函数、合法候选的全集，以及后续优化不能破坏的底线。优化不是换一个答案定义，而是设法不亲自计算那些已经能证明不会更优的下标对。

令 `n` 表示数组长度。合法边界对数量是：

```text
(n - 1) + (n - 2) + 逐项递减到 1 = n(n - 1) / 2
```

每对只做常数次取值、比较和乘法，所以时间复杂度是 `O(n^2)`。除循环变量和最大值外不申请随 `n` 增长的存储，额外空间复杂度是 `O(1)`。

## 6. 暴力到底浪费在哪里

这道题的暴力并没有重复计算同一对下标。它真正浪费的是：已经有数学上足够的信息证明某些组合不可能更好，却仍逐个验证这些组合。

用示例数组观察最外侧 `(0, 8)`：

```text
下标：  0  1  2  3  4  5  6  7  8
高度：  1  8  6  2  5  4  8  3  7
        L                       R

当前面积 = (8 - 0) * min(1, 7) = 8
```

左边界高度是 `1`。如果保留下标 `0`，把右边界换成任意内部位置 `k`：

```text
有效高度 <= 1          因为左边仍然只有 1 高
新宽度   = k - 0 < 8   因为 k 在 8 的左侧
新面积   <= 1 * 7 < 8  高度没有上升空间，宽度却缩短
```

因此 `(0,1)` 到 `(0,7)` 全部已被当前 `(0,8)` 支配。暴力算法之后仍会计算这七对，这些就是可以一次跳过的无效候选。

移动到 `(1,8)` 后：

```text
当前面积 = (8 - 1) * min(8, 7) = 49
```

这次右边界 `8` 较短。保留下标 `8`，让左边界从 `1` 向右走，距离只会更短，而限制高度仍不超过 `7`。所以 `(2,8)` 到 `(7,8)` 也都不可能超过 `49`，右边界 `8` 可以整批淘汰。

这里出现了优化目标：

> 每次计算当前最宽的一对后，不再逐个验证共享较短边的内部组合，而是用“宽度变小且短板上限不升”的支配关系，一次永久淘汰这条较短边。

这比“想办法少一层循环”更具体，因为它说明了少算哪些候选，以及为什么可以少算。

## 7. 容易想到但走不通的方向

### 方向一：只选最高的两根线

这个想法自然，因为面积需要高短板。问题是它只保存高度，丢失了距离。`[1,2,1]` 中最高的 `2` 与任意相邻柱面积都是 `1`，而两端的两个 `1` 面积是 `2`。它不是性能问题，而是建模信息不足导致结论错误。

得到的新条件是：任何可行模型都必须同时保留位置和高度，不能把其中一个因素单独排序后决定答案。

### 方向二：按高度排序后再找两根

排序似乎能让“高柱优先”，但原数组下标决定宽度。若只排序高度，原位置关系被破坏；即使同时携带原下标，也没有自然办法只看相邻高度就排除其他位置组合，仍可能退回枚举许多对。它可以保留正确所需的信息，却没有提供更强的淘汰关系，并额外付出 `O(n log n)` 排序成本。

得到的新条件是：我们需要利用原位置的有序性，让未处理区间单向缩小。

### 方向三：每次同时向中间移动两边

“宽度已经最大，下一轮就一起收缩”看起来对称，但一次删除两条边可能跳过最佳的交叉组合。示例 1 第一轮是 `(0,8)`，若同时移动就直接来到 `(1,7)`，从未计算最佳组合 `(1,8)`，答案 `49` 会被漏掉。

得到的新条件是：一轮只能删除已经被证明劣势的一侧，不能因为图形对称就同时删除两个未经证明的候选边界。

### 方向四：移动较高的一边，保留较短的一边

有人会觉得高边“富余”，先换掉它损失较小。实际恰好相反：短边才是当前面积的高度上限。保留短边时，无论换来的另一边多高，有效高度仍不会超过旧短边，而宽度一定缩短。

数组 `[1,2,4,3]` 是一个反例：

```text
起点 (0,3)：面积 3，右边高度 3 较高
若移动高边：来到 (0,2)，面积 2
继续移动高边：来到 (0,1)，面积 1
错误结果：3
真实最优：(1,3)，面积 2 * min(2,3) = 4
```

得到的新条件是：要争取更大面积，宽度已经不可避免地变小，唯一可能补偿宽度损失的因素是提高短板，所以必须让当前短板离场。

> **小白追问：** 能不能比较当前面积大小，再决定下一步移动哪一边？
>
> **先给短答：** 不能。当前面积只描述这一对边界的成绩，没有告诉我们哪一侧限制了未来；移动方向必须由两端高度关系决定。
>
> **最小例子：** `[1,2,4,3]` 的外侧 `(0,3)` 面积是 `3`。如果因为面积看起来不小而保留左边、移动右边，接下来只能得到 `2` 和 `1`；移动短的左边则到达 `(1,3)`，得到面积 `4`。同一个当前面积不能替代“左高还是右高”这条信息。
>
> **回到模型/代码：** `currentArea` 只参与 `bestArea = Math.max(...)`，不参与移动条件。真正控制分支的是 `height[leftBoundary] < height[rightBoundary]`，因为这次比较识别了当前的瓶颈边界。

## 8. 关键视角转换

暴力的视角是“选定一个左边，再寻找所有右边”。优化后的视角是“面对当前仍可能产生最优解的最外层区间，算完最宽组合，然后证明一整行或一整列候选可以删除”。

候选对可以想成一个上三角表。行是左边界，列是右边界：

```text
             right
          1  2  3  4
left  0   x  x  x  x
      1      x  x  x
      2         x  x
      3            x

每个 x 是一对 (left, right)。
暴力逐个访问所有 x。
优化模型每次访问当前未处理区域的右上角，
然后证明可以删除它所在的一整行或一整列。
```

设当前边界为 `L` 和 `R`，且 `height[L] <= height[R]`。当前面积是：

```text
A(L, R) = (R - L) * height[L]
```

对任何内部右端点 `k`，其中 `L < k < R`：

```text
A(L, k)
= (k - L) * min(height[L], height[k])
<= (k - L) * height[L]
<= (R - L) * height[L]
= A(L, R)
```

第一处“不大于”来自短板不会高于 `height[L]`，第二处来自内部距离不会大于当前距离。当前面积已经写入 `best`，所以所有仍使用 `L` 的内部组合都不可能改善答案。`L` 可以永久删除。

> **小白追问：** “移动短边”为什么是唯一有希望的动作，而不只是经验上更常成功？
>
> **先给短答：** 保留短边时，高度上限被锁死，向内移动另一边又只会缩短宽度；只有换掉短边，新的短板才有机会升高并补偿宽度损失。
>
> **最小例子：** 在 `[2,9,4,8]` 的外侧 `(0,3)`，面积为 `3 * 2 = 6`。保留高度 `2` 的左边，右边无论换到高度 `4` 还是 `9`，面积分别只有 `2 * 2 = 4`、`1 * 2 = 2`。让左边离场后，`(1,3)` 的短板升到 `8`，面积变成 `2 * 8 = 16`。
>
> **回到模型/代码：** 当 `height[leftBoundary] < height[rightBoundary]` 时执行 `leftBoundary++`。这句代码不保证下一轮更大，只保证删除的是已经没有翻身可能的一侧，并保留唯一可能提高瓶颈的搜索方向。

> **小白追问：** 左指针移动一次，究竟淘汰了哪些配对，是否把整个区间都跳过了？
>
> **先给短答：** 它只淘汰“旧左端点与所有内部右端点”的这一组配对；两个端点都在新区间内的组合仍然保留。
>
> **最小例子：** 对下标 `0..3` 的 `[2,5,4,7]`，先算 `(0,3)`。左边较短，于是删除的是 `(0,1)`、`(0,2)` 以及已经算过的 `(0,3)` 这一行。`(1,2)`、`(1,3)`、`(2,3)` 仍位于新区间 `[1,3]`，后续没有被跳过。
>
> **回到模型/代码：** `leftBoundary++` 表示下标 `0` 永久失去“左边界资格”，不是丢弃数组中间的所有组合。不变量中的 `[leftBoundary,rightBoundary]` 正是剩余候选两个端点都必须落入的范围。

这也直接回答“为什么移动长边无收益”。仍保留短边 `L`、只把长边 `R` 向内移动时，短板上限不变，距离却缩小；无论新长边有多高，都无法突破 `height[L]`。移动长边不是一次有潜力的尝试，而是在保留当前瓶颈的同时主动减少另一个正因素。

当右边较短时，论证完全对称，删除 `R`。于是转换后的工作方式是：

```text
转换前：枚举一对 -> 算面积 -> 再枚举下一对
转换后：算当前最宽一对 -> 找到限制因素 -> 淘汰限制因素代表的整批候选
```

每轮至少永久删除一个下标作为边界的资格，未处理区间单向缩小，平方级候选不再需要逐个出现。

## 9. 正式建立模型

经过前面的关系和淘汰证明，现在才给这种控制方式命名：用两个相向移动的边界指针维护尚未排除的区间，并以贪心方式淘汰较短边。

| 建模项 | 本题结论 |
| --- | --- |
| 对象 | 当前未被排除区间的左边界 `left` 和右边界 `right` |
| 关系 | 一对边界的面积等于距离乘以两端短板 |
| 状态 | `left`、`right` 和已经见过的最大面积 `bestArea` |
| 事件 | 当前边界对完成面积计算后，比较两端高度 |
| 不变量 | 区间外的边界组合已经被计算或已证明不可能超过 `bestArea`；任何仍可能改善答案的未计算组合都完整位于 `[left, right]` 内 |
| 结果时机 | 每轮移动边界之前，用当前两端计算面积并更新 `bestArea` |

状态只需要三个整数。原数组已经能按下标提供高度，不必复制元素；过去计算过的每一对也不必保存，因为未来只关心其中最大值。被淘汰边界不会重新获得资格，所以指针没有回退需求。

遍历必须从最外侧开始，因为当前 `(left, right)` 需要是所有未处理组合中宽度最大的那一对。只有这样，当高度上限不升时，才能断言换成内部端点不会更好。若随意从中间开始，外侧可能有更大距离，上述支配式就失去依据。

> **小白追问：** 为什么一定从数组两端开始，不能先挑中间看起来较高的两根？
>
> **先给短答：** 淘汰证明需要“当前配对已经是这个短边能获得的最大宽度”；只有从未处理区间的最外侧取端点，才拥有这个前提。
>
> **最小例子：** `[4,9,9,4]` 中间 `(1,2)` 的短板很高，但宽度只有 `1`，面积是 `9`；最外侧 `(0,3)` 的短板只有 `4`，宽度为 `3`，面积是 `12`。如果先从中间出发，就无法用宽度上界排除外侧配对。
>
> **回到模型/代码：** 初始化必须是 `leftBoundary = 0`、`rightBoundary = height.length - 1`。之后每次内移都让新区间的两端继续保持“该区间内最宽配对”这一证明前提。

每轮遵循固定顺序：

```text
1. 读取当前 left 和 right 的高度。
2. 计算当前面积并更新 bestArea。
3. 若左边更短，left 向右移动一格。
4. 否则 right 向左移动一格。
5. 重复，直到 left == right。
```

### 相等高度怎么处理

若 `height[left] == height[right] == H`，当前面积是 `(right-left) * H`。

- 保留左边、右边内移：有效高度不超过 `H`，宽度更小，不会更优。
- 保留右边、左边内移：结论相同。

因此任意淘汰一边都安全。本文代码统一进入 `else` 分支移动右边，目的是让规则确定且保证每轮恰好缩小一次区间。理论上等高时同时移动两边也不会漏掉比当前面积更大的方案，因为所有使用任一旧边界的内部组合都已被当前组合支配；但统一只移动一边更容易保持、跟踪和复用循环不变量。

> **小白追问：** 两端相等时凭什么移动任意一侧，万一最佳答案正好需要被移动的那根呢？
>
> **先给短答：** 等高时两边都是同一个高度上限；保留任意旧端点再向内配对，只会让宽度变小，短板不会超过原高度，因此不可能超过当前面积。
>
> **最小例子：** `[5,1,5]` 的外侧 `(0,2)` 面积是 `2 * 5 = 10`。删除右端后，仍用左端的 `(0,1)` 只有 `1 * 1 = 1`；删除左端后，仍用右端的 `(1,2)` 也只有 `1`。两侧各自关联的未算组合都不可能优于 `10`。
>
> **回到模型/代码：** 分支使用严格小于号；相等时进入 `else` 执行 `rightBoundary--`。选择右侧只是固定实现规则，安全性来自等高时左右两边都满足同一条支配证明。

## 10. 所需数据结构详解

这道题不需要栈、队列、哈希表或树。真正需要的是数组的随机访问能力，加上两个边界下标和一个最大值变量。这里的“双指针”不是一种新的容器，而是一种用少量下标组织搜索状态的方法。

### 数组：保留位置与高度的有序映射

数组内部按连续下标组织元素，本题使用两个操作：

- 通过 `height[left]` 和 `height[right]` 随机读取端点高度，单次是 `O(1)`。
- 通过下标差 `right - left` 直接得到两条线的距离，单次是 `O(1)`。

数组的关键特征不是“能存很多数”，而是高度与原始位置绑定且可以常数时间访问任一端点。排序后的集合会改变位置顺序，链表虽然能表示顺序，却不方便直接得到原下标差；栈和队列只能方便访问一端，也没有提供本题所需的支配淘汰能力。

数组保存的是**高度值**，两个边界变量保存的是**下标**。不能把 `height[left]` 当成边界位置，也不能用 `right - left + 1` 当宽度。

> **小白追问：** 为什么必须保存下标，只记住左右高度不够吗？
>
> **先给短答：** 高度只能确定短板，面积还需要两条线之间的距离；距离来自位置差，不能由两个高度反推。
>
> **最小例子：** `[4,1,4]` 的两根高度 `4` 位于下标 `0` 和 `2`，面积是 `2 * 4 = 8`。若数组是 `[4,4,1]`，同样出现两个高度 `4`，但它们位于下标 `0` 和 `1`，面积只有 `1 * 4 = 4`。只保存值会把这两个不同配对误认为相同。
>
> **回到模型/代码：** `leftBoundary`、`rightBoundary` 保存身份和位置，`height[...]` 才读取对应高度；`width = rightBoundary - leftBoundary` 明确使用下标而不是高度差。

### 两个边界下标：表示尚未排除的候选范围

`left` 初始为 `0`，`right` 初始为 `n - 1`。它们支持的操作只有比较、读取和单步内移，都是 `O(1)`。

- 什么时候加入：方法开始时建立两个边界。
- 什么时候更新：当前面积已经结算，且较短边代表的所有内部组合已被证明受支配时。
- 更新是否直接产生答案：不产生；答案必须在更新前由当前边界对计算，更新动作负责缩小未来候选范围。
- 最坏保存多少数据：始终只有两个下标，与 `n` 无关。

两个指针的关键特征是**单调性**：`left` 只增不减，`right` 只减不增。一个已淘汰下标不会回来，因此每个下标最多经历一次离场。

> **小白追问：** “双指针”是不是会把所有剩余配对保存起来，为什么两个整数就够？
>
> **先给短答：** 不需要记住每个配对；两个指针只画出尚未排除的连续下标范围，历史成绩由一个最大值压缩保存。
>
> **最小例子：** `[1,3,2,4]` 初始范围是 `[0,3]`。淘汰下标 `0` 后，只需把左边界改成 `1`，剩余候选自然都落在 `[1,3]` 中；无需额外列出 `(1,2)`、`(1,3)`、`(2,3)` 三个配对。
>
> **回到模型/代码：** `leftBoundary` 和 `rightBoundary` 表示未来范围，`bestArea` 表示过去结果。三者分别回答“还去哪找”和“目前最好是多少”，没有必要建立候选列表或额外集合。

### 最大值变量：压缩全部历史结果

`bestArea` 保存所有已经明确计算过的边界对中的最大面积。更新是 `max` 操作，单次 `O(1)`。由于后续只问全局最大值，不需要保存每轮面积列表。最坏情况下仍只占一个整数。

| 模型需要的能力 | 使用的状态 | 为什么足够 |
| --- | --- | --- |
| 常数时间读取两端高度 | 原数组 | 下标与高度绑定，不改变顺序 |
| 表示未排除区间 | `left`、`right` | 支配证明保证区间只需向内缩小 |
| 保存历史最优 | `bestArea` | 题目只返回最大值，不需要恢复全部路径 |

## 11. 生活化类比及边界

可以把问题想成安装一块矩形广告布。街边有一排位置固定、高度不同的立柱，广告布左右两端各挂在一根柱上。布的宽度是两柱距离，能挂起的完整矩形高度由较短柱决定，希望广告布面积最大。

先尝试最远的两根柱。若左柱较短，保留左柱而把右柱换成更近的任意柱，布的宽度必然变小；即使新右柱很高，布的高度仍被旧左柱卡住。因此应该放弃左柱，尝试下一根可能更高的左柱。这不是“较短柱看起来不好”，而是它与所有更近搭档的成绩上限已经被当前最远搭档覆盖。

| 生活对象或动作 | 算法中的对应物 |
| --- | --- |
| 一排位置固定的立柱 | 按原下标排列的 `height` 数组 |
| 当前选择的左右立柱 | `left` 和 `right` 两个下标 |
| 两柱距离 | `right - left` |
| 广告布能达到的高度 | `min(height[left], height[right])` |
| 当前广告布面积 | `currentArea` |
| 已见过的最大广告布 | `bestArea` |
| 放弃较短柱 | 淘汰该边界并向内移动相应指针 |
| “更近搭档不会救活旧短柱” | 支配关系与循环不变量 |

类比到这里为止。现实广告布还可能受柱子承重、材料成本、地形、柱宽和安装顺序影响，本题都没有这些变量。“移动指针”也不是把实体柱子挪位置，而是从候选集合中永久放弃某个原下标。生活故事帮助记住瓶颈和距离的竞争，安全淘汰仍要由不等式证明。

> **小白追问：** 广告布类比听起来已经合理了，为什么还不能直接当作算法正确性的证明？
>
> **先给短答：** 类比只帮助看见“距离”和“短板”，却没有严格限定所有候选；证明还必须说明每个被跳过的下标对都不可能更优。
>
> **最小例子：** `[2,100,3]` 可以想成三根广告柱，但现实中也许能裁斜布、加支架或移动柱子，这些动作会改变答案。题目只允许选原位置的两根线，并用水平矩形计算，因此必须回到 `(right-left) * min(...)` 比较。
>
> **回到模型/代码：** 类比用于理解变量，真正支持指针移动的是第 8、14 节的不等式。代码执行 `leftBoundary++` 前，需要的是支配上界，而不是“短柱看起来应该换掉”的生活感觉。

```text
           ^                    ^

原因：任何 (0,k) 的短板不超过 1，宽度又小于 8。
```

```text
第 2 轮后：得到 49，并淘汰下标 8

           ^                 ^
```


当 `left == right == 1` 时已经无法选出两个不同下标，循环结束。最大值 `49` 在第二轮产生，后续轮次的职责不是“找一个看起来更高的柱子”，而是完成剩余候选的安全排除。

> **小白追问：** 第二轮已经得到很大的 `49`，为什么不能立刻返回，还要继续缩小区间？
>
> **先给短答：** `bestArea` 只证明它是“目前最大”，没有证明它是“所有未处理组合的上界”；在剩余候选被计算或安全淘汰前不能提前结束。
>
> **最小例子：** `[1,8,7]` 第一轮外侧 `(0,2)` 得到面积 `2`，如果觉得已有结果就返回，会漏掉下一轮 `(1,2)` 的面积 `7`。当前最大值本身不提供停止条件。
>
> **回到模型/代码：** 唯一通用终止条件是 `leftBoundary == rightBoundary`，此时不足两个下标。`bestArea` 负责记录成绩，`while` 的边界条件负责确认候选是否已经处理完，两者职责不同。

## 13. 边界场景的数据变化

### 全部相等：`[5,5,5]`

```text
下标：  0  1  2
高度：  5  5  5
        ^     ^
       left right

第 1 轮：宽 2，短板 5，面积 10，best = 10
          两边等高，代码移动 right，状态变为 [0,1]
第 2 轮：宽 1，短板 5，面积 5，best 保持 10
          两边等高，再移动 right，状态变为 [0,0]
结束：只有一个下标，不能再组成容器，返回 10
```

等高不会让循环停住，因为代码的 `else` 明确覆盖相等情况。移动右边没有漏掉 `(1,2)`：它的宽度只有 `1`，短板仍是 `5`，面积不可能超过已经记录的 `10`。移动左边也会得到同样结论。

### 高度为零：`[0,0]`

```text
初始状态：[left=0, right=1, best=0]
当前面积：1 * min(0,0) = 0
动作：等高，right--
结束状态：[left=0, right=0, best=0]
```

循环执行一次，不会越界，返回默认值 `0`。此处支配关系是“不超过”而不是必须“严格小于”：所有候选面积都可能同为 `0`，但题目只求最大数值，不要求找出全部最佳边界，所以丢弃相同成绩的组合是安全的。

> **小白追问：** 被淘汰组合可能和当前组合面积相等，为什么也能删除？
>
> **先给短答：** 题目只要求最大面积数值，不要求返回所有达到最大值的下标对；已经记录一个相同数值后，再保留并列方案不会改变输出。
>
> **最小例子：** `[0,0,0]` 中 `(0,2)`、`(0,1)`、`(1,2)` 的面积都为 `0`。外侧配对先把 `0` 记入 `bestArea`，之后删掉一个端点，即使跳过另一个同为 `0` 的配对，最终最大值仍是 `0`。
>
> **回到模型/代码：** 证明使用 `<= bestArea` 就足够，不需要严格 `< bestArea`。若题目改成返回全部最佳下标对，状态和删除规则都要扩展，当前代码不能直接照搬。

> **小白追问：** 数组里从 `left` 到 `right` 有 `right-left+1` 个元素，宽度为什么只写 `right-left`？
>
> **先给短答：** 宽度是两个横坐标之间的距离，不是闭区间里包含多少个数组位置。
>
> **最小例子：** `[5,5]` 有两个元素，下标是 `0` 和 `1`。两条线之间只有 `1-0=1` 个单位的水平距离，所以面积是 `1 * 5 = 5`；若写 `+1` 会得到不存在的宽度 `2`。
>
> **回到模型/代码：** `width = rightBoundary - leftBoundary` 对应坐标差。`+1` 常用于统计闭区间元素个数，但本题的几何距离不采用那个公式。

本题没有空数组和单元素输入，因为 `n >= 2`。若把模板迁移到没有这项约束的业务场景，应先定义非法输入策略，不能把本题前提默默带过去。

## 14. 正确性与不变量

要证明的不是“移动短边通常更好”，而是：每次删除较短边时，所有可能比当前答案更好的候选仍被保留。

### 循环不变量

每轮开始时保持两件事：

1. `bestArea` 是所有已经实际计算过的边界对中的最大面积。
2. 任何尚未计算且仍可能超过 `bestArea` 的边界对，其两个下标都位于当前闭区间 `[left, right]` 内。

初始时 `[left, right] = [0, n-1]` 覆盖全部下标，`bestArea = 0`。高度非负，所以两条不变量成立。

### 当前结果为什么合法

循环条件保证 `left < right`，两条边界是不同下标。宽度 `right-left` 为正，限制高度取两端较小值，正好符合水平水面不能越过短板的题目条件，因此每轮写入 `bestArea` 的都是合法容器面积。

### 删除较短边为什么安全

假设 `height[left] <= height[right]`。更新 `bestArea` 后，考虑任何仍使用当前左边界、但右端更靠内的组合 `(left, k)`：

```text
k - left <= right - left
min(height[left], height[k]) <= height[left]

所以：
area(left, k)
<= (right - left) * height[left]
= area(left, right)
<= bestArea
```

因此没有任何使用旧 `left` 的未计算组合能够改善答案，`left` 可以删除。所有不使用旧 `left` 的内部组合仍完整位于 `[left+1, right]` 中，所以第二条不变量继续成立。若右边更短，交换左右角色即可得到相同结论。

> **小白追问：** 这里说的“支配”到底是什么意思，为什么一个当前配对能代表许多没算过的配对？
>
> **先给短答：** 支配表示另一个候选的每个有利因素都不可能超过当前候选，因此它的最终成绩也不可能更高，可以不再单独计算。
>
> **最小例子：** `[2,6,5,7]` 的 `(0,3)` 宽度是 `3`、短板是 `2`、面积是 `6`。仍使用左端 `0` 的 `(0,2)` 宽度降为 `2`，短板最多仍是 `2`，面积至多 `4`；`(0,1)` 宽度只有 `1`，面积至多 `2`。它们在宽度和短板上都没有翻盘入口。
>
> **回到模型/代码：** 代码先把 `currentArea` 写入 `bestArea`，再移动较短边。只有“当前成绩已经记账”和“被删配对上界不超过当前成绩”同时成立，`leftBoundary++` 或 `rightBoundary--` 才是安全删除。

### 为什么移动长边没有收益

仍假设左边较短。若先移动右边而保留左边，宽度会减少，但短板的上限仍是 `height[left]`。新右边更矮时短板还会下降，新右边更高时也只能与旧短板持平。这个动作无法产生比当前容器更大的面积，却没有淘汰真正限制高度的左边。更严重的是，如果算法一直按这个规则移动高边，就可能像 `[1,2,4,3]` 一样错过 `(1,3)`。

> **小白追问：** 保留短边、移动长边，为什么不可能找到更优配对？
>
> **先给短答：** 固定短边后，新配对的高度至多等于这根短边，而新宽度严格更小；两个乘积因素一个不升、一个下降，面积必然不超过当前值。
>
> **最小例子：** `[2,100,3]` 的外侧 `(0,2)` 面积是 `2 * 2 = 4`。保留左侧高度 `2`、把右边移到高度 `100`，看似换来了高柱，但短板仍是 `2`，宽度降为 `1`，面积只剩 `2`。高出的 `98` 完全没有进入有效水位。
>
> **回到模型/代码：** 当左侧更短时，代码不会执行 `rightBoundary--`，而执行 `leftBoundary++`。判断依据不是预测下一根柱子的高度，而是旧左边界参与的所有内部配对已有统一上界。

### 等高为什么任移一边

当两端同为 `H`，当前面积为 `(right-left)*H`。任何保留左端或保留右端的内部组合，宽度都更小，短板都不超过 `H`，因此两侧各自关联的内部组合都不会超过当前面积。删除任意一侧都维持不变量。代码删除右侧只是确定性的实现选择。

### 为什么不会漏掉全局最优

每轮先实际计算当前边界对，再删除一个已经证明不可能参与更优答案的边界。于是任意全局最优对只有两种命运：

- 它在某轮成为当前两端，被实际计算；
- 它的某个端点被删除，但删除证明说明该最优值不超过当轮已经写入的 `bestArea`。

无论哪种情况，最终 `bestArea` 都不会小于全局最优；同时 `bestArea` 只来自合法边界对，又不可能大于全局最优，所以二者相等。

> **小白追问：** 算法没有枚举所有配对，怎么保证某个藏在中间的最优配对不会被提前跨过去？
>
> **先给短答：** 每次跨过一个端点前都有删除证书：若最优配对使用这个端点，它的值已不超过当前记录；若不使用，它的两个端点仍留在新区间。
>
> **最小例子：** `[1,3,2,4]` 先计算 `(0,3)=3`，左端 `0` 被删除，但真正最优 `(1,3)=6` 不使用下标 `0`，仍完整留在 `[1,3]`。下一轮它成为当前边界对并被计算。算法跨过的是已证明无用的端点，不是随意跨过中间答案。
>
> **回到模型/代码：** `while` 每轮只移动一侧一格，另一侧保持不动。配合“移动前先更新 `bestArea`”，任意最优对要么实际到达，要么在端点被删时已有不小于它的合法面积被记录。

### 为什么算法一定结束

每轮恰好执行 `left++` 或 `right--`，区间长度 `right-left` 减少 `1`，且指针不会回退。最多经过 `n-1` 轮就有 `left == right`。此时区间内不足两个下标，不存在尚未处理的合法边界对。结合不变量，所有可能改善答案的候选都已计算或被安全支配。

## 15. 时间与空间复杂度推导

令 `n` 表示 `height` 的长度。

### 直接模型

直接模型枚举全部 `left < right`：

```text
候选对数量 = n(n - 1) / 2
每对成本   = 一次下标差、两次数组读取、常数次比较与乘法
总时间     = O(n^2)
```

它只使用两个循环下标、当前面积和最大面积，不把候选对保存起来，所以额外空间为 `O(1)`。输入数组不算额外空间，返回值是一个标量。

### 推荐模型

初始化左右边界是 `O(1)`。每轮执行常数次数组读取、比较、乘法和赋值，然后恰好移动一个指针。初始间距是 `n-1`，每轮间距减少 `1`，所以循环精确执行 `n-1` 次：

```text
总时间 = (n - 1) * O(1) = O(n)
```

从元素生命周期看，一个下标可能先作为当前边界参与若干轮吗？左指针固定时右指针可能多次移动，所以同一个左边界会参与多轮；但每一轮都会让某一侧的一个下标永久离场。总离场次数最多 `n-1`，不会出现边界回退或重新入场。因此即使从“淘汰次数”计数，总操作仍是线性的。这里没有隐藏的内层循环，不需要依靠模糊的均摊说法，轮数可以直接精确界定。

> **小白追问：** 同一个边界可能参加多轮，时间复杂度为什么仍是 `O(n)`？
>
> **先给短答：** 复杂度按总轮数计数，不按某个下标被读取几次猜测；每轮都让左右距离减少一，距离只能从 `n-1` 减到零。
>
> **最小例子：** `[1,8,6,2,5]` 有 `5` 个元素，初始距离是 `4`。无论每轮移动左边还是右边，距离都会依次变为 `3、2、1、0`，因此恰好执行 `4` 轮。某个左端可能重复出现，但每次重复都伴随另一个端点永久离场。
>
> **回到模型/代码：** `while (leftBoundary < rightBoundary)` 内只有一个 `if/else`，且每轮恰好执行一次 `leftBoundary++` 或 `rightBoundary--`。没有回退，也没有第二个扫描，所以总时间是 `O(n)`。

推荐模型只维护 `left`、`right`、`bestArea` 和少量本轮临时变量，数量不随 `n` 增长，额外空间复杂度是 `O(1)`。

> **小白追问：** 输入数组可能有十万个元素，为什么空间复杂度还能写成 `O(1)`？
>
> **先给短答：** 额外空间只计算算法为了工作新申请的存储；传入的 `height` 已经存在，算法没有复制它，也没有创建随长度增长的集合。
>
> **最小例子：** 输入 `[1,3,2]` 时保存左右下标、最佳面积和本轮临时值；输入扩成 `[1,3,2,5,4]` 时仍是同一组变量，并不会多建两个槽位。变量数保持固定。
>
> **回到模型/代码：** `leftBoundary`、`rightBoundary`、`bestArea`、`width`、`limitedHeight`、`currentArea` 都是固定数量的标量。返回值也是一个整数，因此额外空间为 `O(1)`。

在本题约束下最大面积小于 `10^9`，Java `int` 足够。若迁移到更大的坐标或高度范围，乘法应先转为 `long`，否则复杂度不变但可能出现整数溢出。

### 第一层：距离乘瓶颈值的边界淘汰骨架

下面的骨架不依赖等距下标，接受严格递增的位置数组和对应容量数组。只要一对对象的评分是“距离乘以两端较小容量”，相同支配证明就成立。所有调用都在类内定义，没有隐藏方法。

```java
final class BottleneckBoundarySweep {
    private BottleneckBoundarySweep() {
    }

    static long maximize(long[] positions, long[] capacities) {
        if (positions == null || capacities == null
                || positions.length != capacities.length
                || positions.length < 2) {
            throw new IllegalArgumentException(
                    "positions and capacities must have the same length of at least 2");
        }

        for (int i = 1; i < positions.length; i++) {
            if (positions[i] <= positions[i - 1]) {
                throw new IllegalArgumentException(
                        "positions must be strictly increasing");
            }
        }
        for (long capacity : capacities) {
            if (capacity < 0L) {
                throw new IllegalArgumentException(
                        "capacities must be non-negative");
            }
        }

        int leftBoundary = 0;
        int rightBoundary = positions.length - 1;
        long bestScore = 0L;

        while (leftBoundary < rightBoundary) {
            long distance = positions[rightBoundary] - positions[leftBoundary];
            long bottleneck = Math.min(
                    capacities[leftBoundary], capacities[rightBoundary]);
            long currentScore = distance * bottleneck;
            bestScore = Math.max(bestScore, currentScore);

            // 保留当前短板只会缩短距离，因此淘汰短板才可能提高瓶颈。
            if (capacities[leftBoundary] < capacities[rightBoundary]) {
                leftBoundary++;
            } else {
                rightBoundary--;
            }
        }

        return bestScore;
    }
}
```

这个骨架的适用前提不能省略：位置必须有序；向内移动必须让距离不增；评分中的容量必须由两端较小值限制。如果评分改成两端之和、内部最大值或可以倾斜的高度，这个淘汰规则不再自动成立，必须重新证明。

> **小白追问：** Java 循环里为什么必须先计算面积，再移动指针？
>
> **先给短答：** 当前两端本身也是一个合法候选；先移动会让它从未被记录，若它恰好最优，答案就会永久丢失。
>
> **最小例子：** `[5,1,5]` 的最外侧面积是 `10`，也是全局最优。若等高时先执行 `right--`，再计算 `(0,1)`，只能得到面积 `1`；之后指针相遇，面积 `10` 再也没有机会出现。
>
> **回到模型/代码：** 正确顺序是先计算 `currentScore`、更新 `bestScore`，再进入高度比较分支。题目代码中的 `currentArea`、`bestArea` 和指针更新也必须保持同样顺序。

### LeetCode 可直接提交代码

下面只保留题目要求的 `Solution` 入口，可直接提交。它使用 `int` 是因为题目约束下最大面积不会溢出 `int`。

```java
public class Solution {
    public int maxArea(int[] height) {
        int leftBoundary = 0;
        int rightBoundary = height.length - 1;
        int bestArea = 0;

        while (leftBoundary < rightBoundary) {
            int width = rightBoundary - leftBoundary;
            int limitedHeight = Math.min(
                    height[leftBoundary], height[rightBoundary]);
            int currentArea = width * limitedHeight;
            bestArea = Math.max(bestArea, currentArea);

            // 当前面积结算后，共享较短边的内部组合已被当前组合支配。
            if (height[leftBoundary] < height[rightBoundary]) {
                leftBoundary++;
            } else {
                rightBoundary--;
            }
        }

        return bestArea;
    }
}
```

| 模型角色 | Java 变量或代码块 |
| --- | --- |
| 当前对象 | `leftBoundary` 与 `rightBoundary` 指向的两条线 |

| 历史压缩状态 | `bestArea` |
| 触发条件 | `height[leftBoundary] < height[rightBoundary]` |
| 状态变化 | 较短在左则 `leftBoundary++`，否则 `rightBoundary--` |
| 结果时机 | 移动边界前执行 `bestArea = Math.max(bestArea, currentArea)` |
| 终止条件 | `leftBoundary == rightBoundary`，无法再组成一对不同边界 |

> **小白追问：** 代码里的 `if` 是否在贪心地选择下一轮面积更大的方向？
>
> **先给短答：** 不是。算法不知道下一轮面积会变大还是变小；`if` 只负责删除已经证明不可能改善答案的边界。
>
> **最小例子：** `[1,4,3]` 先算外侧面积 `2`，左边较短，于是左移；下一轮 `(1,2)` 面积变成 `3`。而 `[1,2,1]` 同样先移动左边，下一轮面积却从 `2` 降到 `1`。动作相同，下一轮走势不同，说明分支不是局部预测器。
>
> **回到模型/代码：** `bestArea` 负责吸收每轮实际成绩，`if/else` 负责维护候选范围。调试时应检查“删除是否安全”，而不是要求每轮 `currentArea` 单调上升。

## 17. 边界、常见错误与调试观察点

### 建模错误

| 错误 | 后果 | 修正问题 |
| --- | --- | --- |
| 只寻找最高的两根线 | 忽略距离，可能得到错误答案 | 每个候选的两个乘积因素是否都保留了？ |
| 把每次移动理解为追逐更高柱 | 无法解释为何不会漏解 | 当前动作淘汰了哪些组合，支配上界是什么？ |
| 看到左右边界就机械套模板 | 评分函数变化时仍错误移动 | 固定一侧、另一侧向内后，评分是否一定不增？ |
| 认为贪心只需“局部看起来合理” | 缺少全局正确性 | 被删除候选未来为什么也不可能翻身？ |

### 条件错误

- **移动较高边**：在 `[1,2,4,3]` 上会返回 `3` 而不是 `4`。
- **先移动再计算**：最外侧组合从未进入答案，可能漏掉最佳边界。
- **两个独立 `if` 都在一轮执行**：若移动左边后再次读取条件并移动右边，可能一轮删除两侧且状态含义混乱。
- **相等时两边都不动**：若只写 `<` 和 `>` 两个分支，等高输入会死循环。
- **宽度写成 `right-left+1`**：那是数组元素个数，不是两个横坐标的距离。
- **短板写成 `max`**：得到的是高边高度，水会从短边溢出，结果不合法。

### 实现错误

- 把下标和值混用，例如用 `height[right] - height[left]` 计算宽度。
- 忘记在移动前更新 `bestArea`，导致当前边界对被直接跳过。
- 为了“优化”而排序原数组，破坏高度与横坐标的绑定。
- 迁移到更大数值范围时仍用 `int` 相乘，产生溢出后的负数或截断值。

### 可观察的调试状态

不要只打印最终答案。每轮打印下面六项，就能直接对照模型：

```text
left, right, height[left], height[right], currentArea, bestArea
```

对示例 1，关键日志应包含：

```text
left=0 right=8 leftHeight=1 rightHeight=7 area=8  best=8
left=1 right=8 leftHeight=8 rightHeight=7 area=49 best=49
left=1 right=7 leftHeight=8 rightHeight=3 area=18 best=49
```

检查日志时问四件事：区间是否每轮缩小一格；面积是否在移动前计算；移动的是否为较短边；`bestArea` 是否只增不减。等高用例 `[5,5,5]` 还应验证某个分支确实执行，循环不会停在原地。

## 18. 最终模型卡

| 项目 | 结论 |
| --- | --- |
| 题型识别指纹 | 在有序位置中选择两个边界，评分同时受距离和两端瓶颈限制，目标求最大值 |
| 一句话关系模型 | `score = distance * min(leftCapacity, rightCapacity)` |
| 实际保存什么 | 未排除区间的左右下标，以及已计算候选的最大面积 |
| 状态何时变化 | 当前边界对结算后，较短边代表的内部组合被证明受支配时 |
| 答案何时产生 | 每轮移动任一边界之前，由当前宽度和短板计算 |
| 核心不变量 | 所有仍可能超过 `bestArea` 的未计算组合都位于当前 `[left,right]` 内 |
| 时间复杂度 | `O(n)`，每轮永久淘汰一个边界下标 |
| 空间复杂度 | `O(1)`，只保存固定数量变量 |

### 四句建模结论

```text
我正在处理的对象是：当前未排除区间最外侧的一对边界。
我必须持续保存的是：左右边界下标和已经见过的最大面积。
当“当前边界对完成结算，并确认了较短边”这一事件发生时，我执行：永久淘汰较短边并让对应指针向内移动。
答案在每轮移动边界之前，由当前距离、两端短板和历史最大值计算出来。
```

### 迁移变式

1. **有序坐标上的非等距立柱**：宽度改为 `x[right]-x[left]`，变化的是距离计算；只要坐标递增，向内仍会缩短距离，淘汰证明不变。
2. **167. 两数之和 II**：同样维护相向边界，但移动条件由“短板支配”变成“当前和与目标的大小关系”；变化的是触发条件和证明依据。
3. **881. 救生艇**：排序后用最重者与最轻者配对，边界移动由载重可行性决定；变化的是候选关系和状态变化，一轮结果是确定一条船。
4. **42. 接雨水**：仍有左右边界，但答案改为逐位置累加，必须保存左右历史最高值；变化的是最小状态和结果产生时机，不能直接沿用本题面积公式。

复习时最值得保留的不是“短边动”四个字，而是完整判断：固定短边以后，向内更换另一边会让距离变小，同时瓶颈不可能升高，因此这些组合全部被当前最宽组合支配。口诀只是这个证明的压缩结果。
