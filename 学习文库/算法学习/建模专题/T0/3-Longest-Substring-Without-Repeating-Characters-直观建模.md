# 3. 无重复字符的最长子串：从“反复查重”到“增量维护合法窗口”

这道题的代码不长，真正容易卡住的是四个问题：为什么答案可以用一个连续区间表示；右端加入新字符后究竟破坏了什么；左端为什么可以直接跳到某个位置；一个字符虽然以前出现过，但那次出现已经在当前窗口外时，为什么不能让左端后退。

本篇不会把“滑动窗口”当作读题第一反应。我们先从题目关系、人工枚举和重复工作出发，推导出必须维护的最小状态，最后才给这种维护方式命名。

## 2. 完整题目

给定一个字符串 `s`，在 `s` 的所有**连续子串**中，找出不包含重复字符的最长子串，返回它的长度。

- 输入：一个字符串 `s`。
- 输出：一个整数，表示最长无重复连续子串的长度。
- 子串必须由原字符串中一段连续位置组成，不能跳过中间字符。
- 如果存在多个同样长的答案，只返回长度，不需要返回具体子串。

这里的“连续”不是附加条件，而是答案形状的一部分。子串一旦选择了起点和终点，中间位置就全部被选中。算法不能看到中间有重复后把那个字符跳过去，因为跳过后得到的是子序列，已经换了问题。

> **小白追问：** 为什么答案必须是一段连续区间，不能挑几个互不重复的字符拼起来？
>
> **先给短答：** 因为题目要的是子串，子串按定义必须占据一段连续下标。
>
> **最小例子：** 在 `"aba"` 中，可以挑下标 `0、1` 得到子串 `"ab"`；不能挑下标 `0、2` 后说得到长度为 2 的无重复子串，因为两处都是 `a`，而且这种跳选本来就是子序列动作。
>
> **回到模型/代码：** 候选统一写成闭区间 `[left, right]`，长度统一由 `right - left + 1` 计算；代码从不删除区间中间的单个字符。

### 示例 1

```text
输入：s = "abcabcbb"
输出：3
解释："abc"、"bca"、"cab" 都是不含重复字符且长度为 3 的子串。
      再向右扩展任意一个这样的长度 3 区间都会遇到重复字符。
```

### 示例 2

```text
输入：s = "bbbbb"
输出：1
解释：任意两个连续字符都会重复，因此最长合法子串只能包含一个 "b"。
```

### 示例 3

```text
输入：s = "pwwkew"
输出：3
解释："wke" 是长度为 3 的合法子串，"kew" 也是。
      "pwke" 虽然可以从原串按顺序挑出，但它跳过了一个字符，是子序列而不是子串。
```

### 约束与接口

- `0 <= s.length <= 10^5`。
- `s` 由英文字母、数字、符号和空格组成。
- 题目契约中的 `s` 非 `null`，空字符串是合法输入。
- Java 方法入口为：

```java
public int lengthOfLongestSubstring(String s)
```

长度上限达到 `10^5` 是重要信号：对每个起点重新向右扫描的平方级方案可能处理约百亿次字符，不能作为提交方案。字符种类少会限制辅助结构的实际大小，但不能消除重复扫描本身。

## 3. 先把题目说成人话

### 一句话生活化复述

拿一个可以左右伸缩的检查框罩住字符串的一段，要求框内每种字符最多出现一次，想让这个框尽可能长。

### 一句话关系化复述

在所有连续下标区间 `[left, right]` 中，寻找满足“区间内任意两个位置的字符都不相等”的最大区间长度。

先看一张最小关系图：

```text
下标：  0   1   2   3
字符：  a   b   b   a
            ^---^
            1   2       字符相同，任何同时覆盖 1 和 2 的区间都不合法

合法连续区间示例：[0,1] = "ab"，[2,3] = "ba"
非法连续区间示例：[0,2] = "abb"
非连续挑选示例：位置 0、1、3 = "aba"，它不是本题的子串候选
```

| 要素  | 本题中的含义                             |
| --- | ---------------------------------- |
| 对象  | 字符串中的字符及其下标，答案候选是连续下标区间            |
| 关系  | 同一区间内不能存在两个字符值相同的位置                |
| 方向  | 按下标从左到右接收新字符；冲突只可能由新进入的右端字符触发      |
| 目标  | 在所有合法连续区间中最大化 `right - left + 1`   |
| 限制  | 不能重排、不能跳过区间内部字符；输入可能为空，规模可达 `10^5` |

关键不是“找几个不同字符”，而是“找一段连续区域”。一旦连续性确定，候选答案天然有左、右两个边界；一旦“不重复”确定，边界之间必须始终满足一种可检查的合法性。

这里把“合法”说具体：区间 `[left, right]` 合法，表示任取区间中的两个不同下标 `i` 和 `j`，都有 `s[i] != s[j]`。它不是“当前字符没见过”这么宽泛，而是“当前区间内部没有重复”。

> **小白追问：** 为什么要区分“历史上见过”和“当前区间里见过”？
>
> **先给短答：** 已经被 `left` 排除的历史字符不再属于候选，不能继续判它冲突。
>
> **最小例子：** `"abba"` 处理最后一个 `a` 时，最早的 `a` 在下标 `0`，当前 `left = 2`；下标 `0` 虽然历史上见过，却不在窗口 `[2,3]` 中。
>
> **回到模型/代码：** `lastIndex` 负责回答“上次在哪”，`previous >= left` 才把“历史位置”翻译成“窗口内冲突”。

## 4. 第一切入点：读题时先看什么

第一次读题，先圈出三个真正决定模型的词。

1. **子串**：意味着连续，答案可表示为区间 `[left, right]`。如果题目说的是子序列，就不能用一个连续窗口概括候选。
2. **无重复**：这是区间是否合法的条件。右边增加一个字符时，旧区间内部本来合法，所以只需判断新字符是否与旧区间冲突。
3. **最长**：每得到一个合法区间，都可以用其长度更新最大值；还需要说明对每个右端点是否保留了最长的那个合法区间。

“只判断新字符”依赖一个前提：上一轮结束时，旧窗口已经合法。若没有持续维护这个前提，旧窗口内部也可能早就有重复，检查当前字符当然不够。后文会把这种“每轮开始前可依赖、每轮结束后还要恢复”的性质称为不变量。

> **小白追问：** 新字符进入后，为什么不用把整个窗口重新查重？
>
> **先给短答：** 旧窗口已经通过上一轮检查，新增重复对若出现，必然至少包含刚进入的字符。
>
> **最小例子：** 旧窗口 `"ab"` 中的 `a、b` 已知不同；加入 `c` 时只需确认 `c` 不等于 `a、b`，加入 `b` 时唯一新增冲突就是旧 `b` 与新 `b`。
>
> **回到模型/代码：** 循环开始时依赖 `[left, right - 1]` 合法；本轮只查询 `lastIndex.get(current)`，结束时再保证 `[left, right]` 合法。

“字符串”“英文字母”“符号”描述的是数据载体和字符范围，第一分钟可以先把它们当成一列值。题目也没有要求输出子串内容或所有方案，因此暂时不必保存每个候选字符串。

人工处理 `"abba"` 时通常会这样想：

```text
先读 a："a" 合法
再读 b："ab" 合法
再读 b："abb" 重复，只能丢掉前一个 b 以及它左边的内容，剩下 "b"
再读 a：当前得到 "ba"；旧 a 在已经丢掉的区域，不影响现在
最长长度为 2
```

这里已经出现了后续模型的雏形：新字符从右边进入；发生冲突时只移动左边；已经被左边界排除的历史字符不能再次影响当前区间。

## 5. 最直接的人工或暴力模型

暂时不优化。最稳妥的办法是枚举每个可能的起点，再从该起点向右逐个加入字符。

```text
best = 0
对每个起点 start：
    创建一个空集合 seen
    从 end = start 开始向右：
        如果 s[end] 已在 seen 中：停止扩展这个起点
        否则把 s[end] 放入 seen
        用 end - start + 1 更新 best
返回 best
```

这个模型一定正确，原因是所有非空连续子串都有且只有一个起点和一个终点。外层循环枚举所有起点，内层循环按终点递增；一个起点第一次遇到重复后，再继续向右只会保留已经存在的重复对，不可能重新合法，因此可以安全停止。空串没有任何非空候选，初始值 `0` 正好是答案。

> **小白追问：** 暴力扫描遇到第一个重复后，为什么可以直接停止这个起点？
>
> **先给短答：** 固定起点不变时，继续向右只会增加字符，不会删除已经形成的重复对。
>
> **最小例子：** 从 `"abac"` 的下标 `0` 开始，扫描到第二个 `a` 时区间 `"aba"` 已含两个 `a`；再加入 `c` 得到 `"abac"`，两个 `a` 仍然都在。
>
> **回到模型/代码：** 暴力内层在 `seen` 已含 `s[end]` 时 `break`；这次停止只结束当前 `start`，外层仍会枚举下一个起点，所以不会漏掉后续合法区间。

设 `n` 为字符串长度。最坏情况下所有字符互不相同：起点 `0` 检查 `n` 个字符，起点 `1` 检查 `n - 1` 个，直到最后检查 `1` 个，总次数为：

```text
1 + 2 + 3 + 直到 n = n(n + 1) / 2
```

因此时间复杂度为 `O(n^2)`。单次起点扫描使用集合保存当前候选中的不同字符，额外空间是 `O(min(n, σ))`，其中 `σ` 表示字符值域中实际可能出现的不同字符数量。这个方案的价值很大：它先给出了不遗漏答案的参照模型，后面的优化必须与它找到相同的候选，只是不能反复做相同检查。

## 6. 暴力到底浪费在哪里

看输入 `"abcdefa"`。前六个字符互不相同，暴力扫描会出现大量重叠工作。

```text
起点 0：检查 a b c d e f，最后看到 a 重复
        [a b c d e f] a

起点 1：重新检查 b c d e f a
          [b c d e f a]

起点 2：又重新检查 c d e f a
            [c d e f a]
```

当起点 `0` 扫过 `b、c、d、e、f` 时，我们已经知道这几个字符彼此不同。但切换到起点 `1` 后，暴力方案把这个结论全部丢掉，再检查一遍 `b、c、d、e、f`。字符串越接近“全部不同”，不同起点之间重叠的扫描越长。

再看 `"abcabcbb"` 的前几次处理：

```text
start = 0：a -> b -> c -> 遇到 a，得到长度 3
start = 1：     b -> c -> a -> 遇到 b，又验证了一次 c 与 a
start = 2：          c -> a -> b -> 遇到 c，又验证了一次 a 与 b
```

被浪费的不只是字符读取，还有“这个区间当前没有重复”的中间结论。每轮算完后丢弃集合，使下一起点无法复用前一轮几乎相同的合法区间。

所谓“复用合法区间”，不是把旧答案原封不动留下。它只保留仍然属于新候选的后缀。例如 `"abc"` 加入第二个 `a` 后，前面的 `a` 必须退出，但 `"bc"` 互不重复这个结论仍然成立，不必重新扫描 `b、c`。

> **小白追问：** 从起点 `0` 换到起点 `1`，候选已经变了，旧结论真的还能复用吗？
>
> **先给短答：** 能复用的是旧合法窗口删除前缀后仍然合法的后缀，不是复用旧窗口的长度。
>
> **最小例子：** `"abc"` 已知无重复，删除左端 `a` 后的 `"bc"` 当然仍无重复；随后只需检查新来的字符是否与 `b、c` 冲突。
>
> **回到模型/代码：** `left` 排除失效前缀，`right` 加入一个新字符；`lastIndex` 让算法不用重新遍历保留下来的后缀。

因此优化目标可以写成一句具体的话：

> 不再让每个起点重新检查整个候选子串，而是在一个新字符从右边进入时，只处理它带来的新冲突，并保留其余仍然有效的区间状态。

## 7. 容易想到但走不通的方向

### 方向一：排序后数连续的不同字符

“无重复”容易让人想到排序，因为相同字符排序后会相邻。但排序改变原下标顺序，也破坏连续性。例如 `"pwwkew"` 排序后字符被重新排列，已经无法判断原串中的 `"wke"` 是否连续。这个方向能统计不同字符，却丢失了本题最关键的区间位置关系，逻辑上不适用。

得到的新条件是：辅助信息可以重组，但原字符串的遍历顺序和下标必须保留。

### 方向二：只维护一个“全局出现过”集合

从左到右把所有见过的字符放入集合，确实能发现一个字符是否在历史上出现过，但“历史出现过”不等于“当前区间内出现过”。在 `"abba"` 的最后一个 `a` 处，第一个 `a` 已经位于当前合法区间左侧；全局集合仍说它出现过，却无法说明这次出现是否构成当前冲突。

得到的新条件是：状态必须带有当前区间边界语义。只知道“见过”不够，至少要知道上次出现的位置，或者在左边收缩时同步从集合删除字符。

> **小白追问：** 为什么布尔值“见过或没见过”不够，非要保存下标？
>
> **先给短答：** 布尔值不能判断旧字符在窗口内还是窗口外，也不能告诉左边界该跳到哪里。
>
> **最小例子：** `"abba"` 最后一个 `a` 到来时，布尔值只能说 `a` 见过；下标 `0` 配合 `left = 2` 才能说明旧 `a` 已在窗口外，因此不冲突。
>
> **回到模型/代码：** Map 的值类型是 `Integer` 下标；条件 `previous >= left` 判断有效性，冲突时 `previous + 1` 给出新的左边界。

### 方向三：看到重复就无条件令 `left = previous + 1`

这个方向已经很接近答案，但缺少“旧位置是否仍在窗口内”的判断。用 `"abba"` 演算：

```text
处理下标 2 的 b 后：left = 2，当前窗口是 [2,2] = "b"
处理下标 3 的 a 时：previous(a) = 0
错误赋值：left = previous + 1 = 1
结果窗口变成 [1,3] = "bba"，左边界竟然后退，窗口重新非法
```

这个做法不是复杂度问题，而是逻辑错误。它告诉我们：左边界代表已经永久排除的前缀，所以只能右移，不能被窗口外的旧记录拉回。

> **小白追问：** 为什么 `left` 只能前进，回退后再检查一次不行吗？
>
> **先给短答：** 当前模型承诺 `[left, right - 1]` 是已确认的最长合法后缀；回退会把此前因冲突淘汰的字符重新带进来，承诺立刻失效。
>
> **最小例子：** `"abba"` 在下标 `2` 处已经把 `left` 推到 `2` 以排除旧 `b`；处理下标 `3` 的 `a` 时若退回 `1`，窗口变成 `"bba"`，两个 `b` 又同时出现。
>
> **回到模型/代码：** 要么写 `if (previous >= left) left = previous + 1`，要么写 `left = Math.max(left, previous + 1)`；两者都保护 `left` 的单调性。

### 方向四：用集合逐个收缩左边界

维护当前窗口字符集合，若新字符重复，就不断删除 `s[left]` 并让 `left++`，直到重复消失。这并没有走不通，它是正确的线性模型，而且很适合第一次理解“右进左出”。但集合只告诉我们“重复了”，不知道重复字符具体在什么位置，因此可能要逐个退出多个字符。

本篇选择“字符最近位置”模型，是因为它能把多次退出合并成一次边界跳转，并能直接解释窗口外重复。两种写法都可以达到线性时间；最近位置版本状态含义更精确，集合收缩版本的动作更具象。

## 8. 关键视角转换

转换前，我们把每个候选区间当成一个需要从头检查的完整对象：选起点、不断试终点、重新判断整个区间。

转换后，我们把处理过程看成一条时间线：旧窗口在上一轮结束时已经合法，现在只有一个新字符 `s[right]` 进入。合法性如果被破坏，唯一可能的原因就是这个新字符与窗口中的同值字符重复。

这里的“事件”就是右边界来到一个新下标。模型不再为每个起点开一次新扫描，而是让同一条时间线持续向右。旧状态先回答当前事件是否造成冲突，然后本轮更新状态，供下一事件使用。

> **小白追问：** 重复字符为什么会让整个窗口失效，而不是只忽略新字符？
>
> **先给短答：** 当前候选被定义为连续区间，新字符一旦成为右端点就不能跳过；若区间里已有同字符，这个候选便违反无重复条件。
>
> **最小例子：** 旧窗口是 `"ab"`，右边加入 `b` 后候选为 `"abb"`；不能假装最后一个 `b` 没进入，否则右端点仍停在旧位置，也没有处理以新位置结尾的候选。
>
> **回到模型/代码：** `right` 每轮都代表必须处理的新位置；若 `previous >= left`，代码移动 `left` 排除旧 `b`，保留新 `b` 作为当前右端。

| 原视角 | 新视角 |
| --- | --- |
| 为每个起点重新向右寻找终点 | 让右端点只从左到右经过一次 |
| 反复检查整个子串是否有重复 | 只检查新进入字符是否与当前窗口冲突 |
| 遇到冲突后丢掉全部状态 | 只排除导致冲突的最短前缀，保留其余合法部分 |
| 只记录字符是否在历史出现 | 记录字符最近出现的下标，结合当前左边界判断 |

假设上一轮的 `[left, right - 1]` 已经没有重复，新字符 `current = s[right]` 上次出现于 `previous`：

- 若 `previous < left`，旧字符已经在窗口外，新字符不会和当前窗口重复，`left` 不动。
- 若 `previous >= left`，旧字符仍在窗口内。要同时保留新字符并恢复合法性，必须排除旧字符，所以最小移动是 `left = previous + 1`。

把两个分支合并，就是：

```text
left = max(left, previous + 1)
```

如果字符从未出现，可以理解为没有 `previous`，左边界仍不动。这个公式不是需要背诵的模板，它只是两个事实的压缩表达：越过窗口内的冲突位置，并且永远不让左边界后退。

> **小白追问：** 冲突时为什么恰好跳到 `previous + 1`，多跳或少跳会怎样？
>
> **先给短答：** 少跳会保留旧重复字符，多跳会无故丢掉本可组成更长答案的字符。
>
> **最小例子：** 窗口 `"abc"` 加入 `b`，旧 `b` 在下标 `1`；跳到 `1` 后两个 `b` 仍在，跳到 `3` 又会误删 `c`，只有跳到 `2` 才得到最长合法后缀 `"cb"`。
>
> **回到模型/代码：** `previous + 1` 是排除旧同字符的最小新边界；外层的 `max` 或 `previous >= left` 再保证这个边界不会后退。

为什么重复工作减少了？过去每个起点会重新扫描右侧；现在每个下标只作为右端点进入一次。此前合法的窗口不会重验，只在新字符造成冲突时调整一个边界。

## 9. 正式建立模型

先得到模型，再给它命名。

| 建模项 | 本题结论 |
| --- | --- |
| 对象 | 当前右端字符，以及以它结尾的连续区间 `[left, right]` |
| 关系 | 区间内任意字符最多出现一次 |
| 状态 | 左边界 `left`、每个字符最近下标 `lastIndex`、历史最大长度 `best` |
| 事件 | 下标 `right` 的新字符进入候选区间 |
| 不变量 | 每轮结束后 `[left, right]` 无重复，且它是以 `right` 结尾的最长合法子串；`left` 从不后退 |
| 结果时机 | 恢复窗口合法并更新最近位置后，用 `right - left + 1` 更新 `best` |

这个状态是足够的。旧窗口已经合法，所以新冲突只可能涉及当前字符；要判断冲突，只需要它最近一次出现的位置，不需要保存更早的所有位置。若最近一次出现都在 `left` 左边，更早的位置只会更靠左，同样不可能影响当前窗口。

> **小白追问：** 一个字符可能出现很多次，为什么只保存最近一次下标就不会漏判？
>
> **先给短答：** 最近一次是最靠右、也最可能仍在窗口中的那次；它若已在窗口外，更早记录必然也在窗口外。
>
> **最小例子：** 已处理前缀中 `a` 出现在 `0、3、7`，当前 `left = 5`；只看最近位置 `7` 就知道窗口内有 `a`。若当前 `left = 8`，位置 `7` 已在外面，`0、3` 更不可能在里面。
>
> **回到模型/代码：** 每轮 `lastIndex.put(current, right)` 覆盖旧值；Map 每个字符只保留一个下标，但这个下标足以决定冲突和跳转位置。

`lastIndex` 中会保留一些窗口外记录，这不是多余错误，而是有意保留的历史摘要。`left` 决定记录是否仍有效。这样无需在左边界跳转时逐个清理 Map；判断 `previous >= left` 就能区分“窗口内冲突”和“窗口外旧闻”。

当冲突位置为 `previous` 时，所有 `start <= previous` 且以当前 `right` 结尾的区间都同时包含两个相同字符，永久不可能成为当前右端点的合法答案，可以一次丢弃。`previous + 1` 又是排除旧字符后的最左位置，因此不会多丢任何可能更长的合法候选。

> **小白追问：** 一次丢掉 `previous` 及其左侧全部起点，凭什么不会漏掉答案？
>
> **先给短答：** 这些起点构成的区间都会同时覆盖旧字符位置 `previous` 和新字符位置 `right`，所以全部非法。
>
> **最小例子：** 在 `a b c b` 中，新 `b` 位于 `3`，旧 `b` 位于 `1`；起点为 `0` 或 `1` 的区间都含两个 `b`，最早可行起点只能是 `2`。
>
> **回到模型/代码：** `left = previous + 1` 批量淘汰 `start <= previous` 的候选；更新后 `[left, right]` 保留以当前 `right` 结尾的最长合法候选。

遍历必须从左到右，因为“最近位置”和“当前前缀已处理完成”都有时间顺序。相等值正是触发边界变化的事件；空串没有事件，`best` 保持 `0`；单字符只有一次进入，窗口长度为 `1`。

答案不能在冲突处理之前更新。那一刻 `[left, right]` 可能仍含重复字符，长度没有资格参与最大值比较。答案也不应只在发生冲突时更新，因为全不重复输入从来不冲突，最长窗口却会持续增长。

> **小白追问：** `best` 到底应该在什么时候更新，为什么每一轮都要更新？
>
> **先给短答：** 应在左边界处理完成、窗口重新合法后更新；每个右端点都可能产生新的最长答案。
>
> **最小例子：** `"abc"` 没有任何冲突，合法窗口长度依次为 `1、2、3`；若只在冲突时更新，最终仍会错误地得到 `0`。
>
> **回到模型/代码：** 先调整 `left`，再写最近位置，随后计算 `currentLength`，最后执行 `best = Math.max(best, currentLength)`。

现在可以给模型命名：两个只向右移动的边界维护一个连续合法区间，这叫**可变长度滑动窗口**；使用最近位置让左边界直接跳转，是滑动窗口的一种增量维护实现。

## 10. 所需数据结构详解

### 10.1 字符串与两个边界

Java 的 `String` 按下标提供 `charAt(right)`，本题用它把字符串看成只读字符数组。`left` 和 `right` 是整数下标：`right` 由 `for` 循环每轮加一，表示新进入的字符；`left` 只在发生窗口内重复时向右跳。

- `charAt`：按下标读取一个 UTF-16 代码单元，时间 `O(1)`。
- `right - left + 1`：计算当前闭区间长度，时间 `O(1)`。
- 两个边界最坏都走到 `n`，只占 `O(1)` 额外空间。

本题约束中的英文字母、数字、符号和空格可以按 `char` 处理。若把模型扩展到表情或某些辅助平面 Unicode 字符，一个用户感知字符可能由两个 `char` 组成，那时应改为遍历 Unicode code point；这是数据表示变化，不是窗口模型变化。

### 10.2 哈希表 `Map<Character, Integer>`

哈希表通过键的哈希值定位桶，再在桶内确认相等键。这里：

- 键 `Character` 是字符值。
- 值 `Integer` 是该字符截至当前遍历位置最近出现的下标。
- `get(current)` 查询旧位置，平均 `O(1)`。
- `put(current, right)` 写入更新后的最近位置，平均 `O(1)`。

哈希表的关键特征不是“能去重”，而是**按字符直接取回它关联的下标**。模型需要的正是“当前字符上次在哪里”，因此 Map 比只保存成员关系的 Set 多提供了边界跳转所需的信息。

> **小白追问：** 既然窗口目标是去重，为什么不直接用 `Set<Character>`？
>
> **先给短答：** Set 可以判断重复，但不能直接给出旧字符位置；要恢复合法性，只能从左边逐个删除直到冲突消失。
>
> **最小例子：** 窗口 `"abcd"` 加入 `d` 时，Set 只知道有重复；Map 直接给出旧 `d` 的下标 `3`，于是左边界一次跳到 `4`。
>
> **回到模型/代码：** Set 版本需要 `while`、`remove(s.charAt(left))` 和 `left++`；本文主线用 `lastIndex` 把这段逐步退出压成一次定位跳转。

为什么不保存所有出现位置？因为最近位置最靠右。如果最近位置在窗口外，其他更早位置也都在窗口外；如果最近位置在窗口内，越过它就同时越过该字符所有更早位置。保存一个下标已经足够。

为什么不优先使用有序树？本题不需要按字符排序、找前驱或最小键，有序结构的 `O(log σ)` 操作没有提供额外价值。为什么不是队列？我们需要按字符值随机查询其旧下标，而不是只从队头取最早元素。

若字符范围被严格限定为很小的整数值域，也可用下标数组保存最近位置，获得确定的 `O(1)` 访问和更小常数。但数组方案依赖字符编码范围和初始化约定；HashMap 更直观地表达“字符到最近位置”的关系，也更便于迁移到任意可哈希对象。

最坏保存 `min(n, σ)` 个键，其中 `σ` 是不同字符值的数量。按一般输入规模写为空间 `O(min(n, σ))`；在本题字符种类被固定上界约束的语境下，它相对于 `n` 也可视为常量级。Java HashMap 的复杂度通常按平均或期望 `O(1)` 分析，极端哈希冲突不改变本题建模结论。

## 11. 生活化类比及边界

把窗口想成一个从左向右移动的“无重复访客检查区”。每位访客胸牌上有一个字符编号，同一时刻检查区内不能有两个相同编号。门口另有一本登记簿，记录每个编号最近一次进入整条通道的位置。

新访客从右门进入：若登记簿显示同编号访客仍在检查区内，就把左门一次移动到旧访客之后；若旧访客早已在左门外，不必改变左门。随后把登记簿的最近位置改为新访客位置，并统计当前区内人数。

| 生活对象或动作 | 算法中的对应物 |
| --- | --- |
| 通道上的访客 | 字符 `s[right]` |
| 访客所在位置 | 字符下标 `right` |
| 检查区左右门 | `left` 与 `right` 边界 |
| 最近到访登记簿 | `lastIndex` 哈希表 |
| 同编号旧访客仍在区内 | `previous >= left` |
| 左门移到旧访客之后 | `left = previous + 1` |
| 旧访客已在区外 | `previous < left`，不移动左门 |
| 检查区始终无重复编号 | 窗口合法性不变量 |
| 记录最多在场人数 | 用窗口长度更新 `best` |

类比到这里为止。现实中访客可能主动离开、交换位置或同时到达；算法中没有这些动作，字符顺序固定，右边每次只进入一个字符，左边界也只能整体排除一个前缀。登记簿保留区外访客记录并不意味着他们仍在区内，必须结合左门位置判断。类比帮助理解状态变化，但正确性仍由区间和下标关系保证。

## 12. 典型输入的完整数据变化图

完整演算 `s = "pwwkew"`。方向固定为从左到右，窗口写成闭区间 `[left, right]`。

```text
下标：  0   1   2   3   4   5
字符：  p   w   w   k   e   w
方向：  --------------------->
```

| `right` | 当前字符 | 处理前 `left` | 最近位置 `previous` | 判断与动作 | 处理后窗口 | 当前长度 | `best` |
| ---: | :---: | ---: | ---: | --- | --- | ---: | ---: |
| 0 | p | 0 | 无 | 没有旧 p，左边不动；记录 `p -> 0` | `[0,0] = "p"` | 1 | 1 |
| 1 | w | 0 | 无 | 没有旧 w，左边不动；记录 `w -> 1` | `[0,1] = "pw"` | 2 | 2 |
| 2 | w | 0 | 1 | `1 >= 0`，旧 w 在窗口内；跳到 `left = 2`，更新 `w -> 2` | `[2,2] = "w"` | 1 | 2 |
| 3 | k | 2 | 无 | 没有旧 k；记录 `k -> 3` | `[2,3] = "wk"` | 2 | 2 |
| 4 | e | 2 | 无 | 没有旧 e；记录 `e -> 4` | `[2,4] = "wke"` | 3 | 3 |
| 5 | w | 2 | 2 | `2 >= 2`，旧 w 在窗口内；跳到 `left = 3`，更新 `w -> 5` | `[3,5] = "kew"` | 3 | 3 |

把核心冲突步骤拆成统一快照。

```text
当前输入：right = 2，current = 'w'
处理前状态：left = 0，窗口 [0,1] = "pw"，lastIndex['w'] = 1
判断依据：previous = 1 >= left = 0，旧 w 仍在窗口内
执行动作：left = previous + 1 = 2；再记录 lastIndex['w'] = 2
处理后状态：窗口 [2,2] = "w"，重新无重复
新增结果：长度 1，没有超过 best = 2
```

```text
当前输入：right = 5，current = 'w'
处理前状态：left = 2，窗口 [2,4] = "wke"，lastIndex['w'] = 2
判断依据：previous = 2 >= left = 2，加入新 w 会形成两个 w
执行动作：left = 3；再记录 lastIndex['w'] = 5
处理后状态：窗口 [3,5] = "kew"，旧 w 被排除，新 w 被保留
新增结果：长度 3，与 best 相同
```

每一行结束时，表中的窗口都合法。Map 可以包含窗口外的 `p -> 0` 等记录，但这些记录只有在其位置不小于 `left` 时才有资格触发移动。

把“窗口合法性”和变量职责对齐，可以用下面这组检查问题读表。`right` 回答新字符是谁，`previous` 回答它最近在哪，`left` 回答当前候选从哪开始。只有 `previous` 落在 `[left, right - 1]` 内时，新字符才复制了窗口成员。

> **小白追问：** Map 中明明还留着窗口外记录，为什么还能说窗口状态是正确的？
>
> **先给短答：** Map 是已处理前缀的历史索引，不是当前窗口成员清单；成员资格由下标是否大于等于 `left` 决定。
>
> **最小例子：** 处理 `"abba"` 最后一个 `a` 前，Map 有 `a -> 0`，窗口却是 `[2,2]`；因为 `0 < 2`，这条记录只说明历史，不说明当前成员。
>
> **回到模型/代码：** `lastIndex.get(current)` 后必须再检查 `previous >= left`；不能把 `previous != null` 单独当成冲突条件。

## 13. 边界场景的数据变化

### 13.1 关键反例：重复字符位于窗口外

`s = "abba"` 专门检验左边界不能后退。

| `right` | 字符 | 处理前 `left` | `previous` | 动作 | 处理后窗口 | `best` |
| ---: | :---: | ---: | ---: | --- | --- | ---: |
| 0 | a | 0 | 无 | 不移动，记录 `a -> 0` | `"a"` | 1 |
| 1 | b | 0 | 无 | 不移动，记录 `b -> 1` | `"ab"` | 2 |
| 2 | b | 0 | 1 | 旧 b 在窗口内，`left = 2` | `"b"` | 2 |
| 3 | a | 2 | 0 | `0 < 2`，旧 a 在窗口外，`left` 保持 2 | `"ba"` | 2 |

上表再展开成一轮一轮的稳定状态。Map 展示的是“处理完整个当前下标后”的最近位置，而窗口只取下标不小于 `left` 的连续部分。

```text
初始：left=0，best=0，lastIndex={}

right=0，读到 a
查询：a 没有历史位置
动作：left 不动；记录 a->0；长度 1 更新 best
稳定状态：left=0，窗口 [0,0]="a"，lastIndex={a=0}，best=1

right=1，读到 b
查询：b 没有历史位置
动作：left 不动；记录 b->1；长度 2 更新 best
稳定状态：left=0，窗口 [0,1]="ab"，lastIndex={a=0,b=1}，best=2

right=2，读到 b
查询：previous=1，且 1>=left=0，旧 b 在窗口内
动作：left=2；记录 b->2；当前长度 1 不改变 best
稳定状态：left=2，窗口 [2,2]="b"，lastIndex={a=0,b=2}，best=2

right=3，读到 a
查询：previous=0，但 0<left=2，旧 a 已在窗口外
动作：left 保持 2；记录 a->3；当前长度 2 不改变 best
稳定状态：left=2，窗口 [2,3]="ba"，lastIndex={a=3,b=2}，best=2
```

最后一轮正好同时用到三个状态。`previous = 0` 只说明旧 `a` 的历史位置；`left = 2` 划定当前候选范围；比较结果 `0 < 2` 才得出“不冲突”。不能省掉三者中的任何一个。

```text
处理最后一个 a 之前：

下标：  0   1   2   3
字符：  a   b   b   a
        ^       ^
      旧 a    left=2

旧 a 的位置 0 已经位于 left 左边。
若把 left 改回 1，窗口会变成 "bba"，既后退又非法。
正确动作是不移动 left，得到 [2,3] = "ba"。
```

这正是 `previous >= left` 判断或 `max(left, previous + 1)` 公式不可缺少的原因。

把错误版本也完整走到稳定状态，会看到错误不是“少算一点”，而是破坏了窗口定义。

```text
错误动作：left = previous + 1 = 0 + 1 = 1
错误窗口：[1,3] = "bba"
窗口成员：下标 1 的 b、下标 2 的 b、下标 3 的 a
检查结果：两个 b 重复，窗口非法
后续伤害：若仍用 3 - 1 + 1 更新 best，会把非法长度 3 写入答案
```

> **小白追问：** `abba` 最后一轮没有两个 `a` 在窗口内，为什么旧 `a` 记录还不能删除？
>
> **先给短答：** 可以删除，但没有必要；保留最近位置并用 `left` 判有效，能避免边界跳跃时逐项清理 Map。
>
> **最小例子：** 此时 `a -> 0` 是失效历史，读到新 `a` 后直接覆盖为 `a -> 3`；中间无需先执行一次删除。
>
> **回到模型/代码：** 查询阶段用 `previous >= left` 过滤旧记录，更新阶段统一执行 `lastIndex.put(current, right)`。

### 13.2 空串与全部相等

空串 `""` 时，`right < s.length()` 一开始就是假，循环不执行，Map 保持空，`left = 0`，`best = 0`，没有下标访问，也不会越界。

全部相等的 `"bbb"`：

```text
right=0：窗口 "b"，best=1
right=1：旧 b 在 0，left 从 0 到 1，窗口仍为 "b"
right=2：旧 b 在 1，left 从 1 到 2，窗口仍为 "b"
最终 Map 为 {b=2}，best=1
```

每次冲突都只保留最新的一个 `b`，窗口不会变成空区间，也不会产生长度负数。

## 14. 正确性与不变量

要证明的不是“代码看起来像滑动窗口”，而是：对每个右端点，算法保留了以它结尾的最长无重复子串，因此这些长度的最大值就是全局答案。

### 循环不变量

“不变量”不是指变量值永远不变。它指的是每轮处理结束后都重新成立的一组事实，具体数值可以变化。这里 `left、right、best` 一直在变，但“窗口无重复”和“`best` 记录历史最大值”始终成立。

每次处理完下标 `right` 后同时成立：

1. `[left, right]` 内没有重复字符。
2. 在所有以 `right` 结尾的合法子串中，`[left, right]` 的左边界最小，因此长度最长。
3. `lastIndex[c]` 是字符 `c` 在已处理前缀 `[0, right]` 中最近出现的位置。
4. `left` 从不向左移动。
5. `best` 是截至 `right` 为止见过的所有合法窗口的最大长度。

> **小白追问：** 窗口每轮都在变化，为什么还叫“不变量”？
>
> **先给短答：** 不变的是状态必须满足的性质，不是 `left` 或 Map 中的具体数值。
>
> **最小例子：** `"abb"` 的合法窗口依次是 `"a"、"ab"、"b"`，内容和边界都变了，但每轮结束时窗口都无重复。
>
> **回到模型/代码：** 循环体先修复 `left`，再更新 Map 和 `best`；走到下一轮前，上述五条性质必须再次成立。

### 为什么当前动作能恢复合法

处理新字符前，`[left, right - 1]` 已经无重复，所以新增后如果非法，只可能是 `s[right]` 与窗口中的同字符冲突。

- 若最近位置 `previous < left`，窗口内根本没有同字符，直接加入仍合法。
- 若 `previous >= left`，把左边界移到 `previous + 1` 会排除旧字符。旧窗口其他字符原本互不相同，新字符又只与旧同字符可能冲突，因此新窗口合法。

### 为什么不会漏掉更长的当前候选

发生窗口内冲突时，任何左边界 `start <= previous` 的区间 `[start, right]` 都同时含有旧字符和新字符，必定非法。`previous + 1` 是第一个可能合法的位置，算法没有多向右移动一步。因此它得到的是以 `right` 结尾的最长合法区间。

> **小白追问：** 为什么“左边界最小”就等于“以当前右端点结尾时长度最长”？
>
> **先给短答：** 右端点固定后，区间长度只由左端点决定，左端越靠左，包含的位置越多。
>
> **最小例子：** 固定 `right = 4`，起点 `1` 的长度是 `4`，起点 `2` 的长度是 `3`；只要两者都合法，起点 `1` 的候选一定更长。
>
> **回到模型/代码：** `previous + 1` 是最小合法 `left`，随后 `right - left + 1` 就是该 `right` 对应的最大合法长度。

当旧位置在窗口外时，保持现有 `left` 同样必要。更靠左的位置已经因先前的其他冲突被证明不能作为当前合法链条的起点；让 `left` 回退可能重新带回重复字符。算法不回退，所以此前的排除结论一直有效。

### 为什么只保留最近位置就够

若一个字符出现多次，最近位置右侧不可能还有该字符的更晚历史位置。越过最近位置后，该字符全部旧出现都在窗口外；若最近位置本身已在窗口外，更早位置更不可能在窗口内。因此所有历史下标可压缩为一个最近下标。

### 为什么最终是全局最长

任何非空最优子串都有一个确定的右端点 `r`。算法处理 `r` 时，会构造以 `r` 结尾的最长合法子串，它不会比那个最优子串短；算法每轮都用该长度更新 `best`。反过来，写入 `best` 的每个窗口都已由不变量保证合法，所以算法既不会漏掉全局最优，也不会把非法长度算进答案。空串没有候选，初值 `0` 正确。

## 15. 时间与空间复杂度推导

定义：

- `n`：字符串 `s` 的长度。
- `σ`：输入字符值域中可能出现的不同字符数量。
- 返回的一个整数不计入额外空间。

### 直接模型

直接模型为每个起点向右扫描。最坏情况下没有重复字符，检查次数是从 `1` 到 `n` 的等差数列之和 `n(n + 1) / 2`，所以时间复杂度 `O(n^2)`。每次扫描的集合最多保存当前子串中的不同字符，额外空间 `O(min(n, σ))`。

### 最近位置窗口模型

`right` 从 `0` 到 `n - 1`，每个字符恰好作为新事件处理一次。每轮执行常数次 Map 查询、更新、整数比较和最大值计算；HashMap 的 `get`、`put` 按平均 `O(1)` 计，因此总时间复杂度为 `O(n)`。

> **小白追问：** `left` 有时一下跳过很多字符，这会不会让总时间又变成平方级？
>
> **先给短答：** 不会，一次跳跃只是给整数赋一个新值，代码没有逐个访问被跨过的字符。
>
> **最小例子：** `left` 从 `2` 跳到 `100`，执行的仍是一句赋值，而不是运行 98 次循环；本轮 Map 查询和更新次数没有增加。
>
> **回到模型/代码：** 主循环只由 `right` 控制并执行 `n` 轮，循环体没有内层扫描，所以平均总成本是 `n` 次常数工作，即 `O(n)`。

虽然左边界有时会一次跳过多个下标，但跳转本身只是一次整数赋值。按元素生命周期理解：每个位置只会被右边界纳入一次；左边界从 `0` 单调向右，总移动距离不超过 `n`，被排除的位置不会重新回到窗口。若改用 Set 逐个删除的实现，每个字符也至多进入一次、退出一次，内层 `while` 的总执行次数仍不超过线性量，因此同样是均摊 `O(n)`。

“均摊”是在统计一整段运行过程，而不是承诺每一轮都同样便宜。Set 版本的某一轮可能连续删除多个字符，但这些字符退出后不会再次为同一位置退出。把所有轮次的删除次数加起来，最多与加入次数同阶，因此总量仍是线性。

> **小白追问：** 本文 Map 版本没有内层 `while`，为什么还要提元素生命周期和均摊？
>
> **先给短答：** Map 跳转版本本身每轮就是平均常数成本；生命周期解释用于说明同一模型的 Set 逐项收缩写法也不会因嵌套循环变成 `O(n^2)`。
>
> **最小例子：** 字符 `a` 被窗口加入一次、被左侧删除一次；它不能在不重新经过右边界的情况下反复删除，所以删除总数受加入总数限制。
>
> **回到模型/代码：** 当前提交代码直接赋值 `left = previous + 1`；若改写成 Set 与 `while`，复杂度证明要从“每轮常数”切换为“所有元素总进出次数”。

Map 最多为每种出现过的字符保存一个最近下标，额外空间为 `O(min(n, σ))`。在本题固定且较小的字符范围下，`σ` 有固定上界，所以也常被写成相对于 `n` 的 `O(1)`；为了让模型可迁移到一般字符或对象序列，保留 `O(min(n, σ))` 的表达更准确。

Java 的 `Character`、`Integer` 装箱和 HashMap 桶会带来常数级内存开销，但不改变渐进复杂度。复杂度结论按正常哈希分布下的平均操作成本表述。

### 16.1 泛用模型骨架

下面不是把题目变量简单改名，而是把问题抽象成：给定一列对象和一个取键规则，寻找“键不重复”的最长连续段。`keyOf` 是调用者提供的标准 Java `Function`，用于说明对象按什么属性判重；Map 记录每个键的最近位置。

```java
import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.function.Function;

final class DistinctKeyWindow {
    private DistinctKeyWindow() {
    }

    public static <T, K> int longestSegmentWithoutRepeatedKeys(
            List<T> items,
            Function<? super T, ? extends K> keyOf) {
        Map<K, Integer> lastPositionByKey = new HashMap<>();
        int leftBoundary = 0;
        int bestLength = 0;

        for (int rightBoundary = 0; rightBoundary < items.size(); rightBoundary++) {
            K currentKey = keyOf.apply(items.get(rightBoundary));
            Integer previousPosition = lastPositionByKey.get(currentKey);

            if (previousPosition != null) {
                leftBoundary = Math.max(leftBoundary, previousPosition + 1);
            }

            lastPositionByKey.put(currentKey, rightBoundary);
            int currentLength = rightBoundary - leftBoundary + 1;
            bestLength = Math.max(bestLength, currentLength);
        }

        return bestLength;
    }
}
```

这个骨架适用于日志事件按用户编号不重复、商品流按商品 ID 不重复等连续区间问题，前提是键的 `equals` 与 `hashCode` 在遍历期间保持稳定。模型不关心对象内容，只关心“决定冲突的键”和它的最近位置。

### LeetCode 可直接提交代码

这一代码块只保留题目要求的 `Solution` 入口，可直接提交到 LeetCode。

```java
import java.util.HashMap;
import java.util.Map;

public class Solution {
    public int lengthOfLongestSubstring(String s) {
        Map<Character, Integer> lastIndex = new HashMap<>();
        int left = 0;
        int best = 0;

        for (int right = 0; right < s.length(); right++) {
            char current = s.charAt(right);
            Integer previous = lastIndex.get(current);

            // 窗口外的旧位置不能让左边界后退。
            if (previous != null && previous >= left) {
                left = previous + 1;
            }

            lastIndex.put(current, right);
            int currentLength = right - left + 1;
            best = Math.max(best, currentLength);
        }

        return best;
    }
}
```

### 16.3 代码与模型映射

| 模型角色 | Java 变量或代码块 |
| --- | --- |
| 当前对象 | `current = s.charAt(right)` |
| 右侧事件时间 | 循环下标 `right` |
| 当前合法区间左边界 | `left` |
| 历史摘要 | `Map<Character, Integer> lastIndex` |
| 查询当前字符最近位置 | `lastIndex.get(current)` |
| 窗口内冲突条件 | `previous != null && previous >= left` |
| 排除最短冲突前缀 | `left = previous + 1` |
| 更新历史摘要 | `lastIndex.put(current, right)` |
| 当前候选长度 | `right - left + 1` |
| 结果产生时机 | 窗口恢复合法后执行 `best = Math.max(best, currentLength)` |

可以把循环体理解成从一个稳定时刻走到下一个稳定时刻。循环刚开始时，`[left, right - 1]` 是合法窗口；读取 `current` 后进入短暂的“待判断”状态。若旧位置仍在窗口内，调整 `left` 才恢复合法；随后写入当前最近位置，为下一轮查询准备历史摘要。最后计算长度时，边界已经代表一个真实合法候选，所以这个长度才有资格参与 `best` 比较。

这几步的职责不能混在一起。`left` 决定当前窗口成员，`lastIndex` 描述整个已处理前缀的最近位置，`best` 汇总各轮合法窗口。Map 中存在窗口外下标不破坏合法性，因为 Map 本身不是窗口；真正声明窗口范围的始终是 `[left, right]`。

这也是调试时最值得逐步核对的状态链。

代码选择显式判断 `previous >= left`，与 `left = Math.max(left, previous + 1)` 等价，但更直接地表达“只有窗口内旧位置才构成冲突”。读取 `previous` 必须发生在更新 Map 之前，否则拿到的是当前下标自己，会错误地把当前字符也排除。

> **小白追问：** 为什么必须先查询旧位置，再把当前下标写进 Map？
>
> **先给短答：** 本轮判断需要的是“当前字符进入之前最近在哪”，先写会把证据覆盖成当前下标。
>
> **最小例子：** 第一次读到 `a` 且 `right = 0`，若先写 `a -> 0` 再查，会误以为位置 `0` 已经有旧 `a`，并把 `left` 推到 `1`。
>
> **回到模型/代码：** 固定顺序是 `get(current)`、按旧位置调整 `left`、`put(current, right)`、计算长度、更新 `best`。

## 17. 边界、常见错误与调试观察点

| 层次 | 常见错误 | 具体后果 |
| --- | --- | --- |
| 建模错误 | 把子串当成子序列 | 会允许跳过中间重复字符，答案可能虚高 |
| 建模错误 | Map 只记录“是否出现过”，不结合窗口边界 | 窗口外历史被误判成当前冲突 |
| 条件错误 | 无条件执行 `left = previous + 1` | `"abba"` 最后一步让 `left` 从 2 回退到 1 |
| 条件错误 | 冲突时写成 `left = previous` | 旧重复字符仍留在窗口中 |
| 条件错误 | 长度写成 `right - left` | 闭区间长度少算 1，单字符会得到 0 |
| 实现错误 | 先 `put` 再读取 `previous` | 读到当前 `right`，左边界跳到 `right + 1` |
| 实现错误 | 每轮重新创建 Map | 退化回按起点重复扫描，丢失增量状态 |
| 表示错误 | 把任意 Unicode 用户字符都等同于一个 `char` | 扩展场景中可能把代理项当成独立字符 |

空串无需特殊分支；循环自然不执行。空格是普通字符，不能先 `trim()`，否则会改变题意。题目未要求处理 `null`，不要为了本题随意把 `null` 与空串定义成同一种输入；业务代码若允许 `null`，应由业务契约单独规定。

最有价值的调试日志不是只打印最终答案，而是每轮打印：

```text
right, current, previous, leftBefore, leftAfter, windowLength, best
```

对 `"abba"`，重点检查最后一轮是否为：

```text
right=3, current=a, previous=0, leftBefore=2, leftAfter=2, windowLength=2, best=2
```

可以在小输入中临时打印 `s.substring(left, right + 1)` 观察窗口内容，但不要在大输入性能测试中每轮创建子串，因为日志和子串构造会引入额外时间、内存，掩盖算法本身表现。

建议优先回归这些用例：空串 `""`、单字符 `"a"`、全相同 `"bbbb"`、全不同 `"abcd"`、窗口外旧重复 `"abba"`、连续冲突 `"dvdf"`、答案在尾部 `"tmmzuxt"`、包含空格 `"a b a"`。

| 项目 | 结论 |
| --- | --- |
| 题型识别指纹 | 连续区间；右侧新增元素可能破坏合法性；删除左侧前缀能恢复合法；目标是最长 |
| 一句话关系模型 | 对每个右端点，保留以它结尾的最长无重复连续区间 |
| 窗口实际保存什么 | `[left, right]` 表示当前合法候选；Map 保存每个字符在已处理前缀中的最近下标 |
| 状态何时变化 | 每个新字符进入时查询最近位置；若旧位置仍在窗口内，左边界跳到旧位置之后 |
| 答案何时产生 | 窗口恢复合法后，用闭区间长度更新最大值 |
| 核心不变量 | 窗口始终无重复，是以当前右端点结尾的最长合法窗口，且左边界永不后退 |
| 时间复杂度 | 平均 `O(n)` |
| 额外空间复杂度 | `O(min(n, σ))` |

四句建模结论：

```text
我正在处理的对象是：从左到右进入窗口的当前字符及其下标。
我必须持续保存的是：当前合法窗口左边界、各字符最近位置和历史最大长度。
当 新字符的最近位置仍位于当前窗口内 发生时，我执行：把左边界跳到旧位置后一位，并更新该字符的最近位置。
答案在 当前窗口恢复无重复之后 由 当前左右边界的距离 计算出来。
```

### 泛用模板

```text
让 right 单向扫描连续序列
维护能够判断“新元素是否破坏合法性”的最小摘要
新元素进入后，令 left 只向右移动到刚好恢复合法的位置
在窗口合法的稳定时刻计算候选答案
证明每个 right 对应的最优 left 都被保留
```

### 迁移变式

| 变式 | 变化点 |
| --- | --- |
| 至多包含 K 种字符的最长子串 | 合法条件改变；状态从最近位置变为字符频次与不同字符种数，左侧通常逐个收缩 |
| 最小覆盖子串 | 结果目标和产生时机改变；窗口满足覆盖后要主动缩小并记录最短长度 |
| 找到字符串中所有字母异位词 | 窗口长度固定；状态保存目标频次与当前频次，在每个固定长度稳定点判断 |
| 替换后可获得的最长重复字符 | 合法条件改变；状态还要保存窗口内最高字符频次，用允许替换次数控制收缩 |

迁移时不要只问“是不是滑动窗口题”，而要重新回答：连续候选的合法条件是什么，新元素进入破坏了什么，删除左侧是否能单调恢复，状态需要记录成员、频次、最近位置还是目标缺口。
