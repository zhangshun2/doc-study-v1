# 55. 跳跃游戏：从分支搜索到最远可达前缀

本篇重点解决四个常见困难。

第一，题目说每个位置可以选择多种跳跃长度，很容易让人立刻画搜索树，但搜索树保存了大量对最终判断没有用的路线细节。第二，“每次跳得最远”与“维护所有选择共同形成的最远覆盖”看起来相似，实际上前者只走一条路线，后者没有丢掉任何可达性。第三，更新边界之前必须确认当前下标真的可达，否则一个站不到的位置不能提供新的跳跃能力。第四，要理解为什么一个最右下标足以表示全部已知信息，而不只是记住公式 `farthest = max(farthest, i + nums[i])`。

这里会先建立直接但一定正确的分支搜索模型，再用失败输入看清重复工作，随后证明可达位置始终构成连续前缀。直到状态和不变量都明确之后，才给这个做法命名。

## 2. 完整题目

给定一个由非负整数组成的数组 `nums`。开始时位于下标 `0`。当位于下标 `i` 时，`nums[i]` 表示一次最多可以向右跳多少格，因此可以选择跳 `1` 格、`2` 格，直到 `nums[i]` 格；不能向左跳，也不能把数组外的位置当成新的起跳点。

需要判断是否存在至少一种跳跃方案，可以到达数组最后一个下标 `nums.length - 1`。若存在返回 `true`，否则返回 `false`。题目只要求回答能否到达，不要求输出具体路线，也不要求跳跃次数最少。

**示例 1：可以到达**

```text
输入：nums = [2,3,1,1,4]
输出：true
解释：一种路线是 0 -> 1 -> 4。
      下标 0 最多跳 2 格，可以选择只跳 1 格到下标 1；
      下标 1 最多跳 3 格，可以直接到达下标 4。
```

**示例 2：无法到达**

```text
输入：nums = [3,2,1,0,4]
输出：false
解释：从下标 0 能覆盖到下标 1、2、3，但这些位置都不能越过下标 3。
      下标 3 的值为 0，无法继续向右；下标 4 与前面的可达区域之间出现断点。
```

**示例 3：只有一个元素**

```text
输入：nums = [0]
输出：true
解释：起点下标 0 同时就是最后一个下标，不执行跳跃也已经到达目标。
```

官方约束为：

- `1 <= nums.length <= 10^4`；数组一定非空。
- `0 <= nums[i] <= 10^5`；跳跃上限可以是 `0`。
- 数组元素均为非负整数，所以移动方向只会向右。

Java 方法入口为：

```text
class Solution {
    public boolean canJump(int[] nums)
}
```

这些约束会影响建模选择。`n` 最大为一万，指数级枚举所有路线不可接受，最坏 `O(n^2)` 的做法也不是理想目标。由于 `i <= 9999`、`nums[i] <= 100000`，表达式 `i + nums[i]` 最大约为十一万，使用 Java `int` 不会溢出。数组非空则省去了空数组语义，但单元素必须被当成“已经抵达”，不能误判为没有跳跃能力。

## 3. 先把题目说成人话

**一句话生活化复述：** 站在一排编号踏板的第一块上，每块踏板告诉你从这里最多能向右跨多远，问有没有办法踏上最后一块。

**一句话关系化复述：** 给定每个下标向右产生的可达区间，判断从下标 `0` 出发的可达关系是否覆盖目标下标 `n - 1`。

先不要想“我下一步究竟落在哪里”，而要把每个可达下标看成一个能继续扩张覆盖范围的起点：

```text
可达下标 i
    |
    +-- 可以落在 i + 1
    +-- 可以落在 i + 2
    +-- 直到 i + nums[i]

所以它贡献的是连续区间：(i, i + nums[i]]
```

例如下标 `1` 的值是 `3`，那么站到下标 `1` 后，可以抵达 `2、3、4`，而不只是下标 `4`。这个“可以选择不跳满”的事实非常关键，它让新覆盖区间没有内部空洞。

| 要素 | 本题中的含义 |
| --- | --- |
| 对象 | 数组下标，以及下标上给出的最大跳跃长度 |
| 关系 | 一个已可达下标能否把另一个更靠右的下标纳入可达范围 |
| 方向 | 从左向右，跳跃不能回头 |
| 目标 | 判断目标下标 `n - 1` 是否可达 |
| 限制 | 只有已可达位置才能起跳；实际步长在 `1` 到 `nums[i]` 之间；值可能为 `0` |

把故事压缩后，这不是一道要求构造路线的题，而是一道“覆盖能否连续延伸到目标”的题。路线是证明存在性的见证，但返回值只需要一个布尔结论，所以状态有机会比路线小得多。

## 4. 第一切入点：读题时先看什么

读题第一分钟先圈出四组真正决定模型的词。

第一组是“**最大长度**”。它不是“必须跳这么远”，而是从 `1` 到这个上限都可以选。于是从一个位置产生的是连续可达区间，而不是一条固定边。第二组是“**非负整数**”和“位于第一个下标”，它们确定了信息只需从左向右传播。第三组是“**能否到达**”，题目只问存在性，不问路线、不问方案数、不问最少步数。第四组是“**最后一个下标**”，目标固定在最右边，只要覆盖边界到达它就可以提前结束。

“游戏”“玩家”“跳跃”只是帮助叙述的包装。建模初期可以暂时忽略跳跃动作的动画、每次用了几格，以及已经选出的完整路线。真正要观察的是：哪些下标目前已被证明可达，它们合起来最远能覆盖到哪里。

数据范围也在发信号。长度最多一万，枚举所有路线很可能指数爆炸；从每个下标再向右检查所有候选会达到 `O(n^2)`。如果能让每个下标只被处理一次，`O(n)` 才与“只判断一次可达性”的信息量相称。额外空间则有希望降到常数，因为目标并不要求还原路径。

用最小非平凡样例 `[1,0]` 做人工判断：站在下标 `0`，它能覆盖到下标 `1`，所以成功。再看 `[0,1]`：下标 `0` 最远仍是 `0`，下标 `1` 根本没有机会成为起跳点，所以失败。两者的区别不在于数组里是否存在大于零的数，而在于那个数所在的位置是否已经可达。这正是后续更新顺序必须体现的条件。

第一切入点可以记成一句话：

> 不要先选下一跳；先问截至目前，所有合法选择共同证明了多长的连续可达前缀。

## 5. 最直接的人工或暴力模型

完全按题意行动，可以得到一棵分支搜索树。定义“从下标 `i` 出发能否到达终点”这个问题：如果 `i` 已经等于或超过最后下标，返回成功；否则依次尝试步长 `1` 到 `nums[i]`，只要任意一个下一位置最终成功，当前位置就成功；全部分支都失败，当前位置才失败。

自然语言步骤如下：

1. 从下标 `0` 开始。
2. 在当前下标 `i`，列出数组范围内所有下一站 `i + 1` 到 `i + nums[i]`。
3. 对每个下一站重复相同判断。
4. 任何分支到达最后下标，立即返回 `true`。
5. 当前节点的所有分支都无法到达终点，才返回 `false`。

以 `[2,3,1,1,4]` 为例，搜索树的一部分是：

```text
0
|-- 跳 1 格到 1
|   |-- 到 2
|   |-- 到 3
|   `-- 到 4  成功
`-- 跳 2 格到 2
    `-- 到 3
        `-- 到 4  成功
```

这个模型一定正确。每一步都枚举题目允许的全部步长，因此每条合法路线都对应搜索树中的一条根到叶路径，不会漏掉成功方案；反过来，树中的每条边都满足当前位置的跳跃上限，所以找到的成功路径也不会是伪造路线。

它的问题不是逻辑，而是规模。如果很多位置都能跳到多个后续位置，从 `0` 到终点的不同递增下标序列可能达到指数数量。一个极端数组让前面每个位置都能跳到任意后续位置，此时中间下标取或不取就能形成大量不同路线，路径数达到 `2` 的指数级。纯回溯最坏时间可记为 `O(2^n)` 量级，递归调用栈最深为 `O(n)`。

可以给每个下标缓存“从这里出发能否成功”，避免同一下标被递归求解多次，这就是记忆化搜索。但求解某个下标时仍可能枚举 `O(n)` 个后继，总共 `n` 个状态，最坏时间为 `O(n^2)`，缓存和递归栈使用 `O(n)` 空间。它已经明显好于纯回溯，也保留了直接模型的正确性，后续优化正是继续追问：判断存在性时，真的需要逐条检查这些边吗？

## 6. 暴力到底浪费在哪里

用失败输入 `[3,2,1,0,4]` 看重复最清楚。最后的 `4` 看起来很有力量，但下标 `4` 自身不可达，所以它没有任何作用。

```text
从 0 出发：
0 -> 1 -> 2 -> 3  失败
0 -> 1 -> 3       失败
0 -> 2 -> 3       失败
0 -> 3            失败
```

第一次沿 `0 -> 1 -> 2` 处理时，搜索已经发现下标 `3` 的值为 `0`，从那里无法继续。回退到下标 `1` 后，分支 `1 -> 3` 又询问一次相同问题。再回退到下标 `0`，路径 `0 -> 2 -> 3` 第三次抵达同一失败状态，最后 `0 -> 3` 还会第四次抵达它。没有缓存时，“从 3 出发失败”这个结论被反复计算，又在每次回退后丢掉。

记忆化能保留下标 `3` 的失败结论，却仍会枚举大量重复覆盖。例如下标 `0` 已经知道 `1、2、3` 可达；处理下标 `1` 时又逐个列出 `2、3`，处理下标 `2` 时又列出 `3`。这些列表对应不同的跳跃边，但对“最右能否被覆盖”这个问题，它们只是反复证明同一批位置可达。

可以把重复工作写成表：

| 当前起点 | 枚举的后继 | 与此前重复的结论 | 新增最远覆盖 |
| ---: | --- | --- | ---: |
| 0 | 1、2、3 | 无 | 3 |
| 1 | 2、3 | 2、3 已由 0 覆盖 | 没有 |
| 2 | 3 | 3 已被覆盖 | 没有 |
| 3 | 无 | 再次确认断点 | 没有 |

真正有用的新信息不是“多了一条到下标 `3` 的路线”，而是“可达区域的最右边有没有被推得更远”。在这个输入中，第一步得到边界 `3` 后，后续位置都不能扩张它。保留每条边、每条路线或每个位置的多个来源，都是对布尔目标而言的过量信息。

因此优化目标可以明确写成：

> 不再为每条路线重复探索同一个未来，只保留所有已确认可达位置能够共同延伸出的最远边界；只有边界增长才算获得新信息。

## 7. 容易想到但走不通的方向

### 每一步都跳满

这是最自然的“贪心”误解：既然目标在最右边，每次跳得越远似乎越好。但它只承诺当前落点最远，没有比较较近落点后续可能提供的更强跳跃能力。

看数组 `[2,5,0,0,0,0,0]`。若从下标 `0` 直接跳满两格，会落在下标 `2`，值为 `0`，路线立即停止；但选择只跳一格到下标 `1`，再跳五格就能抵达下标 `6`。所以“固定走最远那条路线”在逻辑上错误。失败带来的条件是：不能过早承诺某个实际落点，需要同时保留所有已经可达的位置所代表的可能性。

### 用布尔数组记录每个位置是否可达

可以令 `reachable[0] = true`，随后对每个可达下标 `i`，把 `i + 1` 到 `i + nums[i]` 都标为可达。这个方法逻辑完全正确，也很适合从图可达性过渡到优化模型。它能保存每个位置的可达状态，却没有利用“可达集合是连续前缀”的特殊结构。同一个位置可能被前面许多区间重复标记，最坏时间 `O(n^2)`，空间 `O(n)`。

这不是错误方向，而是受限的中间模型。它提示我们继续问：如果 `reachable[0..r]` 全部为真，还需要逐格保存这些相同的布尔值吗？一个右边界 `r` 已经能完整描述它们。

### 看到零就判失败，或者只从零向前补救

零确实可能成为障碍，但出现零不等于失败。例如 `[2,0,1]` 中，下标 `0` 可以直接跨过下标 `1` 到达下标 `2`。从每个零向左寻找能否跨越它，可以做出某些正确判断，但连续零、多个障碍和“终点本身为零”等细节会让条件变得绕，而且会重复向左扫描。

零不是模型的中心，**不可跨越的断点**才是。断点的精确定义是：准备处理下标 `i` 时，已有最远覆盖仍小于 `i`。这个定义自动兼容单个零、连续零以及被远距离跳跃跨过的零。

## 8. 关键视角转换

直接模型把问题看成“从当前位置选哪一条边继续走”，因此状态天然长成一棵分支树。新的视角是把所有已发现路线做并集，只问它们共同覆盖到哪里。

> **小白追问：** 不保存实际跳法，最后怎么知道答案不是凭空猜出来的？
>
> **先给短答：** 题目只要一个“存在或不存在”的结论；只要当前状态能够证明目标属于可达区域，就不必同时交出那条路线。
>
> **最小例子：** 在 `[2,3,1,1,4]` 中，处理下标 `0` 后先知道 `0、1、2` 都可达；再处理下标 `1`，覆盖直接到 `4`。此时已经证明至少有一条路线存在，是否把 `0 -> 1 -> 4` 另存成列表，不会改变返回值 `true`。
>
> **回到模型/代码：** 模型只保留 `farthestReachable`，因为方法返回 `boolean`。若题目改成“输出一条路线”，才需要增加前驱信息，当前一个整数的状态就不够了。

| 转换前 | 转换后 |
| --- | --- |
| 枚举每一条完整跳跃路线 | 合并所有可达位置贡献的覆盖区间 |
| 当前要决定实际落点 | 当前只判断这个下标有没有资格扩张边界 |
| 保存到达同一位置的不同历史 | 只保存最右可达下标 |
| 遇到失败路线后回退再试 | 从左到右一次扫描，直到出现断点或覆盖目标 |
| 答案由某条路径到达终点产生 | 答案由可达前缀覆盖终点产生 |

这个转换成立的关键不是一句“越远越好”，而是可达位置形成连续前缀。先从下标 `0` 开始，可达集合是 `[0,0]`。若某个可达位置 `i` 最远能到 `i + nums[i]`，它允许的步长是连续的，所以它贡献的也是连续区间 `[i + 1, i + nums[i]]`。由于 `i` 已在当前前缀内，这个新区间要么完全落在旧前缀里，要么从旧前缀内部或紧邻位置向右延伸，不会凭空制造中间空洞。

> **小白追问：** 为什么可达位置一定连成前缀，不能只到达下标 `0` 和 `2`，却到不了 `1`？
>
> **先给短答：** 因为数组值表示“最多跳多少格”，不是“必须正好跳多少格”；能从某处跳两格时，也允许只跳一格。
>
> **最小例子：** 对 `[2,0,0]`，从下标 `0` 可以选择跳一格到 `1`，也可以跳两格到 `2`。于是新得到的不是孤立点 `{2}`，而是连续的 `{1,2}`，连同起点正好组成 `[0,2]`。
>
> **回到模型/代码：** 正是这个无空洞性质，才允许用一个右端点表达整段可达集合。若规则改成“必须正好跳 `nums[i]` 格”，代码就不能只维护 `farthestReachable`。

因此，若当前所有可达位置正好是 `[0,R]`，扫描其中一个位置 `i` 后，新可达集合仍是：

```text
[0, max(R, i + nums[i])]
```

整个集合的具体来源不重要，只要记住右端点 `R`。搜索树中成百上千条路径，最终都被压缩为“这些路径共同能把右边界推到哪里”。每个下标最多触发一次常数时间更新，重复枚举后继区间的工作消失了。

还必须加一道资格检查：只有 `i <= R` 时，下标 `i` 才属于可达前缀，才允许使用 `nums[i]` 扩张边界。若先更新再检查，就等于借用了一个根本站不到的踏板。例如 `[0,100]` 中，错误代码若处理下标 `1` 的 `100`，会虚构出成功结论。

到这里，状态和变化规则已经出现：一个从不减小的最远可达边界，以及“当前下标可达才更新”的事件条件。之后再把这种只保留当前最强覆盖的选择称为贪心，名称才是推导结果，而不是做题起点。

## 9. 正式建立模型

设 `n = nums.length`，目标下标为 `target = n - 1`，`farthestReachable` 表示利用已经处理过且确认可达的位置，最多能够到达的下标。

> **小白追问：** `farthestReachable` 保存的是下一次真正要落脚的位置吗？
>
> **先给短答：** 不是；它保存所有已经处理过的合法起跳点合在一起能够覆盖到的最右下标，并没有承诺下一跳落在哪里。
>
> **最小例子：** 在 `[2,3,0,0,0]` 中，处理下标 `0` 后边界是 `2`，但算法没有选择落在 `1` 还是 `2`。接着下标 `1` 因为位于边界内而有资格扩张，候选终点是 `4`，边界更新为 `4`。
>
> **回到模型/代码：** `candidateEnd = i + nums[i]` 是当前位置的一次贡献，`farthestReachable = max(...)` 是所有贡献的汇总。变量保存覆盖事实，不保存实际路径决定。

| 建模项 | 本题结论 |
| --- | --- |
| 对象 | 按从左到右顺序被检查的数组下标 `i` |
| 关系 | 已可达下标 `i` 将连续可达前缀扩展到 `i + nums[i]` |
| 状态 | 一个整数 `farthestReachable`，表示当前可达前缀的右端点 |
| 事件 | 当 `i <= farthestReachable` 时，用 `i + nums[i]` 尝试扩张右端点 |
| 不变量 | 每轮结束后，`0` 到 `farthestReachable` 的每个下标都可达；该值也是所有已处理可达位置能到达的最远下标 |
| 结果时机 | 边界达到 `target` 时返回 `true`；遇到 `i > farthestReachable` 的第一个断点时返回 `false` |

初始时站在下标 `0`，所以边界初始化为 `0`，不是 `nums[0]`。两种写法都可能得到正确代码，但初始化为 `0` 更忠实地表达状态：处理任何踏板之前，只确认起点本身可达；处理下标 `0` 这个事件后，才把边界扩张到 `nums[0]`。

状态为什么足够？因为题目只问存在性，而且允许从可达位置选择任意不超过上限的正步长。只要知道 `[0,R]` 全部可达，就不需要知道下标 `j` 是从哪个前驱跳来的，也不需要知道到达它用了几步。对未来而言，不同历史的唯一作用都是提供某个最远终点，取这些终点的最大值就是全部有效信息。

状态也没有保存多余信息。一个布尔数组会逐项保存前缀内全为真的事实，一条具体路径会保存题目未要求的见证，队列会保存仍待扩展的多个位置；这里一个整数已经是描述连续前缀右端点的最小自然状态。

哪些候选可以永久丢弃？若某个位置 `i` 的候选终点 `i + nums[i]` 不超过当前边界，它没有带来新覆盖，以后也不需要单独记住，因为它能到达的每个位置已经可达。若出现 `i > farthestReachable`，则 `i` 以及其右侧所有位置当前都不可达；跳跃又只能向右，未处理位置不可能反过来帮助跨越断点，所以可以直接失败，不必继续看后面的巨大数值。

> **小白追问：** 一条较短路线也许后面更有力量，为什么还可以丢掉较短的候选终点？
>
> **先给短答：** 丢掉的是“这个位置再次证明了某段范围可达”的重复记录，不是丢掉范围内的位置；这些位置之后仍会按下标逐个获得扩张机会。
>
> **最小例子：** 在 `[2,4,1,0,0]` 中，下标 `0` 先覆盖到 `2`，其中下标 `1` 这条较短落点并未消失。扫描到 `1` 时，它仍会贡献终点 `5`，从而覆盖目标；算法只是没有保存“通过哪条路线到达 1”。
>
> **回到模型/代码：** `for` 循环负责让前缀内每个下标都被处理，`Math.max` 只淘汰没有扩大右端点的重复候选。较短候选的来源可丢，但已可达下标的扩张资格仍由 `currentIndex <= farthestReachable` 保留。

遍历必须从左到右，因为一个位置的资格来自更左侧位置已经建立的可达前缀。重复值和相等候选终点无需特殊处理，`Math.max` 会保持边界不变。值为零也不需要特殊分支：它只会给出候选终点 `i`，能否越过它由此前边界是否已经在更右侧决定。

> **小白追问：** 扫描到 `nums[i] == 0` 时不能再跳，为什么不立刻返回 `false`？
>
> **先给短答：** 零只说明“这个位置不能新增覆盖”，不说明以前的位置没有把边界扩到它的右边。
>
> **最小例子：** 对 `[2,0,1]`，处理下标 `0` 后边界已经是 `2`，目标已经可达。中间下标 `1` 虽然值为零，却只是没有贡献新的右端点，并没有切断下标 `0` 已经建立的覆盖。
>
> **回到模型/代码：** 代码没有为零写特殊分支。它统一计算 `candidateEnd = i + nums[i]`；零值只让候选等于 `i`，`Math.max` 会保留此前更大的 `farthestReachable`。

## 10. 所需数据结构详解

先由模型提出需求：按顺序读取每个位置的跳跃上限；保存当前前缀的右端点；比较当前下标是否在前缀内；把候选右端点与现有右端点取最大值。这里不需要管理一批顺序复杂的候选，也不需要按键查找历史，因此真正需要的只有输入数组和一个整数状态。

### 输入数组

Java 的 `int[]` 在连续下标上保存跳跃上限。通过 `nums[i]` 随机访问一个元素是 `O(1)`，读取数组长度也是 `O(1)`。本题从左到右只读数组，不修改元素。数组中保存的是“值”，循环变量 `i` 才是位置，二者不能混淆：可扩张终点是 `i + nums[i]`，不是单独比较 `nums[i]` 大小。

数组的随机访问特征与模型匹配，因为处理下标 `i` 时只需要当前值，无需删除、插入或重排。最坏需要读取 `n` 个元素，但输入数组本来就由题目提供，复杂度分析中通常不把它计入额外空间。

### 一个整数边界

`farthestReachable` 保存下标，不保存跳跃长度，也不保存数组值。每轮执行三类常数操作：用 `i > farthestReachable` 检查资格，计算 `i + nums[i]`，再用最大值更新边界。每个操作都是 `O(1)`。边界只会保持不变或向右增加，从不回退，这个单调性让已经确认的前缀无需重新检查。

> **小白追问：** 一个整数怎么可能代替 `boolean[] reachable` 中的一整排真假值？
>
> **先给短答：** 因为这里的真假排列只能是“一段真，后面全是假”，右端点已经唯一决定整排状态。
>
> **最小例子：** 在 `[2,0,1]` 处理完下标 `0` 后，布尔数组会写成 `[true,true,true]`。记录右端点 `R=2` 也能推出 `0、1、2` 全是真；不存在 `[true,false,true]` 这种需要逐项保存的形状。
>
> **回到模型/代码：** 判断 `i` 是否可达只需比较 `i <= farthestReachable`。只要连续前缀不变量成立，额外申请 `boolean[]` 就是在重复存储可以由边界推导的信息。

### 为什么不需要其他结构

| 候选结构 | 能做什么 | 本题为何多余 |
| --- | --- | --- |
| `boolean[]` | 逐个保存每个下标是否可达 | 可达状态必为连续前缀，一个右端点已经等价表示全部真值 |
| 队列 | 按发现顺序扩展所有可达下标 | 会把区间中的每个位置显式入队，保存了不必要的个体身份 |
| 哈希集合 | 去重已访问位置 | 顺序扫描天然不会重复处理下标，且前缀边界已隐含访问集合 |
| 栈或递归 | 保存尚未探索的路线 | 题目不要求路线，分支已被最远覆盖合并 |
| 优先队列 | 反复取得最大候选 | 当前所有候选只需聚合成一个最大值，不需要保留其余候选 |

额外状态最坏仍只有若干整数和循环变量，所以是 `O(1)`。这也说明“贪心”在这里不是某个特殊容器，而是一种信息压缩：对于未来判断，较小覆盖被较大覆盖完全支配，只保留最强状态即可。

> **小白追问：** 既然一直要最大的候选终点，为什么不把所有候选放进大顶堆？
>
> **先给短答：** 后续只会询问“历史最大值是多少”，不会删除最大值或重新查询第二大值，因此一个整数就能完成同样的聚合。
>
> **最小例子：** 对 `[1,3,0,0]`，下标 `0` 给出候选 `1`，下标 `1` 给出候选 `4`。得到 `4` 后，旧候选 `1` 再也不会成为决策依据；保存 `[4,1]` 的堆没有带来额外答案。
>
> **回到模型/代码：** `Math.max(farthestReachable, candidateEnd)` 就是持续聚合最大值的完整操作。优先队列会增加存储和维护成本，却没有对应的弹出或次大值需求。

## 11. 生活化类比及边界

可以把数组想成一条正在铺设的临时通道。起点处已经有一段连续安全地板。每个已经铺到的工位都有一台向右铺板机，机器标牌上的数字表示它最多能把连续地板铺到多远。检查一个工位时，不是决定某个人一定要走到哪块板，而是启动这台机器，看看整条安全通道的右边界能否继续延伸。

| 生活对象或动作 | 算法中的对应物 |
| --- | --- |
| 编号工位 | 数组下标 `i` |
| 工位机器的最大铺设距离 | `nums[i]` |
| 已连续铺好的安全通道 | 可达前缀 `[0, farthestReachable]` |
| 安全通道最右端 | `farthestReachable` |
| 工位已经位于安全通道内 | `i <= farthestReachable`，当前工位有资格工作 |
| 启动机器并尝试延长通道 | 计算 `i + nums[i]` 并取最大值 |
| 通道中出现尚未铺到的工位 | `i > farthestReachable`，形成无法跨越的断点 |
| 通道覆盖最后工位 | 返回 `true` |

例如通道目前已经连续铺到工位 `3`，那么工位 `0、1、2、3` 都能安全到达。检查工位 `2` 时，即使它的机器只能铺到 `3`，也无需登记一条新路线，因为没有延长通道；检查工位 `3` 时若机器能铺到 `6`，只需把右端更新为 `6`。之前由哪台机器铺过工位 `1` 或 `2`，对后续没有影响。

**类比到这里为止。** 现实铺板可能消耗材料、不同机器可能同时工作、工位之间可能有高度或承重差异，这些都不属于算法。题目中的跳跃不会消耗 `nums[i]`，多次到达同一位置也不会改变数值。更重要的是，这个类比依赖“机器铺出连续地板”，对应题目允许选择不超过最大值的任意步长；如果规则变成只能精确跳 `nums[i]` 格，可达位置可能出现空洞，此时一条连续通道就不再是正确模型。

## 12. 典型输入的完整数据变化图

先完整演算成功输入 `[2,3,1,1,4]`。下标和值必须分开看：

```text
方向：从左向右  ---->

下标：  0   1   2   3   4
数值： [2,  3,  1,  1,  4]
目标：                  ^ target = 4
初始：  ^ farthestReachable = 0
```

### 快照 0：初始状态

```text
当前输入：尚未使用任何位置的跳跃能力
处理前状态：farthestReachable = 0
判断依据：起点 0 天然可达，因此可达前缀是 [0,0]
执行动作：准备检查下标 0
处理后状态：[0,0] 内每个位置可达
新增结果：尚未覆盖目标 4
```

### 快照 1：处理下标 0

```text
当前输入：i = 0，nums[0] = 2
处理前状态：可达前缀 [0,0]
判断依据：0 <= 0，当前下标可达，可以使用它的跳跃能力
执行动作：candidateEnd = 0 + 2 = 2
          farthestReachable = max(0,2) = 2
处理后状态：可达前缀扩张为 [0,2]
新增结果：目标 4 尚未覆盖

下标：  0   1   2   3   4
可达：  是  是  是  否  否
边界：          ^ R = 2
```

这里不仅下标 `2` 可达，下标 `1` 也可达，因为在下标 `0` 可以选择跳一格或两格。前缀连续性第一次建立。

### 快照 2：处理下标 1

```text
当前输入：i = 1，nums[1] = 3
处理前状态：可达前缀 [0,2]
判断依据：1 <= 2，当前下标可达
执行动作：candidateEnd = 1 + 3 = 4
          farthestReachable = max(2,4) = 4
处理后状态：可达前缀扩张为 [0,4]
新增结果：4 >= target，目标已经被覆盖，返回 true

下标：  0   1   2   3   4
可达：  是  是  是  是  是
边界：                  ^ R = 4
```

代码此时提前结束，不再处理下标 `2、3、4`。提前结束是安全的，因为题目只问是否存在路线；边界覆盖 `4` 已经证明存在一种到达方式。无需真的选择 `0 -> 1 -> 4` 并把它存入结果，虽然从这次扩张可以知道这条路线确实存在。

把稳定时刻压缩成状态表：

| 处理下标 `i` | 处理前边界 | `i` 是否可达 | 候选终点 `i + nums[i]` | 处理后边界 | 结果 |
| ---: | ---: | --- | ---: | ---: | --- |
| 0 | 0 | 是 | 2 | 2 | 继续 |
| 1 | 2 | 是 | 4 | 4 | 返回 `true` |

再看一个不会立刻成功、能展示边界保持不变的输入 `[1,2,0,1,0]`：

```text
i = 0：R 由 0 变 1，可达 [0,1]
i = 1：R 由 1 变 3，可达 [0,3]
i = 2：候选仍为 2，R 保持 3；零值没有让已有覆盖倒退
i = 3：R 由 3 变 4，可达 [0,4]，成功
```

这说明算法不是遇到每个位置都必须扩张。只要边界不后退，不产生新信息的位置处理后即可忘记。

## 13. 边界场景的数据变化

### 失败场景：`[3,2,1,0,4]`

```text
方向：从左向右  ---->

下标：  0   1   2   3   4
数值： [3,  2,  1,  0,  4]
目标：                  ^
```

| 当前输入 | 处理前状态 | 判断依据 | 执行动作 | 处理后状态 | 新增结果 |
| --- | --- | --- | --- | --- | --- |
| `i=0, nums[0]=3` | `R=0` | `0 <= 0` | `R=max(0,3)` | `R=3`，前缀 `[0,3]` | 继续 |
| `i=1, nums[1]=2` | `R=3` | `1 <= 3` | 候选为 `3` | `R=3` | 无新覆盖 |
| `i=2, nums[2]=1` | `R=3` | `2 <= 3` | 候选为 `3` | `R=3` | 无新覆盖 |
| `i=3, nums[3]=0` | `R=3` | `3 <= 3` | 候选为 `3` | `R=3` | 无新覆盖 |
| `i=4, nums[4]=4` | `R=3` | `4 > 3` | 不允许读取它来扩张 | `R=3` | 返回 `false` |

最后一行是本题最容易写错的地方。下标 `4` 上的值再大也没有用，因为无法站到那里。正确顺序一定是先检查 `i <= R`，再计算候选终点。

```text
可达：  0 -- 1 -- 2 -- 3    4
        <---- [0,R] ---->    X 不可达
                         ^ 断点位于 3 与 4 之间
```

循环在 `i=4` 时终止，状态中没有队列、栈或残留节点，只有 `R=3`。右侧位置不再扫描，因为单向跳跃不可能由它们反过来修补断点。

### 单元素场景：`[0]`

```text
下标：  0
数值： [0]
起点：  ^
目标：  ^
初始：  R = 0
```

处理 `i=0` 时，资格判断 `0 <= 0` 成立，候选终点仍为 `0`，边界保持 `0`。由于目标也是 `0`，条件 `R >= target` 成立，返回 `true`。这里循环会执行一次，但不会访问越界位置，也不要求 `nums[0]` 大于零。语义上“不跳”就是合法成功。

### 零值但可跨过：`[2,0,1]`

处理下标 `0` 后边界直接成为 `2`，已经覆盖目标，返回 `true`。下标 `1` 的零甚至无需处理。这再次说明边界是否连续覆盖目标比“数组中有没有零”更准确。

## 14. 正确性与不变量

要证明的不是代码恰好对几个样例有效，而是一个核心命题：在扫描过程中，`farthestReachable` 始终准确表示由已处理且可达的位置能够覆盖的最右下标，并且从 `0` 到这个边界之间没有不可达空洞。

**初始成立。** 还没使用任何位置的跳跃能力时，起点 `0` 天然可达，因此可达前缀是 `[0,0]`，初始化边界为 `0` 正确。若数组只有一个元素，这个前缀已经包含目标。

**处理一个可达下标后仍成立。** 假设处理下标 `i` 之前，可达位置包含连续前缀 `[0,R]`，并且 `i <= R`。从 `i` 可以选择任意步长 `1` 到 `nums[i]`，所以它新增的候选位置是连续区间 `[i+1, i+nums[i]]`。因为 `i` 本身位于旧前缀内，新区间的左端至多紧挨旧前缀，不会在中间留下空洞。旧前缀与新区间合并后，恰好形成 `[0,max(R,i+nums[i])]`，所以用最大值更新后，不变量继续成立。

**当前动作产生的成功结果满足题意。** 当边界达到或超过 `target` 时，目标属于已证明可达的连续前缀，所以至少存在一条合法跳跃路线到达目标。边界可能超过数组末尾，但这只表示某个合法起跳点的能力足以越过末尾；由于可以选择不超过上限的步长，也就可以恰好落到末尾。

> **小白追问：** 边界刚覆盖目标就返回，会不会漏掉后面某个位置造成的失败？
>
> **先给短答：** 不会；题目问是否存在成功路线，目标一旦被证明可达，尚未处理的位置不能撤销这个已经成立的事实。
>
> **最小例子：** 在 `[3,0,0,0]` 中，处理下标 `0` 后边界直接到 `3`。后面三个零都没有扩张能力，但这不影响从 `0` 选择跳三格直接落到目标。
>
> **回到模型/代码：** 边界更新后立即判断 `farthestReachable >= targetIndex`。这个条件检查的是目标是否已属于可达前缀，而不是未来每个位置是否都还能继续跳。

**不会漏掉成功路线。** 每个属于当前可达前缀的下标都会按从左到右顺序被处理，除非此前已经覆盖目标而提前成功。处理时会把该位置能达到的最远终点纳入最大值。任何合法路线使用的每一个起跳点都在某一时刻属于这个前缀，其贡献不会被遗漏。较短终点无需分别记录，因为同一位置允许选择所有更短步长，它们都包含在连续区间内。

**被丢弃的较小候选以后不需要。** 若 `i + nums[i] <= R`，这个位置能到达的全部下标都已在可达前缀中。未来位置只关心自己是否落在前缀内，以及所有已处理位置形成的最右覆盖；候选由谁提供不会改变这两个事实，所以可以安全丢弃来源和路线。

**遇到断点可以判失败。** 若扫描到第一个 `i > R`，根据不变量，所有已处理可达位置最远只能到 `R`，没有一个能到 `i`。由于后续下标都大于等于 `i`，而跳跃只允许从已可达位置向右出发，后续位置也不可能先被到达再回来修补断点。因此目标不可能可达，立即返回 `false` 正确。

> **小白追问：** 断点右边可能有很大的数字，为什么它永远不能回来修复断点？
>
> **先给短答：** 数字只有站到那个下标上才生效，而跳跃又只能从左向右；到不了右侧，就没有资格使用右侧的能力。
>
> **最小例子：** 对 `[1,0,100]`，下标 `0` 最多把边界推到 `1`，下标 `1` 无法继续。扫描到下标 `2` 时有 `2 > 1`，所以值 `100` 只是写在一个站不到的位置上。
>
> **回到模型/代码：** `if (currentIndex > farthestReachable) return false` 必须发生在读取该位置贡献之前。这个失败条件把“不具备起跳资格”落实成控制流。

**遍历结束时结论完整。** 若提前因覆盖目标返回 `true`，成功已经证明；若遇到断点返回 `false`，失败已经证明。若循环自然结束，说明每个下标都通过了资格检查，而最后下标也在其中，因此应返回 `true`。本文代码通常会在处理到目标之前由边界条件提前返回，但末尾的 `true` 仍让控制流程在所有合法情况下闭合。

## 15. 时间与空间复杂度推导

定义 `n` 为数组长度，目标下标是 `n - 1`。一次“处理位置”的成本包括一次可达资格比较、一次加法、一次最大值比较，以及可能的一次目标比较，这些都是常数时间。

### 纯分支搜索

直接回溯会枚举合法跳跃路线。当前面位置能到达许多后继时，从起点到终点可以形成指数数量的不同递增下标序列。以中间位置是否经过来计数，路径数量可达到 `2` 的指数级，因此最坏时间写作 `O(2^n)` 量级。递归深度最多沿着每次跳一格达到 `n` 层，所以调用栈为 `O(n)`；若还显式保存当前路径，同样需要 `O(n)`。

### 记忆化或布尔可达表

记忆化把“从下标 `i` 能否成功”压缩为 `n` 个状态，但每个状态最坏仍检查 `O(n)` 个后继，因此时间 `O(n^2)`，缓存与递归栈为 `O(n)`。顺推布尔数组同理：有 `n` 个可达起点，每个起点可能标记 `O(n)` 个位置，最坏 `O(n^2)` 时间，`O(n)` 额外空间。

### 最远可达边界模型

循环下标只从左向右增加，每个实际处理到的下标至多进入循环一次；循环内部没有嵌套扫描。最坏在失败断点位于末尾或直到最后才确认成功时处理 `n` 个位置，所以总时间为：

```text
n 次位置处理 × 每次 O(1) = O(n)
```

提前覆盖目标时可能只处理前 `k` 个位置，实际运行时间为 `O(k)`，其中 `k <= n`；渐进最坏复杂度仍记作 `O(n)`。这里不需要用均摊技巧掩盖内层循环，因为根本没有内层移动：每个元素生命周期只有“被按下标读取一次，然后永久略过”。

> **小白追问：** `O(n)` 和 `O(1)` 是怎么数出来的，是否只是因为代码看起来很短？
>
> **先给短答：** 时间看每个下标被处理多少次，空间看新申请的状态是否随数组变长；两者都要按操作计数，而不是按代码行数猜。
>
> **最小例子：** 对 `[1,2,0,1]`，循环依次处理下标 `0、1` 后就覆盖目标；最坏情况下也只会让 `0、1、2、3` 各进入一轮，不会回头。数组从四个元素扩到四万个时，额外状态仍只是几个整数。
>
> **回到模型/代码：** `currentIndex` 单调加一，每轮只有比较、加法和取最大值，所以最坏总时间是 `n × O(1)`。`targetIndex`、`farthestReachable`、`candidateEnd` 的数量固定，因此额外空间是 `O(1)`。

额外空间只包含 `farthestReachable`、`i` 和候选终点等常数个整数，是 `O(1)`。输入数组不属于算法新申请的空间，布尔返回值也不随 `n` 增长。实现没有递归，所以不存在递归栈空间。若题目改为要求返回具体路径，则需要记录前驱或关键落点，空间结论会随之变化。

### 泛用模型骨架

下面的骨架表达一类“位置形成连续可达前缀”的问题。`furthestEndFrom` 接收当前位置，返回该位置能够贡献的绝对最右终点。调用方必须保证目标下标非负，并保证 `0` 到目标之间都是这个问题中的有效位置。骨架先检查当前位置属于已有前缀，再允许它扩张边界。

```java
import java.util.function.IntUnaryOperator;

class ReachablePrefixBoundaryTemplate {
    public boolean canCoverTarget(
            int targetIndex,
            IntUnaryOperator furthestEndFrom) {
        if (targetIndex < 0) {
            return false;
        }

        int farthestReachable = 0;

        for (int currentPosition = 0;
                currentPosition <= targetIndex;
                currentPosition++) {
            if (currentPosition > farthestReachable) {
                return false;
            }

            int candidateEnd = furthestEndFrom.applyAsInt(currentPosition);
            farthestReachable = Math.max(farthestReachable, candidateEnd);

            if (farthestReachable >= targetIndex) {
                return true;
            }
        }

        return true;
    }
}
```

这个骨架不是把题目变量简单改名。它抽出了三个稳定角色：按序到来的 `currentPosition`、聚合所有历史选择的 `farthestReachable`、当前对象贡献的 `candidateEnd`。函数参数只负责告诉骨架“当前对象最远能覆盖到哪里”，资格检查、状态更新与结果时机仍由统一控制流程负责。

> **小白追问：** 为什么代码必须先检查当前位置可达，再计算并合并它的候选终点？
>
> **先给短答：** `nums[i]` 只是“站在 `i` 上以后”的能力；若 `i` 不可达，这份能力根本不存在于当前问题的可用选择中。
>
> **最小例子：** 在 `[0,100]` 中，处理下标 `0` 后边界仍为 `0`。到下标 `1` 时应先发现 `1 > 0` 并失败；若先计算 `1 + 100`，就会借用不可达位置的能力，把失败数组误判为成功。
>
> **回到模型/代码：** `if (currentPosition > farthestReachable)` 位于 `furthestEndFrom.applyAsInt(...)` 之前。题目代码中的同一顺序也必须保留，不能为了少写一段判断而交换。

### LeetCode 可直接提交代码

```java
import java.util.Arrays;

class Solution {
    public boolean canJump(int[] nums) {
        int targetIndex = nums.length - 1;
        int farthestReachable = 0;

        for (int currentIndex = 0; currentIndex < nums.length; currentIndex++) {
            if (currentIndex > farthestReachable) {
                return false;
            }

            farthestReachable = Math.max(farthestReachable, candidateEnd);

            if (farthestReachable >= targetIndex) {
                return true;
            }
        }

        return true;
    }
}

public class Main {
    private static void runCase(Solution solution, int[] nums) {
        System.out.println(
                Arrays.toString(nums) + " -> " + solution.canJump(nums));
    }

    public static void main(String[] args) {
        Solution solution = new Solution();

        runCase(solution, new int[] {2, 3, 1, 1, 4});
        runCase(solution, new int[] {3, 2, 1, 0, 4});
        runCase(solution, new int[] {0});
        runCase(solution, new int[] {2, 0, 1});
    }
}
```

```text

[3, 2, 1, 0, 4] -> false
[0] -> true
[2, 0, 1] -> true
```

模型与代码的对应关系如下：

| 模型角色 | Java 变量或代码块 |
| --- | --- |
| 当前对象 | `currentIndex` |
| 输入位置提供的扩张能力 | `nums[currentIndex]` |
| 当前可达前缀右端 | `farthestReachable` |
| 当前对象的候选覆盖终点 | `candidateEnd` |
| 起跳资格 | `currentIndex <= farthestReachable`；代码用反条件提前失败 |
| 状态变化 | `Math.max(farthestReachable, candidateEnd)` |
| 成功结果时机 | `farthestReachable >= targetIndex` |
| 失败结果时机 | `currentIndex > farthestReachable` |

代码刻意不记录实际跳法，因为方法契约只要求布尔值。变量名也区分了“数组中的跳跃长度”和“计算后的绝对终点”，避免把 `nums[currentIndex]` 误当成下标。

> **小白追问：** 一轮代码里的“资格、候选、汇总、判成功”为什么要按这个次序理解？
>
> **先给短答：** 资格决定当前数据能不能用，候选把相对步长变成绝对下标，汇总更新全局状态，最后才能根据新状态判断答案。
>
> **最小例子：** 对 `[1,2,0]`，下标 `0` 先通过资格检查，候选是 `0+1=1`，边界变为 `1`，还未成功。下标 `1` 再通过检查，候选是 `1+2=3`，边界覆盖目标 `2`，此时返回 `true`。
>
> **回到模型/代码：** 四步依次对应 `currentIndex > farthestReachable`、`candidateEnd`、`Math.max` 和 `farthestReachable >= targetIndex`。调试时按这四个状态点观察，比逐行翻译 Java 语法更容易找到建模错误。

## 17. 边界、常见错误与调试观察点

### 边界清单

- `nums.length == 1`：起点就是目标，应返回 `true`，无论唯一元素是不是零。
- `nums[0] == 0` 且长度大于一：初始边界无法扩张，处理下标 `1` 时失败。
- 中间有零：不能直接判失败，先看此前边界是否已经跨过它。
- 连续多个零：仍然只看边界能否越过整个断点，不需要统计零的数量。
- 某次候选终点超过数组末尾：可直接成功，因为可以选择较短步长落到末尾。
- 大数值：在官方约束下 `currentIndex + nums[currentIndex]` 不会超出 `int`。

### 常见建模错误

| 层次 | 错误表现 | 为什么错 |
| --- | --- | --- |
| 建模错误 | 把“保留最大覆盖”理解成“每次实际跳到最远位置” | 前者合并所有可达路线，后者只保留一条路线，会丢掉较近但后劲更强的位置 |
| 建模错误 | 认为可达位置可能任意离散，却仍只存一个边界 | 本题能存边界是因为步长可在上限内任选；若只能精确跳固定长度，这个状态不够 |
| 条件错误 | 先用 `nums[i]` 更新边界，再检查 `i` 是否可达 | 会借用不可达位置的能力，例如把 `[0,100]` 误判为成功 |
| 条件错误 | 遇到 `nums[i] == 0` 立即返回失败 | 以前的位置可能已经把覆盖范围延伸到零的右边 |
| 条件错误 | 只有 `farthestReachable > target` 才成功 | 恰好等于目标已经成功，必须使用 `>=` |
| 代码错误 | 把边界更新写成 `max(R, nums[i])` | `nums[i]` 是相对步长，绝对终点应是 `i + nums[i]` |
| 代码错误 | 单元素时要求至少执行一次正长度跳跃 | 题目问能否到达，初始位置已经等于目标 |

### 最有价值的调试状态

遇到错误用例时，不要打印整棵假想路线。每轮打印下面五项即可：

```text
currentIndex
nums[currentIndex]
更新前 farthestReachable
candidateEnd = currentIndex + nums[currentIndex]
更新后 farthestReachable
```

对失败输入 `[3,2,1,0,4]`，期望观察到边界序列 `0 -> 3 -> 3 -> 3 -> 3`，随后在 `currentIndex=4` 处发现 `4 > 3`。如果日志中出现使用下标 `4` 后边界突然变大，说明资格检查顺序错了。

对 `[2,0,1]`，应在处理下标 `0` 后直接得到边界 `2` 并成功。如果代码在下标 `1` 的零处失败，说明它错误地把“当前踏板不能扩张”当成“整个可达前缀都不能扩张”。

还可以在调试版本中检查断言：每轮更新后 `farthestReachable` 不应小于更新前值；准备更新时必须满足 `currentIndex <= farthestReachable`。这两个观察分别对应边界单调性与起跳资格，是比逐行追踪语法更接近模型的排错方式。

## 18. 最终模型卡

| 模型卡项目 | 结论 |
| --- | --- |
| 识别指纹 | 从起点单向前进；每个位置提供一个连续的最大覆盖范围；只问目标是否可达，不要求路线或最少次数 |
| 一句话关系模型 | 每个已可达下标贡献一个向右的连续区间，所有区间合并后只需保留可达前缀的最右端 |
| 实际保存什么 | 一个整数 `farthestReachable`，保存最远可达下标 |
| 状态何时变化 | 当前下标位于可达前缀内时，用它的候选终点尝试扩张边界 |
| 答案何时产生 | 边界覆盖末尾时成功；扫描遇到前缀外的第一个下标时失败 |
| 核心不变量 | `[0, farthestReachable]` 中每个下标都可达，且边界是已处理可达位置能提供的最大终点 |
| 时间复杂度 | `O(n)` |
| 额外空间复杂度 | `O(1)` |

四句建模结论：

```text
我正在处理的对象是：从左到右依次出现的数组下标。
我必须持续保存的是：所有已处理可达位置共同形成的最远可达边界。
当当前下标仍位于可达前缀内时，我执行：用当前下标的候选终点扩张边界。
答案在边界覆盖目标或扫描遇到第一个不可达断点时由最远可达边界计算出来。
```

泛用模板可以压缩成五步：

```text
1. 确认起点，初始化连续可达区域的边界。
2. 按信息传播方向扫描当前位置。
3. 先检查当前位置是否属于已有可达区域。
4. 只把当前位置贡献的最强终点聚合到边界中。
5. 边界覆盖目标则成功，出现不可跨越断点则失败。
```

可迁移变式：

- **45. 跳跃游戏 II**：条件仍是连续覆盖，但结果从“能否到达”变成“最少跳几次”。需要额外保存当前跳数能够覆盖的层边界，答案产生时机从首次覆盖变为完成一层扩张。
- **返回一条可行路线**：可达条件不变，但最小状态不再只有一个边界。边界扩张时需要记录由哪个位置首次覆盖新区域，之后才能回溯路径。
- **只能精确跳 `nums[i]` 格**：变化的是可达集合的结构。位置可能离散而不再形成连续前缀，一个右边界不足以表达状态，通常要保存访问集合并做图搜索。
- **允许向左跳或传送**：变化的是信息方向。断点右侧可能通过其他边回到左侧，单向扫描不再足够，需要节点、边、队列或递归栈来维护一般可达性。

真正应记住的不是“跳跃题用 `farthest`”，而是判断状态能否压缩的三个问题：目标是否只关心存在性；较强覆盖是否完全支配较弱覆盖；所有已覆盖位置是否形成无空洞的连续区域。三者都成立时，最远边界模型才自然出现。
