# 20. 有效的括号：把嵌套顺序翻译成一摞未完成约定

这道题代码很短，真正值得练习的却不是记住几行 `push` 和 `pop`。困难在于：为什么只看当前字符和一个“最后尚未完成的对象”就足够，为什么不能只统计数量，为什么右括号出现时可以立即判错，以及扫描结束时为什么还要再检查一次状态。

本篇会刻意晚一点再说数据结构名称。我们先从题目关系、人工消去法、重复扫描和失败方向出发，逐步得到“必须按相反顺序完成未结事项”这个状态要求。等要求已经清楚以后，选择什么结构就不再像猜题型，而只是为模型找一个合适的容器。

## 2. 完整题目

给定字符串 `s`，其中每个字符都属于下面六种括号之一：

```text
(  )  [  ]  {  }
```

判断整个字符串是不是一个有效的括号序列。有效需要同时满足三个条件：

1. 每个左括号最终都由同类型的右括号闭合，例如 `(` 只能由 `)` 闭合。
2. 闭合顺序必须与打开顺序相容。后打开的内部括号必须先闭合，不能交叉配对。
3. 每个右括号在它左侧都必须有一个尚未使用、类型匹配的左括号。

### 输入与输出

- 输入：只含六种括号字符的字符串 `s`。
- 输出：若整个字符串满足类型、数量和嵌套顺序要求，返回 `true`；否则返回 `false`。
- Java 方法入口：

```java
public boolean isValid(String s)
```

### 示例 1

```text
输入：s = "()"
输出：true
```

左括号 `(` 被紧随其后的同类型右括号 `)` 闭合，没有遗留未完成关系。

### 示例 2

```text
输入：s = "()[]{}"
输出：true
```

三个括号对彼此并列。完成一对后可以开始下一对，并列不要求整个字符串只能有一层最外括号。

### 示例 3

```text
输入：s = "(]"
输出：false
```

数量看起来是一左一右，但类型不一致。`(` 建立的闭合要求是 `)`，不能由 `]` 代替。

### 示例 4

```text
输入：s = "([])"
输出：true
```

先打开圆括号，再在其中打开方括号；关闭时先 `]` 后 `)`，正好与打开顺序相反。

### 示例 5

```text
输入：s = "([)]"
输出：false
```

三类数量都可以平衡，但配对发生了交叉：打开顺序是 `(`、`[`，因此下一次必须先关闭 `[`；字符串却先给出 `)`。

### 官方约束及其建模信号

- `1 <= s.length <= 10^4`
- `s` 只由字符 `'('`、`')'`、`'['`、`']'`、`'{'`、`'}'` 组成

长度上限说明平方级方案在极端输入下会做约一亿次量级的字符处理，不应作为目标实现；一次扫描更合适。字符范围又说明本题不需要处理空格、字母、转义或未知符号。若模型迁移到表达式检查器，才需要额外规定普通字符是忽略还是报错。

括号总数为奇数时不可能全部两两配对，可以提前返回 `false`。这是由题意得到的可选剪枝，不是核心模型；即使不写它，后面的扫描模型仍然正确且仍是 `O(n)`。

## 3. 先把题目说成人话

**一句话生活化复述：**每打开一层包装，就记下一张对应的封口要求；封装时必须先完成最后打开的那一层，并且最后不能留下任何没封好的包装。

**一句话关系化复述：**从左到右处理字符，左括号建立一个待完成的同类型闭合关系，右括号只能完成最近建立但尚未完成的那一个关系。

### 对象、关系、方向、目标和限制

| 要素 | 本题含义 |
| --- | --- |
| 对象 | 字符串中的每一个括号字符，以及扫描到当前位置形成的前缀 |
| 关系 | 一个左括号与未来一个同类型右括号配对，所有配对不能交叉 |
| 方向 | 从左向右读取；右括号只能使用已经出现且尚未闭合的左括号 |
| 目标 | 判断所有字符能否恰好组成类型正确、顺序正确的完整配对 |
| 限制 | 一个字符只能使用一次；右括号不能预支未来的左括号；结束时不能有遗留左括号 |

### 题目关系图

以 `([{}])` 为例，下标和值必须分开看：

```text
下标：  0   1   2   3   4   5
字符：  (   [   {   }   ]   )
配对：  |   |   +---+   |   |
        |   +-----------+   |
        +-------------------+

打开方向：0 -> 1 -> 2
关闭方向：3 -> 4 -> 5
```

最里面的 `{` 最晚出现，却由最早到来的 `}` 关闭。也就是说，闭合顺序是打开顺序的逆序。题目中的关键不是“左右字符数量相等”，而是“尚未完成关系的优先级随嵌套改变”。

## 4. 第一切入点：读题时先看什么

第一分钟先圈出三组词：**同类型**、**正确顺序**、**每个右括号都有对应左括号**。

- “同类型”说明只记总数量不够，还必须保留类型信息。
- “正确顺序”说明配对不是任意连线，而是存在先后约束。
- “右括号有对应左括号”说明检查一个右括号时，信息只能来自已经扫描过的左侧，未来字符不能修复当前缺失。

“圆括号、方括号、花括号”只是三种类型的具体名字。先不要因为看见括号就背结构模板，而应问：当我读到一个右括号时，人脑到底检查什么？

对最小嵌套样例 `([])`，人工过程是：

```text
读到 ( ：记住“以后要有 )”
读到 [ ：在上一条要求尚未完成时，再记住“先要有 ]”
读到 ] ：它完成最近的一条要求
读到 ) ：它完成剩下的一条要求
没有遗留要求，所以有效
```

这里已经出现模型雏形：人脑没有枚举所有配对，也没有回头重新数完整字符串，只保留“还没完成什么”和“下一项必须完成什么”。

> **小白追问：** 为什么不能只确认三类左括号和右括号的总数量相等？
>
> **先给短答：** 数量只能说明原料够不够，不能说明每个右括号出现时关掉的是不是当前最里面的一层。
>
> **最小例子：** `([)]` 中 `()` 和 `[]` 都各有一对，但读到 `)` 时，最近尚未闭合的是 `[`。如果让 `)` 越过 `[` 去找 `(`，两条配对线就会交叉，所以数量平衡仍然无效。
>
> **回到模型/代码：** 状态不能只是三个计数器，还要保留每一层未完成要求的先后顺序；后面代码中的 `expectedClosings` 正是这条有顺序的状态。

数据范围 `10^4` 给出性能信号：最好每个字符只处理常数次。要达到这一点，扫描过的前缀必须压缩成一个足够小、又能决定未来是否合法的状态，而不能每来一个字符就重新检查整个前缀。

## 5. 最直接的人工或暴力模型

一种非常自然且一定正确的人工方法是：**反复消去当前相邻的合法括号对**。

完整步骤如下：

1. 在当前字符串中寻找相邻的 `()`、`[]`、`{}`。
2. 把找到的合法相邻对删除，因为这一对内部已经没有未处理内容，可以视为完整结算。
3. 删除后，原本隔着这一对的字符会靠在一起，可能形成新的相邻合法对。
4. 持续重复，直到一轮操作不能再删除任何字符。
5. 若最终字符串为空，原字符串有效；若还剩字符，原字符串无效。

例如：

```text
({[()]})
({[]})
({})
()
空串
```

这不是碰运气。若一个非空括号序列有效，它一定存在一对“最内层括号”。最内层内部没有别的字符，所以这两个括号在当前字符串中相邻，并且类型匹配。删除它以后，剩余部分仍保持有效的嵌套关系。不断删除最终必然得到空串。

反过来，我们只删除题目允许的相邻合法对。每次删除相当于确认一个没有交叉的最内层配对；如果最后能删空，所有原字符都被纳入了合法配对。因此这个直接模型不会把无效字符串误判为有效。

若用不可变 Java `String` 反复执行替换，每一轮都要扫描并创建新字符串。最坏情况下需要约 `n / 2` 轮，每轮处理最多 `O(n)` 个字符，所以时间复杂度为 `O(n^2)`。任一时刻最长临时字符串不超过 `n`，峰值额外空间为 `O(n)`；整个执行期间累计分配的字符量可能达到 `O(n^2)`。

这个模型的价值很大：它揭示了合法序列可以从最内层逐步结算。推荐模型并不是推翻它，而是设法在字符第一次到来时就维护同样的“可结算关系”。

## 6. 暴力到底浪费在哪里

看深度嵌套输入 `(((())))`。为避免替换调用顺序影响描述，下面每一轮只消去当前最内层的一对：

```text
轮次 0：(((())))   扫描 8 个字符，发现中心 ()
轮次 1：((()))     又扫描外层字符，发现新的中心 ()
轮次 2：(())       再次扫描此前已经看过的外层字符
轮次 3：()         再扫描一次
轮次 4：空串       成功
```

最外层第一个 `(` 在多轮中被反复读取。第一次读取时我们已经知道它尚未闭合，但直接模型没有保存这条中间结论；字符串重建以后，只能从头再次发现它。深度越大，重复扫描越明显。

具体浪费可以分成四类：

| 现象 | 被浪费的工作 |
| --- | --- |
| 重复读前缀 | 外层左括号在每次消去内层后又被扫描 |
| 重复创建字符串 | 每次删除都会复制仍然保留的字符 |
| 丢弃中间结论 | “这个左括号正在等待右括号”没有被独立保存 |
| 延迟发现永久错误 | `([)]` 中读到 `)` 时已经无法合法闭合 `[`，反复替换却要等到停止后才判错 |

尤其要注意最后一点。对已经读到的前缀 `([)`，未来无论补什么都不能改变 `)` 出现在 `[` 闭合之前的事实。这个错误是永久的，不必继续扫描，更不必等待整串替换稳定。

因此优化目标可以写成一句具体的话：

> 不再反复重建并检查整个字符串，而是在字符第一次到来时维护所有尚未闭合的要求；右括号一出现，就立刻结算最近要求或确认该前缀永久无效。

## 7. 容易想到但走不通的方向

### 方向一：分别统计三类左右括号数量

看到“每个左括号都要有右括号”，很自然会统计 `(` 与 `)`、`[` 与 `]`、`{` 与 `}` 的数量是否分别相等。它能保存总量信息，也能排除 `"((`、`"(()"` 这样的明显不平衡输入。

但它完全丢失位置和嵌套关系。`([)]` 中圆括号和方括号的左右数量都相等，计数却无法表达 `[` 必须在 `(` 之前关闭。这个方向不是性能差，而是信息不足，逻辑上会误判。失败带来的条件是：状态必须保留未闭合类型的**顺序**，不能只保留频次。

### 方向二：只维护一个“当前深度”整数

若只有一种括号，可以遇 `(` 加一、遇 `)` 减一，并要求中途不为负、结尾为零。于是容易把三种括号也压缩成一个深度：任何左括号加一，任何右括号减一。

深度能发现 `")("` 的第一个字符无对应左括号，也能发现结尾数量不平衡；但 `(]` 的深度变化是 `1 -> 0`，仍会被误判。它知道有几层，却不知道每层是什么类型。结论不是“深度思想没用”，而是本题的最小状态至少要为每一层保存类型。

### 方向三：让最早打开的括号最先关闭

把所有未闭合对象排队似乎很合理：左括号到来就加入尾部，右括号到来就检查最早的头部。它保存了完整类型和顺序，问题出在使用顺序反了。

对合法输入 `([])`：最早打开的是 `(`，但第一个关闭字符是 `]`，它必须匹配最近打开的 `[`。如果检查最早对象，会错误地拿 `]` 与 `(` 比较。这个失败说明所需关系不是先进先出，而是**后建立的内层关系先完成**。

这些偏差方向共同逼出了三个建模条件：保留类型、保留未完成关系的顺序、每次只访问最后加入的未完成关系。

## 8. 关键视角转换

直接模型盯着“哪些相邻字符现在可以删掉”，需要反复观察整个剩余字符串。新模型改为盯着“扫描过的前缀给未来留下了哪些义务”。

| 原视角 | 新视角 |
| --- | --- |
| 从完整字符串中反复寻找最内层合法对 | 每个新字符到来时增量维护前缀状态 |
| 删除字符后重新扫描 | 已匹配对象立即丢弃，只保留未匹配对象 |
| 等替换停止后判断失败 | 右括号无法完成当前义务时立即失败 |
| 保存仍未被删掉的整个字符串 | 只保存会影响未来判断的未闭合要求 |

关键问题变成：处理完前缀以后，未来到底需要知道前缀的什么？

- 已经完整匹配的 `()` 不会再影响任何未来字符，可以永久忘掉。
- 尚未闭合的左括号仍会限制未来，必须保留。
- 对这些左括号，未来首先只能关闭最后打开的一个；外层必须等内层完成。
- 一旦当前右括号不符合这个最近要求，未来字符只能出现在错误之后，无法回到过去修复顺序。

于是长度可能很大的前缀被压缩为一条有顺序的“未完成义务链”。新字符只与链尾交互：左括号在链尾增加义务，右括号检查并删除链尾义务。每个字符只参与一次加入或一次结算，重复扫描就消失了。

> **小白追问：** “左括号建立义务，右括号触发结算”到底是什么意思？
>
> **先给短答：** 左括号出现时答案还不能确定，只能登记未来必须出现的符号；右括号出现时，才有条件检查最近一项登记是否被正确完成。
>
> **最小例子：** 扫描 `([])`：读到 `(` 时登记 `)`；读到 `[` 时再登记 `]`；读到 `]` 时完成第二项；读到 `)` 时完成第一项。两个左括号都只创建要求，两个右括号都只结算要求。
>
> **回到模型/代码：** 三个左括号分支执行 `push`，这是“建立事件”；最后一个右括号分支执行判空、比较和 `pop`，这是“结算事件”。

> **小白追问：** 一对括号匹配以后，为什么可以把它永久忘掉？
>
> **先给短答：** 这两个位置已经互相配对，未来字符既不能插到它们中间，也不能再次使用其中任何一个位置。
>
> **最小例子：** 在 `([]` 的最后一个 `]` 到来后，`[` 与 `]` 已经闭合。后续只需知道外层还期待 `)`；继续保留已经完成的 `[]`，不会帮助判断下一个字符。
>
> **回到模型/代码：** 成功匹配时的 `pop()` 删除的是已结算义务。删除后栈中只剩仍会限制未来的状态，这正是状态压缩的来源。

这也是从“事后消去结果”到“在线维护状态”的通用转换。类似模型会出现在撤销操作、函数调用返回、目录进入与退出、表达式分组以及递归执行上下文中。

## 9. 正式建立模型

先给出不依赖结构名称的统一模型：

| 建模项 | 本题结论 |
| --- | --- |
| 对象 | 当前扫描字符，以及前缀中尚未闭合的左括号 |
| 关系 | 左括号必须被未来同类型右括号闭合，且配对不能交叉 |
| 状态 | 从外层到内层排列的未完成闭合要求；链尾是下一项必须完成的要求 |
| 事件 | 左括号建立新要求；右括号尝试完成最近要求；空状态或类型冲突触发失败 |
| 不变量 | 处理完任意合法前缀后，状态只含尚未闭合的要求，顺序为建立顺序，最后一项必须最先完成 |
| 结果时机 | 扫描中发现无法匹配立即返回 `false`；全部扫描后状态为空才返回 `true` |

### 状态为什么足够

已经匹配完成的括号对不再对未来施加限制，保存它们属于多余历史。未匹配左括号则不能丢，因为未来右括号的类型和先后合法性都由它们决定。状态按照出现顺序保存这些未匹配对象，既没有遗失必要信息，也没有保存完整前缀。

> **小白追问：** 为什么未来只需关心“最近一个”尚未匹配的左括号？更早的左括号不重要吗？
>
> **先给短答：** 更早的左括号仍然重要，但它被最近打开的内层括号暂时挡住；只有内层先闭合，外层才重新获得被检查的资格。
>
> **最小例子：** 读完 `([` 后有两项要求：外层期待 `)`，内层期待 `]`。下一个字符若是 `]`，内层完成，外层的 `)` 才重新成为最近要求；若先来 `)`，就发生交叉。
>
> **回到模型/代码：** 所有未完成要求都保存在 `expectedClosings` 中，但每个右括号只访问栈顶。栈顶代表当前唯一有资格被完成的内层要求。

### 哪些信息可以永久丢弃

当前右括号与最近要求匹配时，这一对已经完整位于某个外层关系内部，或者作为独立关系存在。后续字符不能再与这两个字符配对，所以可以把最近要求删除。删除并不是猜测，而是完成了一项题目要求。

反之，空状态遇到右括号时，左侧不存在可用对象；类型不匹配时，若跳过最近左括号去匹配更早的左括号，就会造成配对交叉。两种情况都无法由未来修复，可以安全地立即结束。

> **小白追问：** 栈里明明可能有同类型左括号，为什么不能向下搜索一个能和当前右括号匹配的？
>
> **先给短答：** 题目要求合法嵌套，不是任意配对；绕过栈顶会留下一个更晚打开的括号，配对关系必然交叉。
>
> **最小例子：** 扫描 `([)]` 到 `)` 时，状态从底到顶期待的是 `[), ]]`。向下确实能找到 `)`，但它属于外层 `(`；越过栈顶 `]` 去匹配它，会让 `[` 悬在圆括号配对线外，顺序已经无法合法化。
>
> **回到模型/代码：** 右括号只比较 `expectedClosings.pop()` 取出的栈顶，不调用遍历或 `contains`。栈顶不匹配就返回 `false`，不能搜索其他位置。

### 为什么从左向右

右括号只能与左侧已出现的左括号配对。从左向右扫描时，状态准确表达“过去对未来的约束”，每个错误都能在形成时发现。理论上也可以从右向左建立对称模型，但那会把开闭角色反转，不符合日常阅读顺序，也不比当前模型更清晰。

### 两种等价的保存方式

未完成要求有两种表示：

| 模型 | 加入时保存 | 右括号到来时的判断 | 特点 |
| --- | --- | --- | --- |
| 保存左括号 | 保存 `(`、`[` 或 `{` | 取最后一个左括号，再通过映射判断是否与当前右括号成对 | 更贴近题面“保存未闭合左括号” |
| 保存期待的右括号 | 读到 `(` 就保存 `)`，读到 `[` 就保存 `]` | 取最后一个期待值，直接与当前字符比较 | 把类型映射提前到建立义务时，关闭分支更统一 |

二者携带的信息量相同，因为每种左括号与期待右括号是一一对应的。本篇完整实现采用“保存期待右括号”：状态中的字符不再描述过去出现了什么，而是直接描述未来下一步必须看到什么。

> **小白追问：** 保存左括号和保存期待右括号，哪一种才是正确写法？
>
> **先给短答：** 两种都正确，差别只在于把“类型转换”放在入栈时还是匹配时；一篇实现必须从头到尾保持同一种语义。
>
> **最小例子：** 读到 `[` 时，可以保存 `[`，等 `]` 到来再判断它们是否成对；也可以立刻保存 `]`，等关闭时直接比较字符。两种状态都表示同一项未完成关系。
>
> **回到模型/代码：** 本文变量名是 `expectedClosings`，所以压入的是 `)`、`]`、`}`。若改存左括号，关闭分支必须增加“当前右括号对应哪种左括号”的映射，不能仍直接比较字符。

相同类型重复出现不需要去重。`((()))` 中三个 `(` 是三项不同层级的义务，即使期待值都为 `)`，也必须保存三份；每个 `)` 只能结算其中一份。

## 10. 所需数据结构详解

模型要求一个容器具备下面的行为：

```text
新义务：只加入到末端
完成义务：只查看并删除最后加入的一项
其他位置：当前不需要随机访问
顺序规则：后加入，先完成
```

满足这种“后进先出”访问规则的抽象数据结构叫作**栈**。

### 栈是什么

可以把栈理解为一个受限序列：元素按顺序加入，但只允许从同一端加入和删除。这个可操作的一端叫栈顶，另一端叫栈底。

```text
加入顺序：A -> B -> C

栈顶
  C   最先被取出
  B
  A   最后被取出
栈底

取出顺序：C -> B -> A
```

本题中，栈底是最外层、最早建立的闭合要求，栈顶是最内层、最近建立的闭合要求。右括号只能接触栈顶，正好对应嵌套关系。

### 本题使用的操作

| 操作 | 本题语义 | `ArrayDeque` 调用 | 成本 |
| --- | --- | --- | --- |
| 压栈 | 建立新的期待右括号 | `push(value)` | 均摊 `O(1)` |
| 判断空栈 | 确认右括号是否有可用左括号 | `isEmpty()` | `O(1)` |
| 出栈 | 读取并完成最近义务 | `pop()` | `O(1)` |
| 查看栈顶 | 若采用“先看后删”写法使用 | `peek()` | `O(1)` |

完整实现用 `isEmpty() || pop() != current`。Java 的 `||` 会短路：空栈时不会执行 `pop()`，因此不会抛出 `NoSuchElementException`。若非空但类型不匹配，代码虽然已经弹出栈顶，随后立刻返回 `false`，不再需要恢复状态。

> **小白追问：** 为什么判断顺序必须先判空，再取栈顶？
>
> **先给短答：** 右括号没有对应义务时本应返回 `false`；若先 `pop()`，程序会在表达题意之前先因空容器抛异常。
>
> **最小例子：** 输入 `)(` 的第一个字符就是 `)`，此时状态为 `[]`。先执行 `isEmpty()` 能得到“没有可关闭对象”；直接执行 `pop()` 则根本取不到元素。
>
> **回到模型/代码：** 条件 `expectedClosings.isEmpty() || expectedClosings.pop() != current` 利用短路顺序。左边为 `true` 时右边不执行，所以空栈失败与类型失败被安全地放在同一分支。

### Java 为什么选 `Deque` 与 `ArrayDeque`

`Deque` 是双端队列接口，也能完整表达栈操作。`ArrayDeque` 是基于可扩容数组组织元素的实现，栈顶操作位于逻辑端点，不需要移动全部元素。扩容并非每次发生，因此连续压栈的总成本按均摊分析仍为线性；普通端点操作是常数时间。

Java 旧类 `Stack` 继承自 `Vector`，带有本题不需要的历史接口和同步语义。Oracle 文档也建议在栈场景优先使用 `Deque` 实现。`LinkedList` 同样能在端点常数时间增删，但每个字符需要额外节点和指针，连续内存的 `ArrayDeque` 更简洁。自己维护 `char[]` 和栈顶下标也可以，常数更小，却增加扩容或容量估计代码，不利于先看清模型。

普通队列不合适，因为它暴露最早加入的义务，而嵌套要求访问最近加入的义务。哈希表适合按键查找，却不能单独表达层级顺序。递归下降解析可以借助调用栈表达嵌套，但本题只需布尔检查，显式栈更直接，也避免深度达到 `10^4` 时的调用栈风险。

> **小白追问：** 都是保存一串字符，为什么普通数组、队列或哈希表不能直接替代栈？
>
> **先给短答：** 容器能否存下数据不是关键，关键是它默认支持的访问顺序是否等于“最后建立的义务先完成”。
>
> **最小例子：** 对 `([])`，先保存 `)`，后保存 `]`。第一个右括号是 `]`，必须取得最后保存的一项；若队列先取 `)` 就会拒绝合法输入，若哈希表任意找 `]` 又丢失了嵌套次序。
>
> **回到模型/代码：** `Deque.push/pop` 直接提供后进先出。数组也能实现同一模型，但还要自行维护栈顶下标；只要访问规则相同，它本质上仍是在实现一个栈。

栈里保存的是**字符值**，不是下标。题目只问是否合法，不要求报告错误位置或最长区间，所以位置不是必要状态。若需求改为返回错误下标，才应保存“括号字符 + 下标”的复合状态。

最坏输入可以是长度为 `n` 的全左括号字符串。每个字符都建立义务而没有字符完成义务，栈会保存 `n` 项，因此最坏空间为 `O(n)`。

## 11. 生活化类比及边界

想象进入一组层层嵌套、出口类型不同的房间。每进入一扇门，工作人员就把这扇门对应的“返回门票”放到一摞票的最上面。离开时只能查看最上面的票，因为必须先退出当前最里面的房间，才能回到外层房间。

| 生活对象或动作 | 算法中的对应物 |
| --- | --- |
| 从左到右经过门 | 按下标从左到右扫描字符 |
| 进入圆形、方形或花形门 | 读到对应左括号 |
| 把对应返回门票放到最上方 | 压入期待的右括号 `)`、`]` 或 `}` |
| 最上面的返回门票 | 栈顶，代表下一次必须出现的右括号 |
| 出门时核验门票 | 当前右括号与栈顶比较 |
| 门票相符并收走 | 匹配成功并出栈 |
| 没有门票却要出门 | 空栈遇到右括号，立即无效 |
| 门型与最上方门票不同 | 类型或嵌套顺序冲突，立即无效 |
| 走完全程仍剩门票 | 有左括号未闭合，最终无效 |
| 走完全程且票堆为空 | 所有关系完整匹配，返回 `true` |

这个类比强调的不是门本身，而是“进入顺序与退出顺序相反”以及“只需查看最上方未完成事项”。它能解释为什么使用后进先出状态。

### 类比到哪里为止

现实房间可能有多个出口、人可以停留或绕路，题目中都不存在。算法不会真的追踪空间位置，也不会判断普通字符、访问权限或门是否物理连通。并列序列 `()[]` 也不是重新进入同一栋建筑的语义，它只表示第一摞义务清空后又建立了新义务。类比帮助理解状态变化，严格正确性仍来自括号配对规则和后面的不变量证明。

## 12. 典型输入的完整数据变化图

完整演算 `([{}])`，它同时包含三种类型和三层嵌套。下面统一规定：**栈底在左，栈顶在右**；栈中保存期待的右括号，而不是已经出现的左括号。

```text
下标：      0    1    2    3    4    5
当前字符：  (    [    {    }    ]    )
扫描方向：  --------------------------------->

配对关系：  0 <--------------------------> 5
                 1 <----------------> 4
                          2 <----> 3
```

### 连续状态表

| 步骤 | 当前输入 | 处理前状态（底 -> 顶） | 判断依据与动作 | 处理后状态（底 -> 顶） | 本步结果 |
| ---: | --- | --- | --- | --- | --- |
| 初始 | 尚未读取 | `[]` | 没有历史义务 | `[]` | 未得出最终结论 |
| 0 | `(` | `[]` | 左括号建立“未来要见 `)`” | `[)]` | 继续 |
| 1 | `[` | `[)]` | 新内层建立“未来先见 `]`” | `[), ]]` | 继续 |
| 2 | `{` | `[), ]]` | 新内层建立“未来先见 `}`” | `[), ], }]` | 继续 |
| 3 | `}` | `[), ], }]` | 非空且当前字符等于栈顶，弹出 `}` | `[), ]]` | 最近一层完成 |
| 4 | `]` | `[), ]]` | 非空且当前字符等于栈顶，弹出 `]` | `[)]` | 方括号层完成 |
| 5 | `)` | `[)]` | 非空且当前字符等于栈顶，弹出 `)` | `[]` | 圆括号层完成 |
| 结束 | 无 | `[]` | 所有字符读完且无遗留义务 | `[]` | `true` |

### 按统一快照展开关键转折

```text
当前输入：下标 2 的 {
处理前状态：[), ]]，栈顶是 ]
判断依据：左括号不是在完成旧义务，而是在旧义务内部建立新义务
执行动作：把对应的期待右括号 } 压到栈顶
处理后状态：[), ], }]，下一次必须先见 }
新增结果：没有最终布尔结果，只更新前缀状态
```

```text
当前输入：下标 3 的 }
处理前状态：[), ], }]，栈顶是 }
判断依据：当前字符正好等于最近建立的闭合要求
执行动作：弹出栈顶 }
处理后状态：[), ]]，外层方括号重新成为最近义务
新增结果：完成一对括号，但仍需继续检查剩余字符
```

```text
当前输入：扫描结束
处理前状态：[]
判断依据：途中没有冲突，且所有已建立义务都已完成
执行动作：不再修改状态
处理后状态：[]
新增结果：返回 true
```

注意，匹配一个 `}` 时不会在结果数组中记录一对括号，因为题目只返回布尔值。所谓“新增结果”是局部关系已经结算；最终答案要等到整个输入处理完成并确认栈空。

## 13. 边界场景的数据变化

本题最常见的错误来自三个不同阶段：右括号到来时栈为空、栈非空但类型不匹配、扫描结束后栈仍非空。三者必须分开理解。

### 边界一：空状态遇到右括号 `)(`

字符串长度为偶数，不能被奇数剪枝提前挡住，因此能直接观察核心分支。

```text
下标：      0    1
字符：      )    (
扫描方向：  --------->

i = 0，current = )
处理前状态：[]
判断依据：右括号只能完成左侧已经建立的义务，但栈为空
执行动作：立即返回 false，不执行 pop
处理后状态：无需继续维护
未读取字符：( 无法修复下标 0 的无来源右括号
```

短路判断先调用 `isEmpty()`，所以不会越界或抛异常。未来的 `(` 位于右侧，不能倒过来与过去的 `)` 配对。

> **小白追问：** 第一个 `)` 没有左括号时，为什么必须立即失败，不能等后面的 `(` 来补？
>
> **先给短答：** 配对有方向：左括号必须先出现，未来的左括号不能移动到已经读过的右括号左边。
>
> **最小例子：** `)(` 的两个字符数量平衡，但下标 `0` 的 `)` 左侧没有字符。下标 `1` 的 `(` 只能等待更右侧的 `)`，不能反向配给下标 `0`。
>
> **回到模型/代码：** 右括号分支先检查 `expectedClosings.isEmpty()`。一旦为空就返回 `false`，这是不可修复的前缀错误，不是暂时缺少信息。

### 边界二：类型与嵌套顺序不匹配 `([)]`

```text
i = 0，current = (
状态：[] -> [)]

i = 1，current = [
状态：[)] -> [), ]]

i = 2，current = )
处理前状态：[), ]]，栈顶期待 ]
判断依据：当前 ) != 栈顶 ]；不能向下搜索外层的 )
执行动作：弹出比较后立即返回 false
未读取字符：最后一个 ] 不可能回到下标 2 之前修复次序
```

这不是“外层正好有一个 `)`，先用上再说”。下标 `2` 的 `)` 若匹配外层 `(`，就会跨过更晚打开但尚未关闭的 `[`。最后一个 `]` 再关闭 `[` 时，两对括号发生交叉，因此当前冲突已经决定整串无效。

> **小白追问：** 类型不匹配以后，为什么也能立即失败？后面也许正好有栈顶需要的 `]`。
>
> **先给短答：** 后面的 `]` 只能处理未来位置，无法撤销当前 `)` 已经以错误顺序出现这个事实。
>
> **最小例子：** `([)]` 读到第三个字符时，下一项唯一合法要求是 `]`，实际却是 `)`。跳过当前 `)` 会让它永远无配对，拿它关闭外层又会跨过 `[`，两条路都失败。
>
> **回到模型/代码：** 非空时取出的栈顶期待值与 `current` 不同，条件立即成立并返回 `false`。代码不会继续扫描，也不会调用 `contains` 寻找更深元素。

### 边界三：结束时仍有义务 `((`

```text
i = 0，current = ( ：[]  -> [)]
i = 1，current = ( ：[)] -> [), )]
扫描结束
最终状态：[), )]，栈顶在右
最终判断：非空，返回 false
```

循环中的每一步都合法，却只说明“目前还可以被未来补全”，不等于整个字符串已经有效。扫描结束以后未来不存在，因此两项期待永远无法完成。结尾检查不能省略。

> **小白追问：** 扫描途中一次冲突都没有，为什么结束时栈不空仍然要判错？
>
> **先给短答：** “目前没冲突”只代表当前前缀有机会被补全；结束后没有未来字符，未完成义务就永久残留。
>
> **最小例子：** `((` 的两步都只是压入 `)`，状态从 `[]` 变为 `[), )]`，从未遇到错误右括号。但输入已经结束，两项 `)` 都没有实际字符来完成。
>
> **回到模型/代码：** 循环只负责发现过程冲突，最后的 `return expectedClosings.isEmpty()` 负责检查完整性。两个判断承担不同职责，缺一不可。

### 并列关系与空状态复用 `()[]`

```text
( ：[]  -> [)]
) ：[)] -> []
[ ：[]  -> []]
] ：[]] -> []
结束：[]，返回 true
```

中途栈变空不是结束信号；它只表示截至当前前缀没有未完成义务。后续仍可以开始新的并列关系。官方约束不允许空字符串，但若将模型迁移到允许空输入的通用验证器，空串没有冲突也没有遗留义务，通常定义为有效。

## 14. 正确性与不变量

要证明的是：算法返回 `true` 时字符串一定有效；字符串有效时算法不会错误返回 `false`；提前丢弃的状态不会在未来再次需要。

### 循环不变量

在处理下标 `i` 之前，只要此前没有返回 `false`，状态从底到顶恰好保存前缀 `s[0..i-1]` 中所有尚未闭合左括号所期待的右括号，顺序从最外层到最内层；栈顶是下一个右括号唯一允许完成的要求。

初始前缀为空，没有未闭合左括号，空状态满足不变量。

> **小白追问：** “循环不变量”听起来很抽象，它在这道题里到底有什么用？
>
> **先给短答：** 它是一句每轮开始和结束都必须为真的状态说明，用来检查代码保存的内容是否始终等于模型需要的内容。
>
> **最小例子：** 读完 `([` 后，前缀中恰有两个未闭合左括号，所以状态必须恰好是 `[), ]]`。少了 `)` 会忘记外层，多了已完成字符又会污染下一次判断。
>
> **回到模型/代码：** 每轮只做两类维护：左括号 `push` 新期待，匹配右括号 `pop` 最近期待。证明这两类动作都让那句话继续成立，就不必逐个枚举所有输入。

### 左括号为什么维持不变量

读到左括号时，它不能与过去字符完成配对，只能等待未来对应右括号。它出现在所有旧义务之后，因此位于旧义务内部或新并列结构的起点；在它完成之前，旧的外层义务不能先完成。把对应右括号加入栈顶后，状态仍按外层到内层排列，新的栈顶就是下一项必须完成的义务。

### 匹配右括号为什么可以删除栈顶

栈非空且当前右括号等于栈顶时，它与最近尚未闭合的左括号类型一致。二者之间出现的所有更内层关系已经被弹出，否则它们仍会位于栈顶。因此这两个括号形成一个完整、无交叉的合法配对。

配对完成后，未来任何字符都不能再使用这两个位置。删除栈顶只忘记已经结算的关系，不会丢失未来所需信息；下一项外层义务自然成为新栈顶，不变量恢复。

> **小白追问：** 成功匹配时立刻弹出，凭什么保证不会删掉未来还需要的信息？
>
> **先给短答：** 被弹出的不是一个仍可选择的候选，而是一项已经由当前右括号唯一完成的义务。
>
> **最小例子：** `([]` 读到 `]` 后，栈顶 `]` 与当前字符已经组成方括号对。未来若再来 `]`，它不能重复使用先前的 `[`；未来真正需要知道的只剩外层期待 `)`。
>
> **回到模型/代码：** `pop()` 同时完成比较与删除。删除后 `expectedClosings` 仍恰好保存未完成义务，因此下一轮可以继续只看新的栈顶。

### 空栈或类型冲突为什么可以立即失败

空栈遇到右括号，说明左侧所有左括号都已使用，当前右括号没有候选。未来左括号位于它右侧，不满足左括号先出现的方向要求，所以无法修复。

类型冲突时，栈顶对应最近的未闭合左括号。合法嵌套要求它先于所有更外层左括号闭合。若当前右括号去匹配更外层对象，配对线就会交叉；若暂时不使用当前右括号，它以后也不能移动位置。两种解释都违反题意，因此返回 `false` 不会漏掉可能的合法补救。

### 结束检查为什么同时保证完整性

若扫描完成且栈为空，每个左括号都在之后遇到了类型匹配的右括号，每个右括号也都在出现时合法完成了最近义务；不变量保证所有配对顺序不交叉，所以字符串有效。

若扫描完成但栈非空，至少一个左括号没有右括号，字符串无效。若输入本来有效，则每个右括号出现时必然与最近未闭合左括号同类型，算法不会在途中失败，并会逐一弹出所有义务，最终必然为空。因此算法既不会接受无效串，也不会拒绝有效串。

每次循环处理一个新字符，下标严格向右移动；每个左括号最多加入一次，每项义务最多删除一次，所以过程一定终止。

## 15. 时间与空间复杂度推导

定义：

- `n` 表示字符串 `s` 的字符数。
- `d` 表示扫描过程中同时尚未闭合的最大嵌套深度，满足 `0 <= d <= n`。
- 一次字符读取、比较、空判断和普通栈顶操作按 `O(1)` 计算；`ArrayDeque` 偶尔扩容，压栈按均摊 `O(1)` 计算。
- 返回结果是一个布尔值，占 `O(1)`，不需要单独的大型输出空间。

### 直接消去模型

对 `((...))` 这样的深度嵌套串，每轮只能暴露下一对相邻括号。各轮处理长度大致为：

```text
n + (n - 2) + (n - 4) + ... + 2
```

这是等差数列，共约 `n / 2` 项，和为平方量级，所以最坏时间复杂度为 `O(n^2)`。每轮替换还会创建长度最高为 `O(n)` 的新字符串；按峰值同时存活空间报告为 `O(n)`，按整个执行期间累计字符分配量则可能是 `O(n^2)`。复杂度分析通常报告峰值辅助空间，因此写作 `O(n)`，同时说明累计分配更准确。

### 推荐的增量状态模型

主循环从左到右读取每个字符一次，共 `n` 次。每个左括号只会压栈一次；每个成功匹配的右括号只会弹出一项；失败分支直接结束。即使代码里既有循环又有栈操作，也不存在重新扫描：

```text
一个字符的生命周期：读取一次
一项义务的生命周期：建立时压入一次，完成时弹出至多一次
全部压入次数 + 全部弹出次数 <= 2n
```

> **小白追问：** 既然既有扫描循环，又有压栈和弹栈，为什么总时间不是 `O(n^2)`？
>
> **先给短答：** 复杂度要看操作总次数，不是看到多种操作就把两个 `n` 相乘；这里没有任何字符被重新扫描，也没有任何义务被重复弹出。
>
> **最小例子：** `((()))` 有六个字符：前三个各压入一次，后三个各弹出一次，总共六次状态操作。嵌套深度从一层增到三层，并不会让某个右括号把三层全部重扫。
>
> **回到模型/代码：** `for` 循环执行 `n` 轮，每轮只有一次常数时间的端点操作。把所有元素的生命周期相加，得到总时间 `O(n)`；这里的“均摊”主要用于说明 `ArrayDeque` 偶尔扩容的成本。

`ArrayDeque` 扩容会偶尔复制内部数组，但容量按批次增长，同一元素不会在每次压栈时都被复制；所有扩容成本摊到全部压栈操作后仍是 `O(n)`。因此总时间复杂度为 `O(n)`，最好情况下可能在开头失败并提前结束，但最坏和渐进上界仍是线性。

栈最多保存 `d` 项，额外空间为 `O(d)`。最坏输入全为左括号时 `d = n`，所以通常写作 `O(n)`。Java 的 `Character` 装箱和 `ArrayDeque` 内部容量会影响实际字节数，但不改变渐进复杂度。若使用预分配 `char[]`，同样需要最坏 `O(n)` 空间。

> **小白追问：** 空间到底该写 `O(d)` 还是 `O(n)`，两种说法会不会矛盾？
>
> **先给短答：** `O(d)` 描述实际由最大嵌套深度决定，`O(n)` 描述在所有长度为 `n` 的合法输入范围内的最坏上界。
>
> **最小例子：** `()()()` 长度为六，但同时最多只有一项义务，所以 `d = 1`；`((()))` 长度同样为六，最多同时有三项义务，所以 `d = 3`。
>
> **回到模型/代码：** `expectedClosings.size()` 的峰值就是 `d`。由于题目允许前半段全是左括号，`d` 最坏可随 `n` 线性增长，因此汇总结论通常写 `O(n)`。

奇数长度剪枝只让部分输入在 `O(1)` 时间返回，不改变整体最坏复杂度，也不能替代核心扫描。

### 泛用 Java 建模骨架

下面的骨架把括号类型作为配置传入，因此不仅限于三组符号。它先把“打开符号 -> 期待关闭符号”保存到映射中；遇到未知字符时返回 `false`。若业务规则允许表达式中的普通字符，只需把最后一个 `else` 改为忽略当前字符，嵌套模型本身不变。

```java
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.HashSet;
import java.util.Map;
import java.util.Set;

final class DelimiterNestingModel {
    static boolean isWellNested(
            String text,
            Map<Character, Character> closingByOpening) {
        if (text == null || closingByOpening == null) {
            return false;
        }

        Set<Character> closingSymbols =
                new HashSet<>(closingByOpening.values());
        Deque<Character> expectedClosings = new ArrayDeque<>();

        for (int index = 0; index < text.length(); index++) {
            char current = text.charAt(index);
            Character expectedForOpening = closingByOpening.get(current);

            if (expectedForOpening != null) {
                expectedClosings.push(expectedForOpening);
            } else if (closingSymbols.contains(current)) {
                if (expectedClosings.isEmpty()
                        || expectedClosings.pop() != current) {
                    return false;
                }
            } else {
                return false;
            }
        }

        return expectedClosings.isEmpty();
    }
}
```

骨架中的 `closingByOpening` 定义类型关系，`expectedClosings` 保存有顺序的未完成义务，`current` 是新事件。建立义务和完成义务都只操作栈顶。若配置含 `p` 种符号，构造关闭符号集合需要 `O(p)` 时间和空间；扫描仍为平均 `O(n)`，状态栈最坏 `O(n)`。

### 代码与模型角色映射

| 模型角色 | Java 变量或代码块 |
| --- | --- |
| 当前对象 | `current = s.charAt(index)` |
| 遍历方向 | `index` 从 `0` 单调增加到 `s.length() - 1` |
| 未完成义务 | `expectedClosings`，底到顶对应外层到内层 |
| 建立新义务 | 三个左括号分支分别 `push` 对应右括号 |
| 空状态失败 | `expectedClosings.isEmpty()` |
| 类型或顺序失败 | `expectedClosings.pop() != current` |
| 完成最近义务 | 匹配时 `pop()` 已删除栈顶 |
| 最终完整性 | `return expectedClosings.isEmpty()` |
| 可选剪枝 | `s.length() % 2 == 1` |

代码没有单独写 `isClosing(current)`，因为官方约束保证非左括号字符一定是三种右括号之一。也没有调用 `peek()` 后再 `pop()`：非空时直接弹出并比较能同时完成“取最近要求”和“匹配后删除”，失败后方法立刻结束，不需要保留原栈。

> **小白追问：** 代码先 `pop()` 再知道类型是否相同，若比较失败，状态不是已经被破坏了吗？
>
> **先给短答：** 比较失败后答案已经永久确定为 `false`，方法立即结束，所以没有下一轮需要使用或恢复这份状态。
>
> **最小例子：** `([)]` 读到 `)` 时弹出期待的 `]`，比较失败并立刻返回。即使把 `]` 放回去，后续字符也无法改变当前顺序冲突，恢复没有价值。
>
> **回到模型/代码：** `expectedClosings.pop() != current` 只出现在直接返回的失败条件中。若代码还要报告完整错误现场，可以改成先 `peek()`、记录信息，再在匹配成功时 `pop()`。

## 17. 边界、常见错误与调试观察点

| 层次 | 常见错误 | 后果 | 应观察的状态 |
| --- | --- | --- | --- |
| 建模错误 | 只统计每类左右数量 | `([)]` 被误判为有效 | 每个前缀的未完成类型顺序 |
| 建模错误 | 用队头匹配最早左括号 | 合法嵌套 `([])` 被拒绝 | 当前要关闭的是最内层还是最外层 |
| 建模错误 | 保存完整历史却不删除已匹配对象 | 状态越来越大，无法明确下一项义务 | 栈中是否只剩未完成关系 |
| 条件错误 | 遇右括号直接 `pop()`，不先判空 | `)(` 抛出 `NoSuchElementException` | 右括号到来前的 `isEmpty()` |
| 条件错误 | 只检查栈顶类型，不在成功后弹出 | `()` 结束时仍残留义务 | 匹配前后栈大小是否减一 |
| 条件错误 | 途中不匹配时继续扫描 | 永久错误被掩盖，可能错误接受 | 首个失败下标、当前字符和栈顶 |
| 条件错误 | 扫描结束直接返回 `true` | `((` 被误判为有效 | 循环结束后的完整栈内容 |
| 实现错误 | 存左括号却拿它直接与右括号比较 | `(` 与 `)` 本来就不相等 | 栈保存的是“过去符号”还是“期待符号” |
| 实现错误 | `==` 比较两个可能为 `null` 的包装对象 | 泛用实现可能出现空值问题 | 映射返回值和拆箱时机 |
| 实现错误 | 迁移到含普通字符的表达式仍把其他字符当右括号 | 合法表达式被拒绝或错误弹栈 | 输入字符分类分支 |

最有价值的调试日志不是只打印最终 `true/false`，而是记录每步稳定状态：

```text
index=0, current=(, before=[],      action=push ), after=[)]
index=1, current=[, before=[)],     action=push ], after=[), ]]
index=2, current=), before=[), ]],  action=mismatch, expected=]
```

如果 `([)]` 被判为有效，打印“栈底到栈顶”通常会立刻暴露是否只做了计数或错误地从栈底取值。如果合法输入在关闭时失败，要先确认栈中存的是左括号还是期待右括号：两种模型都正确，但比较条件不能混用。

建议按风险分组测试：

- 最小有效：`()`。
- 最小类型冲突：`(]`。
- 空状态先关闭：`)(`。
- 深度嵌套：`{[()]}`。
- 多段并列：`()[]{}`。
- 顺序交叉：`([)]`。
- 结束遗留：`((`、`(()`。
- 大规模：一万个字符组成的深嵌套或全左括号，观察时间与最大栈深度。

调试的目标是逐步验证不变量：每一步之后，栈是否恰好等于该前缀尚未完成的闭合要求，而不是凭最终样例猜代码分支。

## 18. 最终模型卡

| 项目 | 复习结论 |
| --- | --- |
| 题型识别指纹 | 成对符号；允许嵌套；后打开对象必须先完成；只需判断整体是否合法 |
| 一句话关系模型 | 每个左括号建立一个未来闭合义务，右括号只能完成最近且同类型的未完成义务 |
| 实际保存什么 | 从外层到内层排列的期待右括号，栈顶是下一项唯一允许的闭合符号 |
| 状态何时变化 | 左括号到来时增加义务，匹配右括号到来时删除最近义务 |
| 答案何时产生 | 空栈遇右括号或类型冲突时立即为 `false`；扫描结束且栈空时为 `true` |
| 核心不变量 | 状态只含当前前缀尚未闭合的义务，并按建立顺序排列，最后一项必须最先完成 |
| 时间复杂度 | `O(n)`，每个字符读取一次，每项义务至多压入和弹出各一次 |
| 空间复杂度 | `O(d)`，`d` 为最大未闭合深度；最坏 `d = n`，即 `O(n)` |

### 四句建模结论

```text
我正在处理的对象是：从左到右到来的括号字符和它对当前前缀嵌套关系的影响。
我必须持续保存的是：尚未闭合的期待右括号，并让最近建立的期待位于最先可访问的位置。
当 左括号建立新义务或右括号尝试完成义务 发生时，我执行：压入对应期待符号，或检查并弹出最近期待；空状态和类型冲突立即失败。
答案在 扫描中出现不可修复冲突或全部字符扫描结束时 由失败事件以及未完成义务是否为空计算出来。
```

### 泛用迁移模板

```text
1. 找出哪些事件会建立一个未来必须完成的义务。
2. 判断多个未完成义务之间是先进先出还是后进先出。
3. 只保留仍会限制未来的义务，已经结算的历史立即删除。
4. 新事件到来时只检查当前优先义务，并定义无法匹配是否可被未来修复。
5. 分开检查“过程中没有冲突”和“结束时没有遗留”。
6. 根据输出需求决定保存符号、下标、数值还是完整上下文。
```

### 后续变式

- **921. 使括号有效的最少添加：**关系从“冲突立即失败”改为“冲突计入修复成本”。状态可以压缩为未闭合数量，因为只有一种括号；答案时机变为扫描中累计缺失左括号，结束时再加遗留左括号。
- **32. 最长有效括号：**输出从整体布尔值变为最长连续区间长度。栈需要保存下标或改用动态规划；变化的是状态内容和答案更新时机，不能只保存字符。
- **856. 括号的分数：**匹配仍是后进先出，但关闭事件不只删除义务，还要把内层分数合并给外层；变化的是栈中保存的状态和结算结果。
- **394. 字符串解码：**左括号前的次数和已有文本建立待恢复上下文，右括号完成最近上下文。后进先出关系不变，栈元素从单个字符升级为“重复次数 + 外层结果”的复合状态。
