# 236. 二叉树的最近公共祖先：让子树向父节点汇报最小充分信息

本篇要解决的困难不是记住三行递归分支，而是回答这些更根本的问题：父节点为什么只接收一个 `TreeNode` 就够了？这个非空节点有时代表目标，有时又代表已经确定的最近公共祖先，语义会不会混乱？左右子树各返回一个非空节点时，为什么当前节点一定是答案？当前节点就是 `p` 或 `q` 时，为什么可以立刻返回，甚至不继续寻找另一个目标？

推导时暂时不把方法叫作“后序 DFS”。我们先规定每棵子树必须向上汇报什么，再看这种信息流自然要求先处理孩子、后处理父节点。数据结构和遍历名称应当是模型的结论，不是读题的起点。

## 2. 完整题目

给定一棵有根二叉树，以及树中两个不同的节点对象 `p`、`q`，返回它们的最近公共祖先节点。

节点 `x` 是节点 `y` 的祖先，表示从 `x` 沿着若干次左孩子或右孩子可以到达 `y`。这里允许走零次，所以一个节点也是它自己的祖先。`p` 和 `q` 的公共祖先可能有多个，“最近”指这些公共祖先中深度最大、离两个目标更近的那一个。

输入中的 `root` 是整棵树的根引用，`p`、`q` 是树里实际存在的节点引用。输出也不是一个整数值，而是答案节点本身的引用；示例为了便于展示，才把该节点的 `val` 打印出来。

### 示例 1：目标分居根节点两侧

```text
输入：root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 1
输出：3

            3
          /   \
         5     1
        / \   / \
       6   2 0   8
          / \
         7   4
```

节点 `3` 的左子树含 `5`，右子树含 `1`。没有任何比 `3` 更深的节点还能同时覆盖左右两个分支，所以答案是节点 `3`。

### 示例 2：一个目标本身就是答案

```text
输入：root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 4
输出：5
```

节点 `4` 位于节点 `5` 的子树中。因为节点 `5` 可以作为自己的祖先，它同时也是 `4` 的祖先，所以最深公共祖先就是 `5`，而不是更高的 `3`。

### 示例 3：最小规模且根为目标

```text
输入：root = [1,2], p = 1, q = 2
输出：1

    1
   /
  2
```

根节点 `1` 是目标之一，并且 `2` 在它下面，因此返回节点 `1`。

### 官方约束

- 树中节点数 `n` 满足 `2 <= n <= 10^5`。
- 每个节点值满足 `-10^9 <= Node.val <= 10^9`。
- 官方输入中所有节点值互不相同。
- `p != q`。
- `p` 和 `q` 都保证存在于树中。

Java 方法入口为：

```java
public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q)
```

这些约束会直接影响模型。两目标都存在，使我们可以把“没找到”和“只找到一个”用 `null` 与非空引用表达，而不必在根调用后再次验证命中数量。`n` 可达 `10^5`，排除了对大量候选反复扫描整棵子树的平方模型。值虽然在本题中互不相同，但接口交付的是节点对象，因此正确的身份判断仍是 `current == p` 或 `current == q`；值唯一只是输入事实，不应偷换输出契约。

## 3. 先把题目说成人话

**一句话生活化复述：**在一张从上级指向下级的组织树里，找出同时管辖员工 `p` 和员工 `q`、并且职位层级最低的那位管理者；员工本人也可以算自己的管理者。

**一句话关系化复述：**在两条“根到目标”的唯一路径上，寻找最后一个共同节点。

| 要素 | 本题中的含义 |
| --- | --- |
| 对象 | 二叉树中的节点对象，而不是节点值 |
| 关系 | 父子关系、祖先关系，以及两条根到目标路径的共同前缀关系 |
| 方向 | 树结构从父到子展开；用于决策的信息从子树向父节点回传 |
| 目标 | 返回同时是 `p`、`q` 祖先且深度最大的节点引用 |
| 限制 | 每个非根节点只有一个父节点；`p`、`q` 不同且都存在；节点可作为自身祖先 |

“最近”不是比较节点值大小，也不是比较数组表示里的下标距离。它比较的是树上的深度。假设根到 `p` 的路径是 `[3,5,2,7]`，根到 `q` 的路径是 `[3,5,2,4]`，共同前缀是 `[3,5,2]`，最后一个共同节点 `2` 才是最近公共祖先。这个路径视角先帮我们确认目标关系，后面还要继续压缩：父节点其实不需要收到两条完整路径，它只需要知道每个孩子分支有没有交付“与目标有关的有效报告”。

## 4. 第一切入点：读题时先看什么

第一分钟先圈出四组真正决定模型的词。

第一组是“二叉树”和“祖先”。树中从根到任意节点只有一条路径，这意味着 `p`、`q` 的祖先集合不是任意集合，而是两条有序路径。问题天然带有上下层级，不能把节点当作无顺序数组元素。

第二组是“两个指定节点”。我们只关心两个身份明确的对象，不需要统计所有节点，也不需要计算任意两点之间的距离。一个子树是否与答案有关，只取决于其中是否出现 `p`、`q`，或是否已经在内部找到二者的汇合点。

第三组是“最近公共”。“公共”要求同时覆盖两个目标；“最近”要求一旦某个最深子树内部已经能覆盖二者，祖先就不能把答案改成自己。这个词直接提示我们：应该优先让更深的子树完成判断，再由父节点处理尚未在子树内部汇合的情况。

第四组是“节点也可以是自身祖先”。这不是边角说明，而是递归出口的依据。当前节点一旦就是 `p` 或 `q`，它本身必须作为一个有效报告向上传递。如果另一个目标在它下面，它就是答案；如果另一个目标在别处，它的祖先会负责完成汇合。

可以暂时忽略的是节点值正负、题目数组展示形式和“二叉”的左右命名。节点值不参与计算；数组只是一种序列化输入；本质模型对每个节点有任意数量孩子的普通树也成立，只是合并多个孩子报告时需要统计非空分支。

数据规模 `10^5` 给出性能信号：每个节点最好只承担常数次工作。与此同时，极端情况下树可能是一条长度 `10^5` 的链，递归深度会成为 Java 的工程风险；这不改变递归模型的正确性，却必须在复杂度和实现边界里诚实记录。

在最小样例 `1 -> 2` 中，人工不会先枚举整棵树。看到 `p` 就是根 `1`，又知道节点可以是自身祖先，立刻得到答案 `1`。这个动作提示了最小报告：命中目标时先把该节点身份向上交付，而不是把节点值、整条路径和深度全部交付。

## 5. 最直接的人工或暴力模型

如果完全不知道递归返回值怎样设计，可以严格照定义做“逐候选验证”。它不聪明，但一定正确。

1. 从根遍历整棵树，记录每个节点以及它的深度。
2. 把每个节点 `candidate` 都当作公共祖先候选。
3. 从 `candidate` 向下搜索一次，判断其子树是否包含节点 `p`。
4. 再从 `candidate` 向下搜索一次，判断其子树是否包含节点 `q`。
5. 如果两次都命中，`candidate` 就是公共祖先；在所有公共祖先中保留深度最大的那个。

概念伪代码如下：

```text
best = null
for candidate in 所有树节点:
    containsP = 子树搜索(candidate, p)
    containsQ = 子树搜索(candidate, q)
    if containsP and containsQ:
        if best == null or depth(candidate) > depth(best):
            best = candidate
return best
```

它为什么不会漏？真正答案本身一定出现在“所有树节点”中；按祖先定义，从答案向下能到达 `p` 和 `q`，所以它会通过两次包含检查。所有通过检查的节点都是公共祖先，再按深度取最大值，正好实现“最近”。它也自然处理一个目标是另一个祖先的情况，因为从 `p` 出发搜索时允许第零步命中 `p` 自己。

设树有 `n` 个节点，高度为 `h`。收集节点和深度需要 `O(n)` 时间。对一个候选做两次子树搜索，最坏各访问 `O(n)` 个节点；对 `n` 个候选重复，最坏时间为 `O(n^2)`。若保存节点与深度，额外空间为 `O(n)`；单次深度搜索还有 `O(h)` 调用栈。这个模型的价值是把题目定义落成可执行判定，也为后续优化指出了精确目标：不要反复问每个祖先“下面有没有目标”，而要让下面只汇报一次。

## 6. 暴力到底浪费在哪里

看一棵最能暴露重复工作的链状树：

```text
深度 0：A
        |
深度 1：B
        |
深度 2：C
        |
深度 3：D = p
        |
深度 4：E = q
```

逐候选模型会发生下面的扫描：

| 候选 | 为寻找 `p` 扫描 | 为寻找 `q` 扫描 | 结论 |
| --- | --- | --- | --- |
| `A` | `A,B,C,D` | `A,B,C,D,E` | 公共祖先 |
| `B` | `B,C,D` | `B,C,D,E` | 公共祖先 |
| `C` | `C,D` | `C,D,E` | 公共祖先 |
| `D` | `D` | `D,E` | 公共祖先且最深 |
| `E` | `E` 后失败 | `E` | 不是公共祖先 |

节点 `D` 被前四个候选的检查反复看到；`C` 到 `E` 这一段也被不同起点重复展开。每次搜索得到的“这个分支里找到 `p`”或“这个分支里找到 `q`”在候选判断结束后就被丢弃，父候选再次从头计算同一个事实。

在官方示例树里也一样。验证根 `3` 时会扫描左子树找到 `5` 和 `4`；之后验证候选 `5` 时，又会把 `5 -> 2 -> 4` 走一遍。其实子树 `2` 是否与目标有关只需计算一次，然后把结论交给 `5`；节点 `5` 的结论也只需计算一次，再交给 `3`。

链状树各候选的子树规模依次为 `n、n-1、n-2` 直到 `1`，总量为 `n(n+1)/2`，这正是平方级重复的来源。并不是“递归里有递归”就一定慢，而是同一个节点作为许多候选的后代被重新进入。

因此优化目标可以写得很具体：

> 每棵子树只搜索一次，并把“这棵子树中与两个目标有关的最小充分结论”返回给父节点，让父节点用左右两份报告在常数时间内完成判断。

## 7. 容易想到但走不通的方向

### 方向一：比较节点值，而不是节点身份

看到 `Node.val` 互不相同，很容易写成 `current.val == p.val`。在本题当前数据约束下，它通常得到同样结果，因此这个问题很隐蔽。但题目传入和要求返回的是节点引用，核心关系是“当前对象是不是目标对象”。值只是对象属性，并不定义身份。

一旦迁移到允许重复值的树，两个值同为 `5` 的不同节点会被错误地视为同一个目标。即使不考虑变式，使用值比较也会让模型错误地依赖一个不必要条件。新的建模要求是：子树报告保存节点引用，命中条件使用引用身份 `==`。

### 方向二：把普通二叉树当二叉搜索树

“树里查节点”容易让人根据 `p.val`、`q.val` 与当前值的大小决定向左还是向右。这只有在二叉搜索树满足“左小右大”时成立。本题没有任何有序约束，示例中节点 `5` 的右孩子是 `2`，已经说明值不能指导方向。这个方向是逻辑错误，不是性能不足。新的条件是：普通二叉树无法排除任一孩子，最坏必须检查所有相关分支。

### 方向三：只在空节点返回，不把 `p`、`q` 当出口

一种看似整齐的写法是无论当前节点是谁都继续搜索左右孩子，最后只按左右非空合并。如果 `p=5、q=4`，节点 `5` 的右子树会返回 `4`，左子树为空；节点 `5` 若不承认自己也是一个目标，就会把 `4` 向上传递，最终错误返回 `4`。

缺失的信息是“当前节点自身也构成一次命中”。命中 `p` 或 `q` 时返回当前节点，不只是剪枝，更是把“节点可以是自身祖先”的定义写进状态语义。

### 方向四：建立父指针和祖先集合

先遍历树建立 `child -> parent` 映射，再把 `p` 的所有祖先放进哈希集合，沿 `q` 向上找到第一个已出现祖先，这个方案完全正确，时间和空间都是 `O(n)`。它并非走不通，而是保存了全树父关系和一整条祖先链，超过单次查询所需的最小信息。

这个方案在不能承受深递归、需要迭代处理，或同一棵树上进行多次查询时很有价值。对本题的一次查询，它反过来提醒我们：若能让子树即时汇报，就不必永久保存每个节点的父节点。

## 8. 关键视角转换

直接模型的提问方式是：

```text
站在每个候选祖先处：
“我的下面有没有 p？”
“我的下面有没有 q？”
```

推荐模型把主动方向倒过来：

```text
先让最深的子树完成内部判断：
“我这里没有目标，报告 null。”
“我这里只掌握一个目标，报告那个节点。”
“我的两个孩子各交来一份有效报告，二者在我这里首次汇合，报告我自己。”
```

> **小白追问：** 递归调用向父节点“汇报”的究竟是什么，是目标数量、完整路径，还是某个节点？
>
> **先给短答：** 它只汇报一个可为空的节点引用；`null` 表示当前子树与目标无关，非空节点表示这棵子树已经能交付的最终有效结论。
>
> **最小例子：** 在 `A -> B` 中，若 `B` 就是 `p`，那么 `B` 向 `A` 返回节点 `B`。`A` 不会收到路径 `[A,B]`，也不会收到“命中数为 1”，只收到一份可以继续向上传递的节点报告。
>
> **回到模型/代码：** 方法返回类型始终是 `TreeNode`；父调用用 `leftReport`、`rightReport` 接住孩子的返回值，再根据空与非空决定下一步。

这次转换包含两个压缩。

第一，把“祖先反复向下查询”变成“子树只向上结算一次”。一个节点的左右分支都处理完，它就能形成一次稳定报告；报告一旦返回，父节点无需重新进入这棵子树。

第二，把“完整路径或命中明细”压缩成一个可空节点引用。父节点真正需要区分的不是报告中究竟有 `p` 还是 `q`，而是左右两个互不重叠的孩子分支是否都出现了有效信息：

- 两侧都空，当前子树与目标无关。
- 只有一侧非空，有效信息仍集中在一侧，原样上传。
- 两侧都非空，两个不同目标只能分处两侧，当前节点成为最深汇合处。

为什么一个非空引用可以同时承载“单个目标”和“已经确定的 LCA”两种表面含义？因为父节点对二者采取同一动作：若另一侧为空，就把它继续上传；若另一侧也非空，就在当前节点汇合。已经在某个子树内部确定的 LCA 说明两个目标都在那里，树的单父结构保证另一个兄弟子树不可能再含那两个目标中的任何一个，所以它只会被原样上传，不会被错误地二次汇合。

> **小白追问：** 一个 `TreeNode` 为什么既能代表“只找到一个目标”，又能代表“已经找到 LCA”，父节点不会理解错吗？
>
> **先给短答：** 不会，因为父节点无需给报告分类；只要另一侧为空，这两种报告都应原样上传，而已含两个目标的子树不可能在兄弟侧再出现目标。
>
> **最小例子：** 节点 `B` 的两个孩子分别是 `p`、`q` 时，`B` 已是 LCA，于是向父节点 `A` 报告 `B`。若 `A` 的另一侧为空，`A` 只需继续报告 `B`；这与“`B` 只是目标之一、仍在等待另一个目标”时的传播动作完全相同。
>
> **回到模型/代码：** 统一语义落在 `return leftReport != null ? leftReport : rightReport`。代码不检查报告属于哪一类，只检查另一侧是否也有有效报告。

遍历次序也由此自然产生：父节点必须先收到左、右子树报告才能合并，所以处理顺序是“左孩子、右孩子、当前节点”。这时我们才给它命名：这是一种后序深度优先递归。

## 9. 正式建立模型

对任意节点 `current`，定义 `report(current)` 为当前子树向父节点交付的报告：

- 子树不含 `p`、`q`：返回 `null`。
- 子树只含其中一个目标：返回该目标节点。
- 子树同时含两个目标：返回二者在当前子树内的最近公共祖先。

| 建模项 | 本题结论 |
| --- | --- |
| 对象 | 当前节点所代表的整棵子树 |
| 关系 | `p`、`q` 是否位于当前节点自身、左子树或右子树，以及它们在哪个最深节点首次汇合 |
| 状态 | 左子树报告 `leftReport`、右子树报告 `rightReport`，每份报告只需一个可空节点引用 |
| 事件 | 当前节点命中目标，或左右孩子递归完成并返回报告 |
| 不变量 | `report(current)` 始终符合“不含则空、单含则目标、双含则子树内 LCA”的语义 |
| 结果时机 | 根调用的返回值就是全树答案；局部上，左右报告都非空时当前节点产生汇合结果 |

状态转移按以下顺序执行：

```text
current 为空：
    report = null

current 就是 p 或 q：
    report = current

否则先取得 leftReport 和 rightReport：
    两者都非空：report = current
    只有一个非空：report = 那个非空报告
    两者都为空：report = null
```

### 为什么状态足够

父节点只做两件事：判断有效报告来自几个孩子分支，以及决定返回自己还是传播唯一报告。它不需要知道完整路径、目标深度或子树节点数量。当前节点是否为目标已经在递归出口处理；之后一个可空引用正好覆盖父节点需要的全部判断，没有保存多余路径。

### 哪些信息可以永久丢弃

一个空子树返回 `null` 后，其内部节点永远不可能影响本次答案，可以全部从调用栈释放。只有一侧非空时，空侧信息也可永久丢弃。左右都非空时，两个子报告的内部路径可以丢弃，因为任何位于单侧的节点都不可能同时成为另一侧目标的祖先；当前节点已经是这两条路径最深的共同连接点。

### 为什么从下向上

“最近”要求优先保留深处已经形成的答案。如果从上向下只看当前节点，尚不知道两个目标集中在一个孩子内还是分散在两边。先处理子树后，若两目标已经在某侧汇合，该侧会直接交付更深答案；父节点在另一侧为空时只传播它，不会用更浅的自己覆盖它。

### 相等值与节点身份

官方保证值互异，但模型仍按引用身份工作。`current == p` 表示两个变量指向同一个 `TreeNode` 对象；`current.val == p.val` 只表示属性相等。在允许重复值的扩展树里，前者仍正确，后者会误判。`p != q` 也指两个目标节点不同，不只是它们的数值不同。

### 命中当前节点时为何可提前返回

若 `current == p`，存在两种可能。若 `q` 在 `current` 子树内，`current` 是自身祖先，也是 `q` 的祖先，答案就是 `current`；若 `q` 在子树外，`current` 作为代表 `p` 的有效报告向上传递，最终会在更高祖先与 `q` 所在分支汇合。两种情况下返回 `current` 都携带了父节点需要的全部信息，因此不必继续搜索它的孩子来区分这两种情况。这个结论依赖题目保证 `q` 确实存在于整棵树中。

> **小白追问：** `current == p` 或 `current == q` 时为什么可以立即返回，万一另一个目标还藏在它的孩子里呢？
>
> **先给短答：** 正因为另一个目标可能在它下面，当前目标才已经是答案；如果另一个目标不在下面，当前节点又正好是需要向上交付的单目标报告。
>
> **最小例子：** 两节点树 `p -> q` 中，调用到 `p` 便返回 `p`。虽然没有继续访问孩子 `q`，但 `p` 既是自己的祖先，也是 `q` 的祖先，而且已经是能够同时覆盖二者的最深节点。
>
> **回到模型/代码：** 这对应出口 `if (root == null || root == p || root == q) return root;`。它必须位于左右递归之前，并依赖题目保证两个目标都在整棵树中。

## 10. 所需数据结构详解

模型确定以后，本题真正需要的结构只有二叉树节点引用和递归调用栈，没有必要额外建立哈希表、队列或路径数组。

### 二叉树节点与引用身份

每个 `TreeNode` 保存一个值 `val` 和两个子节点引用 `left`、`right`。引用可能指向另一个节点对象，也可能是 `null`。从根沿引用向下能到达所有节点；树没有环，并且每个非根节点只有一个父节点，因此左右子树互不重叠。

本题使用的操作是：

| 操作 | 含义 | 单次成本 |
| --- | --- | --- |
| `current == null` | 判断空子树 | `O(1)` |
| `current == p`、`current == q` | 比较对象身份 | `O(1)` |
| 读取 `current.left/right` | 进入两个孩子分支 | `O(1)` |
| 返回某个节点引用 | 向父调用交付报告 | `O(1)` |

结构中保存的是节点引用，不是值、下标或复制出来的节点。返回原树中的引用，正好满足平台的输出契约。数组下标不合适，因为树的数组序列化只是展示形式，缺失节点会让下标关系不再适合作为通用身份；节点值也不合适，因为值不是模型中的身份定义。

> **小白追问：** 官方明明保证节点值不同，为什么还强调按节点身份比较，而不直接比较 `val`？
>
> **先给短答：** 因为题目指定和返回的都是节点对象；值唯一只是当前输入约束，不是“谁是目标”的定义。
>
> **最小例子：** 根节点 `7` 有两个值都为 `5` 的孩子，左孩子是 `p`，右孩子是 `q`。两个节点的值相同但身份不同；只有分别比较对象引用，才能让左右两侧各报告正确的目标。
>
> **回到模型/代码：** 命中条件必须是 `root == p || root == q`，返回值也必须是原树中的 `TreeNode` 引用；`root.val == p.val` 不属于这个模型。

### 递归调用栈

当 `report(current)` 调用 `report(current.left)` 时，当前节点的计算暂时没有完成，程序必须记住“左边回来后还要处理右边并合并”。每一层调用栈帧保存当前节点引用、返回位置，以及计算过程中形成的 `leftReport`、`rightReport`。最深分支处理完后，栈按后进先出顺序逐层恢复，刚好支持子树向父节点回报。

对每个节点，压入一次栈帧、执行常数次比较和合并、再弹出一次，单次操作可视为 `O(1)`。栈中同时存在的是一条尚未完成的根到当前节点路径，最大数量等于树高 `h`，而不是节点总数在任何情况下都同时入栈。平衡树中 `h` 约为 `log n`，链状树中 `h=n`。

为什么不用队列？队列适合让同一层先到先处理，但当前父节点的结果依赖孩子已经完成的返回值，层序展开并不能直接提供这种局部合并。为什么不需要显式 `visited`？输入是树，不存在从不同路径重复到达同一节点或沿环回到祖先。为什么不保存完整根路径？单次查询只需最终节点，局部报告已经把路径信息压缩掉。

需要强调工程边界：算法辅助空间是 `O(h)`，但 Java 默认线程栈通常无法安全容纳 `10^5` 层递归。极端链状输入可能触发 `StackOverflowError`。若运行环境确实覆盖这种深度，可使用迭代遍历建立父指针，再沿祖先集合求交；那会把空间明确转移到堆上的 `O(n)` 映射与集合中。

## 11. 生活化类比及边界

把树想成一张严格的组织架构图，公司要寻找两份指定档案 `p`、`q` 应该交给哪位最低层级的共同负责人。每个部门只允许向直属上级交一个信封，不允许把整个部门花名册都交上去。

部门负责人先让左右两个下属部门分别调查。一个部门的信封规则如下：

```text
没有发现任何指定档案       -> 交空信封
只掌握一份指定档案         -> 交装有该目标工牌的信封
两个下属各交来一份有效信封 -> 两条线索在本部门首次会合，改交本负责人自己的工牌
只有一个下属交来有效信封   -> 不改内容，原样向上转交
负责人本人就是目标之一     -> 直接交自己的工牌
```

| 生活对象或动作 | 算法中的对应物 |
| --- | --- |
| 组织架构中的一个部门负责人 | 当前节点 `current` |
| 左、右下属部门 | `current.left`、`current.right` 两棵子树 |
| 指定的两份员工档案 | 目标节点对象 `p`、`q` |
| 空信封 | 子树返回 `null`，表示没有有效目标信息 |
| 装有某张工牌的信封 | 子树返回一个非空 `TreeNode` 引用 |
| 下属完成调查后向上交信封 | 递归调用返回 |
| 左右各收到一个有效信封 | `leftReport != null && rightReport != null` |
| 本负责人换成自己的工牌上报 | 当前节点是两个分支的最深汇合点，返回 `current` |
| 只有一边有信封，原样转交 | 返回唯一非空的子树报告 |
| 最顶层最终收到的工牌 | 全树最近公共祖先 |

这个类比最重要的地方，是“上级只关心收到几份有效信封，不必打开信封追查全部路线”。一张工牌可能是某个目标，也可能是下级已经确定的共同负责人；对上级而言，它们都是可以继续向上传播的有效报告。

类比到这里为止。现实组织可能有兼职、虚线汇报、多个上级或跨部门协作，这会形成一般图，而本题严格是一棵树，每个节点只有一个父节点。现实中空信封也可能意味着调查尚未完成，本模型中的 `null` 只表示递归已经完成且该子树不含目标。生活故事能帮助理解信息如何向上压缩，但“为什么当前负责人最深”仍要依赖左右子树互不相交和树中路径唯一的性质，不能用类比替代证明。

## 12. 典型输入的完整数据变化图

为了同时看到“单侧传播”和“左右汇合”，沿用示例树，但选择 `p=6`、`q=4`：

```text
递归进入方向：父 -> 子
报告返回方向：子 -> 父

                 3
              /     \
             5       1
           /   \    / \
      p = 6     2  0   8
               / \
              7   4 = q
```

正确答案是 `5`。下面不跳步地演算调用和返回。为保持图可读，空孩子调用记为 `null -> null`。

### 第一段：沿左侧进入并处理节点 6

```text
call report(3)
  call report(5)
    call report(6)
      当前输入：节点 6
      处理前状态：尚无孩子报告
      判断依据：6 与 p 是同一个节点对象
      执行动作：不再进入 6 的孩子，直接返回节点 6
      处理后状态：report(6) = 6
      新增结果：只形成“发现目标 p”的局部报告，尚未确定全局答案
```

调用栈与返回方向是：

```text
栈底 [3, 5, 6] 栈顶
                 |
                 +-- 6 返回后弹出

栈底 [3, 5] 栈顶
节点 5 暂存：leftReport = 6
```

### 第二段：处理节点 2 的左右孩子

节点 `5` 还不能决定，因为右子树尚未报告，于是进入 `2`：

```text
report(2)
  -> report(7)
       -> report(null) = null
       -> report(null) = null
       -> 左右都空且 7 不是目标，所以 report(7) = null

  -> report(4)
       -> 4 与 q 是同一个对象，直接 report(4) = 4
```

在节点 `2` 的稳定快照：

| 快照字段 | 内容 |
| --- | --- |
| 当前输入 | `current = 2` |
| 处理前状态 | `leftReport = null`，`rightReport = 4` |
| 判断依据 | 只有右侧交来有效报告，目标相关信息仍集中在一个分支 |
| 执行动作 | 原样返回唯一非空报告 `4` |
| 处理后状态 | `report(2) = 4` |
| 新增结果 | 没有产生新的汇合点，只把目标 `q` 的报告向上传递 |

返回链此时为：

```text
4  --返回 4-->  2  --传播 4-->  5

节点 5 已收到：
leftReport  = 6
rightReport = 4
```

### 第三段：节点 5 完成首次汇合

```text
当前输入：节点 5
处理前状态：左报告为节点 6，右报告为节点 4
判断依据：左右两个互不重叠的孩子子树都交来有效报告
执行动作：丢弃两条子路径细节，把当前节点 5 作为新报告返回
处理后状态：report(5) = 5
新增结果：局部最近公共祖先在此产生
```

为什么不是返回 `6` 或 `4`？节点 `6` 位于左子树，不能成为右子树节点 `4` 的祖先；节点 `4` 同理。节点 `5` 同时连接左右分支，而且任何位于 `5` 下方的节点只属于其中一个分支，所以 `5` 是能覆盖二者的最深节点。

### 第四段：处理右子树 1，并把答案传播到根

右子树不含目标：

```text
report(1)
  report(0)
    null -> null
    null -> null
    report(0) = null
  report(8)
    null -> null
    null -> null
    report(8) = null
  leftReport = null, rightReport = null
  report(1) = null
```

根节点 `3` 的最终快照：

| 快照字段 | 内容 |
| --- | --- |
| 当前输入 | `current = 3` |
| 处理前状态 | `leftReport = 5`，`rightReport = null` |
| 判断依据 | 两个目标已在左子树汇合，右侧没有新的目标信息 |
| 执行动作 | 原样传播节点 `5`，不能用更浅的 `3` 覆盖它 |
| 处理后状态 | `report(3) = 5` |
| 新增结果 | 根调用结束，最终返回节点 `5` |

完整返回链可以压缩成一张方向图：

```text
6(p) ----------- report 6 ---\
                               \
7 ---- report null ---> 2 ---- report 4 ---\
4(q) --- report 4 ----/                       \
                                               5 ---- report 5 ---\
0 ---- report null ---\                       /                    \
                         1 ---- report null --/                      3 ---- final 5
8 ---- report null ---/                                            /

报告方向统一为：子节点 -----------------------------------------> 父节点
首次左右双非空发生在节点 5，因此答案在那里产生；祖先 3 只负责传播。
```

这次遍历访问了与判断相关的每个节点一次。报告从叶子向上变化为 `6、null、4、4、5、null、5`，从未保存两条完整根路径。

## 13. 边界场景的数据变化

### 场景一：一个目标是另一个目标的祖先

使用官方示例 `p=5、q=4`：

```text
            3
          /   \
     p = 5     1
        / \
       6   2
          / \
         7   4 = q
```

关键变化不是一直搜索到 `4`，而是在 `5` 处提前返回：

```text
report(3)
  -> report(5)
       current == p
       立即返回 5，节点 5 以下不再递归
  -> report(1)
       不含 p、q，返回 null
  -> 节点 3 只有左报告非空，返回 5
最终答案：5
```

虽然这次执行没有实际访问 `4`，仍然正确。题目保证 `q` 存在；若 `q` 在 `5` 下方，`5` 就是答案；若 `q` 在其他分支，`5` 会作为 `p` 的报告继续向上等待汇合。返回值在两种情况下相同，因此搜索 `5` 的后代无法给父节点增加必要信息。最终递归栈清空，没有残留集合或未处理队列。

### 场景二：两个目标分居当前节点两侧

使用 `p=5、q=1`：

```text
report(5) = 5
report(1) = 1

在节点 3：
leftReport  = 5
rightReport = 1
两个报告都非空
=> report(3) = 3
```

节点 `3` 是第一次能同时连接两个分支的位置。循环不存在，下标也不存在，因此不会发生数组越界；边界风险集中在空节点判断必须位于读取 `left/right` 之前。

### 场景三：最小两节点树

```text
    1 = p
   /
  2 = q

report(1)：current == p，直接返回 1
根调用结束：答案 1
```

树至少有两个节点，所以官方输入不会出现空树或单节点树；方法仍保留 `root == null` 的出口，因为递归一定会遇到空孩子。默认报告是 `null`，空调用不读取字段，不会空指针。

### 场景四：重复值的迁移测试

官方保证值唯一，但用重复值可以检查代码是否错误依赖 `val`：

```text
        7
       / \
p ->  5   5  <- q

左侧 5 与右侧 5 数值相等，但对象不同。
report(left)  = 左侧节点引用
report(right) = 右侧节点引用
report(root)  = 节点 7
```

用 `current == p`、`current == q` 能得到 `7`；按值命中会在遇到任意一个 `5` 时混淆目标身份。这个测试超出官方唯一值约束，却能验证模型的可迁移性。

### 场景五：目标可能不存在的变式

本题不出现这个输入。若取消“两节点都存在”的保证，当前简洁报告不足以验证完整性：当树里只有 `p` 时，根调用也会返回 `p`，无法区分“`p` 是 LCA”和“只找到了一个目标”。此时报告要扩展为“候选节点 + 命中数量”，最终只有命中数为 `2` 才接受答案。这个边界说明状态是否足够取决于题目保证，不能脱离约束机械复用代码。

## 14. 正确性与不变量

要证明的是：对任意节点 `current`，递归返回值都满足第 9 节定义的报告语义。只要这个局部不变量对根成立，根子树就是整棵树，返回值自然是全局最近公共祖先。

### 基础情况

`current == null` 时，空子树不含任何目标，返回 `null` 正确。

`current == p` 或 `current == q` 时，返回当前节点也正确。若另一目标在当前子树外，当前返回值代表这棵子树找到的唯一目标；若另一目标在当前子树内，因为当前节点可以是自身祖先，当前节点正是二者在该子树内的最近公共祖先。两种情况均符合报告定义。

### 假设孩子报告正确，再看当前节点

对一个不是目标的非空节点，假设左、右递归已经正确汇报各自子树。只可能出现四种组合。

1. 左右都为空。两个孩子子树都不含目标，当前节点自身也不是目标，所以整棵当前子树不含目标，返回 `null` 正确。
2. 左非空、右为空。所有有效目标信息都在左子树。若左报告是单个目标，应继续等待更高处的另一个目标；若左报告已是 LCA，当前节点比它更浅，不能覆盖它。两种情况下原样返回左报告都正确。
3. 左为空、右非空。与上一种情况对称，原样返回右报告正确。
4. 左右都非空。由于 `p`、`q` 是两个不同节点，且左右子树互不重叠，两份有效报告意味着两个目标分处两个孩子分支。当前节点能同时到达二者，因此是公共祖先。任何比当前节点更深的节点只能位于一个孩子子树中，不可能同时到达另一侧目标，所以当前节点就是最近公共祖先。

> **小白追问：** 左右报告都非空时，为什么当前节点就是答案，而不是随便返回左边或右边的节点？
>
> **先给短答：** 因为左侧节点无法成为右侧目标的祖先，右侧节点也无法覆盖左侧目标；当前节点是第一位能同时通向两侧的人。
>
> **最小例子：** 节点 `A` 的左孩子就是 `p`，右孩子就是 `q`。左报告为 `p`，右报告为 `q`；`p` 到不了右孩子，`q` 也到不了左孩子，只有 `A` 能同时到达二者。
>
> **回到模型/代码：** 条件 `leftReport != null && rightReport != null` 表示两个互不重叠的孩子分支都有效，此时执行 `return root`，把当前节点作为汇合报告。

这里有一个容易疑惑的反问：左右非空报告会不会一边已经包含两个目标，另一边又报告一个目标？不会。树中每个节点只有一个位置，`p`、`q` 各出现一次；如果左子树已经同时包含二者，右子树就不可能再包含任何一个，因此右报告必须为空。两边非空只能对应目标分居两侧。

> **小白追问：** 只有一侧报告非空时，为什么必须原样上传，不能把当前节点换成新的报告？
>
> **先给短答：** 因为当前节点没有形成新的双侧汇合；换成当前节点会丢掉更深报告的身份，并可能把已经找到的最近答案错误抬高。
>
> **最小例子：** 节点 `B` 的两个孩子是 `p`、`q`，所以 `B` 已报告 LCA `B`。它的父节点 `A` 只从左侧收到 `B`，右侧为空；若 `A` 擅自改报自己，答案就从更深的 `B` 错成更浅的 `A`。
>
> **回到模型/代码：** 单侧传播对应 `return leftReport != null ? leftReport : rightReport`。这条语句返回孩子报告本身，不返回 `root`，从而保持报告不变量。

### 为什么不会遗漏更近答案

若两目标集中在某个孩子子树中，该子树按照归纳假设已经返回内部更深的 LCA。当前节点看到另一侧为空，只传播这个节点，所有更高祖先也会继续传播，除非出现不可能的额外目标报告。因此深处答案不会被浅处覆盖。

若目标分居左右，任何更近候选都必须在当前节点下方。但下方节点只能属于左或右一侧，无法覆盖另一侧，所以不存在遗漏的更近公共祖先。当前节点就是两条向上路径第一次相遇的地方。

> **小白追问：** “左右汇合”只能证明当前节点是公共祖先，为什么还能证明它是“最近”的？
>
> **先给短答：** 因为当前节点以下的任何节点都只能落在一个孩子分支里，不可能同时覆盖另一个分支中的目标。
>
> **最小例子：** `A` 的左孩子 `B` 下面有 `p`，右孩子 `C` 下面有 `q`。`B` 比 `A` 深，却到不了 `C` 下的 `q`；`C` 同理，所以比 `A` 更深的节点没有一个能成为公共祖先。
>
> **回到模型/代码：** 后序顺序先让更深子树尝试汇合；只有它们不能内部汇合、却分别返回非空报告时，当前 `root` 才成为第一次汇合的位置。

### 丢弃和提前停止为什么安全

空报告对应的子树不含目标，未来父节点只需知道这个事实，不需保留其节点。左右汇合后，子报告及路径细节也不再需要，因为当前节点已经概括了它们对所有祖先的全部贡献。命中目标时提前停止孩子搜索，依据是节点可作为自身祖先以及另一目标保证存在，前一节已经覆盖两种位置可能。

### 遍历结束为什么得到全部答案

每个未被命中出口剪枝的非空节点都递归处理至返回，空孩子立即终止。树节点有限且没有环，调用一定结束。根没有父节点，它交出的报告不再需要继续合并；由于 `p`、`q` 均存在，根子树同时包含两目标，所以根报告必为二者的最近公共祖先，不会是 `null` 或只含一个目标的未完成状态。

## 15. 时间与空间复杂度推导

定义：

- `n`：整棵树的节点总数。
- `h`：树高，也就是根到最深节点路径上的节点数量。
- `s(x)`：以节点 `x` 为根的子树节点数。
- 返回结果只是一个原树节点引用，不按额外输出集合计费。

### 逐候选直接模型

收集全部节点及深度访问 `n` 个节点，时间 `O(n)`。对每个候选 `x`，两次包含搜索最多各访问 `s(x)` 个节点，成本为 `O(s(x))`。总时间为：

```text
O(n) + O(Σ s(x))
```

在链状树中，子树规模依次为 `n,n-1,n-2` 直到 `1`：

```text
n + (n-1) +（中间各项依次减 1）+ 1 = n(n+1)/2
```

因此最坏时间复杂度为 `O(n^2)`。在较均衡的树中总量可能更低，但最坏上界不能据此缩小。保存全部候选和深度需要 `O(n)` 空间；单次包含搜索的递归栈为 `O(h)`，二者合计辅助空间 `O(n+h)=O(n)`。

若直接模型改成“分别找根到 `p`、`q` 的路径再比较”，时间可做到 `O(n)`，但需要保存两条路径或在回溯中维护路径，额外空间最坏 `O(n)`。这说明推荐模型的主要优势不只是渐进时间，还在于把输出所需信息压缩为 `O(h)` 调用栈和一个节点引用。

### 子树报告推荐模型

每个实际访问节点的生命周期是：

```text
进入调用一次
-> 做至多两次身份比较
-> 最多发起左右两个子调用
-> 接收两份可空报告
-> 做常数次非空判断
-> 返回一个引用并退出一次
```

这些都是常数成本。某些目标节点的孩子因提前返回而不会访问，所以实际访问数不超过 `n`；最坏情况下目标位于深叶，全部节点都可能被访问一次。总时间复杂度是 `O(n)`，不存在同一节点从多个候选处被重复扫描。

> **小白追问：** 每个节点都会递归调用左右孩子，为什么总时间不是指数级，而是 `O(n)`？
>
> **先给短答：** 两次递归走向的是两棵互不重叠的子树，每个真实节点只有一个父节点，因此一个节点对象最多被进入一次、返回一次。
>
> **最小例子：** 三节点树 `A` 的孩子是 `B`、`C`。执行过程只会进入 `A、B、C` 各一次；从 `A` 发出的两个调用不会再次访问对方子树，也不会生成新的节点副本。
>
> **回到模型/代码：** 对每个 `root`，生命周期固定为“进入、比较、接收左右报告、返回”。把所有节点的常数成本相加，就是不超过 `n` 份常数工作。

递归栈同时保留一条未完成的根到当前节点路径，最大深度为 `h`，每个栈帧只保存常数个引用，所以辅助空间为 `O(h)`。平衡树中为 `O(log n)`，极端链状树中为 `O(n)`。算法没有另建与 `n` 等长的集合，也没有返回结果数组。

> **小白追问：** 所有节点都递归过，空间为什么是 `O(h)`，而不是始终为 `O(n)`？
>
> **先给短答：** 空间统计的是同一时刻还没结束的调用；已经返回的栈帧会释放，栈里同时存在的只是一条根到当前节点的路径。
>
> **最小例子：** 在三节点树 `A(B,C)` 中，处理 `B` 时栈是 `[A,B]`；`B` 返回后它的栈帧释放，处理 `C` 时栈变成 `[A,C]`，不会同时出现 `[A,B,C]`。
>
> **回到模型/代码：** `h` 是最长根到叶路径上的节点数。每层只保存 `root`、`leftReport`、`rightReport` 等常数个引用，所以峰值辅助空间为“层数乘常数”，即 `O(h)`。

复杂度上的 `O(h)` 不等于工程上一定安全。Java 的调用栈空间有限，`h=10^5` 时可能在算法逻辑结束前抛出 `StackOverflowError`。迭代父指针方案把时间保持为 `O(n)`，将空间改为显式的 `O(n)` 哈希结构，适合需要规避深递归的环境。

### 泛用模型骨架

下面的骨架不依赖 `TreeNode` 字段名，表达的是“二分支结构中的两个目标向上汇合”。`BinaryChildren` 明确定义如何取得左右孩子，因此不存在未定义的抽象调用；调用方只需提供具体节点类型的孩子访问规则。骨架按对象身份比较目标，适用于树节点、组织节点或语法树节点。

```java
final class BinaryBranchMeetingModel<N> {
    interface BinaryChildren<N> {
        N leftOf(N current);

        N rightOf(N current);
    }

    private final BinaryChildren<N> children;

    BinaryBranchMeetingModel(BinaryChildren<N> children) {
        this.children = children;
    }

    public N findLowestMeetingPoint(N root, N targetA, N targetB) {
        if (root == null || root == targetA || root == targetB) {
            return root;
        }

        N leftReport = findLowestMeetingPoint(
                children.leftOf(root), targetA, targetB);
        N rightReport = findLowestMeetingPoint(
                children.rightOf(root), targetA, targetB);

        if (leftReport != null && rightReport != null) {
            return root;
        }
        return leftReport != null ? leftReport : rightReport;
    }
}
```

骨架中的稳定角色是：`root` 表示当前子结构，`targetA/targetB` 表示两个身份目标，`leftReport/rightReport` 表示孩子向上交付的最小报告。`BinaryChildren` 只负责结构导航，不参与答案判断。该骨架假设输入是无环树且两个目标都存在；若用于一般图，要增加已访问状态；若目标可能缺失，返回值还要携带命中数量。

> **小白追问：** 读这段 Java 时，为什么一定要先得到 `leftReport`、`rightReport`，再判断是否返回当前 `root`？
>
> **先给短答：** 因为父节点是否成为汇合点，取决于两个孩子子树已经完成后的报告；报告没回来前，父节点没有足够信息作决定。
>
> **最小例子：** 节点 `A` 的左右孩子分别是 `p`、`q`。只有先得到左报告 `p` 和右报告 `q`，`A` 才能确认两侧都有效，并把自己作为答案返回。
>
> **回到模型/代码：** 更新顺序是“递归计算 `leftReport`、递归计算 `rightReport`、检查双非空、否则传播唯一报告”。这正是第 9 节状态转移在 Java 中的落点。

## 17. 边界、常见错误与调试观察点

| 层次 | 常见问题 | 现象 | 修正依据 |
| --- | --- | --- | --- |
| 建模错误 | 让返回值表示“当前节点是不是目标” | 无法传播子树内部已经找到的目标或 LCA | 返回值必须概括整棵当前子树 |
| 建模错误 | 非空报告只允许代表单个目标 | 子树内部已找到 LCA 后还要携带复杂状态 | 父节点对目标和已结算 LCA 的传播动作相同，可统一为有效节点报告 |
| 建模错误 | 用节点值代替节点身份 | 重复值变式中命中错误对象 | 使用 `root == p || root == q` |
| 条件错误 | 当前节点命中目标后仍只看孩子报告 | `p` 是 `q` 祖先时可能错误返回 `q` | 节点可作为自身祖先，命中应成为递归出口 |
| 条件错误 | 左右都非空时返回任意一侧 | 目标分居两侧却返回一个不能覆盖另一侧的节点 | 汇合结果必须是当前节点 |
| 条件错误 | 只有一侧非空时返回当前节点 | 深处已确定答案被更浅祖先覆盖 | 唯一非空报告必须原样传播 |
| 实现错误 | 在空判断前读取 `root.left` | 空孩子调用触发 `NullPointerException` | `root == null` 必须先判断 |
| 实现错误 | 递归参数误传成两个左孩子或调换目标为值 | 某个分支从未搜索或身份丢失 | 左右调用分别传 `root.left`、`root.right`，目标引用保持不变 |
| 工程风险 | 极端链状树仍使用深递归 | Java 可能抛出 `StackOverflowError` | 需要时改用父指针迭代模型 |
| 约束迁移错误 | 目标可能缺失仍直接复用简洁报告 | 只找到一个目标时也返回非空节点 | 报告增加命中数，根处验证数量为 2 |

调试这类递归时，打印“进入节点”远远不够。最有效的是在每个调用返回前打印稳定报告：

```text
current=<节点身份和值>
leftReport=<null 或节点身份和值>
rightReport=<null 或节点身份和值>
action=<命中、汇合、传播左、传播右、返回空>
returnReport=<null 或节点身份和值>
```

对于 `p=6、q=4`，关键日志应包含：

```text
current=6, action=命中 p, returnReport=6
current=7, left=null, right=null, action=返回空, returnReport=null
current=4, action=命中 q, returnReport=4
current=2, left=null, right=4, action=传播右, returnReport=4
current=5, left=6, right=4, action=汇合, returnReport=5
current=1, left=null, right=null, action=返回空, returnReport=null
current=3, left=5, right=null, action=传播左, returnReport=5
```

若代码看似按身份比较仍难定位重复值问题，日志不要只打印 `val`，可以同时打印 `System.identityHashCode(node)` 作为本地观察标识。它仅用于调试区分对象，不应参与算法正确性判断。

建议逐层检查三个问题：第一，当前调用承诺的报告语义是否始终一致；第二，左右报告何时都非空，那里是否确实是首次汇合；第三，汇合后的节点是否在所有单侧祖先处原样传播。只看最终返回值会掩盖“深处答案被浅处覆盖”等中间错误。

## 18. 最终模型卡

| 模型卡项目 | 结论 |
| --- | --- |
| 识别指纹 | 树上给定两个节点，要求最深的共同祖先；父节点答案依赖孩子子树是否命中目标 |
| 一句话关系模型 | 两个目标分别从所在子树向上形成报告，第一次在左右不同分支同时出现报告的节点就是汇合点 |
| 实际保存什么 | 每个调用栈帧保存当前节点及左右两个可空节点报告，不保存完整路径 |
| 状态何时变化 | 空子树返回空；命中目标返回自身；孩子返回后按“两空、一非空、两非空”合并 |
| 答案何时产生 | 左右报告都非空时局部答案产生，或当前节点本身是另一个目标的祖先；根返回时得到全局答案 |
| 核心不变量 | 当前子树不含目标则报告空，只含一个则报告该目标，同时含两个则报告子树内 LCA |
| 时间复杂度 | 推荐模型 `O(n)`，每个访问到的节点只结算一次 |
| 空间复杂度 | `O(h)` 递归栈；平衡树 `O(log n)`，链状树最坏 `O(n)` |

**四句建模结论：**

```text
我正在处理的对象是：以当前节点为根、需要向父节点交付结论的一棵子树。
我必须持续保存的是：当前节点身份，以及左右子树各自返回的一个可空节点报告。
当左右子树都交来非空报告时，我执行：把当前节点确定为两个目标的最深汇合点并向上返回；只有一侧非空时原样传播。
答案在根调用完成时，由满足统一语义的子树报告计算出来。
```

**泛用模板：**

```text
定义子问题返回值，而不是先写递归：
    空区域 -> 空报告
    当前对象命中目标 -> 报告当前对象
    先取得所有孩子报告
    多个互斥分支都有效 -> 当前对象成为汇合结果
    只有一个分支有效 -> 原样向上传播
    没有分支有效 -> 空报告
```

**迁移变式：**

| 题目或场景 | 保持不变的部分 | 需要改变的部分 |
| --- | --- | --- |
| 235. 二叉搜索树的最近公共祖先 | 目标仍是两条祖先路径的最深公共点 | 增加有序条件后，可按值判断共同向左、共同向右或当前分叉，无需遍历全部子树 |
| 目标节点可能不存在 | 子树仍向父节点报告 | 状态增加命中数量，根调用只有计数为 2 时才接受候选 |
| 多个目标节点的最近公共祖先 | 仍从子树向上汇总目标信息 | 报告需要目标命中数；累计达到目标总数的最深节点成为答案 |
| 一棵树上进行大量 LCA 查询 | “公共祖先中最深者”的关系不变 | 单次后序遍历不再经济，改为倍增或 Euler Tour 与 RMQ 预处理 |

复习时不要只背“左右都非空就返回根”。先说清楚“非空到底代表什么”，再检查左右分支为什么互斥，最后确认更深答案为何会被原样传播。只要返回值业务语义稳定，递归分支就会从模型中自然长出来。
