## 1. 完整题目：739. Daily Temperatures

给定一个整数数组 `temperatures`，长度为 n，表示每天的温度。返回一个数组 `answer`，其中 `answer[i]` 表示：从第 i 天开始，要等多少天才会出现第一个比今天更高的温度。如果第 i 天之后没有任何一天温度更高，则 `answer[i] = 0`。

```text
示例 1：
输入 [73, 74, 75, 71, 69, 72, 76, 73]
输出 [1, 1, 4, 2, 1, 1, 0, 0]

示例 2：
输入 [30, 40, 50, 60]
输出 [1, 1, 1, 0]

示例 3：
输入 [30, 60, 90]
输出 [1, 1, 0]
```

```text
约束：
1 <= temperatures.length <= 10^5
30 <= temperatures[i] <= 100
```

### 题目关键词逐个拆

- “第一个”：要求最靠左的满足者，不是任意一个
- “更高”：严格大于，相等不算
- “等多少天”：答案是天数差，不是温度差
- “之后都没有”：答案填 0
- “n <= 10^5”：暴力 O(n^2) 大概率过不了

这些词不是装饰，后面每一步代码都能对应回其中一个词。

## 2. 第一次上手最容易卡在哪

### 2.1 第一反应是双指针，不是“遍历”

这是很正常的。脑子里其实是：

```text
i 固定，j 从 i+1 往右找第一个更高的
找到就填 j - i
```

官方说“暴力遍历”，我们说“双指针”，其实是一模一样的东西。真正的复杂度问题不在名字，而在 `j` 每次都会从 `i+1` 重新开始。

具体算一遍：

```text
i=0: j 扫 1,2,3,4,5,6,7   7 次
i=1: j 扫 2,3,4,5,6,7     6 次
i=2: j 扫 3,4,5,6,7       5 次
...
总数 = 7+6+5+...+1 = 28 次
```

n=100000 时，接近 5x10^9 次，所以必须换思路。

### 2.2 对数据量级无感知

LeetCode 给的示例都很小，是为了让人能手工验证。真正决定解法的信息在 `constraints` 里。

固定习惯：

```text
1. 先看 n 的范围
2. 如果 n >= 10^5，主动想象一个最坏的大输入
3. 算暴力在这个输入下做多少次操作
```

对于这道题，想象一个 100000 天全递减的温度数组，暴力就会扫成 50 亿次。

## 3. 从题目推导出“等待名单”

### 3.1 先承认自然语言推不出公式

看到“答案是 j - i”时，如果直接接受，后面还是会对不上。必须代入数据：

```text
temperatures[0] = 73
temperatures[1] = 74
第一个比 73 高的位置是 j = 1
答案 = 1 - 0 = 1
```

再换一个跨度大的例子：

```text
temperatures[2] = 75
temperatures[6] = 76
第一个比 75 高的位置是 j = 6
答案 = 6 - 2 = 4
```

两个例子都成立，`j - i` 才从“公式”变成“从第 i 天走到第 j 天，中间隔了几格”。

### 3.2 暴力代码

```java
public int[] dailyTemperatures(int[] temperatures) {
    int n = temperatures.length;
    int[] ans = new int[n];

    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            if (temperatures[j] > temperatures[i]) {
                ans[i] = j - i;
                break;
            }
        }
    }
    return ans;
}
```

### 3.3 暴力浪费在哪

每一个 i 都重新扫描右边一大段。同一个 j 被不同的 i 反复扫。

换一个视角：一个高温度日子到达时，它能让左边所有“还在等更高温度”且比它冷的日子一次性得到答案。

这就是“下一个更高温度”的另一面。

### 3.4 从双指针长成单调栈

原来的双指针结构：

```text
一个固定的 i 在左边
一个到处跑的 j 在右边
```

问题在同一个 j 被不同 i 重复扫描。

反过来：

```text
让右边的日子只出现一次
一次把所有在等它的左边日子全部结算掉
```

每个日子最多入栈一次、出栈一次，所以从 5x10^9 次降到大约 2x10^5 次。

## 4. 用业务故事重建直觉

不要把栈当成“数据结构”，先把它当成一摞便签。

```text
桌上有一摞便签，每张是一个还在等待更高温度的顾客
新的一天来了，只看最上面那张
如果最上面比今天冷，今天就是他的答案，撕掉，继续看下一张
如果最上面不比今天冷，停，今天的便签放到最上面
```

所以这摞便签永远“底下热，顶上冷”。

### 三个动作

```text
热的来：今天温度到达
冷的走：把上面比今天冷的便签全部结账
自己上：今天的便签放到最上面
```

### 每天固定两件事

```text
1. 替所有更冷的等待者结账，可能 0 次
2. 自己进等待名单，固定 1 次
```

所以没有 `else`。`while` 控制弹出多少次，`push` 无条件执行。

## 5. 为什么一开始觉得栈很难写

### 5.1 双重间接

`stack.peek()` 先给一个下标，`temperatures[...]` 才拿到温度。每读一次都要翻译两层，思路会断。

### 5.2 用手写数组栈拆开两层

```java
int[] stack = new int[n];
int top = -1;

for (int i = 0; i < n; i++) {
    while (top >= 0
           && temperatures[stack[top]] < temperatures[i]) {
        int prev = stack[top--];
        ans[prev] = i - prev;
    }
    stack[++top] = i;
}
```

逐行读成业务故事：

```text
stack[top]               = 最上面那张便签是第几天
temperatures[stack[top]] = 那张便签上的温度
top--                    = 撕掉最上面一张，露出下面一张
stack[++top] = i         = 放一张新便签
```

`top` 不是“最大值”，只是一个位置指针，表示最上面的便签在数组第几位。

### 5.3 换成 Deque 只是换 API 名字

```java
public int[] dailyTemperatures(int[] temperatures) {
    int n = temperatures.length;
    int[] ans = new int[n];
    Deque<Integer> stack = new ArrayDeque<>();

    for (int i = 0; i < n; i++) {
        while (!stack.isEmpty()
               && temperatures[stack.peek()] < temperatures[i]) {
            int prev = stack.pop();
            ans[prev] = i - prev;
        }
        stack.push(i);
    }
    return ans;
}
```

| 数组版 | Deque 版 | 业务含义 |
| --- | --- | --- |
| `int top = -1` | `new ArrayDeque<>()` | 空便签堆 |
| `top >= 0` | `!stack.isEmpty()` | 堆里还有便签 |
| `stack[top]` | `stack.peek()` | 最上面那张便签是第几天 |
| `temperatures[stack[top]]` | `temperatures[stack.peek()]` | 那张便签上的温度 |
| `int prev = stack[top--]` | `int prev = stack.pop()` | 撕掉最上面，拿到它 |
| `stack[++top] = i` | `stack.push(i)` | 放上今天的便签 |

## 6. 单调性是怎么保证的

不是规定出来的，是 `while` 弹出这一步保证的。

```java
while (!stack.isEmpty()
       && temperatures[stack.peek()] < temperatures[i]) {
    stack.pop();
}
```

新日子入栈前，把所有比它冷的栈顶全部弹出。所以入栈后，下面那张温度一定大于等于今天。

```text
栈: [75°, 71°, 69°]，今天 72°

69° < 72° -> 弹出
71° < 72° -> 弹出
75° >= 72° -> 停
压入 72° -> 栈: [75°, 72°]
```

相等不会破坏单调性，因为条件是 `<` 而不是 `<=`。

正因为栈顶是当前最冷的等待者，所以只需要看栈顶。栈顶不冷，下面只会更热，更不可能被今天结算。

## 7. 当时的卡点与解法清单

| 卡点 | 为什么卡 | 怎么解开 |
| --- | --- | --- |
| 第一眼是双指针不是遍历 | 名字不同，但其实是同一个暴力 | 先接受它就是暴力，再分析复杂度 |
| 自然语言推不出 `j-i` | 缺了代入数据这一层 | 先用两个具体下标算出来，再抽象 |
| 栈 API 打断思路 | `peek` 给下标，又要回原数组找温度 | 先写数组版，再换成 Deque |
| `top--` 看不懂 | 误以为 top 是最大值 | 把 top 当“最上面的便签位置” |
| 清空 vs 剩元素 | 想完整模拟 while 每一步 | 把 while 当一个整体动作：结到不能结为止 |
| 为什么没有 else | 以为结账和入栈二选一 | 每天固定两件事，push 无条件 |
| 单调性记不住 | 从结论记，没有从动作推 | 记“热天把冷的撕掉再坐下” |

## 8. 宏观建模方法

### 三层模型

```text
第一层  结构：有序等待名单
第二层  维护：热的来，冷的走，自己上
第三层  取结果：pop 时，获取信息 -> 得到结果
```

### 变题三问

```text
1. 弹出条件是什么？
2. 栈里存什么？
3. 弹出时算什么？
```

### 工具型题目统一四问

```text
1. 暴力在哪里重复？
2. 用哪个状态把重复压掉？
3. 每次变化发生在哪个瞬间？
4. 答案在哪个变化点捕捉？
```

| 工具 | 维护的状态 | 变化触发点 | 捕捉答案的瞬间 |
| --- | --- | --- | --- |
| 双指针 | 两个下标形成的区间 | 指针移动 | 区间满足条件时 |
| 滑动窗口 | 窗口内统计量 | 右边界进、左边界出 | 窗口合法时更新 |
| 单调栈 | 等待名单 | 新元素导致弹出 | pop 的那一瞬间 |
| 简单 DP | `dp[i]` | 状态转移 | 转移完成时 |

### 数据代入三步

```text
1. 挑一个最小例子演算
2. 再挑一个跨度大的例子验证
3. 两个都成立，才写成公式
```
