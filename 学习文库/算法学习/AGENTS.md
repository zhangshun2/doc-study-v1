# 算法学习目录维护约定

## 单题五层与实验层职责

| 层 | 路径 | 只负责 | 不负责 |
| --- | --- | --- | --- |
| 事实层 | `problems.json`、标准题解的官方区 | 题意、示例、约束、签名、来源哈希 | 学习推导与代码技巧 |
| 核心层 | `核心模型/<主题型>/` | 一句话本质、类比、状态事件表、最小演算、识别信号 | 完整试错史和权威代码 |
| 应用层 | `题目/<主题型>/` | 标准方案、权威 Java、复杂度、边界 | 复制完整建模长文 |
| 深挖层 | `建模专题/T0/` | 暴力基线、浪费点、视角转换、证明、迁移 | 维护第二份权威实现 |
| 工具层 | `Java速查/`、`学习看板/` | API 回忆、复习状态、导航和筛选 | 改写题目事实 |
| 实验层 | `LeetCode-系统复习/07-分析法实验/` | 多路径比较、准入门槛、评分和主方向选择 | 复制第二份题面、代码或复习日期 |

每道题最多三次点击即可在核心解释、标准代码和完整推导之间切换。稳定相对链接是层间关系的唯一来源。

实验层与单题五层正交。它不改变读题现场顺序，只在同一题存在多条真实方向时解释“为什么当前选择这一条、其他方向在什么条件下仍可用”。主方向必须通过事实保真、自然可达、因果闭包、代码可定位和闭卷可再生五项门槛；评分不能替代推导，也不能成为新的完成度或打卡指标。

`02-概念专题/` 是与单题五层正交的横向概念层。它只维护跨题可迁移的状态、目标、访问范围、回溯、剪枝和去重模型，通过稳定链接连接代表题；不保存官方题意、方法签名、提交代码或事实哈希。

`04-跨题对照/` 是与单题五层正交的对照层。它集中显示多道题的完整题目、示例、约束、方法入口和权威 Java 摘录，用来比较同一搜索骨架上的状态增量。标准题解仍是事实与代码的唯一权威来源，对照页代码由自动校验逐字比对。

## 教学表达原则

本项目首先帮助读者学会“怎样一步步想出模型”，而不是用经验丰富者的终版结论替代推导过程。所有讲解、核心卡、概念卡和跨题对照都必须尽量避开压缩结论，尤其是依赖经验代差才能理解的概括。

“人类视角”不是把专家答案扩写成更长的说明，而是从学习者真实状态出发。真实卡住时，要让读者看见：我现在确定什么、我还不知道什么、为了排除这个不知道，下一个最小问题是什么、用什么证据进入下一段。思路仍在产生可核对的新内容时可以连续往前走。允许保留错误候选和暂时无法决定的状态；不允许用流畅的最终路径假装中间没有卡点。

零起点也要有明确的下一步。新手的起步标准不是“先产生灵感”，而是先完成一个纸面动作：圈出返回要求、替换代词补出动作、给对象写身份、走一个最小例子、数一轮最坏重复、标出历史信息何时失效，或把操作写成动词。每次动作后记录当前最早空缺、实际做了什么、做完多出的证据、真实候选和下一步只问什么。没有形成候选时如实写“没有形成候选”；没有发生真实转折时如实写“没有发生转折”，不能为了模板补造犹豫。

任何新题解、核心模型和 AI 讲解在发布前，都要通过 `LeetCode-系统复习/05-单题流程/单题推导标准卡.md`。标准卡是逐段验收标准，不是写作素材索引；如果一段只有结论、没有过程证据，该段不得标记为通过。

教学正文必须让每个结论由上一段证据逼出来，不能一次跨过多个认知台阶。至少能指出“现在看见什么、因此发现什么、下一步只能问什么、回答后才允许出现什么”。方法名、结构名和复杂度结论只能给已经说清的操作需求命名；不能让名称反过来承担解释。

“显然”“只需”“本质上”“核心就是”都按未偿还的推导债处理。保留这些压缩句时，必须补出它依赖的观察、判断、反例和适用边界；补不出来就继续展开，不能靠流畅措辞代替推导。

验收不只问读者是否觉得解释通顺，还要问能否预测下一问、闭卷重新生成判断、在卡住时指出最早缺失的证据。只能复述答案或确认“听起来对”，不代表达到本项目的理解标准。

### 发布前的人类解题验收

任何题解、核心模型、AI 讲解和复习记录，发布前都要逐行通过 `LeetCode-系统复习/05-单题流程/单题推导标准卡.md#人类解题验收标准`。验收表检查七件事：先看什么、下一件纸面动作、允许继续的证据、仍禁止出现的内容，以及说不通时退回哪里；它不是新的现场框架。

三条硬规则：

1. **题目事实错误一票否决。**
2. **流畅解释、知道方法名和代码跑通都不等于理解。**
3. **闭卷后必须重新生成判断，不能只复述最终答案。**

讲解过程只沿下面的八个自然问题推进。问题由上一段留下的空缺产生，不能提前把所有问题一次答完：

```text
问题 1：我刚读完题，题目到底给了我什么，要我交回什么？
问题 2：每个字都懂，可一个普通人在纸上第一步做什么？
问题 3：这个任务里有哪些对象，谁和谁有关系？
问题 4：照着最笨的办法走一遍，哪一刻什么变了，答案什么时候定下来？
问题 5：这个笨办法最坏会重复多少，数据范围先排除哪些方向？
问题 6：带着这个代价重看，哪份信息还会被再次问起，哪批候选会过期，
        哪个子问题会复用，哪条顺序不能乱？
问题 7：这些操作需要什么方向来承担，另一个方向为什么不够？
问题 8：方向已经定了，状态、更新顺序、不变量和代码怎样逐段对应？
```

八个问题嵌在七个连续阶段里：

```text
阶段 1：问题 1
阶段 2：问题 2
阶段 3：问题 3 -> 问题 4
阶段 4：问题 5
阶段 5：问题 6
阶段 6：问题 7
阶段 7：问题 8
```

七段现场的具体职责是：

1. 先只读原题事实，区分输入、输出、保证、禁止和未知。
2. 把压缩题干扩写成完整生活过程。
3. 先写下当前困惑、实际纸面动作和它新增的证据，再填六列对象表；对象分清后，用最小示例按时间顺序走人工过程，最后只记录第一次变化和答案产生时刻。这里的每一步都必须依次完成，不能压缩成一句“分析题意”。
4. 单独读约束并估算操作预算，再把“官方事实、操作预算、候选方向”分开写。
5. 带着候选和代价做第二次变化分析，找出重复查询、候选失效、子问题复用或顺序约束。
6. 比较候选方案后确认方向，再从需要执行的查询和操作推导数据结构，不能先报结构名称。
7. 方向确认后进入推导链：状态、初始、转移、更新顺序、不变量、伪代码、Java、反例和闭卷重建。

每一步都按同一份自然追问合同检查，不能因为标题已经写好就进入下一段：

```text
这一步是小白的自然追问，因为：______
我刚得到：______
但这份证据只能说明：______
它还不能说明：______
因此现在只允许问：______
回答它至少需要：一条原句 / 一个最小例子 / 一次手算 / 一次预算 / 一项候选比较
回答后只允许新增：______
在回答之前禁止出现：______
```

| 阶段 | 进入条件 | 允许产物 | 禁止产物 | 说不清时退回 |
| --- | --- | --- | --- | --- |
| 1. 读题 | 原题已打开，题解、标签和讨论区已关闭 | 有来源的输入、输出、保证、禁止、未知和真实初始理解 | 方法名、结构名、复杂度结论、题面没有保证的条件 | 原句没读清就重读；记忆先到就标成“记忆候选，不是题目事实” |
| 2. 扩写 | 阶段 1 的事实和未知已分开 | 逐句动作、顺序、停止条件、防错作用和完整人话过程 | 优化理由、最终方法名、题面没有的规则 | 原句仍读错回第 1 段；只会换同义词留在第 2 段 |
| 3. 当前困惑、证据、对象、过程与第一次变化 | 过程能让另一个人照着演完 | 先留下当前困惑、实际纸面动作和新增证据，再得到对象身份与关系、完整人工过程、第一次变化和答案产生时刻 | 没有新增证据就填对象表；问题 3 未分清就进入问题 4；第一次变化出现结构名 | 没有现场动作退回本段起点；对象说不清回到新增证据；过程或变化说不清回前一段 |
| 4. 范围与候选 | 已有第一次变化和答案产生时刻 | 官方约束、操作预算、被排除的复杂度家族和功能候选 | 具体算法名、结构名、“看到 n 就选某方法”、把候选池当结论 | 没有过程证据回第 3 段；把范围当暗号留在第 4 段 |
| 5. 第二次变化 | 已有操作预算和过程产生的候选 | 重复查询、候选失效、子问题复用或顺序约束的最小证据，以及操作需求 | 具体容器、完整伪代码、尚未比较的最终方向 | 没有真实重复或失效回第 3 段；没有预算回第 4 段 |
| 6. 方向确认 | 操作需求具体，候选待比较 | 候选取舍、代价、失效条件和完整方向确认句 | 完整 Java、状态转移细节、只报方法名 | 候选不是从操作长出来回第 5 段；只会报名字留在第 6 段 |
| 7. 推导链 | 完整方向确认句已经写成 | 状态、初始、转移、更新顺序、不变量、结构、代码、反例和闭卷重建 | 新换算法方向、用模板顺序冒充证明、用运行通过补推导 | 模型不通留在第 7 段；方向无依据回第 6 段 |

这份合同与八问七阶段是同一套标准，不是并列的第二套框架。题目事实读错是一票否决；没有形成候选时如实写“没有形成候选”，不能补造一个事后看起来很顺的独白。

现场不能直接列八个标题再填答案。每次换问前至少写清“我刚得到：______；但它还不能说明：______；所以现在只问：______”。逐句扩写保留原句、新增对象/动作/身份/顺序/停止条件、忽略后的具体错误和来源；进入对象阶段先留下当前困惑、实际纸面动作和新增证据，再用六列对象表写出身份、位置、关系与结果；过程阶段逐步写出看见谁、处理谁、做了什么、什么变了、为什么继续；代码阶段用“题目对象 -> 人工动作 -> 第二次变化提出的操作要求 -> 状态变量 -> 伪代码 -> Java 代码位置 -> 更新顺序或不变量 -> 对应反例”的映射表检查是否断链。

前五段只形成题目事实、人工过程、操作预算和待验证候选，不宣布最终方法名。第六段才比较具体候选并写出方向确认句；第七段才进入状态、代码和正确性。

数据范围不能直接推出方法名。候选池必须同时来自“慢过程真正需要的操作”“当前约束允许的操作预算”和“题目特殊保证”；第二次变化发生时，才根据重复劳动或候选寿命继续淘汰方向。

第一次变化与第二次变化必须分开。第一次只描述“过程里发生了什么”，第二次才回答“哪里重复、什么可以复用、哪批候选会失效、需要保存什么”。如果第一次变化里已经出现结构选择，说明推导被压缩了。

下面这类写法容易跳过关键因果，不能直接承担讲解任务：

- “看到最短路，所以直接 BFS。”
- “要求去重，所以模板里加 `used`。”
- “这题显然用单调栈。”
- “只要维护一个最大值即可。”
- “本质上是决策树。”

压缩结论可以保留，但只能放在推导已经完成之后，或者放在明确的结论区。例如：

- 核心卡的“一句话本质”可以作为后续展开的导航，不能替代展开。
- 概念卡末尾的结论回收、最终题解摘要或识别信号区可以给出高度概括。
- 标准题解在完整方案推导之后的复杂度、边界和最终总结可以给出压缩表达。
- 跨题对照的“五题变化总览”可以压缩，但每道题仍要展开完整题目、状态变化和代码映射。

如果一句话需要读者先具备某种“专家直觉”才能理解，就继续展开它。可以描述的完整链路是：

```text
观察到了什么
-> 人工过程会怎样做
-> 哪项信息会影响未来
-> 哪个事件改变这项信息
-> 需要快速完成什么操作
-> 什么结构自然满足这些操作
-> 代码怎样表达状态变化
-> 为什么不会漏解、重复或得到错误结果
```

示范题解还必须写出“小白下一步会追问什么”。不能只展示已经知道答案的人整理出的正确路径，也不能用“显然”“直觉上”“本质上就是”跳过从困惑到判断的桥。

代码注释也要解释状态语义和操作原因，不要只复述语法。例如应说明“第一次发现就删除，避免重复入队并锁定最短距离”，而不是只写“从集合删除”。

## 数据契约

当前题目、核心卡、深挖专题、Java 卡和概念卡统一使用 `schemaVersion: 3`。公共属性包括：

- `type`：`problem`、`core-model`、`modeling-topic`、`java-api`、`concept` 或 `comparison-topic`。
- `leetcodeId`、`titleCn`、`titleEn`、`difficulty`、`primaryPattern`、`topics`、`priority`。
- `sourceUrl`、`sourceCheckedAt`、`sourceFactsSha256`；标准题解和深挖层还保留 `sourceSectionHashes`。
- `mastery`：`未学`、`已理解`、`可独立实现`、`可迁移`。
- `reviewStatus`：`未安排`、`待复习`、`已复习`，与掌握阶段独立。
- `nextReview`、`lastReviewed`：`YYYY-MM-DD` 或 `null`。
- `errorTags`、`independentAttempts`：错因标签和非负独立尝试次数。

概念卡和跨题对照页不要求 `leetcodeId` 和官方事实字段，但必须提供非空 `relatedProblems` 整数数组，且每个题号都存在于 `problems.json`。

“待复习”不覆盖“可迁移”。旧“已完成”只保守迁移为“已理解”，不能自动写成“可独立实现”。

标准题解（`type: "problem"`）是同一道题复习排期的唯一调度源。核心卡、完整建模和 Java 速查可以维护自己的回忆状态，但不得为同一道题再生成一份日期任务。执行单题复习时，从学习看板筛选，在单题复习工作台完成提取，最后只回写标准题解的 `mastery`、`reviewStatus`、`nextReview`、`lastReviewed`、`errorTags` 和 `independentAttempts`。

## 事实与哈希

- `problems.json` 是官方事实的结构化快照。`sourceFactsSha256` 覆盖题意、示例、约束、提示、标签、方法签名和 Java 模板的规范化结果。
- `sourceSectionHashes` 分别记录 `description`、`examples`、`constraints`、`hints`、`tags`、`signature`、`javaTemplate`，用于定位变化。
- 标准题解、核心卡和深挖文档必须与同题事实哈希一致。概念卡不属于题目事实层，不参与事实哈希校验。不要手工改官方区绕过来源校验。
- LeetCode 的“提示”字段与题面中的输入约束不是一回事，不能混写。

## 六类文档

### 标准题解

- 保留准确题面、标准方案、唯一权威提交代码、本地可运行示例和易错点。
- 正文按 `99-模板/题解.md` 的七阶段组织，开头先声明“现场推导”或“事后校验”。阶段 1-5 不出现最终方法名或结构名，阶段 6 才比较候选，阶段 7 才完成状态、更新顺序、不变量、Java 代码位置和对应反例的逐段映射。
- `### LeetCode 可直接提交代码` 与 `### 本地可运行示例` 是 Java 验证脚本依赖的固定入口。
- 提交代码和运行代码中的题目实现必须一致；本地示例补节点类型、数据构造和 `main`。
- 不再复制整套建模长推理，需要深挖时链接 `建模专题/T0/`。

### 核心模型

- 文件名为 `题号-English-Title-核心模型.md`，每题恰好一张。
- 正文控制在 600 至 1200 个中文字符，伪代码不超过 15 行。
- 必须包含：一句话本质、直观画面或扩题、关系重写、对象/关系/状态/事件/不变量/结果表、最小演算、为什么成立、代码映射、复杂度、30 秒识别信号、最小反例或易错点、三层入口。
- 现实类比必须能一一对应状态和事件，不能只是气氛描写。首次出现的术语要先用普通语言解释。

### 建模专题

- 保留完整推理，不设置固定章节数量或字数硬目标。
- 必须覆盖：题意、暴力基线、浪费点、视角转换、状态、不变量、结构选择、演算、正确性、复杂度、迁移。
- Java 只放泛用骨架、伪代码或引用；题目权威代码回到标准题解。
- 不为了篇幅重复解释，也不因为题目简单删掉关键的因果关系。

### 概念卡

- 文件位于 `02-概念专题/`，文件名使用 `序号-概念名称.md`，只维护跨题模型。
- 正文控制在 600 至 1800 个中文字符，伪代码不超过 20 行。
- 必须包含：一句话本质、直观过程、对象与状态、不变量、最小演算、适用信号、最小反例、代码映射、代表题与相邻概念。
- 代表题使用稳定链接连接核心模型或标准题解，不复制题目正文、方法签名和权威代码。
- 总纲 `README.md` 是索引页，不作为概念卡进入模板、长度、语义块和看板速查规则。

### 跨题对照

- 文件位于 `04-跨题对照/`，正文以基础题共同骨架开头，再逐题展示完整题目、变化分析、Java 入口、权威代码和逐段映射。
- 每篇必须包含“共同搜索骨架”“五题变化总览”，并为每个代表题保留“完整题目”“相对基础模型的变化”“Java 入口”“完整 Java 实现”“代码与搜索模型逐段对照”。
- 对照页中的 Java 必须与对应标准题解 `### LeetCode 可直接提交代码` 的代码逐字一致，只允许忽略行尾空白。
- 对照页可以集中复制完整题意和代码，但仍不作为事实或实现来源；引用变化回到标准题解、核心模型和概念卡。
- 总纲 `README.md` 是索引页，不进入对照文档的语义和看板卡片规则。

### Java API 卡

- 每张卡覆盖典型场景、构造方式、常用操作、复杂度、返回值语义、空值与装箱、比较器或迭代修改陷阱、关联题目。
- API 目标为 Java 8；模板可以说明更高版本的兼容目标，但自动门禁按当前可用 JDK 运行。
- 关联题使用稳定 Wiki 相对链接，不复制题目正文。

## 文件与编码

- 单题文件名使用 `题号-English-Title`；核心卡增加 `-核心模型`，深挖文档增加 `-直观建模`。概念卡使用 `序号-概念名称`。
- 文本统一 UTF-8 无 BOM。
- 中文用于教学正文和属性枚举值。属性值使用可被 Bases 直接筛选的中文字面量。
- 不创建无内容占位文档。模板可以用占位词，真实文档不得残留 `TODO`、`TBD` 或无解释的 `待填写`。

## 维护流程

事实同步需要网络：

```bash
node tools/sync-official-data.mjs
node tools/refresh-official-sections.mjs
python3 tools/migrate_library_v3.py
python3 tools/generate-core-cards.py
```

任何修改后运行：

```bash
./validate-all.sh
```

也可分别运行：

```bash
python3 tools/validate_library.py
python3 tools/verify_java_examples.py
```

Java 编译、运行和官方逐例断言全部通过后，才能把来源同步或题解修改视为完成。跨题对照中的 Java 还会与标准题解逐字比较。旧 Node、PowerShell 脚本仅保留兼容用途，不代替跨平台主门禁。
